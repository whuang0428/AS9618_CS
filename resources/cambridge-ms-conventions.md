# Cambridge-Style Marking Conventions

This project uses original questions. It does not reproduce Cambridge past-paper questions or claim that its mark schemes are official.

Calibration sources:

- [Cambridge 9618 past papers, examiner reports and specimen papers](https://www.cambridgeinternational.org/programmes-and-qualifications/cambridge-international-as-and-a-level-computer-science-9618/past-papers/)
- [Cambridge 9618 syllabus for 2027-2029, Version 2](https://www.cambridgeinternational.org/Images/721397-2027-2029-syllabus.pdf)

## Point Marking

- `B1` is an independent fact, identification, definition or explanation point.
- `M1` is a method or process point. The candidate must show the required operation or stage.
- `A1` is an accurate answer or conclusion. It may depend on an earlier `M1` where the scheme makes that dependency clear.
- `FT` permits follow-through from a candidate's earlier value only when explicitly stated.
- Each listed point is independently testable. A single vague sentence is not stretched across several marks.
- A slash separates acceptable alternatives for one mark; it does not create additional marks.

## Wording Rules

- Use the official syllabus term when the question requires a named concept.
- Allow different wording when it conveys the same precise technical meaning.
- Do not credit a keyword that is contradicted or used without the required explanation.
- Do not credit repetition, mirror statements or the same idea rewritten as a second point.
- For `state` or `identify`, do not demand an explanation unless the question asks for one.
- For `explain`, require a mechanism, reason or cause-consequence link rather than a bare advantage.
- For `compare`, use matched dimensions; two unrelated descriptions are weaker evidence of comparison.
- For `justify` or `evaluate`, require application to the stated scenario and a reasoned decision.

## Calculation Rules

- State units in both the question and final answer where relevant.
- Give `M1` for valid intermediate method stages and `A1` for the accurate result.
- Permit an alternative valid method that reaches equivalent stages.
- Apply FT only where a later method remains valid using the candidate's earlier value.
- Do not award a correct number in the wrong representation or unit when that distinction is being assessed.

## Programming and SQL

- Paper 2 answers use Cambridge pseudocode. Java syntax is not accepted as a substitute when pseudocode is requested.
- Award method points for correct control structure, bounds, conditions and data access before the final output point.
- Minor case or harmless layout differences do not lose marks when meaning is unambiguous.
- SQL keywords are case-insensitive. Credit equivalent valid SQL within the syllabus limit of at most two tables.
- Do not overlook a missing `WHERE` condition when it changes the operation's scope.

## Required Guidance

Every substantial assessment question should provide at least one explicit instruction such as:

- `Allow ...` for a valid alternative.
- `Do not accept ...` for a predictable but technically incorrect response.
- `FT ...` for a permitted follow-through rule.
- `Award ... only when ...` where dependency or context is required.

These instructions are local marking guidance modelled on Cambridge conventions. They are not quotations from an official confidential or public mark scheme.
