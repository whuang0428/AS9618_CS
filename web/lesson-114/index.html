Assignment is not a maths equals sign. It is an update.

Variables store values that may change while an algorithm runs. Constants store named values that should not change. Assignment gives a variable a value, often by using its current value to calculate a new one. That is why Count <- Count + 1 is sensible in pseudocode, even though it would be a very odd maths equation.

Memory model

Identifiers name storage locations

Variable

A named storage location whose value can change while the algorithm runs.

DECLARE Count : INTEGER
Count <- 0
Count <- Count + 1

Constant

A named value that should remain fixed. Use it when the same fixed value is used in several places.

CONSTANT MaxMark = 100
CONSTANT VATRate = 0.2

Assignment

Assignment evaluates the right-hand expression first, then stores the result in the left-hand variable.

Total <- Total + Price
Average <- Total / Count

Constants

Name fixed values so the algorithm explains itself

Without a constant

IF Mark >= 50 THEN
    OUTPUT "Pass"
ENDIF

The value 50 appears without explaining its role.

With a constant

CONSTANT PassMark = 50

IF Mark >= PassMark THEN
    OUTPUT "Pass"
ENDIF

The identifier documents the meaning of the fixed value.

Exam point: changing a constant later is a contradiction. If it must change during execution, it should be a variable.

Pseudocode vs Java

The symbol changes, the update idea does not

Cambridge-style pseudocode

CONSTANT PassMark = 50
DECLARE Mark : INTEGER
DECLARE Passed : BOOLEAN

INPUT Mark
Passed <- Mark >= PassMark

Java support only

final int PASS_MARK = 50;
int mark = input.nextInt();
boolean passed = mark >= PASS_MARK;
Paper 2 reminder: use Cambridge-style assignment <- in pseudocode. Java uses = for assignment.
