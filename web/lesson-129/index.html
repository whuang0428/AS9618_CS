Core syllabus content

Pre-condition, post-condition and loop choice

A WHILE...ENDWHILE loop is a pre-condition loop: it tests before the body and may run zero times. A REPEAT...UNTIL loop is a post-condition loop: it executes the body before testing and therefore runs at least once. A FOR...NEXT loop is count-controlled.

Select and justify the loop structure from the problem: use FOR when the count is known, WHILE when execution may be unnecessary and continuation is tested first, and REPEAT when the body must run once before a stopping condition can be tested. The justification must use the scenario, not only say that one loop is easier.

Worked example: Choose the loop from the stopping rule

Input validation must request a value at least once, so REPEAT; INPUT Mark; UNTIL Mark >= 0 AND Mark <= 100 is suitable. Processing records while a file is not at EOF can use WHILE because an empty file may require zero iterations. Processing twelve months uses FOR because the count is fixed.

Repeat while a condition says so, not because you feel optimistic.

Condition-controlled loops are used when the number of repetitions is not known in advance. A WHILE loop checks before it runs; a REPEAT...UNTIL loop runs once before checking. The condition is the door guard: if it never changes, the program may keep walking into the same wall.

Common error

A loop that never updates the variable in its condition is not persistent; it is stuck.

WHILE loop

Pre-condition loop: check before running

Chinese support: condition 条件, pre-condition 前置条件, termination 终止, infinite loop 死循环。

General pattern

WHILE Condition
    // repeated statements
    // update something used by Condition
ENDWHILE

Password example

INPUT Password
WHILE Password <> CorrectPassword
    OUTPUT "Try again"
    INPUT Password
ENDWHILE
OUTPUT "Access granted"
A WHILE loop may run zero times if the condition is false before the first iteration.

Pre-condition loop: check before running

  1. Lesson fact: A WHILE loop checks its condition before each iteration and may run zero times.
  2. Lesson fact: Input Password before testing whether it differs from CorrectPassword.
  3. Lesson fact: Inside the loop, output the retry message and input a replacement Password.
  4. Lesson fact: Output Access granted only after the WHILE condition becomes false.

REPEAT...UNTIL loop

Post-condition loop: run once, then check

General pattern

REPEAT
    // repeated statements
    // update something used by Condition
UNTIL Condition

Input validation

REPEAT
    INPUT Mark
UNTIL Mark >= 0 AND Mark <= 100
REPEAT...UNTIL is useful when the body must happen at least once, such as asking for the first input.

Post-condition loop: run once, then check

  1. Lesson fact: A REPEAT...UNTIL loop checks its condition after executing the body.
  2. Lesson fact: Place INPUT Mark once inside REPEAT so each attempt obtains one value.
  3. Lesson fact: Do not add a duplicate INPUT before the loop.
  4. Lesson fact: Stop when Mark is between 0 and 100 inclusive.

Sentinel values

A special value can stop the loop

Total until -1

The sentinel value is used to stop the loop; it should not be included in the calculation.

A special value can stop the loop

  1. Lesson fact: Initialise Total and input the first Number before WHILE.
  2. Lesson fact: While Number is not -1, add Number to Total and input the next Number.
  3. Lesson fact: The repeated input changes the condition and allows the loop to terminate.
  4. Lesson fact: The sentinel -1 stops the loop and is not included in Total.
