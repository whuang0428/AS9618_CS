Selection is the algorithm saying, "Depends."

IF handles conditions. CASE handles clear choices from one expression. Nested selection handles decisions inside decisions. The exam skill is not just writing keywords; it is making every possible input land on the correct path without falling through a missing ELSE like a badly labelled lift.

Nesteddecision inside a decision

Every branch needs a reason to exist and a way to end.

Why this matters

Selection errors often appear only on boundary or invalid test data, exactly where exam questions like to stand.

Common trap

CASE is not a magic replacement for every IF. It works best when one expression has clear discrete values.

CASE selection

Use CASE for clear values of one expression

Menu choice

INPUT Choice
CASE Choice OF
    1 : OUTPUT "Add record"
    2 : OUTPUT "Delete record"
    3 : OUTPUT "Search"
    OTHERWISE OUTPUT "Invalid choice"
ENDCASE

Why CASE fits

One variable, Choice, is compared with several discrete values. OTHERWISE handles unexpected input.

If each branch needs a different complex condition, IF is usually clearer than CASE.

Same idea, different syntax

Cambridge-style pseudocode

CASE Choice OF
    1 : OUTPUT "Add"
    2 : OUTPUT "Delete"
    OTHERWISE OUTPUT "Invalid"

Java support example only

switch (choice) {
    case 1 -> System.out.println("Add");
    case 2 -> System.out.println("Delete");
    default -> System.out.println("Invalid");
}
