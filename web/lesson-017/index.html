Who serves, who asks, and who secretly does both?

Network models describe roles. In a client-server model, clients request services from one or more servers. In a peer-to-peer model, devices can act as both clients and servers, sharing resources directly with each other.

request -> service -> response

A server is not “the big computer”. It is the device or software providing a service.

Teaching cue

Ask students to label roles before judging the model: who requests, who stores, who controls, who shares?

Why this matters

Cambridge questions often ask for advantages and disadvantages; marks depend on linking each point to a model feature.

Common trap

Client-server and peer-to-peer are not topologies. They describe how services and resources are organised.

Warm-up hook

A student downloads a file from a school file server. What is the student's computer?

Pick the role. The device requesting a service is the client, even if it looks very important on a desk.

Knowledge point 1

Core roles

Client

A client requests a service or resource, such as a web page, file, login or print job.

Server

A server provides a service or resource to clients, often with central control over data and access.

Peer

A peer can request and provide resources directly, so devices share responsibility instead of relying on one central server.

Service

A service is the function provided, such as file storage, authentication, email, printing or web hosting.

Chinese support: client = 客户端；server = 服务器；peer = 对等节点；service = 服务。

Knowledge point 2

Client-server vs peer-to-peer

Feature
Client-server
Peer-to-peer
Control
Centralised management, security, backups and permissions.
Decentralised control; each peer may manage its own resources.
Cost
May need dedicated server hardware, software and administration.
Can be cheaper for small networks because no dedicated server is required.
Reliability
Server failure may affect many clients unless redundancy is used.
No single central server, but availability depends on peers being online.
Typical use
School login, file server, web server, email server.
Small file sharing, local collaboration, distributed sharing.

Knowledge point 3

Scenario choices

School accounts

Client-server fits because logins, permissions and backups can be centrally managed.

Small home sharing

Peer-to-peer may fit when a few devices share files directly without a dedicated server.

Public web app

Client-server fits because many clients request data from managed servers.

Distributed file sharing

Peer-to-peer can spread sharing across peers, reducing reliance on one central source.

Mistake debugging

Fix the weak model answer

“Client-server is better because it is faster.”

Client-server can be suitable because data, access rights and backups can be centrally managed; do not claim "faster" unless performance is explained.

“Peer-to-peer means every computer is connected to every other computer.”

Peer-to-peer describes the role of devices: peers can request and provide resources. It is not the same as mesh topology.

Summary

Model = roles and control

1A client requests a service; a server provides a service.
