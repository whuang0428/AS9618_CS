Compression makes files smaller, but the method matters.

Compression reduces file size so files take less storage and transfer faster. Lossless compression allows exact reconstruction. Lossy compression permanently removes data, usually aiming to remove data that is less noticeable.

AAAAAABBBBCCCCCCCC

Repeated data is friendly to compression. Random-looking data may be less cooperative.

Why this matters

The wrong compression choice can damage data, waste bandwidth or make a file unusable for its purpose.

Common trap

Compression does not guarantee a smaller file. Overhead and lack of patterns can limit the benefit.

Knowledge point 1

Why compress data?

Less storage

Smaller files use less disk or memory space.

Faster transfer

Smaller files need less bandwidth and may download or upload faster.

Trade-off

Compression and decompression may require processing time.

Chinese support: compression = 压缩；decompression = 解压；reconstruct = 还原。

Knowledge point 2

Lossless compression: exact reconstruction

Definition

Lossless compression reduces file size while allowing the original data to be restored exactly.

Suitable uses

Text files, program files, spreadsheets, databases, medical records and backups.

If one changed bit could change meaning or break the file, lossless is the safer answer.

Knowledge point 3

Lossy compression: smaller, but not exact

Definition

Lossy compression reduces file size by permanently removing some data.

Suitable uses

Images, video and sound where small quality loss may be acceptable.

Lossy is not suitable when exact reconstruction is required.

Knowledge point 4

Compression ratio and saved space

compression ratio = original size : compressed size percentage saved = ((original - compressed) ÷ original) × 100
Example: `1000 KB → 250 KB` gives ratio `4:1` and `75%` saved.

Mistake debugging

Correct the compression myth

“Lossless compression always gives the smallest possible file.”

Lossless keeps exact reconstruction, but the file may not shrink much if there are few patterns or if overhead is high.

“Lossy compression is fine for database backups because it saves space.”

Backups must be restored exactly. Lossy compression permanently removes data, so it is unsuitable.

Homework

Clear tasks

  1. Define compression, lossless compression and lossy compression.
  2. Choose lossless or lossy for: database backup, website photo, source code file and music stream. Give one reason for each.
  3. A file reduces from 2400 KB to 600 KB. Calculate the ratio and percentage saved.
  4. Write a 4-mark explanation of why lossy compression is unsuitable for a legal document archive.

Definitions: compression reduces file size; lossless restores the original exactly; lossy permanently removes some data.

Choices: backup and source code need lossless; website photo and music stream may use lossy if quality loss is acceptable.

Calculation: `2400:600 = 4:1`; saved `1800/2400 × 100 = 75%`.

Explanation focus: legal documents must preserve exact content, so lossy removal of data could alter evidence or meaning.
