Exam Rule

In Paper 2, write algorithms clearly using Cambridge pseudocode. Java punctuation is not part of the required answer format.

Conversion Routine

  1. Write the algorithm in English.
  2. Convert English into Cambridge pseudocode.
  3. Only then implement a Java version for testing.
  4. Compare the trace table from the pseudocode with the Java output.
Common misconceptionsFrequent errors and the precise correction.

Common Misconceptions Bank

Paper 1

  • "More bits always means better." Correction: more bits can increase range or precision, but also increases storage and processing needs.
  • "HTTPS is a different internet." Correction: HTTPS is a secure application-layer protocol used over the internet.
  • "RAM and storage are the same because both hold data." Correction: RAM is volatile primary memory; secondary storage is non-volatile.
  • "The CPU stores all files." Correction: the CPU processes instructions; files are stored in secondary storage.
  • "Encryption prevents all attacks." Correction: encryption protects confidentiality, but does not stop weak passwords, phishing, or poor access control.
  • "Ethics questions are opinion questions." Correction: they require balanced, evidence-based evaluation.
  • "A foreign key is just another primary key." Correction: a foreign key references a primary key in another table to create a relationship.

Paper 2

  • "Pseudocode must compile." Correction: pseudocode must communicate the algorithm clearly using Cambridge conventions.
  • "Java syntax is automatically acceptable in Paper 2." Correction: Java is only a support language in this course; exam answers should use Cambridge pseudocode.
  • "A trace table is busywork." Correction: trace tables expose logic errors before code becomes expensive to fix.
  • "Testing one normal case is enough." Correction: robust testing includes normal, boundary, and erroneous data.
  • "A procedure and function are the same." Correction: a function returns a value; a procedure performs a task and may not return a value.

Understanding Cambridge-Style Mark Schemes

Use this guide to interpret the original practice mark schemes in this course and to check your own answers.

Point Marking

  • B1 is an independent fact, identification, definition or explanation point.
  • M1 is a method or process point. The candidate must show the required operation or stage.
  • A1 is an accurate answer or conclusion. It may depend on an earlier M1 where the scheme makes that dependency clear.
  • FT means that a later method may still earn credit after an earlier incorrect value, but only when the mark scheme explicitly allows it.
  • Theory questions normally use independent positive marking points. They do not acquire M1/A1 merely because an answer contains several sentences.
  • M1/A1 is reserved for a genuine method-result dependency, such as a calculation, trace or derived program output.
  • Each listed point represents separate evidence. A single vague sentence will not normally cover several marks.
  • A slash separates acceptable alternatives for one mark; it does not create additional marks.
  • Do not repeat information already supplied by the question as if it were a new point.

Wording Rules

  • Use the official syllabus term when the question requires a named concept.
  • Different wording is acceptable when it conveys the same precise technical meaning.
  • A keyword is not enough if it is contradicted or lacks the required explanation.
  • Avoid repetition, mirror statements or the same idea rewritten as a second point.
  • For state or identify, do not demand an explanation unless the question asks for one.
  • For explain, require a mechanism, reason or cause-consequence link rather than a bare advantage.
  • For compare, use matched dimensions; two unrelated descriptions are weaker evidence of comparison.
  • For justify or evaluate, require application to the stated scenario and a reasoned decision.
  • For discuss, give balanced reasoning and a conclusion where the question requires judgement; an unsupported conclusion is not a separate developed point.

Calculation Rules

  • State units in both the question and final answer where relevant.
  • Show valid intermediate method stages for M1 and an accurate result for A1.
  • An alternative valid method can earn the same marks when it reaches equivalent stages.
  • Use FT only where the later method remains valid with your earlier value.
  • Give the result in the requested representation and unit.

Programming and SQL

  • Paper 2 answers use Cambridge pseudocode. Java syntax is not accepted as a substitute when pseudocode is requested.
  • Method points come from correct control structures, bounds, conditions and data access, not only the final output.
  • Minor case or harmless layout differences do not normally matter when meaning is unambiguous.
  • SQL keywords are case-insensitive. Equivalent valid SQL is acceptable within the syllabus limit of at most two tables.
  • Check that a required WHERE condition is present when it changes the operation's scope.

Sample Answers

  • Compare a sample answer with every marking point, including intermediate working when method marks are available.
  • Treat it as one illustrative complete response, not the only acceptable wording.
  • Equivalent technically correct answers are valid unless the syllabus requires a named term, notation or representation.
  • In scenario questions, apply the technical point to the stated context; a generic fact alone is not enough for an application mark.
