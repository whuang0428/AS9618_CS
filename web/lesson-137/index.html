Testing is not “try three lucky numbers and hope the program behaves”.

A good test set checks typical valid data, edge values, and invalid data. Cambridge questions often ask for normal, boundary and erroneous test data, plus the expected result. Chinese support: normal 正常数据, boundary 边界数据, erroneous 错误数据, expected result 预期结果。

Teaching cue

Anchor every example to one validation rule first. Without a rule, “boundary” becomes a guessing game with extra stationery.

Why this matters

Paper 2 answers need precise test data and expected outcomes. “Test it a lot” is effort, not a mark-worthy method.

Common trap

Boundary data is not automatically invalid. For a mark range 0 to 100 inclusive, 0 and 100 are valid boundary values.

Warm-up hook

A mark must be an integer from 0 to 100 inclusive. Which value is valid boundary data?

Select one option. The program is not allowed to “feel the vibe”; it must follow the range rule.

Choose the value at the edge of the valid range.

Why testing

Testing compares actual results with expected results

A test is useful only if it can reveal whether the program behaves correctly. A strong test case has input data, a reason for choosing it, and a clear expected result.

Validation rule

IF Mark >= 0 AND Mark <= 100 THEN
    OUTPUT "Accepted"
ELSE
    OUTPUT "Rejected"
ENDIF

Testing question

Which values prove that the rule accepts valid marks and rejects invalid marks?

Normal data checks ordinary use. Boundary data checks the edges. Erroneous data checks rejection.

Erroneous data

Erroneous data is invalid data that should be rejected

Out of range

-1 or 101 for a mark from 0 to 100. Expected result: rejected.

Wrong type

"cat" where an integer mark is required. Expected result: rejected or error handled.

Missing required data

An empty name when a name must be entered. Expected result: rejected with a suitable message.

Validation vs testing

Validation is the check. Testing proves whether the check works.

Validation

A program rule, such as “Mark must be from 0 to 100 inclusive”.

Testing

A planned set of inputs, such as 50, 0, 100, -1, 101 and "cat".

Java support only

Java can help you run examples, but Cambridge pseudocode is the exam answer format

Cambridge-style pseudocode

IF Mark >= 0 AND Mark <= 100 THEN
    OUTPUT "Accepted"
ELSE
    OUTPUT "Rejected"
ENDIF

Java support example only

if (mark >= 0 && mark <= 100) {
    System.out.println("Accepted");
} else {
    System.out.println("Rejected");
}
Do not write Java syntax as the final Cambridge pseudocode answer unless the question specifically asks for Java.
