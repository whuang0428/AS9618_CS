An array of records stores many entities that share the same record structure.

A single record stores one student's fields. An array of records stores many students, where each array element is a complete record. The access pattern combines both ideas: index first, then field name.

Declarean array whose elements are records
Accessone field using index plus dot notation
Processtraverse, search, count and update record fields
Students[1:3] [1] Name, Mark, Enrolled [2] Name, Mark, Enrolled [3] Name, Mark, Enrolled
Students[2].Mark <- 84

Index chooses the record. Field name chooses the value inside it.

Why this matters

Paper 2 algorithms often store many related items, then loop through them to find, count or update fields.

Common trap

Students.Mark[2] is the wrong order for this lesson. Use Students[2].Mark.

Declare

Define the record type, then declare the array

Record type

TYPE TStudent
    DECLARE Name : STRING
    DECLARE Mark : INTEGER
    DECLARE Enrolled : BOOLEAN
ENDTYPE

Array of records

DECLARE Students : ARRAY[1:30] OF TStudent

Students[1].Name <- "Ali"
Students[1].Mark <- 72
The record type describes one element. The array declaration creates many elements of that type.

Traversal

A loop visits each record; field access uses the loop index

FOR Index <- 1 TO 30
    IF Students[Index].Mark >= 70 THEN
        OUTPUT Students[Index].Name
    ENDIF
NEXT Index
The loop variable chooses the current record. The field name chooses which value to inspect.

Pseudocode vs Java

Same structure, different syntax

Cambridge-style pseudocode

DECLARE Students : ARRAY[1:30] OF TStudent

FOR Index <- 1 TO 30
    OUTPUT Students[Index].Name
NEXT Index

Java support only

Student[] students = new Student[30];

for (int index = 0; index < 30; index++) {
    System.out.println(students[index].name);
}
Paper 2 reminder: Java arrays are often zero-based. Cambridge pseudocode ranges follow the declaration shown in the question.
