Bad data enters quietly. Good database controls make it show ID at the door.

This lesson separates four ideas that students often blur together: validation, verification, security and backup. You will choose suitable controls for a database and explain what each control can and cannot guarantee.

Four different jobs. One messy database trying to survive Monday morning.

Why this matters

Cambridge-style questions often reject swapped terms: validation is not the same as verification.

Common trap

Validation can reject impossible data, but it cannot prove the data is true. A valid phone number can still belong to the wrong person.

Warm-up hook

A student types age 216 for a school club member. Which control should catch it first?

The database should not need a philosophy degree to decide that 216 is not a likely student age.

Choose the control that checks whether an input value is sensible for the field.

Knowledge point 1

Validation checks whether input is sensible or acceptable

Validation applies rules before data is accepted into the database. It reduces errors but cannot prove truth.

Check
Purpose
Example
Range check
Checks a value is within limits
Age must be 11 to 19
Type check
Checks data has the correct data type
PaymentAmount must be numeric
Presence check
Checks required data is not blank
StudentID must be entered
Format check
Checks data follows a pattern
Email contains suitable structure
Length check
Checks number of characters
Postcode length is acceptable

Knowledge point 2

Verification checks data has been copied accurately

Verification compares entered data with the source or repeats entry to reduce transcription errors.

Double entryThe same data is entered twice and compared. Useful for passwords or email addresses.
ProofreadingA person checks entered data against the original source document.
Key distinctionVerification checks copying accuracy; it does not decide whether the original source was true.

Knowledge point 3

Database security restricts access and protects confidentiality

Security controls reduce unauthorised access, accidental damage and inappropriate disclosure of data.

Access rightsDifferent users can view or edit only the data they need.
AuthenticationUsernames, passwords and multi-factor methods check user identity.
EncryptionData is encoded so it is unreadable without the correct key.

Knowledge point 4

Backups allow data recovery after loss or corruption

A backup is a separate copy of data kept so the database can be restored after failure, deletion or corruption.

FrequencyHow often backups are made, such as daily or hourly.
LocationCopies should be stored separately, often off-site or in secure cloud storage.
TestingA backup is only useful if restoration is tested. Untested backup plans are optimistic fiction.
