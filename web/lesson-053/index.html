The operating system is the resource referee.

Programs want CPU time, memory, files and devices. The operating system coordinates those requests so applications can run without each one grabbing the whole machine and yelling "mine".

The OS does not do your homework. It makes the computer able to run the homework app.

Why this matters

Exam answers need a role plus a service. "The OS manages things" is a start, not a complete mark.

Common trap

An OS role is not the same as a utility tool. Antivirus and backup are utilities; process scheduling and memory allocation are OS roles.

Knowledge point 1

An OS manages resources and provides services

Process management Controls running programs/processes and allocates processor time.
Memory management Allocates memory to programs and helps prevent one process accessing another's memory incorrectly.
File management Organises, stores, retrieves and controls access to files and directories.
Device management Controls communication with peripherals using drivers, buffers and queues.
Chinese support: process management = 进程管理；memory management = 内存管理；file management = 文件管理；device management = 设备管理；scheduler = 调度程序。

Knowledge point 2

Process management: sharing processor time

ProcessA program in execution, with its own state and resources.
SchedulingDecides which process gets CPU time and when.
MultitaskingAllows several processes to appear to run at the same time by sharing CPU time.
State trackingKeeps information such as running, ready or blocked/waiting status.

Why this matters

When an app freezes, it may be waiting for I/O, blocked, or not receiving CPU time. The OS must track and manage that behaviour.

Knowledge point 3

Memory management: allocate, protect, reuse

1. Program startsThe OS allocates memory for code, data and stack/working space.
2. Program runsThe OS tracks which memory blocks are in use.
3. ProtectionThe OS helps stop processes overwriting each other's memory.
4. Program endsThe OS releases memory so it can be reused.

Common trap

Memory management is not the same as file storage. RAM holds running program data; files are stored and organised on storage devices.

Knowledge point 4

File management: names, folders, access and storage

Directory structureOrganises files into folders/directories so users and applications can locate them.
MetadataStores information such as file name, type, size, location and timestamps.
Access controlUses permissions to control who can read, write or execute files.
File operationsProvides services to create, open, save, move, copy and delete files.

Knowledge point 5

Device management: drivers, buffers and queues

Feature
Purpose
Example
Device driver
Software that allows the OS to communicate with a specific device.
Printer driver translates OS print requests into commands the printer understands.
Buffer
Temporary storage used when devices and CPU work at different speeds.
Keyboard buffer stores keystrokes before a program reads them.
Queue
Orders requests waiting for a device.
Print queue stores documents waiting to print.
Interrupt handling
Responds when a device needs attention.
Printer signals that it is ready for more data.

Knowledge point 6

Other OS services at overview level

User interfaceProvides a way for users to interact with the system; Lesson 054 expands interface types.
SecuritySupports user accounts, authentication and access rights.
Error handlingDetects and reports system or application errors where possible.
Application supportProvides common services/APIs so applications do not control hardware directly.
