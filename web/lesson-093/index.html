Ethics needs judgement. Databases need structure. Both punish waffle politely but firmly.

This review connects Section 7 evaluation answers with Section 8 database design and SQL. You will identify whether a question wants balanced judgement, relational design, SQL, or data protection, then answer with precise terms and scenario consequences.

If the question says "discuss", do not write SQL. If it says "query", do not write a speech about society.

Why this matters

Paper 1 review questions often mix command words. Topic recognition prevents a correct fact being used in the wrong answer.

Common trap

Privacy is not a primary key problem. A database can store personal data accurately and still be ethically questionable.

Database review

Relational design: structure before SQL

Primary keyUnique, reliable field that identifies each record in one table.
Foreign keyField that stores a matching primary key value from another table to create a relationship.
NormalisationSeparates repeated data into related tables to reduce duplication, inconsistency and update errors.

Homework

Clear tasks for consolidation

Task 1: Balanced evaluation Write a 6-mark response about facial recognition in school. Include stakeholder, benefit, concern, safeguard and judgement.
Task 2: Database redesign Take a flat file with repeated CustomerName, Address and ProductName. Propose three related tables and identify primary/foreign keys.
Task 3: SQL mini-set Write three queries for the customer table: filter points over 1000, sort by points descending, and total points by region.
