This lesson extends basic SELECT queries with ORDER BY, aggregate functions and GROUP BY. You will sort rows, calculate summaries and group records by category. Multi-table joins are left for Lesson 086.

Why this matters

Students often write a correct WHERE clause but miss the aggregate or GROUP BY, losing the summary mark.

Common trap

If you select a normal field alongside an aggregate, you usually need GROUP BY for that field.

Knowledge point 1

ORDER BY sorts output rows

ORDER BY controls the order of the result rows. ASC means ascending; DESC means descending.

AscendingORDER BY Price ASC: low to high, A to Z, oldest to newest.
DescendingORDER BY Price DESC: high to low, Z to A, newest to oldest.
DefaultMany SQL systems default to ascending, but exams may expect explicit ASC if asked.

Knowledge point 2

Aggregate functions calculate one summary value

Function
Purpose
Example
COUNT
Counts records or non-null values
SELECT COUNT(*) FROM Book
SUM
Adds numeric values
SELECT SUM(Price) FROM Book
AVG
Calculates the mean
SELECT AVG(Price) FROM Book
MIN, MAX
Finds smallest or largest value
SELECT MAX(Price) FROM Book

Knowledge point 3

GROUP BY calculates summaries per group

Use GROUP BY when the question asks for a summary for each category, each borrower, each course or each group.

Pattern: SELECT Category, COUNT(*) FROM Book GROUP BY Category;
Chinese support: sort = 排序；aggregate = 汇总函数；group = 分组；per category = 每个类别。
