An abstract data type is defined by what you can do with it, not by the box it lives in.

A stack and a queue may both be implemented using arrays, but their rules are different. A stack removes the most recently added item. A queue removes the item that has waited longest. That one rule difference explains many exam traces.

Same data items. Different access rules. Exams enjoy that distinction.

Why this matters

Paper 2 can ask for definitions, operation traces, pointer updates, or checks for full and empty structures.

Common trap

Do not define a stack as “an array”. The ADT rule is LIFO; an array is only one possible implementation.

Why an ADT is defined by behaviour

  1. Mechanism: The ADT specifies permitted operations and their observable effects.
  2. Reason: Client code uses those operations without accessing internal storage directly.
  3. Result: The implementation can change while the behaviour contract remains stable.

Analogy: A service counter defines allowed requests without exposing the storeroom layout.

Boundary: Using an array does not automatically make a structure a stack or queue.

Stack

Push adds to the top; pop removes from the top

PUSH A
PUSH B
PUSH C
POP returns C
A stack behaves like a pile of plates: the newest item blocks the older items until it is removed.

Why one open end creates LIFO

  1. Mechanism: Push adds the new item at the top position.
  2. Reason: Only the current top item is available to pop.
  3. Result: The most recently pushed item therefore leaves first.

Analogy: Only the top plate of a pile can be removed safely.

Boundary: Accessing an older item requires removing items above it first.

Queue

Enqueue adds at the rear; dequeue removes from the front

ENQUEUE A
ENQUEUE B
ENQUEUE C
DEQUEUE returns A
A queue behaves like a waiting line: the earliest item is served first.

Why two ends create FIFO

  1. Mechanism: Enqueue adds a new item at the rear.
  2. Reason: Dequeue removes the waiting item at the front.
  3. Result: Earlier arrivals remain ahead of later arrivals.

Analogy: A single orderly waiting line serves the earliest arrival first.

Boundary: A priority queue follows a different removal rule and is not ordinary FIFO.

Why operation names preserve meaning

  1. Mechanism: Push and pop describe changes at a stack's top.
  2. Reason: Enqueue and dequeue describe changes at opposite queue ends.
  3. Result: Using the correct operation prevents accidental access-rule changes.

Analogy: Door names matter when one room has one entrance and another has two.

Boundary: Generic array insertion is not equivalent unless it preserves the ADT rule.

Overflow and underflow

Check before doing the operation

Underflow

IF StackPointer = 0 THEN
    OUTPUT "Stack is empty"
ELSE
    POP()
ENDIF

Overflow

IF StackPointer = MaxSize THEN
    OUTPUT "Stack is full"
ELSE
    PUSH(NewItem)
ENDIF

Why boundary checks come first

  1. Mechanism: Underflow occurs when removal is requested from an empty structure.
  2. Reason: Overflow occurs when fixed storage has no free position.
  3. Result: Checking first prevents invalid reads, writes and pointer changes.

Analogy: Check whether a shelf is empty or full before moving an item.

Boundary: Dynamic storage changes the capacity strategy but can still exhaust memory.

How pointers enforce ADT behaviour

  1. Mechanism: A stack pointer identifies the current top or next free slot.
  2. Reason: Queue front and rear pointers identify removal and insertion positions.
  3. Result: Each valid operation updates data and pointers in a fixed order.

Analogy: Markers turn a row of storage boxes into a controlled service structure.

Boundary: Incorrect wrap-around or update order can overwrite live queue data.

Pseudocode vs Java

Use Cambridge-style operations in exam answers

Cambridge-style pseudocode

PUSH(Stack, "A")
PUSH(Stack, "B")
Item <- POP(Stack)

Java support only

Stack<String> stack = new Stack<>();
stack.push("A");
stack.push("B");
String item = stack.pop();
Java library classes can support understanding, but Paper 2 answers should show the requested ADT operations and checks.

Why pseudocode must expose state change

  1. Mechanism: Test the empty or full condition before accessing storage.
  2. Reason: Read or write the element at the correct pointer.
  3. Result: Update the pointer so the invariant remains true.

Analogy: A clear procedure shows the safety check, action and new boundary marker.

Boundary: Hiding pointer updates makes correctness impossible to verify.

Extra practice

Linked lists and array-based ADT state

A linked list stores nodes containing data and a pointer/index to the next node; a start pointer identifies the first node and a null value ends the chain. Logical order can differ from physical array order.

In an array implementation, parallel Data and Next arrays store nodes and a free-list pointer tracks unused locations. Insert/delete changes links and the free list; items need not be shifted as in a contiguous array.

Worked example: Insert after node 2

Take node 5 from the free list, set Data[5] to the new value, set Next[5] to old Next[2], then set Next[2] to 5. The logical chain now includes node 5 after node 2.

Targeted practice

1. What marks the end of a linked list?

Show answer

A null/sentinel next pointer.

2. What does the start pointer store?

Show answer

The index/address of the first logical node.

3. Why need a free list in an array implementation?

Show answer

To track unused node positions available for insertion.

Exam-style question

4 marks

An array-based linked list uses Data and Next arrays. Explain how a new node is inserted at the front.

Show MS
  1. B1 obtains an unused index from the free list
  2. B1 stores the new data at that index
  3. B1 sets its Next to the old start index
  4. B1 updates start to the new index / updates free-list head
