Defined algorithm steps and identifier tables

Express a solution precisely and document the names, types and purposes of its data.

Could another programmer follow each step without inventing a rule or guessing what a name represents?

Before you start

Does 'calculate a suitable charge' define an operation when no charging rule is supplied?

Check your answer

No. The formula or decision rule must be stated before the charge can be calculated consistently.

01

Specify an ordered solution

S9.03.A01

Visual overview

A rectangular floor area

  1. InputRead length and width in metres.
  2. ProcessMultiply the two supplied dimensions.
  3. OutputReport the area in square metres.

Core explanation

An algorithm is a solution to a problem expressed as a sequence of defined steps. The order and meaning of the steps must be clear enough to carry out the intended task. Steps may include decisions and repeated actions, so a defined sequence does not mean that every execution follows one straight path.

For a rectangular area, obtain the two dimensions before multiplying them and report the product afterwards. 'Find the area' describes the goal but does not supply the calculation. Conditions also need precise operators: 'at least 18' includes 18 and every greater age, not just the single value 18.

Worked example · Turn an area rule into defined operations

  1. Requirements

    Read two non-negative dimensions and output their product.

  2. Pseudocode
    DECLARE Length : REAL
DECLARE Width : REAL
DECLARE Area : REAL
INPUT Length
INPUT Width
Area <- Length * Width
OUTPUT Area
  3. Check

    Length 4 and Width 2.5 give Area 10.

Common misconception

An algorithm is not restricted to a particular programming language or to a list of vague aims.

Check your understanding

Why must the multiplication follow both input operations?

Check your answer

Both operand values must be available before the product is evaluated.

Make data names and meanings explicit

S9.04.A01

Visual overview

Identifiers for reporting a mean mark

IdentifierData typePurpose
StudentNameSTRINGName to display with the result
Mark1, Mark2, Mark3INTEGERThree whole-number marks entered
MeanMarkREALArithmetic mean of the three marks

Swipe horizontally to compare every column →

Core explanation

An identifier names a data item such as a variable or constant. Select meaningful names that distinguish the item's role, and use each name consistently. MeanMark is more informative than X when the value represents the arithmetic mean of marks.

An identifier table records each name, a suitable data type and its purpose. Whole-number marks can use INTEGER, a mean allowing a fraction needs REAL, and a learner's name needs STRING. The table documents meaning; the program still needs to obtain or calculate values before using them.

Worked example · Names connect the design to the program

  1. Requirements

    Input a learner's name and three integer marks, then display the name and arithmetic mean.

  2. Pseudocode
    DECLARE StudentName : STRING
DECLARE Mark1 : INTEGER
DECLARE Mark2 : INTEGER
DECLARE Mark3 : INTEGER
DECLARE MeanMark : REAL
INPUT StudentName
INPUT Mark1
INPUT Mark2
INPUT Mark3
MeanMark <- (Mark1 + Mark2 + Mark3) / 3
OUTPUT StudentName, MeanMark
  3. Check

    Mina with marks 60, 70 and 83 produces Mina and 71.

Common misconception

A sample value is not a data type, and declaring a variable does not assign it an initial value.

Check your understanding

Why should MeanMark permit a fractional value?

Check your answer

The sum of three integer marks is not always divisible by three.

Question 1 · Command word: State2 marks

State what is meant by an algorithm and explain why 'read a price, calculate the tax at 5%, output the tax' is more precise than 'deal with tax'.

S9.03.A01
Answer and marking points
  1. An algorithm expresses a solution as a sequence of defined steps.
  2. The expanded description specifies the input, calculation rate and required result.

Common error: State the defining property and connect it to the supplied example.

Question 2 · Command word: Complete3 marks

Complete an identifier table for a parcel algorithm using ParcelCode, Mass and Express. Parcel codes contain letters, mass may be fractional, and Express records whether express service was selected. Give each type and purpose.

Complete the missing entries

IdentifierTypePurpose
ParcelCode??
Mass??
Express??

Swipe horizontally to compare every column →

S9.04.A01
Answer and marking points
  1. ParcelCode uses STRING to identify the parcel.
  2. Mass uses REAL for the measured parcel mass.
  3. Express uses BOOLEAN for the express-service choice.

Common error: Use data types rather than example values.

Question 3 · Command word: Suggest2 marks

An area algorithm uses A for width and B for length, then computes Result <- A * B. Suggest clearer identifiers and explain whether renaming alone changes the numerical result.

S9.04.A01
Answer and marking points
  1. Width and Length express the dimension roles; Area names the resulting quantity.
  2. Consistent renaming preserves the multiplication and therefore its numerical result.

Common error: Do not change the formula while explaining a naming improvement.

Question 1 · Command word: Write · 2 marks

Write the missing calculation for a parking algorithm using meaningful identifiers, then explain why the original middle step was incomplete. The algorithm says 'read whole hours, calculate the fee, display it'; the rate is 2.50 per hour with no additional charge.

Answer and marking points
  • Fee <- Hours * 2.50 defines the required calculation.
  • The original statement did not specify how the entered hours determine the fee.

Common error: Use the stated rate, not an invented tariff.

Question 2 · Command word: Write · 4 marks

Write an identifier table for a race result: RunnerName stores text, Laps stores completed whole laps, BestTime stores a time in seconds with a fractional part, and Finished stores whether the runner finished. Include types and purposes.

Answer and marking points
  • RunnerName: STRING, the runner's name.
  • Laps: INTEGER, the number of completed laps.
  • BestTime: REAL, the smallest recorded lap time in seconds.
  • Finished: BOOLEAN, the completion state.

Common error: The meaning and unit of BestTime should be clear.

Question 3 · Command word: Explain · 3 marks

A program calculates Change <- Paid - Cost before it inputs Paid and Cost. Explain the ordering defect and write the three operations in a suitable order.

Answer and marking points
  • The subtraction reads values that have not yet been obtained.
  • INPUT Paid and INPUT Cost must both occur first, in either order.
  • Change <- Paid - Cost follows those two inputs.

Common error: Changing identifier names does not correct an input dependency.
