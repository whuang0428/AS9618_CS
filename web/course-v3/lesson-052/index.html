Before you start

Can OUTPUT "Ready" be valid without a variable named Ready?

Check your answer

Yes. The quoted text is a literal. A variable used in an output expression needs a value, but a literal is written directly.

01

Identify supplied data and required results

S9.05.A01

Visual overview

Core explanation

Work backwards from the required result
  1. Output: Identify what the algorithm must communicate.
  2. Process: State the transformations and decisions that produce it, including compatible measurement units.
  3. Input: Identify which values must be obtained and when. A fixed supplied constant need not be input each run.
Turn the design into executable steps

An IPO table is a design aid. Translate its rules into explicit assignments or control structures when pseudocode is requested. Here the fixed postage 3.50 joins ItemPrice × Quantity to produce Total.

Worked example · Calculate an order total

  1. Requirements

    An order contains Quantity identical items at ItemPrice each, plus fixed postage of 3.50. Assume non-negative prices and positive whole quantities.

  2. Pseudocode
    DECLARE ItemPrice : REAL
DECLARE Quantity : INTEGER
DECLARE Total : REAL
INPUT ItemPrice
INPUT Quantity
Total <- ItemPrice * Quantity + 3.50
OUTPUT Total
  3. Check

    ItemPrice 4.25 and Quantity 3 give 12.75 + 3.50 = 16.25.

Common misconception

Do not list the desired total as an input when the program is required to calculate it.

Check your understanding

Why is 3.50 absent from the input column?

Check your answer

It is a fixed value supplied in the charging rule.

Core explanation

Classify statements by their effect

Use INPUT to read into an identifier, an assignment arrow to store an expression's result, and OUTPUT to present values. Cambridge pseudocode uses uppercase keywords and quoted string literals. The left side of an assignment names the destination; the right side is evaluated using the current values.

Track where values become available

An output can contain a literal, a variable or an expression. Every variable read by that expression must already have a value. A declaration establishes a type, not an initial value. Trace a concrete case to check the calculation, subtraction order and requested output rather than merely checking that three keywords appear.

Worked example · Calculate change after sufficient payment

  1. Requirements

    Read Cost and Paid. Assume Paid is at least Cost and both are non-negative. Output the change.

  2. Pseudocode
    DECLARE Cost : REAL
DECLARE Paid : REAL
DECLARE Change : REAL
INPUT Cost
INPUT Paid
Change <- Paid - Cost
OUTPUT Change
  3. Check

    Cost 12.50 and Paid 20.00 produce Change 7.50.

Common misconception

The assignment arrow stores a value; = compares values in a condition and is used in a constant definition.

Check your understanding

Would Change <- Cost - Paid give the same result?

Check your answer

No. For Cost 12.50 and Paid 20.00 it gives -7.50 instead of 7.50.

Cambridge command words

Practice questions

Question 1 · Command word: Write3 marks

Write pseudocode to input a distance in kilometres and a speed in kilometres per hour, then output the journey time in hours. Assume distance is non-negative and speed is positive.

S9.05.A01
Answer and marking points

One valid pseudocode solution

DECLARE Distance : REAL
DECLARE Speed : REAL
DECLARE Hours : REAL
INPUT Distance
INPUT Speed
Hours <- Distance / Speed
OUTPUT Hours
  1. Inputs obtain Distance and Speed.
  2. Hours <- Distance / Speed calculates the duration.
  3. OUTPUT Hours reports the calculated duration.

Common error: Multiplying distance by speed does not give time.

Question 2 · Command word: Write4 marks

Write an IPO table for converting a non-negative length in centimetres to metres, then write pseudocode implementing that table.

S9.05.A01
Answer and marking points
  1. The input is the length in centimetres.
  2. The processing divides that length by 100.
  3. The output is the resulting length in metres.
  4. The pseudocode reads Centimetres, assigns Metres <- Centimetres / 100, then outputs Metres.

Common error: Changing units requires the stated division, not only renaming the variable.

Question 3 · Command word: State2 marks

The supplied pseudocode is run with Cost 18.25 and Paid 20. State its output and explain the role of the assignment.

Use this algorithm in the question.

DECLARE Cost : REAL
DECLARE Paid : REAL
DECLARE Change : REAL
INPUT Cost
INPUT Paid
Change <- Paid - Cost
OUTPUT Change
S9.05.A01
Answer and marking points
  1. The output is 1.75.
  2. The assignment evaluates Paid - Cost and stores the result in Change.

Common error: Trace the values in the supplied input order.

Question 1 · Command word: Write · 4 marks

A sensor supplies a temperature in degrees Celsius. Write pseudocode to input it and output Fahrenheit using Fahrenheit = Celsius * 9 / 5 + 32. State the output for Celsius 20.

Answer and marking points
  • INPUT Celsius obtains the measurement.
  • Fahrenheit <- Celsius * 9 / 5 + 32 calculates the conversion.
  • OUTPUT Fahrenheit presents the result.
  • For Celsius 20 the output is 68.

Common error: The 32 is added after scaling by 9/5.

Question 2 · Command word: Write · 4 marks

A shop sells identical notebooks at 1.80 each. Write pseudocode to input a positive whole-number quantity, calculate the total and output the literal text "Amount due" followed by the total. Explain whether that text needs to be input.

Answer and marking points
  • INPUT Quantity obtains the number of notebooks.
  • Total <- Quantity * 1.80 computes the charge.
  • OUTPUT "Amount due", Total displays both requested items.
  • The quoted message is a literal and does not need input or assignment.

Common error: Distinguish the literal message from the variable Total.

Question 3 · Command word: Write · 3 marks

A tank contains StartLitres and receives AddedLitres. A program inputs both values but only outputs AddedLitres. Write the missing processing and corrected output, then state the result for inputs 35.5 and 12.

Answer and marking points
  • FinalLitres <- StartLitres + AddedLitres combines the existing and added volumes.
  • OUTPUT FinalLitres reports the tank's final content.
  • The stated inputs produce 47.5 litres.

Common error: The delivered quantity alone is not the final tank volume.
