Selecting and using one-dimensional arrays

Retain an indexed sequence of values and process it with a complete loop.

When is one index enough, and how do we process every element?

Choose one independent position

Choose a one-dimensional array when one index identifies each item, such as a test number selecting one mark. The declaration must provide enough positions and an element type suitable for all values. For four whole-number marks, DECLARE Marks : ARRAY[1:4] OF INTEGER gives one element per test.

Retain values when later work needs them

An array retains individual values for later indexed access. If a task requires only a running total, a total variable alone may be enough; retaining an array is justified when later processing needs the original marks, for example displaying the third test mark after all inputs have been read.

Choose storage from the required result

RequirementSuitable storageReason

Find a total, then revisit any particular markA 1D array plus a total.The original marks must remain available.
Store one pupil name and their payment stateA record with named fields.These are different attributes of one item, not interchangeable marks.

Initialise every value that will be read

Initialisation is a separate task. To give every declared STRING element an empty starting value, assign "" to each valid index in a loop. Do not use Names[1 TO 3] <- "": a range is not an individual element access.

Worked example · Initialise every declared element

  1. Task

    Create Names[3:5], set every element to an empty string, change index 4 to Mina and display all elements.

  2. Pseudocode
    DECLARE Names : ARRAY[3:5] OF STRING
DECLARE Index : INTEGER
FOR Index <- 3 TO 5
    Names[Index] <- ""
NEXT Index
Names[4] <- "Mina"
FOR Index <- 3 TO 5
    OUTPUT Names[Index]
NEXT Index
  3. Result

    Three output lines: an empty line, Mina, an empty line. The bounds remain 3:5.

Core explanation · Exam essentials

  • Declare sufficient bounds and one element type; initialise elements before reading them.
Optional extension · Arrays of records and active length

Use the record definition and indexed access already taught. Each element still has one type, MemberRecord. Stop at selecting a record and its field; no new ADT implementation is required.

Worked example · Select an indexed record, then its field

  1. Task

    Input two names, initialise both Paid fields to FALSE and change only the second member to TRUE.

  2. Pseudocode
    TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE Paid : BOOLEAN
ENDTYPE
DECLARE Members : ARRAY[1:2] OF MemberRecord
DECLARE Index : INTEGER
FOR Index <- 1 TO 2
    INPUT Members[Index].Name
    Members[Index].Paid <- FALSE
NEXT Index
Members[2].Paid <- TRUE
FOR Index <- 1 TO 2
    OUTPUT Members[Index].Name
    OUTPUT Members[Index].Paid
NEXT Index
  3. Result

    Inputs Mina and Jo output Mina, FALSE, Jo, TRUE on four lines.

02

Input, store and total a 1D array

S10.05.A01

Visual overview

Store before processing the element

Initialise Total once before the traversal. Each iteration inputs a value into Marks[Index], then adds that same element to Total. FOR Index <- 1 TO 4 visits both bounds, and NEXT Index closes the count-controlled loop. No DO keyword is used in this FOR form.

Keep the accumulated state

Keeping the final OUTPUT after the loop produces one total for all four elements. OUTPUT Marks[3] then demonstrates that the third value remains available. Moving Total <- 0 inside the loop would discard the contributions from earlier elements.

Trace the first two inputs

  1. Start: Total is 0 and Index begins at 1.
  2. First input: Store 6 at Marks[1], then add it: Total becomes 6.
  3. Second input: Store 9 at Marks[2], then add it to the existing total: Total becomes 15.
  4. Finish: After four iterations Total is 26. The later read of Marks[3] still gives 4.

Avoid losing the collection

INPUT Marks[Index] both obtains and stores a value. INPUT Value would require a separate Marks[Index] <- Value assignment. The loop-control variable selects a new destination each time; reusing Marks[1] would overwrite one cell instead of retaining four inputs.

Choose the operation before writing the loop

A total adds the data values. A count adds one for each qualifying item. A maximum keeps the greatest value seen. All can traverse the same array, but they need different update rules and sometimes different initial values.

Worked example · Store four marks and report their total

  1. Task

    Read four INTEGER marks into a 1D array. Display their total, followed by the third mark.

  2. Pseudocode
    DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Marks[Index]
    Total <- Total + Marks[Index]
NEXT Index
OUTPUT Total
OUTPUT Marks[3]
  3. Result

    Inputs 6, 9, 4, 7 produce 26 and 4.

Core explanation · Exam essentials

  • Initialise Total once before the loop; input and accumulate within valid bounds.
  • Place the final total output after the loop; indexed elements remain available for later access.
Common misconception

INPUT Value without saving Value into the indexed element does not populate the array.

Check your understanding

What total would the example produce if Total were reset immediately before every addition?

Check your answer

Only the final mark, 7, would remain in Total.

Count qualifying items

A conditional count measures how many items satisfy a rule. Initialise Count to zero before traversing the stored marks; add one only when the current mark meets the threshold.

Make the condition match the requirement

The requirement is at least Threshold, so equality qualifies. Keep the input pass and processing pass separate here to show that the stored values can be revisited.

Values 6, 9, 4, 7; threshold 7

IndexValue >= 7?Count afterwards
1FALSE0
2TRUE1
3FALSE1
4TRUE2

Check what the accumulator means

Count <- Count + Marks[Index] would add the qualifying marks, producing 16 in this example. The required result is the number of qualifying marks, 2. No qualifying values must leave the initial count at zero; if all four qualify, the result must be four.

Worked example · Count qualifying marks

  1. Task

    Input four INTEGER marks, then an INTEGER threshold, and output how many marks are at least that threshold.

  2. Pseudocode
    DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Threshold : INTEGER
DECLARE Count : INTEGER
FOR Index <- 1 TO 4
    INPUT Marks[Index]
NEXT Index
INPUT Threshold
Count <- 0
FOR Index <- 1 TO 4
    IF Marks[Index] >= Threshold THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  3. Result

    Inputs 6, 9, 4, 7 followed by threshold 7 output 2. Threshold 10 outputs 0; threshold 4 outputs 4.

Core explanation · Exam essentials

  • Initialise a counter to zero and increase it by one only on the qualifying branch.
  • Test the threshold itself, no qualifying values, and all qualifying values.
Common misconception

Add one per qualifying item, not its mark.

Check your understanding

Which comparison is needed for strictly above 7?

Check your answer

Use > 7; a mark equal to 7 must then be excluded.

Find a maximum and a minimum

Start with a real member of the data

An extreme is the greatest or least supplied value. Copy the first element into each candidate, then inspect the remaining elements so the candidate always represents a value encountered in the data.

Replace the candidate only when necessary

Use separate comparisons for Largest and Smallest. Replacing a candidate only for a strict improvement is sufficient when the required outputs are the values rather than their positions.

Explain why the initial value works

Zero is a valid initial total, but it is not a valid maximum candidate for an all-negative collection. Initialising from the first element makes Largest a value that actually occurs. Every later comparison keeps the greatest value encountered so far.

Handle the paired operation and its boundary

For a minimum, initialise Smallest from the first element and update when a later element is smaller. Equal values need no replacement when only the extreme value is required. These four-element examples always contain data; if an optional active-count model allows no items, report that there is no extreme instead of reading element 1.

Worked example · Find both extremes in signed readings

  1. Task

    Input exactly four REAL readings; output the largest and then the smallest. No empty collection is permitted in this task.

  2. Pseudocode
    DECLARE Reading : ARRAY[1:4] OF REAL
DECLARE Index : INTEGER
DECLARE Largest : REAL
DECLARE Smallest : REAL
FOR Index <- 1 TO 4
    INPUT Reading[Index]
NEXT Index
Largest <- Reading[1]
Smallest <- Reading[1]
FOR Index <- 2 TO 4
    IF Reading[Index] > Largest THEN
        Largest <- Reading[Index]
    ENDIF
    IF Reading[Index] < Smallest THEN
        Smallest <- Reading[Index]
    ENDIF
NEXT Index
OUTPUT Largest
OUTPUT Smallest
  3. Result

    Inputs −6.5, −2.0, −9.0, −3.5 output −2.0 and −9.0. Four equal inputs of 2.5 output 2.5 twice.

Core explanation · Exam essentials

  • Initialise an extreme from a supplied element, then compare the remaining elements.
  • Use > for a maximum and < for a minimum; a zero initial maximum fails on all-negative data.
Common misconception

Zero is not a safe initial extreme unless the permitted data and required result justify it.

Check your understanding

For −8, −3, −3, −10, what are the two extremes?

Check your answer

Largest is −3 and Smallest is −10; equal largest values do not change the required value.

Question 2 · Command word: Write4 teacher marks

Write pseudocode to input four INTEGER marks into Marks[1:4], then output their total and the third mark. Explain where Total is initialised.

Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Index : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Marks[Index]
    Total <- Total + Marks[Index]
NEXT Index
OUTPUT Total

  2. Set Total to zero before a FOR loop from 1 to 4.
  3. Input Marks[Index] and add it to Total on each iteration.

Question 3 · Command word: State2 teacher marks

State the output of the supplied conditional-count program with marks [7,6,7,9] and threshold 7. Then change only the comparison to > and give the new output.

Use this complete algorithm in the question.

DECLARE Index : INTEGER
DECLARE Threshold : INTEGER

Answer and checking points — teacher-written
  1. With >=, three marks qualify, so Count is 3.
  2. With >, only 9 qualifies, so Count is 1.

Original question · Cambridge 9618/22

1. Store inputs and output them in reverse

Cambridge 9618/22 · May/June 2025 · 4 · 6 marks

Selected parts: 4 [6].

Reading the question — teacher guidance

Store all 100 inputs before the output phase. The question does not request array declarations. Use a count-controlled traversal in each direction.

Solution / model answer — teacher-written

The input phase uses Number[1] through Number[100] once each. After it finishes, reset Index to 100. The output phase visits 100, 99, …, 1. The data stays in its original array positions; reverse traversal produces the reversed output order.

Official mark scheme
Why this earns marks — teacher explanation

The scheme lists seven functional groups with a maximum of six marks. Its accepted starting indices include 0 or 1, provided the 100-element input and complete reverse output are consistent.

Common mistakes — teacher analysis

After a 1-based input loop, Index is 101: decrement or reset it before accessing Number again. Reversing each input immediately cannot reverse the entire sequence.

Lesson review

Summary

Selection

Use a 1D array when one index identifies every retained value.

Traversal

Input or process each indexed element within the declared bounds and initialise a total before the loop.

Count and extremes

A conditional count adds one per match. Initialise maximum and minimum from an actual element, including for all-negative data.
