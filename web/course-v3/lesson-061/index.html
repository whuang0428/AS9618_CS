Build a booking system · Concept 11

Choose one index when one position identifies the value

Observe

What will the next step need?

  • Inputs in arrival order: 8, 3, 5, 3, 1
  • Task A: display only their total.
  • Task B: display the third request later.

Look, then discuss

Why keep all five seat requests if the program can read one at a time?

The desk must later search the requests and display them in reverse arrival order. If each new input overwrites a single variable, the earlier requests will no longer be available.

Recall

Recall replacement by assignment

Reading another input into Request replaces that scalar value. An array provides a separate element for each retained value.

Explain

Explanation · 1 / 3

Match one index to one position

A list of five requests needs one position number to locate an item. A one-dimensional array is suitable: Request[1] through Request[5] retain the sequence.

Explanation · 2 / 3

Retain values when later access needs them

Search, reverse output and sorting require access to earlier values. An array allows this repeated access. A running total alone cannot reconstruct the original requests.

Explanation · 3 / 3

Avoid storing values without a reason

If the only requirement is the final total, one current-value variable and an accumulator may suffice. Choose the structure from the required later operations, not merely because several inputs exist.

Work together

Compare two requirements

Both programs receive 8, 3, 5, 3 and 1.

Work together · 1 / 2

Only display the total

A running Total can accumulate 20 while each current input is replaced. No later operation needs each individual value.

Work together · 2 / 2

Display the third request later

Total = 20 cannot identify the third request. Store the inputs in an array so Request[3] remains available and gives 5.

Ask which individual values must remain available after the next input arrives.

Check

Try it yourself · Teacher-written

A program must compare each day’s reading with the previous week after all readings are entered. Is retaining the readings useful?

Check your reasoning

Yes. The later comparisons need individual earlier readings, so indexed storage is appropriate. A total alone would lose the required detail.

Connect

Keep this idea

Use a one-dimensional array for a collection located by one index when later processing needs the values.

A FOR loop can fill, total or display that array using the same bounds.

Trace forward and reverse traversal

Observe

Keep the cards in their original positions

Index12345
Request83531

Look, then discuss

Must the array itself change to display its values in reverse order?

Keep cards [8, 3, 5, 3, 1] in their original positions. Read position 5, then 4, 3, 2 and 1. Only the order of visits changes.

Recall

Recall FOR and an accumulator

FOR assigns successive index values and repeats its body. NEXT returns to the loop control. An accumulator stores a running result: Total <- Total + Value adds the current value to the old total. Set Total to 0 before adding the first value.

Explain

Explanation · 1 / 4

Fill each legal position once

Use FOR Index <- 1 TO 5 to visit all five positions. INPUT Request[Index] stores each entered value in its own element. A later loop can revisit those stored values.

Explanation · 2 / 4

Trace the running total

Start Total at 0 outside the loop. For [8, 3, 5, 3, 1], the successive totals are 8, 11, 16, 19 and 20. Resetting Total inside the loop would discard the previous additions.

Explanation · 3 / 4

Reverse the visits without moving the data

After the input loop completes, start a new loop at the upper bound and use STEP -1. Each output reads the selected element. The stored array remains [8, 3, 5, 3, 1].

DECLARE Request : ARRAY[1:5] OF INTEGER
DECLARE Index : INTEGER
DECLARE Total : INTEGER
FOR Index <- 1 TO 5
    INPUT Request[Index]
NEXT Index
Total <- 0
FOR Index <- 1 TO 5
    Total <- Total + Request[Index]
NEXT Index
OUTPUT Total
FOR Index <- 5 TO 1 STEP -1
    OUTPUT Request[Index]
NEXT Index

Explanation · 4 / 4

Represent the same control flow in a flowchart

For the reverse phase, initialise Index to 5; test Index >= 1; on TRUE output Request[Index], subtract 1 and return to the test. On FALSE, finish. Complete the input phase before beginning the output phase.

Original question · Cambridge 9618/22
1. Store inputs and output them in reverse
Cambridge 9618/22 · May/June 2025 · 4 · 6 marks
Selected parts: 4 [6].
Hint — reading the question
Store all 100 inputs before the output phase. The question does not request array declarations. Use a count-controlled traversal in each direction.
Reasoning and model answer — teacher-written
The input phase uses Number[1] through Number[100] once each. After it finishes, reset Index to 100. The output phase visits 100, 99, …, 1. The data stays in its original array positions; reverse traversal produces the reversed output order.
Official mark scheme
Why this earns marks — teacher explanation
The scheme lists seven functional groups with a maximum of six marks. Its accepted starting indices include 0 or 1, provided the 100-element input and complete reverse output are consistent.
Common mistakes — teacher analysis
After a 1-based input loop, Index is 101: decrement or reset it before accessing Number again. Reversing each input immediately cannot reverse the entire sequence.

Build a booking system · Concept 13
Count matches and combine conditions

    
Observe
Count requests of at least five seats
  • Requests: 8, 3, 5, 3, 1
  • Threshold: 5
  • Count starts at 0.
Look, then discuss
For requests [8, 3, 5, 3, 1], is the number of requests of at least 5 equal to 13?
Only the requests containing 8 and 5 qualify. Their sum is 13, but there are two qualifying requests. Decide whether the task asks “how many?” or “how much altogether?”.

    
Recall
Recall IF, comparisons and Boolean operators
IF runs its body only when the condition is TRUE. AND requires both conditions to be TRUE; OR requires at least one. MOD gives the remainder after integer division: 6 MOD 2 is 0, while 7 MOD 2 is 1.

    
Explain
Explanation · 1 / 3
Increment a count by one
Initialise Count to 0. When an element meets the condition, Count <- Count + 1 records one matching element. Adding the element’s value instead would calculate a total.
DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Threshold : INTEGER
DECLARE Count : INTEGER
FOR Index <- 1 TO 4
    INPUT Marks[Index]
NEXT Index
INPUT Threshold
Count <- 0
FOR Index <- 1 TO 4
    IF Marks[Index] >= Threshold THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
Explanation · 2 / 3
Trace both branches
For requests [8, 3, 5, 3, 1] and threshold 5, the count becomes 1, stays 1, becomes 2, stays 2 and stays 2. The condition is evaluated for every element, even when the count does not change.
Explanation · 3 / 3
Group combined conditions deliberately
A test such as (Index MOD 2 = 0) AND ((Request[Index] = 3) OR (Request[Index] = 5)) requires an even index and one of the two permitted values. The brackets apply the even-index rule to the entire OR group.

    
Work together
An even position with an accepted request value
Use [8, 3, 5, 3, 1] and accept value 3 or 5 only at even positions.
Work together · 1 / 2
Check index 2
2 MOD 2 = 0 is TRUE. Request[2] = 3 is TRUE, so the OR group is TRUE. TRUE AND TRUE qualifies: add one.
Work together · 2 / 2
Check index 3
The value 5 satisfies the OR group, but 3 MOD 2 = 0 is FALSE. FALSE AND TRUE is FALSE, so this element does not qualify. Index 4 does qualify, giving count 2.
Evaluate each grouped condition, then combine their Boolean results.

    
    
Check
Try it yourself · Teacher-written
A row satisfies both alternatives in an OR condition. Should one IF body run twice?
Check your reasoning
No. The OR expression evaluates to one Boolean result, TRUE. The IF body executes once for that evaluation, so a count increments once.

Build a booking system · Concept 14
Find a largest or smallest value safely

    
Observe
Four measured readings
  • Reading[1:4] = [-4, -8, -2, -6]
  • Find the largest and smallest stored readings.
Look, then discuss
Why does starting Largest at 0 fail for readings [-4, -8, -2, -6]?
All four readings are below zero. A proposed maximum of 0 was never measured. Start with a value that is actually in the non-empty collection.

    
Recall
Recall selection and a running result
IF Reading[Index] > Largest updates Largest only when the new reading is greater. The other iterations must retain the best value already found.

    
Explain
Explanation · 1 / 3
Use the first element as the initial candidate
For a non-empty array, set Largest and Smallest to Reading[1]. They are now actual input values. This works whether the inputs are positive, negative or mixed.
Explanation · 2 / 3
Process the remaining elements
Start at index 2 because index 1 is already represented. Replace Largest only for a greater value, and Smallest only for a smaller value. Use two IF statements because each comparison has its own purpose.
DECLARE Reading : ARRAY[1:4] OF REAL
DECLARE Index : INTEGER
DECLARE Largest : REAL
DECLARE Smallest : REAL
FOR Index <- 1 TO 4
    INPUT Reading[Index]
NEXT Index
Largest <- Reading[1]
Smallest <- Reading[1]
FOR Index <- 2 TO 4
    IF Reading[Index] > Largest THEN
        Largest <- Reading[Index]
    ENDIF
    IF Reading[Index] < Smallest THEN
        Smallest <- Reading[Index]
    ENDIF
NEXT Index
OUTPUT Largest
OUTPUT Smallest
Explanation · 3 / 3
Explain the condition after each visit
After processing an element, Largest is the greatest value seen so far and Smallest is the least value seen so far. After the final element, the claim covers the entire array.

    
Work together
Trace negative readings
The inputs are -4, -8, -2 and -6.
Work together · 1 / 2
Initialise and compare
Start Largest = -4 and Smallest = -4. At -8, only Smallest changes. At -2, only Largest changes. At -6, neither changes.

Explain the faulty zero start
Starting Largest at 0 would leave it at 0 because every input is smaller. The result would not belong to the data and would be incorrect.
Initialise from a real element when a non-empty collection must supply the result.

Question 1 · Command word: Select2 teacher marks
A club stores one attendance count for each of 12 meetings. Select a structure and write its declaration.
S10.04.A01
Answer and checking points — teacher-written
  1. A 1D array is suitable because meeting number selects one count.
  2. DECLARE Attendance : ARRAY[1:12] OF INTEGER.
Common error: The number of meetings determines capacity, not the number of dimensions.
Question 2 · Command word: Write4 teacher marks
Write pseudocode to input four INTEGER marks into Marks[1:4], then output their total and the third mark. Explain where Total is initialised.
S10.05.A01
Answer and checking points — teacher-written
One valid pseudocode solution
DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Marks[Index]
    Total <- Total + Marks[Index]
NEXT Index
OUTPUT Total
OUTPUT Marks[3]
  1. Declare the array and INTEGER Index and Total.
  2. Set Total to zero before a FOR loop from 1 to 4.
  3. Input Marks[Index] and add it to Total on each iteration.
  4. After NEXT Index, output Total and Marks[3].
Common error: Initialise the accumulator outside the loop.
Question 3 · Command word: State2 teacher marks
State the output of the supplied conditional-count program with marks [7,6,7,9] and threshold 7. Then change only the comparison to > and give the new output.
Use this complete algorithm in the question.
DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Threshold : INTEGER
DECLARE Count : INTEGER
FOR Index <- 1 TO 4
    INPUT Marks[Index]
NEXT Index
INPUT Threshold
Count <- 0
FOR Index <- 1 TO 4
    IF Marks[Index] >= Threshold THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
S10.05.A01
Answer and checking points — teacher-written
  1. With >=, three marks qualify, so Count is 3.
  2. With >, only 9 qualifies, so Count is 1.
Common error: Test the equality boundary explicitly.
Question 4 · Command word: State3 teacher marks
State both candidates after each comparison in the supplied extremes program for [−8,−3,−3,−10]. Explain why starting Largest at 0 would fail.
Use this complete algorithm in the question.
DECLARE Reading : ARRAY[1:4] OF REAL
DECLARE Index : INTEGER
DECLARE Largest : REAL
DECLARE Smallest : REAL
FOR Index <- 1 TO 4
    INPUT Reading[Index]
NEXT Index
Largest <- Reading[1]
Smallest <- Reading[1]
FOR Index <- 2 TO 4
    IF Reading[Index] > Largest THEN
        Largest <- Reading[Index]
    ENDIF
    IF Reading[Index] < Smallest THEN
        Smallest <- Reading[Index]
    ENDIF
NEXT Index
OUTPUT Largest
OUTPUT Smallest
S10.05.A01
Answer and checking points — teacher-written
  1. Largest progresses −8, −3, −3, −3.
  2. Smallest progresses −8, −8, −8, −10.
  3. Zero would never be replaced by a negative value even though it is not an input.
Common error: Initialise both candidates from an actual element.
Question 5 · Command word: State2 teacher marks
State the Total after each iteration and both outputs from the supplied array-total algorithm for inputs 5, 0, 8, 2.
Use this complete algorithm in the question.
DECLARE Marks : ARRAY[1:4] OF INTEGER
DECLARE Index : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Marks[Index]
    Total <- Total + Marks[Index]
NEXT Index
OUTPUT Total
OUTPUT Marks[3]

Answer and checking points — teacher-written
  1. The successive totals are 5, 5, 13 and 15.
  2. The outputs are 15 and 8.
