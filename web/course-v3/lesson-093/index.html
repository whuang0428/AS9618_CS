Core explanation

Begin with the required result and retain the facts that determine it. Decompose the task into cooperating responsibilities, choose meaningful identifiers and refine the processing until the rules and execution order are explicit. The resulting IPO, pseudocode and flowchart should describe the same solution.

Challenge a completed algorithm at decision boundaries and loop limits. Follow each path using actual values, checking initialisation, new inputs, updates and the final output. A convincing design combines correct logic with a representation that another programmer can implement without guessing.

Worked example · Count accepted parcels

  1. Requirements

    Input four real-valued parcel masses and count those from 2 to 5 kg inclusive.

  2. Pseudocode
    DECLARE Index : INTEGER
DECLARE Weight : REAL
DECLARE Accepted : INTEGER
Accepted <- 0
FOR Index <- 1 TO 4
    INPUT Weight
    IF (Weight >= 2.0) AND (Weight <= 5.0) THEN
        Accepted <- Accepted + 1
    ENDIF
NEXT Index
OUTPUT Accepted
  3. Check

    1.9, 2, 5 and 5.1 produce an accepted count of 2.

Common misconception

A correct count for one input set does not establish that both inclusive boundaries are handled correctly.

Core explanation

Choose each value's type before grouping values: record fields may have different types, whereas an array has a declared element type and explicit bounds. One index selects a 1D element; two select a 2D element. Write complete declarations, field access and bounded iteration before tracing the resulting values.

For array processing, linear search checks consecutive elements and reports a matching position or absence; bubble sort uses complete adjacent swaps. Files retain results between runs through the appropriate read, write or append mode. ADTs specify data and operations: use LIFO for a stack, FIFO for a queue and links for a linked list, and keep the array implementation's active state consistent after each operation.

Worked example · Trace data through a small booking system

  1. Input and store

    A record holds a STRING name and INTEGER seat number. Five seat requests are retained in Request[1:5].

  2. Process

    For Request values 8, 3, 5, 3, 1, a first-match search for 3 returns index 2; ascending sorting gives 1, 3, 3, 5, 8.

  3. Retain and order

    Append the processed booking to a log. A queue controls arrival order; an undo stack stores the latest completed change and its previous state.

Common misconception

The same values can support different access rules; justify the data structure from the required operation, not merely the scenario name.

Core explanation

Translate the stated rules into declarations, expressions and correctly placed control structures. Read supplied routine interfaces before calling them. A complete solution defines values before use, respects condition boundaries and makes progress toward the stopping condition.

Connect subprograms through arguments, returned values and intentional reference updates. In this review, a parking session costs 3 per whole hour; positive integer hours are entered until sentinel zero. A charge function returns each fee and an accumulation procedure updates the running total. The first input may already be zero.

Worked example · Combine a charge function and accumulation procedure

  1. Pseudocode
    FUNCTION Charge(Hours : INTEGER) RETURNS INTEGER
    RETURN Hours * 3
ENDFUNCTION
PROCEDURE AddCharge(BYVAL Amount : INTEGER, BYREF Total : INTEGER)
    Total <- Total + Amount
ENDPROCEDURE
DECLARE Hours, Total : INTEGER
Total <- 0
INPUT Hours
WHILE Hours <> 0
    CALL AddCharge(Charge(Hours), Total)
    INPUT Hours
ENDWHILE
OUTPUT Total
  2. Trace and check

    Inputs 2, 1, 0 produce 9; input 0 alone produces 0.

Common misconception

A sentinel is a stopping signal and must not become an extra charged session.

Check your understanding

Why does this program use WHILE rather than a fixed-count FOR?

Check your answer

The number of sessions is unknown and may be zero.

Core explanation

Connect each development decision to observable evidence: requirements and project constraints guide the life cycle; a hierarchy and labelled interfaces guide implementation; states and transitions document event-dependent behaviour. Use a trace to check that the resulting algorithm implements the intended rules.

Choose tests for the risks being examined and record their expected results before running them. After delivery, identify why a change is needed, analyse its impact, make the requested amendment and check both changed and preserved behaviour. A category name alone cannot demonstrate any of these practical skills.

Common misconception

Correct vocabulary is not enough when a task asks for a chart, a trace or an amended program.

Check your understanding

Which evidence checks that an enhancement preserved the old calculation?

Check your answer

Run the old and amended programs on the same cases and compare their original outputs with independently expected results.

Command word: Explain3 marks

A student uses a procedure call where a value is required inside an expression. Explain the error and give the correct use of a function.

Answer and marking points
  1. A procedure performs an action but does not supply a value, so its call cannot replace an operand inside an expression.
  2. A function declares a return type and executes RETURN to send one value back to its caller.
  3. The corrected expression uses the function call where the returned value is required.

Common error: Do not repeat the same point in different words; each mark needs a separate idea or method step.

Command word: State3 marks

A parcel desk only decides whether a parcel mass is from 2 to 5 kg inclusive and counts accepted parcels. State which mass data its abstract model needs, give one irrelevant detail for this decision, and decompose the task into three responsibilities.

S9.01.RS9.02.R
Answer and marking points
  1. The model retains the mass of each parcel in kilograms.
  2. A sender's preferred envelope colour does not affect the stated mass rule.
  3. The task can be divided into obtaining a mass, deciding acceptance and accumulating/reporting the accepted count.

Common error: Retain the mass rule and count rather than inventing a price calculation.

Command word: Write3 marks

Write an identifier table for the supplied parcel-counting algorithm and describe its input, processing and output. Explain why its steps are sufficiently defined to follow.

Use this algorithm in the question.

DECLARE Index : INTEGER
DECLARE Weight : REAL
DECLARE Accepted : INTEGER
Accepted <- 0
FOR Index <- 1 TO 4
    INPUT Weight
    IF (Weight >= 2.0) AND (Weight <= 5.0) THEN

    ENDIF
NEXT Index
OUTPUT Accepted
S9.03.RS9.04.RS9.05.R
Answer and marking points
  1. Index, Weight and Accepted represent the loop position, current parcel mass and qualifying total, with types INTEGER, REAL and INTEGER.
  2. It inputs four masses, applies the stated interval to each, and outputs the number accepted.
  3. The code explicitly defines the iteration count, comparisons and increment, so no acceptance or counting rule remains unspecified.

Common error: Weight must permit fractional kilograms.

Command word: Write4 marks

Write pseudocode for this structured English: initialise a count to zero; read four parcel masses; for each mass from 2 to 5 kg inclusive increase the count; display the final count. Identify the three basic constructs and state the output for 1.9, 2, 5 and 5.1.

S9.06.RS9.07.RS9.09.R
Answer and marking points

One valid pseudocode solution

DECLARE Index : INTEGER
DECLARE Weight : REAL
DECLARE Accepted : INTEGER
Accepted <- 0
FOR Index <- 1 TO 4
    INPUT Weight
    IF (Weight >= 2.0) AND (Weight <= 5.0) THEN
        Accepted <- Accepted + 1
    ENDIF
NEXT Index
OUTPUT Accepted
  1. Initialisation precedes a four-iteration loop with a fresh input each time.
  2. The selection uses (Weight >= 2) AND (Weight <= 5) and increments only when true.
  3. The final output follows repetition; initialisation/output illustrate sequence, IF illustrates selection and FOR illustrates iteration.
  4. The supplied masses produce 2.

Common error: The interval requires AND, with both endpoints included.

Command word: Explain2 marks

An intermediate parcel design says 'check the mass and update the count'. Refine this step into programmable detail and explain why setting the count to zero belongs outside the four-parcel loop.

S9.08.R
Answer and marking points
  1. IF (Weight >= 2) AND (Weight <= 5) THEN Accepted <- Accepted + 1 ENDIF defines the check and update.
  2. Accepted starts at zero before the loop so later qualifying parcels add to earlier ones rather than replacing their count.

Common error: Initialisation inside the loop would lose earlier acceptances.

Command word: Define4 marks

A booking record needs Name and SeatNumber. Define BookingRecord with suitable types, declare Booking, and write statements to input both fields and display Name.

S10.01.RS10.02.R
Answer and marking points
  1. TYPE BookingRecord and ENDTYPE enclose DECLARE Name : STRING and DECLARE SeatNumber : INTEGER.
  2. DECLARE Booking : BookingRecord creates the variable.
  3. INPUT Booking.Name and INPUT Booking.SeatNumber save the entered fields.
  4. OUTPUT Booking.Name reads and displays the name.

Command word: Give4 marks

A theatre holds one occupied flag per seat in 3 rows of 8 seats. Declare an array and give valid nested traversal bounds. Separately, trace a first-match linear search for 5 in [9,5,2,5] and one ascending bubble-sort pass on [9,5,2,5].

S10.03.RS10.04.RS10.05.RS10.06.R
Answer and marking points
  1. DECLARE Occupied : ARRAY[1:3, 1:8] OF BOOLEAN gives 24 elements.
  2. Use an outer row loop from 1 to 3 and an inner seat loop from 1 to 8, accessing Occupied[Row, Seat].
  3. The search returns the first matching index, 2.
  4. One bubble pass gives [5,2,5,9], fixing 9 at the end.

Common error: Do not sort before tracing the stated search; the two operations start from the supplied array.

Command word: Write4 marks

A log must keep previous bookings and add one new STRING BookingLine. Write its file operations, then describe how a later program reads every line safely, including any blank lines.

S10.07.R
Answer and marking points
  1. OPENFILE "Bookings.txt" FOR APPEND preserves the old bookings.
  2. WRITEFILE "Bookings.txt", BookingLine followed by CLOSEFILE saves the new line.
  3. The reader opens FOR READ and checks NOT EOF before each READFILE.
  4. A blank line is processed as an empty string; CLOSEFILE follows the completed loop.

Common error: Do not use WRITE when the task requires retaining previous entries.

Command word: Suggest4 marks

Booking requests arrive A, B, C and must be processed in that order; completed changes must be undoable latest first. Suggest ADTs and state their next removal after all three are stored. Explain how an array-backed linked list inserts a new node after a known node.

S10.08.RS10.09.RS10.10.R
Answer and marking points
  1. An ADT combines data with its specified operations; the waiting-request queue uses FIFO and removes A next.
  2. The undo stack uses LIFO and removes C next.
  3. A linked-list node stores data and the next node's index in array storage.
  4. Allocate a free node, point it to the known node's former successor, then point the known node to it.

Common error: The queue and stack apply different removal rules to different collections.

Command word: Write3 marks

Write the parking algorithm described in this review. Include INTEGER declarations, zero initialisation, input until sentinel 0 and final output. Justify the loop and state the output for 2, 1, 0.

S11.01.RS11.02.RS11.04.RS11.05.R
Answer and marking points

One valid pseudocode solution

FUNCTION Charge(Hours : INTEGER) RETURNS INTEGER
    RETURN Hours * 3
ENDFUNCTION
PROCEDURE AddCharge(BYVAL Amount : INTEGER, BYREF Total : INTEGER)
    Total <- Total + Amount
ENDPROCEDURE
DECLARE Hours, Total : INTEGER
Total <- 0
INPUT Hours
WHILE Hours <> 0
    CALL AddCharge(Charge(Hours), Total)
    INPUT Hours
ENDWHILE
OUTPUT Total
  1. Define Hours and Total, initialise Total to zero and read Hours before the first test.
  2. WHILE Hours <> 0 processes each positive session and obtains the next input; it permits zero sessions.
  3. Add three times each session's hours and output Total after the loop; the given result is 9.

Common error: Process each value before reading the next, and exclude zero as a session.

A club has changing booking requirements and members who can review prototypes weekly. Explain a suitable life cycle. A diagram starts Idle and changes to Booking on begin, then to Idle on cancel. State the states reached after begin, cancel.

A parent calls GetScore, DecideAward and ShowAward. GetScore returns a score to the parent; DecideAward receives it and returns an award label; ShowAward displays the label. Describe the interface directions and a suitable integration test, then identify why a display-library update for a new operating system is needed.

Answer and marking points
  1. Score flows from GetScore to the parent and from the parent to DecideAward.
  2. The award label returns to the parent and is passed into ShowAward.
  3. A known score with an independently expected award checks the connected modules' data and result.
  4. The operating-system change requires adaptive maintenance because an external interface changed.

Command word: Give4 marks

A field accepts integer ages 12–18 inclusive, but 18 is rejected. Give a likely boundary fault and three tests around that upper limit with expected outcomes. Explain how the test plan and test strategy contribute to checking the correction.

S12.04.RS12.06.RS12.07.R
Answer and marking points
  1. A strict upper comparison such as Age < 18 could cause the observed defect and should be checked in the code.
  2. 17 and 18 should be accepted; 19 should be rejected.

  4. The strategy assigns the method, responsibility and sequence for the correction and related regression checks.

Command word: Write4 marks

Write an amended version of the supplied three-day rainfall program to count WetDays for positive rainfall while retaining Total. State the outputs for 0, 2.0, 0.5 and why zero rainfall belongs in the tests.

Use the stated input assumptions and this program.

DECLARE Day : INTEGER
DECLARE Rain : REAL
DECLARE Total : REAL
Total <- 0.0
FOR Day <- 1 TO 3
    INPUT Rain
    Total <- Total + Rain
NEXT Day
OUTPUT Total
S12.09.RS12.07.R
Answer and marking points

DECLARE Day : INTEGER
DECLARE Rain : REAL
DECLARE Total : REAL
DECLARE WetDays : INTEGER
Total <- 0.0
WetDays <- 0
FOR Day <- 1 TO 3
    INPUT Rain
    Total <- Total + Rain
    IF Rain > 0.0 THEN
        WetDays <- WetDays + 1
    ENDIF
NEXT Day
OUTPUT Total
OUTPUT WetDays

  2. Increment it inside IF Rain > 0.0 and output it after Total.
  3. The supplied data give Total 2.5 and WetDays 2.
  4. Zero verifies that a dry day does not enter the new count.

Question 1 · Command word: Explain · 4 marks

A high-level solution says ‘Process all student marks and report the class average’. Explain how stepwise refinement develops this into implementable pseudocode.

Answer and marking points
  • decompose the high-level process into input marks, accumulate a total, calculate the average and output the result.
  • refine each subtask into smaller ordered steps with defined inputs and outputs.
  • continue until each step can be expressed as a declaration, loop, assignment, calculation or output statement.
  • each refined level must preserve the purpose and result of its parent step.

Common error: Do not merely add more prose; every refinement must make the algorithm more precise and closer to implementable operations.

Question 2 · Command word: Describe · 5 marks

A procedure UpdateMark receives StudentID by value and Mark by reference. Describe the procedure definition, call and effect of the two parameter modes.

Answer and marking points
  • the procedure header declares formal parameters for StudentID and Mark with their types and parameter modes.
  • the call supplies matching arguments in the same order as the formal parameters.
  • StudentID passed by value gives the procedure a local copy, so assigning to that parameter does not change the caller’s variable.
  • Mark passed by reference gives access to the caller’s variable, so assigning to Mark changes that variable after the call.
  • the procedure performs an action and is invoked with CALL rather than returning a function value.

Common error: Do not say that both parameters change the caller; only the parameter passed by reference can do so through assignment.

Question 3 · Command word: Explain · 6 marks

An array Name[1:20] is searched for a target, and an array Score[1:20] is sorted into ascending order. Explain the key control and data operations required for a linear search and a bubble sort.

Answer and marking points
  • linear search initialises an index and a Boolean found flag before examining array elements in order.
  • the search stops when the target is found or the index has passed the upper bound.
  • each search comparison tests Name[Index] against the target and records a match before advancing.
  • bubble sort makes repeated passes and compares adjacent values Score[Index] and Score[Index + 1].
  • when the left value is greater, a temporary variable or equivalent safe method swaps the adjacent values.
  • after each pass the unsorted range is reduced, or a no-swap flag is used to stop when the array is sorted.

Common error: Do not access Index + 1 beyond the upper bound, and do not overwrite one value before completing the swap.
