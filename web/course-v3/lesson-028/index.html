01

Why an operating system is needed

S5.01.A01

Visual overview

A request crosses software layers

  1. UserSelects Save in an editor.
  2. ApplicationRequests a named file operation.
  3. Operating systemChecks the request and coordinates storage access.
  4. HardwarePerforms the physical transfer.

Core explanation

An operating system is system software that manages computer resources and provides services for application programs. It also provides a user interface, such as a graphical interface or command-line interface, through which the user can request operations.

An application can request a file operation through the OS instead of implementing its own controller for every storage device. Coordinating requests centrally lets applications share hardware while the OS controls which operations are permitted. Application software still supplies the task-specific behaviour, such as editing a photograph.

Common misconception

An OS supplies common services; it does not replace the application that performs the user's chosen task.

Check your understanding

Would a new printer require every application to implement the printer's control protocol?

Check your answer

Normally no. Applications use common OS services, with a suitable driver handling the printer-specific communication.

Memory management

S5.01.A02

Visual overview

A simplified allocation record

Editor startsRegion A reserved for its working data
Browser startsA separate region B reserved
Editor exitsRegion A becomes available again

Swipe horizontally to compare every column →

Core explanation

Memory management keeps track of allocated and available main memory. When a process starts or needs more working space, the OS allocates memory; when the process finishes, that allocation can be released for reuse.

The OS also controls access to memory so one process cannot freely overwrite another process's instructions or data. Allocation answers where a process can store its working data; protection answers whether an attempted access is permitted. Allocating RAM does not itself save a file permanently.

Common misconception

Memory management allocates working storage; scheduling processor time is process management.

Check your understanding

A process exits. Why can another process reuse its RAM?

Check your answer

The OS releases the terminated process's allocation and records the region as available.

03

File management

S5.01.A03

Visual overview

Opening a saved timetable

  1. Path suppliedThe application requests Classes/Friday.txt.
  2. File locatedDirectory information identifies the stored file.
  3. Access performedIts data is read into an application buffer.
  4. Handle closedThe completed operation releases associated resources.

Core explanation

File management maintains the organisation of files and directories, with information such as names, locations, sizes and ownership. It supports operations including creation, opening, reading, writing, renaming and deletion.

When an application supplies a path, the OS locates the corresponding file and coordinates the requested operation with storage services. File organisation gives programs a consistent way to retrieve data without needing to know the physical position of each stored block.

Common misconception

A filename is a logical identifier, not a physical memory address.

Check your understanding

Which management task maintains a folder's list of filenames?

Check your answer

File management maintains directory information and the association between names and stored files.

Security management

S5.01.A04

Visual overview

AccountReadModify
StudentAllowedDenied
TeacherAllowedAllowed

Swipe horizontally to compare every column →

Core explanation

Security management authenticates users and enforces access rights. Authentication establishes an identity, for example by checking credentials; permissions determine which resources and operations that identity is allowed to use.

An OS can restrict a student to reading a shared document while allowing a teacher to modify it. An authenticated login therefore does not grant unrestricted access. Logging activity and applying security updates can also support protection of the computer system.

Common misconception

A virus checker is a utility. It cannot substitute for checking user identities and enforcing permissions.

Check your understanding

A valid user cannot edit a file. Does that prove their password was rejected?

Check your answer

No. They may be authenticated but lack write permission for that file.

05

Hardware and peripheral management

S5.01.A05

Visual overview

Two documents share a printer

  1. Requests arriveTwo applications submit separate jobs.
  2. QueueThe second job waits while the first is serviced.
  3. Driver and bufferDevice commands and outgoing data are prepared.
  4. CompletionA device notification permits the next transfer.

Core explanation

Hardware management coordinates communication with input, output and peripheral devices. Device drivers translate general OS requests into commands understood by particular devices, allowing applications to use a consistent interface.

Devices and processors operate at different rates. Buffers hold data during transfers, and queues allow requests to wait until a device is available. An interrupt can notify the OS that a device has completed an operation or needs attention; the OS then arranges the appropriate response.

Worked example · A print request is refused

  1. Situation

    A guest tries to print a protected report using an installed printer.

  2. Permission decision

    Security management checks the guest's rights before the report is released.

  3. Device operation

    If authorised, hardware management passes the job through the driver and print queue.

  4. Distinction

    A working printer does not override a denied permission.

Common misconception

A driver controls communication with a device; the device itself performs the physical operation.

Check your understanding

Why might a print job wait even when its application has finished preparing it?

Check your answer

The printer may be occupied by another job; the OS keeps the pending request in a queue.

06

Process management

S5.01.A06

Visual overview

A possible single-core schedule

IntervalCPU activityOther process
1Editor calculates layoutPlayer ready
2Player prepares audioEditor waits for a file read
3Editor resumes after readPlayer waits for its next turn

Swipe horizontally to compare every column →

Core explanation

A process is a program in execution. Process management records process states and schedules which ready process receives processor time. On one CPU core, switching between processes can give the appearance of simultaneous progress.

A process waiting for input or output cannot usefully continue that work. The OS can give processor time to another ready process, then allow the waiting process to continue when its event completes. Information about the interrupted execution must be retained so that each process resumes correctly.

Common misconception

Fast switching on one core is not the same as two instructions from different processes executing at the same instant on that core.

Check your understanding

A process waits for keyboard input. Must the CPU remain idle?

Check your answer

No. Process management can schedule another process that is ready to execute.

Practice questions

Question 1 · Command word: Explain2 marks

Explain two reasons why applications on a shared desktop use services provided by an operating system.

S5.01.A01
Answer and marking points
  1. Applications can request common operations without each implementing control for every supported device.
  2. The OS coordinates competing requests so the applications can share the desktop's resources.

Common error: Explain the service or coordination benefit rather than naming an application.

Question 2 · Command word: Describe3 marks

Describe how memory management responds when a photo editor starts and later exits. Give one reason for protecting its allocated memory.

S5.01.A02
Answer and marking points
  1. It assigns available RAM to the editor's process when working space is needed.
  2. It returns the editor's allocation to the available pool after the process exits.
  3. Protection prevents another process from freely corrupting the editor's working data.

Common error: Distinguish RAM allocation from writing the photo to disk.

Question 3 · Command word: Describe2 marks

Describe two file-management operations involved in creating and later retrieving Notes/Revision.txt.

S5.01.A03
Answer and marking points
  1. Creation records the file's name and its association with storage in the Notes directory.
  2. Retrieval uses that directory information to locate and read Revision.txt.

Common error: Name the file operation and state what the OS does.

Question 4 · Command word: Explain2 marks

Explain how authentication and access rights can allow a pupil to read a class list while preventing the pupil from changing it.

S5.01.A04
Answer and marking points
  1. Authentication verifies which pupil account is making the request.
  2. The account's permissions allow reading but reject writes to the class list.

Common error: Being logged in does not imply write access.

Question 5 · Command word: Describe2 marks

Describe the roles of a device driver and a queue when three users send jobs to one printer.

S5.01.A05
Answer and marking points
  1. The driver supplies commands suitable for that printer model.
  2. The queue retains jobs awaiting their turn while the printer services another job.

Common error: Do not credit the queue with physically printing pages.

Question 6 · Command word: Explain3 marks

Explain why process management can improve CPU use when a running program must wait for a slow disk read.

S5.01.A06
Answer and marking points
  1. The waiting program cannot continue the dependent operation until the read finishes.
  2. The OS can schedule a different ready process during that wait.
  3. The waiting process can be resumed from its saved execution state when the read completes.

Common error: This concerns allocation of CPU time, not allocation of RAM.

Question 1 · Command word: Describe · 4 marks

Describe how process management allows a music player and a spreadsheet to make progress on one CPU core. Explain why this does not mean both execute an instruction at the same instant on that core.

Answer and marking points
  • The scheduler selects one ready process to execute on the core.
  • It can transfer control between the player and spreadsheet over successive intervals.
  • Each process's execution information is preserved so work can continue when it is selected again.
  • Only the selected process executes on that core at an instant; the apparent concurrency comes from switching.

Common error: Answer in terms of scheduling and execution state, not memory capacity.

Question 2 · Command word: Explain · 4 marks

Explain why each of these OS restrictions is useful: a program cannot write into another program's working memory; a logged-in visitor cannot delete the administrator's documents. Identify the management task for each.

Answer and marking points
  • Memory management enforces the first restriction on another process's allocated address space.
  • It limits damage caused by a faulty or misbehaving program overwriting unrelated working data.
  • Security management checks the visitor's rights for the document deletion.
  • The restriction protects the documents even though the visitor has authenticated successfully.

Common error: Keep memory protection and file-access permission distinct.

Question 3 · Command word: Describe · 4 marks

Describe the separate roles of file management and hardware management when a saved invoice is read from disk and sent to a printer.

Answer and marking points
  • File management resolves the invoice's path to the stored file.
  • It coordinates opening and reading the invoice's recorded data.
  • Hardware management uses the appropriate storage and printer drivers to communicate with those devices.
  • It arranges buffering or queued transfers when the printer cannot accept all the data immediately.

Common error: A valid answer follows the invoice through file services and device services.

Summary

OS purpose

Applications request shared services; the OS coordinates and controls access to resources.

Memory and files

Allocate and protect working RAM; organise and operate on persistent files.

Security and hardware

Check identity and rights; communicate with devices through drivers and managed transfers.

Processes

Schedule ready work and preserve execution state when switching processes.
