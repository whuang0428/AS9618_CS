System software · Concept 01

Who connects the application to the computer?

Observe

Start with a question

When you select Print in a document editor, what makes the separate printer respond?

Look at the computer and printer. The editor lets a student change words on a page. The printer makes marks on paper. Something must carry the request between them and coordinate access when another application also wants to print.

Recall

Use what you already know

Hardware, software and resources

Hardware is the physical equipment. Software is the instructions that run on it. A resource is something programs need to use, such as processor time, working memory, storage or a printer.

Explain

Explanation · 1 / 4

Separate the user task from the shared work

An application is software for a user task: a document editor arranges text, while a music player chooses and plays a track. Both need common operations such as opening files and using devices. Requiring every application to control every device separately would duplicate this work.

Explanation · 2 / 4

Put shared services in the operating system

An operating system, or OS, is system software that manages computer resources and provides services to applications. The editor requests a file or print operation. The OS checks and coordinates that request, then communicates with the relevant hardware. The OS also provides a user interface, such as windows and menus or a command line.

Explanation · 3 / 4

Follow one request through the layers

Selecting Save is an application action. The requested file must be located or created, access must be permitted, and data must reach storage. The OS supplies these common services. The application still decides which document content to save.

LayerAction when Save is selected
UserChooses to save the edited document
ApplicationSupplies the document data and requested file
Operating systemChecks access and coordinates the file and device operation
Storage hardwareRecords the data

Explanation · 4 / 4

Share a computer without losing control

Several applications may request the same resource. The OS coordinates their requests and controls permitted access. For example, one printer can service a waiting sequence of jobs, while a protected file can reject a write from an account without permission. Managing the request is different from creating the document content.

Work together

Two editors, one printer

An editor and a browser each submit a page to the same printer.

Work together · 1 / 2

Identify the shared need

Both applications need an output device. They submit requests using common services instead of each taking unrestricted control of the printer.

Work together · 2 / 2

Explain the benefit

The OS coordinates the jobs so the device can service them in an organised order. Each application can concentrate on preparing its own page.

An operating system provides common services and coordinates access to shared resources.

Connect

Keep this idea

An OS manages resources, provides a user interface and supplies services used by applications.

Opening the editor creates running work that needs somewhere to keep its instructions and changing data.

Give running programs working space

Start with a question

Where can the editor keep a sentence while the student is still changing it?

Imagine a small RAM map with eight equal teaching units. Process A uses three units, process B uses three, and two remain available. A new process requests two units. Follow which units are occupied, released and protected.

Recall

Use what you already know

RAM, storage and a process

RAM is the working memory used during execution; it normally loses its contents when power is removed. Storage retains saved files. A program is a set of instructions; a process is a program in execution, with its current working state.

Explain

Explanation · 1 / 3

Record allocated and available memory

Memory management keeps track of which parts of main memory are in use and which are available. The OS allocates working space when a process starts or needs more memory. In this simplified map, the new process can receive the two available units.

Point in the exampleABNew processAvailable
Before allocation3 units3 units0 units2 units
After allocating 2 units3 units3 units2 units0 units
After A finishes0 units3 units2 units3 units

Explanation · 2 / 3

Protect one process from another

Different processes can occupy RAM at the same time. Memory protection restricts access to their allocated areas so that one process cannot freely overwrite another process’s instructions or data. The issue is which memory a process may access, even if both processes belong to the same user.

Explanation · 3 / 3

Release space when work finishes

When a process ends, the OS can release its allocation and record that memory as available for reuse. This lets another process use the space later. Releasing RAM does not create a saved file: a document needs a separate save operation before its working changes can be relied on after shutdown.

Work together

Explain a blocked memory write

The editor and music player both have RAM allocated. A fault in the editor tries to overwrite the player’s working data.

Work together · 1 / 2

Identify the resource and rule

The attempted access concerns another process’s main-memory allocation. Memory protection restricts that write.

Work together · 2 / 2

State why the rule helps

Preventing the overwrite limits damage to the other process. It does not require the music player to stop using its own memory.

Memory management allocates, protects and releases working memory.

Check

Explain it yourself · Teacher-written

After closing the editor, three units of RAM become available. Does that prove the latest document edits were saved?

Check your reasoning

No. The OS released the process’s working memory. Saving a persistent file is a separate operation, and unsaved changes can be lost.

Connect

Keep this idea

Track available memory, allocate space to processes, protect their allocations and release space for reuse.

The saved document needs a name, a storage location and rules about who may read or change it.

Check a common misunderstanding

Allocating RAM is not scheduling processor time or saving a file to storage.

System software · Concept 03

Locate the document and check the requested access

Observe

Authenticated accountRead Classes/Friday.txtReplace Classes/Friday.txt
StudentAllowedDenied
TeacherAllowedAllowed

Start with a question

Why can a student open Classes/Friday.txt but be refused permission to replace it?

A teacher owns a shared timetable. Both the teacher and student have successfully signed in. The student may read it; the teacher may read and change it. Follow an Open request and then a Save request from the student.

Explain

Explanation · 1 / 4

Use a name and directory to find a file

A file is named data stored for later use. A directory, often shown as a folder, organises entries for files and other directories. The path Classes/Friday.txt identifies Friday.txt inside Classes. File management maintains information such as names, locations, sizes and ownership and supports create, open, read, write, rename and delete operations.

Explanation · 2 / 4

Connect the logical name to stored data

An application can supply the path without knowing the physical position of each block on a storage device. The OS uses directory and file-system information to locate the file and coordinate the requested operation. Reading brings data into working memory; writing records supplied data in storage.

Explanation · 3 / 4

Establish the account’s identity

Authentication checks who is requesting access, for example by checking login credentials. Successful authentication identifies the account. It does not decide that every operation is allowed. The next decision depends on the resource and the account’s access rights.

Explanation · 4 / 4

Enforce the allowed operations

Permissions specify what an account may do. In this example the OS allows the student to read the timetable but rejects the student’s write request. The teacher has both rights. Security management enforces these rules; activity logging and security updates can also support system protection.

Authenticated accountRead Classes/Friday.txtReplace Classes/Friday.txt
StudentAllowedDenied
TeacherAllowedAllowed

Work together

Open succeeds; Save is denied

The student edits a copy of the timetable in RAM and tries to save it over the shared file.

Work together · 1 / 2

Locate the destination

File management resolves Classes/Friday.txt to the existing stored file.

Work together · 2 / 2

Check the operation

Security management checks the student’s write permission. It is denied, so the shared file remains unchanged. Successful login did not grant write access.

File management organises the file; security management controls whether this account may perform this operation.

Check

Explain it yourself · Teacher-written

Does a denied write prove that the filename is wrong or the password was rejected?

Check your reasoning

No. The file can exist and the student can be authenticated while the required write permission is absent.

Connect

Keep this idea

File management organises files and their operations. Security management authenticates users and enforces access rights.

Once a print request is allowed, the OS still has to communicate with the physical printer.

Check a common misunderstanding

A filename is not a RAM address. Being logged in does not mean having unrestricted access.

Learning goals
  • Explain operating-system file management.
  • Explain operating-system security management.

System software · Concept 04

Let different devices work at their own speed

Start with a question

The editor has prepared two pages, but the printer is still making the first. Where does the waiting work go?

Three applications submit jobs to one printer. The computer can prepare data much faster than paper moves through the printer. Separate the job waiting for its turn, the data being transferred and the commands understood by this printer model.

Explain

Explanation · 1 / 4

Use a driver for device-specific communication

A device driver is software that lets the OS communicate with a particular device. It turns general requests into the commands that the device understands and handles device responses. Applications can use a consistent OS interface while a suitable driver handles the printer-specific details.

Explanation · 2 / 4

Keep jobs waiting in a queue

A queue holds work awaiting service. If the printer is busy, later print jobs wait rather than all sending their pages at once. The job currently being serviced can finish before the next one starts. The queue organises waiting requests; it does not physically print pages.

Explanation · 3 / 4

Buffer data during a transfer

A buffer is an area of memory holding data temporarily while it is transferred. It helps equipment operating at different rates exchange data. A queue records waiting work, whereas a buffer holds data for a transfer. A print system may use both, and neither performs the driver’s device-specific translation.

Explanation · 4 / 4

Respond when the device needs attention

A device can use an interrupt, a signal requesting processor attention, to report completion or a condition that needs service. The OS arranges the appropriate response. Hardware management therefore includes coordinating requests, drivers and transfers, not simply detecting that the printer is connected.

System software · Concept 05

Share processor time while a program waits

Start with a question

When the editor waits for a file read, can the music player use the processor?

Use a single CPU core. Process A is the editor and process B is the music player. A starts running, then needs data from a slow device before it can continue. B already has work ready to execute.

Recall

Use what you already know

Processor time is different from RAM space

The CPU carries out instructions. A core is an execution unit within a processor. RAM holds the instructions and working data. Two processes can have RAM allocated while only one of them is selected to execute on this single-core teaching model.

Explain

Explanation · 1 / 4

Distinguish running, ready and waiting

A running process currently has processor time. A ready process can run when selected. A waiting process needs an event, such as completed input, before it can continue its dependent work. Keeping these states lets the OS distinguish useful work from work that cannot progress yet.

Explanation · 2 / 4

Schedule another ready process

Process management schedules which ready process receives processor time. When A waits for input/output, the OS can select B instead of leaving the core idle. Switching between processes over successive intervals can make several applications appear to progress together.

Explanation · 3 / 4

Preserve enough state to resume

Before switching away from a process, the system preserves the execution information needed to resume correctly, such as its current instruction position and working register values. When A’s input completes, A becomes ready again and can later resume. It does not have to restart the document-editing task from the beginning.

EventA: editorB: playerSelected work
Initial stateRunningReadyA
A requests slow inputWaitingRunningB
A’s input completesReady to be scheduledMay still be runningScheduler selects ready work

Explanation · 4 / 4

Explain multitasking precisely

On this single-core model, selected processes take turns. The appearance of simultaneous progress comes from switching; it does not mean two instructions from different processes execute at the same instant on the same core. Memory management keeps their working data available and protected; process management allocates processor time.

Work together

Combine memory and process management

The editor and player remain open while the editor waits for a file read.

Work together · 1 / 2

Account for their data

Memory management retains separate allocations and protects them so one process cannot freely overwrite the other’s data.

Work together · 2 / 2

Account for progress

Process management gives the core to a ready process, preserves execution state when switching and later schedules the editor when it can continue.

A complete explanation of multitasking can identify both the memory arrangements and the allocation of processor time.

Original question · Cambridge 9618/12

1. Link two OS management tasks to multitasking

Cambridge 9618/12 · May/June 2024 · 6 · 4 marks

Selected parts: 6 [4].

Hint — reading the question

Explain both memory management and process management in terms of multiple active programs. Avoid spending the whole answer on just one task.

Reasoning and model answer — teacher-written

Memory management keeps data for the active programs in RAM and protects their allocated areas so that one program does not overwrite another’s data.

Process management schedules which process runs next, pauses one when necessary and switches the processor to another. This lets processes share processor time and make progress.

Official mark scheme
Why this earns marks — teacher explanation

The total is four marks, with no more than three from either management task. This model supplies two memory points and two process points. The official list contains alternatives; listing every alternative still cannot exceed four.

Common mistakes — teacher analysis

Giving four memory facts cannot bypass the three-mark memory cap. Multitasking does not mean that one processor core executes every process simultaneously.

Question 1 · Command word: Describe3 teacher marks

Describe how memory management responds when a photo editor starts and later exits. Give one reason for protecting its allocated memory.

S5.01.A02
Answer and checking points — teacher-written
  1. It assigns available RAM to the editor's process when working space is needed.
  2. It returns the editor's allocation to the available pool after the process exits.
  3. Protection prevents another process from freely corrupting the editor's working data.

Common error: Distinguish RAM allocation from writing the photo to disk.

Question 2 · Command word: Describe4 teacher marks

An authorised application creates Notes/Revision.txt, writes Binary revision, closes it, reopens it for reading, reads and closes it. Describe what file management records and does, then state the saved contents and read-buffer contents. Explain what changes if it instead requests a read of missing Notes/Absent.txt.

S5.01.A03
Answer and checking points — teacher-written
  1. Creation records the filename in the directory and the information used to locate its contents.
  2. File services coordinate opening, writing and reading, and release open-file resources on close.
  3. The saved file and the read buffer both contain Binary revision after the successful sequence.
  4. The missing path produces a failure to locate/open that file, not a successful read of Revision.txt or invented file contents.

Common error: An open-file reference and a read buffer are not the persistent file itself.

Explain how authentication and access rights can allow a pupil to read a class list while preventing the pupil from changing it.

S5.01.A04
Answer and checking points — teacher-written
  1. Authentication verifies which pupil account is making the request.
  2. The account's permissions allow reading but reject writes to the class list.

Question 4 · Command word: Describe2 teacher marks

Describe the roles of a device driver and a queue when three users send jobs to one printer.

S5.01.A05
Answer and checking points — teacher-written
  1. The driver supplies commands suitable for that printer model.
  2. The queue retains jobs awaiting their turn while the printer services another job.

Common error: Do not credit the queue with physically printing pages.

Question 5 · Command word: Explain3 teacher marks

Explain why process management can improve CPU use when a running program must wait for a slow disk read.

S5.01.A06
Answer and checking points — teacher-written
  1. The waiting program cannot continue the dependent operation until the read finishes.
  2. The OS can schedule a different ready process during that wait.
  3. The waiting process can be resumed from its saved execution state when the read completes.

Common error: This concerns allocation of CPU time, not allocation of RAM.

Question 6 · Command word: Explain4 teacher marks

An editor and an audio player share one CPU core. A signed-in reader tries to overwrite a read-only report, while the editor waits for a permitted disk read and a printer is busy with another job. Explain the value of common OS services and identify the different decisions for the denied write, CPU allocation and pending print job.

S5.01.A01S5.01.A04S5.01.A05S5.01.A06
Answer and checking points — teacher-written
  1. Applications can request common services without each implementing every device protocol, while the OS coordinates access.
  2. Security management rejects the overwrite because authentication does not grant write permission.
  3. Process management can select the ready audio player while the editor waits for its required input.
  4. Hardware/peripheral management keeps the print job queued until the device is available, with an appropriate driver providing its commands.

Question 7 · Command word: Explain2 teacher marks

Explain two reasons why applications on a shared desktop use services provided by an operating system.

S5.01.A01
Answer and checking points — teacher-written
  1. Applications can request common operations without each implementing control for every supported device.
  2. The OS coordinates competing requests so the applications can share the desktop's resources.
