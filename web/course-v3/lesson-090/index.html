01

Distinguish ordinary, invalid and extreme values

S12.07.A01S12.07.A02

Visual overview

Use the rule to determine validity

Normal data are valid examples representative of ordinary use. Abnormal data violate the supplied type, format or range rule and require the specified rejection or error response. Valid extremes are the accepted endpoints. Boundary testing examines a limit and useful neighbouring positions; always state whether each chosen value is valid.

Separate a category from a test’s purpose

For integer marks from 0 to 100 inclusive, 55 is an ordinary valid value; 0 and 100 are accepted extremes; -1 and 101 are invalid neighbours. The syllabus groups extreme/boundary terminology: do not turn the labels into a rigid rule that an out-of-range neighbour cannot serve a boundary test. Its validity and testing purpose are different properties.

Keep input type and range checks distinct

A raw input field could receive the text fifty, which fails its integer-input rule. A variable already declared INTEGER cannot itself hold that string. Testing the raw interface’s parsing and testing the range of an already typed value are different tasks. State which interface is being tested before choosing an abnormal example.

Core explanation · Exam essentials

  • Choose normal, abnormal and extreme/boundary cases from the stated type, format and limits.
  • State expected behaviour for every case; boundary position does not by itself determine validity.
Common misconception

Data categories do not determine a result by themselves; the stated input rule determines validity.

Check your understanding

Why can 101 be described as both abnormal and a boundary check?

Check your answer

It is invalid under the range rule and specifically tests the position just beyond the upper limit.

Explain why each case is useful

Select cases because they distinguish plausible mistakes. Values 1 and 30 distinguish inclusive limits from strict comparisons; 0 and 31 check rejection immediately outside; 2 and 29 show that near-endpoint interior values are not accidentally excluded. Some faults are exposed by more than one test, so justify the set rather than adding many interchangeable middle values.

Use data of the requested type

For a username, supply actual strings and count characters. abcde has length 5, abcdef has length 6, abcdefghijkl has length 12 and abcdefghijklm has length 13. A valid length does not establish that every character satisfies a separate character rule. Keep each restriction visible when choosing a test.

Respect precision and output requirements

At one decimal place, -5.1, -5.0 and -4.9 are meaningful neighbouring inputs around -5.0. Without a stated input precision, there is no general “next real number” obtained by adding 1 or 0.1. Use the precision and comparison rules actually supplied. Expected results must include computed outputs when the requirement specifies a calculation, not only Accepted or Rejected.

Worked example · A one-decimal temperature input

  1. Rule

    Accept temperatures from -5.0 to 30.0 inclusive, entered to one decimal place.

  2. Lower limit

    -5.1 is rejected; -5.0 and -4.9 are accepted.

  3. Upper limit

    29.9 and 30.0 are accepted; 30.1 is rejected.

  4. Reason

    These values distinguish incorrect strict comparisons and misplaced endpoints.

Core explanation · Exam essentials

  • Use limits, nearby values and distinct invalid cases to challenge plausible faults.
  • Supply actual inputs, their expected outputs and a reason for choosing each case.
Common misconception

Test values immediately beside a boundary depend on the stated type and precision.

Check your understanding

Why is 6.0 not enough to test the lower length boundary of a username?

Check your answer

The input is a string. Supply a six-character string and state that it should be accepted.

Question 1 · Command word: Give2 teacher marks

Give one normal integer mark and the valid extreme marks for the inclusive range 0 to 100. State their expected results.

Answer and checking points — teacher-written
  1. An ordinary valid example is 55, expected Accepted.
  2. The extreme values are 0 and 100, both expected Accepted.

Common error: Do not use an out-of-range value as a valid extreme.

Question 2 · Command word: Give2 teacher marks

Give abnormal inputs that test the range and the type checks of an integer mark field from 0 to 100, and state the expected responses.

S12.07.A01S12.07.A02
Answer and checking points — teacher-written
  1. 101 is outside the permitted range and should be rejected.
  2. The text "fifty" does not represent an integer and should be rejected at input validation.

Common error: Assume the field accepts raw input for validation; a typed INTEGER variable cannot itself store arbitrary text.

Question 3 · Command word: Write2 teacher marks

Write four username test strings to check just below, on, on and just above the limits of 6 to 12 characters. State the expected results in that order.

S12.07.A01S12.07.A02
Answer and checking points — teacher-written
  1. abcde has length 5 and is rejected; abcdef has length 6 and is accepted.
  2. abcdefghijkl has length 12 and is accepted; abcdefghijklm has length 13 and is rejected.

Common error: Count the supplied characters rather than merely labelling the tests.

Question 4 · Command word: Explain3 teacher marks

For the same inclusive 1–30 rule, a tester proposes only 10, 15 and 20. Explain the weakness, select data that expose erroneous > 1 and < 30 comparisons, and give a just-inside value that checks whether only endpoints are accepted.

S12.07.A01S12.07.A02
Answer and checking points — teacher-written
  1. The three interior values do not distinguish correct inclusive comparisons from either strict-limit fault.
  2. 1 and 30 must be accepted; they expose > 1 and < 30 respectively.
  3. 2 or 29 must also be accepted and challenges an implementation that accepts only the endpoints.

Common error: Select a case because it makes a plausible wrong implementation behave differently.

Explain why testing only mark 55 cannot distinguish the correct range check from one that rejects 0 and 100. Give the additional tests that reveal that particular defect.

S12.07.A01
Answer and checking points — teacher-written
  1. 55 is accepted by both checks, so the results agree for the single interior case.
  2. Inputs 0 and 100 should be accepted and expose a check that incorrectly excludes either endpoint.

1. Design distinct valid test sequences

Cambridge 9618/22 · October/November 2023 · 4(b) · 3 marks

Selected parts: 4(b) [3].

Reading the question — teacher guidance

Every sequence must satisfy the positive-integer input requirement and end with 99. Test different behaviours instead of submitting three mixed lists like the example.

Solution / model answer — teacher-written

Official mark scheme
Why this earns marks — teacher explanation

The official rule is one mark per set including its stated purpose, to three. Although the scheme lists a missing-99 sequence as another example, the question asks for valid data. These three teacher sequences satisfy the written restriction and the listed scoring examples without that conflict.

Common mistakes — teacher analysis

Counting 99 as an odd value gives every result an extra odd count. Three differently numbered mixed lists may test the same behaviour rather than three distinct aspects.
