Core explanation

Normal data are valid values within the accepted range. Abnormal data are invalid and should be rejected. Extreme or boundary data are valid values at the limits of the accepted range; values immediately outside a limit are abnormal boundary checks.

Choose test data from the stated validation rule and give an expected result for each value. A label such as 'boundary' is insufficient unless the value really tests a stated limit.

Extreme/boundary data uses valid values at the accepted lower or upper limit. For an accepted mark range of 0 to 100 inclusive, 0 and 100 are valid extreme/boundary values.

Common misconception

Boundary data is at or immediately beside a valid limit; abnormal data is invalid because of its type, format or permitted range. The categories are not identical.

Question 2 · Command word: Explain · 4 marks

Explain a mark must be an integer from 0 to 100 inclusive. Select normal, abnormal and boundary test data and explain the purpose of each selection.

Marking points

  • A normal value such as 55 is valid and not close to a boundary, checking ordinary accepted input.
  • An abnormal value such as -1 or 101 is outside the valid range and should be rejected.
  • Boundary tests use 0 and 100, together with values immediately outside such as -1 and 101, to check both inclusive limits.
  • Expected results must state whether each value is accepted or rejected so the actual result can be compared with it.

Question 3 · Command word: Explain · 4 marks

A username must contain between 6 and 12 characters inclusive. Explain a complete set of boundary tests and expected outcomes.

Marking points

  • A length of 5 is immediately below the lower boundary and should be rejected.
  • Lengths of 6 and 12 are the valid lower and upper boundary values and should be accepted.
  • A length of 13 is immediately above the upper boundary and should be rejected.
  • Testing values on and immediately outside both limits detects incorrect <, <=, > or >= boundary conditions.
