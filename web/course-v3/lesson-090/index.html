Look, then discuss

Why are 3, 6 and 7 useful for different reasons?

Predict each decision first. Then test the exact upper limit against an implementation using < instead of <=. Explain why an ordinary accepted value might miss the mistake.

Recall

Recall inclusive limits

Inclusive means the endpoint is allowed. For an INTEGER range, the nearest integer below 1 is 0 and the nearest above 6 is 7. Available does not decrease in this independent-request model.

Explain

Explanation · 1 / 4

Choose an ordinary valid value

Normal data represents typical permitted input, such as Seats 3. It should be accepted. It establishes an ordinary working path but may not challenge a limit.

Explanation · 2 / 4

Choose invalid values with stated expectations

Abnormal data violates the requirement. For this integer input contract, 0 and 7 are outside the permitted range and should be rejected. Text and fractional values are separate type-validation cases only when the stated input source can supply them.

Explanation · 3 / 4

Test the boundaries and their neighbours

Extreme valid values are the minimum and maximum permitted values, here 1 and 6. Boundary testing also considers values immediately around the decision boundaries, such as 0, 1, 2 and 5, 6, 7. State the actual value and expected result so different naming conventions do not obscure the test.

Explanation · 4 / 4

Use the type and precision in the requirement

For strings, a length limit concerns the number of characters, not the numeric value of the text. For real values, the useful neighbouring inputs depend on stated precision. With one decimal place, -5.1, -5.0 and -4.9 can challenge -5.0; there is no universal next real value found by adding 1.

Develop a booking system · Concept 18

Test distinct behaviours with complete sequences

Observe

A booking-total routine with a stop value

  • Read positive seat quantities and stop at sentinel 99.
  • 99 marks the end; it is not a booking quantity and must not enter the total.
  • For this separate routine, all data values before 99 are positive integers. The 1–6 validation rule is not part of this input contract.

Look, then discuss

Which cases distinguish no work, one update and several updates?

Predict the final total for 99; for 3, 99; and for 3, 2, 4, 99. Keep the sentinel outside the calculation.

Recall

Recall a sentinel and loop placement

A sentinel is a special value that signals termination. A pre-condition loop can skip its body entirely when the first input is the sentinel. Initialising the total before the loop preserves a correct zero result for that path.

  • Review pre-condition loops and sentinel inputs

Explain

Explanation · 1 / 4

Select behaviours rather than decorative variations

99 alone tests immediate termination and a zero total. 3, 99 tests one update. 3, 2, 4, 99 tests repeated accumulation. Three lists with different numbers can still test the same behaviour if their structure is identical.

Explanation · 2 / 4

Challenge relationships between outputs

For a routine counting odd and even data, use an all-odd sequence to check the even count stays zero, an all-even sequence to check the odd count stays zero, and an immediate sentinel to check both start at zero. Choose according to the outputs actually required.

Explanation · 3 / 4

Keep every proposed sequence valid for the task

If asked for valid sequences, obey the stated type, sign and terminating sentinel. Do not insert an invalid value just because abnormal testing exists elsewhere. Include each sequence’s purpose and independently predicted output when useful.

Explanation · 4 / 4

Connect the case to a plausible fault

Several data items can reveal an accumulator reset inside a loop. An immediate sentinel can reveal processing before the termination check. A sequence containing only one category can expose an unintended update to the other category.

Work together

Prepare for the odd/even counting task

The original paper asks for distinct valid positive-integer sequences ending in 99. The sentinel is excluded from both counts.

Work together · 1 / 2

Calculate from data before the sentinel

A sequence 7, 9, 99 contains two odd data items and no even data. 99 is itself odd but is a terminator, so the expected counts are 2 and 0.

Work together · 2 / 2

Choose a different behaviour next

Use an all-even sequence or immediate sentinel rather than another mixed list resembling the supplied example. Explain the specific behaviour each proposed sequence tests.

The purpose of a sequence should explain why its arrangement may expose a different fault.

1. Design distinct valid test sequences

Cambridge 9618/22 · October/November 2023 · 4(b) · 3 marks

Selected parts: 4(b) [3].

Hint — reading the question

Every sequence must satisfy the positive-integer input requirement and end with 99. Test different behaviours instead of submitting three mixed lists like the example.

Official mark scheme
Why this earns marks — teacher explanation

The official rule is one mark per set including its stated purpose, to three. Although the scheme lists a missing-99 sequence as another example, the question asks for valid data. These three teacher sequences satisfy the written restriction and the listed scoring examples without that conflict.

Common mistakes — teacher analysis

Counting 99 as an odd value gives every result an extra odd count. Three differently numbered mixed lists may test the same behaviour rather than three distinct aspects.

Question 4 · Command word: Explain3 teacher marks

For the same inclusive 1–30 rule, a tester proposes only 10, 15 and 20. Explain the weakness, select data that expose erroneous > 1 and < 30 comparisons, and give a just-inside value that checks whether only endpoints are accepted.

S12.07.A01S12.07.A02
Answer and checking points — teacher-written
  1. The three interior values do not distinguish correct inclusive comparisons from either strict-limit fault.
  2. 1 and 30 must be accepted; they expose > 1 and < 30 respectively.
  3. 2 or 29 must also be accepted and challenges an implementation that accepts only the endpoints.

Common error: Select a case because it makes a plausible wrong implementation behave differently.

Question 5 · Command word: Explain2 teacher marks

Explain why testing only mark 55 cannot distinguish the correct range check from one that rejects 0 and 100. Give the additional tests that reveal that particular defect.

S12.07.A01
Answer and checking points — teacher-written
  1. 55 is accepted by both checks, so the results agree for the single interior case.
  2. Inputs 0 and 100 should be accepted and expose a check that incorrectly excludes either endpoint.

Common error: Use data that make the competing conditions behave differently.
