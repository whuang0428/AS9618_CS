Look, then discuss

Must the next activity in a programme occupy the next array index?

Three activity nodes are stored at indices 3, 0 and 2. Head = 3; links lead 3 → 0 → 2 → -1. The programme order follows those links rather than the numerical index order.

Recall

Recall an array index as a stored value

A pointer in this array representation stores the index of another node. It is different from the data stored in that node. Here -1 is the null link: it means there is no next node.

Explain

Explanation · 1 / 3

Identify the parts of a node

A node contains a data item and a link to the next node. In an array implementation, parallel Data and Next arrays can store these parts at the same index. A record array is another possible representation.

Explanation · 2 / 3

Follow Head, then each link

Head identifies the first node. Read its data, then obtain the next node’s index from its link. Stop on the null link instead of treating null as an array position.

Explanation · 3 / 3

Connect the representation to a use

A linked list is useful when a sequence needs insertion or deletion between known neighbours without shifting every later data item. Finding an unknown position may still require following links from the head; links do not make every search immediate.

Work together

Read the programme in logical order

Use Head = 3 and the node table above.

Work together · 1 / 2

Follow the first two nodes

Visit index 3: Welcome. Its Next value is 0, so visit index 0: Workshop. Its Next value is 2.

Work together · 2 / 2

Stop at the end

Visit index 2: Questions. Next is -1, so stop. The logical sequence is Welcome, Workshop, Questions despite storage indices 3, 0, 2.

The links define the sequence; the array positions only locate its nodes.

Check

Try it yourself · Teacher-written

If Data[1] contains an old title but no active link reaches index 1, is it necessarily part of the list?

Check your reasoning

No. Membership depends on the active chain reachable from Head. An unreferenced cell can be inactive or part of a separate free list.

Connect

Keep this idea

A linked list consists of nodes with data and links; follow Head and the links until null.

An insertion must connect the new node without losing the old successor.

Insert, edit or remove a node between neighbours

Look, then discuss

How can Break be placed between Workshop and Questions without moving their data cells?

The active chain is Welcome at 3 → Workshop at 0 → Questions at 2 → null. A new node at index 1 is available for Break. Preserve a route to Questions while changing the links.

Recall

Recall saving a value before overwriting it

As with a swap, an old link may be needed after an update. Read or retain the old successor before replacing the link that points to it.

Explain

Explanation · 1 / 3

Insert after a known predecessor

Store Break in the new node. Set its Next to the old successor of Workshop, index 2. Then change Workshop’s Next from 2 to 1. The resulting chain passes through the new node and still reaches Questions.

Explanation · 2 / 3

Edit data without changing the chain

To rename Workshop, locate its active node and replace its Data value. Leave its Next link and Head unchanged when the list order should remain the same.

Explanation · 3 / 3

Bypass a node when deleting it

To delete the new Break node, set Workshop’s Next to Break’s successor, 2. Break is no longer reachable from Head. Its physical slot must later be marked available for reuse; removing it from the active chain is only one part of managing storage.

Work together

Preserve the successor during insertion

Before insertion, Next[0] = 2 and node 1 is available.

Work together · 1 / 2

Connect the new node forward

Set Data[1] to Break and Next[1] to 2. At this moment, the old active chain still works because Next[0] has not yet changed.

Work together · 2 / 2

Connect the predecessor to the new node

Set Next[0] to 1. The active indices are now 3 → 0 → 1 → 2 → -1. No other data value needed to shift.

Set the new node’s successor before replacing the predecessor’s old successor link.

Follow links, not neighbouring array slots

Check
Try it yourself · Teacher-written
What can go wrong if the predecessor is pointed at the new node before its old successor is retained?
Check your reasoning
The only stored route to the old successor may be overwritten. The insertion can lose the rest of the active chain or accidentally create a self-link. Retain the successor before replacing the old link.

    
    
Connect
Keep this idea
Insertion links a new node between neighbours; deletion bypasses it; a data edit need not change links.
The first node has no predecessor, so operations at the head need a separate case.

Build a booking system · Concept 37
Handle the first node, the last node and an empty list

    
Observe
A list with one remaining node
  • Head = 2
  • Data[2] = Questions
  • Next[2] = -1
  • Requested operation: remove the first node.
Look, then discuss
Which pointer must change when the first activity is removed?
Head identifies Welcome. No earlier node points to Welcome, so there is no predecessor link to update. The external Head pointer must take the role of that link.

    
Recall
Recall the null-link convention
Here Head = -1 means an empty list, and Next = -1 marks the final node. These values describe absence; they must not be dereferenced as valid indices.

    
Explain
Explanation · 1 / 3
Insert at the head
Point the new node’s Next at the old Head, then set Head to the new node. For an empty list, the old Head is null, so the new node becomes both the first and final node.
Explanation · 2 / 3
Delete at the head
Retain the old head node’s index, then set Head to that node’s Next. If it was the only node, Head becomes null and the list is empty. The removed node can then be returned to available storage.
Explanation · 3 / 3
Handle the final node
To append after a known final node, the new node’s Next must be null and the old final node must point to it. To delete a final node with a predecessor, set the predecessor’s Next to null.

    
Work together
Remove the only remaining node
Head = 2, Data[2] = Questions and Next[2] = -1.
Work together · 1 / 2
Update the external pointer
Save the removed index 2, then set Head to Next[2], which is -1. The active list is now empty.
Work together · 2 / 2
Check the next attempted removal
Head is null, so reject another removal before reading Data[Head]. The old text in cell 2 does not make an active item remain.
Head operations update the external start pointer; end operations preserve a null final link.

    
    
Check
Try it yourself · Teacher-written
An empty list receives its first node at index 4. What must Head and Next[4] become?
Check your reasoning
Set Next[4] to the old null Head, -1, then set Head to 4. The single node is both first and last.

    
    
Connect
Keep this idea
Treat head, tail and empty cases explicitly so every active chain remains reachable and terminates.
A fixed array also needs a reliable record of which node slots are free.

Question 1 · Command word: State2 teacher marks
Head = 3. Data[1] = B, Next[1] = 0; Data[2] = unused; Data[3] = A, Next[3] = 1. State the traversal order and explain why slot 2 is ignored.
S10.09.A03
Answer and checking points — teacher-written
  1. Traversal visits indices 3 then 1, producing A then B.
  2. Slot 2 is not reachable by following the active links from Head.
Common error: Do not traverse in increasing physical index order.
Question 2 · Command word: State3 teacher marks
In the lesson's starting diagram, insert X at free slot 3 after A. State the data assignment and both link changes, in a safe order.
S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Store X in Data[3].
  2. Set Next[3] to 4, A's original successor.
  3. Set Next[2] to 3, making the new node reachable after A.
Common error: Preserve the original successor before overwriting its link.
Question 3 · Command word: Describe3 teacher marks
Using the starting diagram, describe editing C to Z and then deleting head A. State the final head and data order.
S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Change Data[1] to Z without changing Next[1].
  2. Set Head to Next[2] = 4 and release slot 2.
  3. The remaining list traverses B then Z.
Common error: An edit changes a value; deletion changes reachability.
Question 4 · Command word: Give3 teacher marks
A list consists only of node 2 containing P with Head = 2 and Next[2] = 0. Delete it, then reuse slot 2 for Q in the empty list. Give the head and link changes at both stages.
S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Deletion sets Head to 0 and releases slot 2.
  2. Insertion stores Q at 2, sets Next[2] to 0 and Head to 2.
  3. The final traversal contains Q only; old P is not an active item.
Common error: An available slot becomes active only after the head or predecessor makes it reachable.
