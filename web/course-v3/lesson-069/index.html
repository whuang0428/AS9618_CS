01

Represent a sequence using nodes and links

S10.09.A03

Visual overview

Identify nodes, head and the null link

A linked list contains nodes, each holding data and a link to the next node. A head pointer identifies the first node. In the model used here, a link value of 0 means no next node; Head = 0 represents an empty list. The last active node has a null link.

Follow logical order through physical storage

Logical order is determined by links, not by consecutive storage positions. Follow the head and successive links to traverse the list. A linked list suits a sequence that needs insertions or deletions between neighbours because changing links can avoid shifting every following data item, although locating the required node may still require traversal.

Separate a slot address from an ordinal position

These links are INTEGER array indices. The value 0 is a null-link convention outside indices 1 through 4, not a node to read. A node at array index 4 can be second in the logical sequence. Directly selecting slot 4 and selecting the fourth item in the list are different tasks.

State the benefit and the limitation together

Insertion between known neighbours changes links rather than shifting all later values. Finding a named item still requires checking nodes along the chain unless some additional index has been supplied. Array-backed nodes have fixed total capacity even though their logical order can change.

Worked example · Traverse a non-contiguous list

  1. Start

    Head = 2, so read Data[2] = A.

  2. Follow links

    Next[2] = 4 gives B; Next[4] = 1 gives C.

  3. Stop

    Next[1] = 0 ends traversal. The output order is A, B, C.

Core explanation · Exam essentials

  • Nodes store data and links; Head identifies the first node and a null link ends traversal.
  • Logical order follows links, not consecutive array positions.
Common misconception

A link identifies the next node; it is not the data stored in that node.

Check your understanding

Why is array slot 3 skipped in the starting diagram?

Check your answer

No active link points to it. It is a free slot, not part of the list.

02

Update data and links without losing nodes

S10.10.A03S10.10.A04

Visual overview

Preserve the successor during insertion

An array implementation can store Data[Index] and Next[Index] for each node, plus Head and information about unused slots. To insert X at free slot 3 after node 2 in the diagram, first store X and set Next[3] to the old successor 4. Then set Next[2] to 3. The sequence becomes A, X, B, C.

Edit values and remove nodes deliberately

Editing a node's data leaves its links unchanged. Deleting a middle node makes its predecessor point to the deleted node's successor, then returns the removed slot to the available storage. Deleting the head updates Head instead. The programmer must preserve access to the successor before changing links, or the remaining chain can become unreachable.

Explain the safe insertion order

  1. Remember the successor: A at slot 2 currently points to B at slot 4.
  2. Prepare the new node: Put X in free slot 3 and link it onward to 4.
  3. Make it reachable: Set Next[2] to 3. The chain is now A, X, B, C.

Diagnose a lost chain

If Next[2] is overwritten first and its old value was not saved, copying that changed value into Next[3] can make the new node point to itself. The old successor B then becomes unreachable from A. Safe order, or explicitly saved state, prevents this.

Keep separate cases separate

The independent cases below all start from the original A → B → C chain. An edit changes data but retains links; a deletion changes reachability before the storage can be reused. The boundary unit next explains why deleting the head needs a different destination for the changed link.

Core explanation · Exam essentials

  • Insertion links the new node to the old successor before redirecting the predecessor.
  • An edit preserves links; deletion bypasses the node and releases its storage.
Common misconception

Deleting a node means removing it from the active link chain; simply blanking its data leaves a broken logical item.

Check your understanding

When B is deleted from the starting list, what must Next[2] become?

Check your answer

1, the index of B's successor C.

03

Handle the head, tail and empty list

S10.10.A03S10.10.A04

Visual overview

Treat the head and null link explicitly

A node at the head has no active predecessor, so insertion or deletion there updates Head. At the tail, the successor is null. Deleting the only node must make Head null rather than leaving it pointing to a free slot.

Handle one node and no nodes

Each case below starts from its stated snapshot, independently of the other cases. Assume null = 0 and that released slots are recorded as available. If no slot is free, reject an insertion before changing Data or links.

Derive the boundary cases

For a head insertion, the new node takes the old Head as its successor and Head changes to the new slot. For a head deletion, there is no predecessor node to update: Head takes the old head’s successor. These rules also work when that successor is 0.

Empty list is different from exhausted storage

Deleting from Head = 0 is rejected because no node exists. Inserting into an empty list still needs a free slot: put the value there, give it a null next link and make Head identify it. If no slot is free, reject the insertion before changing Head or any active link.

Worked example · Complete the boundary cases independently

  1. Insert into empty

    Head = 0 and free slot 3. Store X in Data[3], set Next[3] = 0, then Head = 3. The list is X.

  2. Insert at head

    Start 2(A) → 4(B) → 1(C) → 0; slot 3 is free. Store X at 3, set Next[3] = 2, then Head = 3. Output order: X,A,B,C.

  3. Insert after tail

    Start the original A,B,C chain; slot 3 is free. Store X at 3, set Next[3] = 0, then Next[1] = 3. Output order: A,B,C,X.

  4. Delete tail

    Start the original A,B,C chain. Set Next[4] = 0 and release slot 1. Head remains 2; output order A,B.

  5. Delete only node

    Start Head = 3, Next[3] = 0, Data[3] = X. Set Head = 0 and release slot 3. No data node remains reachable.

  6. Reject when full

    If all slots are active and no free slot exists, report full; retain the same Head, data and links.

Core explanation · Exam essentials

  • Update Head when the first node changes; deleting the tail sets its predecessor’s next link to null.
  • Deleting the only node makes Head null; empty deletion and insertion without capacity leave state unchanged.
Common misconception

Deleting the only node is also a head deletion; clearing its data alone does not make the list empty.

Check your understanding

When a new node becomes the tail, what must its Next contain?

Check your answer

0, the null link in this model; the former tail must point to the new node.

Question 1 · Command word: State2 teacher marks

Head = 3. Data[1] = B, Next[1] = 0; Data[2] = unused; Data[3] = A, Next[3] = 1. State the traversal order and explain why slot 2 is ignored.

S10.09.A03
Answer and checking points — teacher-written
  1. Traversal visits indices 3 then 1, producing A then B.
  2. Slot 2 is not reachable by following the active links from Head.

Common error: Do not traverse in increasing physical index order.

Question 2 · Command word: State3 teacher marks

In the lesson's starting diagram, insert X at free slot 3 after A. State the data assignment and both link changes, in a safe order.

S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Store X in Data[3].
  2. Set Next[3] to 4, A's original successor.
  3. Set Next[2] to 3, making the new node reachable after A.

Common error: Preserve the original successor before overwriting its link.

Question 3 · Command word: Describe3 teacher marks

Using the starting diagram, describe editing C to Z and then deleting head A. State the final head and data order.

S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Change Data[1] to Z without changing Next[1].
  2. Set Head to Next[2] = 4 and release slot 2.
  3. The remaining list traverses B then Z.

Common error: An edit changes a value; deletion changes reachability.

Question 4 · Command word: Give3 teacher marks

A list consists only of node 2 containing P with Head = 2 and Next[2] = 0. Delete it, then reuse slot 2 for Q in the empty list. Give the head and link changes at both stages.

S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Deletion sets Head to 0 and releases slot 2.
  2. Insertion stores Q at 2, sets Next[2] to 0 and Head to 2.
  3. The final traversal contains Q only; old P is not an active item.

Common error: An available slot becomes active only after the head or predecessor makes it reachable.

Original question · Cambridge 9618/22

1. Insert a node while preserving both lists

Cambridge 9618/22 · October/November 2023 · 3(b) · 4 marks

Selected parts: 3(b) [4].

Reading the question — teacher guidance

Use the first free node F1 and insert it between D32 and D11. Preserve the remaining free list as well as the active list.

Solution / model answer — teacher-written

Step 1: Store D6 in the node currently labelled F1.

Step 2: Set that node’s pointer to the node containing D11.

Step 3: Set Ptr2 to the node containing F2.

Step 4: Set the pointer of D32 to the new D6 node.

The resulting active chain is D40 → D32 → D6 → D11 → D100 → null. The remaining free chain begins at F2. When implementing these steps, retain access to F2 before overwriting F1’s old link.

Official mark scheme
Why this earns marks — teacher explanation

There is one mark per completed step. The official answer labels nodes by their data; the pointer values in an implementation refer to locations, not the text “D6”.

Common mistakes — teacher analysis

Overwriting D32’s link before saving access to D11 can lose the remainder of the list. F1 must also be removed from the free list.

04

Lesson review

Summary

Nodes and links

A head pointer and next links determine sequence order independently of physical positions.

Insertion and deletion

Preserve the successor chain while relinking neighbours and update Head when the first node changes.

Array representation

Store node data and link indices in arrays and track unused slots for later insertions.
