Linked-list features and operations

The node at index 4, regardless of which node occupies index 3.

01

Represent a sequence using nodes and links

S10.09.A03

Visual overview

Core explanation

Nodes, head and the null link

A linked list contains nodes, each holding data and a link to the next node. A head pointer identifies the first node. In the model used here, a link value of 0 means no next node; Head = 0 represents an empty list. The last active node has a null link.

Logical order follows the links

Logical order is determined by links, not by consecutive storage positions. Follow the head and successive links to traverse the list. A linked list suits a sequence that needs insertions or deletions between neighbours because changing links can avoid shifting every following data item, although locating the required node may still require traversal.

Worked example · Traverse a non-contiguous list

  1. Start

    Head = 2, so read Data[2] = A.

  2. Follow links

    Next[2] = 4 gives B; Next[4] = 1 gives C.

  3. Stop

    Next[1] = 0 ends traversal. The output order is A, B, C.

Common misconception

A link identifies the next node; it is not the data stored in that node.

Check your understanding

Why is array slot 3 skipped in the starting diagram?

Check your answer

No active link points to it. It is a free slot, not part of the list.

02

Update data and links without losing nodes

S10.10.A03S10.10.A04

Visual overview

Core explanation

Insert X after node 2
  1. Prepare free slot 3: Store X in Data[3]. Keep the existing successor, node 4, reachable.
  2. Link the new node onward: Set Next[3] to 4, the old successor of node 2.
  3. Link the predecessor to X: Set Next[2] to 3. The sequence is now A, X, B, C.
Other operations preserve the chain
  • Edit: Change Data[Index] without changing the links.
  • Delete a middle node: Point its predecessor to its successor, then return the removed slot to available storage.
  • Delete the head: Update Head to the old head’s successor before releasing the old slot.
Common misconception

Deleting a node means removing it from the active link chain; simply blanking its data leaves a broken logical item.

Check your understanding

When B is deleted from the starting list, what must Next[2] become?

Check your answer

1, the index of B's successor C.

Practice questions

Question 1 · Command word: State2 marks

Head = 3. Data[1] = B, Next[1] = 0; Data[2] = unused; Data[3] = A, Next[3] = 1. State the traversal order and explain why slot 2 is ignored.

S10.09.A03
Answer and marking points
  1. Traversal visits indices 3 then 1, producing A then B.
  2. Slot 2 is not reachable by following the active links from Head.

Common error: Do not traverse in increasing physical index order.

Question 2 · Command word: State3 marks

In the lesson's starting diagram, insert X at free slot 3 after A. State the data assignment and both link changes, in a safe order.

S10.10.A03S10.10.A04
Answer and marking points
  1. Store X in Data[3].
  2. Set Next[3] to 4, A's original successor.
  3. Set Next[2] to 3, making the new node reachable after A.

Common error: Preserve the original successor before overwriting its link.

Question 3 · Command word: Describe3 marks

Using the starting diagram, describe editing C to Z and then deleting head A. State the final head and data order.

S10.10.A03S10.10.A04
Answer and marking points
  1. Change Data[1] to Z without changing Next[1].
  2. Set Head to Next[2] = 4 and release slot 2.
  3. The remaining list traverses B then Z.

Common error: An edit changes a value; deletion changes reachability.

Question 1 · Command word: Explain · 2 marks

A playlist frequently inserts a track between two existing tracks. Explain one advantage of a linked list and one reason finding a named track can still take several steps.

Answer and marking points
  • Once the insertion point is known, updating neighbour links inserts a node without shifting all later tracks.
  • The required track may need to be found by following links and checking node data sequentially.

Common error: Do not claim that every linked-list access is direct indexed access.

Question 2 · Command word: Describe · 4 marks

A linked list has Head = 4, links 4 → 2 → 5 → 0, and free slot 1. Describe inserting a node containing R at the head, then deleting the old node 2. State the final link chain.

Answer and marking points
  • Store R in Data[1] and set Next[1] to the old Head, 4.
  • Set Head to 1.
  • To delete node 2, set Next[4] to Next[2], which is 5, and release slot 2.
  • The final chain is 1 → 4 → 5 → 0.

Common error: The predecessor of node 2 remains node 4 after the head insertion.

Question 3 · Command word: Describe · 3 marks

An array-backed linked list contains one node at slot 3, with Head = 3 and Next[3] = 0. Describe deleting this node and state how both the active list and free storage change.

Answer and marking points
  • Set Head to 0, the deleted node's successor.
  • The active list is now empty.
  • Return slot 3 to the available slots so a later insertion can reuse it.

Common error: An empty list has no reachable data node, even if old bytes remain in the array.

04

Lesson review

Summary

Nodes and links

A head pointer and next links determine sequence order independently of physical positions.

Insertion and deletion

Preserve the successor chain while relinking neighbours and update Head when the first node changes.

Array representation

Store node data and link indices in arrays and track unused slots for later insertions.
