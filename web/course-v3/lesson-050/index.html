Design a ticket system · Concept 16

Give each module a clear responsibility

Observe

Follow information between responsibilities

  • CheckQuantity needs Quantity and PlacesLeft
  • CalculateCharge needs Quantity and Student
  • Payment needs the calculated Total and the amount Paid
  • Receipt needs the confirmed result

Look, then discuss

Which pieces of the ticket task can be understood and checked separately?

The desk must check a quantity, calculate an amount, accept or reject payment and report a result. Giving every piece the name “process tickets” hides the different work each one performs.

Recall

Recall returned values and effects

A function returns a value that its caller can use, such as an amount in a later comparison. A procedure performs a task when called, such as displaying a receipt. Here we design responsibilities and data flow without requiring full subroutine-declaration syntax.

Explain

Explanation · 1 / 4

Break the whole task into smaller problems

Decomposition divides a complex problem into manageable sub-problems. CheckQuantity decides whether the requested number fits availability. CalculateCharge determines the amount due. CompletePayment handles success or failure according to the payment rule.

Explanation · 2 / 4

State what each part receives and supplies

CalculateCharge receives Quantity and Student, uses fixed TicketPrice 25.00 and returns Total. CompletePayment needs Quantity, PlacesLeft, Total and Paid. Naming a module without stating its job or needed data leaves the design incomplete.

Explanation · 3 / 4

Choose a returned value when later processing needs it

A charge function can return 45.00 so the caller can evaluate Paid >= Total. Merely printing 45.00 does not return it. DisplayReceipt can be a procedure because its required effect is presenting information.

Explanation · 4 / 4

Check cooperation and completeness

The parts together must satisfy the original rules. Rejected payment must not reduce places; receipt generation must not recalculate a different price. Giving one part ownership of a calculation makes a changed rule easier to apply consistently.

Work together

Pass the result to the next responsibility

Quantity 2, PlacesLeft 8, Student TRUE and Paid 50.00. TicketPrice is 25.00.

Work together · 1 / 3

Check the request

CheckQuantity determines that 2 is at least one and no greater than 8. The caller may continue to charging.

Work together · 2 / 3

Return the amount due

CalculateCharge obtains subtotal 50.00, applies the student rule and returns 45.00. The caller keeps this numeric value as Total and displays the amount due.

Work together · 3 / 3

Complete the accepted sale

CompletePayment compares 50.00 with 45.00, calculates change 5.00 and changes PlacesLeft to 6. A receipt can use those confirmed values without repeating the charge calculation.

A useful decomposition gives each part a distinct job and connects the data required by the other parts.

Check

Try it yourself · Teacher-written

Decompose a device hire into availability checking, charge calculation and receipt output. The charge is Quantity × 4.00 + 10.00. Identify a suitable function and its inputs and returned value.

Check your reasoning

An availability module checks the requested quantity against devices available. CalculateCharge can be a function receiving Quantity and returning Quantity * 4.00 + 10.00. A receipt procedure receives the accepted hire details and calculated amount and outputs them. Printing the amount alone does not supply the numeric result to a payment comparison.

Take it further · Optional challenge

Two modules separately calculate a charge. One is updated when the discount changes; the other is not. Explain the defect and improve the design.

Check the challenge

The same order can receive inconsistent amounts. Put the charging rule in one calculation module and let other modules use its returned result. Test that module and the connections after a rule change.

Question 1 · Command word: Describe5 teacher marks

Describe a decomposition of a cinema purchase that selects a film, checks seats, calculates a price and produces a ticket. State four sub-problems and explain one connection between them.

S9.02.A01
Answer and checking points — teacher-written
  1. Select the film and requested performance.
  2. Check seat availability for that performance.
  3. Calculate the charge for the accepted seats.
  4. Produce the ticket using the accepted performance and seat details.
  5. For example, the chosen performance and requested seats must be passed to the availability check.

Common error: A list of unrelated activities does not form a solution.

Question 2 · Command word: State3 teacher marks

State whether a function or a procedure returning no value is the better interface for CalculateArea, which receives Length and Width and supplies an area needed in a later paint-cost calculation. Describe its inputs and result.

S9.02.A02
Answer and checking points — teacher-written
  1. A function returning a numeric area is suitable.
  2. Its inputs are Length and Width in consistent units.
  3. It returns Length * Width so the caller can calculate paint cost.

Common error: Displaying the area alone does not supply the value to the caller.

Question 3 · Command word: Explain3 teacher marks

Explain the problem when two modules separately calculate a delivery charge but only one is updated after a tariff change. Describe a better decomposition.

S9.02.A01S9.02.A02
Answer and checking points — teacher-written
  1. The same parcel can receive inconsistent charges from the two calculations.
  2. One charge-calculation module should own the tariff rule.
  3. Both callers should use that module's returned charge.

Common error: Assign the calculation one clear responsibility.
