Decomposition into program modules

Break a problem into manageable sub-problems with clear responsibilities and data passed between them.

What must each part do, and what information must it receive or return?

Before you start

Does renaming 'run the library' as 'manage the library' make the problem smaller?

Check your answer

01

Separate responsibilities

S9.02.A01

Visual overview

Core explanation

Decomposition breaks a complex problem into smaller sub-problems. Each part has a clear responsibility; together, the parts must satisfy the original requirements.

Build a useful decomposition
  1. Name responsibilities: For a loan: identify the copy, check availability, record the loan and report the outcome.
  2. Connect the parts: Agree the data passed between modules and the conditions under which each is used.
  3. Check completeness: Every requirement must be handled. Avoid an arbitrary list of screens or repeated names for the whole task.
Why decomposition helps

Smaller parts are easier to understand, implement and test. Agreed interfaces also allow designers to work on separate parts.

Worked example · From a whole task to cooperating parts

  1. Requirement

    A canteen order records choices, calculates the amount due and issues a receipt.

  2. Breakdown

    CollectOrder handles choices; CalculateTotal determines the amount; PrintReceipt presents the accepted order.

  3. Connection

    The collected items and quantities feed the calculation, then the items and total feed the receipt.

  4. Check

    An order with two items must appear correctly in both the total and receipt; the modules cannot use conflicting quantities.

Common misconception

Decomposition identifies smaller tasks; abstraction selects which details are relevant to a purpose.

Check your understanding

Why is 'process everything' an unsuitable final sub-problem?

Check your answer

It still hides several responsibilities and is too broad to implement or test independently.

02

Define module inputs and results

S9.02.A02

Visual overview

Core explanation

Define each module’s contract
  • Responsibility: Assign one sub-problem to the module.
  • Inputs: State which values the module needs.
  • Result or effect: A function returns a value for an expression; a procedure performs a task when called.
Connect modules without repeating their rules

CalculateCharge can receive quantity and unit price and return an amount; DisplayReceipt receives that amount and prints it. Keeping the calculation in one module avoids different charging rules emerging in the display. Choose these interfaces before detailed subroutine syntax.

Common misconception

A function's returned value and a procedure's displayed output are different interfaces; returning is not the same as printing.

Check your understanding

Which interface suits an amount used later in arithmetic?

Check your answer

Return the numeric amount from a function so the caller can use it in an expression.

Cambridge command words

Practice questions

Question 1 · Command word: Describe5 marks

Describe a decomposition of a cinema purchase that selects a film, checks seats, calculates a price and produces a ticket. State four sub-problems and explain one connection between them.

S9.02.A01
Answer and marking points
  1. Select the film and requested performance.
  2. Check seat availability for that performance.
  3. Calculate the charge for the accepted seats.
  4. Produce the ticket using the accepted performance and seat details.
  5. For example, the chosen performance and requested seats must be passed to the availability check.

Common error: A list of unrelated activities does not form a solution.

Question 2 · Command word: State3 marks

State whether a function or a procedure returning no value is the better interface for CalculateArea, which receives Length and Width and supplies an area needed in a later paint-cost calculation. Describe its inputs and result.

S9.02.A02
Answer and marking points
  1. A function returning a numeric area is suitable.
  2. Its inputs are Length and Width in consistent units.
  3. It returns Length * Width so the caller can calculate paint cost.

Common error: Displaying the area alone does not supply the value to the caller.

Question 3 · Command word: Explain3 marks

Explain the problem when two modules separately calculate a delivery charge but only one is updated after a tariff change. Describe a better decomposition.

S9.02.A01S9.02.A02
Answer and marking points
  1. The same parcel can receive inconsistent charges from the two calculations.
  2. One charge-calculation module should own the tariff rule.
  3. Both callers should use that module's returned charge.

Common error: Assign the calculation one clear responsibility.

Question 1 · Command word: Describe · 5 marks

An online quiz must present questions, accept answers, determine correctness and report a score. Describe a decomposition into four modules and identify data passed from answer collection to marking.

Answer and marking points
  • A question-presentation module displays the current question.
  • An answer-collection module receives the learner's response.
  • A marking module compares that response with the corresponding correct answer.
  • A reporting module displays the accumulated score.
  • The collected response and an identifier for its question pass to marking.

Common error: The response must remain associated with the correct question.

Question 2 · Command word: Describe · 3 marks

A payroll design has a function CalculateNetPay and a procedure PrintPayslip. Describe a suitable interface for each, given gross pay and deductions, and explain why the calculation should return a value.

Answer and marking points
  • CalculateNetPay receives gross pay and deductions and returns net pay.
  • PrintPayslip receives the employee details and pay amounts and outputs the payslip.
  • Returning the amount lets the caller use it for both the payslip and payment processing.

Common error: Keep the calculation separate from the presentation of the payslip.

Question 3 · Command word: Explain · 3 marks

A sports-centre designer divides 'handle a membership' into 'handle a new membership' and 'handle an existing membership'. Explain why more decomposition is needed and give two smaller tasks within handling a new membership.

Answer and marking points
  • The new-membership task still contains several operations with different responsibilities.
  • One smaller task collects the applicant's required details.
  • Another calculates the fee or creates the membership record from accepted details.

Common error: Give concrete tasks rather than repeating the parent task with another adjective.

04

Lesson review

Summary

Partition the work

Give each sub-problem a distinct responsibility that contributes to the whole solution.

Agree interfaces

Specify the information each part receives and the result or effect it provides.

Choose module roles

Use a function when the caller needs a returned value; use a procedure for an action.
