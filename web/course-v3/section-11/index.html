Translate a complete design into pseudocode

Bring together declarations, input, assignment, decisions and loops. This page follows the loop lessons in the learning route because a complete design may require all of those constructs.

Give the booking program its first values

Return to the school event desk from Section 10. Start with one booking and follow what the program must name, read, remember and display before adding any decisions or repetition.

Calculate charges and express booking rules

Use the same booking values to distinguish a calculation from a condition. Test the boundaries of each rule before putting that rule inside a decision.

Use supplied routines to process booking data

A routine call supplies arguments and produces a result or effect through an interface. Learn to read the supplied contract rather than guessing from a familiar-looking name.

Choose the correct booking action

Turn a tested condition into a controlled path through the program. Begin with two alternatives, then add a decision inside one path and a menu based on one value.

Repeat a known number of booking actions

Start with a known count, observe each iteration, then add a running total, a different step and a complete loop inside another loop.

Continue or stop when a condition changes

The desk may receive an unknown number of requests or need several attempts at one input. Place the condition test where the task needs it, and make sure the state can change.

Choose a loop and enforce its stopping rules

A good loop choice follows the required number of actions, first-attempt rule and stopping events. Explain those reasons using the problem’s data.

Define reusable actions and deliberate updates

Move a repeated booking action into a procedure. Trace the call, match its arguments, and distinguish a copied value from a reference to caller storage.

Return a useful value from a function

Define a result the caller can use, explain its interface, and then trace the point at which a return ends the current call. Apply those ideas to strings and stored booking records.

Remove unnecessary work without changing the booking result

Compare complete behaviours before and after a change. Count the comparisons, calculations or array visits removed, and check the cases where a tempting change would be wrong.

Build and check a complete booking program

Process three accepted bookings with one coherent design. Reuse the same validity rule, place updates after acceptance and verify the complete result before transferring the ideas to a different exam context.
