Look, then discuss

How can a charge calculation supply a number for Total <- Charge(Seats)?

The receipt needs a numeric amount, not just a message printed elsewhere. Follow the input quantity into a function and the returned amount back to the calling expression.

Recall

Recall a procedure effect

CALL ShowBooking(…) performs an action. A function instead provides a typed return value that can be used in an assignment, calculation, output or condition.

Explain

Explanation · 1 / 3

Declare the result type in the header

FUNCTION Charge(Quantity : INTEGER) RETURNS REAL declares one parameter and a REAL result. Function parameters are passed by value by default in Cambridge pseudocode; do not design a function interface that relies on BYREF parameters.

Explanation · 2 / 3

Return the computed value

RETURN Quantity * 12.50 evaluates the expression and ends the current function call with that result. RETURNS in the header names a type; RETURN in the body supplies a value.

Explanation · 3 / 3

Use the function call as a value

Total <- Charge(Seats) receives the result. OUTPUT Charge(Seats) + 2.00 uses it in a larger expression. Do not write CALL Charge(Seats); CALL invokes a procedure. The experiment extends the interface to Charge(Quantity : INTEGER, PriceEach : REAL), called as Charge(Seats, Price), so you can change both inputs. The second argument supplies the per-seat price that is fixed at 12.50 in the worked program.

FUNCTION Charge(Quantity : INTEGER) RETURNS REAL
    RETURN Quantity * 12.50
ENDFUNCTION
DECLARE Seats : INTEGER
DECLARE Total : REAL
Seats <- 3
Total <- Charge(Seats)
OUTPUT Total

Work together

Complete the outward and return journey

Seats is 3 and the caller executes Total <- Charge(Seats).

Work together · 1 / 2

Enter and calculate

The parameter Quantity receives a copy of 3. Its multiplication produces 37.5.

Work together · 2 / 2

Return and resume

RETURN supplies 37.5 to the call expression. The caller then assigns it to Total. Replacing RETURN with OUTPUT would display a number without supplying the required function result.

Use a function when a calling expression needs a result; use a procedure for an action invoked with CALL.

Implement a function from a precise interface

Observe

A counting interface

Interface partMeaning
HeaderFUNCTION CountLetter(Text : STRING, Letter : CHAR) RETURNS INTEGER
ParametersText, then Letter
Example arguments"aAba", then 'a'
Returned valueNumber of case-sensitive matches

Look, then discuss

Which facts must caller and function agree on when counting a character in a code?

The caller already has the text and target character. The function must count matches and return an integer; it should not ask the user to input those values again.

Recall

Recall string traversal

LENGTH gives the character count and a one-based MID(Text, Index, 1) extracts the current character as a one-character STRING. For this supplied counting task, the paper permits comparison with its CHAR argument. Upper- and lower-case letters remain distinct.

Explain

Explanation · 1 / 3

Read the header as an agreement

The header gives the name, ordered parameter identifiers and types, and return type. Parameters belong to the definition; arguments belong to a particular call. A receiving variable such as Matches is part of the caller, not a parameter.

Explanation · 2 / 3

Build the body from familiar parts

Initialise Count to 0, traverse positions 1 through LENGTH(Text), compare the extracted character with Letter, and increment only on a match. Declarations inside the function make Index and Count local working variables.

Explanation · 3 / 3

Return only after the complete count

RETURN Count belongs after NEXT Index. A return inside the loop would stop the function before all characters had been examined. An empty string gives zero iterations and returns the initial 0.

FUNCTION CountLetter(Text : STRING, Letter : CHAR) RETURNS INTEGER
    DECLARE Index, Count : INTEGER
    Count <- 0
    FOR Index <- 1 TO LENGTH(Text)
        IF MID(Text, Index, 1) = Letter THEN
            Count <- Count + 1
        ENDIF
    NEXT Index
    RETURN Count
ENDFUNCTION
DECLARE Matches : INTEGER
Matches <- CountLetter("aAba", 'a')
OUTPUT Matches

Work together

Trace a case-sensitive count

Call CountLetter("aAba", 'a').

Work together · 1 / 2

Compare each position

The characters are a, A, b and a. The counts after each comparison are 1, 1, 1 and 2. Converting all text to lower case would change the required rule.

Work together · 2 / 2

Distinguish all three names

Text and Letter are formal parameters. "aAba" and 'a' are arguments. Matches is the caller variable that receives the returned 2.

The interface states what crosses the call boundary; local variables carry out the internal calculation.

Original question · Cambridge 9618/22

1. Write a case-sensitive counting function

Cambridge 9618/22 · May/June 2023 · 4 · 6 marks

Selected parts: 4 [6].

Original insert · reference material

Hint — reading the question

Use both parameters; do not input them inside the function. Return an integer after checking every character, preserving case sensitivity.

Reasoning and model answer — teacher-written
FUNCTION GetNum(ThisString : STRING, ThisChar : CHAR) RETURNS INTEGER
    DECLARE Index, Count : INTEGER
    Count ← 0
    FOR Index ← 1 TO LENGTH(ThisString)
        IF MID(ThisString, Index, 1) = ThisChar THEN
            Count ← Count + 1
        ENDIF
    NEXT Index
    RETURN Count
ENDFUNCTION
Teacher trace: GetNum("aAba", 'a')CharacterCount after comparison
Index 1a1
Index 2A1
Index 3b1
Index 4a2

The return is 2. An empty string makes zero loop iterations and returns the initial count 0. A string with no match also returns 0.

Official mark scheme
Why this earns marks — teacher explanation

Six points cover interface, local integer declarations, full traversal, extraction/comparison, conditional increment and return after the loop. Initialising Count is necessary for the algorithm even though it is not a separately numbered mark.

Common mistakes — teacher analysis

Returning inside the loop stops before checking the remaining characters. Lowercasing both values breaks the required case-sensitive comparison.

Return on success and stop unnecessary searching

Observe

First unused slot

IndexStored attendeeMeaning
1MinaOccupied
2""Unused

Look, then discuss

When a booking is stored in the first free slot, why must the search stop immediately?

Three slots contain "Mina", an empty string and an empty string. A new request from Jo should fill the first empty slot only.

Recall

Recall arrays of records from Section 10

An array element can hold a record with several fields. Booking[Index].Name accesses the Name field of one indexed record. In the real-paper task Loan[Index] is a record with StudentID, BookID and OnLoan fields. The supplied rule defines unused as StudentID = ""; a returned book with OnLoan FALSE still has a historical record.

Explain

Explanation · 1 / 3

Give every execution path a result

A function returning BOOLEAN must supply TRUE when the action succeeds and FALSE when no free slot exists. A path that reaches the end without the promised result is incomplete.

Explanation · 2 / 3

Use RETURN to finish the entire call

After filling the first free slot, RETURN TRUE ends the function immediately, even from inside a FOR loop. It does not merely leave the IF or wait for later iterations. Put RETURN FALSE after the loop for the no-slot path.

Explanation · 3 / 3

Explain the concrete efficiency gain

Once the first slot is filled, visiting remaining slots is unnecessary and could fill multiple entries if the update is repeated. An early return both preserves the “first unused record only” rule and avoids scanning the remaining positions. A match at slot 1 needs one check; a full 7000-record array still needs all 7000 checks.

Work together

Build and trace a complete first-match function

For this small teaching example, an INTEGER function reads a three-element array declared outside the function and reports the first unused position: 0 means no free slot. Names is a global variable in this example, available to both the function and the main program.

Work together · 1 / 2

Use a returned position to isolate the search

FirstFree has no parameters: it reads the explicitly declared global Names array and returns only the first empty position. Index is declared inside the function and is local to that call. The caller then decides whether to write a booking. This establishes the same shared-array context supplied for Loan in the following paper.

DECLARE Names : ARRAY[1:3] OF STRING
FUNCTION FirstFree() RETURNS INTEGER
    DECLARE Index : INTEGER
    FOR Index <- 1 TO 3
        IF Names[Index] = "" THEN
            RETURN Index
        ENDIF
    NEXT Index
    RETURN 0
ENDFUNCTION
DECLARE Position : INTEGER
Names[1] <- "Mina"
Names[2] <- ""
Names[3] <- ""
Position <- FirstFree()
IF Position <> 0 THEN
    Names[Position] <- "Jo"
ENDIF
OUTPUT Position

Work together · 2 / 2

Follow success and failure

With the shown data, Index 1 fails the empty test and Index 2 returns 2; the caller changes only Names[2]. With all three names occupied, the loop finishes and returns 0, so no array element is changed.

The following paper combines this first-match rule with updates to its supplied global array of loan records. Those updates are explicit side effects; the BOOLEAN return reports whether they succeeded.

Original question · Cambridge 9618/22

1. Find and fill the first unused loan record

Cambridge 9618/22 · October/November 2025 · 8(b) · 7 marks

Selected parts: 8(b) [7].

Hint — reading the question

Unused means StudentID is empty, not OnLoan is FALSE. Stop as soon as one unused record has been filled. Returned books still occupy historical records.

Reasoning and model answer — teacher-written
FUNCTION NewLoan(ThisStudentID : STRING, ThisBookID : STRING) RETURNS BOOLEAN
    DECLARE Index : INTEGER
    FOR Index ← 1 TO 7000
        IF Loan[Index].StudentID = "" THEN
            Loan[Index].StudentID ← ThisStudentID
            Loan[Index].BookID ← ThisBookID
            Loan[Index].OnLoan ← TRUE
            RETURN TRUE
        ENDIF
    NEXT Index
    RETURN FALSE
ENDFUNCTION

If slot 1 is unused, it is filled and the function returns immediately. If only slot 7000 is unused, the search reaches and fills it. With no unused slot, no record is changed and FALSE is returned.

Official mark scheme
Why this earns marks — teacher explanation

Seven points include the bounded search, early termination, indexed record notation, empty-ID test, the two identifier assignments, OnLoan = TRUE and correct Boolean returns. The official alternative explicitly permits RETURN inside a FOR loop.

Common mistakes — teacher analysis

Continuing after success fills multiple slots with the same loan. Testing OnLoan = FALSE would overwrite returned-loan history. Do not access Loan[7001] after an unsuccessful search.

Question 4 · Command word: Describe3 teacher marks

Describe the interface of ReadRating() in the supplied program. State the caller output for inputs 0, 6, 5, and explain why its local Rating need not be an argument.

Use this complete program and the stated inputs.

FUNCTION ReadRating() RETURNS INTEGER
    DECLARE Rating : INTEGER
    REPEAT
        INPUT Rating
    UNTIL (Rating >= 1) AND (Rating <= 5)
    RETURN Rating
ENDFUNCTION
DECLARE Result : INTEGER
Result <- ReadRating()
OUTPUT Result
S11.07.A01S11.07.A02S11.07.A03S11.08.A01S11.08.A02S11.08.A03S11.08.A04
Answer and checking points — teacher-written
  1. The function name is ReadRating, its parameter list is empty, and its return type is INTEGER.
  2. It returns the first accepted rating from 1 to 5; the given inputs cause main to output 5.
  3. The function obtains Rating through its own input statements and declares it locally, so the caller supplies no argument.

Common error: A function with no parameters can still execute statements and return a useful result.
