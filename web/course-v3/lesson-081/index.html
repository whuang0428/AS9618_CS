Before you start

A function outputs a number but has no RETURN statement. Has it supplied that number as its result?

Check your answer

No. OUTPUT displays a value; RETURN supplies the function result to the calling expression.

01

Define and use a returned value

S11.07.A01S11.07.A02S11.07.A03S11.07.A04

Visual overview

Define a typed result

A function is a subprogram that returns a value. Its header uses FUNCTION Name(parameters) RETURNS DataType and its body uses RETURN Expression, ending with ENDFUNCTION. The returned expression must match the declared result type, and every reachable result path must supply a return value.

Use the result at the call site

Call a function where its result is needed: in an assignment, condition, output or another expression. Total <- Price + Tax(Price) adds the returned tax to the original price. Do not prefix a function call with CALL; that keyword invokes a procedure. Function parameters use value passing in this Cambridge notation.

Evaluate Total <- Price + Tax(Price) for Price 50

  1. Read the argument: The caller supplies its REAL value 50 to the function parameter.
  2. Run the function: Tax computes 50 * 0.20, giving 10.
  3. Return: RETURN supplies that REAL value to the pending expression.
  4. Resume the expression: Replace Tax(Price) with 10, calculate 50 + 10, then assign 60 to Total.

Separate a type promise from execution

RETURNS REAL describes the result type in the header; it does not perform a return. RETURN 10.0 supplies one result during execution. A function can return a number, BOOLEAN or other permitted type; the caller must use it in a compatible expression. Cambridge function parameters use value passing.

Worked example · Use a function result in a calculation

  1. Pseudocode
    FUNCTION Tax(Price : REAL) RETURNS REAL
    RETURN Price * 0.20
ENDFUNCTION
DECLARE Price, Total : REAL
INPUT Price
Total <- Price + Tax(Price)
OUTPUT Total
  2. Trace and check

    Input 50 causes Tax to return 10 and the caller to output 60.

Core explanation · Exam essentials

  • RETURNS declares the result type; RETURN supplies a value and ends the call.
  • A returned value replaces the function call inside an expression; do not prefix the call with CALL.
Common misconception

RETURNS declares a result type; RETURN supplies an actual result during execution.

Check your understanding

Why is Tax suitable as a function?

Check your answer

The caller needs the calculated tax value in a larger expression.

02

Trace branches and early returns

S11.07.A01S11.07.A02S11.07.A03

Visual overview

Every reachable result path must return a value

A function can choose its result with selection. The chosen execution path must supply a value of the declared result type. RETURN immediately completes the current call; it does not merely display a value or wait for ENDFUNCTION.

Account for the missing path

For equal arguments, the ELSE branch returns Second, which still equals the required larger value. A function with only the TRUE return would leave equal or smaller first arguments without a result. Test both branches and equality, not only an example that reaches the first RETURN.

Explain an early return

RETURN acts immediately. DeliveryFee has a free result for a zero-item order; that branch returns 0.0 and the later fee formula is not evaluated. A positive Quantity skips the first RETURN and reaches the final one. Replacing RETURN with OUTPUT would print inside the function while leaving the caller without that returned result.

Keep paths and assumptions explicit

The delivery task assumes non-negative integer quantities. It is not a negative-quantity validator. A function with several RETURN statements still returns one value in a particular call: only the statement reached first can complete that invocation.

Worked example · Return a value from each branch

  1. Requirements and starting conditions

    Input two INTEGER values A and B. Return the larger through Larger, add 1 in the caller, and output the result.

  2. Cambridge pseudocode
    FUNCTION Larger(First : INTEGER, Second : INTEGER) RETURNS INTEGER
    IF First > Second THEN
        RETURN First
    ELSE
        RETURN Second
    ENDIF
ENDFUNCTION
DECLARE A, B, Result : INTEGER
INPUT A
INPUT B
Result <- Larger(A, B) + 1
OUTPUT Result
  3. Expected result

    7,4 and 4,7 both produce 8. Equal values 5,5 produce 6; negative values -3,-7 produce -2.

Worked example · Finish a call before its last source line

  1. Requirements and starting conditions

    A non-negative INTEGER Quantity of zero has no delivery fee. Otherwise the fee is 2.0 plus 0.5 per item.

  2. Cambridge pseudocode
    FUNCTION DeliveryFee(Quantity : INTEGER) RETURNS REAL
    IF Quantity = 0 THEN
        RETURN 0.0
    ENDIF
    RETURN 2.0 + Quantity * 0.5
ENDFUNCTION
DECLARE Quantity : INTEGER
DECLARE Fee : REAL
INPUT Quantity
Fee <- DeliveryFee(Quantity)
OUTPUT Fee
  3. Expected result

    Quantity 0 returns and outputs 0.0; Quantity 4 gives 4.0; Quantity 1 gives 2.5. The zero path does not evaluate the later fee formula.

Core explanation · Exam essentials

  • Cover every possible result path, including equality and false branches.
  • After RETURN executes, later statements in that invocation are skipped.
Common misconception

RETURN ends the current function call; a later RETURN does not overwrite its result.

Check your understanding

How many RETURN statements execute in a single call of DeliveryFee?

Check your answer

One. The first RETURN reached ends the call, so no later RETURN is executed.

Read headers, parameters and arguments

Read a function’s result contract

A subprogram interface describes how it can be called: its name, ordered formal parameters, their types and relevant passing modes, plus the result type for a function. The header records these details. A caller should be able to use the interface without depending on the internal calculation steps.

Connect arguments, parameters and destination

A parameter is the identifier declared in the subprogram header. An argument is the value, variable or expression supplied at a call. In ValidMark(Value), Mark is the formal parameter and Value is the argument; the result is a BOOLEAN. A correct interface also needs a clear behavioural contract, such as accepting marks from zero to 100 inclusive.

Use zero, one and multiple arguments

A function may receive multiple arguments, as Larger does, or none. ReadRating() has no arguments because its body obtains its own keyboard input; the empty parentheses still identify a function call. Its returned INTEGER can be assigned to Result. Having no parameters does not mean the body performs no work.

Read a complete no-argument example

The no-argument example declares Rating locally, reads at least once, validates integers from 1 to 5, and returns only the accepted value. Input assumptions and the returned meaning are part of its interface. A no-argument function is a useful syntax example here, not a requirement to use keyboard input inside every function.

Connect to program design

Lesson 085 uses these interface contracts in structure charts, and Lesson 088 checks their connections during integration testing. This lesson establishes the typed call, returned value and immediate caller use on which that work depends.

Worked example · Use an argument and a Boolean result

  1. Requirements and starting conditions

    Input INTEGER Value; ValidMark returns TRUE exactly for 0 through 100 inclusive.

  2. Cambridge pseudocode
    FUNCTION ValidMark(Mark : INTEGER) RETURNS BOOLEAN
    RETURN (Mark >= 0) AND (Mark <= 100)
ENDFUNCTION
DECLARE Value : INTEGER
INPUT Value
OUTPUT ValidMark(Value)
  3. Expected result

    -1 and 101 give FALSE; 0 and 100 give TRUE.

Worked example · Use a function with an empty parameter list

  1. Requirements and starting conditions

    Input INTEGER attempts until one is from 1 to 5. Supply enough input to finish; non-integer tokens are outside the task.

  2. Cambridge pseudocode
    FUNCTION ReadRating() RETURNS INTEGER
    DECLARE Rating : INTEGER
    REPEAT
        INPUT Rating
    UNTIL (Rating >= 1) AND (Rating <= 5)
    RETURN Rating
ENDFUNCTION
DECLARE Result : INTEGER
Result <- ReadRating()
OUTPUT Result
  3. Expected result

    0, 6, 5 returns 5 and main outputs 5. An initial 1 returns and outputs 1 after one input.

Core explanation · Exam essentials

  • An interface states the name, ordered parameters, result type and behaviour.
  • Distinguish the argument, formal parameter and caller variable receiving the result.
Common misconception

An argument and a parameter can have different names while representing the same value during a call.

Check your understanding

What type must the calling expression expect from ValidMark?

Check your answer

BOOLEAN.

Question 1 · Command word: Write2 marks

Write a function Double(Value : INTEGER) returning twice its argument, and an assignment that stores Double(6) in Result.

S11.07.A01S11.07.A02S11.07.A03
Answer and marking points

One valid solution to the requested statements

FUNCTION Double(Value : INTEGER) RETURNS INTEGER
    RETURN Value * 2
ENDFUNCTION
DECLARE Result : INTEGER
Result <- Double(6)
  1. Use FUNCTION Double(Value : INTEGER) RETURNS INTEGER with RETURN Value * 2 and ENDFUNCTION.
  2. Result <- Double(6) assigns 12.

Common error: RETURN and RETURNS have different roles.

Explain why a tax calculation is suitable as a function and a print-heading action is suitable as a procedure. State how a caller uses each.

S11.07.A04

  1. A tax function returns a numeric result for a calling expression such as Total <- Price + Tax(Price).
  2. A heading procedure performs a display action and is invoked with CALL Heading().

Question 4 · Command word: State3 marks

State the output of the supplied DeliveryFee program for Quantity 0, 1 and 4. Explain why the later RETURN does not override the zero result.

Use this complete program and the stated inputs.

FUNCTION DeliveryFee(Quantity : INTEGER) RETURNS REAL
    IF Quantity = 0 THEN
        RETURN 0.0
    ENDIF
    RETURN 2.0 + Quantity * 0.5
ENDFUNCTION
DECLARE Quantity : INTEGER
DECLARE Fee : REAL
INPUT Quantity
Fee <- DeliveryFee(Quantity)
OUTPUT Fee
S11.07.A01S11.07.A02S11.07.A03
Answer and marking points
  1. The respective outputs are 0.0, 2.5 and 4.0.
  2. RETURN 0.0 immediately completes the zero-quantity call, so the later formula is not executed on that path.
  3. The returned value replaces DeliveryFee(Quantity) and is assigned to caller variable Fee.

Common error: Source order does not mean execution continues after RETURN.

Question 5 · Command word: Describe3 marks

Describe the interface of ReadRating() in the supplied program. State the caller output for inputs 0, 6, 5, and explain why its local Rating need not be an argument.

Use this complete program and the stated inputs.

FUNCTION ReadRating() RETURNS INTEGER
    DECLARE Rating : INTEGER
    REPEAT
        INPUT Rating
    UNTIL (Rating >= 1) AND (Rating <= 5)
    RETURN Rating
ENDFUNCTION
DECLARE Result : INTEGER
Result <- ReadRating()
OUTPUT Result
S11.07.A01S11.07.A02S11.07.A03S11.08.A01S11.08.A02S11.08.A03S11.08.A04
Answer and marking points
  1. The function name is ReadRating, its parameter list is empty, and its return type is INTEGER.
  2. It returns the first accepted rating from 1 to 5; the given inputs cause main to output 5.
  3. The function obtains Rating through its own input statements and declares it locally, so the caller supplies no argument.

Common error: A function with no parameters can still execute statements and return a useful result.

Question 1 · Command word: Write · 3 marks

Write a function Square(Number : INTEGER) that returns Number multiplied by itself. Write an output statement using Square(4) + 1 and state the output.

Answer and marking points

One valid solution to the requested statements

FUNCTION Square(Number : INTEGER) RETURNS INTEGER
    RETURN Number * Number
ENDFUNCTION
OUTPUT Square(4) + 1
  • The header declares RETURNS INTEGER and the body uses RETURN Number * Number.
  • Close with ENDFUNCTION and use OUTPUT Square(4) + 1.
  • The displayed result is 17.

Common error: Use the returned value in the expression without CALL.

Question 2 · Command word: Describe · 3 marks

A function has the header FUNCTION Discount(Price : REAL, Member : BOOLEAN) RETURNS REAL. It returns 10% of Price for a member and zero otherwise. Describe its interface and write a body that returns a value on both paths.

Answer and marking points

One valid solution to the requested statements

FUNCTION Discount(Price : REAL, Member : BOOLEAN) RETURNS REAL
    IF Member THEN
        RETURN Price * 0.10
    ELSE
        RETURN 0.0
    ENDIF
ENDFUNCTION
  • The ordered parameters are a REAL price and a BOOLEAN membership flag; the result is REAL.
  • IF Member THEN RETURN Price * 0.10 supplies the member result.
  • ELSE RETURN 0.0 with ENDIF supplies the non-member result before ENDFUNCTION.

Common error: Every path used as a function result needs a RETURN.

Question 3 · Command word: Identify · 3 marks

FUNCTION ValidScore(Score : INTEGER) RETURNS BOOLEAN is called in Allowed <- ValidScore(TestMark). Identify the formal parameter, argument and receiving variable, and explain why replacing RETURN with OUTPUT inside the function would not preserve this call's behaviour.

Question 4 · Command word: Write · 4 marks

Write a function Smaller(First : INTEGER, Second : INTEGER) that returns the smaller argument. Write an assignment storing Smaller(8, 3) + 2 in INTEGER variable Result. State the returned value when the arguments are equal, and explain why every path needs a RETURN.

Answer and marking points

One valid pseudocode answer

FUNCTION Smaller(First : INTEGER, Second : INTEGER) RETURNS INTEGER
    IF First < Second THEN
        RETURN First
    ELSE
        RETURN Second
    ENDIF
ENDFUNCTION
DECLARE Result : INTEGER
Result <- Smaller(8, 3) + 2
  • The header declares the two ordered INTEGER parameters and RETURNS INTEGER.
  • IF First < Second THEN RETURN First ELSE RETURN Second ENDIF returns the smaller value, followed by ENDFUNCTION.
  • Result <- Smaller(8, 3) + 2 stores 5.
  • Equal arguments return that same value through ELSE; every reachable path must supply the result needed by the calling expression.

Common error: Returning only on First < Second leaves the false path without a value.
