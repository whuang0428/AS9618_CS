Public and private cloud computing

Locate control, tenancy and dependence before judging a cloud design.

01

Knowledge-point guiding question

Start with the problem

If data is stored ‘in the cloud’, who owns the infrastructure, who may share it, and what happens when the connection or provider fails?
Prior-knowledge diagnostic

Prompt: Does ‘public cloud’ mean that the public can read your files?

Check: No. It describes provider-operated services shared across customers; access controls should still separate each customer’s data.

By the end, you can

  • S2.06.A01Explain cloud computing as remote computing resources accessed through a network.
  • S2.06.A02Distinguish public and private cloud control and tenancy.
  • S2.06.A03Explain benefits and drawbacks of cloud computing.
  • S2.06.A04Justify a cloud choice for a scenario.
02

Knowledge explanation

Explain, model and apply

01

Cloud changes where resources run and who controls the infrastructure

S2.06.A01S2.06.A02

Cloud computing provides storage, processing, applications or platforms from remote infrastructure accessed through a network. The organisation uses the service without operating every physical server locally.

A public cloud is operated by a third-party provider and its underlying resources serve multiple customers with logical separation. A private cloud is dedicated to one organisation and may be operated by that organisation or on its behalf.

Public/private describes tenancy and control, not whether a file is publicly readable. Authentication, permissions and encryption remain necessary.

One cloud request

  1. ClientAuthenticates and requests storage, processing or an application
  2. NetworkCarries the request to remote infrastructure
  3. Cloud serviceAllocates resources and returns the result

Common misconception

Public cloud does not mean public access; access rights are separate from tenancy.

教师讲法 / 易错点

用 ownership、tenancy、control 三个词固定比较轴，避免学生只写 public=free、private=secure。

02

Cloud benefits and risks must be connected to dependence

S2.06.A03S2.06.A04

Benefits can include access from different locations, collaboration, elastic capacity, reduced local hardware, provider maintenance and geographically redundant infrastructure.

Drawbacks can include dependence on broadband and the provider, recurring cost, less direct control, migration difficulty, service outage, data-location/compliance concerns and exposure if accounts or provider controls fail.

A choice depends on sensitivity, required control, expected demand, staff expertise, budget, connection resilience and legal requirements. Cloud storage is not automatically a complete backup strategy.

Scenario decision

Sensitive regulated records

Private cloud may provide stronger organisational control; still evaluate cost, expertise and resilience.

Short-lived variable workload

Public cloud elasticity may avoid purchasing peak local capacity.

Unreliable connection

Remote dependence is a major drawback; local continuity may be required.

Common misconception

Data redundancy at a provider is not the same as an independent, tested backup controlled by the organisation.

教师讲法 / 易错点

要求学生把每个 benefit/drawback 写成因果链，不接受 cloud is cheaper/safer 这种绝对句。

03

Practice

Retrieve, apply, then answer like an exam

Retrieval4 marks

Give two differences between a public cloud and a private cloud.

S2.06.A01S2.06.A02
Answer and marking points
  1. Provider-operated/shared underlying resources versus organisation-dedicated resources.
  2. Less direct organisational control versus greater organisational control.
  3. Credit any two clear paired contrasts.

Common error: Do not claim public-cloud files are open to the public.

Application4 marks

Explain two benefits of a public cloud for a start-up whose demand changes sharply each month.

S2.06.A03S2.06.A04
Answer and marking points
  1. Elastic allocation can match changing workload.
  2. This avoids purchasing all peak hardware in advance.
  3. Provider maintenance reduces local infrastructure work.
  4. Remote authenticated access can support distributed staff.

Common error: Every benefit needs the mechanism and scenario consequence.

Exam-style6 marks

A clinic considers moving patient records to cloud storage. Give a balanced recommendation covering control, access, availability and cost.

S2.06.A02S2.06.A03S2.06.A04
Answer and marking points
  1. Choose public or private cloud with a reason.
  2. Address authorised remote access/collaboration.
  3. Address broadband/provider outage dependence.
  4. Address control, data location or compliance.
  5. Address provider or dedicated infrastructure cost.
  6. State that authentication, permissions and tested backup remain necessary.

Common error: ‘Private cloud is completely secure’ is false.

Original equivalent task

Explain one benefit and one drawback of storing school work in a cloud service rather than only on a local school server.

Build the answer

  1. Benefit: authorised access from multiple locations because data is remote.
  2. Drawback: loss of network/provider access can make the files temporarily unavailable.

How marks are earned

  • Each point links a cloud feature to its consequence.

Common losses

  • Writing two benefits when the task asks for one benefit and one drawback.
  • Stating ‘hacking’ without explaining the cloud-related risk or control.

Summary

The decision frame for this lesson

Where are resources?

Remote infrastructure accessed over a network

Who shares underlying infrastructure?

Multiple customers in public; one organisation in private

What is gained?

Access, elasticity, provider-managed infrastructure

What is depended on?

Connection, provider, accounts and contractual controls
