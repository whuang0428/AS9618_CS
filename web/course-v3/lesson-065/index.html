Why files are needed and text-file pseudocode

Keep text between executions and choose file operations that preserve or replace the intended lines.

01

Select the correct file mode

S10.07.A01

Visual overview

Keep data beyond one execution

Files retain data on secondary storage so it can be reused after a program terminates or transferred to another program. Keeping names only in variables or arrays does not provide this persistence. A text file stores a sequence of lines that can be processed in order.

Choose whether old lines must survive

OPENFILE selects how a program will use the named file. READ permits reading existing lines. WRITE creates a file or replaces existing contents. APPEND adds at the end while retaining existing contents. Select the mode from the task: replacing a report and extending a log require different modes.

Distinguish filename, contents and working variable

A STRING such as "Names.txt" identifies the file; it is not its contents. READFILE transfers one line from storage into a STRING variable. A second read replaces that variable with the next line unless the program stores or processes the previous value.

ModeNext operationEffect to check
READREADFILE after checking EOFThe stored lines are preserved.
WRITEWRITEFILEOpening replaces any previous contents, even before the first new line is written.
APPENDWRITEFILENew lines follow the old lines.

State the conditions of the examples

Open one file in only one mode at a time. Close it before reopening in a different mode. In the following examples, required input files exist and file access succeeds; missing-file and permission handling belong to the chosen programming environment.

Core explanation · Exam essentials

  • Files retain data between executions.
  • READ loads, WRITE creates or replaces, APPEND extends; a quoted filename is a STRING identifier.
Common misconception

WRITE is not interchangeable with APPEND when old lines must remain.

Check your understanding

Which mode extends an existing attendance log?

Check your answer

APPEND, because earlier entries must be retained.

Write a new file and append a line

S10.07.A02

Visual overview

Swipe horizontally to compare every column →

Create the intended complete output

WRITEFILE writes the supplied STRING as a line in an open text file. The complete example opens Names.txt FOR WRITE, inputs three lines, writes each line and closes the file. Existing contents are replaced, so this operation suits creating a fresh list.

Extend it without erasing earlier lines

To extend that list, use APPEND instead. Input a new line, open the same file FOR APPEND, write the line and close the file. Closing completes the file operation and releases the file. When copying between files, use different names so opening the output FOR WRITE cannot erase the input.

Create, close, then extend

  1. Create: Open Names.txt FOR WRITE once. This replaces Old if it existed.
  2. Write the list: Input and write Ada, Ben and Cy on separate iterations.
  3. Close: Finish the writing session; the saved list has three lines.
  4. Extend separately: Input Dia, open FOR APPEND, write it and close. The saved list now has four lines.

Choose the loop from the task

The simple writing example uses a fixed three-iteration FOR loop because the number of input lines is known. A later reading program uses EOF because the number of saved lines need not be known in advance. The two loop choices follow different information available at the start.

Worked example · Create a three-line file

  1. Task

    Input exactly three strings and save them as the replacement contents of Names.txt.

  2. Pseudocode
    DECLARE Line : STRING
DECLARE Index : INTEGER
OPENFILE "Names.txt" FOR WRITE
FOR Index <- 1 TO 3
    INPUT Line
    WRITEFILE "Names.txt", Line
NEXT Index
CLOSEFILE "Names.txt"
  3. Result

    Inputs Ada, Ben and Cy replace any old contents with those three lines.

Worked example · Append one additional line

  1. Pseudocode
    DECLARE Line : STRING
INPUT Line
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", Line
CLOSEFILE "Names.txt"
  2. Result

    Input Dia adds a fourth line after Ada, Ben and Cy.

Core explanation · Exam essentials

  • Open an output once before writing its sequence, then close it afterwards.
  • Use APPEND to preserve earlier lines; repeated opening FOR WRITE discards them.
Common misconception

Opening the output FOR WRITE inside the loop repeatedly replaces the file; open it once before writing the sequence.

Check your understanding

What would happen if APPEND were changed to WRITE in the extension example?

Check your answer

The earlier names would be replaced and only the new line would remain.

03

Read lines with an end-of-file check

S10.07.A02

Visual overview

Read only when another line exists

After OPENFILE in READ mode, check EOF before each READFILE. READFILE copies the next line into a STRING variable and advances the file position. EOF becomes TRUE when there are no further lines to read. CLOSEFILE finishes access after the loop.

A blank value is still a successful read

A blank line is still a line and can be read as an empty string. It is different from reaching the end of the file. The example outputs and counts every line, including blank ones. For an empty file, the loop body is skipped and the count remains zero.

EOF and the current line are different facts

File state before the testEOFAction
No lines at allTRUESkip the body; output count 0 after closing.
Next line is empty, followed by BoFALSERead the empty string, count it, then test again.
Bo is the final unread lineFALSERead and process Bo.
Bo has already been readTRUEStop without another read.

Explain the pre-condition loop

A WHILE loop can perform zero reads and so handles an empty file naturally. Reading once before the first EOF test would assume a first line exists. An empty line does exist; an empty file has no line to return.

Worked example · Display and count stored lines

  1. Task

    Read all lines of Names.txt, output each one, close the file and output the number read.

  2. Pseudocode
    DECLARE Line : STRING
DECLARE Count : INTEGER
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count
  3. Result

    For Ari, a blank line and Bo, the outputs are Ari, an empty line, Bo and then 3. An empty file outputs only 0.

Core explanation · Exam essentials

  • Open FOR READ; test NOT EOF before each READFILE; process the STRING line and close after the loop.
  • A blank line contributes one read; an empty file contributes zero.
Common misconception

Line = "" does not prove EOF; a blank line may be followed by more data.

Check your understanding

Why is EOF tested before READFILE?

Check your answer

To prevent attempting to read a line when no unread line remains.

04

Save, extend and read the data back

S10.07.A01S10.07.A02

Visual overview

Connect saving to a later read

Use one named file throughout a complete lifecycle. Start with Names.txt containing Old. Opening FOR WRITE replaces Old; three writes create Ada, an empty line and Bo. Close before changing the access mode.

Check the stored file at each boundary

Append Cy in a second writing session, close again, then reopen FOR READ. The reading loop processes all four lines and reports the count after closing the file.

What is retained between sessions

The lifecycle below has three separate open/close sessions. A later execution can run the reader alone on the saved file. In this complete demonstration the sessions follow consecutively so every state is visible; reopening FOR READ does not recreate the earlier input array or numeric variables.

Predict before following the program

The deliberately blank second line must survive both the append and the reader. The reader outputs Ada, a blank line, Bo, Cy, then 4. Each successful READFILE increases Count once; the final failed continuation test performs no read.

Worked example · Complete the save-and-read-back cycle

  1. Task

    Names.txt initially contains Old. Replace it with Ada, a blank line and Bo; append Cy; then reopen it, display every line and output the count.

  2. Pseudocode
    DECLARE Line : STRING
DECLARE Count : INTEGER
OPENFILE "Names.txt" FOR WRITE
WRITEFILE "Names.txt", "Ada"
WRITEFILE "Names.txt", ""
WRITEFILE "Names.txt", "Bo"
CLOSEFILE "Names.txt"
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", "Cy"
CLOSEFILE "Names.txt"
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count
  3. Result

    Output lines: Ada; an empty line; Bo; Cy; 4. Final file lines: Ada; an empty line; Bo; Cy. Old is gone; all file sessions are closed.

Core explanation · Exam essentials

  • A complete save-and-load example writes data, closes, reopens, reads and shows the result.
  • Opening alone does not save data; reopening FOR READ does not erase it.
Common misconception

Writing and closing alone do not demonstrate reading the saved data back.

Check your understanding

If APPEND in this program becomes WRITE, what is read back?

Check your answer

Only Cy remains, followed by a line count of 1.

Read one file while writing a transformed copy

Swipe horizontally to compare every column →

Read one file and write a different file

Open an existing input file FOR READ and a different output file FOR WRITE. Every input line is read exactly once and produces one output line in this example.

Transform only the lines selected by the condition

A selection replaces an empty input line with the text [blank]; other lines pass through unchanged. Keeping the input and output names different prevents the output open from destroying the source.

Copy while replacing blank lines

  1. Open: Open the existing source FOR READ and a different destination FOR WRITE.
  2. Read: Check NOT EOF, then read the next STRING line.
  3. Choose the output: If the line is empty, write "[blank]"; otherwise write the original line.
  4. Finish: Close both files after every source line has been processed.

Source has Ada, an empty line, Bo

TaskDestination linesWhy
Copy and label blank linesAda; [blank]; BoOne output line per input line; order unchanged.
Copy only non-empty linesAda; BoThe blank line is read but deliberately not written.
Empty source in either taskNo linesThe loop is skipped; the newly opened output is empty.

Protect the supplied input and transfer the method

Do not use the source filename as the destination: opening it FOR WRITE would remove the lines before they can be read. The independent exercise changes the processing decision; it does not change the safe file-opening and EOF structure.

Worked example · Copy text and label blank lines

  1. Task

    Names.txt exists with Ada, a blank line and Bo. Replace Labelled.txt with a copy that labels each blank. Preserve source contents and close both files.

  2. Pseudocode
    DECLARE Line : STRING
OPENFILE "Names.txt" FOR READ
OPENFILE "Labelled.txt" FOR WRITE
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    IF Line = "" THEN
        WRITEFILE "Labelled.txt", "[blank]"
    ELSE
        WRITEFILE "Labelled.txt", Line
    ENDIF
ENDWHILE
CLOSEFILE "Names.txt"
CLOSEFILE "Labelled.txt"
  3. Result

    Labelled.txt has Ada, [blank], Bo. Names.txt is unchanged. For an empty source, the output is empty and both files still close.

Core explanation · Exam essentials

  • Use distinct source and destination names, guard each read, and apply the condition before writing.
  • Close both files; empty input must produce the specified empty output.
Common misconception

A blank line and an absent next line require different decisions.

Check your understanding

How would you omit blank lines instead of replacing them?

Check your answer

After reading, write Line only if Line <> ""; retain the EOF loop and close both files.

Original question · Cambridge 9618/22

1. Convert three-line records to one-line records

Cambridge 9618/22 · October/November 2025 · 3(a), 3(b) · 7 marks

Selected parts: 3(a) [6]; 3(b) [1].

Original insert · reference material

Reading the question — teacher guidance

Each valid old record consists of exactly three lines. Keep their order and put separators between fields, not between whole records.

Solution / model answer — teacher-written

Step 1: Open OldFile.txt in READ mode.

Step 2: Open NewFile.txt in WRITE mode.

Step 3: Read a line from OldFile.txt into LineX.

Step 4: Read the next line into LineY.

Step 5: Read the next line into LineZ.

Step 6: Set NewString to LineX & '\' & LineY & '\' & LineZ

Step 7: Write NewString as one line in NewFile.txt.

Step 8: Repeat from step 3 until the end of OldFile.txt.

Step 9: Close both files.

3(b): The separator is suitable because it does not appear in the information items in this file design.

Official mark scheme
Why this earns marks — teacher explanation

Part (a) has six marks for the missing operations, not one mark for each of nine steps. The given READ steps and closing step still matter to the complete algorithm. Part (b) gives one mark for distinguishing the separator from the data.

Common mistakes — teacher analysis

Opening NewFile.txt in WRITE inside the loop can overwrite earlier records. This question assumes valid records; a production implementation would also check EOF before attempting to read the first record of an empty file.

Lesson review

Summary

Persistence and modes

Files preserve data between runs; READ loads, WRITE replaces, and APPEND extends stored text.

Reading

Check EOF before each read and distinguish an empty string line from the end of the file.

Writing

Open the intended output once, write every required line and close it after processing.
