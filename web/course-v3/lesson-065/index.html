Build a booking system · Concept 23

Give the next run something to read

Observe

The register is needed in two executions

  • Today: the running program holds Mina and Jo.
  • Tomorrow: a new program execution must recover those names.

Look, then discuss

What must happen before today’s booking register can be reopened tomorrow?

The running program has Mina and Jo in memory. Tomorrow’s program starts a new execution. A saved file provides the data that the new execution can read.

Recall

Recall working variables and saved data

A record or array organises values during execution. Its declaration alone does not save those values to persistent storage.

Explain

Explanation · 1 / 3

Explain why a file is needed

Files retain saved data between program executions and allow programs to read or share that saved data later. A text file stores a sequence of text lines that the program can read in order.

Explanation · 2 / 3

Separate a variable from a file

Line is a STRING variable used while processing one line. "Bookings.txt" identifies the file. READFILE transfers text into Line; WRITEFILE transfers a value from the program into the file.

Explanation · 3 / 3

Plan the complete lifecycle

Open the file with the required mode, perform the reading or writing and close the file. Use different modes for reading existing content, creating replacement content and adding to existing content.

Work together

Follow one name between runs

Mina is entered today and must appear in tomorrow’s register.

Work together · 1 / 2

Save during the first run

The program writes the text Mina to a file and closes it. The persistent file contains the line independently of the current Name variable.

Work together · 2 / 2

Recover during the next run

The next program opens the file for reading and reads the line into a new variable. The program can then display or process Mina again.

Persistence requires a saved representation and later reading, not merely a larger array.

Check

Try it yourself · Teacher-written

A program displays all booking names before it exits. Does displaying them also save them in a text file?

Check your reasoning

No. OUTPUT displays data. Separate file operations are required to write a persistent file that a later run can read.

Connect

Keep this idea

Use files to retain data between program executions.

The opening mode determines whether writing replaces the old content or adds to it.

Build a booking system · Concept 24

Choose replacement or addition before writing

Observe

Existing Names.txt and a new arrival

SourceText
Existing line 1Mina
Existing line 2Jo
New inputSam

Look, then discuss

To add Sam to a register containing Mina and Jo, should the program open it FOR WRITE?

The existing register contains two lines: Mina and Jo. Compare the intended final files [Sam] and [Mina, Jo, Sam]. The choice of opening mode changes which result is produced.

Recall

Recall string values and one line

WRITEFILE writes the supplied text as a line to the open file. The variable supplying the line must already have a value. Opening, writing and closing are separate operations.

Explain

Explanation · 1 / 3

Use WRITE for new replacement content

Opening FOR WRITE creates a new file or replaces the existing contents. Use it when the requirement is to produce a fresh register. It is unsuitable when the old lines must be retained.

DECLARE Line : STRING
DECLARE Index : INTEGER
OPENFILE "Names.txt" FOR WRITE
FOR Index <- 1 TO 3
    INPUT Line
    WRITEFILE "Names.txt", Line
NEXT Index
CLOSEFILE "Names.txt"

Explanation · 2 / 3

Use APPEND to preserve earlier lines

Opening FOR APPEND places new writing after existing content. The program below adds one entered line and keeps the earlier lines.

DECLARE Line : STRING
INPUT Line
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", Line
CLOSEFILE "Names.txt"

Explanation · 3 / 3

Close the file after its operations

CLOSEFILE completes the program’s use of that open file. It belongs after the writing loop, not before later writes. Do not assume OUTPUT Line writes to the file; use WRITEFILE.

Work together

Predict the two resulting files

Names.txt initially contains Mina and Jo. The new line is Sam.

Work together · 1 / 2

Open FOR WRITE and write Sam

The old contents are replaced. After closing, the file contains one line, Sam.

Work together · 2 / 2

Start from the original file and open FOR APPEND

The old two lines remain and Sam is added as the third line. The final order is Mina, Jo, Sam.

State the required final contents before choosing the mode.

Check

Try it yourself · Teacher-written

A daily report must contain only today’s results. Which mode fits that requirement?

Check your reasoning

WRITE, because the report should contain a fresh set of results rather than retaining earlier results. APPEND is appropriate only when those earlier lines must remain.

Connect

Keep this idea

WRITE replaces content; APPEND adds after existing content.

Read every line, including a blank line

Observe

Names.txt contains three lines

Line numberContent
1Ada
2(empty string)
3Bo

Look, then discuss

Is a blank line the same as the end of the file?

Names.txt contains three lines: Ada, an empty line and Bo. The empty second line is real content. The end of the file comes after the third line.

Recall

Recall WHILE and NOT

WHILE checks its condition before entering the body. NOT reverses a Boolean result. NOT EOF(filename) is TRUE when another line is available to read.

Explain

Explanation · 1 / 3

Open in READ mode

FOR READ uses existing content as input. The next read begins at the file’s current read position, initially before its first line. A read moves that position forward.

Explanation · 2 / 3

Check EOF before each read

The loop reads only while NOT EOF is TRUE. An empty file therefore executes the body zero times. This avoids trying to read a line after all lines have been consumed.

DECLARE Line : STRING
DECLARE Count : INTEGER
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count

Explanation · 3 / 3

Process an empty string as a line

A blank line makes Line equal to "". It still came from a successful READFILE and still contributes one to a line count. EOF is a state of the file position, not a particular text value.

Work together

Count three lines

The file lines are Ada, an empty string and Bo.

Work together · 1 / 2

Read all available lines

Count begins at 0. Each successful read increments it: Ada gives 1, the blank line gives 2 and Bo gives 3.

Work together · 2 / 2

Stop after the last line

At the next test, EOF is TRUE and NOT EOF is FALSE. Close the file and output 3. No fourth READFILE occurs.

Test the file state rather than treating blank content as a stop marker.

Check

Try it yourself · Teacher-written

What does the same line-counting program output for an empty file?

Check your reasoning

0. EOF is already TRUE at the first loop test, so the body is skipped and Count remains at its initial value.

Connect

Keep this idea

Use NOT EOF before reading; a blank line is not the end of the file.

Build a booking system · Concept 26

Trace a complete save-and-recover cycle

Observe

Planned file operations

  • WRITE: Ada, an empty line, Bo
  • Close the file.
  • APPEND: Cy
  • Close, reopen FOR READ and count recovered lines.

Look, then discuss

After writing three lines and appending one line, how many reads should succeed?

The program writes Ada, a blank line and Bo, closes the file, reopens it to append Cy and finally reopens it for reading. Predict the order and count before tracing.

Recall

Recall mode and read position

Each OPENFILE establishes the mode for that phase. Closing and reopening FOR READ starts reading the saved content from its beginning. A later APPEND does not replace previous lines.

Explain

Explanation · 1 / 3

Separate the three phases

WRITE produces the initial three lines. APPEND adds a fourth. READ recovers all four. The STRING variable Line is reused for successive text values, but the file retains the full sequence.

Explanation · 2 / 3

Trace the complete program

Keep a separate record of the file contents and the current variables. A WRITEFILE changes saved content, while a READFILE updates Line and the read position.

DECLARE Line : STRING
DECLARE Count : INTEGER
OPENFILE "Names.txt" FOR WRITE
WRITEFILE "Names.txt", "Ada"
WRITEFILE "Names.txt", ""
WRITEFILE "Names.txt", "Bo"
CLOSEFILE "Names.txt"
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", "Cy"
CLOSEFILE "Names.txt"
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count

Explanation · 3 / 3

Verify the result by reading it back

The outputs are Ada, an empty line, Bo, Cy and then the count 4. The blank line remains part of the saved file. This checks more than merely observing that a write statement executed.

Work together

Locate a destructive mode mistake

Suppose the second OPENFILE uses WRITE instead of APPEND.

Work together · 1 / 2

Trace the replacement

The second WRITE opening discards the initial three-line content. Writing Cy leaves a file containing only Cy.

Work together · 2 / 2

Follow the effect into reading

The later read loop succeeds once and outputs a count of 1. The error originates in the opening mode, even though the EOF loop itself is correct.

When a recovered result is wrong, trace both the earlier write mode and the later read loop.

Experiment

The experiment begins with a file containing a blank line. Predict each mode’s effect before opening it. Read to EOF, compare WRITE with APPEND and reset the experiment before trying a second scenario.

Build a booking system · Concept 27
Transform complete records into output lines

    
Observe
BookingFields.txt input lines
Line numberText
1Mina
2Art
3A3
4Jo
5Music
6B2
Look, then discuss
How can three input lines become one output line without mixing two people’s details?
A teaching file stores each booking as three consecutive lines: name, event and seat code. Mina / Art / A3 is followed by Jo / Music / B2. Each group of three lines is one record.

    
Recall
Recall concatenation and file positions
The operator & joins strings. READFILE advances the input position by one line; WRITEFILE writes one output line. A separator marks the boundary between fields in the combined line.

    
Explain
Explanation · 1 / 3
Read one complete logical record
For this specified file format, every record contains exactly three lines and the file contains complete records. After the EOF test, read all three fields in order before processing the next record.
Explanation · 2 / 3
Join fields with an unambiguous separator
Join the three strings with | when that character is excluded from every field by the file design. A separator that can occur inside a field would need an additional escaping or quoting rule.
DECLARE Name : STRING
DECLARE Event : STRING
DECLARE SeatCode : STRING
DECLARE Combined : STRING
OPENFILE "BookingFields.txt" FOR READ
OPENFILE "BookingRows.txt" FOR WRITE
WHILE NOT EOF("BookingFields.txt")
    READFILE "BookingFields.txt", Name
    READFILE "BookingFields.txt", Event
    READFILE "BookingFields.txt", SeatCode
    Combined <- Name & "|" & Event & "|" & SeatCode
    WRITEFILE "BookingRows.txt", Combined
ENDWHILE
CLOSEFILE "BookingFields.txt"
CLOSEFILE "BookingRows.txt"
Explanation · 3 / 3
Keep format assumptions explicit
The outer EOF check is sufficient here because complete three-line records are guaranteed. If incomplete records were possible, check for each remaining line and handle an incomplete record instead of blindly reading past EOF. Follow the given separator and format in the past paper.

    
Work together
Trace six input lines into two output lines
The input lines are Mina, Art, A3, Jo, Music and B2. No field contains |.
Work together · 1 / 2
Process the first record
The first three reads give Mina, Art and A3. Write the single line Mina|Art|A3.
Work together · 2 / 2
Process the second record and finish
The next three reads give Jo, Music and B2. Write Jo|Music|B2. The following EOF test ends the loop. Close both files; six input lines have become two output lines.
Use the record format to decide how many reads belong to one output record.

Why is a separator unsuitable if it can appear unescaped inside a name?
Check your reasoning
A later reader could not reliably distinguish a field boundary from the same character belonging to the name. Choose a separator excluded by the data rules or define an escaping/quoting format.

Original question · Cambridge 9618/22
1. Convert three-line records to one-line records
Cambridge 9618/22 · October/November 2025 · 3(a), 3(b) · 7 marks
Selected parts: 3(a) [6]; 3(b) [1].
Original insert · reference material
Hint — reading the question
Each valid old record consists of exactly three lines. Keep their order and put separators between fields, not between whole records.
Reasoning and model answer — teacher-written
Step 1: Open OldFile.txt in READ mode.
Step 2: Open NewFile.txt in WRITE mode.
Step 3: Read a line from OldFile.txt into LineX.
Step 4: Read the next line into LineY.
Step 5: Read the next line into LineZ.
Step 6: Set NewString to LineX & '\' & LineY & '\' & LineZ
Step 7: Write NewString as one line in NewFile.txt.
Step 8: Repeat from step 3 until the end of OldFile.txt.
Step 9: Close both files.
3(b): The separator is suitable because it does not appear in the information items in this file design.
Official mark scheme
Why this earns marks — teacher explanation
Part (a) has six marks for the missing operations, not one mark for each of nine steps. The given READ steps and closing step still matter to the complete algorithm. Part (b) gives one mark for distinguishing the separator from the data.
Common mistakes — teacher analysis
Opening NewFile.txt in WRITE inside the loop can overwrite earlier records. This question assumes valid records; a production implementation would also check EOF before attempting to read the first record of an empty file.
