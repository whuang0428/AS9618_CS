Why files are needed and text-file pseudocode

Keep text between executions and choose file operations that preserve or replace the intended lines.

How can a program retain text and process every stored line?

Before you start

If a program terminates, will its array automatically be available at the next run?

No. Data needed later must be saved to persistent storage, for example a file.

Select the correct file mode

Core explanation

Why storage must outlive the program

Files retain data on secondary storage after a program terminates and allow another program to reuse it. Variables and arrays alone do not provide this persistence. A text file is a sequence of lines.

Select the OPENFILE mode
ModeEffect
READRead existing lines.
WRITECreate a file or replace its existing contents; suitable for a fresh report.
APPENDAdd at the end while retaining existing contents; suitable for extending a log.

Common misconception

WRITE is not interchangeable with APPEND when old lines must remain.

Which mode extends an existing attendance log?

Check your answer

APPEND, because earlier entries must be retained.

02

Read lines with an end-of-file check

S10.07.A02

Visual overview

Core explanation

Read every available line safely
  1. Open: OPENFILE in READ mode.
  2. Guard and read: Check NOT EOF before each READFILE. The read copies the next line into a STRING and advances the position.
  3. Process: Output, count or otherwise use the line, then return to the EOF check.
  4. Close: CLOSEFILE after the loop.
Distinguish data from the file position

A blank line is an empty string, not end of file, and still counts as one line. EOF becomes TRUE when no further lines remain. An empty file skips the loop and leaves the count at zero.

Worked example · Display and count stored lines

  1. Task

    Read all lines of Names.txt, output each one, close the file and output the number read.

  2. Pseudocode
    DECLARE Line : STRING
DECLARE Count : INTEGER
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count
  3. Result

    For Ari, a blank line and Bo, the outputs are Ari, an empty line, Bo and then 3. An empty file outputs only 0.

Common misconception

Line = "" does not prove EOF; a blank line may be followed by more data.

Check your understanding

Why is EOF tested before READFILE?

Check your answer

To prevent attempting to read a line when no unread line remains.

Write a new file and append a line

S10.07.A02

Visual overview

Swipe horizontally to compare every column →

Core explanation

WRITEFILE writes the supplied STRING as a line in an open text file. The complete example opens Names.txt FOR WRITE, inputs three lines, writes each line and closes the file. Existing contents are replaced, so this operation suits creating a fresh list.

To extend that list, use APPEND instead. Input a new line, open the same file FOR APPEND, write the line and close the file. Closing completes the file operation and releases the file. When copying between files, use different names so opening the output FOR WRITE cannot erase the input.

Worked example · Append one additional line

  1. Pseudocode
    DECLARE Line : STRING
INPUT Line
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", Line
CLOSEFILE "Names.txt"
  2. Result

    Input Dia adds a fourth line after Ada, Ben and Cy.

Worked example · Create a three-line file

  1. Task

    Input exactly three strings and save them as the replacement contents of Names.txt.

  2. Pseudocode
    DECLARE Line : STRING
DECLARE Index : INTEGER
OPENFILE "Names.txt" FOR WRITE
FOR Index <- 1 TO 3
    INPUT Line
    WRITEFILE "Names.txt", Line
NEXT Index
CLOSEFILE "Names.txt"
  3. Result

    Inputs Ada, Ben and Cy replace any old contents with those three lines.

Common misconception

Opening the output FOR WRITE inside the loop repeatedly replaces the file; open it once before writing the sequence.

Check your understanding

What would happen if APPEND were changed to WRITE in the extension example?

Check your answer

The earlier names would be replaced and only the new line would remain.

Question 1 · Command word: Explain3 marks

Explain why an attendance system saves a file at the end of a session. Select modes for loading yesterday's register and adding today's new entry.

S10.07.A01
Answer and marking points
  1. The file retains attendance data for later executions.
  2. Use READ to load yesterday's register.
  3. Use APPEND to add an entry while preserving existing lines.

Common error: Persistence and retaining old lines are separate decisions.

Question 2 · Command word: State2 marks

State every output from the supplied line-counting algorithm for a file whose lines are Red, an empty line, and Blue and explain why the blank line does not end the loop.

Use this complete algorithm in the question.

DECLARE Line : STRING
DECLARE Count : INTEGER
Count <- 0
OPENFILE "Names.txt" FOR READ
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    OUTPUT Line
    Count <- Count + 1
ENDWHILE
CLOSEFILE "Names.txt"
OUTPUT Count
S10.07.A02
Answer and marking points
  1. It outputs Red, an empty line, Blue, then 3.
  2. EOF tests whether another line exists; an empty STRING value can be a valid stored line.

Common error: Do not confuse a blank line with end of file.

Question 3 · Command word: Write4 marks

Write complete pseudocode to replace Names.txt with exactly three input lines, including opening and closing the file.

S10.07.A02
Answer and marking points

One valid pseudocode solution

DECLARE Line : STRING
DECLARE Index : INTEGER
OPENFILE "Names.txt" FOR WRITE
FOR Index <- 1 TO 3
    INPUT Line
    WRITEFILE "Names.txt", Line
NEXT Index
CLOSEFILE "Names.txt"
  1. Declare a STRING line variable and INTEGER loop index.
  2. Open Names.txt FOR WRITE once before the loop.
  3. Repeat input and WRITEFILE for three iterations.
  4. Close Names.txt after the loop.

Common error: The write command must include both the filename and the line value.

Question 4 · Command word: Write3 marks

Write pseudocode to append one input line to Names.txt without losing its existing contents.

S10.07.A02
Answer and marking points

One valid pseudocode solution

DECLARE Line : STRING
INPUT Line
OPENFILE "Names.txt" FOR APPEND
WRITEFILE "Names.txt", Line
CLOSEFILE "Names.txt"
  1. Input a STRING value into Line.
  2. Open Names.txt FOR APPEND.
  3. Use WRITEFILE to write Line, then CLOSEFILE.

Common error: READ mode cannot be used to write the new line.

Question 1 · Command word: State · 3 marks

A program rewrites a daily report but must also retain all earlier entries in a cumulative log. State a suitable mode for each file and explain why the two modes differ.

Answer and marking points
  • Use WRITE for the daily report because its previous contents are to be replaced.
  • Use APPEND for the cumulative log because earlier entries must remain.
  • Both files retain information beyond the lifetime of the program's variables.

Common error: A replacement report and a cumulative log have different retention requirements.

Question 2 · Command word: Write · 6 marks

Write pseudocode to copy all non-empty lines from Names.txt to NonEmpty.txt, replacing any old output file. Preserve line order, close both files and handle an empty input file.

Answer and marking points

One valid pseudocode solution

DECLARE Line : STRING
OPENFILE "Names.txt" FOR READ
OPENFILE "NonEmpty.txt" FOR WRITE
WHILE NOT EOF("Names.txt")
    READFILE "Names.txt", Line
    IF Line <> "" THEN
        WRITEFILE "NonEmpty.txt", Line
    ENDIF
ENDWHILE
CLOSEFILE "Names.txt"
CLOSEFILE "NonEmpty.txt"
  • Declare a STRING line variable and open Names.txt FOR READ.
  • Open the different output file NonEmpty.txt FOR WRITE.
  • Check NOT EOF before each READFILE.
  • Read the next input line into Line.
  • Write Line only when Line <> "", preserving the read order.
  • Close both files after the loop; empty input produces an empty output file.

Common error: The output filename must differ from the input filename.

Question 3 · Command word: Write · 3 marks

A student opens Results.txt FOR WRITE before each of three WRITEFILE commands for A, B and C, closing after each command. State the final contents, explain the fault and describe the correction for writing all three lines.

Answer and marking points
  • Only the line C remains.
  • Each new OPENFILE FOR WRITE replaces the previous contents.
  • Open once before the three writes and close once afterwards.

Common error: The problem is repeated replacement, not EOF checking.

Lesson review

Summary

Persistence and modes

Files preserve data between runs; READ loads, WRITE replaces, and APPEND extends stored text.

Reading

Check EOF before each read and distinguish an empty string line from the end of the file.

Writing

Open the intended output once, write every required line and close it after processing.
