System software · Concept 01

Translate assembly mnemonics for a target processor

Observe

LDM #6
ADD #4
STO 200
END

Start with a question

Does the processor understand the printed letters in LDM and ADD as its native instruction bits?

Read the short assembly sequence below. It loads 6 into a working register, adds 4, stores the result and finishes. The printed source is a readable way to specify the work; it is not the target instruction encoding.

Recall

Use what you already know

Source, machine code and assembly

Source code is the program text supplied to a translator. Machine code uses instruction encodings for a processor. Assembly language represents low-level instructions with mnemonics, such as ADD, and operands that specify the values or locations involved.

Explain

Explanation · 1 / 4

Read what the source asks for

In the Cambridge teaching instruction set, LDM #6 loads the immediate value 6 into the accumulator, a working register. ADD #4 adds the immediate value 4. STO 200 stores the result at address 200, which we reserve as a writable result location. END finishes the program. The # marks an immediate value.

LDM #6
ADD #4
STO 200
END

Explanation · 2 / 4

Use an assembler for that instruction set

An assembler translates assembly-language mnemonics and operands into target machine-code encodings. It must understand the relevant processor’s instruction set. A high-level language such as Java needs a different translation route; an assembler does not translate arbitrary Java statements.

Explanation · 3 / 4

Separate translation from running

Translating ADD #4 creates an encoding of an addition instruction. It does not itself carry out the program’s addition. When the translated program later executes, the accumulator changes from 6 to 10 and 10 is written at address 200.

Explanation · 4 / 4

Locate object code and linking in the route

Assembler output may be object code, a translated module that still requires linking, or a complete executable. A linker combines required modules and resolves references between them. This connects to libraries: a translated call must be connected to the routine it uses before or during execution, according to the linking approach.

Experiment

Select assembly source and choose the assembler. Explain the output before switching to high-level source and identifying why a different translator is required.

Check

Explain it yourself · Teacher-written

The assembler translated the four instructions successfully. Has that translation already put 10 into the program’s result location?

Check your reasoning

No. Translation produces target instructions. Executing those instructions performs the addition and stores 10 at address 200.

Connect

Keep this idea

An assembler translates assembly-language instructions into machine or object code for the target processor.

A high-level program can also be translated before it runs. Its source and built executable remain separate versions.

Check a common misunderstanding

Do not invent binary encodings without an instruction-set specification or confuse translation with execution.

System software · Concept 02

Build one version, then execute that version

Observe

DECLARE Count : INTEGER
DECLARE Total : INTEGER
Count <- 0
Total <- 0
WHILE Count < 3
    Total <- Total + 2
    Count <- Count + 1
ENDWHILE
OUTPUT Total

Start with a question

If the source now says “add 4”, why might Run still display the old result 6?

Version A adds 2 three times and outputs 6. Version B changes that increment to 4 and should output 12. Track the saved source and the last successful executable as two separate artifacts.

Recall

Use what you already know

Read the calculation

DECLARE introduces a variable. The assignment arrow <- stores a value. WHILE checks its condition before each repetition; ENDWHILE returns to that test. Count increases on each repetition, so this loop eventually finishes.

Explain

Explanation · 1 / 4

Understand the source before translating it

Both variables start at 0. Each loop body adds 2 to Total and 1 to Count. The body runs while Count is 0, 1 and 2; it stops when Count becomes 3. The last statement displays Total, which is 6. The listing is Cambridge pseudocode used to model behaviour, not source for an unspecified real compiler.

DECLARE Count : INTEGER
DECLARE Total : INTEGER
Count <- 0
Total <- 0
WHILE Count < 3
    Total <- Total + 2
    Count <- Count + 1
ENDWHILE
OUTPUT Total

Explanation · 2 / 4

Compile and link before native execution

In the native compilation model, a compiler translates a high-level program or compilation unit into target code before it executes. A build can include linking object modules and required routines into an executable. The native executable must be suitable for the target processor and system.

Explanation · 3 / 4

Track the version that was built

Editing and saving source changes the source file. It does not automatically replace an existing executable. A successful rebuild of version B produces the new program; Run must launch that new build to show 12.

ActionSaved sourceLast successful buildRun output
Build A, then runA: add 2A6
Save edit to B, then run without rebuildingB: add 4A6
Build B successfully, then runB: add 4B12

Explanation · 4 / 4

Interpret build feedback carefully

Translation diagnostics describe detected source problems. A successful build does not prove the algorithm correct: subtraction can be valid syntax when addition is required. A later runtime failure can also occur. If a build fails, any retained old executable is still the older version, not a successful translation of the invalid edit.

A compiler reports no errors for a program that subtracts instead of adding. What still needs checking?

Check your reasoning

Connect

Keep this idea

A compiler translates source before execution. A changed native source version needs a successful new build before the executable reflects it.

Start with a question

If a loop body appears once in the source, why can an interpreter carry it out three times?

Return to version A: Count and Total begin at 0, the body adds 2 and increases Count, and the limit is 3. Before each pass, decide whether Count < 3 is true.

Explain

Explanation · 1 / 5

Place the interpreter in the execution route

An interpreter is software that carries out the program as execution progresses. In this high-level interpretation model, statements are translated and executed along the selected control path instead of first saving a separate permanent native executable for the whole source. The interpreter itself runs on the computer.

Explanation · 2 / 5

Follow tests, repetition and skipped paths

A loop can revisit the same statement; a branch can skip one. Therefore “line by line” should not be read as “each displayed line exactly once from top to bottom”. For the same complete version A listing, the condition is checked four times and the body runs three times.

Explanation · 3 / 5

Change a condition and predict the route

If the limit is 0, the initial check 0 < 0 is false. No loop body runs and Total stays 0. In the lab’s additional branch, choosing false skips its marked branch action. The loop still follows its own limit; a skipped branch does not automatically skip everything after it.

Explanation · 4 / 5

Connect feedback to the executed work

An interpreting environment can provide prompt feedback while trying usable parts of a developing program. Earlier statements may execute before a later runtime failure. For example, with numeric input 0, the complete program below outputs Starting and then encounters division by zero in the stated environment; it never reaches the last output. This is a runtime error example, not a rule about when all interpreters detect syntax errors.

DECLARE Count : INTEGER
DECLARE Average : REAL
INPUT Count
OUTPUT "Starting"
Average <- 12.0 / Count
OUTPUT Average

Explanation · 5 / 5

Read a simplified stop-and-correct model

In the usual introductory comparison, a compiler produces an executable file from source code before execution. The interpreter instead works as execution proceeds, stops when it encounters an error and supplies immediate feedback. An interactive environment can let the programmer correct the problem and continue supported work; another environment may require a restart. Follow the conditions given in a question rather than assuming every implementation resumes in the same way.

    Connect

    Keep this idea

    Interpretation translates and executes as the program proceeds; branches and loops determine which statements are reached and repeated.

    Both approaches can carry out the calculation. Their different workflows help decide which suits a development or delivery requirement.

    Check a common misunderstanding

    An interpreter is not required to visit every source line exactly once, and it does not normally create the separate permanent native executable in this model.

    Question 2 · Command word: State4 teacher marks

    Source A outputs 6 and its native executable has been built successfully. The developer saves source B, which should output 12, but has not rebuilt. State what happens when the old executable runs, describe how to obtain the new result, and explain why a successful build can still produce an unintended result.

    S5.04.A02
    Answer and checking points — teacher-written
    1. The old executable still outputs 6 because it contains the translated version A.
    2. Compile B and link required modules successfully to produce an updated native executable.
    3. Run that updated executable on a compatible system to obtain 12 for the stated correct source B.
    4. A build can accept valid language constructs that implement the wrong algorithm; test results against the requirement.

    Common error: Saving source, completing a build and launching a particular build are separate actions.
