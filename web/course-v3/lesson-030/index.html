01

Assembly source to target instructions

S5.04.A01

Visual overview

A small assembly routine

  1. Source notationProcessor-specific mnemonics and operands in a source file
  2. AssemblerEncodes these instructions for the specified teaching processor.
  3. Object or executable codeContains target instruction encodings; linking is performed if required.

Core explanation

Assembly language represents processor instructions using mnemonics and operands. An assembler converts a program written in that notation into the machine-code instruction encodings for its target processor; it does not translate high-level source such as Java.

The output may be a complete machine-code program or an object-code module that still requires linking. A linker combines modules and resolves references between them before a complete executable can be loaded. The instruction set determines which mnemonics and encodings are valid.

Worked example · Trace meaning before translation

  1. Cambridge assembly source
    LDM #6
ADD #4
STO 200
END
  2. Accumulator

    LDM loads 6; ADD changes the accumulator to 10.

  3. Stored result

    STO writes 10 to memory address 200.

  4. Translation

    An assembler supplies the binary encodings; the source mnemonic characters are not the executable instructions.

Common misconception

An assembler translates a particular assembly language; it is not a high-level-language compiler.

Check your understanding

Which translator accepts the mnemonic STO in this processor's assembly language?

Check your answer

An assembler for that instruction set.

02

Compilation before execution

S5.04.A02

Visual overview

Build and run are separate operations

  1. EditChange the high-level source.
  2. TranslateProduce target code or report translation errors.
  3. Link if requiredCombine modules and required routines.
  4. ExecuteRun the successfully built version.

Core explanation

In the native compilation model, a compiler translates high-level source as a whole program or compilation unit into machine code before that code executes. Object-code modules can be linked into a complete executable. Some compilers instead target an intermediate representation, as in the Java example in the next lesson.

Translation diagnostics identify detected source problems. A source correction must be translated again before the built program reflects that correction. Successful compilation does not prove that the algorithm is correct or prevent every run-time error.

Common misconception

Saving changed source does not update an older executable automatically.

Check your understanding

An executable still displays yesterday's message after its source is edited. What step may be missing?

Check your answer

The edited source has not been successfully rebuilt, or the user is running the old build.

Translation during execution

S5.04.A03

Visual overview

Execution order is not just page order

Program constructWhat execution does
SequenceProceeds to the next statement
SelectionFollows the selected branch
IterationReturns to statements while the loop continues

Swipe horizontally to compare every column →

Core explanation

In the high-level interpretation model, an interpreter translates and executes statements as execution proceeds rather than first producing a separate permanent native executable for the complete source program. The interpreter itself is software running on the computer.

Execution follows control flow. A loop can cause the interpreter to process the same statement repeatedly; a branch can skip statements. An error encountered during execution can stop progress at that point. Partial execution and immediate feedback are useful when investigating a developing program.

Common misconception

Statement-by-statement execution does not mean every source line is executed exactly once.

Check your understanding

A loop repeats its body five times. Is the body executed only once because it occupies one source location?

Check your answer

No. Execution revisits the loop body five times.

Practice questions

Question 1 · Command word: Explain2 marks

Explain why an assembler is needed for a routine written in the target processor's assembly language.

S5.04.A01
Answer and marking points
  1. The source uses human-readable mnemonics and operands rather than the required instruction encodings.
  2. The assembler converts that notation into machine or object code for the target instruction set.

Common error: Name both the source form and the required translated form.

Question 2 · Command word: Describe3 marks

Describe what a compiler produces and explain why changing source code does not by itself change an existing executable.

S5.04.A02
Answer and marking points
  1. A compiler translates high-level source into target code, such as native machine code, before the resulting program runs.
  2. The executable represents a previously translated version.
  3. The changed source must be successfully rebuilt for the change to appear in a new executable.

Common error: Do not assume the source file and executable file are the same artifact.

Question 3 · Command word: Describe3 marks

Describe how an interpreter executes a high-level program containing a loop, and state whether it must first save a separate native executable of the whole program.

S5.04.A03
Answer and marking points
  1. It translates and carries out statements as execution progresses.
  2. Statements in the loop body are revisited for successive iterations.
  3. This interpretation model does not require a saved native executable of the entire source before execution.

Common error: A loop changes the order and frequency of execution.

Question 1 · Command word: Identify · 3 marks

A technician has one file containing LDM, ADD and STO instructions and another containing Java class declarations. Identify the appropriate initial translator for each file and explain why the first translator cannot simply translate both languages.

Answer and marking points
  • Use an assembler for the file of assembly instructions.
  • Use a Java compiler for the Java source file.
  • The assembler recognises its processor-specific assembly syntax rather than Java's high-level language constructs.

Common error: Select from the actual source language, not from the file's length.

Question 2 · Command word: Explain · 3 marks

A build produces an object module that refers to a routine in a second module. Explain why successful compilation of the first module may not yet provide a complete executable, and why a completed build can still give the wrong numerical answer.

Answer and marking points
  • Linking must supply the required routine and resolve the reference between the modules.
  • The first object module alone may therefore lack a complete runnable set of instructions.
  • Translation and linking do not prove that the program implements the intended calculation; a logic error can remain.

Common error: Separate missing external code from an incorrect algorithm.

Question 3 · Command word: Explain · 3 marks

An interpreted script displays a heading, then stops when a later statement tries to divide by zero. Explain why the displayed heading does not prove that the whole script is correct, and identify what the developer should investigate.

Answer and marking points
  • Statements before the failing operation can execute and produce output before that later failure occurs.
  • Progress up to the heading is not evidence that subsequent statements will execute successfully.
  • The developer should inspect the divisor and the path that allowed it to be zero at the failing statement.

Common error: Do not infer whole-program correctness from one successful output.

Lesson review

Summary

Assembler

Translate processor-specific mnemonics into the target instruction encoding.

Compiler

Translate source before running the resulting build; linking may also be necessary.

Interpreter

Carry out statements progressively along the program's control flow.

Correctness

A translated or partly executed program still needs testing against its intended result.
