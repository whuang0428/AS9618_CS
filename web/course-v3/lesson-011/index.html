Communicate data · Concept 10

Connect a computer to its first network link

Observe

Two entrances to the school network

  • A desktop uses an Ethernet cable.
  • A tablet uses a wireless network interface.
  • The wireless link reaches an access point with an onward network connection.

Look, then discuss

Where does the computer’s data become a signal suitable for its first link?

Discuss the observation

The network interface joins a computer to a communication medium. Its job differs from storing the requested timetable or deciding a route across distant networks.

Explain

Explanation · 1 / 4

Identify a NIC

A network interface card or controller, NIC, provides an interface between the computer and its network link. It sends and receives data using the link’s signalling and communication rules. A wired Ethernet interface connects through a suitable cable.

Explanation · 2 / 4

Identify a WNIC

A wireless network interface card or controller, WNIC, handles wireless communication using radio. It enables the tablet to communicate with compatible local wireless equipment. It does not mean the tablet itself provides the school’s internet service.

Explanation · 3 / 4

Explain the access point

A wireless access point, WAP, gives wireless clients access to a LAN and connects their wireless communication to the wider local network. It needs power and onward connectivity. Its role differs from a server supplying files and a router forwarding between networks.

Explanation · 4 / 4

Introduce local interface addresses

Ethernet and WiFi interfaces use link-layer addresses commonly called MAC addresses. At this stage, treat them as local interface labels used in frame delivery. They are different from the IP addresses used for routing, which are introduced later.

Work together

Trace the tablet’s first steps

A tablet requests a timetable stored on the school network.

Work together · 1 / 3

Leave the tablet

The application’s data is handled by the tablet’s WNIC and transmitted as a wireless signal.

Work together · 2 / 3

Reach local equipment

The WAP receives the wireless communication and connects it to the LAN.

Work together · 3 / 3

Continue towards the service

Other local equipment forwards the data towards the timetable server. The WAP does not become the timetable file simply because the request passes through it.

Name the interface, medium and access device without confusing them with the requested service.

Check

Try it yourself · Teacher-written

Explain the difference between a WNIC in a tablet and a WAP mounted in a classroom.

Check your reasoning

The tablet’s WNIC provides its wireless network interface and sends/receives radio communication. The classroom WAP provides wireless access to the LAN for compatible clients and has an onward network connection. They occupy different roles in the same first-hop path.

Connect

Keep this idea

NICs and WNICs connect individual devices; a WAP provides wireless access to the local network.

Once the data reaches the LAN, a switch can forward it towards the correct local interface.

Check a common misunderstanding

A WiFi symbol does not identify a router, an internet connection or a file server.

Communicate data · Concept 11

Separate forwarding a frame from answering its request

Observe

The switch has learned where devices connect

Switch portKnown connected interface
1Classroom client A
2Timetable server T
3Printer P

Look, then discuss

If client A requests the timetable from T, which device chooses the outgoing port and which device prepares the timetable response?

Discuss the observation

The switch passes communication through a suitable local port. The server performs the requested service. Both participate, but they solve different problems.

Explain

Explanation · 1 / 4

Package local communication

A frame is a structured unit of link-level communication containing data and control information, including local source and destination addressing. The destination MAC address identifies the intended local interface for the frame.

Explanation · 2 / 4

Use the switch’s forwarding information

A switch uses destination MAC information and its forwarding table to select an appropriate outgoing port. In this example the destination is already known, so it sends towards that port rather than sending through every workstation.

Explanation · 3 / 4

Explain how the server responds

The server receives the request, checks any applicable permission, performs the service and prepares a response. Providing the timetable, managing accounts and storing files are service jobs. A switch does not understand the timetable’s meaning in order to forward a frame.

Explanation · 4 / 4

State the model boundary

A switch can learn interface locations from received frames. If a destination is unknown, forwarding behaviour differs from this known-port example; do not turn the simplified table into a promise that every frame is always sent through exactly one output. Learning-table details are optional here.

Work together

Send the request and return the response

Client A connects to port 1, server T to port 2 and printer P to port 3. The switch already knows their MAC locations.

Work together · 1 / 3

Forward towards T

A sends a frame addressed to T. The switch receives it on port 1 and forwards through port 2.

Work together · 2 / 3

Perform the service

T checks the request and prepares the timetable response. P is not the requested service.

Work together · 3 / 3

Forward back towards A

The response is addressed back towards A. The switch uses its table to forward it through port 1.

The two directions use addressing and forwarding; the service is performed at the server.

Check

Try it yourself · Teacher-written

The printer is on port 3 and the timetable server on port 2. Explain why forwarding a timetable request to port 2 is not the same operation as retrieving the timetable.

Check your reasoning

The switch selects the outgoing port using the destination’s local address and forwarding information. The server then processes the application request and retrieves or generates the timetable. Port selection moves the communication towards the service; it does not perform that service.

Connect

Keep this idea

A switch forwards local frames; a server provides the requested service.

Other devices solve narrower problems: separating local segments or regenerating a weakened signal.

Communicate data · Concept 12

Separate segment filtering from signal regeneration

Observe

Two different problems

  • Unnecessary local traffic crosses into another LAN segment.
  • A signal becomes too weak or distorted along a link.
  • One problem concerns forwarding decisions; the other concerns signal quality.

Look, then discuss

Which problem needs knowledge of a destination address, and which needs reconstruction of a signal?

Discuss the observation

Devices are easier to distinguish when you name their input, decision and output. A box labelled “network equipment” is not enough.

Explain

Explanation · 1 / 4

Connect and filter LAN segments

A bridge connects LAN segments and uses MAC-address information to decide whether a frame needs to cross between them. If sender and known destination are on the same segment, it can avoid forwarding the frame into the other segment.

Explanation · 2 / 4

Forward when the destination is across the bridge

If the known destination belongs to the other segment, the bridge forwards the frame across. This can reduce unnecessary traffic between segments. Unknown and broadcast traffic need appropriate handling; the activity focuses on destinations whose locations are known.

Explanation · 3 / 4

Regenerate the physical signal

A repeater receives a signal and regenerates or reshapes it for continued transmission. It helps extend a suitable link within the technology’s limits. Its task is not to read a destination address and choose a route, and it cannot repair an arbitrary corrupted message by knowing what the sender meant.

Explanation · 4 / 4

Compare by responsibility

Bridge: inspect link-level addressing and filter or forward between segments. Repeater: regenerate a signal. A switch performs related bridging functions across multiple ports. A router, introduced after addressing, forwards between networks using IP information.

Work together

Choose a device for each fault report

A and B are on segment X; C is on segment Y. Separately, a permitted link needs regeneration at an intermediate point.

Work together · 1 / 3

Keep A-to-B traffic local

A bridge knowing both addresses are on X can avoid forwarding that frame into Y.

Work together · 2 / 3

Carry A-to-C traffic across

The bridge forwards towards Y because C is on the other segment.

Work together · 3 / 3

Solve the signal problem

Use suitable repeater equipment to regenerate the signal. It does not replace the bridge’s destination-based decision.

Match the equipment to the layer of the problem: forwarding or physical signalling.

Check

Try it yourself · Teacher-written

Would replacing a bridge with a repeater preserve its ability to keep known same-segment traffic out of another segment? Explain.

Check your reasoning

No. A bridge uses address information to filter or forward frames between segments. A repeater regenerates signals and does not make that destination-based filtering decision.

Connect

Keep this idea

A bridge filters local traffic between segments; a repeater regenerates signals.

With the local equipment identified, use topology diagrams to predict complete physical paths.

Check a common misunderstanding

Repeating a signal does not mean routing it towards the correct destination.

  • Describe bridge and repeater roles.

Communicate data · Concept 25

Send a packet towards another network

Observe

Two destinations from the same classroom

  • A local school server shares the client’s subnet.
  • A remote course server belongs to another network.
  • The school client has a configured default gateway.

Look, then discuss

Why can the same switch be involved in both requests while only the remote one requires a router?

Discuss the observation

The first local link and the complete IP destination are different parts of delivery. The client must reach its gateway locally before a router can forward onwards.

Explain

Explanation · 1 / 4

Recall the local-or-remote decision

In the simple LAN model, a client compares the destination address with its local subnet. A destination on that subnet can be reached locally. For a destination outside it, the client normally sends towards a configured router, often called its default gateway.

Explanation · 2 / 4

Explain the router’s decision

A router connects networks and examines a packet’s destination IP address. It uses routing information to select an outgoing interface or next hop. The next hop may be another router; one router does not need a direct cable to every final destination.

Explanation · 3 / 4

Keep a frame’s next hop separate

On the first Ethernet link, the frame is addressed to the local next-hop interface. For a remote destination that is the gateway interface, while the packet inside identifies the remote IP destination. A switch forwards the local frame; the router handles the packet’s onward network delivery.

Explanation · 4 / 4

Allow a separate return path

The server’s response also needs valid addressing and routing back to the client. The route can involve several networks. Successful outgoing transmission does not prove that the service has answered or that every return-path dependency works.

Work together

Reach a remote course server

Client 192.168.1.10/24 uses gateway 192.168.1.1. A hypothetical remote course server is 203.0.113.60, a documentation address. Assume working onward routing and a suitable gateway address-translation arrangement for public internet access; focus on the first local hop.

Work together · 1 / 3

Compare prefixes

The client’s local /24 prefix is 192.168.1. The remote address does not share it, so this is not ordinary same-subnet delivery.

Work together · 2 / 3

Reach the gateway locally

The client sends through the local network towards the gateway interface. The switch uses local frame addressing for that hop.

Work together · 3 / 3

Route onwards

The gateway router uses the packet’s destination IP address and its routing information to forward towards the remote network. The web server, not the router, will answer the course-resource request.

Local frame forwarding and inter-network packet routing are consecutive jobs.

Check

Try it yourself · Teacher-written

Explain why a switch and a router have different roles when a school laptop contacts a remote server.

Check your reasoning

The switch uses local link-level destination addressing to forward a frame through an appropriate LAN port. The router examines the packet’s destination IP address and uses routing information to forward it between networks. The initial local frame can be addressed to the gateway while its packet is destined for the remote server.

Cambridge 9618/11 · October/November 2023 · 2(a), 2(b) · 6 marks

Hint — reading the question

In 2(a), describe the router receiving, inspecting and forwarding a packet. In 2(b), give the function of each named device; the three devices need different descriptions.

Reasoning and model answer — teacher-written

The router receives a packet, examines its destination IP address and consults its routing information to forward it towards the destination on an appropriate network.

DevicePurpose
SwitchConnects devices within a LAN and forwards received frames towards the destination device.
Wireless Access Point (WAP)Connects wireless devices to the wired LAN using radio signals.
BridgeConnects LAN segments using the same link-layer protocol and forwards traffic between them when needed.

The router scheme includes functions often bundled into a combined internet gateway. Those optional functions are not required properties of every router, and the three-point routing explanation does not depend on using them.

Communicate data · Concept 15

Package data for an Ethernet link

Observe

A payload needs delivery information

  • The requested timetable data is the payload.
  • Local source and destination fields identify the communicating interfaces.
  • Error-checking information helps the receiver detect damaged data.

Look, then discuss

Why is sending only the timetable’s data insufficient for a shared communication system?

Discuss the observation

Equipment needs boundaries, addressing and error-checking information as well as useful content. A frame puts those different jobs into a structured link-level unit.

Explain

Explanation · 1 / 4

Define Ethernet by its rules

Ethernet is a family of standards for wired local-network communication. It defines aspects of physical transmission and link-level frames. It is not a name for every network cable, every internet connection or WiFi.

Explanation · 2 / 4

Separate frame fields from payload

An Ethernet frame carries data together with control information, including source and destination MAC addresses and error-checking information. The addresses guide local delivery; the payload is the data being transported, which can contain an IP packet.

Explanation · 3 / 4

Explain an error check carefully

The sender includes an error-detection value calculated from frame data. The receiver checks the received frame using the corresponding rule. A failed check indicates that the frame should not be accepted as intact; the check does not itself reconstruct any arbitrary damaged data.

Explanation · 4 / 4

Distinguish shared and switched links

Older shared half-duplex Ethernet permits only one successful transmission on the shared medium at a time and uses collision detection. Modern switched full-duplex links can send and receive simultaneously on their separate link and do not use CSMA/CD to arbitrate normal traffic.

Work together

Read a frame without confusing its fields

Client A sends course data towards local interface B using Ethernet.

Work together · 1 / 3

Identify the addresses

The source MAC identifies A’s sending interface and the destination MAC identifies the intended local receiver for this frame.

Work together · 2 / 3

Identify the carried data

The payload transports the useful data or a higher-level packet. The destination field is not the timetable’s text.

Work together · 3 / 3

Check on reception

The receiver checks the frame. The link’s control information supports delivery and integrity checks while the application interprets the content.

A frame is a structured carrier of data, not a synonym for the application’s whole file.

Experiment

Predict which parts help local delivery and which part holds the carried data. Step through the frame path before revealing the receiver’s check.

Check your reasoning

Ethernet defines wired network communication, carries data in frames, and uses local addressing and error-checking information. Ethernet frames combine carried data with local addressing and link-level control information.

A shared Ethernet medium has another problem: two devices may try to transmit at nearly the same time.

Communicate data · Concept 16

Listen, detect a collision, stop and retry after a random delay

Observe

Two senders share a half-duplex Ethernet medium

  • A and B both observe an idle channel.
  • Each starts before the other signal has reached it.
  • Their transmissions overlap and cannot be received as intended.

Look, then discuss

Why can a collision still happen when both devices listened first?

Discuss the observation

Signals take time to propagate. Each sender can observe an idle channel before the other transmission reaches it. Listening reduces conflict but does not eliminate that timing possibility.

Explain

Explanation · 1 / 5

Expand the name into actions

CSMA/CD means Carrier Sense Multiple Access with Collision Detection. Carrier sense means checking whether the shared medium is busy. Multiple access means several devices may attempt to use it. Collision detection means monitoring for overlapping transmissions while sending.

Explanation · 2 / 5

Start only when the channel is available

A device with data checks the shared channel. If it is busy, the device waits; if it is idle, it may begin. Two devices can begin close enough together that their signals overlap before either could sense the other.

Explanation · 3 / 5

Stop the failed attempt

When a collision is detected, transmission is stopped and a jamming signal makes the collision evident on the shared medium. Continuing to send the rest of the frame would waste time because this attempt has failed.

Explanation · 4 / 5

Use a random backoff, then check again

Each sender chooses a backoff delay. Different choices help separate their next attempts; an identical fixed delay could make them collide repeatedly. After the delay, the device still checks whether the channel is available before retrying. Random choice reduces repeated conflict but cannot guarantee that the next choices differ.

Explanation · 5 / 5

Keep the scope explicit

This procedure belongs to shared half-duplex Ethernet. Do not apply it to WiFi or claim that normal switched full-duplex Ethernet uses collision detection to decide who may transmit.

Work together

Compare equal and different retry delays

A and B collide on a shared half-duplex medium. For this first-collision example each selects zero or one backoff slot; other mandatory Ethernet timing intervals are outside this simplified trace.

Work together · 1 / 3

Try equal waits

If both choose zero backoff slots and both find the channel idle when they are permitted to retry, their next starts may overlap again.

Work together · 2 / 3

Try different waits

If A chooses zero slots and B chooses one, A may start first. When B is ready it must check the channel and wait if A is still using it.

Work together · 3 / 3

Explain the mechanism

Random backoff spreads competing retries over time. The final channel check prevents a completed wait from being treated as permission to interrupt another sender.

Both the random delay and the renewed channel check contribute to recovery.

Predict why listening can still lead to a collision. Step through the failure and recovery, then choose equal backoff delays and compare the next attempt.

Check

Try it yourself · Teacher-written

Describe the collision response and explain why two devices should not always wait the same fixed delay.

Check your reasoning

They detect the collision, stop transmitting and send a jamming signal, then wait selected backoff delays before checking the channel and attempting retransmission. The same fixed delay can synchronise retries and cause repeated collisions; different randomly selected delays reduce that risk.

Original question · Cambridge 9618/12

2. Sequence collision-handling tasks

Cambridge 9618/12 · October/November 2023 · 7(c) · 3 marks

Selected parts: 7(c) [3].

Hint — reading the question

The question asks for three tasks in CSMA/CD. Choose actions, and keep the order of detection, stopping and retrying coherent.

Reasoning and model answer — teacher-written

Monitor the shared communication channel and transmit only when it is idle.

If a collision is detected, stop the data transmission and send a jamming signal.

Calculate a random back-off delay before attempting retransmission; check the channel again before sending.

Official mark scheme

The scheme awards a maximum of three marks from the listed channel-monitoring, collision and retry actions. A sentence can contain more than one listed action; sentence count is not the marking rule.

Common mistakes — teacher analysis

An identical fixed delay can make both devices collide again. Waiting does not grant permission to transmit into a busy channel.

Question 1 · Command word: Explain6 teacher marks

A student describes shared Ethernet as follows: “Transmit immediately without listening. Check for a collision only after sending the whole frame. After a collision, every station waits exactly the same fixed time and retries immediately.” Explain three errors in this description of CSMA/CD, giving a correction and its purpose for each.

S2.11.A01S2.11.A02S2.11.A03
Answer and checking points — teacher-written
  1. Sense the shared medium and transmit only if it is idle.
  2. Listening avoids starting a transmission while another station is already using the medium.
  3. Monitor during transmission; if a collision is detected, stop and send a jam signal.
  4. This stops sending a corrupted frame and ensures stations recognise the collision.
  5. Choose an independent random backoff, then sense the medium again before retrying.
  6. Randomisation reduces repeated simultaneous retries; it cannot guarantee that the two waits differ.

Common error: Collision detection must operate during transmission, and a completed wait does not make a busy medium free.

Question 2 · Command word: Describe4 teacher marks

Describe both directions of a local exchange. A switch already knows MAC L via WAP on p1 and server MAC S on p3; a router is on p4. The laptop already knows S’s MAC. State the incoming and outgoing switch ports for the request and response, and explain why the router is unused.

S2.09.A01S2.09.A02S2.09.A03S2.10.A02
Answer and checking points — teacher-written
  1. The laptop sends through its WNIC and WAP, so the request frame enters p1.
  2. The known destination S selects output p3.
  3. The server response addressed to L enters p3 and is forwarded through p1, then WAP to the laptop.
  4. The server is on the same LAN, so this exchange does not cross a routed network boundary.

Common error: The response also needs a complete path; do not send the local request through the router.

Question 3 · Command word: Explain5 teacher marks

Explain why two shared half-duplex Ethernet stations can collide after both sense idle. After the collision, A chooses a shorter random wait than B. B’s wait ends while A is transmitting. Describe B’s next action and what could happen if both had chosen the same wait.

S2.11.A01S2.11.A02S2.11.A03
Answer and checking points — teacher-written
  1. Signal propagation takes time, allowing each station to sense idle before the other’s transmission arrives.
  2. After detecting collision, each stops its attempted frame and sends a jam signal.
  3. Each selects a random backoff before retrying.
  4. B senses again; because A is transmitting, B defers until the medium becomes available under the access rules.
  5. Equal waits can lead to simultaneous retries and another collision; random backoff reduces but cannot eliminate that possibility.

Common error: Wait expiry does not override carrier sensing; this scenario is not full-duplex switched Ethernet.

    NICs and WNICs connect individual devices; a WAP provides wireless access to the local network.

  • Separate forwarding a frame from answering its request

    A switch forwards local frames; a server provides the requested service.

  • Separate segment filtering from signal regeneration

    A bridge filters local traffic between segments; a repeater regenerates signals.

  • Send a packet towards another network

    A router uses IP destination and routing information to forward packets between networks.

  • Package data for an Ethernet link

    Ethernet frames combine carried data with local addressing and link-level control information.

  • Listen, detect a collision, stop and retry after a random delay

    Shared Ethernet recovers through collision detection, stopping, random backoff and a checked retry.
