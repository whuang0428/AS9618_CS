Program a booking system · Concept 12

Count the executions of a FOR loop

Observe

Known request slots

  • First iteration: Index 1
  • Second iteration: Index 2
  • Third iteration: Index 3

Look, then discuss

How many booking slots are processed by FOR Index <- 1 TO 3?

Lay out three numbered request cards. The loop control variable identifies the current card; its value is not the seat quantity requested on that card.

Recall

Recall sequence and selection

Sequence performs statements in order and selection chooses a path. Iteration repeats a block. A count-controlled loop is suitable when its iteration count is determined before it begins.

Explain

Explanation · 1 / 3

Write the inclusive bounds

FOR Index <- 1 TO 3 visits 1, 2 and 3. With the default positive step of 1, the upper endpoint is included when reached.

Explanation · 2 / 3

Place the repeated action inside the loop

Every statement before the matching NEXT Index belongs to the body. Let FOR manage its control variable; do not add a separate Index <- Index + 1 inside the body.

DECLARE Index : INTEGER
FOR Index <- 1 TO 3
    OUTPUT "Process booking ", Index
NEXT Index
OUTPUT "All slots complete"

Explanation · 3 / 3

Check zero and one iteration

1 TO 1 executes once. 1 TO 0 with the default positive step executes zero times because the start is already beyond the endpoint. FOR does not guarantee a first body execution.

Work together

Count a non-one starting range

Change the header to FOR Index <- 2 TO 5.

Work together · 1 / 2

List the body values

The body uses 2, 3, 4 and 5, giving four executions. For a step of 1 and an increasing valid range, the count is End - Start + 1.

Work together · 2 / 2

Keep the final output outside

All slots complete appears once after all four body executions. Moving it inside would print it four times.

Count the values used by the body; do not assume a specific control-variable value after the completed loop.

Check

Try it yourself · Teacher-written

How many times do the bodies run for 3 TO 3 and 3 TO 2 with the default step?

Check your reasoning

One execution for 3 TO 3 and zero for 3 TO 2.

Connect

Keep this idea

A FOR loop controls a predetermined sequence of counter values, including an endpoint it reaches.

Each iteration can read a new request and add it to a running total.

Observe

Three booking requests

Look, then discuss

Where must Total start at zero so that three requests are added together?

Three requests ask for 3, 2 and 4 seats. After each request, keep the earlier total and add only the newly read quantity.

Recall

Recall an update

Total <- Total + Seats reads the old total and the current request, then stores their sum. Total therefore needs an initial value before the first addition.

Explain

Explanation · 1 / 3

Initialise the accumulator once

Set Total <- 0 before the loop. No seats have been counted yet. Setting it to zero inside the loop would discard the result from earlier iterations.

Explanation · 2 / 3

Read and add inside each iteration

INPUT Seats must be inside so that each slot obtains a new request. Reading once before the loop would repeatedly add the same request.

Explanation · 3 / 3

Report after the complete traversal

OUTPUT Total after NEXT gives one final total. A count of bookings and a total of seats are different: three bookings can request nine seats.

DECLARE Index, Seats, Total : INTEGER
Total <- 0
FOR Index <- 1 TO 3
    INPUT Seats
    Total <- Total + Seats
NEXT Index
OUTPUT Total

Work together

Trace every addition

Enter 3, 2 and 4.

Work together · 1 / 2

Preserve the earlier sum

Total begins as 0, becomes 3 after the first request, 5 after the second and 9 after the third.

Work together · 2 / 2

Expose a reset in the wrong place

If Total <- 0 is the first line of the body, the totals become 3, 2 and 4. The final output is only the last request, 4.

Initialisation, repeated input and final reporting belong at different levels of the program.

Check

Try it yourself · Teacher-written

If the loop runs from 1 TO Count and Count is 0, what does the correctly initialised program output?

Check your reasoning

It outputs 0. The body reads no requests and the accumulator keeps its initial value.

Program a booking system · Concept 14

Control direction and step size

Observe

Two descending sequences

  • Start 6, end 0, step -2: 6, 4, 2, 0
  • Start 5, end 0, step -2: 5, 3, 1

Look, then discuss

How can a display visit seat labels 6, 4, 2 and 0?

Move a marker from 6 toward 0, subtracting 2 on every move. Then try the same movement starting at 5 and notice that it never lands on 0.

Recall

Recall inclusive bounds

An endpoint is permitted when the sequence reaches it. Inclusive does not mean that a sequence with a larger step must land exactly on that endpoint.

Explain

Explanation · 1 / 3

Give a positive or negative step

STEP 3 adds 3 each iteration; STEP -2 subtracts 2. The sign must move the control value toward the intended endpoint.

Explanation · 2 / 3

List the sequence before counting it

2 TO 8 STEP 3 uses 2, 5 and 8. 5 TO 0 STEP -2 uses 5, 3 and 1, then stops before the next value would pass the endpoint.

Explanation · 3 / 3

Reject a step that cannot progress

STEP 0 is unsuitable because it never changes the counter. A descending step with a start below the endpoint has no permitted body values, such as 0 TO 5 STEP -1.

DECLARE SeatLabel : INTEGER
FOR SeatLabel <- 6 TO 0 STEP -2
    OUTPUT SeatLabel
NEXT SeatLabel

Work together

Trace both endpoints and an overshoot

Compare 8 TO 2 STEP -3 with 8 TO 1 STEP -3.

Work together · 1 / 2

First sequence

The body values are 8, 5 and 2. The endpoint is reached exactly.

Work together · 2 / 2

Second sequence

The body values remain 8, 5 and 2. The next value would be -1, which is below the endpoint 1, so there is no body execution at 1 or -1.

Direction and step determine the visited values; the endpoint only sets the allowed limit.

Experiment

List the control values and body-execution count before stepping. Compare an ascending step, a descending step and a start already beyond the endpoint. Explain why inclusive does not mean every endpoint is reached.

Program a booking system · Concept 15

Complete the inner loop for every row

Observe

A grid from Section 10

RowSeat 1Seat 2Seat 3
1(1,1)(1,2)(1,3)
2(2,1)(2,2)(2,3)

Look, then discuss

Which seat follows row 1, seat 3 in a two-row, three-seat grid?

Visit all seats in the first row before moving to row 2. The inner seat counter starts again for the new row.

Recall

Recall array indices

An array index selects an element. A two-dimensional position needs two indices. FOR counters can generate these indices, but the counter value and the stored element value are different facts.

Explain

Explanation · 1 / 3

Use a separate control variable for each responsibility

Row identifies the outer iteration and Seat identifies the inner one. Reusing Row for both loops would interfere with the outer sequence.

Explanation · 2 / 3

Restart the inner loop on each outer iteration

For Row 1, Seat visits 1, 2, 3. Only after NEXT Seat completes does NEXT Row advance Row to 2; the inner header then starts Seat at 1 again.

DECLARE Row, Seat, Count : INTEGER
Count <- 0
FOR Row <- 1 TO 2
    FOR Seat <- 1 TO 3
        OUTPUT Row, ",", Seat
        Count <- Count + 1
    NEXT Seat
NEXT Row
OUTPUT Count

Explanation · 3 / 3

Connect the counters to array updates

The body above runs 2 * 3 = 6 times. In an array task, the same pattern may write Flags[Row, Seat]. A one-dimensional Boolean array such as CheckTotal[0:35] instead uses one computed index; its bounds include both 0 and 35, giving 36 elements.

Work together

Prepare to enumerate score combinations

A quiz allows 0 to 5 easy answers worth 3 each and 0 to 4 hard answers worth 5 each.

Work together · 1 / 2

List possible contributions

Easy points are 0, 3, 6, 9, 12, 15. Hard points are 0, 5, 10, 15, 20. Nested loops must include zero because either category may have no correct answer.

Work together · 2 / 2

Use the sum as a Boolean-array index

Initialise CheckTotal[0:35] to FALSE. For every pair of contributions set CheckTotal[EasyPoints + HardPoints] to TRUE. There are 6 * 5 pairs; different pairs may reach the same total, so this does not imply 30 distinct scores.

A nested traversal generates combinations; initialise the result structure before recording those combinations.

Original question · Cambridge 9618/22

1. Build a table of reachable quiz scores

Cambridge 9618/22 · October/November 2025 · 4(a), 4(b) · 9 marks

Selected parts: 4(a) [4]; 4(b) [5].

Hint — reading the question

The largest score is 5 × 3 + 4 × 5 = 35. Include zero. In part (b), the two loop variables represent point contributions, not numbers of questions.

Reasoning and model answer — teacher-written
DECLARE CheckTotal : ARRAY[0:35] OF BOOLEAN
DECLARE Index : INTEGER
FOR Index ← 0 TO 35
    CheckTotal[Index] ← FALSE
NEXT Index

DECLARE EasyQ, HardQ : INTEGER
FOR EasyQ ← 0 TO 15 STEP 3
    FOR HardQ ← 0 TO 20 STEP 5
        CheckTotal[HardQ + EasyQ] ← TRUE
    NEXT HardQ
NEXT EasyQ

The nested loops enumerate six easy-point choices and five hard-point choices, including zero for each. Several combinations may produce the same score; assigning TRUE again leaves it valid. No combination writes outside indices 0 to 35.

Official mark scheme
Why this earns marks — teacher explanation

Part (a) gives four points for the array, loop counter, complete loop and FALSE assignment. Part (b) gives one mark per missing gap, five overall.

Common mistakes — teacher analysis

Starting at 3 or 5 omits valid totals with no correct questions of one type. Declaring only 35 elements for indices 0:35 leaves the upper endpoint out.

Question 4 · Command word: State3 teacher marks

State the ordered Row/Column output pairs and the final Count from the supplied nested-loop program. Explain what happens to Column when Row changes to 2, and where a separate per-row counter would be initialised.

Use this complete program and the stated inputs.

DECLARE Row, Column, Count : INTEGER
Count <- 0
FOR Row <- 1 TO 2
    FOR Column <- 1 TO 3
        OUTPUT Row, Column
        Count <- Count + 1
    NEXT Column
NEXT Row
OUTPUT Count
S11.04.A03
Answer and checking points — teacher-written
  1. The pairs are (1,1), (1,2), (1,3), (2,1), (2,2), (2,3), followed by Count 6.
  2. The inner FOR header is reached again, so Column starts at 1 for Row 2.
  3. A separate per-row counter is initialised inside the outer loop, before the inner loop.

Common error: The whole-table Count and a per-row count measure different groups.
