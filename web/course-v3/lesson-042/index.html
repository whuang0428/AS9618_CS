Flat-file and relational databases

Flat-file database: library loans

A database is an organised collection of related data. A flat-file database keeps the data for this example in one table. Each row below records one borrowing event. The library copies the member’s name and email, and the book’s title, into every relevant event.

Practice question · teacher-written

Asha changes her email address. Explain why updating only loan 201 causes data inconsistency.

Suggested answer

Other loan records for the same member still contain the old email address. The records then give different email addresses for one member. All occurrences must be updated.

Database design and data integrity

Normalisation reduces unnecessary duplication and the risk of update, insertion and deletion anomalies. These benefits depend on the table design and the constraints defined in the DBMS. A value can satisfy a constraint and still be factually incorrect.

Practice question · teacher-written

Explain why MemberID may occur in several Loan records without duplicating the member’s details.

Suggested answer

Each Loan record refers to the member using MemberID as a foreign key. The member’s name and email address are stored once in Member and retrieved using this relationship.

Practice question · teacher-written

State what one record in Loan represents. Explain why LoanID is required.

Suggested answer

It represents one borrowing event. The same person and physical copy can appear in later events, so Loan needs an identifier for the event rather than using the person’s name.

Our business rules guarantee that MemberID is unique and present, and that each registered member has one unique SchoolEmail. Names and TutorGroup values may repeat.

Types of key
TermRuleLibrary example
Candidate keyA minimal set of attributes guaranteed to identify every permitted record uniquelyMemberID and SchoolEmail are each candidate keys.
Primary keyThe candidate key chosen as the table’s main identifier; unique and not nullMemberID is selected because it is short and stable.
Secondary keyAn additional or alternative key used to locate records; its values need not be uniqueTutorGroup retrieves everyone in 8A.

Minimal means no attribute can be removed without losing the guarantee of uniqueness. (MemberID, MemberName) is unique when MemberID is unique, but it is not minimal. Choosing MemberID as the primary key does not stop SchoolEmail from being a candidate key.

Practice question · teacher-written

Identify the candidate keys in Member. State a suitable secondary key for retrieving all members of a tutor group. Explain why MemberName is not a candidate key under the stated rules.

Suggested answer

MemberID and SchoolEmail are candidate keys because each is guaranteed to be unique and present. TutorGroup is a suitable secondary key for this search. MemberName is not guaranteed to be unique: two members may have the same name.

Loan.MemberID is a foreign key referencing Member.MemberID. It identifies the member who borrowed the copy. LoanID identifies the borrowing event itself. MemberID 1 occurs in loans 201 and 202; that is allowed because both events belong to Asha.

A foreign key is an attribute or set of attributes whose non-null values refer to an existing key in a related table. In this chapter they reference primary keys. Copy.BookID and Loan.CopyID provide the other links in the catalogue and borrowing history.

Further explanation

A composite key contains more than one attribute. In an order line where each product occurs at most once per order, (OrderID, ProductID) can be a composite primary key. Do not use (MemberID, CopyID) as the key for historical Loan: one member may borrow the same copy again on a later date.

Practice question · teacher-written

Asha returns copy 101 and borrows it again next month. State the values required for LoanID, MemberID and CopyID in the new record.

Suggested answer

A new unique LoanID, the same MemberID 1 and CopyID 101, and the new event’s date/time and other details. Reusing the two foreign keys is valid; reusing the LoanID is not.

Practice question · teacher-written

Explain why BorrowDate is an attribute of Loan.

Suggested answer

One member can have many borrowing events on different dates. The date describes one event, so it depends on the Loan identity, not solely on the member identity.

Further explanation

These relationship symbols show the maximum number of related records. A member may have no current card and no loans. A book may have no copies, and a copy may have no loans. These participation rules are stated separately. Preventing simultaneous loans of the same copy would require an additional rule.

Practice question · teacher-written

Suppose that, in a different sample, each member has one Loan record. Explain why this sample does not establish a one-to-one relationship.

Suggested answer

The business rules permit a member to have many loans. The relationship is one-to-many even if each member currently has only one loan.

Referential integrity

Referential integrity means every non-null foreign-key value matches an existing value of its referenced key. The library additionally makes Loan.MemberID and Loan.CopyID mandatory using NOT NULL. The foreign-key and required-value rules are separate checks.

Independent attempts from the original data

Further explanation

Different databases can declare different referential actions. Cascading deletion is not automatic. This library restricts deletion of referenced parent records, so an unsuccessful attempt leaves the data unchanged.

Practice question · teacher-written

Explain why an index on MemberName cannot ensure referential integrity for Loan.MemberID.

Suggested answer

No. An index helps retrieval. The foreign-key constraint checks the reference, and adding an index does not create a missing member.

Indexing: purpose, benefits and costs

Illustrative index on TutorGroup
Indexed valueReferences to matching Member records
8AMemberID 1, MemberID 2
8BMemberID 3, MemberID 4

Indexing maintains an additional structure associating indexed values with record locations or suitable record references. An index can make a suitable search more efficient. A secondary retrieval key such as TutorGroup can be indexed even though several records share its value.

Benefit and cost
Change or requestEffect on an index
Find members of 8AMay avoid inspecting every Member row.
Member 2 moves from 8A to 8BMove its reference from the 8A index entry to 8B.
Insert or delete a memberMaintain the corresponding index entry as well as the table.
Keep the indexUse additional storage.

Further explanation

An index does not guarantee that every query is faster. For a small table or a query returning most records, a table scan may require less processing. Indexing does not guarantee the order of a query result; ORDER BY specifies that later in this chapter.

Practice question · teacher-written

Explain one storage cost and one maintenance cost of indexing.

Suggested answer

The index requires additional storage. Inserting or deleting a record, or updating an indexed field, can require changes to both the table and its index, increasing processing time.

Teacher-written practice
Question 1 · Command word: Explain4 teacher marks

A garage repeats a customer's phone number in repair and invoice files. Explain two problems this can cause and describe how a linked Customer table addresses each problem.

S8.01.A01S8.01.A02
Answer and checking points — teacher-written
  1. Multiple phone-number copies consume avoidable storage.
  2. A Customer record can hold one shared number while repair and invoice records retain the customer reference.
  3. Changing only one file leaves conflicting phone numbers.
  4. Retrieving the number from the updated Customer record avoids separate phone-number updates.

Common error: Pair each problem with the specific mechanism that reduces it.

Question 2 · Command word: Identify4 teacher marks

A school assigns each pupil a unique PupilID and a unique exam number. Names and tutor groups may repeat. Identify the candidate keys, choose a primary key, suggest a secondary key for finding tutor-group members, and explain why Attendance.PupilID is a foreign key.

S8.02.A02
Answer and checking points — teacher-written
  1. PupilID and ExamNumber are separate candidate keys under the stated uniqueness rules.
  2. PupilID can be chosen as the primary key; ExamNumber is also a valid choice if used consistently.
  3. TutorGroup is a suitable secondary key for the specified retrieval.
  4. Attendance.PupilID refers to the identifier of the pupil whose attendance is recorded.

Common error: TutorGroup provides an additional way to retrieve records and does not need to be unique.

Question 3 · Command word: Explain3 teacher marks

Department contains IDs 3 and 6. Employee.DepartmentID is a non-null foreign key. Explain whether values 6 and 8 can be inserted, and whether two employees may both contain 3.

S8.02.A04
Answer and checking points — teacher-written
  1. Value 6 is permitted because department 6 exists.
  2. Value 8 must be rejected because no referenced department has that identifier.
  3. Two employees may reference 3 because a valid foreign-key value need not be unique.

Common error: Check the referenced table, not uniqueness in Employee.

Question 4 · Command word: Explain3 teacher marks

A catalogue has 200000 products and users frequently search by Category. Explain one benefit and two costs of adding an index on Category.

S8.02.A05
Answer and checking points — teacher-written
  1. The lookup structure can locate matching products without scanning all catalogue records.
  2. The additional structure occupies storage.
  3. Changes to indexed category values require index maintenance.

Common error: Do not promise that every possible query becomes faster.

Question 5 · Command word: Identify4 teacher marks

Identify the entity, one record and two attributes represented by Book(BookID, Title, Price), containing (7, 'Dunes', 12.50). Give the equivalent terms for record and field.

S8.02.A01
Answer and checking points — teacher-written
  1. Book is the entity type.
  2. The row for BookID 7 is one record.
  3. Title and Price are two attributes; BookID is also acceptable.
  4. Tuple corresponds to record, and attribute corresponds to field.

Common error: Do not call 'Dunes' the name of a field.

Question 6 · Command word: State4 teacher marks

State the relationship in each case: every employee has one parking permit and each permit belongs to one employee; each customer places many orders and every order has one customer; each actor appears in many films and every film has many actors. Explain how to store the final relationship.

S8.02.A03
Answer and checking points — teacher-written
  1. Employee to permit is one-to-one.
  2. Customer to order is one-to-many.
  3. Actor to film is many-to-many.
  4. A linking table stores ActorID and FilmID for each appearance, creating two one-to-many links.

Common error: Read both directions before assigning cardinality.

Question 7 · Command word: Explain3 teacher marks

A club guarantees a unique MemberID for each member but allows names and towns to repeat. Explain whether (MemberID, Town) is a candidate key. The club also records annual membership of several societies: a member may join the same society again in another year. Propose a minimal membership key under that rule.

S8.02.A02S8.02.A03
Answer and checking points — teacher-written
  1. (MemberID, Town) is unique but not minimal because MemberID alone already identifies a member; the pair is not a candidate key.
  2. Use (MemberID, SocietyID, Year) for an annual membership, assuming one membership per member, society and year.
  3. Omitting Year would wrongly treat the same member joining the same society in two years as a duplicate.

Common error: Test both uniqueness and minimality under the changed rule.

Data modelling and logical schema

Data modelling identifies entities, attributes and relationships. A logical schema describes the database design independently of a particular DBMS. The table definitions below implement that design in PostgreSQL.

Data dictionary

The data dictionary contains metadata, including field names, data types, field sizes and constraints. The DBMS maintains this metadata when a table definition changes. Editing a record changes the stored data, not its field definitions.

Data integrity

Data integrity concerns the accuracy and consistency of stored data. The DBMS enforces validation rules and referential integrity constraints. Access rights control which operations a user may perform; authorised operations must still satisfy the constraints.

A foreign key alone permits NULL unless NOT NULL is also declared. This library requires every loan to identify a member and a copy. Its default referential action rejects deleting a referenced record.

Backup and recovery procedures

A backup is a copy of data that can be used to recover from data loss or corruption. Backup procedures specify how often copies are made, where they are stored, how they are protected and retained, and how restoration is tested. This exercise creates and restores a copy of the database at a particular time.

No teaching backup has been made.

A simulated outage hides the live records until recovery. The teaching backup restores the whole database structure, data and grants. Changes after its time are lost from the restored state.
