01

Encryption and decryption

S6.06.A01

Visual overview

Follow both directions

Plaintext is readable original data. Encryption applies an algorithm using a key to produce ciphertext. Decryption uses the corresponding method and required key to recover the original data. An intercepted or stolen encrypted copy should not reveal its readable content to someone without the required secret. Encryption does not prevent the copy from being intercepted.

Separate the copy, the key and the service

Protect the key separately from the exposed copy. An unprotected decryption key on the same lost drive can give the finder both ciphertext and the means to recover it. A legitimate recipient who has the key can read the sent content; possession of that key does not automatically grant permission to edit the original database.

Use a fully specified teaching model

The small character example illustrates reversible transformation only. It uses uppercase letters A–Z, shifts forward by three for encryption and backward by three for decryption, wrapping at either end. Its rule is deliberately simple and is not a secure cipher for real records or an algorithm to memorise for this syllabus. Cryptographic key-system comparisons belong to later study.

Check the result and its limits

The model turns ZOO into CRR and restores ZOO with the inverse rule. It is not a hash: the purpose is recovery of the original. If ciphertext is erased, encryption cannot recreate it. If the original data is false, decrypting it faithfully restores the same false information. Keep confidentiality, availability and integrity judgements separate.

Worked example · A protected archive: normal delivery and loss

  1. Conditions

    An archive contains verified results. Its real encryption system is not the simple character model above. The required key is held separately by authorised users, and a separate backup exists.

  2. Normal delivery

    The sender transmits ciphertext. The intended recipient applies the correct method and key and recovers the original results; a comparison confirms this stated successful round trip.

  3. Lost drive

    A finder who has only the encrypted copy cannot normally read the results. The finder can still erase that copy; restore from the separate backup if needed.

  4. Key also disclosed

    If the required unprotected key is obtained with the ciphertext, confidentiality of that copy can be lost. Rights on the original server do not remove the finder’s copy.

Core explanation · Exam essentials

  • Encryption transforms plaintext into ciphertext; the correct decryption method and key recover the plaintext.
  • Protect the key as well as the copy. Encryption alone does not prevent deletion, control every authorised action or prove source truth.
Common misconception

Encryption can protect a stolen copy's contents without preventing that copy from being destroyed.

Evaluate a complete request

After identifying the user, the service checks the resource and requested operation against its permissions. Read permits viewing, modify permits changing existing data, and delete permits removing it. Other systems may distinguish creation or record-level permissions too; use the rights and resource scope actually stated in the problem.

Connect each right to its consequence

A role groups users with similar responsibilities. Least privilege gives each role only the access needed for its work. A reviewer who checks marks can have read access without modification or deletion rights. Restricting reads supports confidentiality, while restricting updates reduces unauthorised alteration. Neither establishes that an allowed update is factually correct.

State the enforcement boundary

The previous operations concern a resource controlled by the service. If a readable copy has already been exported, an outsider may read it without consulting that service's matrix. Read-only access is not a promise that no external copy can be made. Protect disclosure and exported copies as well. Lesson 044 applies these principles to database users and groups.

Worked example · Interpret the denied operation and the independent copy

  1. Controlled sequence

    After the permitted teacher correction in the table, the saved mark is 48. The reviewer’s denied deletion leaves that same record and value in place.

  2. Authorised mistake

    If the teacher had instead entered an unsupported 84, modify permission would still allow the action. A source comparison is needed to detect that wrong value.

  3. External copy

    An outsider receives an unencrypted export showing 48. Reading this separate copy does not invoke the original service’s Visitor row.

  4. Design choice

    Give reviewers read-only access on the intended records; separately control export/disclosure and protect sensitive copies. Do not claim that a server right follows every external copy automatically.

Core explanation · Exam essentials

  • Access rights specify permitted operations for users or roles on particular resources.
  • Least privilege limits unnecessary actions; authenticated users can still be denied an operation or make an authorised mistake.
Common misconception

Knowing who logged in is not the same as permitting the operation they request.

Check your understanding

Practice questions

4 core tasks · 13 teacher marks · 17–23 minutes (teacher estimate). Explain your reasoning before checking the answer.

Question 1 · Command word: Explain2 teacher marks

Explain why keeping an unprotected decryption key on the same lost drive as an encrypted archive weakens its confidentiality protection.

S6.06.A01
Answer and checking points — teacher-written
  1. The finder obtains the information needed to decrypt the archive as well as the ciphertext.
  2. Using that key may allow recovery of the readable records.

Common error: The key needs protection as well as the encrypted file.

Question 2 · Command word: State4 teacher marks

Using the personnel-file permissions table, state whether a payroll clerk may modify a record, a department manager may delete one, and a visitor may read one. Explain why successful login does not change these decisions.

S6.06.A02
Answer and checking points — teacher-written
  1. The clerk may modify the record.
  2. The manager may not delete it.
  3. The visitor may not read it.
  4. Authentication does not replace the operation-specific permission checks.

Common error: Apply each row and operation rather than assuming every logged-in user has full access.

Question 3 · Command word: Suggest2 teacher marks

Suggest rights for an auditor who must view invoices without changing or removing them. Explain why these rights do not protect an unencrypted invoice copied to an outsider's drive.

S6.06.A02
Answer and checking points — teacher-written
  1. Grant read but deny modify and delete on the controlled invoice records.
  2. Read permission permits access to the contents and does not prevent every external copy. An outsider can read an unencrypted separate copy without consulting the original system’s permission checks.

Common error: Permissions are enforced by the system controlling the resource.

Question 4 · Command word: State5 teacher marks

An invoice starts with Amount=60. Clerk may read and modify it but may not delete it; Auditor may only read it. In order, Clerk changes Amount to 70, Auditor reads it, and Auditor tries to delete it. State each result and the final record. Then explain why this permission matrix cannot establish that 70 is factually correct or protect an unencrypted copy already sent to an outsider.

S6.06.A02
Answer and checking points — teacher-written
  1. Clerk’s modification is allowed and the stored amount becomes 70.
  2. Auditor’s read returns 70; the read does not change the record.
  3. Auditor’s deletion is denied, leaving the invoice present with Amount=70.
  4. An authorised clerk can still enter a wrong value; the permission check does not compare the amount with the source invoice.
  5. An outsider can read the independent unencrypted copy without consulting the original service’s permissions.

Common error: Follow the stated order. A denied operation preserves the current value, not necessarily the initial one.

Original question · Cambridge 9618/12

1. Protect data during transmission

Cambridge 9618/12 · May/June 2024 · 3(a)(ii) · 3 marks

Selected parts: 3(a)(ii) [3].

Reading the question — teacher guidance

Protect the content while it travels between the assessment server and its destination. Explain what an interceptor would see and how the intended recipient can recover the data.

Solution / model answer — teacher-written

Encryption transforms the readable data into ciphertext using an algorithm and a key. Someone who intercepts the transmission cannot understand its content without the required decryption key. The intended recipient uses the appropriate key and algorithm to recover the readable data.

Official mark scheme
Why this earns marks — teacher explanation

One mark is for identifying encryption and up to two for its operation or purpose. The official alternatives include scrambling, unreadability if intercepted, and the key/algorithm needed to decode it.

Common mistakes — teacher analysis

Encryption does not prevent interception itself and does not, by itself, prove that the data has not been altered. Keep confidentiality separate from integrity.

Summary

Transform

Plaintext becomes ciphertext; the correct key enables recovery.

Protect the key

An exposed key can expose an encrypted copy.

Permit operations

Read, modify and delete are separate decisions.

Combine controls

Encryption protects contents; permissions govern use of controlled resources.
