01

Encryption and decryption

S6.06.A01

Visual overview

Core explanation

Encryption applies an algorithm and key to plaintext, producing ciphertext. Decryption applies the corresponding algorithm and correct key to recover the original readable information. An intercepted or stolen encrypted copy should be unintelligible to someone without the required key.

Protect the key separately from the encrypted copy. Encryption does not decide which logged-in user may edit a record, prevent deletion of ciphertext, or prove that the source data was true. Its main role here is confidentiality.

Worked example · An encrypted archive on a lost drive

  1. Stored copy

    An employee exports an encrypted archive, keeping its decryption key separately.

  2. Drive lost

    The finder has the ciphertext but not the correct key, so cannot normally read the archive.

  3. Remaining risk

    The finder can still erase the drive; another recoverable copy is needed for availability.

  4. Key also disclosed

    If the required key is later disclosed, the confidentiality protection of that copy is lost.

Common misconception

Encryption can protect a stolen copy's contents without preventing that copy from being destroyed.

Apply access rights to data

S6.06.A02

Visual overview

Swipe horizontally to compare every column →

Core explanation

Access rights associate users or roles with permitted actions on a resource. Read permits viewing, modify permits alteration, and delete permits removal. A service checks the requested operation against these permissions after identifying the user.

Least privilege gives a role only the rights needed for its work. Restricting read access supports confidentiality; restricting changes supports integrity. Rights on a server do not protect an unencrypted copy outside that server, and authorised users can still make mistakes.

Worked example · Evaluate three requests

  1. Clerk edits salary

    Modify is allowed, so the service permits the operation.

  2. Manager deletes a record

    Delete is denied, so the service rejects the request even after successful login.

  3. Visitor reads a copied file

    The server matrix is not consulted for an external unencrypted copy; that copy needs its own protection.

Common misconception

Knowing who logged in is not the same as permitting the operation they request.

Check your understanding

Which two rights let a user inspect and amend a record but not remove it?

Check your answer

Read and modify; do not grant delete.

Practice questions

Question 1 · Command word: Describe2 marks

Describe how a sender makes a readable data file unintelligible during transfer and how the intended receiver restores it.

S6.06.A01
Answer and marking points
  1. The sender encrypts plaintext with an algorithm and key to produce ciphertext.
  2. The receiver uses the correct decryption key and algorithm to recover the plaintext.

Common error: Distinguish ciphertext from a hash digest.

Question 2 · Command word: Explain2 marks

Explain why keeping an unprotected decryption key on the same lost drive as an encrypted archive weakens its confidentiality protection.

S6.06.A01
Answer and marking points
  1. The finder obtains the information needed to decrypt the archive as well as the ciphertext.
  2. Using that key may allow recovery of the readable records.

Common error: The key needs protection as well as the encrypted file.

Question 3 · Command word: State4 marks

Using the personnel-file permissions table, state whether a payroll clerk may modify a record, a department manager may delete one, and a visitor may read one. Explain why successful login does not change these decisions.

S6.06.A02
Answer and marking points
  1. The clerk may modify the record.
  2. The manager may not delete it.
  3. The visitor may not read it.
  4. Authentication does not replace the operation-specific permission checks.

Common error: Apply each row and operation rather than assuming every logged-in user has full access.

Question 4 · Command word: Suggest2 marks

Suggest rights for an auditor who must view invoices without changing or removing them. Explain why these rights do not protect an unencrypted invoice copied to an outsider's drive.

S6.06.A02
Answer and marking points
  1. Grant read but deny modify and delete.
  2. The outsider reads a separate copy without consulting the original system's permission checks.

Common error: Permissions are enforced by the system controlling the resource.

Question 1 · Command word: Explain · 3 marks

A charity sends donor records to a contractor. Explain how encryption protects the transfer and why giving the contractor the key does not limit which records they may later change in the charity's database.

Answer and marking points
  • Encryption transforms the transmitted records into ciphertext that an interceptor cannot normally understand.
  • The contractor needs the correct key to recover the sent contents.
  • Database changes are controlled by the contractor account's permissions, not by possession of the transfer key.

Common error: Separate decrypting a copy from editing the source database.

Question 2 · Command word: Suggest · 4 marks

A research assistant must add observations and correct their own entries; a reviewer must only read them. Suggest suitable permissions for each role and explain how this arrangement supports data integrity without proving that an observation is true.

Answer and marking points
  • Allow the assistant to create observations and modify only their own records.
  • Give the reviewer read access without modification rights.
  • Restricting changes reduces alteration by users who have no editing role.
  • An authorised assistant may still record an incorrect observation, so permission does not establish truth.

Common error: Use the stated resource scope, not unrestricted write access to all records.

Question 3 · Command word: Explain · 3 marks

An attacker erases an encrypted backup but never discovers its key. Explain the different effects on confidentiality and availability, then suggest a way to improve recovery.

Answer and marking points
  • The attacker has not gained readable content, so the incident does not itself demonstrate lost confidentiality.
  • Erasing the backup removes that recovery copy and therefore harms availability.
  • A separate protected backup copy allows recovery if one copy is destroyed.

Common error: Do not claim encryption makes data undeletable.

04

Lesson review

Summary

Transform

Plaintext becomes ciphertext; the correct key enables recovery.

Protect the key

An exposed key can expose an encrypted copy.

Permit operations

Read, modify and delete are separate decisions.

Combine controls

Encryption protects contents; permissions govern use of controlled resources.
