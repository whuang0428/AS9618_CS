Describe the complete encryption process

Exam description

Encryption transforms plaintext into ciphertext using an algorithm and a key. Intercepted ciphertext cannot be understood without the appropriate decryption key. The recipient applies the decryption process with the correct key to recover the plaintext.

Encryption protects confidentiality. By itself, it does not stop interception, deletion or disruption of the computer, and it does not prove the original message was accurate.

Access rights · the core marking points

Turn the permission matrix into an exam explanation
Marking ideaExplain it concretely
Different users can have different permissions.A teacher may update marks; a reviewer may only read them.
Rights control access to specific data.Check the rights for the requested file or database table.
Rights control the type of operation.Allow reading while denying editing or deletion.
The system enforces those permissions.Only an account with the correct right can carry out the operation.

Exam description

Access rights specify which data a user or group may access and which operations they may perform, for example read only or read and write. The system checks the account’s permissions and denies an operation for which the account has no right.

Permission to edit is not proof that the new value is correct. Rights on the original file also do not protect a separate, readable copy that has already left the system.

Original question · Cambridge 9618/12

1. Separate privacy from integrity

Cambridge 9618/12 · October/November 2023 · 5(a), 5(b) · 2 marks

Selected parts: 5(a) [1]; 5(b) [1].

Original question
Reading the question — teacher guidance

These are two one-mark definitions. State the essential property of each; examples of attacks are not required.

Solution / model answer — teacher-written

5(a): Privacy means that data is accessed by or disclosed to authorised people only.

5(b): Integrity means that data remains accurate, complete and consistent during and after processing.

Official mark scheme
Why this earns marks — teacher explanation

Each subpart has a one-mark maximum. The scheme also accepts data being up to date for integrity; listing all acceptable words does not multiply the mark.

Common mistakes — teacher analysis

Data can be accurate but disclosed to the wrong person, or kept private but entered incorrectly. These properties are independent.

Original question · Cambridge 9618/11

4. Explain signature creation and the receiver check

Cambridge 9618/11 · May/June 2025 · 7(b) · 5 marks

Selected parts: 7(b) [5].

Original question
Reading the question — teacher guidance

Explain the complete sender-to-receiver process. The question asks how the receiver checks that the transferred data has not changed.

Solution / model answer — teacher-written

The sender hashes the document to produce a digest. In the simplified digest-encryption model used by this scheme, the sender encrypts the digest to create a digital signature and sends the document with that signature.

The receiver decrypts the signature to recover the sender digest. The receiver also hashes the received document using the same hashing algorithm and compares the two digests. Matching digests support the conclusion that the signed document has not changed.

In the classroom model, signing uses the sender private key and checking uses the trusted sender public key. These key roles explain the model; this particular mark scheme lists the digest and comparison stages without separately allocating a key-role mark.

Official mark scheme
Why this earns marks — teacher explanation

The official scheme awards one mark per listed point, up to five. Include the received-document hash and the comparison; the signature alone is not a complete verification process.

Common mistakes — teacher analysis

Hashing and encryption are different operations. Do not say that the document itself must be encrypted by the signature process, or that the receiver needs the sender private key. A signature alone does not hide the accompanying document.

Original question · Cambridge 9618/12

1. Protect data during transmission

Cambridge 9618/12 · May/June 2024 · 3(a)(ii) · 3 marks

Selected parts: 3(a)(ii) [3].

Original question
Reading the question — teacher guidance

Protect the content while it travels between the assessment server and its destination. Explain what an interceptor would see and how the intended recipient can recover the data.

Solution / model answer — teacher-written

Encryption transforms the readable data into ciphertext using an algorithm and a key. Someone who intercepts the transmission cannot understand its content without the required decryption key. The intended recipient uses the appropriate key and algorithm to recover the readable data.

Official mark scheme
Why this earns marks — teacher explanation

One mark is for identifying encryption and up to two for its operation or purpose. The official alternatives include scrambling, unreadability if intercepted, and the key/algorithm needed to decode it.

Common mistakes — teacher analysis

Encryption does not prevent interception itself and does not, by itself, prove that the data has not been altered. Keep confidentiality separate from integrity.

Teacher-written practice
Question 1 · Command word: Explain2 teacher marks

Explain why keeping an unprotected decryption key on the same lost drive as an encrypted archive weakens its confidentiality protection.

S6.06.A01
Answer and checking points — teacher-written
  1. The finder obtains the information needed to decrypt the archive as well as the ciphertext.
  2. Using that key may allow recovery of the readable records.

Common error: The key needs protection as well as the encrypted file.

Question 2 · Command word: State4 teacher marks

Using the personnel-file permissions table, state whether a payroll clerk may modify a record, a department manager may delete one, and a visitor may read one. Explain why successful login does not change these decisions.

S6.06.A02
Answer and checking points — teacher-written
  1. The clerk may modify the record.
  2. The manager may not delete it.
  3. The visitor may not read it.
  4. Authentication does not replace the operation-specific permission checks.

Common error: Apply each row and operation rather than assuming every logged-in user has full access.

Question 3 · Command word: Suggest2 teacher marks

Suggest rights for an auditor who must view invoices without changing or removing them. Explain why these rights do not protect an unencrypted invoice copied to an outsider's drive.

S6.06.A02
Answer and checking points — teacher-written
  1. Grant read but deny modify and delete on the controlled invoice records.
  2. Read permission permits access to the contents and does not prevent every external copy. An outsider can read an unencrypted separate copy without consulting the original system’s permission checks.

Common error: Permissions are enforced by the system controlling the resource.

Question 4 · Command word: State5 teacher marks

An invoice starts with Amount=60. Clerk may read and modify it but may not delete it; Auditor may only read it. In order, Clerk changes Amount to 70, Auditor reads it, and Auditor tries to delete it. State each result and the final record. Then explain why this permission matrix cannot establish that 70 is factually correct or protect an unencrypted copy already sent to an outsider.

S6.06.A02
Answer and checking points — teacher-written
  1. Clerk’s modification is allowed and the stored amount becomes 70.
  2. Auditor’s read returns 70; the read does not change the record.
  3. Auditor’s deletion is denied, leaving the invoice present with Amount=70.
  4. An authorised clerk can still enter a wrong value; the permission check does not compare the amount with the source invoice.
  5. An outsider can read the independent unencrypted copy without consulting the original service’s permissions.

Common error: Follow the stated order. A denied operation preserves the current value, not necessarily the initial one.

Question 5 · Command word: Describe2 teacher marks

Describe how a sender makes a readable data file unintelligible during transfer and how the intended receiver restores it.

S6.06.A01
Answer and checking points — teacher-written
  1. The sender encrypts plaintext with an algorithm and key to produce ciphertext.
  2. The receiver uses the correct decryption key and algorithm to recover the plaintext.

Common error: Distinguish ciphertext from a hash digest.
