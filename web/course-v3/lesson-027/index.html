01

Logical, arithmetic and cyclic shifts

S4.15.A01S4.15.A03S4.15.A04S4.15.A13S4.15.A14

Visual overview

What fills the vacated position?

  • Logical: Insert 0 and discard outgoing bits. LSL #n and LSR #n shift ACC logically by n positions.
  • Arithmetic: For two's complement, copy the sign bit when shifting right. A left shift inserts 0, like logical left, but may overflow.
  • Cyclic: Wrap the outgoing bit to the opposite end; the number of 1 bits is unchanged.

Each panel of the six-shift comparison begins again with 10010111. It is not a sequence of six instructions. Use eight bits and discard bits that leave the result unless the operation is cyclic. Under unsigned interpretation the starting value is 151; under two’s complement it is −105.

An arithmetic right shift gives 11001011, representing −53. The exact value −105/2 is −52.5: this shift rounds down to −53 rather than truncating towards zero. A positive odd value such as 00000101 becomes 00000010, or 2. Logical right of a negative pattern instead inserts zero and changes its signed interpretation.

An arithmetic left shift moves bits like a logical left shift. Here it gives 00101110 (46), but the intended signed double −210 is outside −128 to 127, so this is overflow. Left followed by right is not generally reversible: logical left of 10000001 gives 00000010, then logical right gives 00000001; the lost leading 1 cannot be recovered.

Worked example · Two logical instructions

  1. Given

    ACC is unsigned 8-bit 00110100 (52). Execute LSL #1, then LSR #2.

  2. Shift left

    LSL #1 gives 01101000 (104); zero enters at the right.

  3. Shift right

    LSR #2 gives 00011010 (26); two zeros enter at the left.

  4. Check the scope

    These particular shifts lose only zeros. Other inputs can lose 1 bits, so opposite shifts need not restore the original value.

Core explanation · Exam essentials

  • Logical shifts fill with zero; arithmetic right repeats the sign; cyclic shifts wrap. Interpret the fixed-width result using the stated representation.
Common misconception

A cyclic result can coincide with an arithmetic or logical result for one input; their rules are still different.

Check your understanding

What enters at the left in an arithmetic right shift of a negative value?

Check your answer

Copies of the original sign bit, which is 1.

02

AND, OR and XOR with immediate or memory operands

S4.15.A05S4.15.A07S4.15.A08S4.15.A09S4.15.A10S4.15.A11S4.15.A12

Visual overview

These are bitwise operations on equal-width patterns, not one Boolean decision about the whole byte. AND yields 1 only for two 1 bits; OR yields 1 for at least one 1; XOR yields 1 when the pair differs. Zero-extend a shorter unsigned mask to the stated width before aligning it.

The mask’s neutral bits explain preservation: AND with 1 keeps a bit; OR with 0 keeps a bit; XOR with 0 keeps a bit. Their active bits then clear, set or toggle only selected positions. This is why a mask is chosen from the required action instead of from its visual similarity to the data.

AND #15, AND B00001111 and AND &0F use the same immediate value. AND 700 instead reads Memory[700]; it behaves the same only if that location contains 15. Reset ACC between independent examples, but use the updated ACC for a stated instruction sequence.

Worked example · Same mask, different operations

  1. Given

    For each operation independently use ACC=10100110 and mask B00001111 (15). Memory[720]=15 gives the same operand through address 720.

  2. AND

    10100110 AND 00001111 = 00000110. AND 720 also gives 6.

  3. OR

    10100110 OR 00001111 = 10101111. OR &0F also gives 175.

  4. XOR

    10100110 XOR 00001111 = 10101001. XOR #15 also gives 169.

Core explanation · Exam essentials

  • Apply AND, OR and XOR independently at each bit position. Resolve an immediate or memory operand before using its bit pattern.
Optional extension · repeat an update

OR with the same mask twice has the same effect as once, so setting an already-set bit is harmless in this model. XOR with a mask twice restores the original bits because each selected bit toggles twice. These identities explain repeated control actions; no Boolean-algebra proof method is required.

Common misconception

#00001111 is a denary literal, not the binary mask 00001111. Use B00001111 or #15 for that mask.

Check your understanding

Which operation flips precisely the bit positions where a mask contains 1?

Check your answer

XOR toggles those positions and leaves positions masked by 0 unchanged.

03

Monitor and control a device using masks

S4.15.A02S4.15.A05S4.15.A06S4.15.A15S4.15.A16

Visual overview

A device interface can encode several states or controls in one byte. A mask selects the relevant positions: AND with a single 1 tests a bit, while OR with a single 1 sets it. Number bits explicitly; these examples use bit 7 at the left and bit 0 at the right.

Use an 8-bit memory-mapped interface model at address 900: bit 4 is ready, bit 2 enables the motor, and other bits must be preserved. Reads return the current byte; writing a byte replaces it. Assume no independent device update occurs during this short sequence; real interface registers can have different write rules.

Testing with AND B00010000 leaves either 16 or 0 in ACC. CMP #0 followed by JPE DONE skips the update when not ready. On the ready path the AND result has lost other status bits, so LDD 900 reloads the original byte before OR sets bit 2 and STO writes it back.

The required behaviour is conditional: if ready, set the motor bit; otherwise leave the stored byte unchanged. For ready input 00010001 the result is 00010101. For not-ready input 00000001 it stays 00000001. For ready input 00010101 the already-set motor bit stays set and the result is unchanged.

Worked example · Supplied program and initial state

  1. Conditions

    Initial ACC=0, IX=0, PC=100; comparison result unset. Memory[900]=17. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

Worked example · Check both paths and preserve every other bit

  1. Not ready

    Reset Memory[900]=00000001, PC=100, ACC=0 and IX=0. Executed addresses: 100,101,102,103,107. The AND result is 0, comparison=True and JPE reaches END; no STO executes. Memory[900] remains 1.

  2. Already enabled

    Reset Memory[900]=00010101. The ready test gives 16, comparison=False; reload gives 21, OR keeps 21 and STO writes 21.

  3. Clear and toggle variants

    On a fresh copy of 00010101, AND B11111011 clears bit 2 to give 00010001. XOR B00000100 toggles it to 00010001; applying XOR again gives 00010101. Store the chosen updated value when the task requires a persistent change.

Core explanation · Exam essentials

  • Read status, AND a copy to test, compare and branch, then reload before OR and STO. Preserve unrelated bits on both ready and not-ready paths.
Common misconception

Testing and setting are different operations; OR alone cannot tell whether a bit was originally clear.

Check your understanding

Does a successful single-bit AND test necessarily produce denary 1?

Check your answer

No. Testing bit 4 produces 00010000 (16) when set; compare the test result with zero.

Question 1 · Command word: Calculate6 marks

Calculate the six one-place shift results for the 8-bit pattern 10110010: logical left/right, arithmetic left/right, and cyclic left/right. Interpret arithmetic shifts using two's complement and state whether the left arithmetic shift overflows. Discard any bit shifted outside the 8-bit result.

S4.15.A01S4.15.A03S4.15.A04
Answer and marking points
  1. Logical left produces 01100100; logical right produces 01011001.
  2. Arithmetic left produces 01100100, the same bit movement as logical left.
  3. The original signed value is −78; doubling it gives −156, outside −128 to 127, so the arithmetic left result overflows.
  4. Arithmetic right produces 11011001, preserving the sign bit; its signed value is −39.
  5. Cyclic left produces 01100101 by wrapping the old leftmost bit to the right.
  6. Cyclic right produces 01011001 by wrapping the old rightmost bit to the left.

Common error: Arithmetic right repeats the sign bit; cyclic shifts wrap the outgoing bit. Their results can coincide for a particular input.

Question 2 · Command word: Calculate6 marks

Calculate the ACC result for each instruction independently, starting each time with ACC=172 and Memory[700]=15: AND #15, AND 700, OR B00001111, OR 700, XOR &0F, XOR 700. Give every result in 8-bit binary and denary.

S4.15.A05S4.15.A07S4.15.A08S4.15.A09S4.15.A10S4.15.A11S4.15.A12
Answer and marking points
  1. AND #15: 00001100 = 12.
  2. AND 700: 00001100 = 12 because the memory operand is 15.
  3. OR B00001111: 10101111 = 175.
  4. OR 700: 10101111 = 175 using the contents of location 700.
  5. XOR &0F: 10100011 = 163.
  6. XOR 700: 10100011 = 163 using the same mask from memory.

Common error: Reset ACC before each independent calculation; a bare address refers to stored contents.

Question 3 · Command word: Explain5 marks

Explain how to test bit 5 and set bit 1 in an 8-bit device status value without changing unrelated bits in the stored value. Bits are numbered 7 to 0 from left to right. The initial status is 00100100. Give the test result and the updated status, using a fresh copy of the original status for setting.

S4.15.A02S4.15.A05S4.15.A06S4.15.A07S4.15.A11
Answer and marking points
  1. Use AND B00100000 on a copy to isolate bit 5.
  2. The test gives 00100000, so bit 5 is set; a zero result would mean it was clear.
  3. Reload the original status, then use OR B00000010 to set bit 1.
  4. The updated status is 00100110; store that result back to the device register.
  5. The AND test changes ACC, so its result must not overwrite unrelated status bits.

Common error: Testing a bit is not the same as clearing every other bit in the device's stored status.

Question 4 · Command word: Calculate3 marks

Calculate ACC after LSL #2 followed by LSR #3, starting with the unsigned 8-bit value 00101100. Explain what enters each vacated position.

S4.15.A01S4.15.A04S4.15.A13S4.15.A14
Answer and marking points
  1. LSL #2 gives 10110000, which is 176.
  2. LSR #3 then gives 00010110, which is 22.
  3. Logical shifts insert zeros; bits leaving the fixed-width value are discarded.

Question 1 · Command word: Explain · 5 marks

A device register initially contains 10010100. Bit 7 means ready and bit 0 controls a lamp; bits are numbered 7 to 0. Explain how to test ready and then switch on the lamp while preserving the other stored bits. Give both masks, the test result and the final register value.

Answer and marking points
  • Apply AND B10000000 to a copy of the status to test ready.
  • The test result is 10000000, so the ready bit is set.
  • Reload the unmodified status before setting the lamp bit.
  • Apply OR B00000001 to that status copy.
  • Store 10010101 back to the device register; the other seven bits are unchanged.

Common error: Do not write the isolated ready-bit test result back as the full device status.

Question 3 · Command word: Calculate · 5 marks

Calculate the results of logically, arithmetically and cyclically shifting the 8-bit value 01101001 right by one place. Give the results of LSL #1 and an arithmetic left shift of the original value, and explain signed overflow for that left shift.

Answer and marking points
  • Logical right gives 00110100 by introducing zero at the left.
  • Arithmetic right also gives 00110100 here because the original sign bit is zero.
  • Cyclic right gives 10110100 because the old rightmost 1 wraps to the left.
  • LSL #1 and arithmetic left both produce 11010010 as an 8-bit pattern.
  • The original signed value is 105; 210 cannot be represented in signed 8-bit two's complement, so the arithmetic left shift overflows.

Common error: Same bit movement does not guarantee a valid signed multiplication result.

04

Lesson review

Summary

Shifts

Logical inserts zeros, arithmetic right preserves sign, and cyclic wraps outgoing bits.

Masks

AND tests or clears, OR sets, and XOR toggles selected positions; preserve the original device value when needed.

Notation

Use # for denary, B for binary and & for hexadecimal immediates; bare operands and labels can refer to memory addresses.
