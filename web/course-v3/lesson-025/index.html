01

Assembly language and machine code

S4.09.A01

Machine instructions are encoded as binary patterns understood by a particular processor. An instruction contains an opcode and, where required, operand information. Assembly language provides readable mnemonics and symbolic names for the same low-level operations.

An assembler translates assembly source into machine code for its target instruction set. An ordinary mnemonic instruction corresponds to a machine instruction; labels and data declarations organise the source and are not additional operations for the processor to execute. Source for a different instruction set is not automatically interchangeable.

The opcode names the operation; an operand supplies data or information used to obtain data or a target. LDD 4 means load from address 4, whereas a supplied immediate load uses its constant directly. END needs no source operand, even if a teaching encoding reserves a field filled with zeros.

A mnemonic is not converted by adding the character codes of its letters. The target instruction set defines the operation’s binary code and operand format. Translating a source therefore requires those definitions as well as any symbolic addresses.

The example here assigns an 8-bit opcode and an 8-bit address in a 16-bit instruction word. This is a supplied encoding used to practise resolution and conversion, not a machine encoding prescribed by the Cambridge instruction list. The same textual operation could have a different encoding on another target.

Worked example · A supplied encoding

  1. Encoding for this example only

    A 16-bit word uses an 8-bit opcode and an 8-bit address. Let LDD be 00000001.

  2. Resolve the operand

    If TOTAL labels location 6, its 8-bit address is 00000110.

  3. Encode

    LDD TOTAL becomes 00000001 00000110. These bit assignments are invented teaching data, not a binary encoding prescribed by Cambridge.

Core explanation · Exam essentials

  • Assembly uses readable mnemonics and labels; an assembler encodes them for a particular processor. Opcode bit patterns must be supplied or known.
Common misconception

Readable mnemonics are not the binary instruction bits the processor executes.

Check your understanding

Can the opcode bits be calculated just from the letters LDD?

Check your answer

No. The target instruction set's encoding must be supplied or known.

02

Labels for instructions and data

S4.15.A15S4.15.A16

Visual overview

Two label forms

SourceMeaning
AGAIN: DEC ACCAGAIN names the address of this DEC instruction
FLAGS: 36FLAGS names a data location initially containing 36
LDD FLAGSLoad the contents at the address named FLAGS
STO FLAGSStore ACC at the address named FLAGS

Swipe horizontally to compare every column →

The form <label>: <opcode> <operand> names the address of an instruction. The operand is omitted for an instruction that does not require one, such as END. A branch can use an instruction label as its target.

The form <label>: <data> names a location containing the given data. The label denotes the location's address, not its contents. Loading or storing through the label accesses that location; program execution must end or branch before falling into data declarations.

A label binds a readable name to the location of the item that follows its colon. In START: LDD FIRST, START names the instruction’s location and FIRST is a reference to another location. Defining a label is different from using that label as an operand.

In the shared program, FIRST: 18 labels address 4, which initially contains 18. LDD FIRST is therefore LDD 4, not LDD 18. TOTAL labels address 6 even after STO changes its contents from 0 to 42. Storing a result changes memory data, not the label’s address.

Data declarations occupy locations in this model but are not executed as load instructions. Place END before them so normal execution does not fall into data. A forward reference uses a name before its definition; the two-pass assembler resolves it after finding the definition.

Worked example · Read labels before assembling

  1. Source
    000  START: LDD FIRST
001  ADD SECOND
002  STO TOTAL
003  END
004  FIRST: 18
005  SECOND: 24
006  TOTAL: 0
  2. Identify

    START is an instruction label at 0. FIRST, SECOND and TOTAL are data labels at 4, 5 and 6. Every listed item occupies one location; the numeric prefix is an address annotation, not source code.

  3. Distinguish

    FIRST resolves to 4 and Memory[4]=18. TOTAL resolves to 6 initially containing 0; after execution the same address contains 42.

  4. Stop correctly

    END at 3 returns control to the OS before the data declarations at 4–6.

Core explanation · Exam essentials

  • An instruction label names an instruction address; a data label names a data address. The symbol table stores addresses, not the values stored there.
Common misconception

A data declaration does not execute as a load instruction.

Check your understanding

What does FLAGS denote in STO FLAGS?

Check your answer

The destination address associated with FLAGS in the symbol table.

03

Applying both passes of an assembler

S4.10.A01S4.10.A02

Visual overview

What each pass knows

StageKnown informationStill to do
Before scanningOrigin 0; one location per listed itemFind definitions
After pass oneSTART=0, FIRST=4, SECOND=5, TOTAL=6Resolve operands and encode
After pass twoSeven-word memory imageLoad and execute to check the calculation

Swipe horizontally to compare every column →

During pass one, the assembler scans the source, assigns locations and records labels with their addresses in a symbol table. It advances a location counter according to each instruction or data item's size and can detect errors such as duplicate definitions.

During pass two, the assembler uses the completed symbol table to resolve symbolic operands, translates mnemonics to opcodes and emits machine instructions and data. A forward reference is now resolvable even when its label appeared later in the source; a name that remains undefined is reported as an error.

At the first line, the assembler knows START=0 but has not yet reached FIRST. It can still advance its location counter and continue recording definitions. After all seven items, the counter is 7 and the completed symbol table contains every name needed by the instructions.

In pass two, resolve the symbolic address before converting it to bits. FIRST is 4, so the LDD operand is 00000100; the contents 18 belong in the data word at address 4. The resulting seven-word image includes both four instructions and three data words.

Duplicate labels make the source ambiguous: if FIRST is defined at two addresses, the assembler must report the duplicate definition. An operand such as LDD MISSING with no matching definition remains unresolved after pass one and must be reported during resolution. Guessing address zero would hide a source error.

Worked example · Assemble a complete program

  1. Initial state

    Initial ACC=0, IX=0, PC=0; comparison result unset. Data declarations are included below. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

  2. Source and location rule
    000  START: LDD FIRST
001  ADD SECOND
002  STO TOTAL
003  END
004  FIRST: 18
005  SECOND: 24
006  TOTAL: 0
  3. Pass one

    Count all seven items, including the three data declarations. Enter START=0, FIRST=4, SECOND=5 and TOTAL=6.

  4. Pass two: resolve

    The instructions become LDD 4; ADD 5; STO 6; END. FIRST and SECOND were forward references.

  5. Supplied teaching encoding

    Use 16-bit words: 8-bit opcode then 8-bit address. LDD=00000001, ADD=00000010, STO=00000011, END=11111111 with operand 0. Data use a full 16-bit unsigned word.

  6. Pass two: emit
    0  00000001 00000100
1  00000010 00000101
2  00000011 00000110
3  11111111 00000000
4  00000000 00010010
5  00000000 00011000
6  00000000 00000000
  7. Check by execution

    The program loads 18, adds 24 and stores 42 at address 6, then ends before the data declarations.

Core explanation · Exam essentials

  • Pass one assigns locations and records labels. Pass two resolves operands and emits encoded instructions/data; duplicate or undefined names are errors.
Common misconception

The symbol table contains addresses, not the data values 18, 24 and 0 stored at those addresses.

Check your understanding

Why can pass one not immediately resolve FIRST in the first source line?

Check your answer

FIRST is defined later; completing the first scan provides its address for pass two.

Practice questions

Question 1 · Command word: Compare4 marks

Compare assembly language with machine code. Explain why assembly written for one processor instruction set may not run on a processor with a different instruction set.

S4.09.A01
Answer and marking points
  1. Assembly uses mnemonic opcodes and may use symbolic addresses.
  2. Machine code encodes instructions as binary patterns that the processor can execute.
  3. An assembler translates assembly instructions into the corresponding machine instructions.
  4. Different instruction sets define different operations, encodings or operand rules, so the same assembly source may need changes and reassembly.

Common error: Assembly language is a low-level language; its mnemonics are not executed directly as text.

Initial ACC=0, IX=0, PC=10; comparison result unset. Data declarations are included below. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

010  BEGIN: LDD LEFT
011  ADD RIGHT
012  STO RESULT
013  END
014  LEFT: 7
015  RIGHT: 9
016  RESULT: 0
S4.10.A01S4.10.A02
Answer and marking points
  1. The symbol table is BEGIN=10, LEFT=14, RIGHT=15, RESULT=16.
  2. At address 10 the resolved instruction is LDD 14.
  3. At address 11 the resolved instruction is ADD 15.
  4. At address 12 the resolved instruction is STO 16.
  5. The first instructions refer to labels defined later; the completed symbol table lets pass two resolve these forward references.

Common error: A label records the address of its item, not that item's stored data value.

000  START: LDD FIRST
001  ADD SECOND

  1. START labels instruction address 0; FIRST, SECOND and TOTAL label data addresses 4,5,6.

Question 1 · Command word: Complete · 5 marks

Complete the symbol table after pass one and give the resolved operands used by pass two for the supplied program. Explain whether the data value 25 belongs in the symbol table entry for VALUE.

Initial ACC=0, IX=0, PC=60; comparison result unset. Data declarations are included below. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

060  ENTRY: LDD VALUE
061  STO COPY
062  END
063  VALUE: 25
064  COPY: 0
Answer and marking points
  • ENTRY is entered as address 60.
  • VALUE is entered as address 63 and COPY as address 64.
  • LDD VALUE resolves to LDD 63.
  • STO COPY resolves to STO 64.
  • The symbol table stores VALUE's address 63; the separate data item at that address contains 25.

Common error: Do not resolve LDD VALUE as LDD 25.

Question 2 · Command word: Explain · 4 marks

Explain how a two-pass assembler handles a jump to a label defined later in the source. Describe what it should report if that label is never defined, and why simply substituting address zero is unsafe.

Answer and marking points
  • Pass one assigns addresses and collects label definitions in a symbol table.
  • Pass two looks up the later-defined target using the completed table when generating the jump operand.
  • If no definition exists, the assembler reports an undefined-symbol error.
  • Substituting zero could silently generate a jump to an unintended instruction rather than the requested target.

Common error: A forward reference can be valid; a missing definition is an error.

Question 3 · Command word: Write · 4 marks

Write the 16-bit machine word for LDD 63 when a supplied encoding gives LDD opcode 00000110 followed by an 8-bit address. Explain why another processor's assembler might generate a different word for a load operation, and identify the role of the assembly mnemonic.

Answer and marking points
  • The unsigned 8-bit form of address 63 is 00111111.
  • The resulting word is 00000110 00111111.
  • Another instruction set may assign different opcodes, formats or operand rules.
  • LDD is a readable mnemonic naming the operation for the assembler to encode.

Common error: Use the encoding supplied in this question rather than the different teaching encoding used earlier.
