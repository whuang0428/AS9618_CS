Relate assembly to machine code

Start with a question

Why can a person write LDD while the processor executes a bit pattern?

The readable instruction LDD 4 means load the contents at address 4. Compare this meaning with a supplied binary encoding for the same operation.

Explain

Readable instructionOpcode fieldOperand field
LDD 40000000100000100
ADD 50000001000000101
STO 60000001100000110
END1111111100000000

Explanation · 1 / 4

Name the two representations

Machine code consists of instructions encoded as binary patterns for a particular processor instruction set. Assembly language uses mnemonics, such as LDD, to represent operations in a form that is easier for people to read. An assembler translates assembly source into machine code.

Explanation · 2 / 4

Split operation from operand

An opcode specifies the operation. An operand supplies the data or information needed to obtain data or select a target. In LDD 4, the mnemonic denotes the load-direct opcode and 4 is its address operand. END needs no source operand in this example instruction set.

Explanation · 3 / 4

Use the supplied instruction encoding

For this teaching example only, each instruction has a 16-bit word: an 8-bit opcode followed by an 8-bit address field. The supplied codes are LDD = 00000001, ADD = 00000010, STO = 00000011 and END = 11111111. END uses a zero-filled operand field. These are classroom encoding choices, not Cambridge-prescribed machine codes.

Explanation · 4 / 4

Translate meaning, not the letters

The assembler looks up the operation code and encodes its operand using the target format. It does not obtain the LDD opcode by adding the character codes of L, D and D. A different processor instruction set may use different encodings or support different operations.

Work together · 2 / 2

Explanation · 1 / 4

Read a definition and a use

A label is a name assigned to a location. In START: LDD FIRST, START followed by a colon defines an instruction label. FIRST is used as the instruction’s operand; its definition appears later. The numbers in the left margin below are address annotations, not source instructions.

000  START: LDD FIRST
001  ADD SECOND
002  STO TOTAL
003  END
004  FIRST: 18
005  SECOND: 24
006  TOTAL: 0

Explanation · 2 / 4

Name an instruction address

The form label: opcode operand names the address of an instruction. START names address 0. If an instruction has no operand, as with END, none is required after the opcode. A later branch can use an instruction label to identify its target.

Explanation · 3 / 4

Name a data address

The form label: data names a location that contains the given data. FIRST: 18 puts 18 at the location named FIRST. Here FIRST is address 4. TOTAL is address 6, initially containing 0; after the program runs, the same address contains 42.

Explanation · 4 / 4

Keep data out of the execution path

A data declaration reserves and initialises a location; it is not a load instruction. END occurs before the declarations so normal execution finishes before the CPU would fetch them as instructions. A forward reference uses a label before its definition appears; FIRST in the first line is an example.

Work together

Resolve names before running

Addresses start at 0 and each instruction or data declaration takes one location.

Work together · 1 / 2

Replace operand names with addresses

LDD FIRST becomes LDD 4. ADD SECOND becomes ADD 5. STO TOTAL becomes STO 6.

Work together · 2 / 2

Distinguish symbol and data

The symbol table records TOTAL = 6. Running the program changes Memory[6] from 0 to 42 but does not change that symbol-table entry.

A label names an address; reading or writing through it accesses the contents at that address.

Check

Explain it yourself · Teacher-written

After the calculation, does TOTAL mean 42?

Check your reasoning

No. TOTAL still denotes address 6. Its contents are now 42; the symbolic address does not change when data is stored there.

Connect

Keep this idea

Instruction labels name instruction addresses. Data labels name data locations.

A first scan can discover every label before a second scan resolves forward references.

Check a common misunderstanding

Do not place data values such as 18 and 24 in a label-to-address symbol table.

Learning goals
  • Use an instruction label to name an instruction address.
  • Use a data label to name a data location and distinguish its address from its contents.

Find addresses first, emit code second

Observe

Start with a question

How can the first line use FIRST before the assembler reaches FIRST: 18?

Read the labelled program from top to bottom. At its first line, START is known but FIRST has not yet been defined. Track a location counter as the scan continues.

Explain

Explanation · 1 / 5

Prepare and scan the source

In the taught two-pass process, the first pass reads source lines, removes irrelevant comments or extra spacing, and checks their form. It starts a location counter at the supplied origin, here 0. Every instruction or data item in this model advances that counter by one.

Explanation · 2 / 5

Build the symbol table

When a label definition is reached, record the current address for that name. The first pass records START = 0, FIRST = 4, SECOND = 5 and TOTAL = 6. It can continue past the first use of FIRST because resolution will happen after all definitions have been found.

Explanation · 3 / 5

Resolve and encode in pass two

The second pass reads the source again, replaces label operands with their addresses, looks up the machine opcode and emits the encoded word. Data declarations also emit their initial data words. Both passes read source lines; generating object code belongs to the second pass in this taught model.

Explanation · 4 / 5

Check the complete result

The output includes four instruction words and three data words. Here data uses a full 16-bit unsigned word. Address 4 receives the binary representation of 18, while the operand in the instruction at 0 encodes the address 4.

Explanation · 5 / 5

Report unresolved or ambiguous names

Defining FIRST twice is a duplicate-label error. Using MISSING without a definition is an undefined-symbol error when the operand cannot be resolved. Guessing an address would hide the source error. The assembler translates the program; executing the resulting program is a separate step.

The symbol table follows assigned locations, so forward references can be resolved even after relocation.

Answer and checking points — teacher-written
  1. The symbol table is BEGIN=10, LEFT=14, RIGHT=15, RESULT=16.
  2. At address 10 the resolved instruction is LDD 14.
  3. At address 11 the resolved instruction is ADD 15.
  4. At address 12 the resolved instruction is STO 16.
  5. The first instructions refer to labels defined later; the completed symbol table lets pass two resolve these forward references.

Why this earns marks — teacher explanation

The three scoring groups are: object code to the second pass; line-by-line reading to both passes; both white-space removal and symbol-table labels to the first pass. The final two actions form one scoring group.

Question 1 · Command word: Compare4 teacher marks

Compare assembly language with machine code. Explain why assembly written for one processor instruction set may not run on a processor with a different instruction set.

S4.09.A01
Answer and checking points — teacher-written
  1. Assembly uses mnemonic opcodes and may use symbolic addresses.
  2. Machine code encodes instructions as binary patterns that the processor can execute.
  3. An assembler translates assembly instructions into the corresponding machine instructions.
  4. Different instruction sets define different operations, encodings or operand rules, so the same assembly source may need changes and reassembly.

Common error: Assembly language is a low-level language; its mnemonics are not executed directly as text.
