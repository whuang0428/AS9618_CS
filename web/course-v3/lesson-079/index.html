Justify from the problem's conditions

Start with the input and stopping contract

A loop justification connects a property of the problem to a property of the chosen structure. Use FOR when the count is known before repetition. Use REPEAT when an action must happen before its result can be checked. Use WHILE when the continuation rule can be checked before processing and no body execution may be needed.

Explain suitability in context

Different loop structures can often implement the same result with additional setup. Explain suitability rather than claiming that alternatives are impossible or inherently slower. For twelve readings a count-controlled header exposes the count; for repeated menu input a post-condition loop places the first request before validation.

Choose the quantity that is controlled

Distinguish attempts from accepted data. Three accepted ratings may require five attempts. A FOR for three accepted slots can contain a REPEAT for each slot’s attempts. A FOR for only three raw attempts would implement a different contract.

Core explanation · Exam essentials

  • Justify a loop by the known count, required first attempt or possible empty input.
  • Explain necessary setup for alternatives; do not claim only one loop can ever work.
Common misconception

The word input alone does not determine the loop type.

Check your understanding

Why is 'FOR is easier' an incomplete justification?

Check your answer

It does not connect the known iteration count to the loop's count control.

02

Combine a condition with a maximum attempt count

S11.05.A01

Visual overview

Maintain both continuation requirements

Some repetitions end for either of two reasons. A password attempt sequence stops on success or after three attempts. Initialise Password and Attempts before WHILE, then continue only while the password is wrong AND fewer than three attempts have occurred. Increment the counter after every input, including a successful attempt.

Compare equivalent stopping rules

A WHILE loop states the combined continuation rule directly and can be adapted when a preliminary condition should prevent attempts. A REPEAT loop could also express the task if at least one attempt is required, using an UNTIL condition for success OR three attempts. A fixed three-iteration FOR without an extra guard would continue asking after early success.

Explain the connector from the rule

Using OR in the continuation condition would allow one true half to override the other stopping event: a correct first attempt could still be followed by another prompt, or a wrong third attempt could be followed by a fourth. Success OR exhausted attempts is instead the corresponding stopping condition.

Compare complete solutions rather than isolated headers

For this task at least one attempt is allowed. REPEAT therefore avoids the artificial initial Password value used by WHILE: input supplies Password before UNTIL tests it. Both complete versions count the successful input and stop at the same point. If a prior lock state could prohibit all attempts, a pre-condition or an outer guard would be needed.

Worked example · Use a combined continuation condition

  1. Requirements and starting conditions

    The toy password is open. Permit at most three STRING attempts, stopping on the first correct attempt. At least one attempt is allowed.

  2. Cambridge pseudocode
    DECLARE Password : STRING
DECLARE Attempts : INTEGER
Password <- ""
Attempts <- 0
WHILE (Password <> "open") AND (Attempts < 3)
    INPUT Password
    Attempts <- Attempts + 1
ENDWHILE
OUTPUT Password = "open", Attempts
  3. Expected result

    open gives TRUE, 1; x, y, open gives TRUE, 3; x, y, z gives FALSE, 3. These are loop-control examples, not a password-storage design.

Worked example · Use the equivalent stopping condition

  1. Requirements and starting conditions

    Use the same password and attempt limit as the WHILE version, with at least one permitted attempt.

  2. Cambridge pseudocode
    DECLARE Password : STRING
DECLARE Attempts : INTEGER
Attempts <- 0
REPEAT
    INPUT Password
    Attempts <- Attempts + 1
UNTIL (Password = "open") OR (Attempts >= 3)
OUTPUT Password = "open", Attempts
  3. Expected result

    The three cases give the same success flags and attempt counts. No initial Password value is needed because input precedes the first UNTIL test.

Core explanation · Exam essentials

  • Continue only while the password is wrong AND attempts remain.
  • Count every attempt; the equivalent stopping rule is success OR the limit reached.
Common misconception

Using OR in the WHILE continuation condition can continue after success or exceed the attempt limit.

Check your understanding

Which stopping condition corresponds to the two WHILE restrictions?

Check your answer

(Password = "open") OR (Attempts >= 3).

Question 1 · Command word: Justify2 teacher marks

Justify a loop structure for asking for a positive integer until a positive value is entered. State a suitable stopping or continuation condition.

S11.05.A01
Answer and checking points — teacher-written
  1. REPEAT is suitable because the user must enter an attempt before it is checked.
  2. UNTIL Value > 0 stops when that attempt is acceptable.

Common error: Use the acceptance test as the REPEAT stopping condition.

Question 2 · Command word: Explain2 teacher marks

Explain the choice of WHILE for the supplied password program and why its condition joins the restrictions with AND.

Use this complete program for the stated task.

DECLARE Password : STRING

ENDWHILE

S11.05.A01
Answer and checking points — teacher-written
  1. The number of attempts depends on success while a maximum of three must be enforced.
  2. Both a wrong password and remaining attempts are needed for another iteration.

Common error: Another attempt is unnecessary once either stopping event occurs.

Question 3 · Command word: Compare3 teacher marks

Compare the supplied REPEAT password program with the WHILE program in this lesson. Explain why no initial Password assignment is needed here, why UNTIL uses OR, and the result for x, y, open.

Answer and checking points — teacher-written
  1. INPUT Password executes before the first UNTIL test, so it supplies the initial value.
  2. Success or reaching three attempts is sufficient to stop; the stopping conditions therefore use OR.
  3. x, y, open gives TRUE and 3; the successful third input still counts as an attempt.

Common error: Do not copy the WHILE continuation connector into the stopping condition.

Original question · Cambridge 9618/22

1. Justify a loop for an unknown number of inputs

Cambridge 9618/22 · October/November 2023 · 2(b) · 2 marks

Selected parts: 2(b) [2].

Teacher solution and explanation

The input values determine when the phases end. Give a suitable loop type and link its stopping behaviour to that fact.

A condition-controlled loop, for example REPEAT … UNTIL, is suitable because the number of inputs is unknown and the loop ends when a specified input value is entered.

One mark is for a suitable conditional loop and one for the matching justification. The official scheme accepts either a pre-condition or a post-condition loop.

A FOR loop with a guessed count does not follow the sentinel-based requirement. “It repeats” does not explain why this loop type fits.
