Program a booking system · Concept 19

Justify the structure from the requirement

Observe

Three requirements

TaskInformation available
Print four receiptsExactly four actions are required
Process requests until 0Count unknown; first input may be 0
Obtain one valid optionAt least one attempt is required

Look, then discuss

Which fact tells you whether FOR, WHILE or REPEAT is the clearest choice?

Compare printing four receipts, accepting requests until 0, and asking for one valid menu option. All repeat actions, but their stopping information differs.

Recall

Recall the three structures

FOR controls a predetermined counter sequence. WHILE tests a continuation condition before the body. REPEAT tests a stopping condition after the body.

Explain

Explanation · 1 / 3

Use FOR for a known count or sequence

Four receipts give four iterations. “The number of repetitions is known before the loop begins” is the reason; merely saying “FOR repeats” is not a useful justification.

Explanation · 2 / 3

Use WHILE when processing may be skipped

A sentinel stream may contain no ordinary data. Reading before a WHILE test naturally excludes a first sentinel without processing it.

Explanation · 3 / 3

Use REPEAT when an attempt must occur first

A menu option must be entered before validation. REPEAT naturally captures that order. A correctly initialised WHILE solution can also work; suitability does not imply that every other structure is impossible.

Work together

Write a reason that belongs to the question

A sensor supplies readings until -999; the number of readings is unknown.

Work together · 1 / 2

Name a suitable structure

A condition-controlled loop is suitable. For a first marker that must be excluded, use WHILE Reading <> -999 with the initial input before the loop.

Work together · 2 / 2

Connect behaviour to the requirement

The input determines when processing stops, and the first input may already be the marker. A guessed FOR count would either stop too early or ask for unwanted readings.

An exam justification should name the relevant count or stopping behaviour and connect it to the context.

Check

Try it yourself · Teacher-written

A loop displays 20, 15, 10, 5, 0. Which structure fits and why?

Check your reasoning

FOR with 20 TO 0 STEP -5 fits because the complete sequence is predetermined before execution.

Hint — reading the question

The input values determine when the phases end. Give a suitable loop type and link its stopping behaviour to that fact.

Reasoning and model answer — teacher-written

A condition-controlled loop, for example REPEAT … UNTIL, is suitable because the number of inputs is unknown and the loop ends when a specified input value is entered.

A FOR loop with a guessed count does not follow the sentinel-based requirement. “It repeats” does not explain why this loop type fits.

Program a booking system · Concept 20

Stop after success or the final attempt

Observe

Two reasons to stop

  • The entered code is "open".
  • Or, three attempts have been made.
  • Another attempt is needed only while the code is wrong AND attempts remain.

Look, then discuss

How can a desk access-code check allow at most three attempts and stop early on success?

Compare success on attempt 1, success on attempt 3 and three failures. A fourth input must never be requested.

Recall

Recall AND and OR

To continue, both permissions must hold. To stop, either stopping event is enough. This example illustrates loop logic only; it is not a model of a production authentication system.

Explain

Explanation · 1 / 3

Give the tested state initial values

Password <- "" makes the first success test FALSE, and Attempts <- 0 records that no attempt has been made. Both variables have values before WHILE reads them.

Explanation · 2 / 3

Require both continuation conditions

(Password <> "open") AND (Attempts < 3) permits another input only when the previous input failed and fewer than three attempts have occurred.

Explanation · 3 / 3

Count every completed attempt exactly once

After INPUT Password, increment Attempts. The next test can stop on the new success or on the reached limit. OR in the WHILE condition would allow continuation when only one restriction remained true.

DECLARE Password : STRING
DECLARE Attempts : INTEGER
Password <- ""
Attempts <- 0
WHILE (Password <> "open") AND (Attempts < 3)
    INPUT Password
    Attempts <- Attempts + 1
ENDWHILE
OUTPUT Password = "open", Attempts

Work together

Check success at the limit

Inputs are "x", "y", "open".

Work together · 1 / 2

Trace the first two attempts

Attempts becomes 1 and 2, while the password remains wrong. Both continuation conditions are TRUE before the next input.

Work together · 2 / 2

Trace the third test

The third input succeeds and Attempts becomes 3. Both continuation conditions are now FALSE. The final output reports TRUE and 3, with no fourth input.

Count attempts after they occur, and stop when either another attempt is unnecessary or the limit is reached.

Check

Try it yourself · Teacher-written

A post-condition version uses UNTIL. Write its stopping condition.

Check your reasoning

(Password = "open") OR (Attempts >= 3). Success or an exhausted attempt allowance is sufficient to stop.

Connect

Keep this idea

Multiple stopping events usually become AND-connected permissions in WHILE, or OR-connected stopping conditions in UNTIL.

An input buffer has another limit: the program must never store beyond its declared capacity.

Program a booking system · Concept 21

Stop safely at a sentinel or full storage

Observe

Buffer outcomes

InputsStored entriesNext input requested?
0noneno
2, 02no
2, 3, 42, 3, 4no fourth input

Look, then discuss

How can a three-slot request buffer stop without storing 0 or asking for a fourth request?

The buffer accepts positive requests until sentinel 0 or until three ordinary requests have been stored. Compare 0, then 2,0, and finally 2,3,4.

Recall

Recall bounded array access

An ARRAY[1:3] has valid indices 1, 2 and 3. Count records how many entries are stored. The sentinel is a control signal, so it must be checked before storage.

Explain

Explanation · 1 / 3

Separate storage capacity from the next value

Start Count at 0 and read the first request. Continue only while Count < 3 and Seats <> 0. Both values are simple scalar variables, so evaluating either comparison does not risk an invalid array access.

Explanation · 2 / 3

Store only an ordinary request

Increment Count, then write Requests[Count]. Reaching Count 3 is allowed: it is the final valid array element, not an overflow.

Explanation · 3 / 3

Check remaining capacity before asking again

Read the next Seats only if Count < 3. This avoids requesting an unnecessary fourth value after the buffer is full.

DECLARE Requests : ARRAY[1:3] OF INTEGER
DECLARE Seats, Count : INTEGER
Count <- 0
INPUT Seats
WHILE (Count < 3) AND (Seats <> 0)
    Count <- Count + 1
    Requests[Count] <- Seats
    IF Count < 3 THEN
        INPUT Seats
    ENDIF
ENDWHILE
OUTPUT Count

Work together

Prepare the same reasoning for a flowchart

The real-paper task uses 20 REAL values and sentinel 99.9 rather than this three-request buffer.

Work together · 1 / 2

Trace an immediate sentinel

If the first value is 99.9, follow the stop path before any array assignment. No stored-value count or array index should advance as though data had been accepted.

Work together · 2 / 2

Trace the last permitted storage

The twentieth ordinary value must be stored. Advance the next-position index to 21, then stop before an invalid access. Read the exact placement of further INPUT operations when comparing the supplied flowchart alternatives.

Verify sentinel-first, partial-fill and exactly-full paths; they expose different placement errors.

Original question · Cambridge 9618/22

1. Stop input at a sentinel or a full array

Cambridge 9618/22 · October/November 2025 · 2 · 5 marks

Selected parts: 2 [5].

Hint — reading the question

The sentinel 99.9 is not stored. Stop after the twentieth ordinary value without requesting a twenty-first value.

Reasoning and model answer — teacher-written

Start at Index = 1. Check the sentinel before storing. After storing an ordinary value, increment Index; end when it becomes 21. If the first input is 99.9, no array element changes.

Official mark scheme
Why this earns marks — teacher explanation

The five points cover index initialisation, repeated input, the sentinel stop, the capacity stop, and storing with index advancement. Both official flowchart alternatives are included below. The second official diagram requests another input before testing Index = 21; the teacher diagram checks capacity immediately after storing, so it needs no twenty-first input.

Common mistakes — teacher analysis

Testing the sentinel only after storage violates an explicit condition. Testing for Index = 20 before storing can allow only 19 values.

Question 1 · Command word: Justify2 teacher marks

Justify a loop structure for asking for a positive integer until a positive value is entered. State a suitable stopping or continuation condition.

S11.05.A01
Answer and checking points — teacher-written
  1. REPEAT is suitable because the user must enter an attempt before it is checked.
  2. UNTIL Value > 0 stops when that attempt is acceptable.

Common error: Use the acceptance test as the REPEAT stopping condition.

Question 2 · Command word: Explain2 teacher marks

Explain the choice of WHILE for the supplied password program and why its condition joins the restrictions with AND.

Use this complete program for the stated task.

DECLARE Password : STRING
DECLARE Attempts : INTEGER
Password <- ""
Attempts <- 0
WHILE (Password <> "open") AND (Attempts < 3)
    INPUT Password
    Attempts <- Attempts + 1
ENDWHILE
OUTPUT Password = "open", Attempts
S11.05.A01
Answer and checking points — teacher-written
  1. The number of attempts depends on success while a maximum of three must be enforced.
  2. Both a wrong password and remaining attempts are needed for another iteration.

Common error: Another attempt is unnecessary once either stopping event occurs.

Question 3 · Command word: Compare3 teacher marks

Compare the supplied REPEAT password program with the WHILE program in this lesson. Explain why no initial Password assignment is needed here, why UNTIL uses OR, and the result for x, y, open.

Use this complete program and the stated inputs.

DECLARE Password : STRING
DECLARE Attempts : INTEGER
Attempts <- 0
REPEAT
    INPUT Password
    Attempts <- Attempts + 1
UNTIL (Password = "open") OR (Attempts >= 3)
OUTPUT Password = "open", Attempts
S11.05.A01
Answer and checking points — teacher-written
  1. INPUT Password executes before the first UNTIL test, so it supplies the initial value.
  2. Success or reaching three attempts is sufficient to stop; the stopping conditions therefore use OR.
  3. x, y, open gives TRUE and 3; the successful third input still counts as an attempt.

Common error: Do not copy the WHILE continuation connector into the stopping condition.

Question 4 · Command word: Justify2 teacher marks

Justify a loop structure for reading exactly seven daily rainfall values.

S11.05.A01
Answer and checking points — teacher-written
  1. A FOR loop is suitable because seven iterations are known before the loop starts.
  2. Its body reads one new value per iteration.

Common error: Refer to the specified count.
