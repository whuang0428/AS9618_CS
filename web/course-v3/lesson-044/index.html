01

Data management and the data dictionary

S8.05.A01

Visual overview

Identify metadata

A DBMS provides software services to store, retrieve and update database data. It maintains a data dictionary containing metadata: information about the database's tables, fields, types, lengths, keys and constraints rather than the ordinary records themselves.

Use a shared definition

When a table or query is defined, the DBMS can consult that metadata to check field names and permitted structures. Maintaining definitions centrally reduces the risk that separate applications use conflicting assumptions about the same stored data.

One school example: definition versus stored fact

Metadata in the dictionaryApplication data
StudentName: VARCHAR(40)Student 21 has name Amina.
StudentID: INTEGER, primary keyStudentID 21 identifies this student.
Student.TutorID references Tutor.TutorIDAmina has TutorID 7.
Mark must be between 0 and 100Amina has Mark 73.

Follow a use of metadata

A request for StudntName contains a name absent from the schema, so it cannot be resolved as the intended field. A request assigning Mark 145 can be checked against the stored range rule. Neither decision requires the dictionary to contain Amina as a metadata value.

Core explanation · Exam essentials

  • The data dictionary stores metadata describing tables, fields, types, lengths, keys and constraints.
  • The DBMS uses these definitions when checking and processing requests.
Common misconception

A patient's address is application data; the permitted type and size of the address field are metadata.

Check your understanding

Which belongs in the dictionary: a customer's balance of 42.50 or the fact that Balance has type REAL?

Check your answer

The field definition belongs in the dictionary; 42.50 is a value in a customer record.

02

Represent the organisation's data

S8.05.A02

Visual overview

Start with the organisation

Data modelling identifies the entities, attributes and relationships required by an organisation. It starts from the information and business rules, such as whether one appointment may involve several doctors, rather than from how bytes will be arranged on disk.

Test the model

A DBMS modelling tool can help create and inspect the relationships before they are implemented as tables. The designer must still confirm that the model matches the stated requirements; software cannot infer every business rule from field names.

Continue the school example

  1. State the rule: Each student has one tutor; one tutor may advise many students.
  2. Assign facts: Student owns StudentID, StudentName and Mark. Tutor owns TutorID and TutorName.
  3. Connect: Put the tutor reference on Student, the many side.
  4. Change the rule: If each student may have several tutors, a StudentTutor association is needed; one TutorID field no longer records all links.

Separate the tool from the design judgement

The modelling tool can draw these entities and their association. It cannot decide whether the school really permits several tutors per student. Confirm that requirement with the organisation. Lesson 043 supplies the E-R and normalisation methods; here the focus is the DBMS facility supporting that work.

Core explanation · Exam essentials

  • Data modelling identifies entities, attributes and relationships from organisational requirements.
  • Validate the model against business rules before turning it into table definitions.
Common misconception

Data modelling describes what the data represents; it does not choose which individual user may edit a record.

Check your understanding

Why ask whether pupils may belong to several tutor groups?

Check your answer

That rule changes relationship cardinality and may require a linking entity.

03

Define the logical schema

S8.05.A03

Visual overview

Define the logical organisation

The logical schema specifies the logical organisation of the database: its tables, attributes, data types, keys, relationships and constraints. Programs can use these definitions without knowing the physical disk locations of individual records.

Relate schema to dictionary

A model of pupils and groups can become Pupil(PupilID, PupilName, GroupID) and TutorGroup(GroupID, GroupName), with specified primary and foreign keys. The schema is the design being defined; the data dictionary stores metadata describing that design.

School logical schema

RelationDefinitions and rules
TutorTutorID INTEGER primary key; TutorName VARCHAR(40)
StudentStudentID INTEGER primary key; StudentName VARCHAR(40); TutorID INTEGER non-null foreign key; Mark INTEGER in 0–100
RelationshipStudent.TutorID references Tutor.TutorID; many students may reference tutor 7.

Swipe horizontally to compare every column →

Connect all three descriptions

This schema permits a Tutor record (7, Jo) and a Student record (21, Amina, 7, 73). The model expresses which facts belong together; the schema specifies their logical implementation; dictionary entries record those definitions. Moving the underlying files does not require the application to substitute disk-sector numbers for StudentID.

Core explanation · Exam essentials

  • The logical schema defines tables, attributes, types, keys, relationships and constraints.
  • The dictionary records metadata about that schema; physical storage locations are a separate concern.
Common misconception

The logical schema and data dictionary are related, but they are not interchangeable names for the same object.

Check your understanding

Must an application know the disk sector containing TutorGroup before querying it?

Check your answer

No. It uses the logical table and field definitions; the DBMS handles physical access.

04

Enforce valid values and relationships

S8.05.A04

Visual overview

Apply the declared rules

Integrity constraints restrict invalid or inconsistent database changes. A primary key identifies records uniquely, a foreign key checks a declared reference, and field types or validation rules restrict values to a permitted domain.

Distinguish validity from truth

For an examination database, a rule can require Mark to be between 0 and 100 and CandidateID to refer to an existing candidate. The DBMS rejects changes violating those rules. A plausible but incorrectly transcribed mark can still pass them, so integrity constraints do not establish factual truth.

Initial school records

TableComplete records
Tutor(TutorID, TutorName)(7, Jo)
Student(StudentID, StudentName, TutorID, Mark)(21, Amina, 7, 73)

State the rules and reset boundary

For the following independent attempts, restart from the initial records each time. Editors may insert students; Readers may only retrieve them. TutorID is required and must reference Tutor; Mark must be in 0–100. A rejected operation leaves both tables unchanged.

Check the full accepted state

In the accepted case Student becomes (21, Amina, 7, 73), (22, Ben, 7, 80), and Tutor stays (7, Jo). Acceptance means this operation passed these declared checks. A typed mark of 80 could still be a copying mistake if the actual script says 08.

Core explanation · Exam essentials

  • Integrity constraints check identities, references and permitted field values when data changes.
  • A value that passes a constraint can still be factually wrong.
Common misconception

A backup helps recovery after a failure; it does not validate a new examination mark.

Check your understanding

Does a stored mark of 73 prove that 73 was written on the script?

Check your answer

No. It is within range, but it may still be the wrong value for that script.

05

Assign access rights to users and groups

S8.05.A05

Visual overview

Check permission after identity

Database security restricts who can access stored information and which operations are permitted. After authentication establishes identity, access rights can allow reading selected data while denying insertion, modification or deletion.

Manage rights through roles

Rights may be assigned to an individual account or to a group representing a role. A school can give Tutors access to contact information and the Finance group permission to update fees. Group membership must be maintained when responsibilities change.

Same row, different decision

RequestPermissionIntegrityOutcome
Editor inserts (22, Ben, 7, 80)AllowedPasses the school rulesOne student added.
Reader inserts the same valid rowDeniedNo permission to perform this insertionNo student added.
Editor inserts (23, Chen, 9, 80)AllowedMissing tutor 9No student added.

Swipe horizontally to compare every column →

Explain group administration

Assign an account to the Readers group to apply its configured read rights. Moving that account to Editors changes which operations may be requested; it does not relax the primary-key, tutor-reference or mark-range rules. Rights may be limited to particular tables or fields, so access to contact information need not permit changes to marks.

Core explanation · Exam essentials

  • Access rights specify which data and operations an authenticated user or group may use.
  • Permissions and integrity answer different questions and must both be satisfied.
Common misconception

A valid login does not imply permission to modify every table.

Check your understanding

How can a new finance officer receive the existing finance permissions?

Check your answer

Add the authenticated account to the appropriately configured Finance group.

06

Back up and recover a consistent database

S8.05.A06

Visual overview

Prepare a recoverable copy

A backup procedure creates a recoverable copy of database state. Schedule backups often enough for the acceptable data-loss interval, protect copies from the same failure as the live system, and restrict access because the copies may contain sensitive records.

Restore and verify

Recovery restores a suitable consistent backup after loss or corruption. Where the DBMS supports transaction logs, later recorded changes may be replayed to a chosen recovery point. Periodic restore tests check that the stored copies and procedure actually work.

A complete backup-only recovery

Time / eventStudent records (ID, Name, TutorID, Mark)
18:00 consistent backup(21, Amina, 7, 73)
09:00 update and insert(21, Amina, 7, 75), (22, Ben, 7, 80)
11:00 live storage failsLive records unavailable. No recovery logs exist.
Restore the 18:00 backup(21, Amina, 7, 73): the change to 75 and student 22 are absent.

Swipe horizontally to compare every column →

Verify relationships as well as files

Restore the associated Tutor record (7, Jo) as part of the same consistent database state. Then verify the student count, values and reference to tutor 7 before returning to service. A later Student copy combined with an incompatible earlier Tutor copy could fail the reference check.

Worked example · A failure between backups

  1. Timeline

    A verified backup was completed at 18:00 yesterday. The live database fails at 11:00 today.

  2. Backup-only recovery

    Restoring that copy returns the database to its saved 18:00 state.

  3. Loss interval

    Changes after 18:00 are not present unless another recovery source preserves them.

  4. Improve the procedure

    Choose a shorter backup interval or supported log recovery to meet the required recovery point.

Core explanation · Exam essentials

  • Keep protected, consistent recovery copies separate from the live failure risk and test restoration.
  • Backup-only recovery restores the saved state; subsequent changes require another recovery source.
Optional extension · A supported recovery log

After understanding backup-only recovery, a DBMS log can record later committed changes for replay: restore 18:00, replay the mark change to 75, then the insertion of student 22. This reaches the later state only if the required records and recovery mechanism are available. Detailed logging algorithms are outside this lesson.

Common misconception

A backup on the same failed disk may be lost with the live data; a successful copy job is not a restore test.

Check your understanding

Why test a restoration before an actual emergency?

Check your answer

To discover unreadable copies, missing dependencies or an ineffective recovery procedure while the live database is still available.

07

Use the developer interface

S8.06.A01

Visual overview

Build database objects

A DBMS developer interface supplies tools for constructing database objects and applications. A developer can define tables and constraints and build forms or reports that use the database without manually implementing every interface component.

Bind an interface to data

For a school admissions form, the developer chooses the fields, configures validation and links controls to the appropriate data. The resulting form collects a new pupil record. Designing that form is distinct from the query processor carrying out its eventual data request.

Build and use a student-entry form

  1. Design: Provide controls for StudentID, StudentName, TutorID and Mark. Link them to the Student fields.
  2. Configure: Offer existing tutors and display the 0–100 mark requirement.
  3. Use: An Editor enters (22, Ben, 7, 80) and submits the form.
  4. Result: The DBMS checks permission and constraints, then stores the new row. The form can display confirmation.

Explain the boundary of the tool

A form check helps the user correct input, but the database rules must also govern requests from another form or query tool. A report designer chooses fields and layout; the saved query is executed each time the report needs fresh records.

Core explanation · Exam essentials

  • The developer interface helps define objects and construct forms, queries and reports.
  • Designing an interface is separate from executing its later requests.
Common misconception

The developer interface creates and configures objects; it is not the component that executes every user's query.

Check your understanding

Which tool helps arrange fields and labels on a new data-entry form?

Check your answer

The DBMS developer interface or its form-design tools.

08

Follow a query through the query processor

S8.06.A02

Visual overview

Interpret and plan

A query processor interprets a submitted query, checks its syntax and references, and determines how to carry out the requested data access. It can use table definitions and available indexes when choosing a suitable execution plan.

Execute and return

It executes the plan and produces the requested result while DBMS permissions and integrity rules apply. A staff query for overdue loans therefore involves locating, filtering and returning records; it does not require rebuilding the data-entry form each time.

Retrieve from the same school state

  1. Initial data: Student contains (21, Amina, 7, 73) and (22, Ben, 7, 80).
  2. Request: Retrieve StudentName for students whose Mark is at least 75.
  3. Check and plan: Resolve StudentName and Mark using the schema; confirm permitted access and choose a suitable access path.
  4. Execute: Compare 73 and 80 with 75. Only student 22 qualifies.
  5. Return: The result is one value, Ben. Both original records remain stored.

State the abstraction boundary

An index may help a suitable request locate records, but a small table may be scanned instead. This is a conceptual route from request to result, not a claim that every DBMS performs its internal checks in one fixed order. SQL spelling is developed in Lessons 046 and 047.

Core explanation · Exam essentials

  • The query processor interprets a request, checks names and syntax, plans access and executes the query.
  • Metadata and indexes support processing; an execution plan does not change the logical data model.
Common misconception

An execution plan is a way to carry out a query, not a redesign of the organisation's entities.

Check your understanding

Who carries out a saved query when a user presses its Run button?

Check your answer

The query processor executes the request; the button may have been built using the developer interface.

Question 1 · Command word: Describe3 teacher marks

Describe two pieces of metadata a DBMS stores for a field named BirthDate and explain one way the DBMS can use that metadata.

S8.05.A01
Answer and checking points — teacher-written
  1. It stores the field's data type, such as DATE.
  2. It can record a constraint such as whether a null value is permitted.
  3. The stored definition helps the DBMS check whether a proposed field value satisfies the declared requirements.

Common error: Give definitions about BirthDate, not one person's date of birth.

Question 2 · Command word: Describe3 teacher marks

Describe the logical schema for Team(TeamID, TeamName) and Player(PlayerID, PlayerName, TeamID), where each player has one team. Explain why the schema need not contain disk-sector addresses.

S8.05.A03
Answer and checking points — teacher-written
  1. It specifies both table structures, field types and their identifying keys.
  2. Player.TeamID is declared as a reference to Team.TeamID.
  3. Logical definitions are separated from the DBMS's physical storage placement.

Common error: The schema is the organisation being defined; the dictionary records metadata describing it.

Question 3 · Command word: Explain3 teacher marks

A DBMS receives three changes: reuse an existing OrderID primary-key value, reference an absent CustomerID, and set a quantity to -3 when the rule requires at least 1. Explain the integrity reason for rejecting each.

S8.05.A04
Answer and checking points — teacher-written
  1. Reusing OrderID would violate the unique-record identifier constraint.
  2. The absent customer would leave an invalid foreign-key reference.
  3. Quantity -3 is outside the declared permitted range.

Common error: Name the relevant constraint for each proposed change.

Question 4 · Command word: Explain3 teacher marks

Explain how individual or group access rights can allow a receptionist to read appointment times while preventing changes to treatment notes.

S8.05.A05
Answer and checking points — teacher-written
  1. The receptionist account or its role group is granted read access to appointment times.
  2. The role is denied modification rights for the treatment-note data.
  3. The DBMS checks those permissions when the authenticated account requests an operation.

Common error: Do not assume authentication alone provides selective permissions.

Question 5 · Command word: State3 teacher marks

The latest usable backup is from 02:00. A failure occurs at 09:00 and there are no recovery logs. State the restored data state and explain two improvements to the backup procedure.

S8.05.A06
Answer and checking points — teacher-written
  1. The restore can recover the saved 02:00 state, with later changes absent.
  2. More frequent consistent backups can reduce the possible lost interval.
  3. Keeping a protected separate copy and testing restoration improves the ability to recover when the live system fails.

Common error: A backup from 02:00 does not include changes made afterwards.

Question 6 · Command word: Describe3 teacher marks

Describe three actions performed by a query processor after receiving a request for the names of members with unpaid fees.

S8.06.A02
Answer and checking points — teacher-written
  1. It interprets the request and resolves the referenced table and field definitions.
  2. It chooses a suitable sequence of access and filtering operations.
  3. It executes those operations and returns the matching member names.

Common error: Do not substitute the design of the entry form for executing the request.

1. Distinguish two DBMS descriptions

Cambridge 9618/11 · May/June 2024 · 6(b) · 4 marks

Selected parts: 6(b) [4].

Reading the question — teacher guidance

Give a definition and useful detail for each term. Keep the two two-mark answers separate.

Solution / model answer — teacher-written

A data dictionary stores metadata describing the database, such as field names, data types, keys and validation rules.

A logical schema is a conceptual, platform-independent design of the database, showing entities and their relationships before a physical implementation is chosen.

Official mark scheme
Why this earns marks — teacher explanation

There are at most two marks for data dictionary and two for logical schema. An example supports the relevant definition; a long list of field types does not earn the logical-schema marks.

Common mistakes — teacher analysis

Actual quiz scores are data. The definition of the Score field is metadata. A logical schema is not a list of disk locations.

2. Explain a DBMS developer interface

Cambridge 9618/12 · October/November 2025 · 4(d) · 2 marks

Teacher solution and explanation

Describe what a developer can construct or maintain using the interface, rather than how an ordinary user views one saved record.

The interface lets a developer create or modify database tables and set up relationships between them. It can also be used to design data-entry forms with controls such as drop-down lists.

Any two accepted purposes can earn the two marks. The official scheme also accepts reports, menus and inspecting data or metadata through queries.

“It makes the database easy to use” is too general. Name the object or action the interface supports.
