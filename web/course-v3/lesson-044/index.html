8.2.1

Features provided by a DBMS

Features of the Library DBMS

The database is the stored collection of tables, records and associated definitions. The database management system (DBMS) is the software used to define, organise, retrieve, maintain and protect that data. It accepts requests, checks them and manages the resulting state.

Using the Library DBMS

The examples use the same database workspace. Changing section preserves its records. “Load this example” places the SQL in the editor; running the statement may change the database. Restore the initial data before comparing independent operations.

The operations run in a PostgreSQL engine in your browser. Simulated users demonstrate operations under different access rights. Saved progress remains in this browser on this site.

Practice question · teacher-written

A librarian enters a new borrowing record. Identify the data being stored and describe the role of the DBMS.

Suggested answer

The new Loan row is part of the database. The DBMS processes the request, checks types, keys, references and rights, and stores the row if it is valid.

Data modelling and the logical schema

Data modelling identifies the entities, attributes and relationships required by a system. A logical schema describes the conceptual design of a database independently of a particular DBMS. It specifies how the data is organised and how the entities or tables are related. This design can then be implemented using the facilities of a chosen DBMS.

A changed member name is a data change: the definition of MemberName stays the same. Adding a new Note attribute changes the schema. The model should be checked against real events before implementation; the DBMS’s structure tools then create and inspect the chosen definitions.

Practice question · teacher-written

Explain whether adding a valid Loan record changes the cardinality of the Member–Loan relationship.

Suggested answer

The cardinality remains one-to-many because the existing relationship already permits several loans per member. A change to the business requirements may require a change to the model.

The DBMS maintains a data dictionary

A data dictionary stores metadata: data describing the database’s data and structure. It can record table and attribute names, data types, lengths, required values, keys, references, validation constraints and permissions. The Member and Loan records contain the data described by this metadata.

ALTER TABLE Member ADD Note VARCHAR(80);

State the expected change before running the statement. The data dictionary gains an entry for Note with type VARCHAR(80); this definition permits NULL. The four existing Member records remain, with no Note value supplied. Updating a Note value later does not change the column definition.

Maintaining the data dictionary

The DBMS updates the metadata when the table definition changes. The dictionary view displays this metadata. If Note already exists, a second attempt to add the same column is rejected.

Practice question · teacher-written

Explain how the DBMS uses the data dictionary when processing a request for MemberName.

Suggested answer

It can check that MemberName exists in the named table, determine its type and associated constraints, and use the stored structure information while planning and executing the request.

Maintaining data integrity

Data integrity concerns maintaining the validity and consistency of stored data. The DBMS checks declared constraints when changes are attempted. If a statement violates a constraint, the DBMS rejects that statement and its changes are not applied.

Constraints and accuracy

A value can satisfy a constraint and still be incorrect. For example, an existing MemberID may identify the wrong borrower. Verification is needed to check that entered data matches its source.

Practice question · teacher-written

Explain why an insertion referring to MemberID 99 is still rejected when the user has permission to insert records.

Suggested answer

Permission allows the user to attempt the insertion, but MemberID 99 does not exist in Member. The foreign-key constraint rejects the invalid reference.

Access rights for individuals and groups

Access rights specify which operations a user may perform on which database objects. Assigning rights to a group makes it easier to manage people who need the same access. An individual can also receive a direct grant without giving that right to every member of their group.

Users, groups and initial access rights
UserGroup / roleInitial rights
Studentlibrary_readersRead the library tables; cannot insert, update or delete.
Librarianlibrary_writersRead and maintain library records.
AdministratorDatabase ownerManage definitions, roles, grants and the database.

Grant an operation directly to Student using the individual-rights control, then revoke it and repeat the operation. Compare the result with granting the right to the group: members inherit the rights assigned to their group. Access rights should permit the operations required by each user’s role.

Practice question · teacher-written

Explain one advantage of assigning SELECT access to a group of users.

Suggested answer

Adding a user to the group gives the common access without repeating each grant. Changing the group’s rights updates the shared policy. A direct individual grant can provide additional access for a particular user.

Backup and recovery procedures

A backup is a saved copy used to recover the database after loss, damage or an unwanted change. A backup procedure specifies the data to copy, the backup schedule, the storage location, access rights and the method used to test restoration.

Database state during backup and recovery
MomentActionLoan 203
T0Start from the teaching dataReturned FALSE; Fee 6
T1Create a backupBackup contains FALSE and 6
T2Record the return and waive the feeCurrent data becomes TRUE and 0
T3Restore the T1 backupCurrent data returns to FALSE and 6

Check the date and time of the backup before restoring it. This operation replaces the current database with its earlier state, so changes after that point are lost from the restored state. The workbench backup includes the schema, records and roles. Its separate automatic progress save helps you continue across pages; it is not a substitute for an independent recovery copy.

Requirements of a backup procedure
DecisionPurpose
Schedule backups according to acceptable data lossMore recent copies reduce the amount of work lost after a failure.
Keep protected copies away from the original failure locationA fault or theft affecting the original should not destroy every copy.
Restrict access and protect stored copiesBackups contain data that still requires access control.
Retain suitable earlier versionsA newly discovered problem may already exist in the latest copy.
Test restorationVerify that the database can be restored from the backup.

Scope of the backup demonstration

The demonstration backup is stored in the browser workspace. An operational backup procedure should use independent storage and test restoration. Recovering changes made after a backup requires an additional recovery source, such as a transaction log.

Practice question · teacher-written

A backup is made at 09:00 and a failure occurs at 11:00. Describe the data recovered when only the 09:00 backup is restored.

Suggested answer

The database is restored to the state recorded in the 09:00 backup. Changes made between 09:00 and 11:00 are not recovered from that backup.

Developer interface and query processor

Use and purpose of the developer interface

The table and schema views, SQL editor, example controls and result viewer provide a simplified developer interface in this simulation. A developer can test a statement, inspect an error, correct it and verify the result. A DBMS may also provide tools for designing forms and reports.

Developer interface facilities
TaskInterface facilityOutcome
Define Member and its keyTable-definition editor or SQL editorThe DBMS creates a table definition.
Find outstanding loansQuery editor and result gridTest which records the request returns.
Create a form for recording a returnDevelop a form or prepared operationUsers supply the relevant loan and request the update.
Present a weekly totalReport designer or saved queryFormat retrieved summaries for the intended audience.

Practice question · teacher-written

Identify the component that provides the query editor and the component that processes the SQL statement.

Suggested answer

The developer interface provides the editor and execution control. The query processor within the DBMS checks, plans and executes the request and returns its outcome.

Use and purpose of the query processor

The query processor interprets a query, checks it against the database definitions and access rights, determines an execution plan and executes the query. The execution plan may use an index to locate the required records.

Interpreting an execution plan

EXPLAIN displays the execution plan selected by the DBMS. For a small table, the plan may use a sequential scan. The presence of an index does not mean that the DBMS will use it for every query.

Practice question · teacher-written

Explain why a statement with valid SQL keywords can be rejected when an attribute name is misspelled.

Suggested answer

The syntax can be recognisable while a named attribute is absent from the schema. The processor must resolve the statement’s names against metadata before it can retrieve the requested values.

Question 1 · Command word: Describe3 teacher marks

Describe two pieces of metadata a DBMS stores for a field named BirthDate and explain one way the DBMS can use that metadata.

S8.05.A01
Answer and checking points — teacher-written
  1. It stores the field's data type, such as DATE.
  2. It can record a constraint such as whether a null value is permitted.
  3. The stored definition helps the DBMS check whether a proposed field value satisfies the declared requirements.

Common error: Give definitions about BirthDate, not one person's date of birth.

Question 2 · Command word: Describe3 teacher marks

Describe the logical schema for Team(TeamID, TeamName) and Player(PlayerID, PlayerName, TeamID), where each player has one team. Explain why the schema need not contain disk-sector addresses.

S8.05.A03
Answer and checking points — teacher-written
  1. It specifies both table structures, field types and their identifying keys.
  2. Player.TeamID is declared as a reference to Team.TeamID.
  3. Logical definitions are separated from the DBMS's physical storage placement.

Common error: The schema is the organisation being defined; the dictionary records metadata describing it.

Question 3 · Command word: Explain3 teacher marks

A DBMS receives three changes: reuse an existing OrderID primary-key value, reference an absent CustomerID, and set a quantity to -3 when the rule requires at least 1. Explain the integrity reason for rejecting each.

S8.05.A04
Answer and checking points — teacher-written
  1. Reusing OrderID would violate the unique-record identifier constraint.
  2. The absent customer would leave an invalid foreign-key reference.
  3. Quantity -3 is outside the declared permitted range.

Common error: Name the relevant constraint for each proposed change.

Question 4 · Command word: Explain3 teacher marks

Explain how individual or group access rights can allow a receptionist to read appointment times while preventing changes to treatment notes.

S8.05.A05
Answer and checking points — teacher-written
  1. The receptionist account or its role group is granted read access to appointment times.
  2. The role is denied modification rights for the treatment-note data.
  3. The DBMS checks those permissions when the authenticated account requests an operation.

Common error: Do not assume authentication alone provides selective permissions.

Question 5 · Command word: State3 teacher marks

The latest usable backup is from 02:00. A failure occurs at 09:00 and there are no recovery logs. State the restored data state and explain two improvements to the backup procedure.

S8.05.A06
Answer and checking points — teacher-written
  1. The restore can recover the saved 02:00 state, with later changes absent.
  2. More frequent consistent backups can reduce the possible lost interval.
  3. Keeping a protected separate copy and testing restoration improves the ability to recover when the live system fails.

Common error: A backup from 02:00 does not include changes made afterwards.

Question 6 · Command word: Describe3 teacher marks

Describe three actions performed by a query processor after receiving a request for the names of members with unpaid fees.

S8.06.A02
Answer and checking points — teacher-written
  1. It interprets the request and resolves the referenced table and field definitions.
  2. It chooses a suitable sequence of access and filtering operations.
  3. It executes those operations and returns the matching member names.

Common error: Do not substitute the design of the entry form for executing the request.

Question 7 · Command word: Describe2 teacher marks

A designer discovers that a patient can have several appointments and an appointment concerns one patient. Describe how data modelling represents that rule.

S8.05.A02
Answer and checking points — teacher-written
  1. The model identifies Patient and Appointment as entities with their relevant attributes.
  2. It represents a one-to-many association from Patient to Appointment.

Common error: Do not answer with account permissions or backup scheduling.

Question 8 · Command word: Describe2 teacher marks

A school needs a new enrolment form and a formatted class-list report. Describe how the DBMS developer interface helps with these two tasks.

S8.06.A01
Answer and checking points — teacher-written
  1. Its form tools let the developer arrange controls and associate entries with enrolment fields.
  2. Its report tools select and lay out the class-list information for presentation.

Common error: Describe construction tasks rather than simply saying that the tool executes queries.

Question 9 · Command word: State4 teacher marks

Class contains ClassID 4. Pupil initially contains (10, Ana, 4), with fields PupilID primary key, PupilName and required ClassID referencing Class. Editors can insert; Readers can only retrieve. Starting again from that initial state for each attempt, explain the result of: an Editor inserting (11, Bo, 4); a Reader inserting the same row; and an Editor inserting (11, Bo, 7). State the Pupil records after the accepted operation.

S8.05.A04S8.05.A05
Answer and checking points — teacher-written

  2. The Reader is denied insertion even though the proposed values satisfy the stated integrity rules.
  3. Class 7 is absent, so the Editor’s third proposal is rejected by the foreign-key rule.

Data management

Data modelling and logical schema

Data modelling identifies entities, attributes and relationships. A logical schema describes the database design independently of a particular DBMS. The table definitions below implement that design in PostgreSQL.

Table designer: add an attribute

The designer issues ALTER TABLE. Inspect the same attribute in the data dictionary.

Data dictionary

The data dictionary contains metadata, including field names, data types, field sizes and constraints. The DBMS maintains this metadata when a table definition changes. Editing a record changes the stored data, not its field definitions.

Data integrity

Data integrity concerns the accuracy and consistency of stored data. The DBMS enforces validation rules and referential integrity constraints. Access rights control which operations a user may perform; authorised operations must still satisfy the constraints.

A foreign key alone permits NULL unless NOT NULL is also declared. This library requires every loan to identify a member and a copy. Its default referential action rejects deleting a referenced record.

Access rights for individuals and groups

Select a user above. Student inherits SELECT access rights from the library_readers group. Librarian inherits rights to retrieve, insert, update and delete records from library_writers. Administrator can change table definitions and assign access rights to individuals or groups.

Administrator: change an individual or group right

Revoking an individual grant does not cancel a right still inherited from a group.

Backup and recovery procedures

A backup is a copy of data that can be used to recover from data loss or corruption. Backup procedures specify how often copies are made, where they are stored, how they are protected and retained, and how restoration is tested. This exercise creates and restores a copy of the database at a particular time.

No teaching backup has been made.

A simulated outage hides the live records until recovery. The teaching backup restores the whole database structure, data and grants. Changes after its time are lost from the restored state.

Developer interface and query processor

The developer interface provides tools for defining tables and creating queries. The query processor interprets SQL, checks its syntax and referenced tables and fields, produces an execution plan and carries out the query. The results and errors below are produced by PostgreSQL.
