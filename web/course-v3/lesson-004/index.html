Character encoding: ASCII, extended ASCII and Unicode

Follow characters through codes and stored bytes to decoded text, then compare ASCII, eight-bit extensions and Unicode.

How does a computer store character data as binary, and why do different character sets support different collections of symbols?

Before you start

A display shows 01000001. Can you identify a character without knowing the encoding?

Check your answer

No. A character encoding is needed to map the stored code to a character; ASCII maps this code to A.

01

Character sets and internal binary representation

S1.07.A01

Visual overview

Follow meaning through to a visible glyph

A character is an abstract item such as A, 5 or a space. A character set identifies the available characters; a coded character set assigns numeric codes to them. An encoding specifies how these codes are stored as bits or bytes. A font supplies the visible glyph shapes when the text is drawn.

Encode, store and decode in order

  1. Encode: Look up A, 5 and space in that order. With one byte per character the file contains 01000001 00110101 00100000.
  2. Separate stored units: The reader uses the agreed one-byte convention to obtain codes 65, 53 and 32.
  3. Decode: The same ASCII mapping recovers A, then 5, then the space. Changing the order or dropping the space changes the text.
  4. Display: The selected font draws the recovered characters. Changing the font changes their shapes without requiring different ASCII codes.

Distinguish a digit character from a number

The numeric integer 5 stored as an unsigned byte is 00000101. The character “5” under ASCII is code 53, stored here as 00110101. Arithmetic on a numeric value and displaying a digit character are different uses of data. Lesson 058 revisits this distinction when selecting data types.

State the decoding requirement

A code has meaning only under an agreed mapping and encoding. A bit sequence alone cannot identify the intended text. In these exercises all required codes are supplied; learn the method rather than a table of memorised codes.

Core explanation · Exam essentials

  • A character maps to a numeric code, then an encoding stores the code as bits or bytes.
  • Decode using the agreed mapping, storage boundaries and original order.
  • A glyph is a drawn shape; a digit character is not the same stored value as an integer.
Common misconception

A computer stores a character code, not the visual shape drawn by a particular font.

Check your understanding

A is code 65 and B is code 66. Which code is stored first for BA?

Check your answer

66 for B; retain the order of the characters.

ASCII

S1.07.A02

Visual overview

ASCII capacity

Swipe horizontally to compare every column →

Count codes from zero

Standard ASCII uses seven bits for each code, allowing 2⁷ = 128 codes numbered 0–127. Some represent letters, digits and punctuation; others are control codes, so 128 codes does not mean 128 printable symbols.

Decode a code at the correct width

Seven-bit code 1000010 has value 64 + 2 = 66. If the supplied ASCII table says 66 is B, it decodes to B. In a system storing each ASCII code in a byte it is 01000010; the extra leading zero does not create a different ASCII character.

Connect capacity to suitability

ASCII can represent basic English text efficiently, but its limited repertoire cannot cover all writing systems. An agreement on standard ASCII ensures that the same supported code is interpreted consistently by different systems.

Core explanation · Exam essentials

  • Standard ASCII has seven-bit codes: 128 possibilities, numbered 0–127.
  • The repertoire includes printable characters and control codes.
  • A leading zero may pad a seven-bit ASCII code for byte storage.
Common misconception

ASCII does not provide 256 codes; standard ASCII uses 7 bits and therefore provides 128 codes.

Check your understanding

What is the largest numeric code in seven-bit standard ASCII?

Check your answer

127; the 128 codes include zero.

Extend the available code space

An eight-bit extension can use 2⁸ = 256 code values, 0–255. It normally retains the original ASCII assignments in the lower half and uses the extra values for more characters. The extension adds 128 code positions, not another 256.

Worked mismatch using two supplied example tables

ByteTable A assignmentTable B assignment
01000001 (65)AA

Swipe horizontally to compare every column →

Separate a mapping mismatch from corrupted data

These two rows are an illustrative pair of mappings, not named real code pages. A sender using Table A encodes Aé as bytes 65, 128. A receiver using Table B decodes the same bytes as A€. No transmitted bit changed: the systems disagreed about the mapping. Using the same agreed table restores Aé.

Identify the remaining limitations

“Extended ASCII” does not name one universal table. Different eight-bit code pages use the extra positions differently. A single extension also still has too few code positions for a wide multilingual repertoire.

Core explanation · Exam essentials

  • An eight-bit extension has 256 possible codes and 128 extra positions beyond ASCII.
  • Different extensions may assign different characters to the same extra code.
  • Both systems must agree on the character mapping.
Common misconception

Extended ASCII is not a single universal worldwide repertoire; an 8-bit code still provides only 256 values.

Check your understanding

Why must two systems agree on which extended ASCII character set they use?

Check your answer

Different extensions can assign different characters to codes above 127.

Separate repertoire, code point and encoding

Unicode gives a much larger shared repertoire for characters from many writing systems and assigns code points to them. Code points are conventionally written as U+ followed by hexadecimal digits. A code point is a number identifying a character; it is not by itself a rule saying how many bytes to store.

A supplied Unicode example

Swipe horizontally to compare every column →

Follow a multilingual round trip

For this supplied example, A中 encoded in UTF-8 has bytes 41 E4 B8 AD. A UTF-8 decoder recovers U+0041 and U+4E2D, then the characters A中. The two characters use four bytes in total. A font must also contain suitable glyphs to display them.

Avoid a fixed-width misconception

UTF-8 and UTF-16 are encodings of Unicode code points. UTF-8 uses a variable number of bytes; UTF-16 uses one or two 16-bit code units for a code point. “Unicode always uses 16 bits per character” is therefore incorrect. The exact UTF-8 bit-construction algorithm is an optional extension, not needed to explain the distinction.

Connect purpose to storage

A shared character repertoire supports consistent multilingual exchange; the sender and receiver must still use compatible encodings. Without a stated encoding and text, character count alone is insufficient to calculate a Unicode file’s byte size.

Core explanation · Exam essentials

  • Unicode assigns code points across a broad shared repertoire.
  • An encoding such as UTF-8 or UTF-16 determines the stored code units and bytes.
  • State the encoding before estimating text size.
Optional extension · UTF-8 compatibility

ASCII code points U+0000–U+007F keep their single-byte values in UTF-8. Other code points need more bytes. This helps explain why basic ASCII text is also valid UTF-8, but an arbitrary eight-bit extension is not automatically valid UTF-8.

Common misconception

Unicode is not restricted to exactly 16 bits per character; the stored length depends on the encoding and character.

Check your understanding

Does Unicode mean every character occupies exactly 16 bits in a file?

Check your answer

No. The encoding, such as UTF-8 or UTF-16, determines how code points are stored.

Original question · Cambridge 9618/13

1. Explain the character-to-code mapping

Cambridge 9618/13 · October/November 2025 · 1(b), 1(c) · 4 marks

Selected parts: 1(b) [2]; 1(c) [2].

Reading the question — teacher guidance

Part (b) asks how a whole file name becomes codes in sequence. Part (c) asks for two differences between character sets, not two examples of characters.

Solution / model answer — teacher-written

1(b): Each character has a unique ASCII code. Replace each character of the file name, in its original order, with its code to represent the text.

1(c): Standard ASCII uses seven bits per character, whereas Unicode can use more bits. Unicode includes a much wider range of characters and writing systems than ASCII.

Official mark scheme
Why this earns marks — teacher explanation

Part (b) has one point for the unique code and one for replacing characters in sequence. Part (c) accepts the storage-width difference and the wider character repertoire, for two marks in total. The official allowance for “7 / 8 bits” includes extended ASCII; it does not redefine standard ASCII as eight-bit.

Common mistakes — teacher analysis

“Stored in binary” does not explain the character mapping or the order. Do not claim that every Unicode encoding always uses exactly 32 bits.

Character sets and internal binary representation

Extended ASCII

An eight-bit extension has 256 possible codes and 128 extra positions beyond ASCII. Different extensions may assign different characters to the same extra code. Both systems must agree on the character mapping.

Unicode

Unicode assigns code points across a broad shared repertoire. An encoding such as UTF-8 or UTF-16 determines the stored code units and bytes. State the encoding before estimating text size.
