Look, then discuss

Which message does 010 000 001 011 100 represent?

Read each three-bit group using the table, keeping the original order. The space has its own code; it is information too. This small teaching table is not ASCII.

Explain

Explanation · 1 / 3

Define a character set

A character set is an agreed collection of characters with a unique code for each character in the set. Characters include letters, digits, punctuation and spaces. The code allows the computer to identify a character without storing a picture of its printed shape.

Explanation · 2 / 3

Encode a sequence

To encode text, replace each character with its code and preserve the order. With this table, CAB becomes 010 000 001. The receiver needs the same table and must know that each code contains three bits.

Explanation · 3 / 3

Decode using the same agreement

To decode, split the stored data into code groups and look up the corresponding characters. A font then supplies shapes for displaying them. Changing a font can change the appearance without changing the underlying character codes.

Work together

Send and recover “A B!”

Use the supplied three-bit character set. Include the space.

Work together · 1 / 3

Encode all four characters

A → 000, space → 011, B → 001, ! → 100. Store 000 011 001 100.

Work together · 2 / 3

Count the data

Four characters × three bits = twelve bits of character data in this teaching model.

Work together · 3 / 3

Decode in order

Read 000, 011, 001 and 100 as A, space, B and !. The complete message is recovered.

Unique codes and preserved order let a receiver reconstruct the original text.

Check

Try it yourself · Teacher-written

Decode 010 000 001 011 100. Why would deleting the 011 group change the message?

Check your reasoning

The message is “CAB !”. The group 011 represents a space; deleting it changes the text to “CAB!”. Spaces are characters rather than gaps that can simply be ignored.

Connect

Keep this idea

A shared character table maps each character to a code, and a text file preserves those codes in sequence.

Real computers need larger shared sets than our five-character teaching table. ASCII is one such standard.

Look, then discuss

Is the character “0” stored using the same code as the numerical value zero?

In this character table, the digit character 0 has code 48. Its shape looks like a number, but its role in text is a character. Also compare uppercase A and lowercase a.

Explain

Explanation · 1 / 3

Connect seven bits with 128 codes

Standard ASCII is a seven-bit character set. Seven bits provide 2⁷ = 128 distinct codes, numbered 0 through 127. The set includes English letters, digits, punctuation and control codes; not every code displays a printable symbol.

Explanation · 2 / 3

Preserve case and character identity

Uppercase and lowercase letters have different codes. A file containing A differs from a file containing a even if a chosen font makes them look similar. A code table supplies the mapping; do not guess a code solely from a character’s appearance.

Explanation · 3 / 3

Distinguish a seven-bit code from a storage container

The code for A is 1000001 in seven bits. It can be stored in an eight-bit byte as 01000001. The extra leading zero does not make standard ASCII an eight-bit character set. Use the storage width specified by a file-size question.

Work together

Encode “A0a” in byte containers

Use standard ASCII codes, with one byte allocated to each character.

Work together · 1 / 3

Look up the codes

A is 65, 0 is 48 and a is 97.

Work together · 2 / 3

Write eight bits for each allocated byte

65 → 01000001; 48 → 00110000; 97 → 01100001.

Work together · 3 / 3

Count the allocated storage

Three bytes contain 24 bits. The character set itself still requires only seven bits to identify each code.

Character-set capacity and a file’s allocated storage width are related but different facts.

Standard ASCII defines 128 codes. A leading 0 in an 8-bit byte does not create a new character. Different extended ASCII encodings can map bytes 128–255 differently. Unicode code points are encoded using formats such as UTF-8 or UTF-16; Unicode is not universally fixed at 16 bits per character.

Represent information · Concept 17

Add an eighth bit, but keep the table agreed

Observe

Two illustrative extension tables

  • Both keep ordinary ASCII letters in their original positions.
  • Table X assigns an added byte code to an accented letter.
  • Table Y assigns that same added byte code to a different symbol.

Look, then discuss

Would sending the byte alone tell the receiver which symbol was intended?

The sender may have preserved the byte perfectly. The receiver can still show the wrong character if it chooses a different extension table.

Explain

Explanation · 1 / 3

Use the larger pattern count

An eight-bit extended-ASCII character set has up to 2⁸ = 256 code values. The additional bit doubles the available patterns compared with standard ASCII. Extensions commonly retain the original ASCII range and use the additional range for extra characters.

Explanation · 2 / 3

Recognise that extensions differ

“Extended ASCII” does not name one universal extra-character table. Different eight-bit encodings assign different characters to some values from 128 to 255. Extra accented letters or symbols depend on which extension is selected.

Explanation · 3 / 3

Explain a decoding mismatch

Correct reconstruction requires both the stored codes and the matching character table. Choosing the wrong table may display incorrect characters even though no byte was lost. One extension also remains too small to accommodate the many writing systems needed together.

Work together

Separate transmission from interpretation

A sender and receiver use different illustrative eight-bit extension tables. In their added ranges, the same byte selects different symbols.

Work together · 1 / 3

Check the stored data

Suppose the receiver gets exactly the byte that was sent. Transmission preserved the bits.

Work together · 2 / 3

Check the decoding rule

The receiver looks up that byte in the wrong table, so it selects the wrong character.

Work together · 3 / 3

Correct the cause

Use the matching encoding when decoding. Resending the identical byte without agreeing the table does not resolve the mismatch.

More available codes help only when the sender and receiver agree on their meanings.

Check

Try it yourself · Teacher-written

Does using eight bits guarantee that any two extended-ASCII files use the same characters for codes 128 to 255?

Check your reasoning

No. Different eight-bit extensions can assign different characters to those codes. The decoder must know the particular encoding, not just the number of bits.

Connect

Keep this idea

Eight-bit extensions provide up to 256 codes, but their added character mappings are not universal.

A much larger shared character repertoire is needed when text combines many languages and symbols.

Represent information · Concept 18

Represent text across writing systems

Observe

One message needs more than English letters

  • A name contains an accented letter.
  • Another line uses a different writing system.
  • A symbol appears beside the text. All must keep their identities.

Look, then discuss

Why is adding just 128 extra codes not a general solution?

A document may need characters from several writing systems at once. Switching among small incompatible tables makes that difficult.

Explain

Explanation · 1 / 3

Use a much larger shared repertoire

Unicode assigns code points to a much wider range of characters and symbols than ASCII. A code point is a number identifying a character in the Unicode system. The larger repertoire supports text from many writing systems in one consistent system.

Explanation · 2 / 3

Separate the code point from stored bytes

An encoding specifies how a sequence of Unicode code points is represented as stored units or bytes. UTF-8, for example, uses a variable number of bytes. Unicode is therefore not accurately described as “every character always takes sixteen bits” or “always thirty-two bits”.

Explanation · 3 / 3

Keep rendering separate

The stored code identifies the character; a font and text-rendering system produce its visible shape. A missing glyph may prevent a correct character from displaying, even when its code was stored correctly. This is different from decoding bytes with the wrong encoding.

Work together

Read a supplied UTF-8 example

A supplied reference says A is U+0041 and é is U+00E9. In UTF-8 their bytes are 41 and C3 A9 respectively, shown in hexadecimal.

Work together · 1 / 3

Count characters

The text Aé has two characters in this example.

Work together · 2 / 3

Count stored bytes

A uses one byte and é uses two bytes, giving three bytes in total.

Work together · 3 / 3

Draw the correct conclusion

A larger character repertoire does not imply one fixed storage size for every character. Use the named encoding and supplied data when calculating size.

For the syllabus comparison, explain the much wider repertoire; use encoding details only when the task requires them.

Original question · Cambridge 9618/13

1. Explain the character-to-code mapping

Cambridge 9618/13 · October/November 2025 · 1(b), 1(c) · 4 marks

Selected parts: 1(b) [2]; 1(c) [2].

Hint — reading the question

Part (b) asks how a whole file name becomes codes in sequence. Part (c) asks for two differences between character sets, not two examples of characters.

Reasoning and model answer — teacher-written

1(b): Each character has a unique ASCII code. Replace each character of the file name, in its original order, with its code to represent the text.

1(c): Standard ASCII uses seven bits per character, whereas Unicode can use more bits. Unicode includes a much wider range of characters and writing systems than ASCII.

Official mark scheme
Why this earns marks — teacher explanation

Part (b) has one point for the unique code and one for replacing characters in sequence. Part (c) accepts the storage-width difference and the wider character repertoire, for two marks in total. The official allowance for “7 / 8 bits” includes extended ASCII; it does not redefine standard ASCII as eight-bit.

Common mistakes — teacher analysis

“Stored in binary” does not explain the character mapping or the order. Do not claim that every Unicode encoding always uses exactly 32 bits.
