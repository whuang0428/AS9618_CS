Querying and maintaining data with SQL DML

Select, filter, sort, group and join records, calculate aggregates, then insert, delete and update precisely identified rows.

Which rows and columns should a query return, and which stored records should a maintenance statement change?

01

Choose the result columns and source

S8.10.A01

Visual overview

Choose columns and source

SELECT lists the fields or expressions required in the result, while FROM names the source table. Returning MemberName alone does not return MemberID or Active. Reading a result leaves the original Member records unchanged.

Read the result

Use the Member and Loan data in this lesson to trace each request. Each example states any required ordering explicitly; without ORDER BY, a DBMS need not return records in insertion or primary-key order.

Library Member: the complete starting data

MemberID (PK)MemberNameActive
1AshaTRUE
2BenTRUE
3ChenFALSE
4DaraTRUE

Swipe horizontally to compare every column →

Separate projection from record identity

SELECT MemberName FROM Member; returns four name values. SELECT * FROM Member; requests all three columns. The stored Member rows are unchanged in both cases. A selected column need not uniquely identify people: if two members share a name, the result can contain that name twice. The next units add conditions and ordering.

Read names, literals and aliases

SQL keywords identify operations; table and field names identify database objects. A text value such as 'Asha' uses single quotes. Do not quote MemberName as a string when the task requires values from that field. AS LoanCount later labels a calculated result column; it does not add a field to Loan.

Worked example · Retrieve one column before adding ordering

  1. Initial data

    Use all four Member rows above.

  2. SQL

    SELECT MemberName FROM Member;

  3. Result

    Asha, Ben, Chen and Dara each occur once. No order is guaranteed by this statement. The Member table still contains all four original rows.

Core explanation · Exam essentials

  • SELECT names result columns and FROM names their source.
  • A query result leaves stored records unchanged; request ordering explicitly when it matters.
Common misconception

SELECT * requests every column; use a named field list when the task requests only specific fields.

Check your understanding

Does SELECT MemberName FROM Member delete the other columns?

Check your answer

No. It chooses result columns without modifying the stored table.

S8.10.A02

Visual overview

Filter the supplied records

WHERE retains only records for which the condition is true. Combine comparisons with AND when all conditions must hold, or OR when an alternative is sufficient. Parentheses make the intended grouping explicit in compound expressions.

Combine conditions

Vary the condition

Replacing AND with OR admits a row when either test is true: IDs 201, 202, 203 and 205 qualify. Comparisons include =, <>, <, >, <= and >=. Separate filtering from ordering

The examples display qualifying IDs in ID order for checking. ORDER BY, taught next, is what requests that order in a full SQL query. WHERE itself chooses rows and does not sort them.

Worked example · Apply both conditions

  1. Read the task

    Find LoanID and Fee for unreturned loans whose fee is at least 3.

FROM Loan

Core explanation · Exam essentials

  • WHERE keeps rows whose condition is true; AND requires both tests and OR at least one.
  • Use parentheses to express intended mixed conditions, and quote text literals.
Common misconception

Do not replace AND with OR when every condition is required; doing so changes which records qualify.

Check your understanding

Check your answer

03

Sort the returned records

S8.10.A03

Visual overview

Specify an ordering

ORDER BY arranges result rows by the specified field or expression. ASC means increasing order and is the default; DESC means decreasing order. Sorting changes result presentation rather than the stored values.

Resolve ties

Multiple sort fields are applied in sequence: sort by the first field, then use the next field for ties. The example sorts fees from largest to smallest and uses LoanID ascending to make any equal-fee ordering predictable.

Choose data that exercises the rule

The main Loan example has no equal fees, so its second field does not affect the visible order. Use the separate Charge data below to see a real tie. ORDER BY Fee DESC alone puts fee 6 first, but does not determine the relative order of the two fee-3 records.

Core explanation · Exam essentials

  • ORDER BY sorts the returned rows; ASC is ascending and DESC descending.

Common misconception

WHERE decides which records qualify; ORDER BY does not filter them out.

Check your answer

04

Calculate SUM, COUNT and AVG

S8.10.A06

Visual overview

Calculate one overall result

SUM adds the numeric values of an expression, COUNT(*) counts records, and AVG calculates the mean of the included non-null values. Without GROUP BY, an aggregate query calculates one overall result for the selected records.

Choose the correct denominator

For the five library fees, 2 + 4 + 6 + 0 + 3 = 15, with five records and a mean of 3. A null denotes a missing value: COUNT(Fee), SUM(Fee) and AVG(Fee) ignore null fees, whereas COUNT(*) still counts their rows. Zero is a known numeric value and remains included.

Explain the missing-value effect

FeeSample has three rows but two known fees. Its known total is 2 + 4 = 6; AVG(Fee) is 6 / 2 = 3. Replacing NULL with 0 changes the known-value count to three and the mean to 2, while the total remains 6. AS Mean names the result column without changing FeeSample.

Worked example · Calculate the same result by hand

  1. Read the task

    Return total fees, number of Loan records and mean fee over all five loans.

  2. Write SQL
    SELECT SUM(Fee) AS TotalFee, COUNT(*) AS LoanCount, AVG(Fee) AS MeanFee
FROM Loan;
  3. Check the result

    15 | 5 | 3

Worked example · Calculate with a missing fee

  1. Starting state

    FeeSample is a separate one-column table containing exactly 2, NULL and 4, as shown above.

  2. SQL
    SELECT COUNT(*) AS Rows, COUNT(Fee) AS KnownFees, SUM(Fee) AS Total, AVG(Fee) AS Mean
FROM FeeSample;
  3. Result

Swipe horizontally to compare every column →

Core explanation · Exam essentials

  • SUM adds known numeric values, COUNT(*) counts rows and AVG divides the known-value total by its count.
  • COUNT(field) excludes NULL values; zero is a known value and is included.
Optional extension · Aggregating an empty set

With the initial Loan data, WHERE Fee > 6 selects no rows. Without GROUP BY, SELECT COUNT(*), SUM(Fee), AVG(Fee) still returns one aggregate row: 0, NULL, NULL. No known-value total or mean is available. A grouped query over the empty set has no groups and returns no rows. This distinction explains an edge case; subqueries and further aggregate functions are not required.

Common misconception

COUNT(*) and COUNT(Fee) can differ when some Fee values are null; do not treat a missing value as zero.

Check your understanding

For fees 2, 4 and 0, what is AVG(Fee)?

Check your answer

It is 2: the total 6 is divided by all three known values, including zero.

05

Form groups before calculating group results

S8.10.A04

Visual overview

Create the groups

GROUP BY places records sharing the grouping values into the same group. An aggregate can then calculate one result for each group. Grouping loans by MemberID lets COUNT(*) report the number of loans for each represented member.

Calculate one row per group

Include non-aggregated selected fields in GROUP BY so each returned value has a defined meaning for the group. ORDER BY can subsequently arrange the grouped results; it does not create the groups. A member with no Loan row does not appear in a grouping of Loan alone.

Contrast grouping choices

Without GROUP BY, the same five rows give one overall count of 5. With GROUP BY MemberID, the result has three groups with counts 2, 2 and 1. GROUP BY Returned would form different groups because its grouping values express a different question.

Explain an invalid selection

Do not select LoanID alongside COUNT(*) while grouping only by MemberID: member 1 has IDs 201 and 202, so no single LoanID describes its group. Select the grouping fields and calculated values. A member with no Loan rows is not a zero-sized group in this table; there is no row to place into such a group.

Worked example · Count loans per member

  1. Read the task

    Group the five Loan records by MemberID and count rows in each group.

  2. Write SQL
    SELECT MemberID, COUNT(*) AS LoanCount
FROM Loan
GROUP BY MemberID
ORDER BY MemberID;
  3. Check the result
    1 | 2
2 | 2
3 | 1

Core explanation · Exam essentials

  • GROUP BY forms sets with equal grouping values and aggregates within each set.
  • Group selected non-aggregate fields; ORDER BY arranges the resulting groups separately.
Common misconception

Selecting an arbitrary LoanID beside a member's aggregate would not identify the whole group; use the grouped identifier instead.

Check your understanding

Why is Dara absent from this Loan grouping?

Check your answer

MemberID 4 has no Loan records, so it contributes no group.

06

Match records from two tables with INNER JOIN

S8.10.A05

Visual overview

Match the two tables

An INNER JOIN combines row pairs satisfying its ON condition. Here Member.MemberID = Loan.MemberID connects each loan to its member. Qualify shared field names with the table name to make the intended reference unambiguous.

Count pairs, not just parents

A member with two loans contributes two joined rows, while a member with no matching loan contributes none. WHERE may further filter the joined rows. These AS SQL tasks use at most two tables; use an explicit INNER JOIN and a separate ON matching condition.

Choose the relationship deliberately

Member.MemberID and Loan.MemberID are qualified field names: the prefix identifies the table containing the field. Match these related identifiers in ON. Comparing Member.MemberID with Loan.LoanID would compare different kinds of identifier, even if a coincidental number happened to match. Dara has no matching Loan, so she produces no joined pair.

The combined task is: for each member with unreturned loans, return the name, number of those loans, total fee and mean fee, with the largest total first. Preserve identity through grouping

Grouping by MemberID as well as MemberName keeps two different people named Asha separate. The name is output information, not a guaranteed unique identifier. The grouped table is then ordered by decreasing total fee; MemberID ASC supplies a tie rule if totals are equal.

Worked example · Complete two-table query and exact result

  1. Starting state

    Use the original Member and Loan data and the intermediate rows above. No maintenance example has changed this input.

  2. SQL
    SELECT Member.MemberName, COUNT(*) AS LoanCount,
       SUM(Loan.Fee) AS TotalFee, AVG(Loan.Fee) AS MeanFee
FROM Member INNER JOIN Loan
ON Member.MemberID = Loan.MemberID
WHERE Loan.Returned = FALSE
GROUP BY Member.MemberID, Member.MemberName
ORDER BY SUM(Loan.Fee) DESC, Member.MemberID ASC;
  3. Result
    Ben | 2 | 9 | 4.5

Core explanation · Exam essentials

  • INNER JOIN returns matching pairs under ON; one parent can contribute several result rows or none.
  • Combine row matching, filtering, grouping, aggregates and ordering in their appropriate roles, using at most two tables.
Optional extension · Two members with the same name

Add a separate member (5, Asha, TRUE) and loan (206, 5, 4, FALSE) to a fresh copy of the library data. Grouping by MemberID and MemberName produces separate unreturned counts for (1, Asha): 1, (2, Ben): 2 and (5, Asha): 1. Grouping by name alone would merge the two Ashas into one count of 2. No additional join type is needed.

Common misconception

A join is not a one-row-per-member list: repeated matching child records produce repeated parent values.

Check your understanding

Why is Asha shown twice in the result?

Check your answer

Two different Loan rows contain her MemberID, so two row pairs match the ON condition.

Insert values into named fields

S8.11.A01

Visual overview

Match each value to a field

INSERT INTO adds a record. Name the target fields and supply the corresponding VALUES in the same order. Text literals use single quotes; numeric and Boolean values are written according to their types.

Check the new record

Check the new primary key and any foreign-key values before insertion. The library example adds MemberID 5 with the name Elena and Active TRUE. It does not alter an existing member's record, and it must fail if that primary key is already present.

Verify matching and unchanged data

This example starts from the original library data. An alternative field order is valid only if the values move with their fields: naming MemberName, Active, MemberID requires values 'Elena', TRUE, 5. The five Loan records are unchanged. Repeating the insertion fails because MemberID 5 already exists; it is not an instruction to replace Elena.

Worked example · Add a member

  1. Initial state

    The Member table contains IDs 1 to 4.

  2. Statement
    INSERT INTO Member (MemberID, MemberName, Active)
VALUES (5, 'Elena', TRUE);
  3. Check

    MemberID 5 now stores Elena and TRUE; the four existing records remain.

Core explanation · Exam essentials

  • INSERT INTO supplies values in the same order as its named fields.
  • A new row must satisfy existing keys, references and field constraints.
Common misconception

Do not swap the values for MemberName and Active; field order and value order must agree.

Check your understanding

Can the same statement be repeated unchanged when MemberID is a primary key?

Check your answer

No. The second insertion would duplicate MemberID 5.

08

Delete only the intended records

S8.11.A02

Visual overview

Identify target rows

DELETE FROM removes complete records from the named table. WHERE selects the records to remove. To remove the completed loan with LoanID 204, match that identifier rather than a member identifier shared by several loans.

Verify the remaining records

Without a WHERE condition, deletion targets all rows in the table, subject to constraints. Check the intended rows first with a corresponding SELECT. Removing a referenced parent may be rejected by foreign-key constraints; this example removes the child Loan record.

State the reset and no-match result

Reset to the original five Loan rows before this example. Deleting LoanID 204 leaves 201, 202, 203 and 205, with every field in those four records unchanged. The Member records also remain. Deleting WHERE LoanID = 999 would match no rows and leave the database unchanged.

  • DELETE FROM removes whole rows selected by WHERE; the table definition remains.

DELETE removes the row, not just the value in one of its fields.

09

Change fields while keeping the record

S8.11.A03

Visual overview

Specify replacements and targets

UPDATE names the table, SET supplies the new field values, and WHERE selects the affected records. Updating Returned to TRUE for LoanID 203 leaves that loan's identity, member and fee in place.

Check the resulting state

A missing or incorrect WHERE condition can affect unintended records. Decide whether the business task requires changing a value or removing a record, then verify both the affected rows and the values that should remain unchanged.

Follow identity and scope

Reset to the original library data before the main update. Loan 203 changes from (203, 2, 6, FALSE) to (203, 2, 6, TRUE). Loans 201, 202, 204 and 205 retain all their fields. A missing WHERE would target every Loan record; WHERE MemberID = 2 would target both 203 and 205.

Change two fields in one target

For a separate update, suppose returning loan 203 also waives its fee. SET can assign Returned = TRUE, Fee = 0 in one statement. The target becomes (203, 2, 0, TRUE); its identity and member stay unchanged and every other row remains as before.

Worked example · Record a returned loan

  1. Target

    Loan 203 has been returned; other loans must retain their current status.

  2. Statement
    UPDATE Loan
SET Returned = TRUE
WHERE LoanID = 203;
  3. Verify

    Loan 203 remains in the table with Returned TRUE. Loan 205 for the same member remains FALSE.

Worked example · Update two fields from a fresh starting copy

  1. Initial record

    Loan 203 is (203, 2, 6, FALSE); all other records are the original library rows.

  2. SQL

    UPDATE Loan SET Returned = TRUE, Fee = 0 WHERE LoanID = 203;

  3. Final check

    Loan 203 is (203, 2, 0, TRUE). MemberID stays 2; loan 205 remains (205, 2, 3, FALSE).

Core explanation · Exam essentials

  • UPDATE names the table, SET assigns values and WHERE chooses existing rows.
  • Verify changed fields, unchanged fields and unaffected rows; a no-match update does not insert a row.
Common misconception

Filtering by MemberID 2 instead of LoanID 203 would also change loan 205.

Check your understanding

Stock initially contains only (30, Cable, 6) and (31, Adapter, 2). What is its final state after UPDATE Stock SET Quantity = 8 WHERE StockID = 99?

Check your answer

Both original records remain unchanged. No record matches 99, and UPDATE does not create one.

Original question · Cambridge 9618/13

1. Count scheduled performances for each show

Cambridge 9618/13 · May/June 2024 · 4(c) · 4 marks

Selected parts: 4(c) [4].

Reading the question — teacher guidance

The result needs the show name and a named count, not one count for the entire theatre. The performance records identify shows through ShowID.

Solution / model answer — teacher-written
SELECT SHOW.Title, COUNT(PERFORMANCE.PerformanceID) AS NumberOfShowings
FROM PERFORMANCE INNER JOIN SHOW
ON PERFORMANCE.ShowID = SHOW.ShowID
GROUP BY SHOW.Title;

Join each performance to its show to obtain Title. Group those rows by Title, then count the performance identifiers inside each group. In the supplied sample MK12 has three performances and OP3 has three; their titles are obtained from SHOW, whose rows are not supplied, so do not invent titles as official output.

Official mark scheme
Why this earns marks — teacher explanation

The four marks cover a named COUNT, the FROM clause, the join, and selecting/grouping by title. The last requirement is a combined point. The scheme also accepts a comma-separated FROM with the join condition in WHERE.

Common mistakes — teacher analysis

COUNT(*) without GROUP BY produces one total. An unjoined pair of tables multiplies rows and inflates counts. Do not add a filter for MK12: it is an example, not the only show requested.

Original question · Cambridge 9618/12

2. Update one game character

Cambridge 9618/12 · May/June 2025 · 5(d)(ii) · 3 marks

Selected parts: 5(d)(ii) [3].

Reading the question — teacher guidance

Both values must change in the existing row identified by CharacterID. The identifier 0002 is text, including its leading zeros.

Solution / model answer — teacher-written
UPDATE CHARACTER
SET Level = 3, Money = 10000.00
WHERE CharacterID = "0002";

SET lists both changes, separated by a comma. WHERE restricts the change to the named character; it does not filter by username or character name.

Official mark scheme
Why this earns marks — teacher explanation

The three points are UPDATE of the correct table, SET of both values, and the correct WHERE condition. Changing only one value does not satisfy the combined SET point.

Common mistakes — teacher analysis

Without WHERE, every character is changed. INSERT would create a row rather than alter the character specified.
