Queries using SELECT and FROM

The field list after SELECT determines which attributes appear in the answer. FROM names the table to read. Each qualifying source record contributes its selected values; the stored records are unchanged.

SELECT MemberID, MemberName
FROM Member
ORDER BY MemberID;
Expected result for the initial data
memberidmembername
1Asha
2Ben
3Chen
4Dara

SELECT * requests all columns. Naming columns explicitly makes the intended answer clearer. The ORDER BY in this introductory example makes the displayed row order predictable; its operation is explained below. Without ORDER BY, a particular row order is not guaranteed.

Practice question · teacher-written

Describe the effect of SELECT MemberName FROM Member on the stored data.

Suggested answer

The statement retrieves member names without changing the stored data. The other stored Member columns remain present even though they are not included in the result.

Select records using WHERE

WHERE decides which source rows qualify. Test the condition for each row before selecting its output fields. With AND, both conditions must hold; with OR, at least one must hold.

FROM Loan
WHERE Returned = FALSE AND Fee >= 3
ORDER BY LoanID;

Practice question · teacher-written

Explain why Fee >= 3 includes loan 205 but Fee > 3 excludes it.

Suggested answer

Loan 205 has fee exactly 3. The first comparison includes equality; the second requires a strictly larger value. Testing values at a boundary helps distinguish these comparison operators.

Sort query results using ORDER BY

ORDER BY sorts the result, not the underlying table definition. ASC means ascending and is the default; DESC means descending. A second sort expression decides the order of rows tied on the first.

SELECT LoanID, Fee
FROM Loan
ORDER BY Fee DESC, LoanID ASC;
Expected result for the initial data

The highest fee is 6 for loan 203; the lowest is 0 for loan 204. LoanID ASC provides the secondary sort order: if two fees become equal, the smaller LoanID comes first. Sorting does not by itself remove rows.

Practice question · teacher-written

Identify the clause required to display the highest fees first.

Suggested answer

ORDER BY Fee DESC sorts the result in descending order of Fee. WHERE specifies the condition used to select records.

Aggregate functions: SUM, COUNT and AVG

An aggregate combines values from several rows. With no GROUP BY here, the five Loan records contribute to one summary row.

SELECT SUM(Fee) AS TotalFee, COUNT(*) AS LoanCount, AVG(Fee) AS MeanFee
FROM Loan;
Expected result for the initial data

AS gives a result column a readable alias, such as TotalFee. COUNT(*) counts rows; COUNT(attribute) counts non-null values of that attribute. SUM and AVG ignore NULL values. The Fee column is defined as NOT NULL, so all five fees participate.

Practice question · teacher-written

State whether a fee of 0 is included in AVG. Calculate the mean of the three unreturned fees: 2, 6 and 3.

Suggested answer

Zero is a real value and participates in AVG; it is not NULL. The three unreturned fees total 11, so their average is 11/3, approximately 3.67. Filter the records first to summarise only that set.

Practice question · teacher-written

Explain why MemberID should be used when grouping records to calculate one total per member.

Suggested answer

Different members may share a name. Grouping by that name alone could merge distinct people. Use the unique identity, and include the name as another grouping field when selecting it.

Queries using INNER JOIN

Use two tables when the required answer contains facts stored separately. Member supplies MemberName; Loan supplies LoanID. The ON condition matches the foreign key to the referenced primary key.

SELECT Member.MemberName, Loan.LoanID
FROM Member INNER JOIN Loan
ON Member.MemberID = Loan.MemberID
ORDER BY Loan.LoanID;

Practice question · teacher-written

Explain why Dara does not appear in the result of this INNER JOIN query.

Suggested answer

INNER JOIN returns records with matching values in both tables. Dara has no matching Loan record, so the query does not include her in the result.

A query combining INNER JOIN, WHERE, GROUP BY and ORDER BY

Request: for each member with outstanding loans, show their member identifier, name, number of outstanding loans and total fee. Display the results in descending order of total fee.

SELECT Member.MemberID, Member.MemberName, COUNT(*) AS LoanCount, SUM(Loan.Fee) AS TotalFee
FROM Member INNER JOIN Loan ON Member.MemberID = Loan.MemberID
WHERE Loan.Returned = FALSE
GROUP BY Member.MemberID, Member.MemberName
ORDER BY SUM(Loan.Fee) DESC, Member.MemberID;

Practice question · teacher-written

Explain the effect of changing WHERE Returned = FALSE to WHERE Returned = TRUE on the counts and totals.

Suggested answer

The condition selects returned loans 202 and 204 before grouping. Asha has COUNT = 1 and SUM = 4; Chen has COUNT = 1 and SUM = 0. Ben no longer appears because neither of his loans is returned. In descending order of total fee, Asha appears before Chen.

Add records using INSERT INTO

Register Elena before she borrows. Name the target fields, then supply one matching value for each field in the same order. The database definition still applies: MemberID and SchoolEmail must be unique and required values must be present.

Practice question · teacher-written

State the change required in VALUES when SchoolEmail is listed before MemberName in the INSERT field list.

Suggested answer

The corresponding values must be placed in the same order as the listed fields. SQL matches values to the explicit field list by position. A statement can be syntactically valid yet place the wrong text in the wrong field.

Modify records using UPDATE

Request: record that loan 203 was returned and waive its fee. First preview the target using the same condition, then make the change.

SELECT LoanID, Fee, Returned
FROM Loan
WHERE LoanID = 203;
UPDATE Loan
SET Returned = TRUE, Fee = 0
WHERE LoanID = 203;
Check changed and unchanged records
RecordBeforeAfter
Loan 203Fee 6; Returned FALSEFee 0; Returned TRUE
Loan 205, also belonging to BenFee 3; Returned FALSEFee 3; Returned FALSE

SET gives the new values. WHERE identifies the rows receiving them. Without WHERE, all rows are targeted, subject to constraints. A WHERE condition matching nothing updates zero rows; it does not insert a new row.

Practice question · teacher-written

Explain why WHERE MemberID = 2 does not correctly identify only loan 203.

Suggested answer

It matches both loans 203 and 205. The instruction names one borrowing event, so use its unique LoanID to avoid changing Ben’s other loan.

Delete records using DELETE FROM

The following statement removes the completed borrowing record with LoanID 204. Preview the target, execute the deletion and verify the remaining records. Removing an event is different from marking it returned.

SELECT LoanID FROM Loan WHERE LoanID = 204;
DELETE FROM Loan
WHERE LoanID = 204;

Practice question · teacher-written

Identify the command required to record that a loan has been returned while retaining the borrowing record.

Suggested answer

UPDATE changes the Returned value while retaining the event. DELETE removes the event record. The required operation is therefore UPDATE.

7. Read and repair a four-error SQL query

Cambridge 9618/12 · May/June 2023 · 2(c)(iii) · 4 marks

Selected parts: 2(c)(iii) [4].

Original question
Reading the question — teacher guidance

The query should count beginner riders with a lesson on the stated date. Compare each expression and condition against that purpose. The original question uses a comma-separated join and #DD/MM/YYYY# date literals.

Solution / model answer — teacher-written
Error in the supplied queryCorrection and reason
SUM(STUDENT.RiderLevel)Use COUNT(STUDENT.RiderLevel): count matching rider values, rather than trying to sum level names.
WHERE StudentID = StudentIDUse STUDENT.StudentID = LESSON.StudentID so the condition joins a student to their lesson.
OR Date = #09/09/2023#Use AND Date = #09/09/2023# so the date condition must hold as well as the join.
STUDENT.RiderLevel = BeginnerQuote the string value: STUDENT.RiderLevel = 'Beginner'.
SELECT COUNT(STUDENT.RiderLevel) AS NumberOfRiders
FROM STUDENT, LESSON
WHERE STUDENT.StudentID = LESSON.StudentID
AND Date = #09/09/2023#
AND STUDENT.RiderLevel = 'Beginner';

The corrected version above retains the date notation stated in this paper. In the PostgreSQL classroom workbench use an ISO date literal, DATE '2023-09-09', and its matching local schema. Do not silently change the original question or treat its date notation as executable PostgreSQL.

Common mistakes — teacher analysis

Replacing SUM with COUNT is not enough: an ambiguous join or incorrect OR can still select the wrong records. This question asks for four corrections, not invented output rows; no full set of stored data is supplied.

A table stores records about an entity type. Each record contains values for its fields. Select a table to inspect its records, then use the form or SQL to maintain the data.

Data modelling and logical schema

Data modelling identifies entities, attributes and relationships. A logical schema describes the database design independently of a particular DBMS. The table definitions below implement that design in PostgreSQL.

Table designer: add an attribute

The designer issues ALTER TABLE. Inspect the same attribute in the data dictionary.

Data dictionary

The data dictionary contains metadata, including field names, data types, field sizes and constraints. The DBMS maintains this metadata when a table definition changes. Editing a record changes the stored data, not its field definitions.

Data integrity

Data integrity concerns the accuracy and consistency of stored data. The DBMS enforces validation rules and referential integrity constraints. Access rights control which operations a user may perform; authorised operations must still satisfy the constraints.

A foreign key alone permits NULL unless NOT NULL is also declared. This library requires every loan to identify a member and a copy. Its default referential action rejects deleting a referenced record.

Backup and recovery procedures

A backup is a copy of data that can be used to recover from data loss or corruption. Backup procedures specify how often copies are made, where they are stored, how they are protected and retained, and how restoration is tested.
