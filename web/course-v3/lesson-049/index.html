Design a ticket system · Concept 01

Give the ticket seller instructions that can be followed

Observe

The first ticket desk

  • Request: 2 tickets
  • Price: 25.00 per ticket
  • Poster: blue background and a photograph
  • Task: tell the buyer the total price

Look, then discuss

Could a new volunteer sell the correct tickets using only your instructions?

Two people want to attend a school performance. Tickets cost 25.00 each. The volunteer has a poster, a list of seats and a note saying “work out the price”. Explain what the volunteer can determine and what the note still leaves unstated.

Recall

Start with an ordinary calculation

You only need multiplication and the idea of following instructions in order. This first version assumes that the requested tickets are available. Discounts, payment and repeated orders will be added later, one rule at a time.

Explain

Explanation · 1 / 4

Carry out the task before naming it

Read the requested quantity, multiply it by 25.00 and tell the buyer the result. For two tickets the result is 50.00. Another volunteer should obtain the same result from those instructions.

Explanation · 2 / 4

Replace an aim with defined actions

“Sell tickets” names a goal but leaves the method open. “Read the quantity; multiply the quantity by 25.00; display the result” supplies operations and their order. A solution expressed as a sequence of defined steps is an algorithm.

Explanation · 3 / 4

Ask which facts can change the answer

Changing the quantity from two to three changes the total. Changing the poster background from blue to green does not change this calculation. Keep quantity and price when representing this particular task.

Explanation · 4 / 4

Name abstraction after making the choice

Abstraction removes unnecessary detail while retaining essential features. Its purpose here is to make the price calculation easier to understand. Removing the price would make the representation unusable, even though it would contain less information.

Work together

Change the request, keep the same method

The next buyer wants three tickets at 25.00 each. The poster now has a red background.

Work together · 1 / 3

Select the relevant facts

Keep quantity 3 and unit price 25.00. The new colour has no role in the stated price rule.

Work together · 2 / 3

Follow the ordered operations

Obtain 3 before calculating 3 × 25.00 = 75.00. Display 75.00 after calculating it; do not guess the total before reading the request.

Work together · 3 / 3

Check the model against the purpose

A second volunteer can reproduce 75.00. If the task changes to printing matching posters, colour becomes relevant; relevance belongs to a purpose, not permanently to a fact.

Defined steps make the calculation repeatable; abstraction keeps the information those steps need.

Experiment

Choose the price-calculation purpose. Retain or remove each information card, then change to a publicity task and explain which choices change.

The same event can need different models. Select the facts needed for the chosen purpose.

Information to keep

Predict: Can your model answer the chosen question? Is any selected detail unnecessary?

Predict the result before revealing a step.

Check

Try it yourself · Teacher-written

A model keeps the poster colour and quantity but removes the ticket price. Can it calculate the total? Explain the missing information.

Check your reasoning

No. Quantity alone does not determine the total. The model must retain the price or a rule that supplies it. Keeping an unrelated colour does not repair that omission.

Connect

Keep this idea

An algorithm solves a problem using defined steps. Abstraction retains the details essential to the stated purpose.

Design a ticket system · Concept 02

Build and challenge an abstract model

Observe

Two requests with different outcomes

  • A: 8 places left; request 2
  • B: 0 places left; request 2
  • Both performances have the same poster
  • Decision: can this request be accepted?

Look, then discuss

What must a model show to decide whether a ticket request can be met?

Performance A has eight places left and performance B has no places left. A buyer requests two tickets for A. A model saying only “the school sells tickets” cannot distinguish this request from one for B.

Recall

Choose a purpose before choosing fields

A field is one named item recorded in a model, such as the performance identifier. You can write values in an ordinary table; you do not need database commands or programming syntax.

Explain

Explanation · 1 / 4

State the exact question

This model answers whether enough places remain for a specified performance and quantity. It does not allocate named seats or take payment. State these limits so that a reader knows which decisions the model can support.

Explanation · 2 / 4

Represent the facts, not only their names

Record a performance identifier and its available places. Record the requested performance and quantity separately. The identifier connects the request to the correct availability record.

PerformancePlaces left
A8
B0

Explanation · 3 / 4

Add the relationship needed for a decision

Find the requested performance, then check that quantity is at least one and does not exceed its places left. In ordinary words, request 2 for A fits within 8; request 2 for B does not fit within 0.

Explanation · 4 / 4

Test omissions with contrasting cases

If the model stores only a total of eight places across all performances, it could wrongly accept a request for B. A useful abstraction removes unrelated detail while preserving distinctions that change the answer.

Work together

Model a new performance

Performance C has five places left. Requests R1 and R2 ask for four and six tickets respectively. Ignore seat positions and assume whole-number quantities.

Work together · 1 / 3

Produce the representation

Add the row C, 5. Record R1 as performance C, quantity 4, and R2 as performance C, quantity 6. Keep the two trial requests independent.

Work together · 2 / 3

Use the model

R1 can be met because 4 is positive and no greater than 5. R2 cannot be met because 6 exceeds 5. No payment or stock change is being performed in this model test.

Work together · 3 / 3

Explain a limit and a benefit

Omitting seat positions makes the availability decision easier to inspect, but the model cannot tell a buyer their seat number. That limitation is acceptable only because named-seat allocation is outside the stated task.

An abstract model must show retained data and useful relationships, with limits that match its purpose.

Experiment

Remove the performance identifier or availability value in turn. Predict a pair of requests the reduced model can no longer distinguish.

Check

Try it yourself · Teacher-written

Create a model for hiring devices: D1 is available and D2 is already hired. The task is to identify a device that can be hired now. Give fields, both rows and one assumption.

Check your reasoning

Use DeviceID and Availability: D1, Available; D2, Hired. Select D1. A suitable assumption is that both devices work and there are no reservations. A list of field names without the two states is incomplete.

Take it further · Optional challenge

The purpose changes to emailing buyers about a cancelled performance. Which information must be added, and why?

Check the challenge

Add a way to associate each booking with its performance and a contact email address. Availability alone cannot identify affected recipients or deliver the message. Explain each additional field through the new purpose.

Question 1 · Command word: Explain3 teacher marks

Explain why a fire-escape model retains exits and blocked corridors but omits classroom display colours.

S9.01.A01S9.01.A02S9.01.A03
Answer and checking points — teacher-written
  1. Exits and corridor accessibility determine whether an escape route can be used.
  2. Display colours do not change route availability in the stated task.
  3. Removing unrelated display detail makes the routes and obstructions easier to inspect.

Common error: Relate relevance to finding a usable escape route.

Write a table model for deciding whether a bicycle can be hired. Bicycle C1 is available and C2 is already hired. The decision depends only on the bicycle identifier and whether it is hired. State one assumption of this model.

One suitable model

BicycleIDOnHire

  1. The table has a BicycleID field and an OnHire Boolean field.
  2. It contains C1 with FALSE and C2 with TRUE.
  3. A suitable assumption is that all bicycles are serviceable and no reservation changes availability.

Common error: Supply the rows as well as field names.

Question 3 · Command word: Explain2 teacher marks

A bus model used to choose the lowest fare stores stops and travel times but no fares. Explain the defect and state a change.

S9.01.A01S9.01.A04
Answer and checking points — teacher-written
  1. Travel time does not establish which route costs least.
  2. The model needs fare information and any relevant fare rules for the available journeys.

Common error: A model must retain information needed for its particular output.
