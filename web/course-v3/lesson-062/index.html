Why is “seat 2” ambiguous when the room has three rows?

A small room has three rows and four seats in each row. Seat position 2 exists in all three rows. Give both the row number and the seat position to identify one seat.

Recall

Recall indices and inclusive bounds

One index selects an element in a one-dimensional array. Each dimension of a two-dimensional array has its own lower and upper bounds. Count each inclusive range separately.

Explain

Explanation · 1 / 3

Give the dimensions a meaning

Use the first index for Row and the second for Seat. Occupied[2, 3] refers to seat 3 in row 2. Declare each element BOOLEAN because each seat is either occupied or not occupied.

Explanation · 2 / 3

Declare both bounds

DECLARE Occupied : ARRAY[1:3, 1:4] OF BOOLEAN defines 3 × 4 = 12 elements. The comma separates dimensions. Both coordinates must be valid for an access to be valid.

DECLARE Occupied : ARRAY[1:3, 1:4] OF BOOLEAN
Occupied[2, 3] <- TRUE
OUTPUT Occupied[2, 3]

Explanation · 3 / 3

Compare a grid with a list

A list of participant names needs one position. A seating plan naturally uses two coordinates. A two-dimensional table still has one declared element type; it is not a record with differently typed fields.

Work together

Count a grid with zero-based bounds

A table is declared ARRAY[0:2, 0:3] OF INTEGER.

Work together · 1 / 2

Count each dimension

The first dimension has 2 - 0 + 1 = 3 positions. The second has 3 - 0 + 1 = 4 positions. Total capacity is 3 × 4 = 12.

Work together · 2 / 2

Check two coordinates independently

[2, 3] is valid. [3, 2] is invalid because the first index exceeds 2, even though 3 is permitted in the second dimension.

A two-dimensional element is located by an ordered pair of valid indices.

Check

Try it yourself · Teacher-written

How many elements are in ARRAY[2:4, 5:8], and is [4, 8] valid?

Check your reasoning

There are (4 - 2 + 1) × (8 - 5 + 1) = 3 × 4 = 12 elements. [4, 8] is valid because both indices are within their own inclusive bounds.

Cambridge 9618/22 · May/June 2025 · 1(d)(i), 1(d)(ii), 1(d)(iii) · 4 marks

Hint — reading the question

Both dimensions start at zero. Count allowed index values, not the number printed as the upper bound.

Reasoning and model answer — teacher-written

1(d)(i): Two dimensions.

1(d)(ii): (99 − 0 + 1) × (9 − 0 + 1) = 100 × 10 = 1000 elements.

DECLARE Product : ARRAY[0:99, 0:9] OF INTEGER

The first two answers earn one mark each. The declaration has one mark for both correct ranges and one for the remaining declaration syntax and INTEGER type.

99 × 9 omits the zero-indexed row and column. Replacing the ranges with 1:100 and 1:10 changes the required indexing even though the element count is the same.

After visiting [1, 3] in a two-row, three-column grid, which position comes next?

Trace a finger across the first row from columns 1 to 3, then return to column 1 of row 2. The column changes more often because its loop is inside the row loop.

Recall

Recall the body of a loop

Every statement between FOR and NEXT belongs to that loop body. If another loop is inside it, that complete inner loop runs for each outer-loop value.

Explain

Explanation · 1 / 3

Choose the outer and inner variables

Row takes 1 then 2. For each Row value, Column starts at 1 and runs through 3. The visit order is [1,1], [1,2], [1,3], [2,1], [2,2], [2,3].

Explanation · 2 / 3

Use both variables in the access

Scores[Row, Column] selects the current location. Using Scores[Row, 1] would repeatedly access only the first column. The nested loops themselves do not make a fixed access change.

DECLARE Scores : ARRAY[1:2, 1:3] OF INTEGER
DECLARE Row : INTEGER
DECLARE Column : INTEGER
DECLARE RowTotal : INTEGER
FOR Row <- 1 TO 2
    RowTotal <- 0
    FOR Column <- 1 TO 3
        INPUT Scores[Row, Column]
        RowTotal <- RowTotal + Scores[Row, Column]
    NEXT Column
    OUTPUT RowTotal
NEXT Row

Explanation · 3 / 3

Reset one row total for each new row

RowTotal <- 0 is inside the outer loop but before the inner loop. It runs once per row. Resetting inside the inner loop would discard earlier values from the same row; resetting before both loops would combine rows.

Work together

Work together · 1 / 2

Complete row 1

RowTotal starts at 0 and becomes 2, then 6, then 7. Output 7 after the inner loop finishes.

Work together · 2 / 2

Start row 2 afresh

Row becomes 2 and RowTotal resets to 0. Column starts again at 1. The total becomes 3, stays 3, then becomes 8. Output 8.

The indentation shows which statements repeat per row and which repeat per element.

Recall
Recall reset scope, MOD and grouped conditions
Initialise an accumulator immediately before the group of additions it represents. Row MOD 2 = 0 tests an even row number. A AND (B OR C) requires A and at least one of B or C.

    
Explain
Explanation · 1 / 3
Keep the grand total outside both loops
GrandTotal starts at 0 once and accumulates all six elements. RowTotal resets once per row. They can be updated in the same inner loop because both totals need the current element.
DECLARE Scores : ARRAY[1:2, 1:3] OF INTEGER
DECLARE Row : INTEGER
DECLARE Column : INTEGER
DECLARE RowTotal : INTEGER
DECLARE ColumnTotal : INTEGER
DECLARE GrandTotal : INTEGER
GrandTotal <- 0
FOR Row <- 1 TO 2
    RowTotal <- 0
    FOR Column <- 1 TO 3
        INPUT Scores[Row, Column]
        RowTotal <- RowTotal + Scores[Row, Column]
        GrandTotal <- GrandTotal + Scores[Row, Column]
    NEXT Column
    OUTPUT RowTotal
NEXT Row
FOR Column <- 1 TO 3
    ColumnTotal <- 0
    FOR Row <- 1 TO 2
        ColumnTotal <- ColumnTotal + Scores[Row, Column]
    NEXT Row
    OUTPUT ColumnTotal
NEXT Column
OUTPUT GrandTotal
Explanation · 2 / 3
Put Column outside when producing one total per column
For a column total, fix Column and visit every Row. Reset ColumnTotal at the start of each outer column iteration. The example produces column totals 5, 4 and 6, whose sum is the grand total 15.
Explanation · 3 / 3
Read two fields in one row before deciding
A different two-column STRING table stores choices. To select an even row containing Search in either column, combine the even-row test with the whole OR group. A row matching both columns is still one qualifying row.
IF (Row MOD 2 = 0) AND
   ((Choice[Row, 1] = Search) OR (Choice[Row, 2] = Search)) THEN
    Count <- Count + 1
ENDIF

Both column comparisons are TRUE, but the even-row test is FALSE. FALSE AND TRUE is FALSE. Row 3 does not qualify. Counting each matching column would answer a different question.

Original question · Cambridge 9618/21
1. Combine a row condition with two column matches
Cambridge 9618/21 · October/November 2023 · 4(b) · 3 marks
Selected parts: 4(b) [3].
Original insert · reference material
Hint — reading the question
Row and Search are already available. Test the current row; do not write a new complete search function. MOD gives the remainder, so an even row has remainder zero on division by two.
Reasoning and model answer — teacher-written
IF (Row MOD 2 = 0) AND
   ((Data[Row, 1] = Search) OR (Data[Row, 2] = Search)) THEN
    // Both required conditions are satisfied
ENDIF
The two equality tests form one OR group. The AND applies the even-row restriction to that entire group. A row with the search string in both columns satisfies the condition once, not twice.
Official mark scheme
Why this earns marks — teacher explanation
The three points are the even-row test, a match in either column, and a correctly combined selection structure. The official alternatives include nested selection. The comment here identifies where the counting action belongs; no counting statement is requested.
Common mistakes — teacher analysis
Using AND between the column tests demands both matches. Omitting the parentheses around OR can let an odd row pass when column 2 matches.

Question 3 · Command word: Write4 teacher marks
Write pseudocode to input a 2 by 3 INTEGER array Scores and output a separate total for each row.
S10.05.A01
Answer and checking points — teacher-written
One valid pseudocode solution
DECLARE Scores : ARRAY[1:2, 1:3] OF INTEGER
DECLARE Row : INTEGER
DECLARE Column : INTEGER
DECLARE RowTotal : INTEGER
FOR Row <- 1 TO 2
    RowTotal <- 0
    FOR Column <- 1 TO 3
        INPUT Scores[Row, Column]
        RowTotal <- RowTotal + Scores[Row, Column]
    NEXT Column
    OUTPUT RowTotal
NEXT Row
  1. Declare the 2D array, loop indices and row total.
  2. Loop over rows 1 to 2 and reset RowTotal within that outer loop.
  3. Loop over columns 1 to 3, input Scores[Row, Column] and accumulate it.
  4. Output each completed row total after the inner loop.
Common error: Do not output a partial total for every cell.

The supplied combined-total program receives [1,0,−1] then [2,3,4] as its rows. State all six outputs and explain how the two independent checks agree.

DECLARE Row : INTEGER
DECLARE Column : INTEGER
DECLARE RowTotal : INTEGER
DECLARE ColumnTotal : INTEGER
