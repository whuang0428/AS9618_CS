Visual overview

Core explanation

A record groups related named fields of different data types under one identifier. Define the record between TYPE and ENDTYPE, then declare a variable of that record type.

A record structure groups a set of related fields, which may have different data types, under one identifier. Field names preserve the meaning of each value, so a record suits several facts about one entity better than an array of same-type indexed elements.

Common misconception

A record groups named fields that may have different types; an array groups indexed elements of one declared element type. The access notation is therefore different.

Cambridge command words

Practice questions

Command word: Define6 marks

Define TProduct with Code, Description, Price and InStock fields, Write declarations for Product1, save values to Price and InStock, then read both fields.

S10.02.A03S10.02.A01S10.02.A02
Answer and marking points
  1. opens TYPE TProduct and declares suitable named fields.
  2. uses suitable STRING, REAL and BOOLEAN field types.
  3. closes the definition with ENDTYPE.
  4. declares Product1 : TProduct after ENDTYPE.
  5. assigns/saves values through Product1.Price and Product1.InStock.
  6. reads/outputs the two named fields without replacing other data.

Common error: For the command word define, perform that exact action; do not replace it with an unrelated fact.

Explain why a record can contain both STRING and DATE fields.

Answer and marking points
  1. Record fields may have different data types but belong to one entity under one identifier.
