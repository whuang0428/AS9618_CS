Records: defining, reading and saving structured data

Related fields form one record while retaining their individual names and data types.

How can one identifier group named fields of different types?

Before you start

Can one INTEGER array directly hold a member's name, year group and payment state?

Check your answer

No. Those values need different types; a record groups named fields of those types.

01

Define a record type and declare a variable

S10.02.A01S10.02.A02

Visual overview

Core explanation

Related fields can have different types

A record groups related named fields under one identifier. Each field has its own type: one member can have a STRING name, INTEGER year group and BOOLEAN payment state.

Define, declare, then store
  1. Define the type: TYPE MemberRecord … ENDTYPE encloses the field DECLARE statements.
  2. Declare a variable: DECLARE Member : MemberRecord creates one variable of that type.
  3. Assign its fields: Store suitable values using field names. A type definition alone creates neither a member nor its field values.
Common misconception

A record is not restricted to one field type, and its field names are not array indices.

Check your understanding

What creates an actual Member variable?

Check your answer

DECLARE Member : MemberRecord, after the record type has been defined.

02

Read and save values using field names

S10.02.A03

Visual overview

Field operations

INPUT Member.NameSave entered text in Name

Member.YearGroup <- Member.YearGroup + 1Read, calculate and overwrite this field
OUTPUT Member.NameRead and display Name

Swipe horizontally to compare every column →

Core explanation

Use dot notation to identify a field, for example Member.YearGroup. INPUT can save a new value directly into that field; an assignment can update it; OUTPUT reads its current value. Updating one field leaves the other fields unchanged.

In the example, the name and current year group are inputs. FeesPaid is explicitly initialised to FALSE, and YearGroup increases by one. Saving data into a record means storing values in its fields. Keeping the record after the program finishes requires a separate file operation.

Worked example · Create and update a member

  1. Task

    Input a member's name and current year group, initialise payment to FALSE, and display the promoted member's fields.

  2. Pseudocode
    TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE Member : MemberRecord
INPUT Member.Name
INPUT Member.YearGroup
Member.FeesPaid <- FALSE
Member.YearGroup <- Member.YearGroup + 1
OUTPUT Member.Name
OUTPUT Member.YearGroup
OUTPUT Member.FeesPaid
  3. Result

    Inputs Mina and 11 produce Mina, 12 and FALSE, on separate output lines.

Common misconception

Member <- "Mina" would assign text to the whole record; Member.Name <- "Mina" identifies the STRING field.

Check your understanding

After FeesPaid changes to TRUE, does Name change?

Check your answer

No. Assigning the FeesPaid field does not overwrite the Name field.

Cambridge command words

Practice questions

Question 1 · Command word: Explain2 marks

Explain why a record suits one product with a description, price and in-stock flag. State a suitable type for each field.

S10.02.A01
Answer and marking points
  1. It groups related product fields under one identifier while allowing different field types.
  2. Description uses STRING, Price uses REAL and InStock uses BOOLEAN.

Common error: Do not describe an array as allowing arbitrary element types.

Question 2 · Command word: Write3 marks

Write pseudocode to define ProductRecord with Description : STRING and Price : REAL, then declare Product of that type.

S10.02.A02
Answer and marking points

One valid pseudocode answer

TYPE ProductRecord
    DECLARE Description : STRING
    DECLARE Price : REAL
ENDTYPE
DECLARE Product : ProductRecord
  1. TYPE ProductRecord starts the record definition.
  2. DECLARE Description : STRING and DECLARE Price : REAL define its fields.
  3. ENDTYPE ends the definition; DECLARE Product : ProductRecord creates a variable.

Common error: The variable declaration belongs after ENDTYPE.

Question 3 · Command word: State2 marks

State all outputs from the supplied member algorithm for input Tariq and 9 and explain which statement saves a BOOLEAN into the record.

Use this complete algorithm in the question.

TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE Member : MemberRecord
INPUT Member.Name
INPUT Member.YearGroup
Member.FeesPaid <- FALSE
Member.YearGroup <- Member.YearGroup + 1
OUTPUT Member.Name
OUTPUT Member.YearGroup
OUTPUT Member.FeesPaid
S10.02.A03
Answer and marking points
  1. The outputs are Tariq, 10 and FALSE.
  2. Member.FeesPaid <- FALSE saves the BOOLEAN value in the FeesPaid field.

Common error: The increment affects YearGroup, not the name.

Question 1 · Command word: Define · 5 marks

A vehicle record needs Registration, Mileage in whole kilometres and Electric. Define VehicleRecord with suitable types and declare Car of that type.

Answer and marking points

One valid pseudocode answer

TYPE VehicleRecord
    DECLARE Registration : STRING
    DECLARE Mileage : INTEGER
    DECLARE Electric : BOOLEAN
ENDTYPE
DECLARE Car : VehicleRecord
  • TYPE VehicleRecord and ENDTYPE enclose the fields.
  • Registration is declared STRING.
  • Mileage is declared INTEGER (whole kilometres in this system).
  • Electric is declared BOOLEAN.
  • DECLARE Car : VehicleRecord creates the record variable.

Common error: The mileage unit is whole kilometres; use the types stated for this system.

Question 2 · Command word: Write · 4 marks

Car has fields Registration : STRING, Mileage : INTEGER and Electric : BOOLEAN. Write statements to input the registration, save 12000 into Mileage, save TRUE into Electric, and display Mileage.

Answer and marking points
  • INPUT Car.Registration.
  • Car.Mileage <- 12000.
  • Car.Electric <- TRUE.
  • OUTPUT Car.Mileage.

Common error: Use field access for each operation, rather than replacing the whole record.

Question 3 · Command word: Explain · 3 marks

A pupil claims that TYPE defines one stored member, and that Member.Name <- "Jo" saves the member permanently. Explain both errors.

Answer and marking points
  • TYPE defines a reusable structure; a separate DECLARE creates a variable using it.
  • The assignment changes only the Name field of the existing record variable.
  • Persistence between executions requires writing data to a file.

Common error: Do not confuse a record variable in a running program with persistent storage.

04

Lesson review

Summary

Structure

A record combines named fields whose types can differ, all under one identifier.

Definition and use

Define the type with TYPE and ENDTYPE, then declare a variable of that type.

Access

Dot notation selects a field for input, assignment or output; file storage is a separate operation.
