Define the fields of one record

Observe

One booking card

FactCurrent value
NameMina
Seats3
PaidFALSE

Look, then discuss

How can Mina, 3 and FALSE all describe the same booking?

Read one booking card: name Mina, three seats, payment not yet received. The values differ in type, but each belongs to one booking. A record keeps the relationship visible.

Recall

Recall names and types

STRING suits the name, INTEGER the seat count and BOOLEAN the payment state. A field is a named part of a record, with its own declared type.

Explain

Explanation · 1 / 3

Group related fields

A record is a composite data structure that groups related fields under one identifier. The fields can have different types. Their names explain which fact each value represents.

FieldTypeExample value
NameSTRINGMina
SeatsINTEGER3
PaidBOOLEANFALSE

Explanation · 2 / 3

Define a reusable record type

TYPE and ENDTYPE enclose the field declarations. BookingRecord is the name of the new type. This definition describes the structure; it does not yet create a booking variable.

TYPE BookingRecord
    DECLARE Name : STRING
    DECLARE Seats : INTEGER
    DECLARE Paid : BOOLEAN
ENDTYPE

Explanation · 3 / 3

Create a variable of that type

DECLARE Booking : BookingRecord creates a variable with those fields. Another variable of BookingRecord has the same structure but can hold a different booking.

DECLARE Booking : BookingRecord
DECLARE AnotherBooking : BookingRecord

Work together

Extend a booking card with a price

The price per seat may be fractional.

Work together · 1 / 2

Choose the field

Add DECLARE Price : REAL inside the TYPE definition. Price belongs to the booking and has a different type from Seats.

Work together · 2 / 2

Distinguish definition from data

The type definition contains names and types, not Mina’s current values. Each declared record variable can later receive its own name, seats, payment state and price.

A record type specifies fields; a record variable holds one set of their values.

Check

Try it yourself · Teacher-written

Can a record contain a STRING, an INTEGER and a BOOLEAN? Must every field have the same type?

Check your reasoning

Yes, it can contain those different field types. Each field has its own declared type. A record groups related facts; it does not require all fields to share one type.

Original question · Cambridge 9618/22

1. Declare a mixed-type record

Cambridge 9618/22 · May/June 2024 · 3(a)(i) · 4 marks

Selected parts: 3(a)(i) [4].

Hint — reading the question

Use the exact type and field names. Item_Num is used as an array index, Stage is one letter, and either limit may contain a fraction.

Reasoning and model answer — teacher-written
TYPE Component
    DECLARE Item_Num : INTEGER
    DECLARE Reject : BOOLEAN
    DECLARE Stage : CHAR
    DECLARE Limit_1 : REAL
    DECLARE Limit_2 : REAL
ENDTYPE

A record groups related fields of different types under one record type. This declaration describes the structure; it does not allocate the later array of items.

Official mark scheme
Why this earns marks — teacher explanation

Four grouped marks cover the TYPE/ENDTYPE pair, Item_Num with Reject, Stage, and both REAL limit fields. Five fields do not mean five marks.

Common mistakes — teacher analysis

An identifier that happens to contain digits may normally be text, but this question explicitly says it is used as a numeric array index. Do not omit either limit.

Build a booking system · Concept 08

Read and change a named field

Observe

Before the additional-seat request

VariableNameSeatsPaid
BookingMina3FALSE

Look, then discuss

Which part changes when Booking.Seats is increased by one?

Mina adds a seat to an existing booking. Her name and payment state should remain as they were. Identify the precise field the program must update.

Recall

Recall assignment and INPUT

INPUT stores entered data in its destination. Assignment evaluates the right side and replaces the left-side value. OUTPUT reads and displays a value without changing it.

Explain

Explanation · 1 / 3

Read the dot notation

Booking.Seats means the Seats field inside the record variable Booking. BookingRecord names the type; Booking names one variable of that type. Use the variable name when accessing its current fields.

Explanation · 2 / 3

Input, initialise and update fields

This complete example inputs two fields, explicitly initialises Paid, then changes only Seats.

TYPE BookingRecord
    DECLARE Name : STRING
    DECLARE Seats : INTEGER
    DECLARE Paid : BOOLEAN
ENDTYPE
DECLARE Booking : BookingRecord
INPUT Booking.Name
INPUT Booking.Seats
Booking.Paid <- FALSE
Booking.Seats <- Booking.Seats + 1
OUTPUT Booking.Name
OUTPUT Booking.Seats
OUTPUT Booking.Paid

Explanation · 3 / 3

Keep instances separate

Two variables can share a record type without sharing their current data. Updating AnotherBooking.Name does not instruct the program to update Booking.Name. The variable name identifies which record is being accessed.

Work together

Follow Mina’s additional seat

The input values are Mina and 3.

Work together · 1 / 2

State the record before the update

After the input and initialisation, Booking contains Name = "Mina", Seats = 3 and Paid = FALSE.

Work together · 2 / 2

Trace the field update and output

The program reads Booking.Seats as 3, computes 4 and stores 4 in that field. It displays Mina, 4 and FALSE. No statement changes Name or Paid.

A field update changes the selected field of the selected record.

Question 1 · Command word: Explain2 teacher marks
Explain why a record suits one product with a description, price and in-stock flag. State a suitable type for each field.
S10.02.A01
Answer and checking points — teacher-written
  1. It groups related product fields under one identifier while allowing different field types.
  2. Description uses STRING, Price uses REAL and InStock uses BOOLEAN.
Common error: Do not describe an array as allowing arbitrary element types.
Question 2 · Command word: Write3 teacher marks
Write pseudocode to define ProductRecord with Description : STRING and Price : REAL, then declare Product of that type.
S10.02.A02
Answer and checking points — teacher-written
One valid pseudocode answer
TYPE ProductRecord
    DECLARE Description : STRING
    DECLARE Price : REAL
ENDTYPE
DECLARE Product : ProductRecord
  1. TYPE ProductRecord starts the record definition.
  2. DECLARE Description : STRING and DECLARE Price : REAL define its fields.
  3. ENDTYPE ends the definition; DECLARE Product : ProductRecord creates a variable.
Common error: The variable declaration belongs after ENDTYPE.
Question 3 · Command word: State2 teacher marks
State all outputs from the supplied member algorithm for input Tariq and 9 and explain which statement saves a BOOLEAN into the record.
Use this complete algorithm in the question.
TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE Member : MemberRecord
INPUT Member.Name
INPUT Member.YearGroup
Member.FeesPaid <- FALSE
Member.YearGroup <- Member.YearGroup + 1
OUTPUT Member.Name
OUTPUT Member.YearGroup
OUTPUT Member.FeesPaid
S10.02.A03
Answer and checking points — teacher-written
  1. The outputs are Tariq, 10 and FALSE.
  2. Member.FeesPaid <- FALSE saves the BOOLEAN value in the FeesPaid field.
Common error: The increment affects YearGroup, not the name.
Question 4 · Command word: State2 teacher marks
Using the supplied two-record algorithm, add First.YearGroup <- 13 immediately before the outputs. State both final year groups and explain why they differ.
Use this complete algorithm in the question.
TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE First : MemberRecord
DECLARE Second : MemberRecord
First.Name <- "Mina"
First.YearGroup <- 11
First.FeesPaid <- FALSE
Second <- First
Second.Name <- "Jo"
Second.YearGroup <- 12
Second.FeesPaid <- TRUE
OUTPUT First.Name
OUTPUT First.YearGroup
OUTPUT First.FeesPaid
OUTPUT Second.Name
OUTPUT Second.YearGroup
OUTPUT Second.FeesPaid
S10.02.A03
Answer and checking points — teacher-written
  1. First.YearGroup is 13; Second.YearGroup remains 12.
  2. The field assignment selects First only; the earlier copy did not make the two variables one record.
Common error: Copying a record value does not make later field updates apply to both variables.
