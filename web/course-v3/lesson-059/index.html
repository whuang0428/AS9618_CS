Records: defining, reading and saving structured data

Related fields form one record while retaining their individual names and data types.

How can one identifier group named fields of different types?

Before you start

Can one INTEGER array directly hold a member's name, year group and payment state?

Check your answer

No. Those values need different types; a record groups named fields of those types.

01

Define a record type and declare a variable

S10.02.A01S10.02.A02

Visual overview

One item with related fields

A record groups related fields, potentially of different data types, under one identifier. Each field has a name and its own type. A record for one member can therefore hold a STRING name, an INTEGER year group and a BOOLEAN payment state without losing their different meanings.

Define the structure before creating an instance

TYPE MemberRecord introduces the record definition and ENDTYPE closes it. The DECLARE statements inside define its fields. DECLARE Member : MemberRecord then creates a variable of that type; defining the type alone does not create a member or supply values for its fields.

Choose grouping by meaning

The fields may have different types; they do not have to be different. A record with two STRING fields is still a record because those fields have distinct names and roles. An array instead applies one element type to its indexed positions.

Connect the term to its context

A database row is also often called a record. Here TYPE describes a record value in a program. It does not create a database table or a persistent file. Defining MemberRecord once allows First and Second to hold two different members.

Core explanation · Exam essentials

  • A record groups named fields under one identifier; each field has its own declared type.
  • TYPE … ENDTYPE defines the record type; DECLARE creates a variable of that type.
Common misconception

A record is not restricted to one field type, and its field names are not array indices.

Check your understanding

What creates an actual Member variable?

Check your answer

DECLARE Member : MemberRecord, after the record type has been defined.

Select one field with dot notation

Use dot notation to identify a field, for example Member.YearGroup. INPUT can save a new value directly into that field; an assignment can update it; OUTPUT reads its current value. Updating one field leaves the other fields unchanged.

Read, change and retain the intended data

In the example, the name and current year group are inputs. FeesPaid is explicitly initialised to FALSE, and YearGroup increases by one. Saving data into a record means storing values in its fields. Keeping the record after the program finishes requires a separate file operation.

Trace a field update

  1. Before: Member.YearGroup contains 11 after input.
  2. Evaluate: Read 11 and calculate 11 + 1.
  3. Store: Write 12 into Member.YearGroup. Name and FeesPaid retain their existing values.

Follow the complete examples

The two-instance example supplies all initial fields before any output. Read the final table as two separate records: updating Second does not update First. A whole-record assignment requires a compatible record type; the later field assignment still selects just one destination.

Worked example · Create and update a member

  1. Task

    Input a member's name and current year group, initialise payment to FALSE, and display the promoted member's fields.

  2. Pseudocode
    TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE Member : MemberRecord
INPUT Member.Name
INPUT Member.YearGroup
Member.FeesPaid <- FALSE
Member.YearGroup <- Member.YearGroup + 1
OUTPUT Member.Name
OUTPUT Member.YearGroup
OUTPUT Member.FeesPaid
  3. Result

    Inputs Mina and 11 produce Mina, 12 and FALSE, on separate output lines.

Worked example · Create two independent record values

  1. Task

    Define the type, fill First, copy its value to Second, then change each of Second's fields.

  2. Pseudocode
    TYPE MemberRecord
    DECLARE Name : STRING
    DECLARE YearGroup : INTEGER
    DECLARE FeesPaid : BOOLEAN
ENDTYPE
DECLARE First : MemberRecord
DECLARE Second : MemberRecord
First.Name <- "Mina"
First.YearGroup <- 11
First.FeesPaid <- FALSE
Second <- First
Second.Name <- "Jo"
Second.YearGroup <- 12
Second.FeesPaid <- TRUE
OUTPUT First.Name
OUTPUT First.YearGroup
OUTPUT First.FeesPaid
OUTPUT Second.Name
OUTPUT Second.YearGroup
OUTPUT Second.FeesPaid
  3. Result

    The six output lines are Mina, 11, FALSE, Jo, 12, TRUE. First retains its original fields.

Core explanation · Exam essentials

  • Use Variable.Field for input, assignment and output.
  • Initialise fields before reading them; changing one field preserves the others.
  • Saving values in record fields does not make them persistent between runs.
Common misconception

Member <- "Mina" would assign text to the whole record; Member.Name <- "Mina" identifies the STRING field.

Check your understanding

After FeesPaid changes to TRUE, does Name change?

Check your answer

No. Assigning the FeesPaid field does not overwrite the Name field.

Question 1 · Command word: Explain2 teacher marks

Explain why a record suits one product with a description, price and in-stock flag. State a suitable type for each field.

S10.02.A01
Answer and checking points — teacher-written
  1. It groups related product fields under one identifier while allowing different field types.
  2. Description uses STRING, Price uses REAL and InStock uses BOOLEAN.

Common error: Do not describe an array as allowing arbitrary element types.

Question 2 · Command word: Write3 teacher marks

Write pseudocode to define ProductRecord with Description : STRING and Price : REAL, then declare Product of that type.

S10.02.A02
Answer and checking points — teacher-written

One valid pseudocode answer

TYPE ProductRecord
    DECLARE Description : STRING
    DECLARE Price : REAL
ENDTYPE
DECLARE Product : ProductRecord
  1. TYPE ProductRecord starts the record definition.
  2. DECLARE Description : STRING and DECLARE Price : REAL define its fields.
  3. ENDTYPE ends the definition; DECLARE Product : ProductRecord creates a variable.

Common error: The variable declaration belongs after ENDTYPE.

Original question · Cambridge 9618/22

1. Declare a mixed-type record

Cambridge 9618/22 · May/June 2024 · 3(a)(i) · 4 marks

Selected parts: 3(a)(i) [4].

Reading the question — teacher guidance

Use the exact type and field names. Item_Num is used as an array index, Stage is one letter, and either limit may contain a fraction.

Solution / model answer — teacher-written
TYPE Component
    DECLARE Item_Num : INTEGER
    DECLARE Reject : BOOLEAN
    DECLARE Stage : CHAR
    DECLARE Limit_1 : REAL
    DECLARE Limit_2 : REAL
ENDTYPE

A record groups related fields of different types under one record type. This declaration describes the structure; it does not allocate the later array of items.

Official mark scheme
Why this earns marks — teacher explanation

Four grouped marks cover the TYPE/ENDTYPE pair, Item_Num with Reject, Stage, and both REAL limit fields. Five fields do not mean five marks.

Common mistakes — teacher analysis

An identifier that happens to contain digits may normally be text, but this question explicitly says it is used as a numeric array index. Do not omit either limit.

04

Lesson review

Summary

Structure

A record combines named fields whose types can differ, all under one identifier.

Definition and use

Define the type with TYPE and ENDTYPE, then declare a variable of that type.

Access

Dot notation selects a field for input, assignment or output; file storage is a separate operation.
