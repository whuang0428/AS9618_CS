Does a function call merely display a result?

Check your answer

No. A function returns a value that the caller can use in an expression; a separate output statement or procedure can display it.

01

Decompose a problem into a structure chart

S12.02.A01S12.02.A02S12.02.A03

Visual overview

Core explanation

Show which modules call which

A structure chart records the decomposition of a problem into modules. A rectangle names a module, and a connecting hierarchy line shows a calling relationship. Place the controlling module above the modules it calls, then refine a large subtask into another level when needed. The chart documents the overall design rather than every statement executed inside a module.

Apply the hierarchy to ProcessOrder

For one order, ProcessOrder obtains a positive integer Quantity and a non-negative real UnitPrice, calculates their product and displays the cost. The three child modules have distinct responsibilities. ReadOrder obtains the inputs, CalculateCost returns their product, and DisplayCost presents the supplied amount. For this example the parent calls them in that left-to-right sequence.

Common misconception

A structure chart is not a flowchart: module hierarchy does not show each decision or loop inside a module.

Check your understanding

Why should DisplayCost receive Cost rather than ask for the quantity again?

Check your answer

It displays the result already calculated for the current order; obtaining fresh inputs could make the output describe a different order.

Make parameters and returned values explicit

S12.02.A01

Visual overview

Swipe horizontally to compare every column →

Core explanation

Show the direction of transferred values

Label each transferred value and show its direction. A module needs an input value before it can use that value. ReadOrder instead supplies newly entered values back to the parent, so its parameters are passed by reference. CalculateCost can receive copies of the quantity and price by value and return one numeric cost.

Match parameters, arguments and returned results

A formal parameter appears in a procedure or function header. An argument appears in the call. The number, order and types must match the interface. A function result is assigned or used in an expression; a procedure that changes a by-reference argument can update the caller's variable without returning a function value.

Common misconception

A printed number is not a function return value. CALL DisplayCost(Cost) does not assign a numeric result.

Check your understanding

What changes if ReadOrder receives Quantity only by value?

Check your answer

Assigning the local copy does not supply the entered quantity to the parent.

03

Derive and check equivalent pseudocode

S12.02.A03S12.02.A04

Visual overview

From chart to implementation

  1. InterfacesSpecify reader outputs, calculation inputs and returned result.
  2. DefinitionsWrite the input, multiplication and output bodies.
  3. ParentDeclare data and connect the calls through its variables.
  4. TraceUse Quantity 3 and UnitPrice 2.50; the displayed cost must be 7.50.

Core explanation

Implement the module interfaces and bodies

Convert module boxes into complete subprogram definitions with the specified interfaces. Inside each parent, write calls or function expressions in the required order. Add the module bodies from the problem requirements; a chart gives responsibility and interface information but does not supply every internal statement.

Check agreement between chart and program

Check equivalence by following the same data through chart and program. In this design, the reader changes the parent's two variables, the function computes their product, and the display procedure receives that result. Declarations, parameter modes, return type and argument order must agree. A list of headers without the parent calls or bodies is not a complete implementation.

Worked example · Order chart translated into a complete program

  1. Assumptions

    One order; Quantity is a positive integer and UnitPrice a non-negative real. Inputs already have these types.

  2. Equivalent pseudocode
    PROCEDURE ReadOrder(BYREF Quantity : INTEGER, BYREF UnitPrice : REAL)
    INPUT Quantity
    INPUT UnitPrice
ENDPROCEDURE

FUNCTION CalculateCost(BYVAL Quantity : INTEGER, BYVAL UnitPrice : REAL) RETURNS REAL
    RETURN Quantity * UnitPrice
ENDFUNCTION

PROCEDURE DisplayCost(BYVAL Cost : REAL)
    OUTPUT Cost
ENDPROCEDURE

PROCEDURE ProcessOrder
    DECLARE Quantity : INTEGER
    DECLARE UnitPrice : REAL
    DECLARE Cost : REAL
    CALL ReadOrder(Quantity, UnitPrice)
    Cost <- CalculateCost(Quantity, UnitPrice)
    CALL DisplayCost(Cost)
ENDPROCEDURE

CALL ProcessOrder
  3. Trace

    ReadOrder supplies 3 and 2.50; CalculateCost returns 7.50; DisplayCost outputs 7.50.

Common misconception

Preserving module names is insufficient if the call order or direction of data changes.

Check your understanding

Why must the parent assign CalculateCost's result before displaying Cost?

Check your answer

Cost must contain the returned amount before DisplayCost receives it.

Question 1 · Command word: State2 marks

State what a rectangle represents in a structure chart and explain what the connecting hierarchy lines show.

S12.02.A01S12.02.A02
Answer and marking points
  1. A rectangle represents a module, procedure or function.
  2. A hierarchy connection identifies which module calls a lower-level module.

Common error: Do not describe a rectangle as an individual assignment statement.

Question 2 · Command word: Draw4 marks

Draw a structure chart for ProcessOrder calling ReadOrder, CalculateCost and DisplayCost in sequence. Label the quantity, price and cost flows specified in this lesson.

S12.02.A01S12.02.A03
Answer and marking points
  1. ProcessOrder is the parent of the three named child modules.
  2. ReadOrder supplies Quantity and UnitPrice to the parent.
  3. The parent passes those two values to CalculateCost and receives Cost.
  4. The parent passes Cost to DisplayCost.

Common error: Draw the data directions as well as the module names.

Question 3 · Command word: Explain2 marks

Explain why ReadOrder uses by-reference parameters while CalculateCost can use by-value parameters.

S12.02.A01
Answer and marking points
  1. ReadOrder must update the caller's variables with the newly entered order data.
  2. CalculateCost needs copies for arithmetic and supplies its single result through RETURN.

Common error: A function return and a by-reference update are different ways to supply a result.

Question 4 · Command word: Write4 marks

Write the parent ProcessOrder procedure for the supplied chart, including declarations, the reader call, the calculation and the display call. The three child definitions are those shown in the worked example.

S12.02.A04
Answer and marking points

Complete program including the requested parent

PROCEDURE ReadOrder(BYREF Quantity : INTEGER, BYREF UnitPrice : REAL)
    INPUT Quantity
    INPUT UnitPrice
ENDPROCEDURE

FUNCTION CalculateCost(BYVAL Quantity : INTEGER, BYVAL UnitPrice : REAL) RETURNS REAL
    RETURN Quantity * UnitPrice
ENDFUNCTION

PROCEDURE DisplayCost(BYVAL Cost : REAL)
    OUTPUT Cost
ENDPROCEDURE

PROCEDURE ProcessOrder
    DECLARE Quantity : INTEGER
    DECLARE UnitPrice : REAL
    DECLARE Cost : REAL
    CALL ReadOrder(Quantity, UnitPrice)
    Cost <- CalculateCost(Quantity, UnitPrice)
    CALL DisplayCost(Cost)
ENDPROCEDURE

CALL ProcessOrder
  1. Quantity is INTEGER; UnitPrice and Cost are REAL within the parent.
  2. CALL ReadOrder(Quantity, UnitPrice) obtains the two values.
  3. Cost <- CalculateCost(Quantity, UnitPrice) stores the returned result.
  4. CALL DisplayCost(Cost) follows the calculation, and ENDPROCEDURE closes the parent.

Common error: Do not use CALL for the function expression.

Question 1 · Command word: Draw · 4 marks

A payroll parent named ProcessPayroll calls ReadHours, CalculatePay and PrintPay. Hours and Rate are obtained by ReadHours; CalculatePay receives them and returns Pay; PrintPay receives Pay. Draw the hierarchy and label each transfer.

Answer and marking points
  • The payroll parent connects to all three child modules.
  • Hours and Rate flow from ReadHours back to its caller.
  • Both values flow from the parent into CalculatePay, with Pay returned to the parent.
  • The final transfer carries Pay from the parent to PrintPay.

Common error: Do not draw a direct child-to-child call that the description does not specify.

Question 2 · Command word: Write · 6 marks

Write complete pseudocode matching the supplied journey chart. ReadJourney inputs Distance and Speed as REAL values; Speed is greater than zero. CalculateDuration returns Distance / Speed. DisplayDuration outputs the duration. Include all definitions and the controlling call.

Answer and marking points

One valid journey program

PROCEDURE ReadJourney(BYREF Distance : REAL, BYREF Speed : REAL)
    INPUT Distance
    INPUT Speed
ENDPROCEDURE

FUNCTION CalculateDuration(BYVAL Distance : REAL, BYVAL Speed : REAL) RETURNS REAL
    RETURN Distance / Speed
ENDFUNCTION

PROCEDURE DisplayDuration(BYVAL Duration : REAL)
    OUTPUT Duration
ENDPROCEDURE

PROCEDURE PlanJourney
    DECLARE Distance : REAL
    DECLARE Speed : REAL
    DECLARE Duration : REAL
    CALL ReadJourney(Distance, Speed)
    Duration <- CalculateDuration(Distance, Speed)
    CALL DisplayDuration(Duration)
ENDPROCEDURE

CALL PlanJourney
  • ReadJourney has two BYREF REAL parameters and inputs both values.
  • CalculateDuration has the matching BYVAL REAL parameters and returns Distance / Speed as REAL.
  • DisplayDuration receives a REAL duration and outputs it.
  • PlanJourney declares Distance, Speed and Duration locally.
  • The parent reads the values, assigns the function result, then calls the display procedure.
  • All definitions close correctly and CALL PlanJourney starts the program.

Common error: Match the interface directions shown, not the names from the order example.

Question 3 · Command word: Explain · 3 marks

Explain what a structure chart showing Main calling ReadSize and DisplayArea tells a programmer, and what detail it lacks for calculating a rectangle's area.

Answer and marking points
  • The connections identify the two submodules called by Main.
  • The design must specify where multiplication of length by width occurs and which module owns it.
  • Labelled size and area interfaces are needed to connect the calculation to input and display.

Common error: Module names alone do not define the arithmetic or parameter flow.
