From a request to a reliable booking program.

A working program begins with an agreed purpose. Follow the school booking system as its team clarifies a request, designs the solution, investigates faults, collects test evidence and responds to change. Recall programming foundations exactly where you need them.

Turn a booking request into a development plan

The booking program from Sections 9–11 is a starting point. Follow one requirement through the work that makes a program suitable for its users, then compare ways to organise that work.

Design modules that exchange the right information

Split one booking calculation into input, calculation and display. Rebuild parameter knowledge at each interface, then translate the design into complete pseudocode.

Describe what the booking can do next

A booking can remain in one state while waiting for an event. Trace state, event, condition and action separately before transferring the method to an unfamiliar diagram.

Find the first point where the program goes wrong

Begin with a visible symptom. Distinguish different kinds of fault, compare a trace with the required behaviour and verify a focused correction.

Choose tests for the question you need to answer

Different testing methods reveal different evidence. Start with a manual trace, then test paths and interfaces, and finally consider user environments and acceptance.

Make testing repeatable and its evidence usable

After choosing methods and purposeful data, plan who will test what, then keep records that distinguish expectation, observation and retest.

Choose data that could expose a real mistake

Start with the permitted input domain. Challenge the limits and then choose complete input sequences that distinguish different behaviours.

Keep the delivered booking system useful

Delivery does not freeze the world around a program. Identify why a change is needed, then keep the requirement, implementation and tests consistent.

Amend a program while preserving required behaviour

Trace the existing program, identify the full impact of the requested change and verify the result. Then transfer this method from calculations to interfaces and stored records.
