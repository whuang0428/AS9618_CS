Validation, verification, parity and checksums

Apply validation rules, compare entered data with its source, and calculate checks for transmitted data.

Does the value satisfy a rule, agree with its source, or reveal a transmission error?

Before you start

Both source and entered age say 200; the allowed range is 0 to 120. Which process rejects it?

Check your answer

Validation rejects the age. A comparison with that source would find agreement.

01

Validation and verification answer different questions

S6.07.A01S6.07.A09

Visual overview

A source mark of 46 is entered as 64

CheckTestResult
ValidationIs the mark between 0 and 75?64 passes
VerificationDoes the entry match the source value 46?Mismatch detected

Swipe horizontally to compare every column →

Core explanation

Validation tests whether input satisfies stated rules and is reasonable for its purpose. Verification checks whether information has been entered, copied or transferred accurately relative to its source. Both reduce the acceptance of errors and so help maintain data integrity.

A plausible wrong value can pass validation, and two copies of a false original can agree. Neither process proves that the source is true. Use both when a system needs acceptable values and faithful copying.

Common misconception

Passing a rule does not prove agreement with the source.

Check your understanding

Both source and entered age say 200; the allowed range is 0 to 120. Which process rejects it?

Check your answer

Validation rejects the age. A comparison with that source would find agreement.

Range and limit checks

S6.07.A02S6.07.A07

Visual overview

Core explanation

A range check applies both a lower and an upper bound, such as 0 <= Mark <= 75. Test both endpoints as well as values outside them; the stated rule decides whether the bounds are inclusive.

A limit check applies one upper or lower bound, such as FileSize <= 10 MiB. It does not introduce a second bound that was not specified. Choose a range when both ends matter and a limit when the requirement supplies one bound.

Worked example · Test an inclusive temperature range

  1. Rule

    Accept temperatures from -20 to 50 degrees Celsius inclusive.

  2. Endpoints

    -20 and 50 pass because equality is included.

  3. Outside

    -21 and 51 fail because they lie beyond a bound.

  4. Single-bound alternative

    A minimum-only limit Temperature >= -20 would accept 51; it does not impose the upper bound.

Common misconception

Do not describe a one-sided limit as if it also enforced an unstated second limit.

Check your understanding

Does 75 pass the rule 0 <= Mark < 75?

Check your answer

No. The upper comparison is strict, so 75 is excluded.

Format and length checks

Core explanation

A format check tests a required pattern, for example two uppercase letters followed by four digits. A length check tests the number of characters, for example exactly six. The two checks ask different questions about the same string.

A six-character value can still have the wrong format. Check the complete pattern and the specified character count, preserving leading zeros when a code is a string.

Common misconception

The correct length alone does not establish the correct character pattern.

Check your understanding

Does 123456 satisfy both rules in the table?

Check your answer

It passes length but fails format because the first two characters are not uppercase letters.

Core explanation

A presence check requires an entry rather than a blank required field. An existence check looks for the supplied value in a specified stored lookup or file, such as checking that a customer identifier belongs to an existing customer.

A value can be present but absent from the lookup. Define which field is required and which stored set supplies valid identifiers; do not confuse these checks with a format test.

Common misconception

A non-empty identifier is not evidence that the referenced record exists.

Check your understanding

An order names C999. What extra information is needed to check existence?

Check your answer

The stored customer lookup against which C999 will be searched.

05

Calculate and check an identifier's check digit

S6.07.A08

Visual overview

Core explanation

A check digit is derived from the other digits in an identifier and stored with them. On entry or scanning, the system repeats the stated calculation and compares the expected check digit with the supplied digit. A mismatch causes rejection or re-entry.

Use the algorithm given in the question: different schemes use different weights and moduli. For the example here, multiply the four data digits by 3, 1, 3, 1 and choose a final digit that makes the total a multiple of 10. Some errors can still produce the same check digit.

Worked example · Verify a scanned code

  1. Received code

    The scanner returns 47268; its last digit is the supplied check digit 8.

  2. Recalculate

    4 x 3 + 7 x 1 + 2 x 3 + 6 x 1 = 31.

  3. Compare

    The expected final digit is 9, so the supplied 8 does not match.

  4. Decision

    Reject or request re-entry; the check does not identify with certainty which digit was mistyped.

Common misconception

The final check digit is not another data digit to which the four supplied weights are applied.

Check your understanding

If the weighted total is already 40, what check digit is needed?

Check your answer

0: the total already is a multiple of 10.

Verify entered data

S6.08.A01S6.08.A02

Visual overview

Source code: BK209

Repeated mistakeBK290 and BK290Copies agree despite wrong source copying

Swipe horizontally to compare every column →

Core explanation

For a visual check, a person compares the entered value with the original source and investigates differences. It is a comparison with a source, not simply a judgement that the value looks reasonable.

For double entry, the value is entered independently twice and the computer compares the entries. A mismatch is flagged for correction or re-entry. Agreement still cannot establish that the original source is correct, and repeating the same mistake can evade detection.

Worked example · Resolve a double-entry mismatch

  1. Entries

    First operator enters 8371; second operator enters 8731.

  2. Comparison

    The computer finds different strings and flags the entry.

  3. Resolution

    Compare against the original form, which reads 8371, then correct and check again.

Common misconception

Double entry compares copies; it does not use a numeric average of them.

Check your understanding

Source 640 is entered as 604 twice. Does double entry detect the mistake?

Check your answer

No. Both entered copies agree, so an independent source comparison is still useful.

07

Use parity on a byte

S6.08.A03S6.08.A05

Visual overview

Core explanation

A parity bit is chosen so the total number of 1 bits, including that bit, has the agreed even or odd parity. The examples use seven data bits and one parity bit to form an eight-bit transmitted group.

The receiver counts the 1s and compares the result with the agreed convention. Any odd number of flipped bits changes parity and is detected. An even number of flips can leave parity unchanged; the check alone cannot identify the incorrect bit or prove the byte is correct.

Worked example · An undetected two-bit change

  1. Sent

    Even-parity byte 10110010 contains four 1 bits.

  2. Two flips

    If its first two bits flip, the receiver gets 01110010.

  3. Test

    The received byte still contains four 1 bits, so it passes even parity despite different data.

Common misconception

Passing parity means no parity error was detected; it is not proof of an error-free transfer.

Check your understanding

Under odd parity, should the parity bit for data 1110000 be 0 or 1?

Check your answer

0: there are already three 1 bits, an odd total.

08

Use row and column parity

S6.08.A03S6.08.A05

Visual overview

Core explanation

Block parity organises transmitted groups into rows, applies a parity bit to each row, and adds a parity row or byte for the columns. The receiver checks parity in both directions using the agreed convention.

If exactly one bit has changed, the failing row and failing column intersect at that bit, allowing it to be located and corrected by flipping it. Multiple errors may be ambiguous or undetected; four flipped corner bits in a rectangle leave every affected row and column parity unchanged.

Worked example · Correct the illustrated received block

  1. Row checks

    In the received block, row 2 has odd rather than even parity.

  2. Column checks

    Column 5 also has odd parity; the other rows and columns satisfy the rule.

  3. Locate

    Assuming one changed bit, it is at row 2, column 5.

  4. Correct and recheck

    Change that bit from 1 back to 0. Recompute both directions to confirm the block satisfies even parity.

Common misconception

Locating an error depends on the error pattern; do not promise correction of every corrupted block.

Check your understanding

What can happen if the four corners of a rectangle all flip?

Check your answer

Each affected row and column has two changes, so all parity checks can still pass.

09

Calculate and compare a checksum

S6.08.A04S6.08.A05

Visual overview

Core explanation

The sender calculates a value from a data block using an agreed checksum algorithm and sends it with the data. The receiver applies the same algorithm to the received block and compares its result with the transmitted checksum.

A mismatch indicates an error and can trigger rejection or retransmission. A match means no error was detected by that checksum; different data can produce the same value. Use the stated algorithm rather than assuming that all checksums are simple sums.

Worked example · A matching checksum can miss an error

  1. Original block

    84 + 121 + 77 = 282; this example's checksum is 26.

  2. Changed block

    85 + 120 + 77 is also 282.

  3. Limitation

    The two opposite changes cancel in the sum, so checksum 26 matches even though two data values differ.

Common misconception

A checksum is used on a transferred block; a check digit is attached to an identifier under a validation rule.

Check your understanding

The received and recomputed checksums differ. What should the receiver conclude?

Check your answer

An error was detected; do not accept the block as verified. Reject it or request retransmission.

Question 1 · Command word: Explain3 marks

A source form says 28 but 82 is entered. The allowed range is 0 to 100. Explain the validation result and the result of comparison with the source.

S6.07.A01S6.07.A09
Answer and marking points
  1. 82 satisfies the range, so that validation check passes.
  2. 82 differs from 28, so source verification detects a copying error.
  3. This shows that a valid value need not be the true or intended value.

Common error: Keep rule compliance separate from faithful copying.

Question 2 · Command word: State3 marks

State which values pass -10 <= Temperature <= 40 from -11, -10, 40 and 41. Then apply the single limit Temperature >= -10 to the same values and explain the difference.

S6.07.A02S6.07.A07
Answer and marking points
  1. The range accepts -10 and 40 only.
  2. The limit accepts -10, 40 and 41.
  3. The range has an upper bound as well as a lower bound; the stated limit has only a lower bound.

Common error: Include the endpoints where equality is allowed.

Question 3 · Command word: State3 marks

A code must contain exactly six characters in the format two uppercase letters followed by four digits. State the length and format result for AB1234, 123456 and AB123.

S6.07.A03S6.07.A04
Answer and marking points
  1. AB1234 passes length and format.
  2. 123456 passes length but fails format.
  3. AB123 fails both the length and the specified format.

Common error: Assess each check independently.

Question 4 · Command word: State4 marks

The stored product IDs are P10 and P20. Apply presence and existence checks to a blank entry, P20 and P99, and state what each check tests.

S6.07.A05S6.07.A06
Answer and marking points
  1. Presence tests for a non-blank required entry; the blank fails.
  2. Existence tests for membership in the stored product lookup.
  3. P20 is present and exists.
  4. P99 is present but does not exist in that lookup.

Common error: A supplied value can fail existence without failing presence.

Question 5 · Command word: Calculate3 marks

Calculate the check digit for data digits 5834 using weights 3,1,3,1. Choose the digit that makes the weighted total plus that digit a multiple of 10. State whether code 58345 passes.

S6.07.A08
Answer and marking points
  1. The products are 15, 8, 9 and 4.
  2. Their total is 36, so the check digit is 4.
  3. 58345 fails because its supplied check digit 5 differs from the calculated 4.

Common error: The weight rule applies to the four data digits, not the appended check digit.

Question 6 · Command word: Describe3 marks

An original reference is KX304. A visual check sees KX340 entered. A separate double-entry attempt produces KX304 and KX340. Describe how each check detects an error and how it should be resolved.

S6.08.A01S6.08.A02
Answer and marking points
  1. The visual check compares the entered reference with the original and spots the transposed digits.
  2. The computer compares the two independently entered strings and flags their mismatch.
  3. Consult the original source, correct the entry and compare again.

Common error: Do not choose the first entry as correct without checking the source.

Question 7 · Command word: Calculate3 marks

Calculate the parity bit for seven data bits 1100101 under even parity, then under odd parity. Explain why flipping two bits may evade a byte parity check.

S6.08.A03S6.08.A05
Answer and marking points
  1. The data has four 1 bits, so the even-parity bit is 0.
  2. The odd-parity bit is 1, giving five 1 bits in total.
  3. Two flips change the count by an even amount, preserving its odd/even parity.

Common error: Count the parity bit in the total.

Question 8 · Command word: Calculate4 marks

Calculate the even-parity row for these three complete eight-bit rows: 11100001, 01010101, 00110011. Then suppose only row 2 becomes 01011101. Identify the changed bit and describe the correction.

S6.08.A03
Answer and marking points
  1. The column parity row is 10000111.
  2. Only row 2 fails its parity check.
  3. Column 5 fails, locating the error at row 2 column 5.
  4. Flip that bit from 1 to 0 and recheck both row and column parity.

Common error: Use column counts rather than adding the rows as binary integers.

Question 9 · Command word: Calculate3 marks

Calculate a checksum for data bytes 200,45,30 using sum modulo 256. If the receiver gets 200,46,30 with the original checksum, calculate its check value and state the decision.

S6.08.A04
Answer and marking points
  1. The original sum is 275, giving checksum 19.
  2. The received sum is 276, giving checksum 20.
  3. 20 differs from transmitted 19, so reject the block or request retransmission.

Common error: Apply the same modulo rule at both ends.

Question 10 · Command word: Explain2 marks

Explain why both identical double-entry values and matching transfer checksums can still occur when the information is wrong.

S6.08.A05
Answer and marking points
  1. The operator can repeat the same incorrect entry, producing identical copies.
  2. Different data blocks can produce the same checksum, so a changed block may escape detection.

Common error: Agreement is evidence from a particular check, not proof of truth.

Question 1 · Command word: Identify · 5 marks

A membership form requires a non-blank member ID that exists in a stored membership file, a six-character booking code, and an age from 5 to 18 inclusive. Identify one validation check for each requirement. Explain why an age of 12 may pass even if the member is actually 14.

Answer and marking points
  • Use a presence check for the required member ID.
  • Use an existence check against the membership file.
  • Use a length check for the six-character booking code.
  • Use a range check with inclusive bounds 5 and 18 for age.
  • 12 meets the permitted range, but the rule does not establish the member's true age.

Common error: An existence check needs the specified stored file, not just a plausible identifier.

Question 2 · Command word: Calculate · 4 marks

A reference has data digits 2468. Using weights 3,1,3,1, its final digit must make the weighted total a multiple of 10. Calculate the check digit. A clerk then enters the same incorrect full reference twice. Explain why the two checking methods may give different results.

Answer and marking points
  • The weighted total is 6 + 4 + 18 + 8 = 36.
  • The required check digit is 4, producing 24684.
  • Double entry accepts matching copies even when the same mistake is repeated.
  • The check-digit rule may reject those copies if their supplied final digit fails the recalculated rule.

Common error: Do not claim every possible wrong reference is detected by a check digit.

Question 3 · Command word: Explain · 4 marks

A transfer uses even parity and a separate sum-modulo-256 checksum. Explain why 10101100 passes byte parity, why four flipped rectangle-corner bits may escape block parity, and why changing data bytes 40,50,60 to 41,49,60 escapes this checksum.

Answer and marking points
  • 10101100 contains four 1 bits, so its complete group has even parity.
  • Each affected row and column in the rectangle has two changed bits and retains its parity.
  • Both byte lists total 150 and therefore have checksum 150 modulo 256.
  • The checks can agree despite changed data, so passing them is not a guarantee of an error-free transfer.

Common error: Explain each failure mechanism rather than saying all checks are unreliable.

04

Lesson review

Summary

Validation

Test bounds, pattern, length, presence, lookup membership and a stated check-digit rule.

Entry verification

Compare with the source or compare two independent entries.

Byte and block parity

Count all 1 bits; row and column failures can locate one flipped bit.

Checksum

Calculate, send, recalculate and compare using the same algorithm.

Limits

Valid values can be false; agreeing checks can miss some errors.
