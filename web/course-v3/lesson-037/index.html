6.2.1

Validation and verification

Validation · does the entered value obey the rule?

Exam description

Validation checks data against specified rules to test whether it is reasonable or acceptable. It helps protect integrity by rejecting invalid entries; it does not establish that the data is true.

Exam evidence9618/13/O/N/23 · Q8(a), 2 marks · name and explain a method other than verification (QP p12; MS p8).

Verification · was the source copied accurately?

Exam description

Verification checks whether data has been copied or transferred accurately. It checks agreement with the source or with the checking information sent with the data.

Validation and verification compared

Two checks, two different questions
AspectValidationVerification
QuestionDoes the value satisfy the required rules?Does the copy agree with the source or checking information?
ExampleA mark must be from 0 to 75.Compare entered 64 with source 46.
Result for 64Pass: it is inside the range.Fail: it differs from 46.
MethodsRange, format, length, presence, existence, limit, check digit.Visual check, double entry, parity check, checksum.
LimitA plausible wrong value can pass.A faithfully copied wrong source can still be wrong.

Suppose the source itself incorrectly says 64 and the entry also says 64. The value can pass both checks. Neither proves that the source describes the real mark.

6.2.2

Seven methods of data validation

Range check

1 / 7Range check

Exam description

A range check tests whether a value lies between stated lower and upper bounds. For example, accept a mark only if 0 ≤ Mark ≤ 75.

Exam evidence9618/13/O/N/25 · Q7(e), 3 marks across three algorithms · identifying a range check (QP p14; MS p12).

Format check

2 / 7Format check

Exam description

A format check tests whether characters follow a specified pattern, for example two uppercase letters followed by four digits.

Exam evidence9618/13/M/J/23 · Q4(d)(i), 2 marks · applying a character pattern to a registration number (QP p8; MS p7).

Length check

3 / 7Length check

Exam description

A length check tests the number of characters. It does not by itself check which characters were entered.

Exam evidence9618/13/M/J/23 · Q4(d)(i), 2 marks · the required registration number has six characters (QP p8; MS p7).

Presence check

4 / 7Presence check

Exam description

A presence check ensures that a required field is not left blank.

Exam evidence9618/12/M/J/23 · Q2(c)(i), 2 marks · checking that the rider level is entered (QP p6; MS p4).

Existence check

5 / 7Existence check

Exam description

An existence check tests whether the entered value is found in a specified stored list or lookup, for example an existing student ID.

Exam evidence9618/12/M/J/23 · Q2(c)(i), 2 marks · RiderLevel must exist in the allowed set (QP p6; MS p4).

Limit check

6 / 7Limit check

Exam description

A limit check compares a value with one stated upper or lower bound. For example, reject an upload if its size exceeds 10 MiB. A range check has both bounds.

Check digit

7 / 7Check digit

Exam description

On entry, recalculate the expected check digit from the data digits and compare it with the supplied check digit. A mismatch detects an error; it does not reveal with certainty which digit was wrong.

Exam evidence9618/23/O/N/25 · Q6 uses a different check-digit rule, sum modulo 10 (QP p14). Its programming tasks are an extension, not a requirement for this diagram.

Exam description

The sender and receiver agree on even or odd parity. The sender adds a parity bit so that the total number of 1 bits has that parity. The receiver checks the complete group again; a mismatch indicates an error and can trigger retransmission.

Count the parity bit as well as the data bits. A parity byte check can detect an odd number of bit errors, but cannot locate the incorrect bit. An even number of bit errors can escape detection.

Exam evidence9618/11/M/J/24 · Q5(b), 5 marks · parity construction (QP p11; MS p6).9618/12/O/N/25 · Q6(c)(i), 1 mark · fill the parity bit (QP p11; MS p9).

Block parity · construct, locate and correct

Resolve this single-bit error
StepReasoning
LocateRow 2 has an odd count and column 5 has an odd count. Their intersection is the changed bit.
Correct under the single-error assumptionFlip row 2, column 5 from 1 to 0.
RecheckAll rows and columns now have even parity. The restored second row is 01100000.

Exam description

The sender adds a parity bit to each data row and calculates a parity byte for the columns. Both are sent with the data. The receiver checks rows and columns again. If exactly one bit changed, the failing row and column locate it at their intersection.

Correcting the intersection assumes one changed bit. Multiple errors can be ambiguous or undetected; four flipped corners of a rectangle preserve every affected row and column parity.

Exam evidence9618/12/O/N/25 · Q6(c)(ii), 1 mark · locate a changed bit (QP p11; MS p9).9618/13/M/J/24 · Q7(f)(i) · block parity as a transfer-verification method (QP p16; MS p9).

    The two checksum values differ, so an error is detected.

    COMPARE
    Transmitted checksum26
    Recalculated checksum27
    DecisionERROR DETECTED

    Reject the block or request retransmission. A checksum mismatch does not by itself identify the changed byte.

Exam description

The sender uses an algorithm to calculate a checksum from the data and sends both. The receiver applies the same algorithm to the received data and compares its result with the received checksum. Different results show an error; the receiver rejects the data or requests retransmission.

A matching checksum means this check detected no error. Different data may produce the same checksum. The sum-modulo-256 calculation shown here is a specified example, not the definition of every checksum.

1. Validate and verify a car registration number

Cambridge 9618/13 · May/June 2023 · 4(d)(i), 4(d)(ii), 4(d)(iii) · 5 marks

Original question
Reading the question — teacher guidance

Use the given registration pattern. Presence checking is already supplied, so name and describe two other validation methods. Then give two verification methods and explain the final limitation.

Solution / model answer — teacher-written
PartModel answer
4(d)(i)Length check: exactly six characters. Format check: one letter, three digits, then two letters.
4(d)(ii)Visual check: compare the entered registration with the original document. Double entry: enter the registration twice and let the computer compare the two entries.
4(d)(iii)The source document can contain the wrong registration for the car even though it has the required format; copying that source correctly does not make it true.
Official mark scheme
Why this earns marks — teacher explanation

Two validation descriptions earn up to two marks, the two verification descriptions earn two marks, and the source-data limitation earns one mark. The scheme also allows an alphanumeric type check for the validation part.

Common mistakes — teacher analysis

Do not use presence as one of the two other checks. Verification compares against a source or a second entry; it does not apply the registration format. Passing both checks does not prove that the source identified the correct car.

4. Calculate a parity bit and locate one altered bit

Cambridge 9618/12 · October/November 2025 · 6(c)(i), 6(c)(ii) · 2 marks

Original question
Reading the question — teacher guidance

The supplied rule is even parity, with the rightmost bit reserved for parity. In the block question, the paper explicitly states that one data bit has changed.

Solution / model answer — teacher-written

6(c)(i): The seven data bits 0101110 contain four 1s, so the missing parity bit is 0. The completed byte is 01011100.

6(c)(ii): Row 2 has odd parity, and column 5 from the left has odd parity when the received parity byte is included. Circle the 0 at row 2, column 5. Under the stated single-bit-error condition, changing it to 1 restores even parity.

Original question · Cambridge 9618/11

5. Explain a sender-to-receiver checksum check

Cambridge 9618/11 · May/June 2025 · 7(c) · 3 marks

Selected parts: 7(c) [3].

Original question
Reading the question — teacher guidance

Explain how the sender and receiver use the same checksum algorithm. No particular arithmetic algorithm or numerical data is supplied in this question.

Solution / model answer — teacher-written

The sender applies an agreed algorithm to the data to produce a checksum and sends the checksum with the data.

The receiver applies the same algorithm to the received data and compares its result with the checksum that was sent. A mismatch indicates a detected transmission error; a match passes this checksum check.

Official mark scheme
Why this earns marks — teacher explanation

The official scheme awards one mark per listed point, up to three, covering calculation, sending, recalculation and matching. The phrase verified refers to passing this check.

Common mistakes — teacher analysis

The receiver must compare with the transmitted checksum, not replace it with a newly generated value. Matching checksums do not prove that all possible errors were absent. Do not invent a required modulo rule when none is supplied.

Original question · Cambridge 9618/13

1. Describe two transmission-verification methods

Cambridge 9618/13 · May/June 2024 · 7(f)(i) · 4 marks

Selected parts: 7(f)(i) [4].

Original question
Reading the question — teacher guidance

The robot-to-computer link transfers data. Give two suitable methods and pair each name with its own detection process.

Solution / model answer — teacher-written
MethodDescription
Parity byte checkThe sender includes a parity bit so the byte has the agreed odd or even number of 1s. The receiver checks that parity; a mismatch indicates an error.
ChecksumThe sender calculates a value from the data and sends it with the data. The receiver repeats the same calculation and compares the result with the received checksum; a mismatch indicates an error.
Official mark scheme
Why this earns marks — teacher explanation

Each method-and-description pair can earn two marks, four in total. The official scheme also describes parity block checking as another valid method.

Common mistakes — teacher analysis

A matching checksum or parity does not guarantee that no error occurred: some changes preserve the check value. Encryption is a security mechanism, not a replacement for either requested verification description.

Question 1 · Command word: Explain3 teacher marks

A source form says 28 but 82 is entered. The allowed range is 0 to 100. Explain the validation result and the result of comparison with the source.

S6.07.A01S6.07.A09
Answer and checking points — teacher-written
  1. 82 satisfies the range, so that validation check passes.
  2. 82 differs from 28, so source verification detects a copying error.
  3. This shows that a valid value need not be the true or intended value.

Common error: Keep rule compliance separate from faithful copying.

Question 2 · Command word: State3 teacher marks

State which values pass -10 <= Temperature <= 40 from -11, -10, 40 and 41. Then apply the single limit Temperature >= -10 to the same values and explain the difference.

S6.07.A02S6.07.A07
Answer and checking points — teacher-written
  1. The range accepts -10 and 40 only.
  2. The limit accepts -10, 40 and 41.
  3. The range has an upper bound as well as a lower bound; the stated limit has only a lower bound.

Common error: Include the endpoints where equality is allowed.

Question 3 · Command word: State3 teacher marks

A code must contain exactly six characters in the format two uppercase letters followed by four digits. State the length and format result for AB1234, 123456 and AB123.

S6.07.A03S6.07.A04
Answer and checking points — teacher-written
  1. AB1234 passes length and format.
  2. 123456 passes length but fails format.
  3. AB123 fails both the length and the specified format.

Common error: Assess each check independently.

Question 4 · Command word: State4 teacher marks

The stored product IDs are P10 and P20. Apply presence and existence checks to a blank entry, P20 and P99, and state what each check tests.

S6.07.A05S6.07.A06
Answer and checking points — teacher-written
  1. Presence tests for a non-blank required entry; the blank fails.
  2. Existence tests for membership in the stored product lookup.
  3. P20 is present and exists.
  4. P99 is present but does not exist in that lookup.

Common error: A supplied value can fail existence without failing presence.

Question 5 · Command word: Calculate3 teacher marks

Calculate the check digit for data digits 5834 using weights 3,1,3,1. Choose the digit that makes the weighted total plus that digit a multiple of 10. State whether code 58345 passes.

S6.07.A08
Answer and checking points — teacher-written
  1. The products are 15, 8, 9 and 4.
  2. Their total is 36, so the check digit is 4.
  3. 58345 fails because its supplied check digit 5 differs from the calculated 4.

Common error: The weight rule applies to the four data digits, not the appended check digit.

Question 6 · Command word: Describe3 teacher marks

An original reference is KX304. A visual check sees KX340 entered. A separate double-entry attempt produces KX304 and KX340. Describe how each check detects an error and how it should be resolved.

S6.08.A01S6.08.A02
Answer and checking points — teacher-written
  1. The visual check compares the entered reference with the original and spots the transposed digits.
  2. The computer compares the two independently entered strings and flags their mismatch.
  3. Consult the original source, correct the entry and compare again.

Common error: Do not choose the first entry as correct without checking the source.

Question 7 · Command word: Calculate3 teacher marks

Calculate the parity bit for seven data bits 1100101 under even parity, then under odd parity. Explain why flipping two bits may evade a byte parity check.

S6.08.A03S6.08.A05
Answer and checking points — teacher-written
  1. The data has four 1 bits, so the even-parity bit is 0.
  2. The odd-parity bit is 1, giving five 1 bits in total.
  3. Two flips change the count by an even amount, preserving its odd/even parity.

Common error: Count the parity bit in the total.

Question 8 · Command word: Calculate5 teacher marks

Calculate the checking bits to complete an even-parity block from these three seven-bit data rows: 1110000, 0101010, 0011001. Append one parity bit at the right of each row, then calculate the transmitted parity byte. Only the second complete row changes during transmission to 01011101. Identify the failed row and column, correct the bit under a single-bit error assumption, and state the final complete block.

S6.08.A03
Answer and checking points — teacher-written
  1. All three data rows have three 1s, so each row-parity bit is 1. The complete rows are 11100001, 01010101 and 00110011.
  2. The parity byte is 10000111; it is sent with the complete data rows.
  3. Only row 2 and column 5 fail even parity, locating the single changed bit at their intersection.
  4. Change that bit from 1 to 0. The final block is 11100001 / 01010101 / 00110011 / 10000111.
  5. All final row counts are 4; column counts are 2,2,2,2,0,2,2,4. All are even, confirming the recheck.

Common error: Calculate from the data bits first. Do not silently generate replacement column parity from the corrupted block.

Question 9 · Command word: Calculate3 teacher marks

Calculate a checksum for data bytes 200,45,30 using sum modulo 256. If the receiver gets 200,46,30 with the original checksum, calculate its check value and state the decision.

S6.08.A04
Answer and checking points — teacher-written
  1. The original sum is 275, giving checksum 19.
  2. The received sum is 276, giving checksum 20.
  3. 20 differs from transmitted 19, so reject the block or request retransmission.

Common error: Apply the same modulo rule at both ends.

Question 10 · Command word: Explain2 teacher marks

Explain why both identical double-entry values and matching transfer checksums can still occur when the information is wrong.

S6.08.A05
Answer and checking points — teacher-written
  1. The operator can repeat the same incorrect entry, producing identical copies.
  2. Different data blocks can produce the same checksum, so a changed block may escape detection.

Common error: Agreement is evidence from a particular check, not proof of truth.

Question 11 · Command word: Identify5 teacher marks

A form requires CustomerID to be non-blank, in the format one uppercase letter followed by two digits, and present in {C10,C20}; BookingCode must have exactly four digits; Age is an integer from 5 to 18 inclusive. The source form says C20 / 0042 / 14, but the submitted record is C99 / 0042 / 12. Identify the checks, state which validation checks pass or fail, compare the submission with the source, and give the corrected accepted record.

S6.07.A02S6.07.A03S6.07.A04S6.07.A05S6.07.A06S6.07.A09S6.08.A01
Answer and checking points — teacher-written
  1. CustomerID uses presence, format and existence checks. C99 passes presence and format but fails existence in the supplied customer set.
  2. 0042 passes the four-character length and digit-format requirements; preserve the leading zeros.
  3. 12 passes the age range because 5 <= 12 <= 18; this does not prove it is the source age.
