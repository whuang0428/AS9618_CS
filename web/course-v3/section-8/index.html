Section 8 · Databases

Build a library that remembers.

Start with one borrowing record. Discover how related tables keep facts organised, then build and query a database yourself.

Follow these modules in order. Some modules revisit a familiar topic with a new question. Keep time for prediction, discussion and practice.

Suggested 45-minute sessions

These stopping points include explanations, experiments and practice. Take more time when a check shows that an idea needs another example.

  1. Session 1 · 45 minutes suggested

    Why the library needs shared facts

    Predict a failed repeated update, compare the relational mechanism and explain the corresponding past-paper benefits.

    • Why does the library need shared records? →
  2. Session 2 · 45 minutes suggested

    What one row represents

    Identify entities, records and fields; distinguish a title, a physical copy and a borrowing event.

    • Read a table as facts about things and events →
  3. Session 3 · 45 minutes suggested

    Identify people and events

    Test candidate-key minimality, secondary retrieval and the difference between a loan identity and a member reference.

    • Choose a key that really identifies one record →
    • Connect a loan without confusing its two identifiers →
  4. Session 4 · 45 minutes suggested

    Accept and reject references

    Predict independent constraint outcomes, explain nullable versus required references and apply referential integrity in the sourced question.

    • Reject a loan for a member who does not exist →
  5. Session 5 · 45 minutes suggested

    Read relationships in both directions

    Compare one-to-one, one-to-many and many-to-many rules; build the membership association and attempt the keys question.

    • Read every relationship in both directions →
  6. Session 6 · 45 minutes suggested

    Draw and test the library ER design

    Separate Book, Copy, Member and Loan; test new members and repeated events, then transfer to the ER past-paper task.

    • Draw a design and test it with real events →
  7. Session 7 · 45 minutes suggested

    Make individual order items addressable

    Expand the full product lists into three 1NF rows and justify the composite key under explicit rules.

    • Give each order item an addressable row →
  8. Session 8 · 45 minutes suggested

    Remove partial dependencies

    Assign each order fact to its determinant, create the 2NF relations and explain the three modification anomalies.

    • Move facts that depend on only part of a key →
  9. Session 9 · 45 minutes suggested

    Remove transitive dependencies

    Separate customer facts, retain references and practise explaining a transitive dependency in a different table.

    • Separate a customer fact from an order fact →
  10. Session 10 · 45 minutes suggested

    Judge and reconstruct a complete design

    Account for every field, reconstruct all three order lines, test changed pricing rules and attempt the two normalised-design questions.

    • Prove that the new tables still tell the whole story →
  11. Session 11 · 45 minutes suggested

    Describe the structure and its metadata

    Connect model, logical schema and dictionary; classify changes and apply the metadata past-paper question.

    • Turn the library model into a logical schema →
    • Read the data about the data →
  12. Session 12 · 45 minutes suggested

    Build tools and read SQL requests

    Explain forms and reports, distinguish DDL from DML and read identifiers, literal values and exact operators.

    • Build forms and reports from defined fields →
    • Separate changing a structure from using its records →
    • Read a statement before predicting its effect →
  13. Session 13 · 45 minutes suggested

    Separate integrity and permission

    Run independent request attempts, compare role changes with invalid values and apply the access-rights question.

    • Check valid values before accepting a change →
    • Decide who may perform each operation →
  14. Session 14 · 45 minutes suggested

    Recover a known database state

    Trace a backup timeline, predict the recovered records and compare backup-only recovery with a supported later log.

    • Recover a known consistent state →
  15. Session 15 · 45 minutes suggested

    Retrieve precisely chosen columns

    Use guided SELECT controls, inspect the unchanged source, then edit and independently write a simple field selection.

    • Choose the information a result should show →
  16. Session 16 · 45 minutes suggested

    Filter using complete conditions

    Trace AND, OR, boundaries and parentheses, then write conditions that exclude near-matching records.

    • Test each row against a precise condition →
  17. Session 17 · 45 minutes suggested

    Sort results and test ties

    Predict ASC and DESC results, test a second sort field and distinguish arranging rows from filtering them.

    • Arrange the result and resolve ties →
  18. Session 18 · 45 minutes suggested

    Calculate over the selected records

    Compute SUM, COUNT and AVG by hand, compare NULL with zero and verify queries over changed selections.

    • Calculate a total, count and mean →
  19. Session 19 · 45 minutes suggested

    Produce one summary per group

    Build member groups, filter before counting and explain missing groups and ambiguous non-grouped fields.

    • Make one summary for each member →
  20. Session 20 · 45 minutes suggested

    Match two tables and inspect every pair

    Trace each Member–Loan match, explain repeated and absent names, write an outstanding-loan JOIN and attempt the first JOIN paper.

    • Match a loan with its member →
  21. Session 21 · 45 minutes suggested

    Combine matching and grouped summaries

    Predict complete summaries, change a source record, keep same-name members separate and attempt the grouped JOIN question.

    • Build a complete two-table summary →
  22. Session 22 · 45 minutes suggested

    Explain access paths and query processing

    Operate the simplified index model, account for maintenance and explain a query from checking through result production.

    • Find records through an index →
    • Follow a request from SQL to its result →
  23. Session 23 · 45 minutes suggested

    Define a database and suitable fields

    Separate database creation from table creation, choose all seven syllabus types and inspect a real DDL sandbox definition.

    • Create the named database before its tables →
    • Choose types that match the facts →
  24. Session 24 · 45 minutes suggested

    Declare keys and change a definition

    Write primary and foreign keys, account for required values and existing rows, then attempt the sourced CREATE and ALTER parts.

    • Declare primary and foreign keys in SQL →
    • Change a definition while preserving its records →
  25. Session 25 · 45 minutes suggested

    Add and update records precisely

    Match insertion field/value order, predict repeated insertion and compare unique-loan with shared-member update conditions.

    • Add a new record in the defined field order →
    • Change a value without losing the event →
  26. Session 26 · 45 minutes suggested

    Remove records and verify the final state

    Preview deletion targets, distinguish deleting from updating and rehearse the maintenance operations on a reset fixture.

    • Remove the intended record and explain the whole solution →
  27. Session 27 · 45 minutes suggested

    Transfer the whole method independently

    Use a fresh library, shop or booking problem: justify design and constraints, predict and write a two-table query, choose the correct maintenance operation, then explain the evidence.

    • Prove that the new tables still tell the whole story →
    • Build a complete two-table summary →
    • Change a value without losing the event →
    • Remove the intended record and explain the whole solution →
