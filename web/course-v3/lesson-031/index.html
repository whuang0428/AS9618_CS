Start with a question

Would you give the same recommendation to a learner trying frequent edits and a team distributing a finished native program?

Team A keeps changing a small usable section and checking intermediate values. Team B has completed a program that will run hourly on known compatible computers; they will keep the source internally. Link each recommendation to one of those conditions.

Explain

Explanation · 1 / 4

Compare preparation and feedback

Native compilation requires a successful build before that built code runs. A suitable interpreting environment can let a programmer try supported sections and see feedback as execution proceeds. This can help an edit, test and correct cycle. The section still needs to be executable in the chosen environment; arbitrary unfinished text cannot simply be run.

Explanation · 2 / 4

Compare repeated execution and delivery

A completed native executable can be reused without retranslating the original source for each run and can be distributed without that source. Interpretation requires a suitable execution environment and may repeat translation-related work. These are reasons tied to the taught models, not guaranteed speed measurements for all language implementations.

Explanation · 3 / 4

Compare what happens after a correction

A correction to compiled source needs a successful rebuild and distribution of the corrected executable. An interpreting environment can execute the corrected source it is given. In either case, a correction needs testing against the expected result, and the users must receive the intended version.

Explanation · 4 / 4

Build an explanation from the requirement

Use “because” to join requirement, mechanism and benefit. For Team A, prompt feedback on usable sections supports frequent corrections. For Team B, a suitable compiled executable can be repeatedly run and supplied without source. A compiler can also support debugging, and an interpreter is not always the best choice during development; the stated reasons decide whether a recommendation is justified.

Original question · Cambridge 9618/12

1. Use translation tools at different development stages

Cambridge 9618/12 · October/November 2025 · 10(a) · 4 marks

Selected parts: 10(a) [4].

Hint — reading the question

The question supplies the order: interpreter first, compiler later. Explain what the programmer gains at each stage.

Reasoning and model answer — teacher-written

While coding, the programmer can use an interpreter to test and debug partially completed code, observe errors and try corrections promptly.

After completing the program, the programmer can compile it to produce an executable. That executable can be distributed without supplying the source and run repeatedly without re-interpreting the source each time.

Official mark scheme
Why this earns marks — teacher explanation

At most two marks come from the interpreter section and at most two from the compiler section. Four generic compiler advantages do not answer the whole question.

Common mistakes — teacher analysis

Do not say the interpreter produces a saved executable as its normal result. The compiler does not prove that a syntactically correct program fulfils the requirements.

Original question · Cambridge 9618/12

2. Justify a translator choice during development

Cambridge 9618/12 · May/June 2023 · 7(b) · 3 marks

Selected parts: 7(b) [3].

Hint — reading the question

The team is still writing the program. State a choice, then give reasons tied to testing and correction at that stage.

Reasoning and model answer — teacher-written

An interpreter is suitable. The developer can test incomplete sections, rather than wait for the whole program to be finished. Changes can be tried promptly so their effects are visible, supporting debugging as each section is developed.

Official mark scheme
Why this earns marks — teacher explanation

The choice itself earns no mark. Up to three marks are for justification. The scheme also accepts a justified compiler choice, such as producing an executable for repeated tests without recompiling unchanged code. This is not a question with only one creditworthy label.

Common mistakes — teacher analysis

“Interpreter because it is easier” has no technical support. Do not reject every compiler answer when the official scheme explicitly allows a supported alternative.

System software · Concept 02

Compile Java source; run bytecode with a JVM

Observe

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Start with a question

If two computers have different physical processors, how can both run a suitable Hello.class file?

Hello.java is readable Java source. Compiling it produces Hello.class. A second computer has a compatible Java runtime but no Java compiler. Follow which file and tool each stage needs.

Recall

Use what you already know

Bytecode and a virtual machine

Bytecode is an intermediate instruction form defined for a virtual machine. A virtual machine here is software that provides an execution environment for those instructions. A compatible host implementation carries out that work on the actual computer.

Explain

Explanation · 1 / 5

Start with a complete source file

Save the following as Hello.java. Its public class is named Hello, main is the starting method and the print statement displays the quoted message. The surrounding Java syntax makes a complete runnable example; this is Java source, not Cambridge pseudocode. Development requires tools providing javac and java, such as a JDK.

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Explanation · 2 / 5

Compile to a class file

The command javac Hello.java invokes the Java compiler. It translates the source into bytecode stored in Hello.class. The bytecode targets the Java Virtual Machine, or JVM; it is not universal native machine code understood directly by every physical CPU.

Explanation · 3 / 5

Execute through a compatible JVM

The command java Hello launches the class through a suitable runtime. The JVM provides the host-specific execution of the bytecode. This illustrates partial compilation followed by interpretation; real JVMs may also compile frequently executed bytecode just in time for the host. The second computer needs a compatible runtime to run this already built class, but it does not need javac merely to perform that run.

Explanation · 4 / 5

Track source and bytecode after an edit

Change the message to Hello, Class! and save the source. The old class file still contains the earlier bytecode. Running java Hello before recompiling therefore displays Hello, World! A successful javac Hello.java updates the class file; the next run displays Hello, Class!

Explanation · 5 / 5

Locate a failure at the correct stage

If javac is missing, the development tools are unavailable. If the destination lacks a compatible JVM, it cannot execute this bytecode by the stated route. Producing another class file does not install the missing runtime. Use java Hello without the .class extension and run from an environment that can locate the class.

Build, edit, rebuild and move

Use a development environment with javac and java, and save the complete file as Hello.java.

Run javac Hello.java, then java Hello. The output is Hello, World!.

Work together · 2 / 3

Work together · 3 / 3

Run the artifact elsewhere

Copy Hello.class to a host with a compatible runtime and launch java Hello there. The runtime supplies the execution route appropriate to that host.

Java source → compiler → bytecode → compatible JVM → execution on the host.

Original question · Cambridge 9618/11

1. Explain why a language can combine compilation and interpretation

Cambridge 9618/11 · October/November 2023 · 6(b) · 1 marks

Selected parts: 6(b) [1].

Teacher solution and explanation

Give one reason for combining the two stages. Use the Java source-to-bytecode-to-JVM example to explain portability.

The partially compiled program can run on different platforms because each platform’s compatible runtime interprets the intermediate code.

For Java, the same bytecode can be executed by compatible JVM implementations on different platforms. Each host needs a suitable JVM; the bytecode is not the native machine code of every processor.

This part has a one-mark maximum. Portability through interpretation on the target platform is one accepted reason. The additional Java explanation makes the mechanism clear; it does not earn an extra mark.

“It runs on any computer” leaves out the required compatible runtime. Changing the source also requires rebuilding the bytecode before the new version can run.

Connect

Keep this idea

javac compiles Java source to bytecode. A compatible JVM executes that bytecode on its host, supporting portability across suitable runtimes.

An IDE brings editing, translation, execution and debugging tools into one environment so the developer can work through this cycle.

Check a common misunderstanding

Editing .java does not update .class, and bytecode is not the same native CPU instruction file for every platform.

Teacher-written consolidation. Attempt these tasks after studying this topic’s concepts.

Question 1 · Command word: Suggest4 teacher marks

Suggest a translation approach for testing a partly written high-level calculation with frequent edits, and another for distributing a finished native program without source. Justify both choices.

S5.05.A02
Answer and checking points — teacher-written
  1. Interpretation is suitable for the developing calculation.
  2. Immediate feedback during partial execution supports correction and retesting.
  3. Compilation is suitable for the specified native distribution.
  4. Its completed executable can be supplied without the original source code.

Common error: Give a reason tied to each requirement, not a preference without evidence.

Question 2 · Command word: Describe4 teacher marks

Describe what javac produces from Hello.java and how a compatible destination executes it. A second computer can run an existing Hello.class but cannot find javac. Explain why these observations are consistent, and why bytecode is not a universal physical-processor instruction set.

S5.06.A01
Answer and checking points — teacher-written
  1. javac produces Hello.class containing bytecode for the JVM.
  2. A compatible Java runtime on the destination executes that bytecode through its JVM.
  3. Running an existing class does not require the source compiler; the second computer may have suitable runtime support without javac available.
  4. Bytecode targets a virtual machine, and its implementation must suit the host; the physical CPU does not directly recognise universal JVM instructions.

Common error: A missing compiler and a missing execution environment are different problems.

Question 3 · Command word: Predict3 teacher marks

Hello.class currently prints Hello, World! The saved Hello.java has been edited to print Hello, Class! Predict the result of java Hello before recompilation. Give the two commands needed to obtain the edited output, and explain why an unsuccessful rebuild would not establish that the class has been updated.

S5.06.A01
Answer and checking points — teacher-written
  1. java Hello runs the old class and prints Hello, World! before a successful rebuild.
  2. Run javac Hello.java successfully, then java Hello; the updated output is Hello, Class!
  3. A failed build does not supply evidence of a valid updated class; identify and run the successfully built version.

Common error: The run command names the class Hello, not Hello.class.

Question 4 · Command word: Compare4 teacher marks

Compare compilation and interpretation in terms of repeated execution and the work needed after a source correction.

S5.05.A01
Answer and checking points — teacher-written
  1. A compiled build can be reused without translating its original source on each run.
  2. Interpretation can repeat translation-related work during successive executions.
  3. A changed compiled source version needs a new successful build.
  4. An interpreting environment can execute the corrected source without first producing a separate complete native executable.

Common error: Compare the same factors for both approaches.
