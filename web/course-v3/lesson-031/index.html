Choosing a translator and understanding Java translation

Justify compilation or interpretation from a requirement, then follow Java source through bytecode to JVM execution.

Why can a development workflow use more than one translation approach?

Before you start

Which translator accepts assembly source? Does that answer decide how to run every high-level language?

Check your answer

Assembly needs an assembler; the high-level language and development requirements determine its translation tools.

Core explanation

Choose by the required workflow rather than calling one translator universally better. An interpreter can provide immediate feedback while individual statements or incomplete program sections are tested. The environment must still support the source language and the required operations.

A native compiled executable avoids translating the original source on every run and can be distributed without that source. It can suit repeated execution or delivery to end users. A separate build is needed after source changes, and the produced native code must suit the target platform.

Interpretation can add execution overhead and normally requires the interpreter and an executable form of the program's source or intermediate code to remain available. Real tools may combine techniques, so a justified exam answer links the specified translation model to a concrete requirement instead of making an unconditional speed claim.

Worked example · Choose for two phases of a project

  1. Early requirement

    A learner is investigating a partly completed calculation and frequently changing one statement.

  2. Development choice

    An interpreter can give feedback at the current execution point, helping the learner correct and retest the section.

  3. Delivery requirement

    The completed native program will run thousands of times and its source must not be supplied.

  4. Delivery choice

    Compilation can provide a reusable executable; build an appropriate version for the users' platform.

Common misconception

An advantage earns a justification only when it addresses the stated requirement; translation success does not establish logical correctness.

Check your understanding

Why is 'a compiler is always better' an inadequate justification?

Check your answer

It ignores the workload, debugging needs, delivery constraints and target environment.

Java source, bytecode and the JVM

S5.06.A01

Visual overview

Two translation stages, one program

  1. Hello.javaHuman-readable Java source
  2. javacCompile to Hello.class bytecode
  3. Compatible host JVMInterpret bytecode and/or JIT-compile executed code
  4. Host processorCarries out the operations on its own hardware

Core explanation

Java illustrates partial compilation and partial interpretation. The Java compiler javac translates .java source into .class files containing bytecode. Bytecode targets the Java Virtual Machine (JVM), not one particular physical processor's instruction set.

A compatible JVM on the host executes that bytecode. It may interpret instructions and use a just-in-time (JIT) compiler for frequently executed code. The same suitable bytecode can run on different platforms with compatible JVMs, although platform-specific native dependencies can limit portability.

The source-to-bytecode build and the host execution are distinct stages. Installing a JVM does not by itself translate an edited .java file, and copying a .class file does not make it direct universal CPU machine code.

Worked example · A complete console program

  1. Save as Hello.java
    public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
  2. Compile and run
    javac Hello.java
java Hello
  3. Observe

    The console displays Hello, World!

  4. Move to another platform

    Copy Hello.class to a machine with a compatible JVM and run java Hello there; do not assume its CPU directly recognises bytecode.

Common misconception

A .class file contains JVM bytecode; it is not the same native instruction file for every processor.

Check your understanding

Which part must match the host platform: the JVM implementation or the Java source text?

Check your answer

The JVM implementation must run on that host. Suitable bytecode can be shared between compatible JVMs.

Practice questions

Question 1 · Command word: Compare4 marks

Compare compilation and interpretation in terms of repeated execution and the work needed after a source correction.

S5.05.A01
Answer and marking points
  1. A compiled build can be reused without translating its original source on each run.
  2. Interpretation can repeat translation-related work during successive executions.
  3. A changed compiled source version needs a new successful build.
  4. An interpreting environment can execute the corrected source without first producing a separate complete native executable.

Common error: Compare the same factors for both approaches.

Question 2 · Command word: Suggest4 marks

Suggest a translation approach for testing a partly written high-level calculation with frequent edits, and another for distributing a finished native program without source. Justify both choices.

S5.05.A02
Answer and marking points
  1. Interpretation is suitable for the developing calculation.
  2. Immediate feedback during partial execution supports correction and retesting.
  3. Compilation is suitable for the specified native distribution.
  4. Its completed executable can be supplied without the original source code.

Common error: Give a reason tied to each requirement, not a preference without evidence.

Question 3 · Command word: Describe3 marks

Describe the role of javac and the JVM when running a Java console program. Explain why bytecode is not a universal physical-processor instruction set.

S5.06.A01
Answer and marking points
  1. javac translates the Java source into bytecode in class files.
  2. The JVM carries out bytecode using interpretation and/or just-in-time compilation.
  3. Bytecode is defined for the virtual machine; each host needs an implementation suited to its own system.

Common error: Do not replace the two stages with a claim that javac always emits native code for one CPU.

Question 1 · Command word: Justify · 3 marks

A company will run a completed native report program every hour on identical computers. It will keep the source private. Justify compiling it for distribution and explain one disadvantage when a calculation in the source is corrected.

Answer and marking points
  • The scheduled jobs can reuse one suitable executable without translating the original source at every launch.
  • The company can distribute that executable while retaining its source internally.
  • The correction requires rebuilding and deploying the corrected executable to the affected computers.

Common error: Do not claim that editing the private source automatically updates installed executables.

Question 2 · Command word: Explain · 3 marks

A learner wants to run a partly written script, observe the first incorrect value, edit it and try again. Explain why interpretation can suit this work and give one execution dependency and one possible performance drawback.

Answer and marking points
  • The learner can obtain feedback as the available statements execute, without first building a complete native program.
  • The interpreting environment must be available to execute the script.
  • Repeated interpretation-related work can add overhead compared with reusing a suitable compiled build.

Common error: The dependency and overhead are drawbacks of the specified workflow, not proof that interpreters are defective compilers.

Question 3 · Command word: Explain · 4 marks

A class file built from a simple Java console program runs on a school computer but a second computer has no JVM installed. Explain the missing requirement, how a suitable JVM can execute the class file, and why recompiling to bytecode alone does not solve the missing-runtime problem.

Answer and marking points
  • The second computer needs a compatible JVM implementation for its platform.
  • That JVM can interpret the class file's bytecode or JIT-compile parts for the host.
  • The physical CPU does not directly execute the JVM instruction set just because a class file exists.
  • Rebuilding another bytecode file still leaves the required host execution environment absent.

Common error: Distinguish a compilation problem from a missing execution environment.

Lesson review

Summary

Make a justified choice

Match feedback, repeated execution, distribution and platform requirements to the translation approach.

Expect tradeoffs

A reusable native build needs rebuilding after changes; interpretation requires its execution environment.

Java compilation

javac produces class-file bytecode from source.

Java execution

A compatible JVM interprets bytecode and may JIT-compile frequently executed code.
