Program a booking system · Concept 09

Take one of two paths

Observe

Two alternatives

  • If the request fits, display "Seats available".
  • Otherwise, display "Not enough seats".
  • Assume Seats is a positive integer in this example.

Look, then discuss

What should the desk display when a request needs more seats than are available?

There are four seats left. Compare a request for three with a request for five. In each run, choose exactly one message.

Recall

Recall a Boolean condition

Seats <= Available evaluates to TRUE or FALSE without changing either variable. IF uses that result to choose the next statements.

Explain

Explanation · 1 / 3

Write the TRUE action after THEN

IF Seats <= Available THEN starts a decision. If the expression is TRUE, execute its indented block. With no ELSE, a FALSE result simply skips that block.

Explanation · 2 / 3

Use ELSE for the alternative

The ELSE block runs only when the same condition is FALSE. One IF/ELSE chooses exactly one branch, so it cannot display both messages in a single execution.

Explanation · 3 / 3

Close the decision before continuing

ENDIF marks where both paths rejoin. Statements after ENDIF run whichever branch was chosen.

DECLARE Seats, Available : INTEGER
Available <- 4
INPUT Seats
IF Seats <= Available THEN
    OUTPUT "Seats available"
ELSE
    OUTPUT "Not enough seats"
ENDIF
OUTPUT "Check complete"

Work together

Trace both paths and their shared continuation

Run the program once with 3 and once with 5.

Work together · 1 / 2

Request three seats

3 <= 4 is TRUE. Display Seats available, skip ELSE, then display Check complete.

Work together · 2 / 2

Request five seats

5 <= 4 is FALSE. Skip the THEN output, display Not enough seats, then display Check complete.

A trace follows only the selected branch, then continues after ENDIF.

Check

Try it yourself · Teacher-written

What is displayed for Seats 4? What happens if <= is replaced with <?

Check your reasoning

With <= the exact-fit request displays Seats available, then Check complete. With < it incorrectly displays Not enough seats, then Check complete.

Connect

Keep this idea

IF/ELSE chooses between alternatives; ENDIF joins their paths.

A second rule may matter only after the first has succeeded. Place that decision inside the appropriate branch.

Observe

Seats fit?Paid?Outcome

Look, then discuss

Should payment confirmation matter when no seats are available?

The desk first checks availability. If the request fits, it checks payment; otherwise it reports a lack of seats without entering the payment branch.

Recall

Recall a branch

A block inside a branch is executed only if that branch is reached. Each IF has its own matching ENDIF; indentation makes the relationships visible.

Explain

Explanation · 1 / 3

Put the first restriction outside

Seats <= Available determines whether the payment decision is reached. The outer FALSE branch handles the failure immediately.

Explanation · 2 / 3

Nest the payment decision in the TRUE branch

Inside THEN, IF Paid selects Confirmed or Payment needed. Its ENDIF closes the inner decision before ELSE introduces the outer false branch. The experiment offers another nested rule: first reject Seats < 1, then check whether the positive request exceeds Available. Its three outcomes are invalid quantity, insufficient seats or a confirmed request.

Explanation · 3 / 3

Distinguish nesting from independent decisions

Two separate IF statements are tested independently and may both execute. An exclusive classification should use appropriate IF/ELSE branches rather than two overlapping tests.

DECLARE Seats, Available : INTEGER
DECLARE Paid : BOOLEAN
Available <- 4
INPUT Seats
INPUT Paid
IF Seats <= Available THEN
    IF Paid THEN
        OUTPUT "Confirmed"
    ELSE
        OUTPUT "Payment needed"
    ENDIF
ELSE
    OUTPUT "Not enough seats"
ENDIF

Work together

Follow the outer decision before the inner one

Use the complete program with (Seats, Paid) equal to (5, TRUE), (4, FALSE) and (3, TRUE).

Work together · 1 / 2

Trace the paths

The outputs are Not enough seats, Payment needed and Confirmed respectively. In the first run, Paid has been input but its inner condition is not evaluated.

Work together · 2 / 2

Explain an overlapping classification

IF Seats >= 3 followed by IF Seats >= 5 executes both blocks for Seats 5. If only one classification is required, test the larger threshold first and put the other test in its ELSE branch.

Use the structure to express which decisions depend on earlier decisions.

Program a booking system · Concept 11

Choose a menu action with CASE

Observe

Booking menu

ChoiceAction
1New booking
2View register
Anything elseInvalid option

Look, then discuss

How can one menu value select exactly one action?

The booking menu offers 1 for a new booking and 2 for viewing the register. A value such as 0 must produce a defined response.

Recall

Recall exclusive alternatives

An IF/ELSE follows one selected branch. CASE similarly selects an alternative based on one identifier, rather than treating every label as an independent IF.

Explain

Explanation · 1 / 3

Name the identifier after CASE OF

Write CASE OF Choice, put each label before a colon, and close with ENDCASE. There is no break statement in Cambridge pseudocode.

Explanation · 2 / 3

Provide a response for unmatched values

OTHERWISE supplies the default branch. A range label such as 1 TO 5 includes both endpoints. Prefer clear, non-overlapping intended alternatives.

DECLARE Choice : INTEGER
INPUT Choice
CASE OF Choice
    1 : OUTPUT "New booking"
    2 : OUTPUT "View register"
    OTHERWISE : OUTPUT "Invalid option"
ENDCASE

Explanation · 3 / 3

Check the order when reading overlapping supplied clauses

If a supplied CASE first handles values below 30, a later clause for values below 20 is unreachable: every such value already matched the earlier clause. If all values are covered, OTHERWISE is also unreachable. Follow the original code rather than silently repairing it.

Work together

Explain both a working menu and an unreachable clause

First input Choice 2. Then consider ordered ranges: below 30; below 20; 30 to 40 inclusive; above 40.

Work together · 1 / 2

Trace the menu

Choice 2 matches its label and displays View register. OTHERWISE is skipped.

Work together · 2 / 2

Test a value in the narrower range

15 is below 20 but is also below 30, so the earlier clause is selected. Values below 30, 30 through 40 and above 40 already cover all possibilities, leaving none for OTHERWISE.

A branch is reachable only if some permitted input reaches it after the preceding alternatives have been considered.

Check

Try it yourself · Teacher-written

For CASE labels 1 TO 5 and 6 TO 7 followed by OTHERWISE, which branch receives 5, 7 and 8?

Check your reasoning

5 selects the first range; 7 selects the second; 8 selects OTHERWISE. Both range endpoints are included.

Original question · Cambridge 9618/21

1. Find unreachable CASE assignments

Cambridge 9618/21 · October/November 2023 · 1(b), 1(c) · 4 marks

Selected parts: 1(b) [3]; 1(c) [1].

Hint — reading the question

The original CASE clauses are checked in their written order. Identify which narrower condition is already covered, then consider whether any value remains for OTHERWISE.

Reasoning and model answer — teacher-written

1(b): Level ← "Very Low" is never executed. The clauses are checked in sequence; every value below 20 is also below 30 and has already selected the first clause.

1(c): The other clauses already cover all possible values: below 30, 30 through 40 inclusive, and above 40. No value reaches OTHERWISE.

Official mark scheme
Why this earns marks — teacher explanation

Part (b) gives one point for the assignment and two for the ordered-clause explanation. Part (c) gives one for complete coverage of the possible values.

Common mistakes — teacher analysis

Do not evaluate each CASE clause independently as though they were separate IF statements. Moving the narrower condition first would repair that problem, but the question asks for an explanation of the given code.

Question 1 · Command word: State2 teacher marks

State the outputs of the supplied nested selection for Age 18, Member FALSE, and for Age 20, Member TRUE. Explain the role of the outer comparison.

Use this complete program for the stated task.

DECLARE Age : INTEGER
DECLARE Member : BOOLEAN
INPUT Age
INPUT Member
IF Age >= 18 THEN
    IF Member THEN
        OUTPUT "Adult member"
    ELSE
        OUTPUT "Adult visitor"
    ENDIF
ELSE
    OUTPUT "Junior"
ENDIF
S11.04.A01
Answer and checking points — teacher-written
  1. The outputs are Adult visitor and Adult member respectively.
  2. Age >= 18 admits all adults to the inner membership decision.

Common error: Age = 18 would exclude adults older than 18.

Question 2 · Command word: Write2 teacher marks

Write CASE pseudocode for integer Option: 1 outputs "Add", 2 outputs "Remove" and all other values output "Unknown".

S11.04.A02
Answer and checking points — teacher-written

One valid solution to the requested statements

CASE OF Option
    1 : OUTPUT "Add"
    2 : OUTPUT "Remove"
    OTHERWISE : OUTPUT "Unknown"
ENDCASE
  1. Begin CASE OF Option and give separate 1 and 2 labels with their required outputs.
  2. Use OTHERWISE : OUTPUT "Unknown" and close with ENDCASE.

Common error: Place OF before the identifier.

Question 3 · Command word: Write2 teacher marks

Write an IF/ELSE statement that outputs "Pass" for Mark at least 50 and "Fail" otherwise. State the output for Mark 50.

S11.04.A01
Answer and checking points — teacher-written

One valid solution to the requested statements

IF Mark >= 50 THEN
    OUTPUT "Pass"

  1. Use IF Mark >= 50 THEN with OUTPUT "Pass".
  2. Use ELSE with OUTPUT "Fail", then ENDIF; 50 outputs Pass.
