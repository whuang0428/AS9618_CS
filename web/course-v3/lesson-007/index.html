Network purpose, models and client types

Separate network scope, computer roles and processing location before choosing a design.

A school has one computer room, three campuses and centrally controlled examination files. Which parts are a LAN or WAN, who provides each service, and where should processing happen?

Before you start

A student says, ‘client-server is a topology and a WAN is always faster than a LAN.’ What two ideas have been confused?

Check your answer

Client-server describes roles, not link layout. LAN and WAN describe geographical/management scope, not guaranteed speed.

Teaching checkpoints
  • After network scope and models, use Q1 and Q2 to check that a network type and a role model answer different questions.
  • Teach thin and thick clients next; use Q3 to connect processing location to management and network dependence.

01

Concept teaching

Visual overview and core explanation

01

Networking creates shared access; LAN and WAN describe scope

S2.01.A01S2.01.A02S2.01.A03

Visual overview

Core explanation

What users can share

Networking devices connect systems so authorised users can share files, printers, storage, applications and an internet connection. Networks also support communication, collaboration, central account management and central backup.

Explain a benefit through its cause

A benefit needs a cause and a consequence. For example, storing one managed copy of an examination file on a server allows authorised users to access the current version and lets administrators back it up centrally.

LAN and WAN describe geographical scope

A LAN covers a limited geographical area such as one building or site and is normally owned or managed by one organisation. A WAN covers a large geographical area, links separate sites or LANs and commonly uses telecommunications-provider infrastructure. These terms do not guarantee a particular speed.

Common misconception

A network benefit is not ‘it is easier’; name what is shared or managed and state the result.

WAN and wireless are different classifications. A WAN may contain wired and wireless links.

02

Network models describe who requests and who provides

S2.02.A01S2.02.A02S2.02.A03

Visual overview

Core explanation

In a client-server model, clients request services or resources and one or more servers provide and manage them. Server roles may include authentication, file storage, web hosting, printing and backup.

In a peer-to-peer model, each peer may request and provide resources directly. No dedicated server is required, but accounts, security, backup and availability are distributed across peers.

A justified choice links the scenario to number of users, trust, central control, required availability, administration and cost. A topology name cannot replace a model choice.

Choose the model from the consequence

FactorClient-serverPeer-to-peer
ManagementCentral accounts, permissions, updates and backupEach peer manages its own sharing and protection
CostServer infrastructure and administrationLower initial cost for a small group
AvailabilityServer failure can affect dependent clientsA resource disappears when its providing peer disconnects
Best fitLarger or controlled organisationSmall trusted group sharing non-critical resources

Client-server request cycle

  1. ClientRequests a named service or resource
  2. ServerChecks access and provides/manages the service
  3. ClientReceives the response

Worked example · Choose a model for shared accounts

  1. Requirement

    A library has 40 terminals. Staff need one set of accounts and nightly backups.

  2. Compare

    A client-server model centralises account permissions and backups. Peer-to-peer would require separate management on the sharing computers.

  3. Decision

    Choose client-server to maintain consistent access and one managed backup process.

  4. Trade-off

    Budget for server administration and recovery: loss of the server can stop dependent services.

Common misconception

Peer-to-peer does not mean every resource is always available.

Client-server is not the same as star topology; one describes roles and the other describes links.

03

Thin and thick describe where the client work happens

S2.03.A01S2.03.A02S2.03.A03

Visual overview

Core explanation

A thin client relies mainly on a server for processing and/or storage. It can use lower-specification hardware and supports central software management, but it depends heavily on the server and network.

A thick client performs more processing locally and normally stores more applications or data locally. It can continue more work when disconnected, but updates, security and maintenance are distributed across devices.

Thin/thick is not a synonym for client-server/peer-to-peer. It describes processing placement within a system design.

Common misconception

A thin client is not simply a physically small laptop; ‘thin’ refers to reliance on server-side resources.

Cambridge command words

Practice questions

Command word: State4 marks

State two networking benefits and explain the consequence of each.

S2.01.A01
Answer and marking points
  1. Users can share a network printer.
  2. One shared printer reduces the need to buy a separate printer for every computer.
  3. Files can be stored and backed up centrally.
  4. A single managed backup process makes shared data easier to recover after loss.

Common error: Accept other valid feature-and-consequence pairs; give a mechanism rather than “easier” or “faster” alone.

Command word: Explain6 marks

A company has one LAN in each of three cities. Explain why the complete network is a WAN. Compare client-server with peer-to-peer for centrally controlled payroll files, then suggest a model and give one drawback of your choice.

S2.01.A02S2.01.A03S2.02.A01S2.02.A02S2.02.A03
Answer and marking points
  1. Each city LAN covers a limited managed site.
  2. The WAN joins these geographically separated LANs through inter-site provider links.
  3. Client-server uses servers to provide requested services; in peer-to-peer each computer can both request and provide files.
  4. Client-server centralises permissions and backup, whereas peers manage their own sharing and protection.
  5. Client-server suits the requirement for centrally controlled payroll files.
  6. Dedicated server hardware and administration cost more, or a server failure can make the payroll service unavailable.

Common error: Compare the models using the same factor before linking the choice to payroll control.

Command word: Suggest5 marks

Suggest thin or thick clients for a school examination room that requires identical software and central storage. Justify the choice, compare the processing location with the alternative and give one drawback.

S2.03.A01S2.03.A02S2.03.A03
Answer and marking points
  1. Thin clients suit the centrally managed examination room.
  2. They rely mainly on the server for processing and storage.
  3. Thick clients carry out more processing and store more applications locally.
  4. Central software installation and updates help keep the examination environment consistent.
  5. A server or network failure can prevent the thin clients from using the required applications.

Common error: A recommendation without scenario-linked reasons is incomplete.

Question 1 · Command word: Compare · 4 marks

Compare a LAN with a WAN in terms of geographical scope and control of the network infrastructure.

Answer and marking points
  • A LAN normally covers a limited geographical area, such as one managed campus.
  • A WAN spans a large geographical area and can link networks at distant sites.
  • A LAN is normally owned or controlled by a single organisation.
  • A WAN commonly depends on telecommunications-provider infrastructure for its inter-site links.

Common error: Compare the same factors for both networks; speed alone does not define LAN or WAN.

Question 2 · Command word: Explain · 4 marks

Explain why a peer-to-peer model may suit a four-person design studio that shares non-critical files, has a very small budget and has no specialist administrator. Include two drawbacks.

Answer and marking points
  • A peer-to-peer model is suitable because each computer can provide files directly without a dedicated server.
  • Avoiding dedicated server hardware and administration matches the small budget and group size.
  • Accounts, permissions and backups are managed separately on the peers rather than through one central system.
  • A shared file becomes unavailable when the peer providing it is switched off or disconnected.

Common error: Do not describe peer-to-peer as a topology; it specifies which computers request and provide resources.

Syllabus/source focusCambridge 9618 syllabus 2.1 · S2.03 (course mapping)
Official Cambridge access page ↗

Question 3 · Command word: Suggest · 4 marks

Field engineers must run large CAD applications when disconnected and synchronise their work after returning online. Suggest thin or thick clients and justify the choice with one management drawback.

Answer and marking points
  • Thick clients are suitable because substantial application processing takes place on each local computer.
  • Local applications remain usable offline; a thin client relying on server processing would lose that access when disconnected.
  • Local hardware must have enough processing power and storage for the engineering workload.
  • Software updates, security controls and synchronisation must be managed across several separate devices.

Common error: Do not choose a client type from the physical size of the computer; base the decision on processing placement and network dependence.
