Network purpose, models and client types

Separate network scope, computer roles and processing location before choosing a design.

A school has one computer room, three campuses and centrally controlled examination files. Which parts are a LAN or WAN, who provides each service, and where should processing happen?

Before you start

A student says, ‘client-server is a topology and a WAN is always faster than a LAN.’ What two ideas have been confused?

Check your answer

Client-server describes roles, not link layout. LAN and WAN describe geographical/management scope, not guaranteed speed.

Concept explanations and worked examples

01

Networking creates shared access; LAN and WAN describe scope

S2.01.A01S2.01.A02S2.01.A03

Visual overview

Establish the concept

Networking devices connect systems so authorised users can share files, printers, storage, applications and an internet connection. Networks also support communication, collaboration, central account management and central backup.

A benefit needs a cause and a consequence. For example, storing one managed copy of an examination file on a server allows authorised users to access the current version and lets administrators back it up centrally.

A LAN covers a limited geographical area such as one building or site and is normally owned or managed by one organisation. A WAN covers a large geographical area, links separate sites or LANs and commonly uses telecommunications-provider infrastructure. These terms do not guarantee a particular speed.

From a shared resource to a measurable benefit

  1. Situation: Forty library terminals need the same catalogue and one printer. Separate copies would need separate updates; separate printers would duplicate hardware.
  2. Networked arrangement: Terminals request the managed catalogue and submit print jobs over the local network. Access permissions determine which users may change records.
  3. Consequence: A catalogue update is available to authorised clients without copying it to every terminal. Sharing the printer reduces the number of printers needed.
  4. Boundary: A network does not automatically provide permissions, current backups or uninterrupted service. Those require configuration and maintenance.

Change the scale without changing the definition

The library site is a LAN. A link joining this site to two libraries in other cities forms part of a WAN. The WAN may use provider-owned fibre while each site uses both Ethernet cables and WiFi. Area and control classify scope; the carrier and measured data rate answer different questions.

Core explanation · Exam essentials

  • Link each network benefit to a shared resource or a management process and its consequence.
  • LAN and WAN describe scope and control; neither guarantees speed or a particular carrier.
Common misconception

A network benefit is not ‘it is easier’; name what is shared or managed and state the result.

WAN and wireless are different classifications. A WAN may contain wired and wireless links.

Check your understanding

A school replaces room Ethernet cables with WiFi. Has its LAN become a WAN?

Check your answer

No. The carrier changes, but the school network still covers the same limited managed site.

02

Network models describe who requests and who provides

S2.02.A01S2.02.A02S2.02.A03

Visual overview

Establish the concept

In a client-server model, clients request services or resources and one or more servers provide and manage them. Server roles may include authentication, file storage, web hosting, printing and backup.

In a peer-to-peer model, each peer may request and provide resources directly. No dedicated server is required, but accounts, security, backup and availability are distributed across peers.

A justified choice links the scenario to number of users, trust, central control, required availability, administration and cost. A topology name cannot replace a model choice.

Follow a service request and its response

  1. Request: Terminal T asks the catalogue server for the record with book ID 104. The terminal is the client for this exchange.
  2. Service: The server receives the request, checks the applicable access rules, retrieves the record and prepares a result.
  3. Response: The server sends the record to T, which displays it. A different request could update a record if the user has permission.

A contrasting model choice

For four trusted colleagues occasionally sharing non-critical photographs, peer-to-peer can avoid buying and administering a dedicated server. Each person shares selected files from their own computer. A file becomes unavailable when its providing peer is switched off, and backup responsibility remains distributed. If central accounts, reliable shared availability and uniform backup become requirements, the model should be reconsidered.

Keep roles separate from layout

A server is a role, not a guarantee of one physical box or one level of reliability. One computer can provide several services; several servers can support a service. A client-server network may use a star or mesh link pattern. Lesson 008 examines those patterns separately.

Worked example · Choose a model for shared accounts

  1. Requirement

    A library has 40 terminals. Staff need one set of accounts and nightly backups.

  2. Compare

    A client-server model centralises account permissions and backups. Peer-to-peer would require separate management on the sharing computers.

  3. Decision

    Choose client-server to maintain consistent access and one managed backup process.

  4. Trade-off

    Budget for server administration and recovery: loss of the server can stop dependent services.

FactorClient-serverPeer-to-peer

Core explanation · Exam essentials

  • A client requests a service; a server provides and manages it. Peers may do both.
  • Justify a model using control, availability, scale, administration and cost.
Common misconception

Peer-to-peer does not mean every resource is always available.

Client-server is not the same as star topology; one describes roles and the other describes links.

Check your understanding

Why does a peer-to-peer shared file disappear when its owner shuts down, even though the other peers remain connected?

Check your answer

That peer provides the file. Working network links and other online peers do not create another copy of its resource.

03

Thin and thick describe where the client work happens

S2.03.A01S2.03.A02S2.03.A03

Visual overview

Establish the concept

A thin client relies mainly on a server for processing and/or storage. It can use lower-specification hardware and supports central software management, but it depends heavily on the server and network.

A thick client performs more processing locally and normally stores more applications or data locally. It can continue more work when disconnected, but updates, security and maintenance are distributed across devices.

Thin/thick is not a synonym for client-server/peer-to-peer. It describes processing placement within a system design.

Trace the same editing task with different processing locations

StageThin-client arrangementThick-client arrangement
InputThe terminal sends the user’s keystrokes or commands to a remote application.The local application receives and processes the input.
ProcessThe server runs most application processing and retains the working data.The client CPU and memory perform substantial application processing.
ResultThe terminal receives output to display; the server may save the file.The client displays the result and may save locally or send a file to a server.
Lost connectionThe dependent remote session is interrupted.Local work can continue if its program, data and required permissions are available locally.

Make a complete choice and test its limits

For the 40 library terminals, a thin-client application can centralise application updates and reduce local processing requirements, but the server and connection must support the simultaneous sessions. For an engineer running CAD at a site with intermittent connectivity, choose a thick client with the application and authorised working files stored locally; synchronise completed files when connected. A powerful local CAD client can still request central accounts and files in a client-server model.

Core explanation · Exam essentials

  • Thin and thick describe how much application work occurs on the client.
  • Client-server can use thin or thick clients; offline work also needs local software and data.
Common misconception

A thin client is not simply a physically small laptop; ‘thin’ refers to reliance on server-side resources.

Check your understanding

Is every client that uses a file server a thin client?

Check your answer

No. A thick client may process a file locally while using a server for storage or authentication.

Practice questions

3 core tasks · 15 teacher marks · 12–16 minutes (teacher estimate). Explain your reasoning before checking the answer.

Question 1 · Command word: Explain6 teacher marks

A company has one LAN in each of three cities. Explain why the complete network is a WAN. Compare client-server with peer-to-peer for centrally controlled payroll files, then suggest a model and give one drawback of your choice.

S2.01.A02S2.01.A03S2.02.A01S2.02.A02S2.02.A03
Answer and checking points — teacher-written
  1. Each city LAN covers a limited managed site.
  2. The WAN joins these geographically separated LANs through inter-site provider links.
  3. Client-server uses servers to provide requested services; in peer-to-peer each computer can both request and provide files.
  4. Client-server centralises permissions and backup, whereas peers manage their own sharing and protection.
  5. Client-server suits the requirement for centrally controlled payroll files.
  6. Dedicated server hardware and administration cost more, or a server failure can make the payroll service unavailable.

Common error: Compare the models using the same factor before linking the choice to payroll control.

Question 2 · Command word: Suggest5 teacher marks

Suggest thin or thick clients for a school examination room that requires identical software and central storage. Justify the choice, compare the processing location with the alternative and give one drawback.

S2.03.A01S2.03.A02S2.03.A03
Answer and checking points — teacher-written
  1. Thin clients suit the centrally managed examination room.
  2. They rely mainly on the server for processing and storage.
  3. Thick clients carry out more processing and store more applications locally.
  4. Central software installation and updates help keep the examination environment consistent.
  5. A server or network failure can prevent the thin clients from using the required applications.

Common error: A recommendation without scenario-linked reasons is incomplete.

Question 3 · Command word: Explain4 teacher marks

Explain why a CAD workstation can be a thick client in a client-server network. Its engineers must edit while the site connection is unavailable. State two local requirements for that offline work.

S2.02.A01S2.03.A02S2.03.A03
Answer and checking points — teacher-written
  1. The workstation performs substantial CAD processing locally, so it is a thick client.
  2. It can still request centrally provided accounts or files, which is client-server use.
  3. The required CAD application must be available to run locally.
  4. The required working data and permission to use it must be available without the lost connection.

Common error: A server connection does not make all application processing remote.

Original question · Cambridge 9618/11

1. Assign client and server roles in a banking app

Cambridge 9618/11 · May/June 2024 · 5(a) · 4 marks

Selected parts: 5(a) [4].

Reading the question — teacher guidance

Identify the devices in this banking system before describing what each does. Give both ends of the request-response exchange.

Solution / model answer — teacher-written

The bank’s central computer is the server. It receives account requests from customers’ devices, processes them using account data, and sends a response.

The customer’s smartphone running the banking application is a client. It sends the customer’s request, waits for the server’s response and displays the returned information.

Official mark scheme
Why this earns marks — teacher explanation

The four marks distinguish identifying the server, describing its role, identifying the client and describing its role. “A server serves clients” does not supply the banking application or the work performed.

Common mistakes — teacher analysis

The phone does not become the server simply because it displays the balance. Identify where the request is processed and where the response is requested and shown.
