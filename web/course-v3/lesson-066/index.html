Build a booking system · Concept 28

Specify data and permitted operations

Observe

The same arrivals, two requirements

  • A, then B, then C are added.
  • Collection 1: serve the earliest waiting request.
  • Collection 2: undo the latest completed action.

Look, then discuss

If two collections contain A, B and C, must they remove A next?

One collection represents requests waiting in arrival order. Another represents completed changes that can be undone. Their stored labels can look similar while the required next removal differs.

Recall

Recall an operation

An operation is an action on data, such as adding an item, removing an item or inspecting one. State which item the operation acts on and what happens if the action is impossible.

Explain

Explanation · 1 / 3

Define an abstract data type

An abstract data type, or ADT, consists of a collection of data and a set of operations on those data. Its definition specifies the permitted behaviour without requiring a particular storage implementation.

Explanation · 2 / 3

Make an operation precise

“Remove an item” is incomplete when several items exist. A waiting-request collection removes the earliest remaining arrival. An undo collection removes the latest remaining completed action. These are different contracts.

Explanation · 3 / 3

Include success and failure behaviour

An empty collection cannot supply an item for removal. A fixed-capacity implementation may reject an addition when full. An unsuccessful operation must not silently damage the collection.

Work together

Use the same labels with different rules

A, B and C are added in that order.

Work together · 1 / 2

Follow arrival order

If removal must be earliest first, A is removed first, then B and then C.

Work together · 2 / 2

Follow undo order

If removal must be latest first, C is removed first, then B and then A. The chosen operation rule determines the order.

Describe what an operation promises before deciding how its data will be stored.

Check

Try it yourself · Teacher-written

Does saying “an ADT is an array” give a complete definition?

Check your reasoning

No. An ADT specifies data and operations with defined behaviour. An array is one possible representation; the statement does not explain the permitted operations or their rules.

Connect

Keep this idea

An ADT specifies a collection of data and the operations on it.

An array implementation needs extra state to enforce those rules.

Separate behaviour from its array representation

Observe

Physical array and current membership

Current membershipactiveactiveinactiveinactiveinactive

Look, then discuss

Can unused array cells still contain old values?

An array has five positions, but the collection contains only two active items. A pointer or count tells the program which positions belong to the current collection.

Recall

Recall capacity and logical contents

Capacity is the number of storage positions. The number of active items can be smaller. A stale value in an unused position is not automatically a member of the current collection.

Explain

Explanation · 1 / 3

Give storage and state different jobs

The array holds data. A top pointer, front and rear pointers, a count, or links describe which positions are active and the order in which operations access them.

Explanation · 2 / 3

Preserve the same external behaviour

Different implementations can satisfy the same ADT rules. Users of a stack still expect latest-in-first-out behaviour whether its internal storage uses an array or another representation.

Explanation · 3 / 3

Describe operations at the required level

For this part of the syllabus, explain how array positions and state change during ADT operations. Full implementation pseudocode is not required. Be precise about the checks, affected positions and resulting pointers.

Work together

Interpret five physical positions

Cells 0 and 1 contain active values A and B. Cells 2, 3 and 4 contain old values from earlier use.

Work together · 1 / 2

Use the state to decide membership

If the state defines only cells 0 and 1 as active, the collection contains two items, not five.

Work together · 2 / 2

Remove without relying on erasure

An operation can make cell 1 inactive by updating the relevant pointer or count. Clearing its old value may help a display, but the state determines whether it remains a member.

Interpret the data together with the state that defines the active collection.

Check

Try it yourself · Teacher-written

A display shows five non-blank array cells but Count is 2. Can you conclude that the ADT contains five items?

Check your reasoning

No. Some displayed values may be stale. Follow the implementation’s pointers, links and count to identify the active items.

Connect

Keep this idea

An implementation must maintain state that makes its array obey the ADT’s operation rules.

A stack uses one end to make the most recent remaining item available first.

Question 1 · Command word: Define2 teacher marks

Define an abstract data type and illustrate both parts using a queue.

S10.08.A01
Answer and checking points — teacher-written
  1. An ADT specifies a collection of data together with operations on it.
  2. A queue contains ordered waiting items; enqueue adds at the rear and dequeue removes the front item.

Common error: Include operations, not only the word collection.

Question 2 · Command word: Identify2 teacher marks

Identify whether each statement describes ADT behaviour or an implementation detail: pop removes the newest item; items occupy Array[1:10]; Top stores an index.

S10.08.A01
Answer and checking points — teacher-written
  1. Removing the newest item specifies stack behaviour.
  2. The array bounds and Top index describe an implementation.

Common error: An implementation variable is not itself the abstract removal rule.

Question 3 · Command word: Explain2 teacher marks

Two stack implementations receive PUSH 2, PUSH 5, POP. One returns 5 and the other returns 2. Explain whether both satisfy the same stack ADT.

S10.08.A01
Answer and checking points — teacher-written
  1. Only the implementation returning 5 satisfies the required LIFO result.
  2. Storage may differ, but changing observable removal order changes the ADT behaviour.

Common error: Abstraction does not mean that any result is acceptable.
