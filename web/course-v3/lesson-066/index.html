Abstract data types

An abstract specification defines the behaviour that every valid implementation must provide.

Core explanation

Specify the data and operations

An abstract data type is a collection of data together with a set of operations on those data. The specification describes what each operation does and any conditions for using it. For example, a stack specifies adding at the top and removing the most recently added item.

Include what each operation must do

The word abstract separates observable behaviour from representation. A user of an ADT needs to know which item a removal returns and how empty or full conditions are handled. The user does not need to know the array position or pointer updates that implement the operation.

Worked example · Describe an ADT without choosing storage

  1. Operation sequence

    PUSH Red; PUSH Blue; POP.

  2. Required result

    POP returns Blue and leaves Red in the stack.

  3. Abstraction

    This result is required whether the implementation uses an array or linked nodes.

Common misconception

Naming a structure or listing its stored items does not specify the permitted operations.

Check your understanding

Which two parts must an ADT definition contain?

Check your answer

The collection of data and the operations defined on those data.

Core explanation

Separate behaviour from storage

An implementation chooses concrete storage and procedures that satisfy the ADT's rules. An array implementation may use extra INTEGER variables to track active positions. Those variables are implementation details; changing them must not change the specified order in which clients receive data.

Use the implementation to preserve the contract

A bounded implementation also needs defined behaviour when storage is full or empty. Rejecting a removal from an empty collection prevents an invalid access. Replacing an array implementation with another representation is acceptable only if valid operations still produce the specified results.

Common misconception

An array is a possible representation; its arbitrary indexed access does not automatically become part of every ADT's interface.

Check your understanding

Can changing the backing array make a queue return the newest item first?

Check your answer

No. That would change FIFO behaviour and violate the queue specification.

Practice questions

Question 1 · Command word: Define2 marks

Define an abstract data type and illustrate both parts using a queue.

S10.08.A01
Answer and marking points
  1. An ADT specifies a collection of data together with operations on it.
  2. A queue contains ordered waiting items; enqueue adds at the rear and dequeue removes the front item.

Common error: Include operations, not only the word collection.

Question 2 · Command word: Identify2 marks

Identify whether each statement describes ADT behaviour or an implementation detail: pop removes the newest item; items occupy Array[1:10]; Top stores an index.

S10.08.A01
Answer and marking points
  1. Removing the newest item specifies stack behaviour.
  2. The array bounds and Top index describe an implementation.

Common error: An implementation variable is not itself the abstract removal rule.

Question 3 · Command word: Explain2 marks

Two stack implementations receive PUSH 2, PUSH 5, POP. One returns 5 and the other returns 2. Explain whether both satisfy the same stack ADT.

S10.08.A01
Answer and marking points
  1. Only the implementation returning 5 satisfies the required LIFO result.
  2. Storage may differ, but changing observable removal order changes the ADT behaviour.

Common error: Abstraction does not mean that any result is acceptable.

Question 1 · Command word: Explain · 3 marks

A collection offers AddToRear and RemoveFromFront. Explain what must be specified about these operations before a programmer can use the collection without seeing its code.

Answer and marking points
  • AddToRear places a new item after items already waiting.
  • RemoveFromFront returns and removes the earliest remaining item.
  • The specification must state how invalid operations such as removal from an empty collection are handled.

Common error: Array positions alone do not explain the operation contract.

Question 2 · Command word: State · 2 marks

A programmer replaces an array-backed queue with linked nodes. State two observable properties that must remain unchanged for clients of the queue ADT.

Answer and marking points
  • Successful removals still return items in their arrival order.
  • Enqueue and dequeue retain their specified effects, including the documented handling of empty removal.

Common error: The physical node addresses are not an observable queue ordering rule.

Question 3 · Command word: Explain · 3 marks

A description says only 'the ADT stores A, B and C in cells 1, 2 and 3'. Explain why this does not fully define an ADT, and give a missing operation rule that would distinguish a stack from a queue.

Answer and marking points
  • The description gives stored data and locations but omits the defined operations.
  • For additions A then B then C, a stack's next removal returns C.
  • A queue's next removal returns A.

Common error: The same values can support different ADTs when their access rules differ.

04

Lesson review

Summary

Definition

An ADT specifies both its data and the operations that act on those data.

Abstraction

Clients rely on operation behaviour; representations may change while preserving that behaviour.
