Section 2 · Communication

How does a school share files, reach a website and play a video?

Begin with familiar devices and shared resources. Follow signals, connections and addresses to explain how data reaches its destination. Recall the basics where you need them, then use what you understand in a new situation.

Browse by topic

Begin with people who need to share something

Follow a school from one shared printer to a connected set of classrooms. Separate why devices communicate, how far the network reaches, who supplies a service and where work is processed.

Read the links before predicting a network path

Use the devices and connections already introduced to trace bus, star, mesh and hybrid networks. A design claim should follow from its actual links and the failure under discussion.

Locate the resources behind a cloud application

Return to the school course site after learning how to reach a remote resource. Identify which resources are supplied, who shares the infrastructure and what happens when a dependency fails.

Choose a carrier that fits the physical task

Data needs a physical signal. Compare electrical signals, light and radio before deciding how to connect fixed desks, moving tablets, school buildings and a remote field station.

Give each network device a specific job

Move from a device’s physical interface to local forwarding, routing and Ethernet access rules. Keep local frame delivery separate from delivery between networks.

Explain video playback using arrival, consumption and a buffer

Return to the school’s lesson video. First distinguish live and stored media, then count bits per second and track temporary storage so that pauses and adaptations have a visible cause.

Reach services beyond the school’s local network

Separate the internet’s connected infrastructure from the web service used in a browser. Then compare the access links that join a site or mobile device to wider networks.

Turn a web address into a request that can reach a resource

Give each interface an address, compare network prefixes, separate routing scope from assignment, then trace a URL through name resolution to a web response. Use each distinction to diagnose a different failure.
