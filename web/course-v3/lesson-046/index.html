Understanding and writing SQL data definitions

Read a supplied SQL statement, then create a database, select field types, define keys and alter table structure.

How does a SQL definition turn a database design into tables with enforceable constraints?

Before you start

What distinguishes changing a table definition from changing a value in one row?

Check your answer

The former is DDL and affects structure; the latter is DML and affects stored data.

  • For SQL, compare the exact result or changed records with the specified data and constraints.

01

Read the supplied statement before explaining it

S8.08.A01S8.08.A02

Visual overview

Core explanation

A SQL statement must be interpreted from the actual identifiers, conditions and values supplied. In a retrieval statement, SELECT identifies output expressions, FROM identifies the source and WHERE restricts rows. A changed field list can alter the columns without changing which records qualify.

Read a definition statement by identifying the object created or altered, its field types and its constraints. Quoted text literals represent values rather than field names. Explain the effect of the operator or limit given; recognising a keyword alone does not determine the result.

Worked example · Interpret an exact supplied query

  1. Read the task

    Output Title and Price for books costing at least 10, in BookID order.

  2. Write SQL
    SELECT Title, Price
FROM Book
WHERE Price >= 10
ORDER BY BookID;

Do not invent a filtering value or source table that is absent from the supplied statement.

Check your understanding

If >= 10 becomes > 10 in the example, which title is no longer returned?

Check your answer

River is excluded because its price is exactly 10; Atlas remains.

02

Create a named database

S8.09.A01

Visual overview

Core explanation

CREATE DATABASE creates a named database in a DBMS that supports this SQL operation. The name is an identifier, not a quoted data value. Creating the database does not by itself define its tables or populate records.

After creating SchoolLibrary, the developer selects that database in the chosen DBMS interface and defines its tables. The interface command for selecting a database varies between products; the SQL statement below expresses the required creation operation.

Common misconception

CREATE DATABASE and CREATE TABLE create different objects.

Check your understanding

How many Student rows does CREATE DATABASE SchoolLibrary insert?

Check your answer

None. Tables and record insertions require further operations.

03

Choose data types and define fields

S8.09.A02

Visual overview

Core explanation

Choose a field type from the meaning and range of its values. CHARACTER stores fixed-length character data; VARCHAR(n) stores text up to the specified maximum length. INTEGER represents whole numbers, REAL represents values with a fractional part, and BOOLEAN represents true or false.

DATE and TIME represent calendar dates and times of day separately. Field names and types appear inside the CREATE TABLE brackets, separated by commas. A numeric-looking identifier may still need a text type when leading zeroes or non-arithmetic meaning must be preserved.

Worked example · Create a referenced table before its child

  1. Prerequisite

    SchoolLibrary has been selected in the DBMS. Tutor must exist before Student's reference to it is defined.

  2. Complete definitions
    CREATE TABLE Tutor (
    TutorID INTEGER,
    TutorName VARCHAR(40),
    PRIMARY KEY (TutorID)
);
CREATE TABLE Student (
    StudentID INTEGER,
    Initial CHARACTER(1),
    StudentName VARCHAR(40),
    Active BOOLEAN,
    Score REAL,
    BirthDate DATE,
    ArrivalTime TIME,
    TutorID INTEGER,
    PRIMARY KEY (StudentID),
    FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID)
);
  3. Read the fields

    StudentID and TutorID are whole-number identifiers. The remaining fields and constraints define the permitted structure.

  4. Check

    Both primary keys identify their own rows; Student.TutorID references Tutor.TutorID. No student records have yet been inserted.

Common misconception

Do not use REAL for every value containing digits; dates, times and textual codes have different meanings.

Check your understanding

A room code may be '007B'. Is INTEGER suitable?

Check your answer

No. VARCHAR(4) can preserve the letters and leading zeroes in that code.

04

Alter an existing table definition

S8.09.A03

Visual overview

Core explanation

ALTER TABLE changes the structure of an existing table. To add Email to the Student definition, identify the existing table and supply the new field name and type after ADD. Existing student records remain present.

In this example the added Email field is nullable and has no default, so existing records initially have no supplied email value. Setting an email for one student is a later UPDATE operation. The new attribute and the value in one occurrence are separate changes.

Worked example · Add a contact field

  1. Existing structure

    Student already exists from the preceding definition.

  2. DDL

    ALTER TABLE Student ADD Email VARCHAR(80);

  3. Result

    Email is available in the table definition. This statement does not assign a particular student's address.

Common misconception

UPDATE changes values in defined fields; it does not add the new Email field to the schema.

Check your understanding

Which table is changed by the displayed statement?

Check your answer

Student is altered; Tutor is unaffected.

05

Declare the primary key

S8.09.A04

Visual overview

Core explanation

A PRIMARY KEY constraint declares the chosen identifier for a table. The key must distinguish every record and cannot be null. Write the selected field inside PRIMARY KEY brackets in the CREATE TABLE definition.

A composite primary key lists all fields needed for identification, for example PRIMARY KEY (StudentID, ClubID) in Membership. The combination must be unique; either component may recur in other combinations. Choose the key from the stated business rules.

Common misconception

Declaring an INTEGER field alone does not generally declare it as the primary key.

Check your understanding

Can Membership contain (12, A) and (12, B) under the composite declaration?

Check your answer

Yes. The pairs differ. A second (12, A) would duplicate the primary key.

06

Declare the referenced relationship

S8.09.A05

Visual overview

Core explanation

FOREIGN KEY names the field or fields in the current table; REFERENCES names the related table and referenced key. In Student, FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID) declares which parent identifier each non-null tutor reference must match.

Create the referenced table and key first when using this teaching sequence. The child field may repeat when many students share a tutor. A foreign-key declaration enforces the link; it does not automatically assign a tutor or create the missing parent record.

Common misconception

REFERENCES must name the parent table and key, not simply repeat the child table's primary-key name.

Check your understanding

Why does defining Student.TutorID not create a Tutor row for value 9?

Check your answer

The declaration only defines and checks the reference; the parent record must be inserted separately.

Answer and marking points
  1. The output contains Title from Book.
  2. Only Reference records qualify and they are sorted by increasing Price, giving Map then Atlas.

Question 2 · Command word: Write2 marks

Write an SQL statement to create a database named SportsCentre. State whether it creates any Booking records.

S8.09.A01
Answer and marking points

One valid SQL answer

CREATE DATABASE SportsCentre;
  1. CREATE DATABASE SportsCentre;
  2. It does not create Booking records; a table definition and record insertions are separate operations.

Common error: Use the database identifier requested, without confusing it with a table name.

Question 3 · Command word: Write7 marks

Write CREATE TABLE for Event with EventID (whole number), Code (one character), EventName (up to 30 characters), Confirmed (true/false), Duration (fractional hours), EventDate (calendar date) and StartTime (time of day). Use the seven syllabus data types.

S8.09.A02
Answer and marking points

One valid SQL answer

CREATE TABLE Event (
    EventID INTEGER,
    Code CHARACTER(1),
    EventName VARCHAR(30),
    Confirmed BOOLEAN,
    Duration REAL,
    EventDate DATE,
    StartTime TIME
);
  1. EventID uses INTEGER in the Event table definition.
  2. Code uses CHARACTER(1).
  3. EventName uses VARCHAR(30).
  4. Confirmed uses BOOLEAN.
  5. Duration uses REAL.
  6. EventDate uses DATE.
  7. StartTime uses TIME, with valid comma-separated field definitions inside CREATE TABLE brackets.

Common error: Each type must match the field's meaning; do not quote type names as data values.

Question 4 · Command word: Write2 marks

Write DDL to add Room, containing at most 12 characters, to the existing Event table. Explain why an UPDATE statement is insufficient.

S8.09.A03
Answer and marking points

One valid SQL answer

ALTER TABLE Event ADD Room VARCHAR(12);
  1. ALTER TABLE Event ADD Room VARCHAR(12);
  2. The new field must first be introduced into the definition; UPDATE only assigns existing fields.

Common error: Adding a column and filling its values are distinct operations.

Question 5 · Command word: Write3 marks

Write a Locker table definition containing LockerID as INTEGER and Location as VARCHAR(30), making LockerID its primary key. State the two requirements this identifier must satisfy.

S8.09.A04
Answer and marking points

One valid SQL answer

CREATE TABLE Locker (LockerID INTEGER, Location VARCHAR(30), PRIMARY KEY (LockerID));
  1. The definition declares PRIMARY KEY (LockerID).
  2. LockerID values must be unique across Locker records.
  3. A record must not have a null LockerID.

Common error: Do not substitute a unique-looking example value for a declared key constraint.

Question 6 · Command word: Write3 marks

Locker(LockerID) already has its primary key. Write Allocation with integer AllocationID as primary key and integer LockerID as a foreign key to Locker. Explain whether several allocations can reference the same locker under these constraints alone.

S8.09.A05
Answer and marking points

One valid SQL answer

CREATE TABLE Allocation (AllocationID INTEGER, LockerID INTEGER, PRIMARY KEY (AllocationID), FOREIGN KEY (LockerID) REFERENCES Locker(LockerID));
  1. Allocation defines its two integer fields and its own AllocationID primary key.
  2. FOREIGN KEY (LockerID) REFERENCES Locker(LockerID) declares the parent link.
  3. Repeated LockerID references are permitted unless an additional uniqueness rule forbids them.

Common error: The referencing field and the referenced table/key must all be named.

Question 1 · Command word: Describe · 4 marks

Describe the structure created by the supplied statement. Explain the length limit on AccountName, the meaning of Verified and the constraint on AccountID.

Supplied SQL definition

CREATE TABLE Account (AccountID INTEGER, AccountName VARCHAR(25), Verified BOOLEAN, PRIMARY KEY (AccountID));
Answer and marking points
  • An Account table is defined with AccountID, AccountName and Verified attributes.
  • AccountName holds variable-length text up to 25 characters.
  • Verified stores a Boolean truth value.
  • AccountID is the declared identifier, requiring distinct non-null values.

Common error: This statement defines storage; it does not populate an account.

Question 2 · Command word: Write · 6 marks

Write SQL definitions for Venue(VenueID, VenueName) and Booking(BookingID, VenueID, BookingDate, Confirmed). Both ID fields in Booking and VenueID in Venue are integers; venue names contain at most 50 characters. Use suitable date and Boolean types, declare each primary key and link Booking to Venue.

Answer and marking points

One valid SQL answer

CREATE TABLE Venue (VenueID INTEGER, VenueName VARCHAR(50), PRIMARY KEY (VenueID));
CREATE TABLE Booking (BookingID INTEGER, VenueID INTEGER, BookingDate DATE, Confirmed BOOLEAN, PRIMARY KEY (BookingID), FOREIGN KEY (VenueID) REFERENCES Venue(VenueID));
  • Venue is created with integer VenueID and VARCHAR(50) VenueName.
  • VenueID is declared as the Venue primary key.
  • Booking is created with integer BookingID and VenueID.
  • BookingDate is DATE and Confirmed is BOOLEAN.
  • BookingID is the Booking primary key.
  • Booking.VenueID is declared as a foreign key referencing Venue.VenueID, after the parent definition exists.

Common error: Keep the venue reference on Booking, where several bookings can name one venue.

Question 3 · Command word: Write · 3 marks

The Booking table already exists. Write SQL to add a Cost field that can contain fractional amounts. Explain how this differs from assigning 24.50 to one booking and whether creating a new database is required.

Answer and marking points

One valid SQL answer

ALTER TABLE Booking ADD Cost REAL;
  • ALTER TABLE Booking ADD Cost REAL;
  • The statement adds the field definition; assigning one booking's amount would be a subsequent data update.
  • A new database is not needed to alter this existing table.

Common error: Use the existing table name rather than CREATE DATABASE Booking.

04

Lesson review

Summary

Read exact SQL

Identify the object, names, operators and values actually supplied.

Define fields

Match whole numbers, fractional values, text, truth values, dates and times to appropriate types.

Declare relationships

State primary and foreign-key constraints explicitly and create the referenced definition first.

Alter structure

Use ALTER TABLE for definition changes and a separate data operation to assign values.
