In VARCHAR(n), n is the maximum permitted length; VARCHAR(40) therefore allows up to 40 characters. Select a data type according to the values an attribute must store and the operations performed on those values. A card code is text even if some characters are digits; arithmetic on its characters would not represent the business meaning. A date type lets the DBMS reject impossible dates and compare calendar values.

REAL and the required data types

REAL stores approximate floating-point values. It is used for Fee in this example. The specified SQL data types are CHARACTER, VARCHAR(n), BOOLEAN, INTEGER, REAL, DATE and TIME.

Practice question · teacher-written

Explain why VARCHAR(40) is suitable for MemberName and BOOLEAN is suitable for Returned.

Suggested answer

Names vary in length and contain text, so a bounded variable-length character field fits them. Returned represents one of two logical states and should not be treated as arbitrary text.

Create table definitions with primary and foreign keys

After connecting to the empty LibraryBuild database, run this complete definition. Create referenced parent tables before their children: Member before MemberCard and Loan; Book before Copy; Copy before Loan.

CREATE TABLE Member (
  MemberID INTEGER PRIMARY KEY,
  MemberName VARCHAR(40) NOT NULL,
  SchoolEmail VARCHAR(80) UNIQUE NOT NULL,
  TutorGroup VARCHAR(4),
  Active BOOLEAN NOT NULL
);
CREATE TABLE MemberCard (
  MemberID INTEGER PRIMARY KEY REFERENCES Member(MemberID),
  CardCode CHARACTER(6) UNIQUE NOT NULL,
  IssueDate DATE NOT NULL
);
CREATE TABLE Book (
  BookID INTEGER PRIMARY KEY,
  Title VARCHAR(60) NOT NULL,
  Category VARCHAR(20)
);
CREATE TABLE Copy (
  CopyID INTEGER PRIMARY KEY,
  BookID INTEGER NOT NULL REFERENCES Book(BookID),
  ShelfCode VARCHAR(8)
);
CREATE TABLE Loan (
  LoanID INTEGER PRIMARY KEY,
  MemberID INTEGER NOT NULL REFERENCES Member(MemberID),
  CopyID INTEGER NOT NULL REFERENCES Copy(CopyID),
  BorrowDate DATE NOT NULL,
  BorrowTime TIME NOT NULL,
  Fee REAL NOT NULL CHECK (Fee >= 0),
  Returned BOOLEAN NOT NULL
);

PRIMARY KEY requires unique, non-null key values. UNIQUE NOT NULL gives SchoolEmail the independent uniqueness and presence required of its candidate-key role. REFERENCES names the parent table and referenced field. Loan’s NOT NULL references require every event to identify an existing member and copy. CHECK (Fee >= 0) rejects negative fees.

Foreign-key declarations
DeclarationMeaning
MemberCard.MemberID PRIMARY KEY REFERENCES Member(MemberID)One card row at most per member; every card refers to a Member.
Copy.BookID REFERENCES Book(BookID)Each stored BookID must identify a Book.
Loan.MemberID REFERENCES Member(MemberID)Each loan’s member reference must exist.
Loan.CopyID REFERENCES Copy(CopyID)Each loan’s physical copy reference must exist.

Practice question · teacher-written

Explain whether a foreign-key value may occur in more than one record in the referencing table.

Suggested answer

Several Loan records may contain the same MemberID. The foreign-key constraint requires a matching referenced member; it does not by itself require unique values in Loan.MemberID.

Modify a table definition using ALTER TABLE

ALTER TABLE Member ADD Note VARCHAR(80);
Before and after adding Note
AspectBeforeAfter
Member attributesFive defined attributesSix defined attributes, including Note.
Existing Member recordsAny records already stored in this databaseThe same records; adding the attribute does not insert or delete members.
New Note valuesNo such attribute existsNULL for any existing records until a value is assigned.

If you are following the steps in the new LibraryBuild database, Member is still empty until the initial records are inserted. The new attribute changes the table definition and appears in the data dictionary. Use DML later to supply values. When a constraint is added to a populated table, the existing records must satisfy that constraint. Otherwise, the DBMS rejects the change.

Practice question · teacher-written

Explain why UPDATE Member SET Note = 'New member' cannot create a missing Note attribute.

Suggested answer

UPDATE changes values in an existing attribute. ALTER TABLE is required to add the attribute before UPDATE can assign a value to it.

Add primary-key and foreign-key constraints

A table can be created with constraints immediately, as above, or have them added later. The following reading-group tables illustrate adding constraints to existing definitions.

CREATE TABLE ReadingGroup (GroupID INTEGER, GroupName VARCHAR(40));
ALTER TABLE ReadingGroup ADD PRIMARY KEY (GroupID);

ReadingGroup initially has attributes but no declared primary key. The ALTER statement makes GroupID its primary key. Existing duplicates or NULL identifiers would cause the new constraint to be rejected.

CREATE TABLE ReadingGroupMember (GroupID INTEGER, MemberID INTEGER, PRIMARY KEY (GroupID, MemberID));
ALTER TABLE ReadingGroupMember ADD FOREIGN KEY (MemberID) REFERENCES Member(MemberID);

ReadingGroupMember identifies a membership with the pair (GroupID, MemberID). The ALTER statement adds a reference from MemberID to Member.MemberID. This example adds that one relationship; a complete reading-group design should also declare GroupID’s reference to ReadingGroup.

Practice question · teacher-written

Explain why MemberID is a suitable referenced key, whereas a MemberName that may repeat is not.

Suggested answer

MemberID uniquely identifies a Member record. A MemberName that may repeat does not identify a unique record, so it is not suitable as the referenced key.

Practice question · teacher-written

Explain why SELECT returns no records immediately after the five tables have been created.

Suggested answer

The DDL statements have created the table definitions, but no records have been inserted. INSERT INTO is required to add data to the tables.

Question 2 · Command word: Write7 teacher marks

Write CREATE TABLE for Event with EventID (whole number), Code (one character), EventName (up to 30 characters), Confirmed (true/false), Duration (fractional hours), EventDate (calendar date) and StartTime (time of day). Use the seven syllabus data types. Then check whether Code = "AB" and Duration = 1.5 match your chosen field definitions, explaining both decisions.

S8.09.A02
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Event (
    EventID INTEGER,
    Code CHARACTER(1),
    EventName VARCHAR(30),
    Confirmed BOOLEAN,
    Duration REAL,
    EventDate DATE,
    StartTime TIME
);
  1. EventID uses INTEGER in the Event table definition.
  2. Code uses CHARACTER(1); "AB" exceeds the declared length.
  3. EventName uses VARCHAR(30).
  4. Confirmed uses BOOLEAN.
  5. Duration uses REAL and can represent the supplied fractional value 1.5.
  6. EventDate uses DATE.
  7. StartTime uses TIME, with valid comma-separated field definitions inside CREATE TABLE brackets.

Common error: Each type must match the field's meaning; do not quote type names as data values.

Question 3 · Command word: Write2 teacher marks

Write DDL to add Room, containing at most 12 characters, to the existing Event table. Explain why an UPDATE statement is insufficient.

S8.09.A03
Answer and checking points — teacher-written

One valid SQL answer

ALTER TABLE Event ADD Room VARCHAR(12);
  1. ALTER TABLE Event ADD Room VARCHAR(12);
  2. The new field must first be introduced into the definition; UPDATE only assigns existing fields.

Question 4 · Command word: Write3 teacher marks

Write a Locker table definition containing LockerID as INTEGER and Location as VARCHAR(30), making LockerID its primary key. State the two requirements this identifier must satisfy.

S8.09.A04
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Locker (LockerID INTEGER, Location VARCHAR(30), PRIMARY KEY (LockerID));
  1. The definition declares PRIMARY KEY (LockerID).
  2. LockerID values must be unique across Locker records.
  3. A record must not have a null LockerID.

Common error: Do not substitute a unique-looking example value for a declared key constraint.

Question 5 · Command word: Write3 teacher marks

Locker(LockerID) already has its primary key. Write Allocation with integer AllocationID as primary key and integer LockerID as a foreign key to Locker. Explain whether several allocations can reference the same locker under these constraints alone.

S8.09.A05
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Allocation (AllocationID INTEGER, LockerID INTEGER, PRIMARY KEY (AllocationID), FOREIGN KEY (LockerID) REFERENCES Locker(LockerID));
  1. Allocation defines its two integer fields and its own AllocationID primary key.
  2. FOREIGN KEY (LockerID) REFERENCES Locker(LockerID) declares the parent link.
  3. Repeated LockerID references are permitted unless an additional uniqueness rule forbids them.

Common error: The referencing field and the referenced table/key must all be named.

Question 6 · Command word: Write3 teacher marks

Venue(VenueID INTEGER PRIMARY KEY) and Booking(BookingID INTEGER PRIMARY KEY, VenueID INTEGER) already exist. Venue contains 4; Booking contains (20, 4). Write ALTER TABLE to add the missing foreign key. Explain the resulting constraint and whether this same addition would succeed if Booking instead contained (20, 9).

S8.09.A03S8.09.A05
Answer and checking points — teacher-written

One valid SQL answer

ALTER TABLE Booking ADD FOREIGN KEY (VenueID) REFERENCES Venue(VenueID);
  1. ALTER TABLE Booking ADD FOREIGN KEY (VenueID) REFERENCES Venue(VenueID);
  2. Each non-null Booking.VenueID must match Venue.VenueID; the successful addition preserves (20, 4).
  3. With (20, 9) and no venue 9, the existing data violates the proposed constraint, so adding it fails until the mismatch is corrected.

Common error: ALTER adds a missing rule to the existing table; do not recreate it or add the already-existing field.

Data management

A table stores records about an entity type. Each record contains values for its fields. Select a table to inspect its records, then use the form or SQL to maintain the data.

This form submits an INSERT statement to the database. The DBMS checks access rights and enforces primary key and unique constraints.

Data modelling and logical schema

Data modelling identifies entities, attributes and relationships. A logical schema describes the database design independently of a particular DBMS. The table definitions below implement that design in PostgreSQL.

Table designer: add an attribute

The designer issues ALTER TABLE. Inspect the same attribute in the data dictionary.

Data dictionary

The data dictionary contains metadata, including field names, data types, field sizes and constraints. The DBMS maintains this metadata when a table definition changes. Editing a record changes the stored data, not its field definitions.

Data integrity

Data integrity concerns the accuracy and consistency of stored data. The DBMS enforces validation rules and referential integrity constraints. Access rights control which operations a user may perform; authorised operations must still satisfy the constraints.

A foreign key alone permits NULL unless NOT NULL is also declared. This library requires every loan to identify a member and a copy. Its default referential action rejects deleting a referenced record.

Access rights for individuals and groups

Select a user above. Student inherits SELECT access rights from the library_readers group. Librarian inherits rights to retrieve, insert, update and delete records from library_writers. Administrator can change table definitions and assign access rights to individuals or groups.

Backup and recovery procedures

A backup is a copy of data that can be used to recover from data loss or corruption. Backup procedures specify how often copies are made, where they are stored, how they are protected and retained, and how restoration is tested. This exercise creates and restores a copy of the database at a particular time.

No teaching backup has been made.

A simulated outage hides the live records until recovery. The teaching backup restores the whole database structure, data and grants. Changes after its time are lost from the restored state.

The browser’s automatic course save is separate from this teaching backup. Keeping both in one browser is not protection against losing that device.

Developer interface and query processor

The developer interface provides tools for defining tables and creating queries. The query processor interprets SQL, checks its syntax and referenced tables and fields, produces an execution plan and carries out the query. The results and errors below are produced by PostgreSQL.
