Understanding and writing SQL data definitions

Read and write table definitions, select data types, declare keys and alter existing structure.

How does a SQL definition turn a database design into tables with enforceable constraints?

Before you start

What distinguishes changing a table definition from changing a value in one row?

Check your answer

The former is DDL and affects structure; the latter is DML and affects stored data.

Teaching checkpoints
  • Read a small definition; create the database and select the seven field types.
  • Define parent and child keys, then explain the permitted and rejected records.
  • Add a field or constraint to an existing table and check the before/after state.

Read structure before writing it

Start by identifying the command and the named object. Then read each comma-separated field declaration and the key clause. This first definition is small enough to interpret before constructing a larger linked design.

Interpret the supplied definition

ElementMeaning
CREATE TABLE AccountCreate a new table named Account.
AccountID INTEGERDefine a whole-number identifier field.
AccountName VARCHAR(25)Allow variable-length names up to 25 characters.
Verified BOOLEANStore a truth value.
PRIMARY KEY (AccountID)Use distinct, non-null AccountID values.

Swipe horizontally to compare every column →

Identify the resulting state

Names such as AccountName are identifiers, while 25 is a length limit. No VALUES clause or record data is present. Query interpretation continues in Lesson 047 after SELECT, WHERE and ORDER BY have been taught.

Worked example · Read the complete definition

  1. Statement
    CREATE TABLE Account (
  AccountID INTEGER,
  AccountName VARCHAR(25),
  Verified BOOLEAN,
  PRIMARY KEY (AccountID)
);
  2. Final state

    Account exists with three fields and a primary-key constraint. It contains zero records.

  3. Predict a changed definition

    Using VARCHAR(40) instead allows a longer name; it still inserts no account.

Core explanation · Exam essentials

  • Read the exact SQL identifiers, data types and constraints before describing the result.
  • CREATE TABLE defines an initially empty structure; it does not add records.
Common misconception

A number inside VARCHAR brackets is a field-length limit, not a number of records.

Check your understanding

What changes if VARCHAR(25) becomes VARCHAR(40), and how many account records are created?

Check your answer

The maximum name length changes from 25 to 40 characters. The statement creates zero records.

02

Create a named database

S8.09.A01

Visual overview

Create the container

CREATE DATABASE creates a named database in a DBMS that supports this SQL operation. The name is an identifier, not a quoted data value. Creating the database does not by itself define its tables or populate records.

Choose its context

After creating SchoolLibrary, the developer selects that database in the chosen DBMS interface and defines its tables. The interface command for selecting a database varies between products; the SQL statement below expresses the required creation operation.

Count objects and records separately

After CREATE DATABASE SchoolLibrary, the named database exists without the Tutor or Student tables in this example. After defining those tables, both initially have zero records. After inserting tutor 7 and student 21, the database has actual related data. These are three distinct states.

Keep product details separate

SQL products differ in how a database is selected and in some supported statements. Use the syllabus form for the requested definition and the local DBMS interface to choose its context; do not treat an interface selection command as universal SQL.

Core explanation · Exam essentials

  • CREATE DATABASE names a database container; table creation and population are separate steps.
  • Select the database in the DBMS interface before defining its tables.
Common misconception

CREATE DATABASE and CREATE TABLE create different objects.

Check your understanding

How many Student rows does CREATE DATABASE SchoolLibrary insert?

Check your answer

None. Tables and record insertions require further operations.

03

Choose data types and define fields

S8.09.A02

Visual overview

Choose from meaning

Choose a field type from the meaning and range of its values. CHARACTER stores fixed-length character data; VARCHAR(n) stores text up to the specified maximum length. INTEGER represents whole numbers, REAL represents values with a fractional part, and BOOLEAN represents true or false.

Build comma-separated declarations

DATE and TIME represent calendar dates and times of day separately. Field names and types appear inside the CREATE TABLE brackets, separated by commas. A numeric-looking identifier may still need a text type when leading zeroes or non-arithmetic meaning must be preserved.

Distinguish similar-looking values

Value and purposeSuitable typeReason
007B room codeVARCHAR(4)Letters and leading zeroes belong to an identifier.
007 telephone-area codeCHARACTER(3)A fixed three-character code; not arithmetic 7.
7 pupilsINTEGERA whole-number count.
7.5 hoursREALA quantity with a fractional part.
2028-02-29; 09:15:00DATE; TIMEA calendar date and a time of day have different domains.

State the limits of a type

A name exceeding VARCHAR(40) is outside the declared limit in a DBMS enforcing that type. A syntactically valid date can still be the wrong birth date. REAL is the required fractional-number choice here, but real-number implementations may approximate some decimals; exact financial decimal types and product-specific date formats are outside this lesson.

Worked example · Create a referenced table before its child

  1. Prerequisite

    SchoolLibrary has been selected in the DBMS. Tutor must exist before Student's reference to it is defined.

  2. Complete definitions
    CREATE TABLE Tutor (
    TutorID INTEGER,
    TutorName VARCHAR(40),
    PRIMARY KEY (TutorID)
);
CREATE TABLE Student (
    StudentID INTEGER,
    Initial CHARACTER(1),
    StudentName VARCHAR(40),
    Active BOOLEAN,
    Score REAL,
    BirthDate DATE,
    ArrivalTime TIME,
    TutorID INTEGER,
    PRIMARY KEY (StudentID),
    FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID)
);
  3. Read the fields

    StudentID and TutorID are whole-number identifiers. The remaining fields and constraints define the permitted structure.

  4. Check

    Both primary keys identify their own rows; Student.TutorID references Tutor.TutorID. No student records have yet been inserted.

Core explanation · Exam essentials

  • Choose CHARACTER, VARCHAR, INTEGER, REAL, BOOLEAN, DATE or TIME from the meaning of each field.
  • A type describes permitted representation; it does not prove factual accuracy.
Common misconception

Do not use REAL for every value containing digits; dates, times and textual codes have different meanings.

Check your understanding

A room code may be '007B'. Is INTEGER suitable?

Check your answer

No. VARCHAR(4) can preserve the letters and leading zeroes in that code.

04

Declare the primary key

S8.09.A04

Visual overview

Declare the chosen identifier

A PRIMARY KEY constraint declares the chosen identifier for a table. The key must distinguish every record and cannot be null. Write the selected field inside PRIMARY KEY brackets in the CREATE TABLE definition.

Apply the composite rule

A composite primary key lists all fields needed for identification, for example PRIMARY KEY (StudentID, ClubID) in Membership. The combination must be unique; either component may recur in other combinations. Choose the key from the stated business rules.

Independent Membership insertions; initial pairs (12, A), (12, B)

Proposed pairResult
(13, A)Allowed: a new combination.
(12, A)Rejected: duplicates an existing pair.
(12, NULL)Rejected: a primary-key component is missing.

Swipe horizontally to compare every column →

Avoid two separate uniqueness rules

PRIMARY KEY (StudentID, ClubID) declares one composite key. Declaring each field individually unique would wrongly prevent student 12 from joining both A and B. Choose the constraints that match the one-membership-per-student-per-club rule.

Core explanation · Exam essentials

  • Declare PRIMARY KEY explicitly for the selected minimal identifier.
  • A composite key requires a unique, non-null combination; each component can repeat.
Common misconception

Declaring an INTEGER field alone does not generally declare it as the primary key.

Check your understanding

Can Membership contain (12, A) and (12, B) under the composite declaration?

Check your answer

Yes. The pairs differ. A second (12, A) would duplicate the primary key.

05

Declare the referenced relationship

S8.09.A05

Visual overview

Read both sides of the declaration

FOREIGN KEY names the field or fields in the current table; REFERENCES names the related table and referenced key. In Student, FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID) declares which parent identifier each non-null tutor reference must match.

Apply it to records

Create the referenced table and key first when using this teaching sequence. The child field may repeat when many students share a tutor. A foreign-key declaration enforces the link; it does not automatically assign a tutor or create the missing parent record.

Tutor contains only TutorID 7; attempts are independent

Student row / operationResult
New StudentID 21, TutorID 7Allowed if the remaining values satisfy their constraints.
New StudentID 22, TutorID 7Allowed: a tutor may have several students.
New StudentID 23, TutorID 9Rejected: tutor 9 is absent.
Change student 21 from tutor 7 to 9Rejected; the existing reference stays 7.

Swipe horizontally to compare every column →

Read only the constraints actually supplied

The complete Tutor/Student DDL in this lesson does not declare TutorID NOT NULL. It therefore allows a missing association where the DBMS permits NULL; the non-null school rule in Lesson 044 was a separately stated scenario constraint. To require every student to have a tutor, that additional requirement must be declared too.

Core explanation · Exam essentials

  • FOREIGN KEY identifies the local field; REFERENCES identifies the parent table and key.
  • Each non-null value must match the parent; repeated child references are permitted.
Common misconception

REFERENCES must name the parent table and key, not simply repeat the child table's primary-key name.

Check your understanding

Why does defining Student.TutorID not create a Tutor row for value 9?

Check your answer

The declaration only defines and checks the reference; the parent record must be inserted separately.

06

Alter an existing table definition

S8.09.A03

Visual overview

Extend a definition

ALTER TABLE changes the structure of an existing table. To add Email to the Student definition, identify the existing table and supply the new field name and type after ADD. Existing student records remain present.

Separate the field from its value

In this example the added Email field is nullable and has no default, so existing records initially have no supplied email value. Setting an email for one student is a later UPDATE operation. The new attribute and the value in one occurrence are separate changes.

Prepare to add constraints to existing tables

For the next independent example, Tutor(TutorID INTEGER, TutorName VARCHAR(40)) and Student(StudentID INTEGER, TutorID INTEGER) already exist without the two constraints being added. Tutor contains (7, Jo), Student contains (21, 7). TutorID values in Tutor are distinct and non-null; every student tutor reference matches.

Worked example · Add a contact field

  1. Existing structure

    Student already exists from the preceding definition.

  2. DDL

    ALTER TABLE Student ADD Email VARCHAR(80);

  3. Result

    Email is available in the table definition. This statement does not assign a particular student's address.

Worked example · Add keys after the tables already exist

  1. Prerequisite

    Use the separate unconstrained Tutor/Student tables and records stated above, not the earlier tables whose keys are already declared.

  2. Add the parent key, then the child reference
    ALTER TABLE Tutor ADD PRIMARY KEY (TutorID);
ALTER TABLE Student ADD FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID);
  3. Final structure and data

    Tutor.TutorID is now the primary key and Student.TutorID a foreign key. The records remain Tutor(7, Jo) and Student(21, 7).

  4. Check an invalid starting state

    If Student instead contained (21, 9) while only tutor 7 existed, adding the foreign-key constraint would fail until the data or intended relationship was corrected.

Core explanation · Exam essentials

  • ALTER TABLE can add a field or a primary/foreign-key constraint to an existing table.
  • Adding a constraint requires existing data to satisfy it; adding a field does not fill its values.
Common misconception

UPDATE changes values in defined fields; it does not add the new Email field to the schema.

Check your understanding

Student.TutorID exists but has no reference constraint. Tutor.TutorID is already the primary key. Write the statement that adds the link.

Check your answer

ALTER TABLE Student ADD FOREIGN KEY (TutorID) REFERENCES Tutor(TutorID);

Question 1 · Command word: Write2 teacher marks

Write an SQL statement to create a database named SportsCentre. State whether it creates any Booking records.

S8.09.A01
Answer and checking points — teacher-written

One valid SQL answer

CREATE DATABASE SportsCentre;
  1. CREATE DATABASE SportsCentre;
  2. It does not create Booking records; a table definition and record insertions are separate operations.

Common error: Use the database identifier requested, without confusing it with a table name.

Question 2 · Command word: Write7 teacher marks

Write CREATE TABLE for Event with EventID (whole number), Code (one character), EventName (up to 30 characters), Confirmed (true/false), Duration (fractional hours), EventDate (calendar date) and StartTime (time of day). Use the seven syllabus data types. Then check whether Code = "AB" and Duration = 1.5 match your chosen field definitions, explaining both decisions.

S8.09.A02
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Event (
    EventID INTEGER,
    Code CHARACTER(1),
    EventName VARCHAR(30),
    Confirmed BOOLEAN,
    Duration REAL,
    EventDate DATE,
    StartTime TIME
);
  1. EventID uses INTEGER in the Event table definition.
  2. Code uses CHARACTER(1); "AB" exceeds the declared length.
  3. EventName uses VARCHAR(30).
  4. Confirmed uses BOOLEAN.
  5. Duration uses REAL and can represent the supplied fractional value 1.5.
  6. EventDate uses DATE.
  7. StartTime uses TIME, with valid comma-separated field definitions inside CREATE TABLE brackets.

Common error: Each type must match the field's meaning; do not quote type names as data values.

Question 3 · Command word: Write2 teacher marks

Write DDL to add Room, containing at most 12 characters, to the existing Event table. Explain why an UPDATE statement is insufficient.

S8.09.A03
Answer and checking points — teacher-written

One valid SQL answer

ALTER TABLE Event ADD Room VARCHAR(12);
  1. ALTER TABLE Event ADD Room VARCHAR(12);
  2. The new field must first be introduced into the definition; UPDATE only assigns existing fields.

Common error: Adding a column and filling its values are distinct operations.

Question 4 · Command word: Write3 teacher marks

Write a Locker table definition containing LockerID as INTEGER and Location as VARCHAR(30), making LockerID its primary key. State the two requirements this identifier must satisfy.

S8.09.A04
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Locker (LockerID INTEGER, Location VARCHAR(30), PRIMARY KEY (LockerID));
  1. The definition declares PRIMARY KEY (LockerID).
  2. LockerID values must be unique across Locker records.
  3. A record must not have a null LockerID.

Common error: Do not substitute a unique-looking example value for a declared key constraint.

Question 5 · Command word: Write3 teacher marks

Locker(LockerID) already has its primary key. Write Allocation with integer AllocationID as primary key and integer LockerID as a foreign key to Locker. Explain whether several allocations can reference the same locker under these constraints alone.

S8.09.A05
Answer and checking points — teacher-written

One valid SQL answer

CREATE TABLE Allocation (AllocationID INTEGER, LockerID INTEGER, PRIMARY KEY (AllocationID), FOREIGN KEY (LockerID) REFERENCES Locker(LockerID));
  1. Allocation defines its two integer fields and its own AllocationID primary key.
  2. FOREIGN KEY (LockerID) REFERENCES Locker(LockerID) declares the parent link.
  3. Repeated LockerID references are permitted unless an additional uniqueness rule forbids them.

Common error: The referencing field and the referenced table/key must all be named.

Question 6 · Command word: Write3 teacher marks

Venue(VenueID INTEGER PRIMARY KEY) and Booking(BookingID INTEGER PRIMARY KEY, VenueID INTEGER) already exist. Venue contains 4; Booking contains (20, 4). Write ALTER TABLE to add the missing foreign key. Explain the resulting constraint and whether this same addition would succeed if Booking instead contained (20, 9).

S8.09.A03S8.09.A05
Answer and checking points — teacher-written

One valid SQL answer

ALTER TABLE Booking ADD FOREIGN KEY (VenueID) REFERENCES Venue(VenueID);
  1. ALTER TABLE Booking ADD FOREIGN KEY (VenueID) REFERENCES Venue(VenueID);
  2. Each non-null Booking.VenueID must match Venue.VenueID; the successful addition preserves (20, 4).
  3. With (20, 9) and no venue 9, the existing data violates the proposed constraint, so adding it fails until the mismatch is corrected.

Common error: ALTER adds a missing rule to the existing table; do not recreate it or add the already-existing field.

Question 7 · Command word: Describe3 teacher marks

Describe the structure and initial record count produced by the supplied SQL. Explain what changing VARCHAR(12) to VARCHAR(20) changes.

Supplied SQL definition

CREATE TABLE Badge (BadgeID INTEGER, Label VARCHAR(12), PRIMARY KEY (BadgeID));

Answer and checking points — teacher-written
  1. Badge has BadgeID INTEGER and Label VARCHAR(12); BadgeID is the primary key, with distinct non-null identifiers.
  2. The table initially contains zero records; CREATE TABLE does not insert a badge.

Reading the question — teacher guidance

Read the sample values before choosing types: ExamID contains leading zeros. Part (c) changes an existing table’s relationship, not the data stored in its rows.

Solution / model answer — teacher-written
CREATE TABLE EXAM(
    ExamID VARCHAR(8) NOT NULL,
    Subject VARCHAR(40),
    Level INTEGER,
    TotalMarks INTEGER,
    PRIMARY KEY (ExamID)
);

ALTER TABLE EXAM_QUESTION
ADD FOREIGN KEY (ExamID) REFERENCES EXAM(ExamID);

Text preserves an identifier such as 00956124. Level and TotalMarks are whole-number fields. The second statement makes ExamID in EXAM_QUESTION refer to the primary key of EXAM. The text lengths shown here are teacher choices sufficient for the supplied examples.

Summary

Read exact SQL

Identify the object, names, operators and values actually supplied.

Define fields

Match whole numbers, fractional values, text, truth values, dates and times to appropriate types.

Declare relationships

State primary and foreign-key constraints explicitly and create the referenced definition first.

Alter structure

Use ALTER TABLE for definition changes and a separate data operation to assign values.
