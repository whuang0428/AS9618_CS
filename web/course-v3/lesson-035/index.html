6.1.4

Threats to computer and data security

Virus · a host runs, and the code replicates

  • A virus is a type of malware.
  • An unopened infected file can be present without its code having run.
  • Copying a file is not itself proof that a virus infected it.
Exam evidence9618/11/O/N/25 · Q8(a), 2 marks across two threats · self-replication and file modification/deletion identify the virus description (QP p14; MS p13).

Spyware · secretly collect and send information

  • It does not need to replicate like a virus.
  • The target can be passwords, browsing activity or other private information.
  • Deleting local spyware does not erase copies already sent away.
Exam evidence9618/12/O/N/23 · Q5(c), 4 marks across phishing and spyware · monitoring, keystrokes and disclosure (QP p8; MS p6).

Hackers · gaining access without authorisation

  • A person is the actor; a virus or spyware is software.
  • A stolen correct password may pass the login check without making the access authorised.
  • Do not assume every successful intrusion deletes data; identify the stated consequence.
Exam evidence9618/12/O/N/25 · Q5(e), 3 marks · unauthorised access and suitable precautions (QP p9; MS p8).

Phishing · a deceptive message prompts the victim to act

Exam evidence9618/12/O/N/23 · Q5(c) · phishing email description (QP p8; MS p6).9618/13/O/N/23 · Q8(b), 2 marks · compare phishing with pharming (QP p12; MS p8).

Pharming · the destination changes despite the intended address

  • Both phishing and pharming can imitate a trusted organisation and seek personal information.
  • Phishing centres on a deceptive message and user response.
  • Pharming centres on a changed route to a website.
Exam evidence9618/13/O/N/23 · Q8(b), 2 marks · one difference and one similarity (QP p12; MS p8).9618/11/O/N/25 · Q8(a) · identifying pharming from redirection (QP p14; MS p13).

6.1.5

Reduce the risks posed by threats

Match each threat to a precaution and a recovery action

Threat → intervention → remaining risk
ThreatPrevention / risk reductionWhat the measure doesIf the incident has occurred
VirusUse updated anti-virus; restrict untrusted downloads and execution.Recognises known infection and blocks or isolates the infected file before it can run or spread.Quarantine/remove the infection. Recover damaged data from a trusted backup; a backup does not remove active malware.
SpywareUse updated anti-spyware; install software only from trusted sources.Detects and disables software that secretly monitors or sends information.Remove it, then change exposed passwords through a trusted system. Information already disclosed may remain with the recipient.
HackersUse strong authentication, appropriate access rights, patches and firewall rules.Makes unauthorised entry harder, closes known weaknesses and limits permitted actions or connections.Disable compromised access, repair the exploited weakness and restore trusted operation. Investigate which data was accessed or changed.
PhishingFilter suspicious messages; check requests through a known independent contact; avoid unknown links or attachments.Reduces deceptive messages and prevents the requested disclosure to an impostor.If passwords were supplied, change them using the genuine service and report the attempt.
PharmingUse updated anti-malware and protect local/router/DNS settings; heed certificate warnings and independently verify suspicious destinations.Reduces malicious redirection and gives the user a reason to stop before entering private information.Remove the cause of redirection and restore trusted settings; change details disclosed at the fake site.

Exam description

Identify a suitable measure and explain the link: what it checks or changes, which stage of the threat it interrupts, and how this reduces the stated risk. A firewall is not a general cure for every malicious file, and encryption does not stop deletion.

Additional past-paper practice

Original question · Cambridge 9618/12

1. Describe phishing and spyware as different mechanisms

Cambridge 9618/12 · October/November 2023 · 5(c) · 4 marks

Selected parts: 5(c) [4].

Original question
Reading the question — teacher guidance

Explain the two named threats separately. One deceives a person into disclosure; the other secretly collects activity on a computer.

Solution / model answer — teacher-written

A phishing email pretends to come from a trusted or official organisation and tries to persuade the recipient to disclose private information, often through a link to an imitation login page.

Spyware is malicious software installed without the user’s knowledge that secretly records activity such as keystrokes and sends the collected information to a third party.

Official mark scheme
Why this earns marks — teacher explanation

Phishing and spyware each have a maximum of two marks, giving four overall. The scheme lists several spyware details; an extended spyware paragraph cannot compensate for omitting phishing.

Common mistakes — teacher analysis

An unwanted advertisement alone does not explain phishing. A phishing message does not have to install spyware to cause disclosure.

Teacher-written practice
Question 1 · Command word: Describe3 teacher marks

Describe how an infected shared program can spread a virus and state one possible effect on the receiving computer.

S6.04.A01
Answer and checking points — teacher-written
  1. Viral code is attached to the shared host program.
  2. Running the infected host allows the code to execute and replicate into other files.
  3. It may corrupt data, delete files or disrupt processing.

Common error: Give the host and execution stages, not just the word malware.

Question 2 · Command word: Explain3 teacher marks

Explain how spyware that records keystrokes could compromise a user's email account.

S6.04.A02
Answer and checking points — teacher-written
  1. The program covertly records the account identifier and password as they are typed.
  2. It transmits the captured credentials to a third party.
  3. The third party can attempt to impersonate the user at the email service.

Common error: Identify the collected information and its consequence.

Question 3 · Command word: Explain3 teacher marks

Explain how an unpatched network service can enable unauthorised access and how patching restricts this risk.

S6.04.A03S6.05.A01
Answer and checking points — teacher-written
  1. An attacker may exploit a known flaw in the exposed service.
  2. The exploit may allow actions without legitimate permission.
  3. A relevant patch repairs the flaw that provided this entry route.

Common error: Patching a software flaw is different from changing a weak password.

Question 4 · Command word: Explain3 teacher marks

An email says a student's account will close unless they sign in through its link. Explain two features of this phishing route and describe one suitable precaution.

S6.04.A04S6.05.A01
Answer and checking points — teacher-written
  1. The sender impersonates a trusted service and uses urgency.
  2. The link can deliver credentials to a fraudulent page.
  3. Open the known school site independently or contact school support using trusted details.

Common error: Do not verify a suspicious link by entering a real password into it.

Question 5 · Command word: Describe3 teacher marks

Describe how corrupting local name-resolution information can cause pharming even when a user types the correct address. State a suitable precaution.

S6.04.A05S6.05.A01
Answer and checking points — teacher-written
  1. The typed name is translated using the corrupted mapping.
  2. The resulting destination is an attacker-controlled site rather than the intended server.
  3. Restrict changes to name-resolution settings and investigate unexpected certificate warnings.

Common error: A deceptive email is not necessary for this route.

Question 6 · Command word: Suggest2 teacher marks

Suggest two different precautions for a shared computer where users install unknown downloads, and explain the specific risk addressed by each.

S6.05.A01
Answer and checking points — teacher-written
  1. Restrict software installation to reduce unapproved executable code entering the system.
  2. Maintain anti-malware scanning to detect and isolate malicious code that still reaches the computer.

Common error: Accept another control only when its mechanism addresses the stated installation risk.
