Internet threats, malware and access restriction

Distinguish malware, unauthorised access, phishing and pharming, then match precautions to the route of each threat.

01

Viruses attach to a host and replicate

S6.04.A01

Visual overview

Identify the host and activation event

A virus attaches to or modifies a host file or program. A shared or downloaded infected host provides a route to another computer, but the arrival of the file and the execution of its code are different events. In the executable-host model used here, running the infected program runs the attached code.

Separate spread from impact

The virus can copy its code into additional hosts, creating further opportunities to execute and spread. Its payload may alter or delete data or disrupt normal processing. Replication describes how it spreads; the payload describes harmful actions it performs. A virus need not immediately erase every file to count as an infection.

Explain the link to a precaution

Avoiding untrusted execution and controlling software installation reduce opportunities for the code to run. Updated anti-virus can detect and isolate recognised infection; a trusted backup may support recovery after damage. None of these precautions can be justified merely by saying that it makes the computer safe: identify the stage it interrupts.

Worked example · Follow one infected shared program

  1. Initial state

    Computer A has an infected drawing program. Computer B has two clean executable files and an independent backup of its work.

  2. Arrival

    The program is copied to B. In this stated model it has not yet executed on B.

  3. Execution and replication

    A user runs it. The viral code executes and infects one other executable on B; that file can now carry infection when shared or run.

  4. Possible impact

    Its payload corrupts a saved drawing. Detection and isolation address the infected files; recovery of the drawing requires a usable clean copy.

  5. Changed condition

    If the copied host is detected and quarantined before execution, this execution-and-replication path is interrupted.

Core explanation · Exam essentials

  • A virus infects a host file or program; executing the infected host can run the viral code and spread infection.
  • Explain arrival, execution, replication and possible damage separately.
Common misconception

A virus is code, not a person gaining unauthorised access.

Check your understanding

Which event activates the virus in this model: downloading or running the infected host?

Check your answer

Running the host executes the attached code; merely describing a download is not a complete mechanism.

02

Spyware monitors and discloses

S6.04.A02

Visual overview

Name the captured information

Spyware can log keystrokes, record the screen or collect browsing activity without the user's informed awareness. Identify what is collected: a typed password, a visible customer record, or activity history. Merely saying that information is stolen omits the mechanism. Not every openly declared monitoring or analytics function is automatically spyware.

Follow collection into disclosure

A monitoring component can store a log and send it to a third party. A keylogger may therefore expose credentials for another service, even though the spyware is installed on the local computer. The recipient can try to impersonate the user. Removing the local component does not erase that separate log.

Use behaviour to distinguish threats

Spyware need not infect other executable hosts. A single program can both replicate like a virus and collect secrets like spyware; classify the behaviours rather than forcing a mutually exclusive label. Controlled installation reduces entry, and anti-spyware addresses detected monitoring components. L034 explains the response after exposure.

Worked example · A local keylogger affects a separate email service

  1. Capture

    On the shared computer, a user types their email account identifier and password. The keylogger records the keystrokes.

  2. Disclosure

    The component sends a log to a third party. The email service itself need not have been infected.

  3. Misuse

    The recipient attempts to sign in to the email service using the captured credentials.

  4. Response and final state

    Isolate and remove the component, then invalidate exposed credentials using a trusted device. The old password can cease to work, but the recipient may retain information obtained earlier.

Core explanation · Exam essentials

  • Spyware secretly collects activity or information and may disclose it to a third party.
  • Covert collection, not self-replication, defines the behaviour; one program can have several malicious behaviours.
Common misconception

Do not substitute a virus replication explanation for spyware's collection mechanism.

Check your understanding

Why can a keylogger threaten an account on a different website?

Check your answer

It may capture that website's credentials when the user types them and disclose them to an attacker.

Separate accepted credentials from legitimate permission

In this syllabus security context, hackers attempt or gain unauthorised access to systems or data. Access is unauthorised because the person lacks legitimate permission, even if the system accepts a guessed or stolen password. The label refers here to an access threat rather than every possible use of the word hacker.

Diagnose the entry route

A weak password permits guessing; a disclosed password permits impersonation; an unpatched vulnerability can allow unintended actions through a software flaw. These are different entry routes. Replacing a password does not repair a vulnerable service, and a patch does not automatically invalidate a previously stolen credential.

Distinguish preventing access from limiting its impact

After access, permissions determine which records and operations the compromised account can reach. Least privilege limits unnecessary access but does not make the intrusion legitimate. Restrict exposed services, apply relevant patches and strengthen authentication according to the stated cause. Record the remaining risk instead of claiming complete prevention.

Worked example · A receptionist account is impersonated

  1. Conditions

    A receptionist account may read appointment times but cannot modify medical notes. An intruder guesses its password.

  2. Login

    The credential check succeeds for the account, but the intruder still lacks legitimate authorisation to act as its owner.

  3. Allowed account action

    The intruder can see appointment times available to that identity, creating a disclosure risk.

  4. Denied account action

    The service rejects a request to change medical notes. Restricted permissions limit the impact of the compromised account.

  5. Reduce recurrence

    Replace the exposed secret, limit guessing attempts and consider an additional authentication factor. Do not claim that the read-only medical restriction stopped the original login.

Core explanation · Exam essentials

  • Unauthorised access may exploit stolen or guessed credentials, exposed services or software flaws.
  • Match authentication, patches and restricted permissions to the relevant route or consequence.
Common misconception

Successful login using stolen credentials can still be unauthorised access.

Check your understanding

A stolen student password works. Does that make the intruder authorised?

Check your answer

No. Possessing the secret does not give the intruder legitimate permission.

04

Phishing persuades the user

S6.04.A04

Visual overview

Explain persuasion and the requested action

Phishing uses a deceptive email, text message or other communication to impersonate a trusted person or organisation. Urgency, a familiar logo and a plausible sender name can persuade the recipient to disclose private information or act unsafely. The message may direct the user to a copied sign-in page, but installing malware is not necessary for credential theft.

Follow the information or instruction

Trace where the action sends information. If a user submits credentials to an attacker-controlled form, they reach the attacker rather than the intended service. If the message requests a payment change, the harm can result from following that instruction even without a fake login page. Describe the stated route instead of assuming every phishing attempt works identically.

Explain why the independent channel matters

Use an independently known address or trusted contact record to verify the request. A phone number or reply address inside the suspicious message may also belong to the attacker. Filtering and training reduce exposure, and an additional authentication factor can reduce some consequences of a stolen password; it does not make every deceptive instruction harmless.

Worked example · Two outcomes for the same support message

  1. Message

    An urgent message claims school support will close the account today unless the user follows a sign-in link.

  2. Unsafe branch

    The user opens the copied page and enters credentials. The form sends them to the attacker; no virus installation is required for this disclosure.

  3. Independent branch

    The user opens the school portal from a previously known address or contacts support using a trusted directory. Support confirms there is no such request.

  4. Decision

    Reject and report the deceptive request without entering credentials into its form. A convincing logo did not authenticate the sender.

Core explanation · Exam essentials

  • A phishing communication impersonates a trusted source and induces disclosure or an unsafe action.
  • Verify the request using independently known contact details or a known service, not the message’s supplied route.
Common misconception

A convincing logo or urgent tone is not proof of the sender's identity.

Check your understanding

Why should the phone number in the suspicious email not be used to verify it?

Check your answer

The attacker may control that number as well as the message.

05

Pharming changes the destination

S6.04.A05

Visual overview

Recall the normal resolution step

Normally the browser needs an address for the intended domain name before contacting its server. Lesson 014 separates DNS name resolution from the later web request. Pharming manipulates the destination, for example by corrupting a DNS record or local name-resolution entry, so the intended name leads to an attacker-controlled server.

Locate the change before the page is returned

The user may type the correct name and receive a convincing imitation page. Unlike the phishing route taught alongside it, no deceptive link is needed to start this redirection. Merely advising the user to type the address does not repair a corrupted mapping. The two routes can also be combined in a wider attack.

Match the precaution to the destination problem

Restrict unauthorised changes to resolution settings, maintain relevant software and investigate unexpected certificate or hostname warnings. An HTTPS indicator describes an encrypted connection and its certificate context, not a guarantee that every site or request is honest. Certificate acquisition and TLS protocol details are outside this AS explanation.

Worked example · The correctly typed payroll address

  1. Normal state

    The known payroll name maps to the real payroll server. The browser then requests its sign-in page.

  2. Changed state

    An unauthorised edit replaces a local name mapping with the attacker’s destination. The legitimate name itself is unchanged.

  3. Request

    A user types the correct known name. Resolution uses the corrupted mapping and the request reaches the attacker’s server.

  4. Consequence

    The imitation form can disclose entered credentials. This route is pharming even without an email link.

  5. Recovery and check

    Repair the unauthorised mapping and its entry route, then check that the intended name resolves to the intended service. Investigate warnings; do not assume that a familiar page appearance proves recovery.

Core explanation · Exam essentials

  • Pharming redirects a user to a fraudulent destination, for example through corrupted DNS or local name-resolution information.
  • A correctly typed name can still be misdirected; protect resolution settings and investigate certificate or hostname warnings.
Common misconception

Not every fake website visit is pharming; identify how the destination was selected.

Check your understanding

A correct typed address resolves through a corrupted hosts entry. Which threat fits?

Check your answer

Pharming: the destination has been redirected without requiring a deceptive link.

Build a reasoned recommendation

Start with the mechanism rather than a product. Ask what permits entry, what the attacker or code then does, and which data or service is affected. Map a control to that stage: patches repair known flaws, limited installation reduces unapproved execution, and independent confirmation challenges a deceptive request.

Different purposes in a response

PurposeExampleImportant limit
PreventionRestrict new software installation or unnecessary access.A permitted program or compromised account may still be misused.
Detection and containmentIdentify and quarantine recognised malicious code.Unknown threats may escape detection; earlier damage may remain.
RecoveryRestore a trusted saved state to a usable system.The backup cannot prevent prior disclosure or recover changes it never captured.

Test whether the proposed control reaches the risk

Physical protection, staff procedures and technical controls can complement each other. For a lost drive, restricting server permissions is insufficient for a readable independent copy; encryption and key protection fit that exposure. For a fake payment request, an encrypted disk does not authenticate the instruction. Reconsider the recommendation when the scenario changes.

Worked example · Change the risk, then change the response

  1. Shared laboratory

    Users install unknown downloads. Restrict installation and scan for recognised malicious code: these reduce entry and support detection.

  2. One layer fails

    A permitted connection delivers a new undetected keylogger. Connection filtering alone has not established safe content.

  3. Respond

    Isolate the affected system/component, investigate, restore trusted operation and address disclosed credentials from a trusted device.

  4. Different incident

    An unchanged results file is intentionally emailed outside the permitted audience. Focus on access, disclosure procedures and recipient checks; restoring a backup cannot recall the recipient’s copy.

Core explanation · Exam essentials

  • A justified precaution interrupts a threat route or reduces a specified consequence.
  • Combine prevention, detection and recovery; state what each measure does and what remains.
Common misconception

Encryption of a file does not decide whether an email is a truthful request.

Check your understanding

Can a backup prevent phishing?

Check your answer

No. It supports recovery after loss; it does not authenticate a message or prevent disclosure.

  1. The program covertly records the account identifier and password as they are typed.
  2. It transmits the captured credentials to a third party.
  3. The third party can attempt to impersonate the user at the email service.

Common error: Identify the collected information and its consequence.

  2. The exploit may allow actions without legitimate permission.
  3. A relevant patch repairs the flaw that provided this entry route.

  2. The link can deliver credentials to a fraudulent page.

Original question · Cambridge 9618/12

1. Describe phishing and spyware as different mechanisms

Cambridge 9618/12 · October/November 2023 · 5(c) · 4 marks

Selected parts: 5(c) [4].

Reading the question — teacher guidance

Explain the two named threats separately. One deceives a person into disclosure; the other secretly collects activity on a computer.

Solution / model answer — teacher-written

A phishing email pretends to come from a trusted or official organisation and tries to persuade the recipient to disclose private information, often through a link to an imitation login page.

Spyware is malicious software installed without the user’s knowledge that secretly records activity such as keystrokes and sends the collected information to a third party.

Official mark scheme
Why this earns marks — teacher explanation

Phishing and spyware each have a maximum of two marks, giving four overall. The scheme lists several spyware details; an extended spyware paragraph cannot compensate for omitting phishing.

Common mistakes — teacher analysis

An unwanted advertisement alone does not explain phishing. A phishing message does not have to install spyware to cause disclosure.
