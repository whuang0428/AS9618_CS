Internet threats, malware and access restriction

Distinguish malware, unauthorised access, phishing and pharming, then match precautions to the route of each threat.

Did the attack execute code, gain access, deceive a person or redirect a destination?

Concept teaching

01

Viruses attach to a host and replicate

S6.04.A01

Visual overview

Core explanation

Trace host-based replication
  1. Attach: Virus code attaches to or modifies a host file or program.
  2. Execute: Running the infected host can run the virus.
  3. Replicate: The virus can infect further files; a payload may corrupt, delete or disrupt data.
Control the route into execution

Shared files, networks and downloaded attachments can carry infected hosts to another computer. Avoid executing untrusted files and maintain detection software to reduce the risk.

Follow an infected host

  1. ArrivalAn infected program is downloaded.
  2. ExecutionThe user runs its host program.
  3. ReplicationViral code infects additional host files.
  4. ImpactData or normal processing may be damaged.
Common misconception

A virus is code, not a person gaining unauthorised access.

Check your understanding

Which event activates the virus in this model: downloading or running the infected host?

Check your answer

Running the host executes the attached code; merely describing a download is not a complete mechanism.

02

Spyware monitors and discloses

S6.04.A02

Visual overview

Core explanation

Spyware covertly monitors activity or collects data, for example by logging keystrokes or recording the screen. Collected information may be sent to a third party, exposing private details or credentials.

Its defining feature is covert collection, not necessarily self-replication. Anti-spyware can address the installed component, while controlled installation and caution with downloads reduce entry opportunities.

Common misconception

Do not substitute a virus replication explanation for spyware's collection mechanism.

Check your understanding

Why can a keylogger threaten an account on a different website?

Check your answer

It may capture that website's credentials when the user types them and disclose them to an attacker.

Unauthorised access by hackers

Core explanation

In this security context, a hacker gains or attempts unauthorised access to a system or its data. Weak credentials, exposed services or unpatched vulnerabilities can provide an entry route.

The resulting access may permit disclosure, alteration or disruption. Strong authentication reduces impersonation, software patches address known vulnerabilities, and access rights limit what a compromised account can do.

Common misconception

Successful login using stolen credentials can still be unauthorised access.

Check your understanding

A stolen student password works. Does that make the intruder authorised?

Check your answer

No. Possessing the secret does not give the intruder legitimate permission.

04

Phishing persuades the user

S6.04.A04

Visual overview

Core explanation

Recognise the persuasion mechanism
  1. Impersonation: A message claims to come from a trusted person or organisation.
  2. Unsafe action: Urgency or a pretext encourages disclosure, a link click or another unsafe action.
  3. Credential capture: A linked fake sign-in page can collect the supplied password.
Check independently

Verify a request through an independently obtained contact or known website. Filtering and training reduce exposure. Multi-factor authentication can reduce the impact of a stolen password, but does not make every deceptive request harmless.

A deceptive sign-in request

  1. ImpersonationMessage claims to come from school support.
  2. PressureIt says the account will close today.
  3. InteractionUser follows a link to a copied sign-in page.
  4. DisclosureThe entered password goes to the attacker.

Worked example · Verify a payment change

  1. Message

    An email asks the bursar to use a new bank account immediately.

  2. Independent check

    The bursar calls the supplier using the number already held in the supplier register.

  3. Decision

    The supplier denies the change, so the request is rejected without using contact details from the email.

Common misconception

A convincing logo or urgent tone is not proof of the sender's identity.

Check your understanding

Why should the phone number in the suspicious email not be used to verify it?

Check your answer

The attacker may control that number as well as the message.

05

Pharming changes the destination

S6.04.A05

Visual overview

Core explanation

Trace the changed destination
  1. Correct entry: The user may type the intended address correctly.
  2. Corrupted resolution: DNS or local name-resolution information redirects the lookup.
  3. Fraudulent site: The resulting destination belongs to the attacker rather than the intended service.
Address the redirection

Protect name-resolution settings, update affected software and investigate certificate or hostname warnings. An HTTPS indicator alone does not prove legitimacy; check the intended destination and do not ignore a certificate mismatch.

Common misconception

Not every fake website visit is pharming; identify how the destination was selected.

Check your understanding

A correct typed address resolves through a corrupted hosts entry. Which threat fits?

Check your answer

Pharming: the destination has been redirected without requiring a deceptive link.

Match precautions to the threat

S6.05.A01

Core explanation

A useful precaution interrupts a specific route or reduces a specific consequence. Explain that link: patching repairs a known software weakness, permission restrictions reduce exposure, and independent verification challenges a deceptive request.

Controls reduce risk rather than eliminate every possible incident. Combining prevention, detection and recovery allows a response when one measure fails. Choose controls appropriate to the system and explain what remains outside each control's role.

Common misconception

Encryption of a file does not decide whether an email is a truthful request.

Check your understanding

Can a backup prevent phishing?

Check your answer

No. It supports recovery after loss; it does not authenticate a message or prevent disclosure.

Cambridge command words

Practice questions

Question 1 · Command word: Describe3 marks

Describe how an infected shared program can spread a virus and state one possible effect on the receiving computer.

S6.04.A01
Answer and marking points
  1. Viral code is attached to the shared host program.
  2. Running the infected host allows the code to execute and replicate into other files.
  3. It may corrupt data, delete files or disrupt processing.

Common error: Give the host and execution stages, not just the word malware.

Question 2 · Command word: Explain3 marks

Explain how spyware that records keystrokes could compromise a user's email account.

S6.04.A02
Answer and marking points
  1. The program covertly records the account identifier and password as they are typed.
  2. It transmits the captured credentials to a third party.
  3. The third party can attempt to impersonate the user at the email service.

Common error: Identify the collected information and its consequence.

Question 3 · Command word: Explain3 marks

Explain how an unpatched network service can enable unauthorised access and how patching restricts this risk.

S6.04.A03S6.05.A01
Answer and marking points
  1. An attacker may exploit a known flaw in the exposed service.
  2. The exploit may allow actions without legitimate permission.
  3. A relevant patch repairs the flaw that provided this entry route.

Common error: Patching a software flaw is different from changing a weak password.

Question 4 · Command word: Explain3 marks

An email says a student's account will close unless they sign in through its link. Explain two features of this phishing route and describe one suitable precaution.

S6.04.A04S6.05.A01
Answer and marking points
  1. The sender impersonates a trusted service and uses urgency.
  2. The link can deliver credentials to a fraudulent page.
  3. Open the known school site independently or contact school support using trusted details.

Common error: Do not verify a suspicious link by entering a real password into it.

Question 5 · Command word: Describe3 marks

Describe how corrupting local name-resolution information can cause pharming even when a user types the correct address. State a suitable precaution.

S6.04.A05S6.05.A01
Answer and marking points
  1. The typed name is translated using the corrupted mapping.
  2. The resulting destination is an attacker-controlled site rather than the intended server.
  3. Restrict changes to name-resolution settings and investigate unexpected certificate warnings.

Common error: A deceptive email is not necessary for this route.

Question 6 · Command word: Suggest2 marks

Suggest two different precautions for a shared computer where users install unknown downloads, and explain the specific risk addressed by each.

S6.05.A01
Answer and marking points
  1. Restrict software installation to reduce unapproved executable code entering the system.
  2. Maintain anti-malware scanning to detect and isolate malicious code that still reaches the computer.

Common error: Accept another control only when its mechanism addresses the stated installation risk.

Question 1 · Command word: Identify · 4 marks

Two staff members reach fake banking pages. Staff member A follows an urgent text-message link. Staff member B types the correct address, but a modified local lookup sends them elsewhere. Identify each threat and explain one suitable precaution for each route.

Answer and marking points
  • A is phishing because a deceptive communication persuades the recipient to use a supplied link.
  • B is pharming because the destination mapping redirects a correctly entered name.
  • A should reach the bank through an independently known address or contact.
  • B's device needs protected or repaired name-resolution settings, with suspicious certificate warnings investigated.

Common error: Distinguish the route, not simply the appearance of the fake page.

Question 2 · Command word: Explain · 3 marks

A downloaded utility copies code into other executable files and silently sends typed account details to an outsider. Explain why both virus and spyware descriptions apply, and suggest an appropriate detection response.

Answer and marking points
  • Infecting other executable hosts is viral replication.
  • Secretly collecting and sending typed credentials is spyware activity.
  • Updated anti-malware capable of virus and spyware detection can scan and isolate the utility and affected files.

Common error: One malicious program may have more than one behaviour.

Question 3 · Command word: Explain · 3 marks

An intruder uses a guessed receptionist password. The account can read appointment times but cannot edit medical records. Explain the unauthorised-access risk, what the restricted permissions achieved, and a precaution against a repeat login.

Answer and marking points
  • The intruder impersonates the receptionist and can disclose information readable by that account.
  • The lack of write permission limits alteration of medical records despite the successful login.
  • A harder-to-guess password, attempt limits or an additional authentication factor reduces this entry risk.

Common error: Permissions reduce the impact but do not make the stolen identity legitimate.

Lesson review

Summary

Virus

Host infection and replication can damage processing or data.

Spyware

Covert collection can disclose activity and credentials.

Hacking

Unauthorised access exploits credentials or system weaknesses.

Phishing and pharming

Distinguish persuasion from destination redirection.

Precautions

Name the interrupted route or reduced consequence.
