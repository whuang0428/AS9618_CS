Reconstruct a bitmap from its stored codes

Observe

A tiny image file

  • Width: 3 pixels; height: 2 pixels.
  • Each pixel has one bit: 0 = white, 1 = blue.
  • Pixel sequence: 1 0 1 0 1 0. Read each row from left to right, top row first.

Look, then discuss

How does the receiver know where the first row ends?

The six bits alone do not specify whether the image is 3 × 2 or 2 × 3. The dimensions and reading order are needed to reconstruct the intended grid.

Explain

Explanation · 1 / 3

Divide an image into pixels

A bitmap represents an image as a rectangular grid of pixels. Each stored pixel has one colour. Pixels are the smallest individual image elements in this representation; they are not tiny vector shapes with independent smooth boundaries.

Explanation · 2 / 3

Assign a binary colour code

Each available colour has a code. The stored pixel data consists of those codes in a defined sequence. In this one-bit example, two codes are enough for white and blue. Real formats may store colour components directly or use a palette that maps codes to colours.

Explanation · 3 / 3

Use the header to interpret the data

A bitmap file header contains information needed to interpret the image, such as dimensions and colour depth; formats may also record compression or other properties. The decoder uses the file format and this metadata to split and place the codes correctly. Pixel codes and header information perform different jobs.

Work together

Draw the six-pixel image

Use the supplied 3 × 2 one-bit file model.

Work together · 1 / 3

Read the first row

Take the first three codes: 1, 0, 1. Draw blue, white, blue.

Work together · 2 / 3

Read the second row

The remaining codes are 0, 1, 0. Draw white, blue, white underneath.

Work together · 3 / 3

Change one piece of metadata

If the width were instead 2 and the height 3, the same sequence would create rows 1 0, 1 0, 1 0. The colours survive but their positions change.

A correct bitmap needs both the ordered pixel data and the information required to interpret it.

Represent information · Concept 20

Give each pixel more colour choices

Observe

The same gradient, different choices

  • Keep the image at 8 × 8 pixels.
  • Represent its shades using 1, 2 or 4 bits per pixel.
  • Compare the number of available shades, not the number of squares.

Look, then discuss

Why can a larger colour depth make a gradient look less stepped?

With two shades, many different source tones must share the same stored colour. More available shades can distinguish smaller differences in the source.

Explain

Explanation · 1 / 3

Define colour depth

Colour depth is the number of bits used to represent the colour of each pixel. At n bits per pixel, up to 2ⁿ distinct colour codes are possible. One bit gives two choices; two bits give four; four bits give sixteen.

Explanation · 2 / 3

Connect choices to colour accuracy

If the available colours match the source better, each pixel can preserve a more accurate colour. With too few levels, gradual changes may appear as bands or steps. More depth does not add more pixel positions; it adds choices at each existing position.

Explanation · 3 / 3

Connect depth to data size

For a fixed width and height, doubling bits per pixel doubles the uncompressed pixel data. Increasing from 2 to 4 bits doubles storage per pixel but increases the number of codes from 4 to 16, a factor of four. These are different relationships.

Work together

Compare two versions of a 64-pixel image

Both images have 8 × 8 = 64 pixels. One uses 2 bits per pixel and the other 4.

Work together · 1 / 3

Count colour choices

2² = 4 possible colours versus 2⁴ = 16.

Work together · 2 / 3

Count pixel-data bits

64 × 2 = 128 bits versus 64 × 4 = 256 bits.

Work together · 3 / 3

Explain the trade-off

The second image can distinguish more colours at each position but needs twice the pixel-data storage. Header and palette costs are excluded here.

Colour choices grow exponentially with depth; data size grows in direct proportion to depth.

Represent information · Concept 21

Distinguish the stored grid from the display grid

Observe

One file displayed on two screens

  • Stored image: 800 × 600 pixels.
  • Screen A: 1280 × 720 display pixels.
  • Screen B: 1920 × 1080 display pixels.

Look, then discuss

Does opening the file on Screen B automatically create a 1920 × 1080 image file?

The file still contains 800 × 600 stored pixels. The display can map them onto its own pixel grid in different ways, but reading the file has not added original image detail.

Explain

Explanation · 1 / 3

Name the image resolution

Image resolution describes the stored pixel detail, here specified by width and height in pixels. An 800 × 600 image contains 480,000 pixels. At a fixed depicted area, capturing more pixels can preserve finer spatial detail.

Explanation · 2 / 3

Name the screen resolution

Screen resolution is the number of display pixels available across and down the screen. It describes the output device or display setting, not the stored image file. The physical size of the screen and the zoom setting also affect how large an image appears.

Explanation · 3 / 3

Explain enlargement and size changes

Enlarging a bitmap spreads its existing information over a larger display area. The viewer may repeat pixels or interpolate new values, but cannot recover detail never recorded. Creating an image with twice the width and twice the height gives four times as many pixels and, at fixed depth, four times the raw pixel data.

Work together

Double both dimensions before capture

Compare 400 × 300 and 800 × 600 images at the same colour depth.

Work together · 1 / 3

Count the original pixels

400 × 300 = 120,000 pixels.

Work together · 2 / 3

Count the new pixels

800 × 600 = 480,000 pixels, four times as many.

Work together · 3 / 3

Separate capture from zoom

Capturing with more pixels can preserve more original detail. Merely zooming the smaller saved image does not create the missing detail.

More display space and more recorded information are different things.

Build the bitmap-size calculation from units

Observe

A small image specification

  • Width: 120 pixels; height: 80 pixels.
  • Colour depth: 4 bits per pixel.
  • Calculate uncompressed pixel data only; exclude headers and palettes.

Look, then discuss

What must be counted before converting the result to bytes?

There are pixels in each row, rows in the image and bits in each pixel. Multiplying these counts produces bits, not bytes.

Explain

Explanation · 1 / 3

Count every pixel

Width × height gives the number of stored pixels. For this image, 120 × 80 = 9600 pixels. Do not add width and height; that does not count the rectangular grid.

Explanation · 2 / 3

Multiply by bits per pixel

Each of the 9600 pixels needs four bits, so pixel data occupies 9600 × 4 = 38,400 bits. This is the origin of width × height × colour depth; it is a count of repeated storage requirements.

Explanation · 3 / 3

Convert the requested unit

Divide by eight to obtain bytes, then use the correct prefix divisor if needed. Keep intermediate values unrounded. Add header or palette bytes only if supplied or required by the question. A compressed file cannot generally be sized from these properties alone.

Work together

Calculate the size in bytes and KiB

Use the supplied 120 × 80 image at four bits per pixel.

Work together · 1 / 3

Obtain bits

120 × 80 × 4 = 38,400 bits.

Work together · 2 / 3

Obtain bytes

38,400 ÷ 8 = 4800 bytes.

Work together · 3 / 3

Obtain KiB

4800 ÷ 1024 = 4.6875 KiB. Multiplying 4.6875 by 1024 returns 4800 bytes.

The units show why each operation is needed; the stated assumptions define what is included.

Experiment

Predict the byte count before revealing it. Change either the square grid size or colour depth, keeping the other setting fixed, and explain the multiplier. The grid control changes both dimensions together.

Original question · Cambridge 9618/12

1. Calculate the bitmap size in mebibytes

Cambridge 9618/12 · October/November 2023 · 6(c) · 2 marks

Selected parts: 6(c) [2].

Hint — reading the question

Width × height gives pixels; bit depth gives bits per pixel. The requested unit is mebibytes, and working is required. No header size is supplied.

Reasoning and model answer — teacher-written

Pixels = 2048 × 1024 = 2,097,152.

Pixel data = 2,097,152 × 10 = 20,971,520 bits.

Bytes = 20,971,520 ÷ 8 = 2,621,440.

Mebibytes = 2,621,440 ÷ (1024 × 1024) = 2.5 MiB.

Official mark scheme
Why this earns marks — teacher explanation

One mark is for correct working and one for 2.5 mebibytes. The complete expression (2048 × 1024 × 10) ÷ (8 × 1024 × 1024) also shows the method.

Common mistakes — teacher analysis

Omitting division by eight confuses bits and bytes. Dividing by 1,000,000 gives megabytes instead of mebibytes. Do not invent header overhead.

Draw an image from objects and properties

Observe

A two-object drawing list

  • 1. Rectangle: top-left (10, 10), width 40, height 20, blue fill, no outline.
  • 2. Line: (10, 30) to (50, 30), black, thickness 2.
  • Origin is top-left; x increases right and y increases down. Draw in list order.

Look, then discuss

Which information is needed to recreate the picture without storing every pixel colour?

The rectangle description supplies a type, position, dimensions and appearance. The line has endpoints and thickness. Together these descriptions instruct the renderer what to draw.

Recall

Read a coordinate pair

The pair (x, y) identifies a position. In this diagram, x is the horizontal distance from the left and y is the vertical distance from the top. This convention is stated explicitly; other coordinate systems can use a different origin or direction.

Explain

Explanation · 1 / 3

Store objects rather than a fixed pixel grid

A vector graphic stores a drawing list of objects or drawing commands. Objects can include lines, rectangles, circles and curves. The list describes how to construct them instead of prescribing a colour for every pixel of one fixed-resolution grid.

Explanation · 2 / 3

Record the properties needed by each object

A line needs endpoints or equivalent position and direction information, plus properties such as colour and line thickness. A rectangle needs a position, dimensions, fill and outline information. A circle can be described by a centre and radius. Properties depend on the object type.

Explanation · 3 / 3

Render the list in order

A renderer interprets the object descriptions and draws the image for an output device. Later objects may cover earlier ones. The screen still uses pixels to display the result; that does not make the source representation a bitmap.

Work together

Reconstruct the supplied drawing list

Use the top-left origin and draw the rectangle before the line.

Work together · 1 / 3

Locate the rectangle

Its left edge is x = 10 and top edge y = 10. Width 40 puts the right edge at x = 50; height 20 puts the bottom edge at y = 30.

Work together · 2 / 3

Draw the line

Join (10, 30) to (50, 30). The line lies on the rectangle’s lower edge and is visible because it is drawn afterward.

Work together · 3 / 3

Explain what is stored

The source contains object descriptions and properties, not a separate saved colour code for every screen pixel.

A complete vector description tells the renderer what to draw, where and with which appearance.

Original question · Cambridge 9618/12

1. Describe bitmap encoding and a vector drawing list

Cambridge 9618/12 · May/June 2024 · 2(d)(i), 2(d)(ii) · 5 marks

Selected parts: 2(d)(i) [3]; 2(d)(ii) [2].

Hint — reading the question

Use the same VR-video context for both answers, but distinguish the stored representation. Part (i) needs a sequence of pixel codes; part (ii) needs the contents of a drawing list.

Reasoning and model answer — teacher-written

2(d)(i): A bitmap consists of pixels, each with one colour. Each colour has a unique binary code, and the codes for the pixels are stored in sequence.

2(d)(ii): A vector drawing list contains objects to draw, with commands or descriptions for constructing them. Each object has properties such as coordinates, fill colour and line weight.

Official mark scheme
Why this earns marks — teacher explanation

Part (i) has three specific encoding points. Part (ii) allows at most two marks from the listed drawing-list features; the model answer supplies several linked details, not additional marks.

Common mistakes — teacher analysis

Describing enlargement or comparing file sizes does not answer what is encoded. Saying “vectors store pixels too” removes the essential distinction.

Represent information · Concept 24

Choose a representation for the task

Observe

Two enlargement jobs

  • A school logo must appear on a small badge and a large sign.
  • A photograph must preserve irregular colours, textures and fine detail.
  • Both will be displayed at several sizes.

Look, then discuss

Should both images be stored in the same way?

A logo often contains a manageable number of shapes and text elements. A photograph contains many small, irregular colour changes. Consider what each representation would need to describe.

Explain

Explanation · 1 / 3

Scale vector geometry

To enlarge a vector graphic, scale its coordinates and dimensions and render it again at the required output size. Edges are recalculated from the shapes, so enlarging the source does not expose a fixed grid of original image pixels. The final device still has finite resolution.

Explanation · 2 / 3

Explain bitmap enlargement

A bitmap starts with fixed recorded pixels. Enlargement repeats or interpolates this data, which can make edges look blocky or soft. A photograph can nevertheless suit a bitmap because a pixel grid directly records its complex colour variation.

Explanation · 3 / 3

Justify a choice from the task

Vector graphics suit many diagrams, logos and illustrations requiring scalable geometry or object editing. Bitmaps suit photographs and pixel-level editing. File-size advantages depend on content and complexity; neither representation is always smaller or always better.

Work together

Double the supplied vector drawing

Scale all coordinates, dimensions and line thicknesses by two.

Work together · 1 / 3

Scale the rectangle

Top-left (10, 10) becomes (20, 20). Width 40 becomes 80 and height 20 becomes 40.

Work together · 2 / 3

Scale the line

Endpoints (10, 30) and (50, 30) become (20, 60) and (100, 60). Thickness 2 becomes 4 under the stated rule.

Work together · 3 / 3

Explain the visual result

The renderer constructs the larger shapes from their properties. It does not enlarge a saved low-resolution grid of source pixels.

Scaling rules operate on geometry; the output is redrawn at the required size.

Describe how a bitmap's file header and ordered pixel values allow software to reconstruct the image.

S1.08.A01
Answer and checking points — teacher-written

  2. The pixel values encode the colour for each position in the grid.

Command word: Calculate4 teacher marks

Calculate the number of available colours at a depth of 4 bits per pixel. Explain the effects of increasing the depth to 8 bits while keeping image resolution unchanged.

S1.08.A03S1.08.A06
Answer and checking points — teacher-written
  1. Four bits provide 2^4 = 16 colours.
  2. Eight bits provide 2^8 = 256 colours.
  3. More available colours can represent colour differences more accurately.
  4. Uncompressed pixel-data size doubles because each pixel uses twice as many bits.

Common error: Colour depth changes the number of possible colour values, not the number of pixels.

Command word: Compare4 teacher marks

Compare image resolution with screen resolution. Explain the effects of capturing the same scene with twice as many pixels in each dimension, at unchanged colour depth.

S1.08.A02S1.08.A05
Answer and checking points — teacher-written
  1. Image resolution specifies the pixel dimensions of the stored image.
  2. Screen resolution specifies the pixel dimensions available on the display.
  3. Doubling both image dimensions gives four times as many pixels, allowing finer spatial detail to be captured.
  4. The uncompressed pixel data is four times larger at the same colour depth.

Common error: Changing the display or enlarging an existing bitmap does not recover detail absent from the original capture.

Command word: Calculate3 teacher marks

Calculate the complete size of a 40 × 20 bitmap at 4 bits per pixel with a 24-byte header and no other overhead. Repeat at 8 bits per pixel. Explain why the whole file does not exactly double.

S1.08.A04S1.08.A06
Answer and checking points — teacher-written
  1. Original pixel data: 40 × 20 × 4 / 8 = 400 bytes; complete file: 424 bytes.
  2. New pixel data: 40 × 20 × 8 / 8 = 800 bytes; complete file: 824 bytes.
  3. The pixel data doubles, but the 24-byte header remains fixed.

Common error: Keep header bytes separate from pixel bits until the units match.

A 200 by 100 bitmap uses 24-bit colour. Calculate its pixel-data size in bytes, ignoring the file header. Show your working.
