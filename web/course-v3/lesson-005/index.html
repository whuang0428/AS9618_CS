Bitmap and vector graphics

Reconstruct a bitmap, explain its quality and size, then render and scale a vector drawing list.

How are bitmap and vector graphics stored, what controls bitmap quality and file size, and what happens when each type is enlarged?

How a bitmap image is stored

S1.08.A01

Visual overview

Rebuild an image from ordered values

A bitmap stores an ordered rectangular grid of pixels. Each pixel is one position in that grid and has one selected colour value. The file stores codes for these values; a palette may map short codes to colours, or a format may store colour components directly.

Complete the code-to-pixel procedure

The supplied diagram is a 10-column, 6-row bitmap with two bits per pixel and a four-colour palette. Read row by row from the top left. The second row contains codes 00 01 01 00 00 00 01 01 00 00. Use the palette to replace each code with its colour while keeping its position. Repeating this for all six rows reconstructs the shown grid.

Explain why the metadata is needed

The header supplies information needed to interpret the data, such as width, height and colour depth. Here the width tells the reader to start a new row after every ten codes. The palette tells it which colour each code selects. A format can store other header information too; never assume every real header has the same fields or size.

Check the reconstructed data

There are 10 × 6 = 60 pixels, each needing two bits. The pixel data is 120 bits = 15 bytes. This count excludes the header and palette. The same 120 bits cannot be reconstructed correctly without the agreed dimensions, pixel order and colour mapping.

Core explanation · Exam essentials

  • A bitmap contains an ordered pixel grid and the information needed to interpret it.
  • Each pixel stores one colour value; its position matters.
  • Distinguish pixel-data size from the complete file size.
Common misconception

The file header describes how to interpret the bitmap; it is not one of the image pixels.

Check your understanding

Why does the reader need the bitmap width as well as the pixel values?

Check your answer

The width tells the reader where each row ends when rebuilding the two-dimensional arrangement.

02

Colour depth

S1.08.A03S1.08.A06

Visual overview

Count possible colour values

Colour depth is the number of bits used for one pixel’s colour code. With n bits there are 2ⁿ possible codes. One bit allows two colours; two bits allow four; four bits allow sixteen. The bits select one colour for a pixel, not several colours at once.

Change one variable at a time

The diagram uses the same 8 × 8 source pattern in every panel. Only the number of available grey levels changes. With 1, 2 and 4 bits per pixel, the raw pixel data uses 64, 128 and 256 bits: 8, 16 and 32 bytes respectively. Dimensions and pixel count stay fixed.

Explain quality and size together

More levels can represent smaller tonal differences, reducing visible banding when the source contains such differences. Doubling the depth from 2 to 4 bits doubles the raw data size but increases the possible colours from 4 to 16. Doubling bits does not merely double the colour count.

Choose depth for the content

A two-colour diagram may need only one bit per pixel. A photograph with many shades may benefit from more colour values. Raising the depth of an existing low-depth file adds representational capacity; it does not recover colours that were discarded earlier.

Core explanation · Exam essentials

  • n bits per pixel allows 2ⁿ colour codes.
  • Increasing depth can preserve finer colour or tonal differences.
  • At fixed dimensions, raw pixel-data size is proportional to colour depth.
Common misconception

Colour depth changes the bits stored for each pixel; it does not change the number of pixels in the image.

Check your understanding

How many colours can a three-bit pixel code select?

Check your answer

2³ = 8 possible colours.

Image resolution

S1.08.A02S1.08.A05

Name the grid being measured

Image resolution here means the dimensions of the stored pixel grid, such as 640 × 480 pixels. This is 640 columns and 480 rows, giving 307,200 pixels. A screen has its own pixel grid; showing an image on a larger screen does not change the image’s stored resolution.

Connect sampling density to detail

Capturing the same scene with more suitably measured pixels can preserve finer spatial detail. Doubling both dimensions gives four times as many samples and four times the raw data at the same depth. It does not merely double the file size.

Separate new capture from enlargement

Enlarging a stored bitmap instead copies or interpolates its existing pixel values. It cannot recover original scene detail that was never captured. Nearest-neighbour enlargement exposes square blocks; interpolation may smooth the boundaries but does not recreate the missing measurements.

Core explanation · Exam essentials

  • Stored image resolution specifies the pixel grid, independent of screen resolution.
  • At fixed depth, raw data size is proportional to width × height.
  • More captured pixels may retain detail; enlargement cannot restore absent source detail.
Common misconception

Image resolution describes the stored image and screen resolution describes a display; the two terms are not interchangeable.

Check your understanding

Does a higher-resolution screen add stored image pixels?

Check your answer

No. Screen resolution and stored image resolution describe different grids.

Uncompressed bitmap file size

S1.08.A04

Visual overview

Swipe horizontally to compare every column →

State the storage model

For an uncompressed bitmap under the stated simplified model, pixel-data bits = width × height × bits per pixel. Divide by eight for bytes. If an actual format adds a header, palette or row padding, include these only when their sizes or rules are supplied; compression requires a different calculation.

Worked file size: 640 × 480 pixels, 8 bits per pixel, 54-byte header

  1. Count pixels: 640 × 480 = 307,200 pixels.
  2. Count pixel-data bits: 307,200 × 8 = 2,457,600 bits.
  3. Convert to bytes and KiB: 2,457,600 / 8 = 307,200 bytes = 300 KiB of pixel data.
  4. Include the supplied header: 307,200 + 54 = 307,254 bytes. Assume no palette, padding or other overhead for this calculation.
  5. Check a changed depth: At 16 bits per pixel, data becomes 614,400 bytes. With the same 54-byte header the whole file is 614,454 bytes, not twice 307,254.

Keep the result within its assumptions

When dimensions, depth and overhead are specified, this is an exact count. Real compressed image sizes cannot be found from dimensions and depth alone because content and compression settings affect the stored size.

Core explanation · Exam essentials

  • Raw pixel bits = width × height × colour depth.
  • Divide bits by eight before applying byte prefixes.
  • Add stated overhead in consistent units; do not double a fixed header when depth doubles.
Common misconception

Do not multiply by the number of colours; multiply the pixel count by the number of bits stored per pixel.

Check your understanding

Why divide a bit total by eight to obtain bytes?

Check your answer

Each byte contains eight bits.

How a vector graphic is stored

S1.09.A01

Visual overview

Define the representation

A vector graphic stores descriptions of objects and their properties in a drawing list. The renderer interprets these descriptions to produce a visible image. Unlike a bitmap, the source does not have to list a colour for every output pixel.

Complete drawing list for the diagram

OrderObjectGeometryOther properties
1RectangleTop-left (10, 10); width 40; height 20Blue fill; no outline
2LineStart (10, 30); end (50, 30)Black stroke; thickness 2

Swipe horizontally to compare every column →

Render the list on a 60 × 45 canvas

  1. Establish coordinates: Origin (0, 0) is at the top left. x increases to the right; y increases downwards. Coordinates and thickness use the same arbitrary drawing units.
  2. Draw object 1: The rectangle extends from x = 10 to 50 and y = 10 to 30. Fill that area blue.
  3. Draw object 2: Draw the horizontal line from (10, 30) to (50, 30), with a black stroke of width 2 centred on the line.
  4. Check order: The line is drawn last, so it lies over the rectangle’s lower edge. Swapping overlapping objects can change which parts remain visible.

Generalise the drawing-list method

Different objects require different defining properties: a circle can use a centre and radius; a polygon can use a sequence of vertices. Colour, fill, line thickness and position are common properties. Include enough data to reconstruct the intended object instead of merely naming its shape.

Core explanation · Exam essentials

  • Vector files store object descriptions and properties in a drawing list.
  • Coordinates, dimensions, style and drawing order determine the rendered result.
  • Choose defining properties appropriate to each object type.
Common misconception

A vector file stores drawing objects and their properties, not the colour of every pixel in a fixed grid.

Check your understanding

Which coordinates can define a straight line in a drawing list?

Check your answer

Its start and end coordinates, with properties such as colour and thickness.

Explain why scaling differs

The vector renderer recalculates the objects from their descriptions for the required output size. Its geometry therefore retains smooth shapes under enlargement. A screen still displays a rasterised result on pixels: the advantage concerns the scalable source representation, not the absence of display pixels.

Compare the mechanisms

A bitmap has a fixed source grid. Enlarging it must copy or interpolate that grid, so edges can become blocky or blurred. A vector description instead continues to define the edge geometrically at the new size. Neither representation guarantees a smaller file in every case: complexity and encoding also matter.

Choose a representation from the requirement

Pixel-art game spriteBitmapThe deliberately designed pixel grid is part of the intended appearance.

Core explanation · Exam essentials

  • Enlargement of a bitmap uses its existing pixel grid.
  • Vector geometry can be recalculated at the output size.
  • Justify a choice using content, scaling and editing requirements.
Common misconception

Vector scaling stays smooth because objects are redrawn; it does not create missing photographic detail or make vector suitable for every image.

Check your understanding

Why can an enlarged bitmap show square edges?

Check your answer

Its fixed grid is enlarged; extra original scene detail is not created.

Command word: Justify4 teacher marks

A website needs a logo that will also appear on a large banner and a detailed photograph. Justify vector graphics for the logo and a bitmap for the photograph.

S1.09.A02S1.09.A03
Answer and checking points — teacher-written
  1. A logo's shapes can be represented as mathematical drawing objects.
  2. Those objects can be redrawn at banner size without enlarging stored pixels.
  3. A bitmap stores the photograph's many local colour variations as pixels.
  4. Describing that detailed photographic scene as individual vector objects would be impractical.

Common error: Relate each representation to the particular image, rather than claiming that one is always better.

Command word: Describe3 teacher marks

Describe how a bitmap's file header and ordered pixel values allow software to reconstruct the image.

S1.08.A01
Answer and checking points — teacher-written
  1. The header gives dimensions and colour depth needed to interpret the data.
  2. The pixel values encode the colour for each position in the grid.
  3. Software uses the dimensions and data order to place each decoded colour at its intended pixel position.

Common error: The header is metadata; it does not replace the colour data for individual pixels.

Command word: Calculate4 teacher marks

Calculate the number of available colours at a depth of 4 bits per pixel. Explain the effects of increasing the depth to 8 bits while keeping image resolution unchanged.

S1.08.A03S1.08.A06
Answer and checking points — teacher-written
  1. Four bits provide 2^4 = 16 colours.
  2. Eight bits provide 2^8 = 256 colours.
  3. More available colours can represent colour differences more accurately.
  4. Uncompressed pixel-data size doubles because each pixel uses twice as many bits.

Common error: Colour depth changes the number of possible colour values, not the number of pixels.

Command word: Compare4 teacher marks

Compare image resolution with screen resolution. Explain the effects of capturing the same scene with twice as many pixels in each dimension, at unchanged colour depth.

S1.08.A02S1.08.A05
Answer and checking points — teacher-written
  1. Image resolution specifies the pixel dimensions of the stored image.
  2. Screen resolution specifies the pixel dimensions available on the display.
  3. Doubling both image dimensions gives four times as many pixels, allowing finer spatial detail to be captured.
  4. The uncompressed pixel data is four times larger at the same colour depth.

Common error: Changing the display or enlarging an existing bitmap does not recover detail absent from the original capture.

Command word: Calculate3 teacher marks

Calculate the complete size of a 40 × 20 bitmap at 4 bits per pixel with a 24-byte header and no other overhead. Repeat at 8 bits per pixel. Explain why the whole file does not exactly double.

S1.08.A04S1.08.A06
Answer and checking points — teacher-written
  1. Original pixel data: 40 × 20 × 4 / 8 = 400 bytes; complete file: 424 bytes.
  2. New pixel data: 40 × 20 × 8 / 8 = 800 bytes; complete file: 824 bytes.
  3. The pixel data doubles, but the 24-byte header remains fixed.

Common error: Keep header bytes separate from pixel bits until the units match.

Original question · Cambridge 9618/12

1. Calculate the bitmap size in mebibytes

Cambridge 9618/12 · October/November 2023 · 6(c) · 2 marks

Selected parts: 6(c) [2].

Teacher solution and explanation

Width × height gives pixels; bit depth gives bits per pixel. The requested unit is mebibytes, and working is required. No header size is supplied.

Pixels = 2048 × 1024 = 2,097,152.

Pixel data = 2,097,152 × 10 = 20,971,520 bits.

Bytes = 20,971,520 ÷ 8 = 2,621,440.

Mebibytes = 2,621,440 ÷ (1024 × 1024) = 2.5 MiB.

One mark is for correct working and one for 2.5 mebibytes. The complete expression (2048 × 1024 × 10) ÷ (8 × 1024 × 1024) also shows the method.

Omitting division by eight confuses bits and bytes. Dividing by 1,000,000 gives megabytes instead of mebibytes. Do not invent header overhead.

Original question · Cambridge 9618/12

2. Describe bitmap encoding and a vector drawing list

Cambridge 9618/12 · May/June 2024 · 2(d)(i), 2(d)(ii) · 5 marks

Selected parts: 2(d)(i) [3]; 2(d)(ii) [2].

Reading the question — teacher guidance

Use the same VR-video context for both answers, but distinguish the stored representation. Part (i) needs a sequence of pixel codes; part (ii) needs the contents of a drawing list.

Solution / model answer — teacher-written

2(d)(i): A bitmap consists of pixels, each with one colour. Each colour has a unique binary code, and the codes for the pixels are stored in sequence.

2(d)(ii): A vector drawing list contains objects to draw, with commands or descriptions for constructing them. Each object has properties such as coordinates, fill colour and line weight.

Official mark scheme
Why this earns marks — teacher explanation

Part (i) has three specific encoding points. Part (ii) allows at most two marks from the listed drawing-list features; the model answer supplies several linked details, not additional marks.

Common mistakes — teacher analysis

Describing enlargement or comparing file sizes does not answer what is encoded. Saying “vectors store pixels too” removes the essential distinction.
