Develop a booking system · Concept 25

Understand the existing program before editing

Observe

The existing booking report

  • Read exactly three already valid requests, each an integer from 1 to 6.
  • Output the sum of their Seats values. Requests are independent; the sum is not a remaining-capacity calculation.
  • The new request is to report how many bookings contain at least 3 seats as well, without changing the original total.

Look, then discuss

Which old behaviour must remain, and which new information is missing?

Use 2, 3, 6. The total is 11, while two bookings meet the new group threshold. Counting qualifying bookings is different from totalling their seats.

Recall

Recall count versus total

A count increases by 1 for each qualifying item. A total increases by the item’s numeric value. Both need initialisation before repetition and final output after the relevant inputs have been processed.

Explain

Explanation · 1 / 3

State the current contract

The program receives three validated INTEGER quantities and outputs one sum. It does not validate raw input, process a sentinel or subtract bookings from Available. Preserve those assumptions while analysing this amendment.

Explanation · 2 / 3

Read the actual placement of operations

Total is initialised once, updated for every input and displayed once after the loop. Trace those statements before proposing new code.

DECLARE Index, Seats, Total : INTEGER
Total <- 0
FOR Index <- 1 TO 3
    INPUT Seats
    Total <- Total + Seats
NEXT Index
OUTPUT Total

Explanation · 3 / 3

Make an impact list for the new requirement

The additional count needs an INTEGER declaration, zero initialisation, a qualifying condition, an increment and a final output. The original total, input count and update remain. A heading saying “add group count” is not enough to locate all affected operations.

Work together

Establish a baseline for the amendment

Run a manual trace using input 2, 3, 6.

Work together · 1 / 2

Trace the original values

Total progresses 0 → 2 → 5 → 11. There is one final output, 11. No group counter currently exists.

Work together · 2 / 2

Write the new expected outcome before editing

The enhanced program should still output 11, then output 2 for the number of requests with at least 3 seats. The requested new output does not replace the old one.

A baseline identifies the old contract, current implementation and behaviour that the change must preserve.

Check

Try it yourself · Teacher-written

Why would replacing Total <- Total + Seats with Total <- Total + 1 fail the change request?

Check your reasoning

It would change the original sum into a count and lose the required total. Add a separate counter and retain the existing total update.

Look, then discuss

Where must the new counter start, change and be displayed?

Imagine initialising GroupBookings inside the loop. Then imagine displaying it before the loop finishes. Explain which required output each placement would break.

Recall

Recall overlapping responsibilities

Every request contributes its seats to Total. Some also add one to GroupBookings. These are not mutually exclusive alternatives: a qualifying request must contribute to both results.

Explain

Explanation · 1 / 4

Declare and initialise once

Declare GroupBookings as INTEGER and set it to 0 before the loop. Starting it inside the loop would erase earlier qualifying bookings.

Explanation · 2 / 4

Update at the correct scope

Retain Total <- Total + Seats for every input. Then use IF Seats >= 3 to increment GroupBookings by 1. The group test does not belong in an ELSE that would prevent its seats entering Total.

Explanation · 3 / 4

Output both final results

Place both output statements after NEXT so they describe the complete set. Keep the original result first, followed by the added count.

DECLARE Index, Seats, Total : INTEGER
DECLARE GroupBookings : INTEGER
Total <- 0
GroupBookings <- 0
FOR Index <- 1 TO 3
    INPUT Seats
    Total <- Total + Seats
    IF Seats >= 3 THEN
        GroupBookings <- GroupBookings + 1
    ENDIF
NEXT Index
OUTPUT Total
OUTPUT GroupBookings

Explanation · 4 / 4

Test boundaries, accumulation and preservation

Use 2 and 3 around the new inclusive threshold. Include no qualifying bookings, all qualifying bookings and several early qualifying bookings. For every set, check that the total matches the old program as well as checking the new count.

Work together

Expose a misplaced reset

Compare the correct enhancement with a version that resets GroupBookings to 0 on every loop visit.

Work together · 1 / 2

Use a sequence with repeated qualifying items

For 3, 4, 6 the correct outputs are total 13 and group count 3. The reset-inside-loop version ends with group count 1, so this sequence distinguishes the fault.

Work together · 2 / 2

Transfer to overlapping grade categories

In the separate mark example, Mark >= 70 is a merit and also a pass at >= 50. Two independent IF statements update both counts; ELSE would incorrectly exclude one. Input 49, 50, 69, 70 must yield 3 passes and 1 merit.

DECLARE Index : INTEGER
DECLARE Mark : INTEGER
DECLARE PassCount : INTEGER
DECLARE MeritCount : INTEGER
PassCount <- 0
MeritCount <- 0
FOR Index <- 1 TO 4
    INPUT Mark
    IF Mark >= 50 THEN
        PassCount <- PassCount + 1
    ENDIF
    IF Mark >= 70 THEN
        MeritCount <- MeritCount + 1
    ENDIF
NEXT Index
OUTPUT PassCount
OUTPUT MeritCount

Use complete datasets that would fail under plausible wrong amendments, not just one convenient example.

Check

Try it yourself · Teacher-written

For bookings 3, 1, 1, what are Total and GroupBookings? Why is this also useful for testing a counter reset inside the loop?

Check your reasoning

Total is 5 and GroupBookings is 1. A faulty counter reset on each iteration would lose the first qualifying booking and finish at 0 because the last two requests do not qualify.

Develop a booking system · Concept 27

Change the interface and every affected caller

Observe

A configurable booking rule

  • The old function IsValid(Seats) checks the fixed range 1–6.
  • The new version reads one Limit before one Seats value. Limit is already validated as an integer from 1 to 12.
  • Change the function to IsValid(Seats, Limit). Keep its BOOLEAN result and accept Seats from 1 through Limit inclusive.

Look, then discuss

Why is adding a parameter to the function header only part of the change?

Locate the source of Limit, its position in the call and the comparison that uses it. Two INTEGER arguments can have the correct types yet be passed in the wrong order.

Recall

Recall an ordered interface

Formal parameters appear in the function header; arguments appear in its call. Number, order, types and intended roles must agree. A returned BOOLEAN is used by the caller’s selection.

  • Review ordered function interfaces and returns

Explain

Explanation · 1 / 4

Revise the contract before its implementation

The function now needs two inputs. Replace the fixed upper bound with the supplied Limit, but preserve the lower bound and BOOLEAN return. Document that Limit itself has already been validated.

Explanation · 2 / 4

Update the caller’s state and input sequence

Declare Limit and read it before Seats. Pass Seats first and Limit second at every call. An old one-argument call no longer matches the header; reversed arguments compare the wrong roles.

Explanation · 3 / 4

Show the complete revised connection

This small program checks one integer request against one selected limit. It does not read a different limit for each part of a calculation.

FUNCTION IsValid(BYVAL Seats : INTEGER, BYVAL Limit : INTEGER) RETURNS BOOLEAN
    RETURN (Seats >= 1) AND (Seats <= Limit)
ENDFUNCTION

DECLARE Limit, Seats : INTEGER
INPUT Limit
INPUT Seats
IF IsValid(Seats, Limit) THEN
    OUTPUT "Accepted"
ELSE
    OUTPUT "Rejected"
ENDIF

Explanation · 4 / 4

Update tests and examples to the new interface

With Limit 6, old accepted and rejected quantities must behave as before. With Limit 8, Seats 7 now passes, while 9 fails. Include Seats 0 to protect the unchanged minimum. Each fixture must supply the limit before the quantity.

Work together

Distinguish compatibility from new behaviour

Test the revised function and its complete caller.

Work together · 1 / 2

Check the old parameter setting

Inputs 6, 6 must display Accepted and 6, 7 must display Rejected. These reproduce the old upper-limit rule.

Work together · 2 / 2

Check a deliberately different setting

Inputs 8, 7 must display Accepted. If the function body still compares with 6, it incorrectly rejects the request. Inputs 8, 9 must display Rejected. A reversed call IsValid(Limit, Seats) would make the latter comparison 8 <= 9 and wrongly accept it.

Header, body, callers, input fixtures and documentation are one connected change.

Check

Try it yourself · Teacher-written

The header becomes IsValid(Seats, Limit), but the function still returns Seats <= 6. Why can tests using only Limit 6 miss the fault?

Check your reasoning

Those tests reproduce the old fixed rule, so the hard-coded 6 appears correct. Use a different valid limit, such as Limit 8 with Seats 7, to prove the new parameter actually changes the decision. Retain the lower-bound check too.

Connect

Keep this idea

Interface amendments require coordinated changes at every definition, call and dependent test.

Develop a booking system · Concept 28

Preserve field boundaries when data changes

Observe

A changed record requirement

  • A booking record stores BookingID, Name and Email, separated by |. These original fields are guaranteed not to contain |.
  • Two new encoded fields may contain any visible character, including |. Each has length 0–99.
  • The whole record must remain on one physical line. How will a reader know where each added field ends?

Look, then discuss

Can choosing a different separator solve a field that may contain any separator?

Try storing the added value A|B. A reader that splits at every | would treat one value as two fields. The format must describe boundaries without mistaking field data for separators.

Recall

Recall text records and string length

A text record needs a defined way to separate its fields. LENGTH counts characters; a substring operation extracts a specified number of characters. Leading zeros in a fixed-width length are meaningful text. Read each paper’s supplied string interface before using its function names.

  • Review text records and file operations
  • Review string lengths and substrings

Explain

Explanation · 1 / 4

Analyse the old assumption that no longer holds

Delimiter-separated fields work only when the delimiter is excluded or handled by a defined escaping rule. The new fields can contain it, so the old “split everywhere” reader is no longer valid. Both writer and reader depend on the format.

Explanation · 2 / 4

Choose an unambiguous length representation

For each added field, store its length as exactly two decimal digits followed immediately by that many characters. The limit 99 makes two digits sufficient. A one-character field begins 01, an empty field 00. Unseparated variable-width lengths would introduce another ambiguous boundary.

Explanation · 3 / 4

Find the new section and read by length

Preserve the three original fields and their agreed delimiters, including a delimiter after the email before the added section. Read two digits as a length, then exactly that many characters. Repeat for the next field. Characters inside those spans are data, even when they look like delimiters.

Explanation · 4 / 4

Amend both sides and verify the new contract

Update writing, reading, format documentation and fixtures together. Check an empty added field, one containing the old delimiter and a maximum-length field. If line breaks are possible, first encode them into a single-line representation and define lengths consistently for that stored representation.

Work together

Decode a record with an embedded separator

The teacher-written record is B004|Mina|mina@example.org|03A|B02xy. The new values are A|B and xy.

Work together · 1 / 3

Locate the section boundary

The first three delimiters bound the original BookingID, Name and Email fields. After the email delimiter, the reader changes to the new length-prefixed format.

Work together · 2 / 3

Read the two new fields

Read 03, then exactly A, | and B. That internal | belongs to the first field. Read 02 next, then x and y. The consumed characters now end at the record end. Both values are recovered without choosing a forbidden separator.

Work together · 3 / 3

Connect the format change to program enhancement

The implementation must write and read matching formats. An amended writer paired with the old split-at-every-separator reader still fails. Use the same analysis–impact–amend–verify method as for the changed function interface.

A reliable enhancement revises the assumptions and every component that depends on them.

Check

Try it yourself · Teacher-written

How would you store the added fields "" and "A|B" using two-digit lengths? Why does picking # as a new separator not solve the general problem?

Check your reasoning

The added section is 0003A|B: 00 introduces an empty first field; 03 introduces the three-character second field. Choosing # is insufficient because the new data may also contain #.

Original question · Cambridge 9618/22

1. Redesign a record format when separators can occur in data

Cambridge 9618/22 · October/November 2025 · 3(c) · 3 marks

Selected parts: 3(c) [3].

Original insert · reference material

Hint — reading the question

The encrypted fields may contain any separator you choose. Their maximum length of 99 makes a fixed two-digit length prefix sufficient for each field. Preserve one physical record line as required.

Reasoning and model answer — teacher-written

Add a separator after the original email field to identify where the new section begins. Calculate the length of each encrypted item and write it as a fixed-width two-digit decimal string immediately before that item. Read the first two digits, then exactly that many characters, then repeat for the next item.

Teacher example with invented encrypted data:
AB1234\Freddie Jones\FreddieJ909@Cambridge.org\03A\B02xy

After the email separator, 03 means read the next three characters A, backslash, B. The following 02 means read x and y. The embedded backslash is data because the length determines the boundary. If “any character” includes a line break, encode it before writing and measure the encoded representation consistently so the record remains on one line; the printed examples use visible characters.

Official mark scheme
Why this earns marks — teacher explanation

The scheme lists four points with a maximum of three: boundary after the third original field, length calculation, stored lengths, and a fixed-width or separated representation of the lengths.

Common mistakes — teacher analysis

Picking a different delimiter does not solve “any character”. An unseparated variable-width length is itself ambiguous. Document whether lengths describe the stored representation or decoded data.

Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Index : INTEGER
DECLARE Mark : INTEGER
DECLARE PassCount : INTEGER
DECLARE MeritCount : INTEGER
PassCount <- 0
MeritCount <- 0
FOR Index <- 1 TO 4
    INPUT Mark
    IF Mark >= 50 THEN
        PassCount <- PassCount + 1
    ENDIF
    IF Mark >= 70 THEN
        MeritCount <- MeritCount + 1
    ENDIF
NEXT Index
OUTPUT PassCount
OUTPUT MeritCount
  1. MeritCount is declared INTEGER.
  2. It is initialised to zero before the loop.
  3. An independent IF Mark >= 70 increments it inside the loop.
  4. The existing pass rule and accumulation remain in place.
  5. Both final counters are output after the loop and all constructs close.

Common error: Do not use ELSE to separate merit and pass categories.

Answer and checking points — teacher-written

One complete Cambridge pseudocode solution

FUNCTION IsPass(Mark : INTEGER, PassMark : INTEGER) RETURNS BOOLEAN
    RETURN Mark >= PassMark
ENDFUNCTION

DECLARE Index : INTEGER
DECLARE Mark : INTEGER
DECLARE PassCount : INTEGER
DECLARE PassMark : INTEGER
INPUT PassMark
PassCount <- 0
FOR Index <- 1 TO 4
    INPUT Mark
    IF IsPass(Mark, PassMark) THEN
        PassCount <- PassCount + 1
    ENDIF
NEXT Index
OUTPUT PassCount
  1. The old IsPass accepts one mark, compares against 50 and supplies a BOOLEAN used by main’s counter.
  2. Add a typed PassMark parameter and compare Mark >= PassMark in the function.
  3. Declare and input PassMark once before the existing four-input loop.
  4. Update every IsPass call to supply Mark followed by PassMark.
  5. Retain the initialisation, four-mark traversal, conditional increment and final output; the specified result is 2.

Common error: Reading PassMark inside the loop changes the input contract.
