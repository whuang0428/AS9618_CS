01

Document persistent states and transitions

S12.03.A01

Visual overview

Core explanation

States persist between events

A state-transition diagram documents the possible conditions of a system and the events that move it between those conditions. It helps a designer communicate behaviour that depends on the current state. An initial-state indicator tells the reader where an event sequence starts.

Transitions depend on current state and event

In the turnstile model, a coin unlocks a locked barrier and passing locks it again. A push while locked leaves it locked. A second coin while already unlocked leaves it unlocked. Each arrow is directed and labelled with an event; a self-loop represents an event that leaves the current state unchanged. More detailed diagrams may add conditions to an event label.

Common misconception

A state name describes a condition, not an instruction such as calculate the total.

Check your understanding

Does the push loop mean the turnstile becomes unlocked briefly?

Check your answer

No. Its source and destination are both Locked.

Core explanation

Follow one event from the current state

Read one event at a time, starting at the initial state. Follow an outgoing arrow whose label matches that event and any stated condition, then use the new state for the next event. An arrow from another state cannot be used merely because its label matches.

Distinguish state, structure and flow diagrams

A structure chart answers which modules call other modules; a state-transition diagram answers which state changes are possible. A flowchart records processing steps and control flow. These documents can describe different aspects of one system, but none should be read as a substitute for the others. If a required event has no transition from the current state, the diagram needs clarification rather than an invented transition.

Worked example · Explain a trace, not just the final state

  1. Start

    The initial state is Locked.

  2. First event

    coin follows the directed arrow to Unlocked.

  3. Second event

    pass follows the arrow back to Locked.

  4. Meaning

    The diagram documents when access is enabled and when the barrier locks again.

Common misconception

A matching event on an arrow from the wrong state is not an available transition.

Check your understanding

What follows coin, coin, pass from Locked?

Check your answer

Unlocked, Unlocked, Locked; the second coin takes the self-loop.

Cambridge command words

Practice questions

Question 1 · Command word: Describe2 marks

Describe the purpose of a state-transition diagram and what an event-labelled arrow records.

S12.03.A01
Answer and marking points
  1. It documents the conditions a system can occupy and its possible changes of condition.
  2. A directed arrow identifies the event that moves the system from its source state to its destination state.

Common error: Do not answer with the purpose of a walkthrough.

Question 2 · Command word: State2 marks

State the turnstile state after each event in push, coin, pass, starting from Locked. Explain the first result.

S12.03.A01
Answer and marking points
  1. The states after the three events are Locked, Unlocked and Locked.
  2. The push transition is a self-loop on Locked, so it preserves that state.

Common error: Use the current state before choosing the next arrow.

Question 3 · Command word: Compare2 marks

Compare a structure chart and a state-transition diagram as ways of documenting a login system.

S12.03.A01
Answer and marking points
  1. The structure chart shows login module responsibilities and calling interfaces.
  2. The state diagram shows conditions such as LoggedOut and LoggedIn and the events that change them.

Common error: Keep module hierarchy separate from persistent conditions.

Question 1 · Command word: Explain · 3 marks

Explain what a state diagram documents for this player and give the states after play, pause, stop. The player starts Paused. play changes Paused to Playing; pause changes Playing to Paused; stop changes either state to Stopped. Explain why stop needs transitions from both active modes.

Answer and marking points
  • The diagram records the playback modes and permitted changes caused by button events.
  • The sequence leads to Playing, then Paused, then Stopped.
  • The same stop event has outgoing transitions from two different source states.

Common error: Do not invent a transition out of Stopped.

Question 2 · Command word: Explain · 3 marks

Explain the meaning of a progress self-loop on Uploading and why Uploading is a suitable state name. Compare this with a completion event that leads to Ready.

Answer and marking points
  • Progress can be reported while the upload remains in the same condition.
  • Completion changes the condition to Ready instead of taking that loop.
  • Uploading describes an ongoing mode in which the system can wait for further events.

Common error: The self-loop is not evidence that the upload restarts.

Question 3 · Command word: Explain · 3 marks

Explain why the final state after close cannot be determined when a door diagram specifies Closed --open--> Open and Open --close--> Closed but gives no initial-state indicator.

Answer and marking points
  • If the door starts Open, close has a defined transition to Closed.
  • If it starts Closed, no close transition from that state has been specified.
  • The starting state or missing-event behaviour must be clarified before a unique trace is claimed.

Common error: Do not assume every unshown event is ignored.
