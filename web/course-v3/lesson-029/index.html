Utility software, libraries and linked files

Choose utilities by the problem they solve, then explain code reuse and the benefits and constraints of DLL files.

Which tool repairs or protects data, and which supplies code for a developer?

Before you start

A backup and an antivirus scan both protect work. Are they interchangeable?

Check your answer

No. A backup supports restoration; a virus checker detects and handles malware.

01

Disk formatter

S5.02.A01

Visual overview

Disk formatter: input, operation and outcome

  1. Starting pointBlank volume
  2. OperationCreate file-system structures
  3. OutcomeReady to organise new files

Core explanation

A disk formatter prepares a storage medium or volume with the file-system structures needed to organise files. Formatting establishes an empty organisational structure; it does not install all application software or restore a previous user's documents.

Reformatting an existing volume can make its current files inaccessible. A storage fault or a missing file is therefore not a reason to format a disk automatically; preserve needed data and choose the utility appropriate to the problem.

Common misconception

Formatting does not recover deleted files.

Check your understanding

A new empty volume needs a file system. Which utility is appropriate?

Check your answer

A disk formatter prepares the volume for file storage.

02

Virus checker

S5.02.A02

Visual overview

Virus checker: input, operation and outcome

  1. Starting pointFile or activity
  2. OperationScan and detect suspicious content
  3. OutcomeQuarantine, remove or attempt repair

Core explanation

A virus checker scans files, memory or activity for evidence of malware, using methods such as known signatures and suspicious behaviour. Its detection information needs updating as new threats are identified.

Detected items may be quarantined so they cannot run, removed, or repaired where that is possible. Detection does not guarantee that every new threat is found, and removing malware does not necessarily recover data it has already damaged.

Common misconception

A successful scan is not proof that no malware exists.

Check your understanding

Why can an old set of malware signatures reduce protection?

Check your answer

It may not recognise threats whose signatures were identified after that set was published.

03

Defragmentation software

S5.02.A03

Visual overview

Core explanation

Why an HDD can benefit
  1. Relocate blocks: Move separated parts of a file into fewer, more contiguous groups; consolidate free space where possible.
  2. Reduce seeking: The magnetic drive’s head can move less while reading the file, reducing access delays.
Keep the mechanism and limitation together

The file’s logical contents stay the same. The performance explanation depends on mechanical seeking: an SSD has no moving read head, so routine HDD-style defragmentation is not the same treatment for an SSD.

Defragmentation software: input, operation and outcome

  1. Starting pointSeparated HDD blocks
  2. OperationRearrange block placement
  3. OutcomeLess seeking during sequential reads
Common misconception

Defragmentation changes placement, not the number of data bits in the file.

Check your understanding

Does defragmentation shorten a file's actual contents?

Check your answer

No. It changes where blocks are stored; compression is the utility that changes the representation to reduce size.

04

Disk contents analysis and disk repair

S5.02.A04

Visual overview

Disk contents analysis and disk repair: input, operation and outcome

  1. Starting pointStorage warning
  2. OperationInspect space, structures or errors
  3. OutcomeReport findings and attempt supported fixes

Core explanation

Disk contents analysis can report how storage space is being used. Disk checking and repair tools examine file-system consistency and may detect problems such as lost allocation information or unreadable sectors.

A repair utility attempts supported corrections and can mark unsuitable areas to avoid further use. It cannot guarantee recovery from physical damage. Analysing a disk does not mean erasing it, and a recoverable backup remains valuable if repairs fail.

Common misconception

A repair attempt is not a guarantee that damaged data will be restored.

Check your understanding

A disk reports inconsistent file allocation. Is defragmentation the appropriate repair?

Check your answer

No. A disk checking/repair utility investigates the file-system fault; rearranging file blocks is a different operation.

05

File-compression utilities

S5.02.A05

Visual overview

File-compression utilities: input, operation and outcome

  1. Starting pointOriginal files
  2. OperationLossless archive encoding
  3. OutcomeDecompress to recover identical data

Core explanation

A file-compression utility encodes data in a representation that can use fewer bits. Smaller files can require less storage space and less time to transfer over a connection with a given data rate.

A general-purpose archive utility uses lossless compression so decompression restores the original file exactly. The reduction depends on the data: an already compressed or poorly compressible file may shrink very little or even gain overhead. Compression alone does not create a recovery copy or encrypt the contents.

Common misconception

A compressed archive is not automatically a backup or an encrypted file.

Check your understanding

Why must a compressed source-code archive restore every original character?

Check your answer

Changing a character can change or invalidate the program, so exact lossless recovery is required.

06

Back-up software

S5.02.A06

Visual overview

Core explanation

Prepare for recovery
  1. Copy: Create recoverable copies of files or system data, using a separate recovery destination.
  2. Schedule and retain: Select changed files and keep suitable versions so an earlier state can be restored.
  3. Restore and check: Test that the saved copy and recovery procedure actually work after loss, corruption or failure.
Know what the copy protects

A copy on the same failing disk does not protect against that disk’s failure. Only changes present in the chosen backup can be recovered from it; a completed copy job alone is not proof of successful restoration.

Back-up software: input, operation and outcome

  1. Starting pointWorking data
  2. OperationCopy to a separate recovery destination
  3. OutcomeRestore a selected saved version
Common misconception

A copy lost with the original cannot provide recovery from that loss.

Check your understanding

Does compressing the only copy of a document protect it from disk failure?

Check your answer

No. Recovery requires an available separate copy, whether or not that copy is compressed.

07

Program libraries and routine calls

S5.03.A01S5.03.A02

Visual overview

Core explanation

Reuse an existing implementation

A program library is a collection of routines or modules other programs can use, such as mathematical functions or image-reading operations.

Check the interface before calling
  • Inputs: Use the specified name, argument order, data types and conditions.
  • Result: Know what is returned and use it correctly in the surrounding program.
  • Integration: Test the caller: a correct routine can still be called with inappropriate data.
Benefits depend on suitability

Suitable documented, tested libraries reduce implementation and testing effort and provide specialist operations. Those benefits depend on the chosen library; they are not guaranteed for every downloaded file.

Worked example · Reuse in a distance calculator

  1. Requirement

    The program needs the square root of a calculated value of 81.

  2. Call

    Result <- SQRT(81)

  3. Returned value

    Result becomes 9 without the developer writing a square-root algorithm.

  4. Integration test

    Test a zero argument as well; prevent negative input if the selected routine does not support it.

Common misconception

A library supplies reusable code, not an automatic guarantee that the complete calling application is correct.

Check your understanding

Why test a program that calls a well-tested library?

Check your answer

The caller may supply incorrect arguments, misunderstand the result or integrate the routine incorrectly.

08

Dynamic linking and developer benefits

S5.03.A03

Visual overview

Core explanation

Where library code is held
Linking modelArrangement
StaticRequired library code is incorporated into the built executable.
DynamicA DLL remains separate; routines are linked at load time or as needed during execution.

Swipe horizontally to compare every column →

Benefits and conditions
  • Less duplication: Compatible applications can use one library, reducing repeated disk copies and allowing loaded code to be shared in memory. Calling executables can be smaller.
  • One compatible correction: Update the library without recompiling each caller; running programs may need a restart or reload.
  • Compatibility matters: The interface and behaviour must remain compatible. Missing or incompatible DLLs can prevent loading or cause failures, so updates need checking.

Worked example · Two tools share a label library

  1. Before

    An invoice tool and a stock tool both load Label.dll.

  2. Compatible fix

    A corrected file retains the same routine names, parameters and expected results.

  3. Deployment

    Replace the shared file; restart both tools so they load the corrected version.

  4. Failure case

    If a required routine is removed, one caller may fail even though the DLL filename is unchanged.

Common misconception

Updating a DLL is safe for existing callers only when compatibility is preserved; a common filename alone is insufficient.

Check your understanding

Why can replacing one DLL affect more than one application?

Check your answer

Several applications may depend on the routines in that same separate library file.

Practice questions

Question 1 · Command word: Identify2 marks

Identify the utility needed to prepare an empty storage volume for files and describe what it creates.

S5.02.A01
Answer and marking points
  1. Use a disk formatter.
  2. It creates the volume's file-system organisation for storing and locating files.

Common error: Do not suggest formatting as a way to recover files already on a damaged disk.

Question 2 · Command word: Explain2 marks

Explain why a virus checker needs updated detection information and describe the purpose of quarantine.

S5.02.A02
Answer and marking points
  1. Updated information can identify threats that were not recognised by the older detection data.
  2. Quarantine isolates a suspect item to prevent normal execution while it is investigated or handled.

Common error: Quarantining an item does not restore every document it may already have damaged.

Question 3 · Command word: Explain3 marks

Explain why defragmentation may speed up reading a large fragmented file from a magnetic hard disk without reducing the file's size.

S5.02.A03
Answer and marking points
  1. It brings separated file blocks into fewer contiguous groups.
  2. The magnetic read head can spend less time seeking between those groups.
  3. The file still contains the same data; only its placement has changed.

Common error: Do not describe the mechanism as compression or apply the moving-head explanation to an SSD.

Question 4 · Command word: Identify2 marks

Identify a utility for investigating inconsistent file-system records and give one limitation of its repair operation.

S5.02.A04
Answer and marking points
  1. Use disk checking/analysis and repair software.
  2. It may be unable to recover data that is physically unreadable or no longer present.

Common error: A repair tool cannot promise recovery from all hardware failures.

Question 5 · Command word: Explain2 marks

Explain why lossless file compression is appropriate for a folder of source-code files being sent to a colleague.

S5.02.A05
Answer and marking points
  1. Reducing the transmitted size can shorten the transfer on the same connection.
  2. Lossless decompression restores the original source characters without changing the program.

Common error: Compression reduces representation size, not the importance of the data.

Question 6 · Command word: Explain3 marks

Explain why a scheduled backup on a separate device can recover work after the computer's main disk fails. State why a restore check is useful.

S5.02.A06
Answer and marking points
  1. A saved copy remains available outside the failed disk.
  2. Back-up software can restore the selected saved files to replacement storage.
  3. A restore check verifies that the saved copy is readable and usable for recovery.

Common error: A backup only contains the data captured by its completed backup jobs.

Question 7 · Command word: Explain3 marks

Explain what a program library provides and how a developer can use an existing routine correctly.

S5.03.A01S5.03.A02
Answer and marking points
  1. It provides pre-written routines or modules for reuse.
  2. The developer calls the chosen routine according to its documented arguments and result.
  3. The calling program is tested to check that the routine has been integrated correctly.

Common error: Calling existing code does not eliminate all testing of the caller.

Question 8 · Command word: Explain3 marks

Explain one storage benefit and one maintenance benefit of a DLL used by several applications. Give one compatibility risk.

S5.03.A03
Answer and marking points
  1. One separate DLL can avoid storing an incorporated copy of its code in every executable.
  2. A compatible library correction can serve the applications without rebuilding each calling executable.
  3. An interface change can make an existing application's calls fail.

Common error: Distinguish two benefits and one risk; do not award the same reuse benefit twice.

Question 1 · Command word: Explain · 3 marks

Explain which action meets each requirement: prepare a new empty disk for files; send an exact copy of a text folder using fewer transmitted bits; recover yesterday's folder after accidental deletion. Name the type of utility for each.

Answer and marking points
  • A formatter establishes the new disk's file system.
  • A lossless compression utility produces an archive that may reduce the transferred size while preserving exact recovery.
  • Back-up software restores yesterday's saved copy from an available recovery destination.

Common error: The third requirement depends on an earlier copy; compressing today's remaining files cannot recreate yesterday's deleted data.

Question 2 · Command word: Explain · 3 marks

Explain the different purposes of a virus checker, disk repair software and a defragmenter for these magnetic-disk problems: an infected program, inconsistent file-system records, and slow reads caused by scattered file blocks. Give the matching action for each.

Answer and marking points
  • The virus checker detects the infected program and isolates or removes the malicious content.
  • Disk repair software checks the inconsistent records and attempts a supported correction.
  • The defragmenter relocates scattered blocks to reduce mechanical seek work during reads.

Common error: Match the mechanism to the diagnosed problem rather than recommending every utility for every fault.

Question 3 · Command word: Explain · 4 marks

A developer replaces SharedMath.dll with a new version. Explain why two unchanged applications might benefit, why they may need restarting, and why testing is still required even when the new DLL exists at the same path.

Answer and marking points
  • Both callers can obtain corrected routines from the replacement separate library.
  • A process already using an older loaded version may need to reload the library, for example by restarting.
  • An unchanged path does not ensure that routine interfaces or results remain compatible.
  • Tests must confirm that both callers still supply suitable arguments and receive the results they expect.

Common error: Do not claim that every running program immediately adopts any DLL replacement.

Lesson review

Summary

Choose by need

Prepare, scan, rearrange, inspect, compress and restore are different operations.

Recovery

Keep usable copies outside the failure affecting the originals.

Libraries

Use an existing implementation through its documented interface and test its integration.

DLLs

Separate compatible code can serve several callers; dependency and update compatibility must be checked.
