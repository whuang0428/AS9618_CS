System software · Concept 01

Prepare empty storage; investigate damaged organisation

Start with a question

Would you treat a new empty volume and a disk with a damaged file-system record in the same way?

Volume A is known to be empty and has no file system. Volume B contains work, but a check reports inconsistent allocation information. Both involve storage, yet the desired outcomes are different.

Recall

Use what you already know

A file system and a utility

A file system is the organisation and information used to store, name and locate files. A volume is a storage area managed with a file system. Utility software performs a particular maintenance, management or protection task.

Explain

Explanation · 1 / 4

Create the organisation for new files

A disk formatter prepares a medium or volume with the file-system structures needed to organise files. It creates allocation records that track which storage areas belong to files; a File Allocation Table, or FAT, is one example used by some file systems. A full-format operation may also check the disk for errors. The result is a volume ready to create and locate new files, not a restoration of previous documents.

Explanation · 2 / 4

Inspect how storage is being used

Disk contents analysis can report which files or categories occupy space. That evidence can explain why a disk is nearly full. Finding one large folder is a different result from finding an error in the structures that record a file’s location.

Explanation · 3 / 4

Check consistency and attempt supported repairs

Disk checking and repair tools examine file-system records and may identify lost allocation information or unreadable sectors. A repair tool attempts corrections it supports and may mark unsuitable areas to avoid further use. It cannot guarantee recovery of physically damaged or missing data.

Explanation · 4 / 4

Match the action to the desired outcome

Use formatting to prepare the known-empty volume. Investigate Volume B with checking and repair tools because its existing files matter. Reformatting a volume that contains needed work can make that work inaccessible. A separate recoverable copy is valuable before a fault occurs.

Check

Explain it yourself · Teacher-written

A repair attempt fails to recover an unreadable document. Does formatting recreate the missing contents?

Check your reasoning

No. Formatting creates file-system organisation; it does not reconstruct the document’s data. Recovery may require an available earlier copy.

Connect

Keep this idea

Formatting prepares a file system. Analysis reports disk contents or problems. Repair attempts supported corrections.

A disk can have valid records and enough space but still read one file slowly because its blocks are separated.

Check a common misunderstanding

Do not recommend formatting merely because a disk is slow, full or reporting an error.

System software · Concept 02

See why separated HDD blocks require more movement

Observe

Start with a question

If a file has exactly the same contents, how can moving its blocks help a magnetic hard disk read it?

A magnetic hard disk stores a file in blocks. Label the three blocks of one file A1, A2 and A3. Other files occupy B1 and C. In the simplified block map, A’s blocks are separated by other occupied or free positions.

Explain

Explanation · 1 / 4

Connect a stored block to a physical read

A magnetic hard disk, or HDD, has rotating platters and moving read/write heads. To read a required area, the drive positions a head over the relevant track and waits for the required sector to rotate into position. Mechanical movement and rotational waiting contribute to access time.

Explanation · 2 / 4

Follow a fragmented file

A file is fragmented when its parts occupy separate areas rather than one contiguous sequence. Saving and deleting files can leave gaps into which later file parts are placed. Reading the separated parts can require more head movement between their locations.

Simplified order123456
BeforeA1B1FreeA2CA3
After rearrangementA1A2A3B1CFree

Explanation · 3 / 4

Rearrange placement with defragmentation

Defragmentation software relocates file blocks into fewer, more contiguous groups and can consolidate free space. Reading A1, A2 and A3 can then need less seeking between separated areas. The file’s three blocks still contain the same data; the utility changes where those blocks are stored.

Explanation · 4 / 4

Keep the explanation tied to the device

The performance explanation depends on mechanical head movement in an HDD. A solid-state drive, or SSD, has no moving read head. Routine HDD-style defragmentation is therefore not the same performance treatment for an SSD. Defragmentation also does not compress file data or repair every disk fault.

Work together

Explain the improvement without changing file size

A report occupies three separated HDD blocks before rearrangement and three adjacent blocks afterwards.

Work together · 1 / 2

State the operation

The defragmenter places the report’s parts into a more contiguous group.

Work together · 2 / 2

Connect cause and result

The head can need less movement while reading the report, reducing access delays. The report still has three blocks of the same contents.

Use the chain: scattered blocks → rearranged placement → less mechanical seeking → faster access where fragmentation caused delays.

Check

Explain it yourself · Teacher-written

After defragmentation, a 6 MB file is still 6 MB. Has the utility necessarily failed?

Check your reasoning

No. Its purpose is to improve file placement, which can reduce HDD head movement. Reducing the number of data bits is compression’s job.

Connect

Keep this idea

Defragmentation places separated file blocks more contiguously, reducing HDD head movement and potentially improving access time.

Better placement does not protect a file from malicious changes or provide a copy after loss.

Check a common misunderstanding

Do not describe an SSD as having a moving read head or claim that defragmentation shrinks a file.

System software · Concept 03

Detect harmful code and keep a recoverable copy

Observe

Start with a question

A suspicious program damages today’s document. Which tool can handle the program, and where can the old document come from?

Yesterday’s version V1 was copied to a separate backup device. Today the working document becomes V2, then the computer’s main disk fails. First follow the malicious-file case; then follow recovery after the failed disk.

Explain

Explanation · 1 / 4

Scan for evidence of malware

A virus checker examines files, memory or activity for evidence of malicious software. It may compare known signatures, which are recognisable patterns, and look for suspicious behaviour. Detection information needs updates because an old signature set may not recognise a newly identified threat.

Explanation · 2 / 4

Contain the detected item

The utility can quarantine a suspect item, isolating it from normal use, or remove or attempt to repair infected content. A scan does not guarantee that every threat will be detected. Handling the malicious program also does not automatically reconstruct a document it has already damaged.

Explanation · 3 / 4

Create copies before the loss

Back-up software creates recoverable copies of files or system data. It can schedule jobs, select changed files and retain versions. Restoring means copying a saved version back into use after deletion, corruption or equipment failure. The needed version must have been captured before it was lost.

Explanation · 4 / 4

Check what the surviving copy contains

If the separate device holds V1 and the failed disk held the only V2, recovery gives V1. The changes made after the last successful backup are absent. A copy on the same physical disk is also lost if that disk fails. Restore checks establish that the saved copy is readable and usable.

Start with a question

How can a folder of source files be sent using fewer bits without changing any character when it is restored?

The text AAABBB contains repeated runs. As a small conceptual model, describe it as “three A characters, then three B characters”. Compare the compact description with reconstructing the exact original sequence. Real archive formats use specified encodings and include overhead.

Explain

Explanation · 1 / 4

Change the representation

A file-compression utility encodes data in a representation that can require fewer bits. For suitable data, the smaller result needs less storage and less transfer time over the same connection. Compression changes how data is represented; it does not rearrange HDD blocks to reduce head movement.

Explanation · 2 / 4

Require exact recovery for general files

Lossless compression allows decompression to reproduce the original data exactly. This is essential for a folder of source code: losing or changing one character can alter or invalidate a program. An archive can package files and may compress them; extracting restores the stored file data.

Explanation · 3 / 4

Explain why the reduction varies

Some data has useful redundancy and some is already compressed or difficult to compress. The result may shrink very little, and format overhead can even make a small result larger. The utility cannot promise the same reduction for every file.

Explanation · 4 / 4

Choose by the required change

Name the problem before naming the tool. Compression seeks a smaller representation; backup provides recovery; defragmentation changes HDD placement; a formatter prepares organisation; analysis and repair investigate storage use or faults; a virus checker handles evidence of malware. A compressed file is not automatically encrypted or stored as a separate backup.

System software · Concept 05

Call a tested routine instead of rewriting its algorithm

Observe

Routine nameSQRT
ArgumentOne non-negative number
ResultThe square root of the argument

Start with a question

A calculation needs the square root of 81. Must its developer write a square-root algorithm?

The supplied routine SQRT accepts a non-negative number and returns its square root. The caller needs to supply 81, receive 9 and use that result in the rest of the program.

Explain

Explanation · 1 / 4

Identify the reusable code

A program library is a collection of pre-written or pre-compiled routines or modules that other programs can use. A routine is a named section of code that performs a task. A library can supply specialist operations such as mathematical calculations or reading an image format.

Explanation · 2 / 4

Read the routine’s interface

The interface tells the caller how to use the routine: its name, arguments, returned result and conditions for use. An argument is a value supplied in a call. Here SQRT(Value) supplies Value and returns its square root; the chosen routine requires Value to be non-negative.

Interface itemSQRT example
Routine nameSQRT
ArgumentOne non-negative number
ResultThe square root of the argument
Caller’s responsibilityCheck the condition and use the returned value

Explanation · 3 / 4

Follow a complete call

INPUT supplies Value. The condition checks it before the call. Assignment stores the returned result in Result, then OUTPUT displays it. This is Cambridge-style pseudocode using a documented library operation, not a claim that an unspecified real compiler accepts the listing.

DECLARE Value : REAL
DECLARE Result : REAL
INPUT Value
IF Value >= 0.0 THEN
    Result <- SQRT(Value)
    OUTPUT Result
ELSE
    OUTPUT "Unsupported input"
ENDIF

Explanation · 4 / 4

Explain the benefit and remaining work

Reusing suitable tested code reduces implementation and testing effort and can improve reliability. It gives access to specialist routines without writing their algorithms from scratch. The calling program still needs testing: valid library code can be supplied with unsuitable data or have its result ignored or misused.

Work together

Use the interface at three inputs

Use the complete listing with inputs 81, 0 and −4, starting a fresh run each time.

Work together · 1 / 2

Use valid arguments

81 passes the condition, returns 9 and displays 9. Zero also passes and returns 0.

Work together · 2 / 2

Handle an unsupported argument

−4 fails the condition. SQRT is not called; the program displays Unsupported input.

A library call is useful when its inputs and returned result are handled correctly.

Explain it yourself · Teacher-written

Check your reasoning

The calling program may have ignored the returned result or displayed the wrong variable. A tested routine does not prove that its integration is correct.

Connect

Keep this idea

A program library supplies existing routines. The caller uses their documented interfaces, reducing development effort while retaining responsibility for integration.

The next decision is whether to copy library code into each built application or keep shared code in a separate file.

Check a common misunderstanding

A library is reusable program code, not merely a folder of unrelated data files.

Start with a question

Three applications use MakeLabel(name). Could they use one corrected library file instead of three incorporated copies?

App A, App B and App C all need the same label routine. Compare a copy inside each application with one separate Label.dll. Then imagine that Label.dll is corrected, removed or changed incompatibly.

Explain

Explanation · 1 / 4

Compare two ways to supply code

With static linking, required library code is incorporated into the built executable. An executable is a built program that can be launched in its target environment. With dynamic linking, a Dynamic Link Library, or DLL, remains a separate file and its routines are linked when the program is loaded or when needed during execution.

Explanation · 2 / 4

Reduce duplicated code

Several applications can use one compatible DLL rather than each containing its own incorporated copy. Their executable files can be smaller, disk duplication can be reduced and loaded library code can be shared in memory where supported. The library code still exists in the separate file.

Explanation · 3 / 4

Correct the library separately

A compatible correction can be made to the DLL without recompiling each calling application. Recompiling means translating the application’s source code again to rebuild it. Each caller must load the corrected library version; a running application may need restarting or reloading. Compatibility means that required routine names, arguments and expected behaviour remain usable by the caller.

Explanation · 4 / 4

Recognise the runtime dependency

The DLL must be available and compatible when needed. If MakeLabel is removed or its parameter requirements change, an unchanged caller can fail even if the filename is still Label.dll. A missing library can also prevent loading or execution. Test the callers after an update.

  • Prepare empty storage; investigate damaged organisation

    Formatting prepares a file system. Analysis reports disk contents or problems. Repair attempts supported corrections.

  • See why separated HDD blocks require more movement

    Defragmentation places separated file blocks more contiguously, reducing HDD head movement and potentially improving access time.

  • Detect harmful code and keep a recoverable copy

    A virus checker detects and handles malware. Backup software creates recoverable copies and restores saved versions.

  • Use fewer bits and choose the correct utility

    Lossless compression can reduce storage or transfer size while allowing exact reconstruction of the original files.

  • Call a tested routine instead of rewriting its algorithm

    A program library supplies existing routines. The caller uses their documented interfaces, reducing development effort while retaining responsibility for integration.

  • Share a separate library and track the dependency

    A DLL supplies separately linked reusable code, reducing duplication and allowing compatible library updates without rebuilding every caller.
