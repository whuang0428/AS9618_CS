Design a ticket system · Concept 05

Translate a written rule into pseudocode

Observe

A rule with an order

  • Read the quantity
  • Multiply quantity by the fixed ticket price
  • Display the calculated total
  • Do not invent a discount or extra fee

Look, then discuss

Which parts of an English instruction must survive when we change its notation?

A volunteer’s card says: “Read a positive ticket quantity. Multiply it by 25.00. Display the total.” The result must remain the same when those words become pseudocode.

Recall

Reuse the effects of statements

INPUT obtains a value, assignment stores a calculated result and OUTPUT displays a value or literal. Structured English uses controlled natural-language steps to make operations and their grouping clear.

Explain

Explanation · 1 / 4

Underline actions and data separately

“Read” is an action and “quantity” is the data it obtains. “Multiply” names the processing, while quantity and price are its operands. This separates instructions from the values on which they operate.

Explanation · 2 / 4

Choose one statement for each effect

Translate reading into INPUT Quantity. Translate the calculation into Total ← Quantity * TicketPrice. Translate displaying the answer into OUTPUT Total. Choose meaningful names and declare the types required by their roles.

Explanation · 3 / 4

Preserve every stated rule

Keep the multiplier 25.00 and the original operation order. Changing names consistently is acceptable, but changing the price, adding a discount or displaying only Quantity changes the algorithm.

Explanation · 4 / 4

Check equivalence with actual values

Follow both versions for Quantity 2 and then Quantity 3. Each should produce 50.00 and 75.00 respectively. Matching one example is useful evidence, but you must also check that the statements preserve the general rule.

Work together

Translate a two-output receipt

Structured English: read the buyer’s name and ticket quantity; calculate the total at 25.00 each; display the name followed by the total. Assume available tickets and a positive whole-number quantity.

Work together · 1 / 3

List the data roles

BuyerName is STRING, Quantity is INTEGER and Total is REAL. TicketPrice is the fixed constant 25.00. The name is displayed but is not an operand in the multiplication.

Work together · 2 / 3

Translate in order

Read BuyerName, then Quantity; calculate Total; output BuyerName and Total. The result can now be written as a complete listing.

CONSTANT TicketPrice = 25.00
DECLARE BuyerName : STRING
DECLARE Quantity : INTEGER
DECLARE Total : REAL
INPUT BuyerName
INPUT Quantity
Total ← Quantity * TicketPrice
OUTPUT BuyerName, Total

Work together · 3 / 3

Trace against the written rule

For "Mina" and 2, display Mina followed by 50.00. Quoting "BuyerName" would display the identifier’s spelling instead of the buyer’s name and would fail the rule.

Translation changes the representation while preserving operations, data dependencies and results.

Design a ticket system · Concept 07

Draw and follow a simple decision

Observe

A path to one output

  • Start and obtain Quantity and Student
  • Calculate Subtotal
  • Decision: Student?
  • TRUE gives a discount; FALSE keeps the subtotal
  • Join the paths and display Total

Look, then discuss

Can someone follow the student-discount rule using arrows alone?

Place a buyer at a decision with two labelled exits: TRUE for a student and FALSE for another buyer. Follow only one exit, then return to the shared instruction that displays the total.

Recall

A diagram must describe execution

You already know what INPUT, assignment, OUTPUT and IF do. A flowchart expresses those operations with standard symbols and directed connections. Position on the page alone does not determine the next operation; follow arrowheads.

Explain

Explanation · 1 / 4

Give each symbol a specific job

Use a terminator for start and end, a parallelogram for input or output, a rectangle for processing, and a diamond for a decision. Put the actual operation or condition inside the shape.

Explanation · 2 / 4

Use the condition to choose a labelled exit

Label the diamond’s exits consistently as Yes/No or True/False. For Student TRUE, follow the branch calculating Subtotal × 0.90. The labels represent the truth of the condition, not whether the outcome is desirable.

Explanation · 3 / 4

Show where the paths rejoin

Connect both Total assignments to the shared output. The join does not execute both assignments; it gives either completed branch a next instruction. Connect the output forward to the end.

Explanation · 4 / 4

Verify the arrows with two traces

Trace one student and one non-student request. Every required input must be reached before it is used, and exactly one Total must be output. A correct-looking collection of shapes with a missing arrow is not a complete flowchart.

Work together

Draw an entry-height decision

Read a whole-number Height in centimetres. Display Enter for a height of at least 120; otherwise display Wait. End after that message.

Work together · 1 / 3

Place the shared beginning

Connect Start to an input parallelogram labelled INPUT Height, then to a diamond labelled Height >= 120.

Work together · 2 / 3

Draw both outcomes and the end

Yes leads to an output parallelogram labelled OUTPUT "Enter". No leads to OUTPUT "Wait". Connect both outputs to End without an arrow from one output to the other.

Work together · 3 / 3

Check the boundary paths

119 follows No and displays Wait. 120 and 121 follow Yes and display Enter. Replacing >= with > would change the result at 120.

A flowchart records operations and control flow through connected symbols and labelled decisions.

Experiment

The diagram first stores the full price in Total and changes it only for a student. Its No route keeps that value and reaches the output directly. Trace both routes, then change Student while keeping Quantity fixed and predict the final total.

Design a ticket system · Concept 14

Preserve behaviour in all four conversions

Observe

Things every representation must preserve

  • Total starts at 0
  • Exactly 3 new quantities are read
  • Each quantity is added once
  • One final output happens after repetition

Look, then discuss

How can different-looking representations read exactly the same inputs and produce the same outputs?

Four boxes show the same task in words, pseudocode and two possible diagram arrangements: read three quantities and output their sum. The layout can change, but the input count, additions and final output must agree.

Recall

Track execution rather than appearance

You know sequence, decisions, FOR, WHILE and REPEAT. When a FOR loop becomes a flowchart, show the counter’s initial value, comparison and update explicitly. A different arrangement of boxes is acceptable if its directed paths preserve the algorithm.

Explain

Explanation · 1 / 5

Translate Structured English into pseudocode

Identify the input, update and stopping rule in the words. “Read three quantities” means three inputs, not one input reused three times. Write the initialisation before the loop and the final output after it.

Explanation · 2 / 5

Translate a flowchart into pseudocode

Start at the terminator and follow arrows. Recover which paths repeat and when each condition is tested. A decision reached before the repeated input may represent WHILE; do not choose a loop solely because a diamond appears.

Explanation · 3 / 5

Draw from Structured English

Choose symbols for each required operation and connect them in order. Show both exits of a decision and where each goes. For a repeated operation, show the return path and the exit to the final output.

Explanation · 4 / 5

Draw from pseudocode

Expand FOR Index ← 1 TO 3 into Index ← 1, a test Index <= 3, a repeated body, Index ← Index + 1 and a return to the test. When Index reaches 4, exit without reading a fourth quantity.

Explanation · 5 / 5

Use a shared trace to compare results

Trace quantities 2, 1, 3 in both representations. The intermediate totals must be 2, 3, 6 and the only final output 6. Also inspect the control paths; one matching example cannot excuse a missing branch.

Work together

Convert the three-input total into a flowchart

Source pseudocode initialises Total to zero, repeats input and addition with FOR Index ← 1 TO 3, then outputs Total.

Work together · 1 / 3

Expand the hidden loop control

After Start, use a processing rectangle for Total ← 0 and Index ← 1, then a diamond for Index <= 3.

Work together · 2 / 3

Connect the repeated path

Yes leads to INPUT Quantity, then Total ← Total + Quantity, then Index ← Index + 1. The arrow returns to the same diamond, not to the initialisation.

Work together · 3 / 3

Connect and verify the exit

No leads to OUTPUT Total and End. With 2, 1, 3 the total becomes 6; Index then becomes 4 and the next test exits.

The expanded diagram preserves the count-controlled loop even though it makes its control operations visible.

Experiment

Follow one representation and predict the next operation in the other. Check initial values, the final failed loop test and the output after the exit.

Complete four independent tasks before comparing answers.

A — Structured English to pseudocode: read a non-negative whole-number Age. Display "Adult" for an age of at least 18; otherwise display "Minor". Display exactly one message.

B — Flowchart to pseudocode: use the supplied flowchart labelled B. Level is an INTEGER percentage from 0 to 100. Preserve both branch outputs and state the result for Level 20.

C — Structured English to flowchart: read a positive whole-number Quantity; multiply it by 25.00 and store the result in Total; display Total; end.

D — Pseudocode to flowchart: use the supplied listing labelled D. Draw the initialisation, loop test, counter update, return path and final output explicitly.

D — Supplied pseudocode

DECLARE I, Value, Total : INTEGER
Total ← 0
FOR I ← 1 TO 2
    INPUT Value
    Total ← Total + Value
NEXT I
OUTPUT Total
Check your reasoning

A: declare and input Age; use IF Age >= 18 THEN OUTPUT "Adult" ELSE OUTPUT "Minor" ENDIF. B: declare and input Level; use IF Level < 20 THEN OUTPUT "Refill" ELSE OUTPUT "No action" ENDIF. Level 20 outputs No action. C: Start → input parallelogram for Quantity → processing rectangle Total ← Quantity * 25.00 → output parallelogram for Total → End. D: initialise Total=0 and I=1; test I<=2; Yes → input Value → add Value to Total → increment I → return to the test; No → output Total → End. Both diagrams require connected symbols and labelled decision exits where applicable.

Take it further · Optional challenge

A diagram returns from Index ← Index + 1 to Total ← 0 rather than to the condition. What behaviour changes?

Check the challenge

The accumulator is reset on later iterations, losing earlier inputs. If the same initialisation also resets Index, the loop may never progress to its exit. The return must go to the condition after the initialisation has run once.

Design a ticket system · Concept 15

Separate waiting from collecting data

Observe

Mark the phase boundary before calculating

  • Waiting: 0, 5
  • Start signal: first 27
  • Collected data: 4, 27
  • Stop signal: final 0
  • Expected total: 31

Look, then discuss

Can the same number mean “ignore” in one phase and “stop” in another?

Read 0, 5, 27, 4, 27, 0. The first 27 starts collection and is not added. After that point, add values until 0. Before the first 27, even 0 must be ignored.

Recall

A sentinel has a role within a phase

Inputs are INTEGER values and the supplied stream contains a start signal followed eventually by a stop signal. You can use two loops in sequence. The value 27 is a start signal only while waiting; after collection starts, a later 27 is ordinary data.

Explain

Explanation · 1 / 4

Describe the two tasks separately

The first task consumes inputs until the first 27. It does not add any of those values. The second task starts after that signal and accumulates later values until 0.

Explanation · 2 / 4

Choose a loop for waiting

A REPEAT input UNTIL Value = 27 reads at least once and stops on the start signal. A 0 encountered here does not satisfy Value = 27, so waiting continues.

Explanation · 3 / 4

Read fresh data when collection begins

After the waiting loop finishes, initialise Total to zero and input the next Value. Do not add the Value still holding the starting 27. Use WHILE Value <> 0 to control the collecting loop.

Explanation · 4 / 4

Place the update and final output

Inside collection, add the current Value and input the next one. A later 27 is added because it is not 0. Output the total only after the collecting loop exits.

Work together

Trace both phases before drawing

Use input sequence 0, 5, 27, 4, 27, 0.

Work together · 1 / 3

Finish the waiting phase

Read 0 and 5 without adding either. Reading the first 27 makes the waiting condition true and ends that phase. No collection total includes that 27.

Work together · 2 / 3

Collect the subsequent values

Start Total at zero. Read 4 and add it to make 4; read the next 27 and add it to make 31; read 0 and exit without adding another value.

Work together · 3 / 3

Draw the phase transition

The waiting loop’s successful exit leads to the collection initialisation and a fresh input. The collection test has its own return arrow through addition and new input, and its exit leads to OUTPUT Total.

Separate control phases preserve the changing role of each sentinel value.

Check your reasoning

The two-loop flowchart waits for the first 27, initialises Total, reads a fresh value, then adds and reads again while Value <> 0. Inputs 27, 0 give total 0. Inputs 0, 27, 27, 0 give total 27: the first 0 is ignored, the first 27 starts collection and the second 27 is added.

Take it further · Optional challenge

Write equivalent pseudocode using a waiting loop followed by a collecting loop.

Check the challenge
DECLARE Value, Total : INTEGER
REPEAT
    INPUT Value
UNTIL Value = 27
Total ← 0
INPUT Value
WHILE Value <> 0
    Total ← Total + Value
    INPUT Value
ENDWHILE
OUTPUT Total

Original question · Cambridge 9618/22

1. Draw an algorithm with two stopping conditions

Cambridge 9618/22 · October/November 2023 · 2(a) · 5 marks

Selected parts: 2(a) [5].

Hint — reading the question

The first 27 starts collection and is not added. Before it, even 0 is ignored. After it, 0 stops collection; a later 27 is ordinary data and must be added.

Reasoning and model answer — teacher-written

The first loop consumes values until 27. A separate loop then inputs and adds values until 0. For the teacher test sequence 0, 5, 27, 4, 27, 0, the total is 31: only 4 and the second 27 contribute.

Official mark scheme
Why this earns marks — teacher explanation

The five points cover initialisation, waiting for the first 27, the ending 0 loop, summing after the first 27, and output after a reasonable attempt. The official flowchart gives a complete accepted drawing.

Common mistakes — teacher analysis

One loop that stops at any 0 can terminate before collection starts. Adding the first 27 changes the specified result. Make each decision branch and return arrow explicit.

Question 1 · Command word: Write3 teacher marks

Write pseudocode for this structured English: read an integer temperature; if it is below zero display Frost, otherwise display Clear; finish after one message.

S9.07.A01S9.07.A02
Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Temperature : INTEGER
INPUT Temperature
IF Temperature < 0 THEN
    OUTPUT "Frost"
ELSE
    OUTPUT "Clear"
ENDIF
  1. Temperature is input as an integer.
  2. The decision tests Temperature < 0.
  3. The true and false branches output "Frost" and "Clear" respectively.

Common error: Zero belongs to the Clear branch.

Question 2 · Command word: Write3 teacher marks

Write pseudocode equivalent to the supplied flowchart. Level is a whole-number percentage between 0 and 100. State the output for Level 20.

S9.07.A02
Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Level : INTEGER
INPUT Level
IF Level < 20 THEN
    OUTPUT "Refill"
ELSE
    OUTPUT "No action"
ENDIF
  1. The program inputs Level and tests Level < 20.
  2. The two branches output "Refill" or "No action" as drawn.
  3. Level 20 follows No and outputs No action.

Question 4 · Command word: Draw5 teacher marks

Draw a flowchart equivalent to the supplied pseudocode. Show the accumulator initialisation, loop condition, counter update and final output explicitly.

Use this algorithm in the question.

DECLARE Index : INTEGER
DECLARE Value : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Value
    Total <- Total + Value
NEXT Index
OUTPUT Total
S9.07.A03
Answer and checking points — teacher-written
  1. Total starts at 0 and Index at 1 before the loop condition.
  2. The decision Index <= 4 admits exactly four iterations.
  3. Each true path inputs Value and adds it to Total.
  4. Index increments and the arrow returns to the decision.
  5. The false path outputs Total and then ends.

Common error: The exit path must lead to the output, not backwards from it.
