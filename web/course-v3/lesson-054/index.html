Structured English, flowcharts and pseudocode

Preserve operations, conditions and execution order when converting between three algorithm representations.

Do all representations select the same output for the same input, including boundary cases?

Before you start

When changing a flowchart into pseudocode, may a condition Age >= 18 be shortened to Age = 18?

Check your answer

No. The operator is part of the algorithm's meaning, so it must be preserved.

01

Document a solution in structured English

S9.07.A01

Visual overview

Age classification in structured English

  1. ReadRead a person's age as a non-negative whole number.
  2. DecideIf the age is at least 18, display Adult; otherwise display Minor.
  3. FinishEnd after displaying one classification.

Core explanation

Structured English expresses an algorithm using controlled natural-language steps and clear grouping. State the operations in order, identify both outcomes of a decision and make the scope of any repetition explicit. It should leave the same computational choices determined as pseudocode does.

A flowchart shows that control structure with symbols and directed lines, while pseudocode uses statements and indentation. Changing notation should not change the accepted inputs or results. Trace a value on each side of a boundary when comparing two representations.

Worked example · Translate a written age rule

  1. Requirements

    Write pseudocode for the displayed structured English.

  2. Pseudocode
    DECLARE Age : INTEGER
INPUT Age
IF Age >= 18 THEN
    OUTPUT "Adult"
ELSE
    OUTPUT "Minor"
ENDIF
  3. Check

    The comparison remains >= 18. Ages 17, 18 and 19 produce Minor, Adult and Adult.

Common misconception

Structured English must describe the rule; 'process the age' is not a defined decision.

Check your understanding

Must an ELSE outcome be preserved during conversion?

Check your answer

Yes, when the source specifies an alternative action for a false condition.

02

Use symbols and arrows consistently

S9.07.A01

Visual overview

Core explanation

Use terminators for start and end, parallelograms for input and output, rectangles for processing, and diamonds for decisions. Arrowheads indicate the next operation. Label the outgoing decision paths consistently, for example Yes and No, so the truth value selects an unambiguous route.

A loop needs a return path to its condition or repeated body, according to when it tests. Paths that rejoin must not imply that both selection branches execute. Inspect the arrow direction at the final output as well as at the decision; an output cannot follow an end terminator.

Common misconception

A decorative arrow or an unlabelled split does not define a reliable execution path.

Check your understanding

Which symbol holds Total <- Price * Quantity?

Check your answer

A processing rectangle.

03

Write pseudocode from a flowchart

S9.07.A02

Visual overview

Core explanation

Begin at the start symbol and follow the arrows. Translate each input, process and output into its corresponding statement. At a decision, retain the full expression and place each path's operations in the appropriate block. Declare suitable types for the data used by the resulting program.

In the displayed countdown, a false condition goes directly to the final message. A true condition outputs the current value, decreases it and returns to the same test. That control flow corresponds to WHILE, with the message placed after ENDWHILE.

Worked example · Recover a loop from directed paths

  1. Requirements

    Write equivalent pseudocode for the countdown flowchart; Count is a non-negative integer.

  2. Pseudocode
    DECLARE Count : INTEGER
INPUT Count
WHILE Count > 0 DO
    OUTPUT Count
    Count <- Count - 1
ENDWHILE
OUTPUT "Finished"
  3. Check

    Starting at 3 gives 3, 2, 1, Finished. Starting at 0 skips the body and gives Finished.

Common misconception

The backward arrow must become repetition; writing the body once loses the loop.

Check your understanding

Where does the No path from Count > 0 lead?

Check your answer

To OUTPUT "Finished", then the end terminator.

04

Draw a flowchart from a written algorithm

S9.07.A03

Visual overview

Core explanation

When drawing from structured English or pseudocode, identify the sequence, branch boundaries and loop boundaries before choosing symbols. Put a complete condition in every decision and show where execution continues after each path. Convert implicit loop control into visible initialisation, a condition and an update where needed.

A FOR loop that totals four values can be drawn using Index initialised to 1, a decision Index <= 4 and an increment after each addition. The false path outputs the final total. This expands the loop notation while preserving exactly four input operations.

Worked example · Expand a count-controlled loop

  1. Source pseudocode
    DECLARE Index : INTEGER
DECLARE Value : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Value
    Total <- Total + Value
NEXT Index
OUTPUT Total
  2. Initial state

    Set Total to 0 and Index to 1 before the diamond.

  3. Repeated path

    For a true Index <= 4, input Value, add it, increment Index and return to the test.

  4. Exit path

    After the fourth addition, Index becomes 5; the No path outputs Total and ends.

Common misconception

A flowchart answer must contain connected symbols and labelled branches, not only a list of the required shapes.

Check your understanding

Does the flowchart request a fifth value when Index is 5?

Check your answer

No. The condition is false, so it exits to the output.

Practice questions

Question 1 · Command word: Write3 marks

Write pseudocode for this structured English: read an integer temperature; if it is below zero display Frost, otherwise display Clear; finish after one message.

S9.07.A01S9.07.A02
Answer and marking points

One valid pseudocode solution

DECLARE Temperature : INTEGER
INPUT Temperature
IF Temperature < 0 THEN
    OUTPUT "Frost"
ELSE
    OUTPUT "Clear"
ENDIF
  1. Temperature is input as an integer.
  2. The decision tests Temperature < 0.
  3. The true and false branches output "Frost" and "Clear" respectively.

Common error: Zero belongs to the Clear branch.

Question 2 · Command word: Write3 marks

Write pseudocode equivalent to the supplied flowchart. Level is a whole-number percentage between 0 and 100. State the output for Level 20.

S9.07.A02
Answer and marking points

One valid pseudocode solution

DECLARE Level : INTEGER
INPUT Level
IF Level < 20 THEN
    OUTPUT "Refill"
ELSE
    OUTPUT "No action"
ENDIF
  1. The program inputs Level and tests Level < 20.
  2. The two branches output "Refill" or "No action" as drawn.
  3. Level 20 follows No and outputs No action.

Common error: Copy the strict comparison exactly.

Question 3 · Command word: Draw4 marks

Draw a flowchart for this structured English: input a person's height in whole centimetres; if the height is at least 120 output Enter, otherwise output Wait; end after that output.

S9.07.A03
Answer and marking points
  1. Start leads to an input parallelogram for Height.
  2. A decision diamond tests Height >= 120 with labelled branches.
  3. Yes leads to OUTPUT "Enter" and No to OUTPUT "Wait" in output symbols.
  4. Both outcomes connect forward to the end terminator.

Common error: Height 120 must follow the entry branch.

Question 4 · Command word: Draw5 marks

Draw a flowchart equivalent to the supplied pseudocode. Show the accumulator initialisation, loop condition, counter update and final output explicitly.

Use this algorithm in the question.

DECLARE Index : INTEGER
DECLARE Value : INTEGER
DECLARE Total : INTEGER
Total <- 0
FOR Index <- 1 TO 4
    INPUT Value
    Total <- Total + Value
NEXT Index
OUTPUT Total
S9.07.A03
Answer and marking points
  1. Total starts at 0 and Index at 1 before the loop condition.
  2. The decision Index <= 4 admits exactly four iterations.
  3. Each true path inputs Value and adds it to Total.
  4. Index increments and the arrow returns to the decision.
  5. The false path outputs Total and then ends.

Common error: The exit path must lead to the output, not backwards from it.

Question 1 · Command word: Write · 4 marks

Write pseudocode for this structured English: input an integer Temperature; display Low if it is below 10, High if it is above 30, and Normal otherwise; output exactly one message. State the message at Temperature 30.

Answer and marking points

One valid pseudocode solution

DECLARE Temperature : INTEGER
INPUT Temperature
IF Temperature < 10 THEN
    OUTPUT "Low"
ELSE
    IF Temperature > 30 THEN
        OUTPUT "High"
    ELSE
        OUTPUT "Normal"
    ENDIF
ENDIF
  • Temperature is input before either comparison.
  • A Temperature < 10 branch outputs "Low".
  • Otherwise, Temperature > 30 outputs "High" and the remaining case outputs "Normal".
  • Temperature 30 outputs Normal, with no second message.

Common error: Preserve the three mutually exclusive outcomes, including both boundaries.

Question 2 · Command word: Write · 4 marks

Write structured English describing the supplied flowchart, then write equivalent pseudocode. State the classification for an age of 19.

Answer and marking points

One valid pseudocode solution

DECLARE Age : INTEGER
INPUT Age
IF Age >= 18 THEN
    OUTPUT "Adult"
ELSE
    OUTPUT "Minor"
ENDIF
  • The description reads an age, classifies ages at least 18 as Adult and all other permitted ages as Minor, then finishes.
  • The pseudocode inputs Age and uses Age >= 18.
  • The true path outputs "Adult"; the false path outputs "Minor".
  • Age 19 is classified as Adult.

Common error: The condition is not equality to 18.

Question 3 · Command word: Draw · 4 marks

Draw a flowchart for the supplied countdown pseudocode. Indicate the path taken when the initial Count is zero.

Use this algorithm in the question.

DECLARE Count : INTEGER
INPUT Count
WHILE Count > 0 DO
    OUTPUT Count
    Count <- Count - 1
ENDWHILE
OUTPUT "Finished"
Answer and marking points
  • Start leads to input of Count and a Count > 0 decision.
  • The Yes path outputs Count and subtracts one before returning to the decision.
  • The No path outputs "Finished" and reaches the end.
  • An initial zero follows No immediately without outputting a number.

Common error: The decrement must lie on the return path.
