Stacks and LIFO operations

Latest-first access supports undo histories and the return order of nested calls.

How does a stack preserve last-in, first-out access?

Before you start

Edits A, B and C are made in that order. Which edit should Undo reverse first?

Check your answer

C, the most recent edit. That reversal order matches a stack.

01

Use LIFO for nested or reversible work

S10.09.A01

Visual overview

Remove the latest remaining item

A stack is a last-in, first-out structure. PUSH adds an item at the top; POP removes and returns the top item. A peek operation, if provided, reads the top item without removing it. Items below the top wait until the items above them have been removed.

Match the order to the application

Undo history and nested subroutine calls fit this access order. The latest action is undone first, and the most recent unfinished call returns before an earlier call resumes. Choose a stack because of that ordering requirement, rather than merely because the task stores several items.

Track the active history

After undoing an action it is no longer in this active undo history. Recording a new action makes that new action the top. The example models Undo only; Redo would require its own stated rules and storage.

Worked example · Follow an undo history

  1. Add actions

    Start empty, then PUSH Insert; PUSH Bold; PUSH Delete.

  2. Undo twice

    The two POP operations return Delete, then Bold.

  3. Remaining state

    Insert remains at the top; a peek reads it without deleting it.

Core explanation · Exam essentials

  • A stack uses LIFO: push and pop act at the top.
  • Peek reads without removing; use a stack when the latest remaining item must be handled first.
Common misconception

Removing the earliest action first would be FIFO and would not implement this undo rule.

Check your understanding

After PUSH A, PUSH B, POP, PUSH C, which item is popped next?

Check your answer

C; B has already been removed and C is now the newest item.

02

Track the active top in an array

S10.10.A01S10.10.A04

Visual overview

State the Top convention

In this 1-based array model, Top is the index of the last occupied element; Top = 0 means empty. To push, check that Top is below capacity, increase Top and store the new item at that position. To pop, check that Top is above zero, read the top value and decrease Top.

Keep membership and value edits separate

Editing the top item changes its stored value without changing Top. Access to a deeper item must follow the permitted interface, for example temporarily popping the items above it and restoring them in reverse removal order. Removing an item does not require erasing its old cell; positions above Top are inactive.

PUSH into a 1-based stack

  1. Check: If Top equals capacity, reject without modifying the array or Top.
  2. Reserve the next position: Increase Top by one only on the successful path.
  3. Store: Write the new value into Stack[Top].

POP from the same stack

  1. Check: If Top is zero, report empty without an array read.
  2. Read first: Save the value at Stack[Top] for the caller.
  3. Remove logically: Decrease Top by one. The old bytes may remain above the active range.

Do not invent extra access operations

This example permits an in-place edit of the active top. A different interface allowing only push and pop needs temporary storage to reach a deeper item. State that interface before choosing the operation; direct access through the backing array is not automatically available to an ADT client.

Core explanation · Exam essentials

  • With Top as the last occupied index: empty is 0 and full is capacity.
  • Check limits before changing state; read before decreasing Top on pop.
  • An allowed value edit preserves Top and the order of other items.
Common misconception

Deleting an arbitrary middle cell and leaving a gap does not preserve this stack representation.

Check your understanding

Does POP need to clear the old array cell?

Check your answer

No. Decreasing Top excludes the old cell from the active stack; the next push can overwrite it.

Question 1 · Command word: State2 teacher marks

A stack receives PUSH 7, PUSH 4, POP, PUSH 9, POP. State both returned values and the remaining stack.

S10.09.A01
Answer and checking points — teacher-written
  1. The first POP returns 4 and the second returns 9.
  2. Only 7 remains.

Common error: Read the operations in order; a popped item is no longer active.

Question 2 · Command word: Describe3 teacher marks

A stack uses Stack[1:4] and Top as the last occupied index. Top is 2 with values A, B. Describe pushing C, editing the top to D, then popping it.

S10.10.A01S10.10.A04
Answer and checking points — teacher-written
  1. Increase Top to 3 and store C at Stack[3].
  2. Replace Stack[3] with D without changing Top.
  3. Return D and decrease Top to 2, leaving A and B active.

Common error: An edit does not add another element.

Question 3 · Command word: Explain2 teacher marks

Explain why a stack suits nested subroutine return information, and state the empty condition for the Top convention used in this lesson.

S10.09.A01S10.10.A04
Answer and checking points — teacher-written
  1. The latest unfinished subroutine must return before its caller continues, matching LIFO.
  2. Top = 0 identifies an empty 1-based stack in this model.

Common error: State the chosen Top convention rather than assuming every implementation uses the same one.

04

Lesson review

Summary

LIFO

Push and pop act at the top, so the latest remaining item is removed first.

Array state

With this convention, Top = 0 is empty and Top = capacity is full.

Edits

Change values only through permitted access and preserve the order of any temporarily removed items.
