Design a ticket system · Concept 08

Combine conditions without changing the rule

Observe

Two restrictions on one request

  • At least one ticket: Quantity >= 1
  • No more than the available places: Quantity <= PlacesLeft
  • PlacesLeft = 8
  • Test 0, 1, 8 and 9

Look, then discuss

Does a request qualify if it satisfies only one of the quantity restrictions?

There are eight places left. Compare requests for 0, 1, 8 and 9 tickets. A quantity must be positive and must fit the remaining capacity. State both answers before combining them.

Recall

Compare first, combine second

Each comparison produces TRUE or FALSE. A compound expression combines these complete truth-valued conditions. Quantities and PlacesLeft are INTEGER values; PlacesLeft is non-negative.

Explain

Explanation · 1 / 4

Require both restrictions with AND

Use (Quantity >= 1) AND (Quantity <= PlacesLeft). With eight places, quantity 0 fails the first condition and 9 fails the second. Quantities 1 and 8 satisfy both, so both boundaries are included.

Explanation · 2 / 4

Use OR for genuine alternatives

A separate example offers an invitation to a performer OR a helper. Performer OR Helper is TRUE if either or both values are TRUE. This invitation example does not alter the student-only ticket discount.

Explanation · 3 / 4

Reverse a whole condition with NOT

NOT Available is TRUE when Available is FALSE. To reject the complete valid-quantity rule, use NOT ((Quantity >= 1) AND (Quantity <= PlacesLeft)), or equivalently (Quantity < 1) OR (Quantity > PlacesLeft).

Explanation · 4 / 4

Choose counterexamples before trusting the expression

Quantity >= 1 OR Quantity <= 8 wrongly admits both 0 and 9: each satisfies one side. Evaluate values at and just outside each boundary, and vary Boolean inputs independently.

Work together

Add a cancellation status to entry

Entry is allowed when a ticket has been paid for and is not cancelled. Let PaidTicket and Cancelled be BOOLEAN inputs.

Work together · 1 / 3

Translate each requirement

PaidTicket represents the first requirement. NOT Cancelled represents the requirement that cancellation must be false.

Work together · 2 / 3

Combine and test

Use PaidTicket AND NOT Cancelled. (TRUE, FALSE) allows entry; (TRUE, TRUE) rejects it; (FALSE, FALSE) also rejects it.

Work together · 3 / 3

Challenge a wrong connector

PaidTicket OR NOT Cancelled accepts an unpaid but uncancelled ticket. That counterexample shows why OR changes the rule, even though it gives the right answer for a paid uncancelled ticket.

The English requirements determine the operator; successful results for one case do not establish equivalence.

Experiment

Predict the accepted quantities with AND, then replace it with OR. Use 0 and 9 to explain the difference; test a zero-capacity performance as well.

Accept a request only when its quantity is at least 1 and no more than the places left. Compare that requirement with an expression.

Predict: Will this expression match the rule? Try each boundary.

Predict the result before revealing a step.

Check

Try it yourself · Teacher-written

Write a condition accepting a REAL parcel mass from 2 to 5 kg inclusive. Write its rejection condition and evaluate 1.9, 2, 5 and 5.1.

Check your reasoning

Accept: (Mass >= 2) AND (Mass <= 5). Reject: (Mass < 2) OR (Mass > 5), equivalently NOT ((Mass >= 2) AND (Mass <= 5)). Acceptance results are FALSE, TRUE, TRUE, FALSE.

Take it further · Optional challenge

An invitation is allowed for a performer or helper, but never for a suspended person. Construct the expression and test Performer TRUE, Helper FALSE, Suspended TRUE.

Check the challenge

(Performer OR Helper) AND NOT Suspended. The stated case is FALSE. Without the parentheses, the suspension rule may not apply to both qualifying roles as intended.

Connect

Keep this idea

AND requires both conditions; OR allows either or both; NOT reverses a truth value. Test boundaries and counterexamples.

Design a ticket system · Concept 09

Put decisions in an order that preserves the rules

Observe

Calculation and confirmation are different events

  • Quantity 2; PlacesLeft 8; Student TRUE
  • Subtotal 50.00; Total 45.00
  • Paid 40.00 is insufficient
  • Expected result: no sale; PlacesLeft stays 8

Look, then discuss

Should the desk reduce PlacesLeft as soon as it calculates a price?

A student requests two tickets from eight available places. The amount due is 45.00, but the buyer tenders only 40.00. The price calculation succeeds; the sale does not.

Recall

A returned value can be used later

Imagine giving Quantity and Student to a calculation box. It sends back the numeric Total for the caller to use in Paid >= Total. That is a returned value. Printing 45.00 on a screen does not by itself supply a numeric result to another calculation. We use this idea before formal module design.

Explain

Explanation · 1 / 4

Check quantity before asking for later data

Reject a quantity below one or above PlacesLeft. On that route, do not request student status or payment. Those values are needed only after a valid request reaches the calculation.

Explanation · 2 / 4

Calculate and keep the amount due

For a valid request, calculate the subtotal and apply the student decision. Store or receive the numeric Total and display it. A later comparison must use that value, not the text of a message.

Explanation · 3 / 4

Place state changes inside the success branch

Read Paid after displaying Total. Only if Paid >= Total should the program calculate change, subtract Quantity from PlacesLeft and confirm the sale. Underpayment leaves PlacesLeft unchanged.

Explanation · 4 / 4

Trace conditions in their actual order

A later decision can be reached only through the preceding arrows or branches. Checking a high threshold first and sending its false path directly to the end may make a middle band unreachable. Trace a failing example before proposing a repair.

Work together

Compare two payments for the same request

Use independent runs with Quantity 2, PlacesLeft 8, Student TRUE and TicketPrice 25.00. First use Paid 40.00, then Paid 45.00.

Work together · 1 / 3

Follow the common path

The request fits the eight places. Subtotal is 50.00; the returned or stored Total is 45.00. Display that amount and obtain payment.

Work together · 2 / 3

Trace the insufficient-payment run

40.00 >= 45.00 is FALSE. Display insufficient payment. Skip the availability update, so PlacesLeft remains 8.

Work together · 3 / 3

Trace exact payment

45.00 >= 45.00 is TRUE. Change is zero, PlacesLeft becomes 6 and the sale is confirmed. Exact payment belongs on the success branch.

The branch controls both the output and whether stored state is allowed to change.

Check

Try it yourself · Teacher-written

A design subtracts Quantity from PlacesLeft before testing Paid >= Total. Explain its result for the underpaid request and correct the placement.

Check your reasoning

The design wrongly reduces PlacesLeft from 8 to 6 even though payment is rejected. Move the subtraction into the sufficient-payment branch, after the payment condition succeeds. A failed payment must preserve 8 places.

Take it further · Optional challenge

For the separate bonus task, bands are 0 below 2000, 10 from 2000 through 4000, and 100 above 4000. Give a decision order and test both boundaries.

Check the challenge

First test ValueOfSales >= 2000. If FALSE, bonus is 0. If TRUE, test ValueOfSales > 4000: TRUE gives 100, FALSE gives 10. Values 2000 and 4000 both receive 10; 1999 receives 0 and 4001 receives 100.

Original question · Cambridge 9618/21

1. Diagnose a bonus flowchart

Cambridge 9618/21 · May/June 2025 · 2(a)(i), 2(a)(ii) · 2 marks

Selected parts: 2(a)(i) [1]; 2(a)(ii) [1].

Hint — reading the question

Trace a value from the failing range through the actual arrows. Then change the decisions while preserving the pay bands in the table.

Reasoning and model answer — teacher-written

2(a)(i): For a value from 2000 to 4000, the first test ValueOfSales > 4000 is false, so the path bypasses the second decision and returns the initial bonus of 0.

2(a)(ii): Swap the two decision tests. First test ValueOfSales >= 2000; on its YES path test ValueOfSales > 4000. This gives 0 below 2000, 10 from 2000 through 4000, and 100 above 4000.

Official mark scheme
Why this earns marks — teacher explanation

Each subpart has one mark. The scheme accepts identifying the wrong first decision for (i) and swapping the two decision boxes or specifying both corrected tests for (ii).

Common mistakes — teacher analysis

Changing > 4000 to >= 4000 alone does not repair the middle band. Check 1999, 2000, 4000 and 4001 after the change.

Question 1 · Command word: Write2 teacher marks

Write a logic expression that is true when Mark is between 0 and 100 inclusive. State its values for -1, 0, 100 and 101.

S9.09.A01
Answer and checking points — teacher-written
  1. (Mark >= 0) AND (Mark <= 100) requires both inclusive bounds.
  2. The four truth values are FALSE, TRUE, TRUE and FALSE.

Common error: OR would admit out-of-range values.

Question 2 · Command word: Write2 teacher marks

Write a condition for a discount given to anyone under 12 or anyone with Member TRUE. Complete the result column for the supplied cases.

S9.09.A01
Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Age : INTEGER
DECLARE Member : BOOLEAN
DECLARE Discount : BOOLEAN
INPUT Age
INPUT Member
Discount <- (Age < 12) OR Member
OUTPUT Discount
  1. (Age < 12) OR Member expresses the rule.
  2. The rows (11, FALSE), (12, FALSE) and (30, TRUE) give TRUE, FALSE and TRUE.

Common error: Membership qualifies regardless of age in this rule.

Question 3 · Command word: Write2 teacher marks

Write a condition for login when PasswordCorrect is TRUE and Locked is FALSE. Explain why replacing AND with OR changes the rule.

S9.09.A01
Answer and checking points — teacher-written
  1. PasswordCorrect AND NOT Locked requires the correct password and an unlocked account.
  2. Using OR would allow an unlocked account even when the password is wrong, or a locked account with a correct password.

Common error: NOT must apply to Locked, not PasswordCorrect.
