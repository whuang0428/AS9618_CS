Section 5 · System software

Understand system software

Open a file, change it, save it and print it. Follow the software that makes these familiar actions possible. Then follow a small program from readable source to execution and debugging.

Start the software journey →

A connected route through system software

01

Open, edit, save and print: meet the operating system

A student opens a class document, changes one line, saves a copy and prints it while music plays. Follow those familiar actions to discover the shared work that an operating system performs.

02

Maintain saved work and reuse existing code

The class document now exists as a file. Investigate six different maintenance needs before choosing a utility. Then switch to the developer’s view: use a library routine and decide how its code should be supplied.

03

Follow source code into execution

Keep three things separate: the source a programmer writes, the translator that processes it and the execution that performs the task. Use a complete small calculation to compare building an executable with interpreting a program.

04

Choose a translation route and follow Java through two stages

A team is first developing a calculation, then delivering a completed program for repeated use. Compare the same factors for each translation route. Finally, follow one Java source file through bytecode and a compatible runtime.

05

Write, inspect and correct a small program

Build a label-cost calculation: three items at four units each should cost twelve. Use editor support to enter and read it, then use execution evidence to find why one version prints six.

Learn in manageable sections

Take time to predict, observe and explain. The suggested times include discussion and short practice; use the stopping points when you need a break. Classroom shows one teaching step. Full reading keeps the explanations together for review.

  1. Part 1 · 25–40 minutes suggested

    A document needs an operating system

    Separate applications from OS services; allocate and protect working memory.

    • Who connects the application to the computer? →
    • Give running programs working space →
  2. Part 2 · 30–45 minutes suggested

    Locate, permit and print

    Follow paths and permissions, then distinguish a driver, queue and buffer.

    • Locate the document and check the requested access →
    • Let different devices work at their own speed →
  3. Part 3 · 25–40 minutes suggested

    Keep several processes progressing

    Trace waiting and ready processes, then apply memory and process management to a past-paper question.

    • Share processor time while a program waits →
  4. Part 4 · 30–45 minutes suggested

    Explain two different storage needs

    Prepare or repair file-system organisation; connect HDD block placement to head movement.

    • Prepare empty storage; investigate damaged organisation →
    • See why separated HDD blocks require more movement →
  5. Part 5 · 30–45 minutes suggested

    Protect, restore and compress

    Separate detection, recovery and representation size; choose a utility from the stated problem.

    • Detect harmful code and keep a recoverable copy →
    • Use fewer bits and choose the correct utility →
  6. Part 6 · 30–45 minutes suggested

    Reuse a routine and share a library

    Follow arguments and results, then explain DLL benefits and compatibility.

    • Call a tested routine instead of rewriting its algorithm →
    • Share a separate library and track the dependency →
  7. Part 7 · 30–45 minutes suggested

    Translate, build and run

    Distinguish assembly from high-level source and track source versus executable versions.

    • Translate assembly mnemonics for a target processor →
    • Build one version, then execute that version →
  8. Part 8 · 30–45 minutes suggested

    Follow control flow and justify a choice

    Trace interpreted execution and compare translation routes using matched factors.

    • Translate and execute along the selected path →
    • Justify a choice from the work that must be done →
  9. Part 9 · 25–40 minutes suggested

    Track Java across two stages

    Compile a complete source file, track old bytecode after an edit and identify the runtime requirement.

    • Compile Java source; run bytecode with a JVM →
  10. Part 10 · 25–40 minutes suggested

    Use an editor’s evidence

    Separate valid suggestions, syntax checking, readable formatting and code visibility.

    • Use suggestions and syntax feedback while entering code →
    • Make code readable without changing what it does →
  11. Part 11 · 30–45 minutes suggested

    Find the statement that changes the result

    Predict, pause, inspect, step, correct and verify; answer the related IDE question.

    • Pause, inspect, step and verify the correction →
