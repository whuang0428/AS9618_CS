01

Immediate, direct, indirect, indexed and relative addressing

S4.14.A01S4.14.A02

Visual overview

Rules for resolving an operand

ModeResolution rule
ImmediateUse the operand itself as the value.
DirectRead Memory[address].
IndirectRead Memory[Memory[address]]: the first read supplies another address.
IndexedRead Memory[base address + IX].
RelativeTarget address = stated PC base + signed displacement.

Swipe horizontally to compare every column →

Check the PC base

For relative addressing, use the PC convention given in the question; it may already include the fetch increment. The example instruction set supplies no separate relative-jump mnemonic, so state the base and displacement explicitly.

An effective address is a calculated or selected location. It is not the value stored at that location. Resolve the location first when the instruction reads memory, then read its contents. An immediate operand is already a value and needs no data-memory lookup.

Given Memory[100]=150, Memory[150]=7, Memory[102]=9 and IX=2: immediate #100 supplies 100; direct 100 supplies 150; indirect 100 first reads pointer 150 and then supplies 7; indexed 100 forms address 102 and supplies 9. The instruction fetch is separate from these operand accesses.

Relative addressing forms a target from a stated PC base and a signed displacement. Base 40 with −5 gives target 35; with +6 it gives 46. A branch uses that address for PC, not Memory[35] or Memory[46]. Use the base supplied by the question, because an instruction format determines which PC value is the base.

Worked example · Moving through array elements

  1. Given

    An array starts at 800; Memory[800]=21, Memory[801]=34, Memory[802]=55.

  2. First access

    With IX=1, LDX 800 reads location 801 and sets ACC=34.

  3. Next access

    INC IX makes IX=2. Another LDX 800 now reads 55 from location 802.

Core explanation · Exam essentials

  • Immediate gives a value; direct reads one location; indirect follows a pointer; indexed adds IX; relative adds a signed offset to the stated PC base.
Common misconception

A negative relative displacement moves to an earlier address; it is not a negative memory value to load.

Check your understanding

What information is missing from 'relative offset −4' alone?

Check your answer

The PC base from which to calculate the effective address.

02

Data movement: ACC, IX and memory contents

S4.13.A01S4.13.A05

Visual overview

An immediate operand supplies a value directly. The example syntax uses # for denary, B for binary and & for hexadecimal: #15, B00001111 and &0F denote the same value. A bare address instead directs an instruction to memory.

Copying preserves the source. LDD does not empty memory, MOV IX does not empty ACC, and STO does not clear ACC. This explains why later instructions can reuse the same value and why a trace must retain unchanged state.

The instruction fixes the register destination. LDR #2 puts 2 into IX; LDM #2 puts 2 into ACC. An indexed read then uses the current IX value, which may have been changed by MOV IX. Resolve that address again for each instruction rather than assuming the initial index remains in use.

Indirect and indexed addressing solve different problems: LDI follows a stored address, while LDX adds an offset to a base. With Memory[310]=303 and Memory[303]=12, LDI 310 loads 12. With IX=2 and Memory[302]=9, LDX 300 loads 9. Neither loads its effective address as the answer.

Worked example · Indexed load and store

  1. Given

    IX=2, Memory[402]=31; execute LDX 400 then STO 450.

  2. Resolve and load

    The effective address is 400+2=402. ACC becomes the stored contents, 31.

  3. Store

    STO 450 puts 31 in Memory[450]; ACC remains 31 and IX remains 2.

Data-movement instruction meanings

InstructionEffect
LDM #nACC ← n (immediate value)
LDD <address>ACC ← Memory[address]
LDI <address>ACC ← Memory[Memory[address]]
LDX <address>ACC ← Memory[address + IX]
LDR #nIX ← n (immediate value)
MOV IXIX ← ACC
STO <address>Memory[address] ← ACC

Swipe horizontally to compare every column →

Core explanation · Exam essentials

  • Resolve the source, copy to the specified destination and retain other state. LDX loads Memory[base+IX]; MOV IX copies ACC into IX; STO writes ACC to memory.
Common misconception

LDX loads the contents at address+IX, not the address+IX sum itself.

Check your understanding

If ACC=9, what does MOV IX change?

Check your answer

IX becomes 9; ACC stays 9.

Arithmetic and character input/output

S4.13.A02S4.13.A04

Visual overview

Instruction / conditionsResult

Then SUB &03ACC=12
Memory[330]=4; then ADD 330ACC=16
IX=2; INC IXIX=3, ACC stays 16

Swipe horizontally to compare every column →

Resolve an arithmetic operand before calculating. With ACC=10, ADD B00000101 gives 15 and then SUB &03 gives 12. ADD 330 instead adds the contents of address 330. A bare number in an address form is not an immediate constant.

INC IX changes IX only; DEC ACC changes ACC only. These different destinations matter when a register is used as an index or a loop counter. Use the stated number representation and width when judging overflow; do not invent a width for an otherwise unrestricted trace.

IN reads one character and stores its ASCII code in ACC. Input A gives 65; adding 1 gives 66; OUT then emits B. It does not output the two digits 6 and 6. END terminates the program after the output.

Worked example · Character conversion from start to finish

  1. Given

    PC=0, ACC=0, IX=0, input A; ASCII A=65, B=66. No data memory is used; each instruction occupies one location.

  2. Program
    0  IN
1  ADD #1
2  OUT
3  END
  3. Trace

    IN gives ACC=65 and next PC=1. ADD gives 66 and next PC=2. OUT emits B, leaves ACC=66 and gives next PC=3. END returns to the OS; IX remains 0.

Core explanation · Exam essentials

  • ADD/SUB change ACC; INC/DEC change the named register. IN reads a character code; OUT emits its character, not its printed denary digits.
Common misconception

OUT emits the character represented by ACC, not the digits of its denary value.

Check your understanding

Input A is followed by ADD #2 and OUT. What is output?

Check your answer

IN gives ASCII 65, ADD gives 67, and OUT emits C.

04

Comparison and conditional control: accept or reject input

S4.13.A03

Visual overview

A decision needs both operations

InstructionACC effectControl effect
CMP #n / CMP addressUnchanged; compare with value / contentsRecord equality result
CMI addressUnchanged; compare with indirectly addressed valueRecord equality result
JPE target / JPN targetUnchangedBranch if comparison True / False
JMP targetUnchangedAlways select target

Swipe horizontally to compare every column →

A comparison supplies a condition, then a conditional branch uses it. In the validation example, CMI 340 follows Memory[340]=341 to compare ACC with Memory[341]=65. Input A makes that comparison True; input B makes it False. CMI does not copy 65 into ACC.

JPN means jump if the comparison is not equal, not jump if ACC is negative. On the A path it falls through; after adding 1, CMP #66 is True and JPE SEND skips the rejection assignment. On the B path JPN immediately selects REJECT, avoiding the addition and the second comparison.

Keep a separate “last CMP/CMI” column. It records the comparison being explained, not an assumption that every arithmetic instruction on every CPU preserves every hardware status flag. The given sequence explicitly compares before the conditional decisions that depend on it.

Worked example · Rejected input B reaches the other output

  1. Reset

    Use the same program, PC=180, ACC=0, IX=0, Memory[340]=341 and Memory[341]=65, but input B (ASCII 66).

  2. Compare

    180: IN gives ACC=66. 181: CMI 340 compares 66 with 65, recording False.

  3. Branch and output

    182: JPN REJECT sets next PC=186. 186: LDM #63 gives ACC=63. 187: OUT emits ? (ASCII 63). 188: END returns to the OS. IX stays 0 and memory is unchanged.

  4. Contrast

    The A path emits B. The B path emits ? and never executes addresses 183–185. Both paths terminate.

Core explanation · Exam essentials

  • CMP/CMI compare without changing ACC. JPE branches on equality, JPN on inequality; JMP always branches. Follow the last explicit comparison.
Common misconception

JPE and JPN use the preceding comparison; their letters should not be expanded into invented parity or sign conditions.

Check your understanding

Does CMP #4 change ACC when ACC=6?

Check your answer

No. ACC remains 6 and the comparison result is False.

05

Trace the executed instruction sequence

S4.11.A01

Visual overview

Trace fields

FieldRecord
Executed addressThe address of the instruction just carried out
ACC / IXValues after the instruction, retaining unchanged values
Next PCSequential address or taken branch target
ComparisonTrue/False from CMP or CMI when needed for a branch
Memory/outputAny stored value or output character

Swipe horizontally to compare every column →

Start a trace from the supplied PC, register values, memory contents and input. Fetch the instruction at PC, apply its exact operation, then record the resulting state. Record a row whenever an instruction executes; a loop therefore repeats rows for the same instruction address.

Use the branch condition produced by the preceding compare operation. JPE jumps when that comparison was True; JPN jumps when it was False. A skipped instruction has no trace row. END terminates execution and returns control to the operating system, rather than fetching the following data declarations.

Write the initial conditions above the table rather than assuming registers start at zero. State the input sequence, memory values, labels or resolved addresses and any word-width rule needed by the task. An unset comparison cannot be used as if it were already True.

For each row, use the previous row’s state to resolve the operand, perform the operation, and decide the next PC. Update only the specified destination. Record a memory write when STO runs, and an output character when OUT runs; an unchanged value remains available to later instructions.

A listing is static, but the trace is the actual route through it. In a loop the same source address appears more than once; in a branch some listed addresses never appear. END is a final executed instruction whose next control destination is the OS, not the data that follows it.

Worked example · A skipped instruction

  1. Given

    At address 10: JMP 12; at 11: LDM #99; at 12: END. Initially ACC=7.

  2. First row

    Address 10 executes and sets next PC=12; ACC stays 7.

  3. Last row

    Address 12 returns to the OS. Address 11 has no row, so ACC never becomes 99.

Core explanation · Exam essentials

  • Record post-instruction state in execution order; repeat loop rows, omit skipped lines, and show comparison, memory writes and output where relevant.
Common misconception

A trace follows actual execution, not simply the printed top-to-bottom source listing.

Check your understanding

Does an unconditional JMP ever have a false condition?

Check your answer

No. It always transfers to its target when it executes.

Worked program: loop, comparison and output

S4.11.A01S4.13.A06

Visual overview

Read the loop before its trace

StageWhat to establish
Initial stateACC=0, IX=0, PC=20; Memory[90]=67; no input
Loop conditionCMP #0 followed by JPN LOOP
CompletionLoad 67, output C and END

Swipe horizontally to compare every column →

Start with the complete program and memory values before inspecting the answer. LDM #2 establishes the counter. Each visit to DEC subtracts one, CMP #0 records equality, and JPN repeats only while that comparison is False.

The counter reaches zero before execution leaves the loop, but ACC does not remain zero. LDD 90 replaces it with 67, which OUT converts to C. At termination ACC=67, IX=0, Memory[90]=67 and there is one output character.

For the boundary variant, replace the first instruction with LDM #1 and reset all initial state. There is one DEC/CMP/JPN visit: the comparison is True, so the branch is never taken. Execution addresses are 20,21,22,23,24,25,26 and the output is still C. Starting at zero would instead decrement before testing; termination would depend on numeric limits and wrap rules, which this trace does not specify.

07

Instruction groups in the example instruction set

S4.12.A01S4.12.A02S4.12.A03S4.12.A04S4.12.A05

Visual overview

Five syllabus groups

GroupInstructions
Data movementLDM, LDD, LDI, LDX, LDR, MOV, STO
Input and output of dataIN, OUT
Arithmetic operationsADD, SUB, INC, DEC
Unconditional and conditional controlJMP; JPE, JPN
Compare operationsCMP, CMI

Swipe horizontally to compare every column →

Group an instruction by the operation it performs. Movement instructions copy a value, arithmetic instructions calculate a value, and input/output instructions transfer character data between the program and its environment.

Control instructions alter the sequence of execution. JMP does so unconditionally; JPE and JPN depend on a comparison result. CMP and CMI are compare operations: they compare values without themselves jumping. END terminates the program and returns control to the operating system.

Use the traced action to classify an instruction. STO is movement because it copies ACC to memory; it is not character output. OUT is input/output because it sends the character represented by ACC to the external environment.

CMP and CMI are compare operations even though their results support later control. JMP, JPE and JPN select the next instruction address. Separating condition creation from using that condition helps locate a wrong branch in a trace.

Now apply these groups to the full programs: the indexed example obtains data, arithmetic changes the result, and a store retains it. The validation example adds comparison and control to choose which character is output. A group name should be supported by the instruction’s actual effect.

Worked example · Compare followed by control

  1. Initial value

    ACC=8; CMP #8 records comparison True without changing ACC.

  2. Conditional control

    JPE MATCH takes the branch to MATCH because the recorded result is True.

  3. Different role

    CMP makes the comparison; JPE uses it to choose the next instruction.

Core explanation · Exam essentials

  • Classify by effect: movement; input/output; arithmetic; unconditional/conditional control; compare. END terminates execution.
Common misconception

Compare operations are a separate group from the conditional jumps that use their results.

Check your understanding

Which group contains STO?

Check your answer

Data movement: it copies ACC to a memory location.

Question 3 · Command word: Calculate · 6 marks

Calculate the operand values obtained by immediate #100, direct 100, indirect 100 and indexed 100 with IX=4. Memory[100]=108, Memory[108]=19 and Memory[104]=28. Calculate a relative branch target with PC base 300 and displacement −6, and explain why the target is not the contents of location 294.

Answer and marking points
  • Immediate #100 supplies the constant 100.
  • Direct addressing reads 108 from location 100.
  • Indirect addressing first obtains address 108, then reads value 19.
  • Indexed addressing forms 100+4=104 and reads value 28.
  • The relative branch target is address 294, calculated as 300−6.
  • A branch puts the target address into PC; it does not load the data stored at that address as the target.

Common error: Do not confuse an operand read with a control-flow target.
