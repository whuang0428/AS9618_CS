Tracing instructions and addressing modes

Trace a simple assembly-language program. · Understand instruction groups: data movement, input/output, arithmetic, conditional/unconditional branch and compare. · Use the specified instruction set: LDM, LDD, LDI, LDX, LDR, MOV, STO, ADD, SUB, INC, DEC, JMP, CMP, CMI, JPE, JPN, IN, OUT and END.

Which instruction actually runs next, and which value does its operand supply?

Before you start

With Memory[200]=700 and Memory[700]=12, does LDI 200 load 700 or 12?

Check your answer

12. Indirect addressing reads the pointer 700 at location 200, then the value at location 700.

Trace the executed instruction sequence

Swipe horizontally to compare every column →

Core explanation

Start from the supplied state

Start a trace from the supplied PC, register values, memory contents and input. Fetch the instruction at PC, apply its exact operation, then record the resulting state. Record a row whenever an instruction executes; a loop therefore repeats rows for the same instruction address.

Follow branch decisions and termination

Use the branch condition produced by the preceding compare operation. JPE jumps when that comparison was True; JPN jumps when it was False. A skipped instruction has no trace row. END terminates execution and returns control to the operating system, rather than fetching the following data declarations.

Worked example · A skipped instruction

  1. Given

    At address 10: JMP 12; at 11: LDM #99; at 12: END. Initially ACC=7.

  2. First row

    Address 10 executes and sets next PC=12; ACC stays 7.

  3. Last row

    Address 12 returns to the OS. Address 11 has no row, so ACC never becomes 99.

Common misconception

A trace follows actual execution, not simply the printed top-to-bottom source listing.

Check your understanding

Does an unconditional JMP ever have a false condition?

Check your answer

No. It always transfers to its target when it executes.

Instruction groups in the example instruction set

S4.12.A01S4.12.A02S4.12.A03S4.12.A04S4.12.A05

Visual overview

Five syllabus groups

GroupInstructions
Data movementLDM, LDD, LDI, LDX, LDR, MOV, STO
Input and output of dataIN, OUT
Arithmetic operationsADD, SUB, INC, DEC
Unconditional and conditional controlJMP; JPE, JPN
Compare operationsCMP, CMI

Swipe horizontally to compare every column →

Core explanation

Group an instruction by the operation it performs. Movement instructions copy a value, arithmetic instructions calculate a value, and input/output instructions transfer character data between the program and its environment.

Control instructions alter the sequence of execution. JMP does so unconditionally; JPE and JPN depend on a comparison result. CMP and CMI are compare operations: they compare values without themselves jumping. END terminates the program and returns control to the operating system.

Worked example · Compare followed by control

  1. Initial value

    ACC=8; CMP #8 records comparison True without changing ACC.

  2. Conditional control

    JPE MATCH takes the branch to MATCH because the recorded result is True.

  3. Different role

    CMP makes the comparison; JPE uses it to choose the next instruction.

Common misconception

Compare operations are a separate group from the conditional jumps that use their results.

Check your understanding

Which group contains STO?

Check your answer

Data movement: it copies ACC to a memory location.

03

Data movement: ACC, IX and memory contents

S4.13.A01S4.13.A05

Visual overview

Core explanation

Read the operand notation

Immediate #15, B00001111 and &0F supply the same value in denary, binary and hexadecimal forms. A bare address instead directs an instruction to memory.

Copy in the specified direction
  • LDX: Add IX to the address operand, then read the contents at that effective address.
  • MOV IX: Copy ACC into IX, not IX into ACC.
  • STO: Copy ACC into memory while leaving ACC unchanged.
Preserve the source

A copy does not consume its source. LDX 400 with IX = 2 reads location 402; STO 450 then saves a copy at 450 while the original value remains at 402.

Data-movement instruction meanings

InstructionEffect
LDM #nACC ← n (immediate value)
LDD <address>ACC ← Memory[address]
LDI <address>ACC ← Memory[Memory[address]]
LDX <address>ACC ← Memory[address + IX]
LDR #nIX ← n (immediate value)
MOV IXIX ← ACC
STO <address>Memory[address] ← ACC

Swipe horizontally to compare every column →

Worked example · Indexed load and store

  1. Given

    IX=2, Memory[402]=31; execute LDX 400 then STO 450.

  2. Resolve and load

    The effective address is 400+2=402. ACC becomes the stored contents, 31.

  3. Store

    STO 450 puts 31 in Memory[450]; ACC remains 31 and IX remains 2.

Common misconception

LDX loads the contents at address+IX, not the address+IX sum itself.

Check your understanding

If ACC=9, what does MOV IX change?

Check your answer

IX becomes 9; ACC stays 9.

04

Arithmetic, comparison, branches and character I/O

S4.13.A02S4.13.A03S4.13.A04

Visual overview

Operation forms

InstructionAction
ADD #n / Bn / &n; ADD <address>Add immediate value or addressed contents to ACC
SUB #n / Bn / &n; SUB <address>Subtract immediate value or addressed contents from ACC
INC ACC / INC IX; DEC ACC / DEC IXIncrease/decrease the named register by one
CMP #n / Bn / &n; CMP <address>Compare ACC with immediate value or addressed contents
CMI <address>Compare ACC with Memory[Memory[address]]
JMP <address>Always set PC to the target
JPE <address>; JPN <address>Jump if preceding compare was True; jump if False
IN; OUT; ENDRead ASCII character; output ASCII character; return to OS

Swipe horizontally to compare every column →

Core explanation

Change values in the intended register
  • ADD / SUB: Combine ACC with an immediate operand or directly addressed contents; retain the result in ACC.
  • INC / DEC: Increase or decrease the named ACC or IX register by one.
Compare, then branch
  • CMP / CMI: CMP compares with an immediate or direct operand; CMI uses an indirect operand. Neither replaces ACC.
  • JPE / JPN: JPE jumps when the comparison was True (equal); JPN jumps when it was False (not equal). JPN does not mean negative.
Input, output and finish
  • IN: Read one character and put its ASCII value in ACC.
  • OUT: Output the character represented by ACC: 65 produces A, not the printed digits 65.
  • END: Return control to the operating system.

Worked example · An input-dependent output

  1. Given
    Input is E (ASCII 69); ACC and IX start at 0. Each instruction occupies one location.
0  IN
1  CMP #69
2  JPN REJECT
3  ADD #2
4  JMP SEND
5  REJECT: LDM #63
6  SEND: OUT
7  END
  2. Compare and branch

    IN gives ACC=69. CMP #69 is True, so JPN REJECT is not taken.

  3. Output

    ADD #2 gives 71; JMP SEND skips the rejection instruction. OUT produces G (ASCII 71), then END finishes the program.

Common misconception

JPE and JPN use the preceding comparison; their letters should not be expanded into invented parity or sign conditions.

Check your understanding

Does CMP #4 change ACC when ACC=6?

Check your answer

No. ACC remains 6 and the comparison result is False.

Core explanation

Follow execution rather than source order

The program below repeats DEC and CMP until ACC reaches zero. The same JPN instruction is taken after the first comparison and not taken after the second. The trace therefore includes two visits to each loop instruction.

Distinguish the loop counter from the output value

The load after the loop replaces the loop counter with an ASCII value before OUT executes. Separate the value used for loop control from the later output value; a register's meaning can change during a program.

Worked example · Trace the supplied loop

  1. Program and initial state
    Initially ACC=0, IX=0, PC=20; Memory[90]=67. Each instruction occupies one address. No input is required.
020  LDM #2
021  LOOP: DEC ACC
022  CMP #0
023  JPN LOOP
024  LDD 90
025  OUT
026  END
  2. First comparison

    After the first DEC, ACC=1. CMP #0 gives False; JPN returns to LOOP at address 21.

  3. Second comparison

    After the second DEC, ACC=0. CMP #0 gives True; JPN falls through to 24.

  4. Completion

    LDD 90 loads 67; OUT prints C; END returns to the OS. IX remains 0 throughout.

Common misconception

A loop trace must include the final failed branch test that lets execution leave the loop.

Check your understanding

How many times does address 23 execute, and how many times is its branch taken?

Check your answer

It executes twice; the branch is taken only on the first execution.

06

Immediate, direct, indirect, indexed and relative addressing

S4.14.A01S4.14.A02

Visual overview

Core explanation

An addressing mode specifies how to obtain an operand or target. Keep the instruction's operand, a selected address and that address's contents separate.

Rules for resolving an operand
ModeResolution rule
ImmediateUse the operand itself as the value.
DirectRead Memory[address].
IndirectRead Memory[Memory[address]]: the first read supplies another address.
IndexedRead Memory[base address + IX].
RelativeTarget address = stated PC base + signed displacement.

Swipe horizontally to compare every column →

Check the PC base

For relative addressing, use the PC convention given in the question; it may already include the fetch increment. The example instruction set supplies no separate relative-jump mnemonic, so state the base and displacement explicitly.

Worked example · Moving through array elements

  1. Given

    An array starts at 800; Memory[800]=21, Memory[801]=34, Memory[802]=55.

  2. First access

    With IX=1, LDX 800 reads location 801 and sets ACC=34.

  3. Next access

    INC IX makes IX=2. Another LDX 800 now reads 55 from location 802.

Common misconception

A negative relative displacement moves to an earlier address; it is not a negative memory value to load.

Check your understanding

What information is missing from 'relative offset −4' alone?

Check your answer

The PC base from which to calculate the effective address.

Question 6 · Command word: Calculate6 marks

Calculate the loaded operand value for immediate #200, direct 200, indirect 200 and indexed 200 with IX=3, given Memory[200]=250, Memory[250]=18 and Memory[203]=44. Calculate a relative target using a supplied PC base of 90 and displacement −6. Explain the distinction between an effective address and its contents.

S4.14.A01S4.14.A02
Answer and marking points
  1. Immediate #200 supplies value 200 without a memory lookup.
  2. Direct 200 loads Memory[200], which is 250.
  3. Indirect 200 follows address 250 and loads Memory[250], which is 18.
  4. Indexed 200 uses effective address 203 and loads value 44.
  5. Relative target = 90 + (−6) = 84.
  6. An effective address identifies a location; the operand value is the data obtained from that location when the operation reads memory.

Common error: For relative addressing use the stated PC base, not an assumed before-fetch or after-fetch convention.

Question 3 · Command word: Calculate · 6 marks

Calculate the operand values obtained by immediate #100, direct 100, indirect 100 and indexed 100 with IX=4. Memory[100]=108, Memory[108]=19 and Memory[104]=28. Calculate a relative branch target with PC base 300 and displacement −6, and explain why the target is not the contents of location 294.

Answer and marking points
  • Immediate #100 supplies the constant 100.
  • Direct addressing reads 108 from location 100.
  • Indirect addressing first obtains address 108, then reads value 19.
  • Indexed addressing forms 100+4=104 and reads value 28.
  • The relative branch target is address 294, calculated as 300−6.
  • A branch puts the target address into PC; it does not load the data stored at that address as the target.

Common error: Do not confuse an operand read with a control-flow target.

Summary

Operand resolution

Read prefixes and addressing modes before calculating a loaded or compared value.

Instruction effects

ACC/IX, memory, comparisons and PC change only as defined by the executed instruction.

Trace

Follow taken branches, repeat loop rows, record stores and output characters, and stop at END.
