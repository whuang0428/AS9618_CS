01

Unsigned binary addition and subtraction

S1.04.A01

Visual overview

Core explanation

An unsigned binary integer uses every bit as a non-negative place value. An unsigned 8-bit value represents an integer from 0 to 255.

For addition, align equal-width operands and work from the rightmost bit to the left. Use 0 + 0 = 0, 0 + 1 = 1, 1 + 1 = 10 and 1 + 1 + 1 = 11, carrying 1 into the next column when required.

For unsigned subtraction, align equal-width operands and borrow from the next column when the upper bit is smaller than the lower bit. A negative mathematical result cannot be represented as an unsigned value.

Unsigned binary addition

  1. Align equal-width operandsPlace bits with the same value in the same column.
  2. Start at the rightAdd both bits and any carry from the previous column.
  3. Write and carryWrite the result bit and carry 1 left for totals 2 or 3.
  4. Complete every columnKeep the result at the stated width for later checking.

Worked example · Add two unsigned 8-bit integers

  1. Write equal-width operands

    45 is 00101101 and 23 is 00010111.

  2. Add from right to left

    Apply the four column rules and carry 1 into the next column whenever the column total is 2 or 3.

  3. Record the result

    00101101 + 00010111 = 01000100.

  4. Interpret the result

    01000100 represents 68 as an unsigned 8-bit integer.

Common misconception

In unsigned arithmetic the most-significant bit is an ordinary positive place value; a leading 1 does not make the value negative.

02

Overflow in fixed-width arithmetic

S1.05.A01

Visual overview

Core explanation

Overflow occurs when the true mathematical result is outside the range that the stated bit width and representation can store. The stored bit pattern then cannot represent the true result.

For unsigned 8-bit addition, the permitted range is 0 to 255. A carry beyond the eighth bit shows that the true result needs nine bits; only the rightmost eight bits fit in the register.

A leftmost stored bit of 1 is not by itself overflow. For example, 01111111 + 00000001 = 10000000 represents 128 and still fits in the unsigned 8-bit range.

Check for overflow

  1. State the rangeUse the bit width and representation to establish the limits.
  2. Calculate the true resultRetain any bit produced beyond the fixed storage width.
  3. Compare with the limitsOverflow occurs only when the true result lies outside the range.
  4. Report the stored patternDistinguish the retained bits from the true mathematical result.

Worked example · Identify unsigned 8-bit overflow

  1. State the range

    Eight unsigned bits can store values from 0 to 255.

  2. Add the operands

    11110000 + 00010000 = 1 00000000, which is the true value 256.

  3. Compare with the range

    256 is greater than 255, so overflow has occurred.

  4. State the stored result

    Only 00000000 fits in the 8-bit register; it is not the true mathematical sum.

Common misconception

Overflow is not any internal carry and is not caused merely by a leftmost stored 1; it means the true result is outside the representable range.

Extension: signed binary addition and subtraction

S1.04.A02

Swipe horizontally to compare every column →

Core explanation

Signed arithmetic extends the same fixed-width column addition method to positive and negative integers. Encode every negative operand in the stated signed representation before calculating.

With two's-complement operands, add every column including the most-significant bit and discard any carry beyond the fixed width. Interpret the retained result as a two's-complement value.

To calculate A − B, form the two's complement of B and add it to A at the same width. For signed 8-bit arithmetic, the final mathematical result must remain in the range −128 to +127.

Unsigned binary addition

  1. Fix the widthUse the same number of bits for every operand and result.
  2. Encode negative operandsApply the stated signed representation before addition.
  3. Add every columnUse ordinary binary addition and discard a carry beyond the width.
  4. Interpret and range-checkDecode the retained signed result and compare it with the signed limits.

Worked example · Calculate +5 + (−3) in 8-bit two's complement

  1. Encode the operands

    +5 is 00000101 and −3 is 11111101.

  2. Add at fixed width

    00000101 + 11111101 = 1 00000010.

  3. Retain eight bits

    Discard the carry beyond the 8-bit width, leaving 00000010.

  4. Interpret the result

    00000010 is positive 2, so +5 + (−3) = +2.

Common misconception

For signed two's-complement addition, a carry beyond the most-significant bit is discarded; signed overflow is decided from the signed range, not from that carry alone.

Question 1 · Command word: Calculate · 4 marks

Calculate the 8-bit two's-complement sum 11011011 + 00010010, Give the denary value of the result in denary and state whether signed overflow occurs.

Marking points

  • The 8-bit addition produces 11101101.
  • The first operand represents -37 and the second operand represents +18.
  • Invert 11101101 and add 1 to obtain magnitude 00010011, so the result represents -19.
  • The exact result -19 lies in the 8-bit signed range -128 to +127, so no signed overflow occurs.

Question 2 · Command word: Explain · 3 marks

Two unsigned 8-bit values are added and produce the nine-bit result 1 00000010. Explain why overflow has occurred and what is stored in the 8-bit register.

Marking points

  • An unsigned 8-bit register can represent only values from 0 to 255.
  • The mathematical result needs a ninth bit, so it is outside that representable range.
  • Only the lower eight bits 00000010 remain in the register and the carry out indicates overflow.
