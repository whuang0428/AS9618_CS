INTEGER and REAL: counts and measurements

S10.01.A01S10.01.A02

Visual overview

What values must the variable allow?

QuantityPossible valuesSuitable type
Number of pupils0, 1, 2, 3, ...INTEGER: whole pupils
Change in a score-3, 0, 4INTEGER: whole-number changes
Temperature in degrees Celsius-4.0, 18.6, 20.0REAL: fractional readings allowed
Mass in kilograms0.3, 2.75, 5.0REAL: fractional measurements allowed

Swipe horizontally to compare every column →

Start with what the value means

A data type describes permitted values and helps determine which operations are appropriate.

Why a pupil count needs INTEGER

  • Whole steps: 0, 1, 2, 3, ... represent complete pupils. Zero can represent an empty class.
  • A counterexample: 18.6 pupils cannot describe a count of people.
  • Negative whole numbers: -3 is still a valid INTEGER; it can represent a score change.

The thermometer reads 20.0: choose the type

  1. Observe one reading: The current value happens to be a whole number.
  2. Read the requirement: The sensor can also report fractional readings, such as 18.6.
  3. Choose REAL: The variable must allow every permitted reading, including future fractional values.

Type validity and task validity are different

Value and contextDecision and reason
-2 as an INTEGER valueValid: it is a whole number.
-2 as a pupil countInvalid for this task: a separate check must reject negative counts.
2.75 kilogramsUse REAL when fractional kilograms must be retained.
2750 whole gramsINTEGER suits a task that stores only whole numbers of grams.

Swipe horizontally to compare every column →

Write REAL literals clearly

  • Decimal point: Write at least one digit on each side: 0.3, 20.0, -4.0.
  • Keep the distinction: The sample value, measurement units and permitted precision each help explain the chosen type.

Worked example · Select types for a weather station

  1. Read the requirements

    SamplesTaken counts completed measurements. Temperature may include tenths of a degree, even when the current reading is 20 degrees.

  2. Declare and initialise
    DECLARE SamplesTaken : INTEGER
DECLARE Temperature : REAL
SamplesTaken <- 0
Temperature <- 20.0
  3. Record the next reading
    SamplesTaken <- SamplesTaken + 1
Temperature <- 18.6
  4. Read the counter

    SamplesTaken is now 1: one completed measurement.

  5. Read the temperature

    Temperature is now 18.6. REAL allows this fractional reading even though the previous reading was 20.0.

Core explanation · Exam essentials

  • INTEGER stores whole numbers; REAL permits a fractional part.
  • Justify the type using the task's permitted values, including future inputs.
Common misconception

INTEGER is not limited to positive numbers. A whole-number example does not prove that a measured quantity should use INTEGER.

Check your understanding

A sensor currently reads 12 degrees but can report tenths of a degree. Which type should store its readings, and why?

Check your answer

REAL, because permitted future readings may contain a fractional part, such as 12.4. The current whole-number reading does not determine the type.

CHAR and STRING: characters, text and codes

S10.01.A03

Visual overview

The symbols and quotes change the meaning

LiteralTypeWhat it represents
7INTEGERA number used in arithmetic
'7'CHAROne digit character
"7"STRINGA string of length 1
"0072"STRINGFour characters, including the leading zeros
""STRINGAn empty string: zero characters

Swipe horizontally to compare every column →

Choose from the text requirement

Choose CHAR for exactly one character; choose STRING for text that may be longer or empty.

What counts as one character?

  • A letter: 'A' can represent a shelf letter.
  • A digit or symbol: '7' and '@' are characters too; CHAR is not limited to letters.
  • A space: ' ' contains one space. It is different from the empty string, which contains no characters.

Read the quotes, then count the stored characters

LiteralHow to read it
'7'Single quotes identify CHAR. One character is stored; the quotes are delimiters.
"7"Double quotes identify STRING. Length 1 does not make this CHAR.
7Without quotes, this is an INTEGER value for arithmetic.
""A valid empty STRING. An empty value cannot satisfy the one-character CHAR requirement.

Swipe horizontally to compare every column →

Choose a type for account code 0072

  1. Identify its purpose: The digits identify an account; adding or multiplying the code is not required.
  2. Preserve its representation: All four characters matter. Treating the code as the integer 72 would lose the leading zeros.
  3. Choose STRING: Store "0072" and explain the need to retain the complete identifier.

Worked example · Keep a grade and an account code distinct

  1. Choose Grade's type

    Exactly one letter is required, so use CHAR.

  2. Choose AccountCode's type

    All four characters must be retained, including leading zeros, so use STRING.

  3. Declare and assign
    DECLARE Grade : CHAR
DECLARE AccountCode : STRING
DECLARE Message : STRING
Grade <- 'A'
AccountCode <- "0048"
Message <- ""
  4. Read Grade and AccountCode

    Grade contains one character. AccountCode retains all four characters: 0048.

  5. Read Message

    Message is an empty STRING: zero characters.

  6. Spot a mismatch

    Grade <- "AB" supplies two characters to a CHAR variable.

  7. Choose the correction

    Keep CHAR and supply 'A' for a one-letter requirement. Use STRING if the requirement allows two-letter grades.

Core explanation · Exam essentials

  • CHAR holds one character; STRING holds zero or more.
  • Use single quotes for CHAR literals and double quotes for STRING literals.
  • Store codes with significant leading zeros as STRING.
Common misconception

A digit character is not a number, and a STRING containing one character does not automatically become CHAR.

Check your understanding

Identify the types of '4', "4", 4 and "". Which value cannot be stored in a CHAR variable because it contains no characters?

Check your answer

They are CHAR, STRING, INTEGER and STRING respectively. The empty string "" contains zero characters; CHAR requires exactly one.

03

BOOLEAN: store a logical state

S10.01.A04

Visual overview

Logical values and text labels

ValueTypeMeaning
TRUEBOOLEANA logical condition holds
FALSEBOOLEANA logical condition does not hold
"TRUE"STRINGFour text characters
"Yes"STRINGA text label, not a BOOLEAN literal

Swipe horizontally to compare every column →

Define the condition before storing its state

A BOOLEAN stores the answer to one logical condition: TRUE or FALSE.

Give the identifier a clear meaning

Condition being storedMeaning of its values
Paid: has payment been received?TRUE: received. FALSE: not received.
IsOpen: is the shop open?TRUE: open. FALSE: closed.
AlarmRaised: is the alarm active?TRUE: active. FALSE: inactive.

Swipe horizontally to compare every column →

Separate the logical value from a display label

  • TRUE or FALSE: BOOLEAN literals have no quotes.
  • "TRUE" or "Yes": These are STRING literals. They may be screen labels, but they are not logical values.
  • 1 or 0: These are INTEGER literals; use TRUE and FALSE in Cambridge pseudocode.

Trace the confirmation state

  1. DECLARE Confirmed : BOOLEAN: Create a variable of this type. No initial state is explicitly assigned.
  2. Confirmed <- FALSE: Set the starting state: confirmation has not been received.
  3. Confirmed <- TRUE: Update the state when confirmation arrives. The type remains BOOLEAN.

Check how many states the task needs

Pending, confirmed and cancelled are three different statuses. One BOOLEAN cannot distinguish all three; choose a representation with enough states.

Worked example · Trace a booking's confirmation flag

  1. Declare the flag

    DECLARE Confirmed : BOOLEAN

  2. Before confirmation

    Confirmed <- FALSE

  3. After confirmation is received
    Confirmed <- TRUE
OUTPUT Confirmed
  4. Trace the change

    Confirmed changes from FALSE to TRUE. OUTPUT displays TRUE; the type stays BOOLEAN.

  5. Avoid a text value

    Confirmed <- "TRUE" supplies STRING, so it is incompatible with the declared BOOLEAN type.

Core explanation · Exam essentials

  • BOOLEAN has exactly two values: TRUE and FALSE.
  • BOOLEAN literals have no quotes; "TRUE" is STRING.
Common misconception

FALSE is a stored logical value, not an empty value. Declaring a BOOLEAN does not explicitly initialise it to FALSE.

Check your understanding

Paid is declared BOOLEAN. A student writes Paid <- "FALSE". What is wrong, and how should the assignment be written?

Check your answer

"FALSE" is a STRING literal. Write Paid <- FALSE to store the BOOLEAN value without quotes.

DATE: calendar values and their format

S10.01.A05

Visual overview

Interpret dates using the stated format

ExampleInterpretationValidity
09/04/2027 as DATE, dd/mm/yyyy9 April 2027Valid calendar date
04/09/2027 as DATE, dd/mm/yyyy4 September 2027Valid, but a different date
31/04/2027 as DATE, dd/mm/yyyy31 April 2027Invalid: April has 30 days
"09/04/2027"Text containing ten charactersSTRING literal; not itself a DATE literal

Swipe horizontally to compare every column →

Store day, month and year as one date

DATE represents a valid calendar date, such as an appointment day or a book's return date.

Read 09/04/2027 using dd/mm/yyyy

  • dd = 09: The ninth day of the month.
  • mm = 04: The fourth month: April.
  • yyyy = 2027: The year. Together, the parts mean 9 April 2027.

Check a proposed date

  1. State the type: Confirm that the value represents DATE, not just a sequence of text characters.
  2. State the format: Normally use dd/mm/yyyy in Cambridge pseudocode. Date conventions differ, so make the interpretation explicit.
  3. Check the calendar: 31/04/2027 matches the pattern but is invalid: April has only 30 days.

Similar appearance does not establish the same type

RepresentationWhat the program knows
09/04/2027 as DATE, dd/mm/yyyyA calendar value: 9 April 2027.
"09/04/2027" as STRINGTen text characters. Text input must be interpreted and checked before use as a date.
31/04/2027 as a proposed DATENo such calendar day exists. Changing the display format cannot make it valid.

Swipe horizontally to compare every column →

Worked example · Record the date of a booking

  1. Specify the value

    The booking is for 9 April 2027. The following assignment uses a DATE literal in dd/mm/yyyy format.

  2. Declare and assign
    DECLARE BookingDate : DATE
BookingDate <- 09/04/2027
  3. Read the declaration

    BookingDate is a variable of type DATE.

  4. Read the assignment

    09 is the day, 04 the month and 2027 the year. The stated format identifies 9 April 2027.

  5. Check a proposed replacement

    Reject 31/04/2027: April has only 30 days. A correctly shaped value is not necessarily a valid date.

Core explanation · Exam essentials

  • DATE represents a valid calendar date.
  • State the date format explicitly; normally use dd/mm/yyyy.
Common misconception

A value can match the dd/mm/yyyy pattern and still be an invalid calendar date. A quoted date-like value is a STRING literal.

Check your understanding

Using dd/mm/yyyy, what date does 06/11/2027 represent? Why is 31/11/2027 invalid?

Check your answer

06/11/2027 represents 6 November 2027. November has 30 days, so 31/11/2027 is not a valid calendar date.

Declarations and assignments: type, name and value

S10.01.A01S10.01.A02S10.01.A03S10.01.A04S10.01.A05

Visual overview

Trace one variable through three statements

StatementWhat it establishes or changesSeats afterwards
DECLARE Seats : INTEGERIdentifier Seats; permitted type INTEGERNo value explicitly assigned yet
Seats <- 3Store the INTEGER value 33
Seats <- Seats + 1Read 3, calculate 4, then replace the old value4

Swipe horizontally to compare every column →

Name, type and current value

Keep three things separate: the identifier names a variable, the type restricts its values, and assignment sets its current value.

Read DECLARE Seats : INTEGER

PartRole
DECLAREIntroduces a variable.
SeatsThe identifier used to refer to this variable later.
:Separates the identifier from its type.
INTEGERThe declared type. No initial value has yet been explicitly assigned.

Swipe horizontally to compare every column →

Trace Seats <- Seats + 1 when Seats is 3

  1. Read the right-hand value: Seats currently contains 3.
  2. Evaluate the expression: 3 + 1 gives 4.
  3. Store on the left: Replace the previous value in Seats with 4. The variable remains INTEGER.

Spot and correct type mismatches

Assignment and declared typeDecision
Seats <- "three"; Seats is INTEGERA STRING literal is incompatible. Use Seats <- 3 when the requirement is a whole count.
Confirmed <- "TRUE"; Confirmed is BOOLEANRemove the double quotes: Confirmed <- TRUE stores a logical value.
Zone <- "AB"; Zone is CHARTwo characters do not fit CHAR. Use STRING only if the requirement now allows two-letter zones.

Swipe horizontally to compare every column →

Before reading or updating a variable

  • Initialise it: Assign a starting value before reading it. DECLARE alone does not explicitly set zero or FALSE.
  • Interpret <- as an update: Evaluate the right side, then store the result on the left; this is not a mathematical equality.

Worked example · Declare, assign and update a complete booking

  1. Read the booking fields

    Store a seat count, fractional fare, single zone letter, code with leading zeros, confirmation flag and booking date.

  2. Declare the six variables
    DECLARE Seats : INTEGER
DECLARE Fare : REAL
DECLARE Zone : CHAR
DECLARE BookingCode : STRING
DECLARE Confirmed : BOOLEAN
DECLARE BookingDate : DATE
  3. Assign initial values
    Seats <- 3
Fare <- 12.50
Zone <- 'C'
BookingCode <- "0072"
Confirmed <- FALSE
BookingDate <- 09/04/2027
  4. Check the numbers

    Seats is a whole count. Fare allows fractional currency.

  5. Check the text

    Zone holds one character. BookingCode retains four characters, including its leading zeros.

  6. Check the state and date

    Confirmed stores FALSE. BookingDate stores 9 April 2027 as DATE in dd/mm/yyyy format.

  7. Update two values
    Seats <- Seats + 1
Confirmed <- TRUE
OUTPUT Seats
OUTPUT BookingCode
OUTPUT Confirmed
  8. Read the outputs

    4, 0072 and TRUE appear on separate lines.

  9. Identify the changes

    Seats changed from 3 to 4. Confirmed changed from FALSE to TRUE.

  10. Identify what stayed the same

    BookingCode still contains 0072. Updating values has not changed any declared type.

Core explanation · Exam essentials

  • Declare with DECLARE Identifier : Type before use.
  • Assignment <- stores the right-hand result in the left-hand variable.
  • Initialise before reading; assign values compatible with the declared type.
Common misconception

A declaration specifies a type, not an initial value. Updating a variable changes its stored value, not its declared type.

Check your understanding

After DECLARE Seats : INTEGER, Seats <- 2 and Seats <- Seats + 3, what are the identifier, type and current value?

Check your answer

The identifier is Seats, its type remains INTEGER and its current value is 5. The final assignment reads 2, adds 3 and stores the result back in Seats.

ARRAY and FILE: working values and saved data

S10.01.A06

Visual overview

One score, several scores, and scores for tomorrow

RequirementConstructExample
Hold one current scoreAn INTEGER variableDECLARE Score : INTEGER
Hold five indexed scores while processingAn ARRAY of INTEGERDECLARE Scores : ARRAY[1:5] OF INTEGER
Retain scores for another executionA file in persistent storageScores.txt stores score lines that a later execution can read.

Swipe horizontally to compare every column →

Match the storage to the job

A scalar holds one value. An array groups indexed elements. A file keeps saved data for later executions.

Read DECLARE Scores : ARRAY[1:5] OF INTEGER

PartMeaning
ScoresThe identifier for the whole array.
[1:5]Inclusive lower and upper bounds: indices 1, 2, 3, 4 and 5.
OF INTEGEREach element has type INTEGER.
Scores[3]Selects the element at index 3, not the whole collection.

Swipe horizontally to compare every column →

Keep indices and values separate

  • ARRAY[1:5]: Five elements. The declaration does not itself assign five score values.
  • ARRAY[0:9]: Ten elements: both bounds count. Number of elements = upper bound - lower bound + 1.
  • Assign, then read: Changing Scores[3] leaves other elements unchanged. Only read elements after values have been assigned.

Keep scores for the next execution

  1. During this run: The array supplies working values. Declaring it does not save those values permanently.
  2. Save the required data: Write values to a file and close it. File operations transfer data to persistent storage.
  3. During a later run: Open the saved file and read the required values back into working variables.

Choose the file mode

OPENFILE modeEffect
FOR WRITECreate a new file or replace all existing contents. Then use WRITEFILE to save each line.
FOR APPENDKeep existing contents and add new lines at the end using WRITEFILE.
FOR READOpen an existing file for input. Then use READFILE to retrieve each line.

Swipe horizontally to compare every column →

Distinguish the file from its name and operations

Item or operationRole
"Scores.txt"A STRING literal naming the file; it is not the stored scores themselves.
WRITEFILE "Scores.txt", "12"Write the text 12 as one line. Opening a file alone does not write any scores.
READFILE "Scores.txt", ScoreLineRead the next line into ScoreLine, declared as STRING. Reading again advances to the next line.
EOF("Scores.txt")TRUE means no unread lines remain. Check NOT EOF before each read; an empty file needs no reads.
CLOSEFILE "Scores.txt"Finish using the file. Close it before reopening in a different mode.

Swipe horizontally to compare every column →

Worked example · Use an array, then write, append and read a text file

  1. Declare indexed working storage
    DECLARE Scores : ARRAY[1:5] OF INTEGER
Scores[1] <- 12
Scores[3] <- 18
OUTPUT Scores[3]
  2. Read the selected element

    OUTPUT displays 18 from index 3. Index 1 holds 12.

  3. Check the other positions

    Indices 2, 4 and 5 have no explicitly assigned values here, so the program does not read them.

  4. Start the separate file example

    Save two scores as text lines. These programs demonstrate file storage separately from the INTEGER array above.

  5. WRITE: create or replace the file
    OPENFILE "Scores.txt" FOR WRITE
WRITEFILE "Scores.txt", "12"
WRITEFILE "Scores.txt", "18"
CLOSEFILE "Scores.txt"
  6. Check the saved contents

    Scores.txt now contains 12 and 18 on separate lines. Any previous contents have been replaced.

  7. APPEND: keep the saved scores and add one
    OPENFILE "Scores.txt" FOR APPEND
WRITEFILE "Scores.txt", "20"
CLOSEFILE "Scores.txt"
  8. Check the extended file

    The lines are now 12, 18 and 20, in that order. APPEND retains the first two lines.

  9. READ: reopen and display every saved line
    DECLARE ScoreLine : STRING
OPENFILE "Scores.txt" FOR READ
WHILE NOT EOF("Scores.txt")
    READFILE "Scores.txt", ScoreLine
    OUTPUT ScoreLine
ENDWHILE
CLOSEFILE "Scores.txt"
  10. Expected output from the reader
    12
18
20
  11. Trace the end of the loop

    After reading 20, EOF is TRUE. The loop stops before another READFILE, and the file closes.

  12. Check what was loaded

    ScoreLine holds text, even when a line contains digits. READFILE does not automatically populate the INTEGER array.

Core explanation · Exam essentials

  • ARRAY groups indexed elements of one specified type; bounds are inclusive.
  • FILE retains saved data between runs; its quoted filename is STRING.
Common misconception

Declaring an array does not save it to a file. A quoted filename identifies stored data; it is not the data itself.

Check your understanding

What does DECLARE Reading : ARRAY[0:9] OF REAL provide, and does the declaration preserve readings after the program ends?

Check your answer

It provides ten REAL elements, indexed 0 through 9. The declaration alone does not preserve values between executions; the program must save the required data, for example by writing it to a file.

Question 1 · Command word: State2 marks

State suitable types for a number of pupils and a measured temperature of 18.6 °C. Justify each choice.

S10.01.A01S10.01.A02
Answer and marking points
  1. INTEGER suits a pupil count because only whole pupils are counted.
  2. REAL suits temperature because fractional degrees are permitted.

Common error: A sample whole-number temperature does not exclude later fractional readings.

Question 2 · Command word: Write2 marks

Write declarations and assignments for Grade containing the single letter A and AccountCode containing 0048.

S10.01.A03
Answer and marking points
  1. DECLARE Grade : CHAR followed by Grade <- 'A'.
  2. DECLARE AccountCode : STRING followed by AccountCode <- "0048".

Common error: Double quotes distinguish a string from a character literal.

Question 3 · Command word: State2 marks

State suitable types for IsOpen and an appointment date, and give one valid value for each. Use dd/mm/yyyy for the date.

S10.01.A04S10.01.A05
Answer and marking points
  1. IsOpen has type BOOLEAN and may contain TRUE.
  2. The appointment has type DATE, for example 09/04/2027 in dd/mm/yyyy format.

Common error: A BOOLEAN is not the text string "TRUE".

Question 4 · Command word: Describe2 marks

Describe what DECLARE Prices : ARRAY[1:8] OF REAL creates and why a shop might also use a file.

S10.01.A06
Answer and marking points
  1. Prices groups eight REAL elements accessed with indices 1 through 8.
  2. A file retains the prices so another execution can load them.

Common error: An array declaration alone does not save data to secondary storage.
