Build a booking system · Concept 01

Count seats and represent a price

Observe

One event booking

  • Seats requested: 3
  • Price per seat: 12.50
  • Another permitted price: 8.75

Look, then discuss

Why can a booking contain 3 seats and a price of 12.50, but not 3.5 seats?

Place three seat cards beside a price label of 12.50. Both facts use digits, but only one may take a fractional value. Decide which future values each fact must allow.

Recall

Recall a variable

A variable is a named storage location whose value can change while a program runs. An identifier such as Seats is its name. A data type describes the values it can represent and the operations that are appropriate.

Explain

Explanation · 1 / 3

Choose INTEGER for whole-number counts

Seats can be 0, 1, 2 or 3. INTEGER represents whole numbers, including negative whole numbers. A separate rule must reject a negative seat count; choosing INTEGER alone does not enforce the booking rules.

Explanation · 2 / 3

Choose REAL when fractions are allowed

A price can be 12.50 or 8.75. REAL allows a fractional part. A current price of 10.00 does not justify INTEGER if later prices may be fractional.

FactPermitted examplesType
Seats booked0, 1, 2, 3INTEGER
Price per seat10.00, 12.50, 8.75REAL
Change in seats-2, 0, 1INTEGER

Explanation · 3 / 3

Declare before storing

DECLARE Seats : INTEGER specifies a name and a type. Seats <- 3 explicitly gives it the value 3. Read <- as “is assigned”; it stores the right-hand value in the left-hand variable.

DECLARE Seats : INTEGER
DECLARE Price : REAL
Seats <- 3
Price <- 12.50

Work together

Choose a type from the requirement

An event stores the number of tickets and the mass of equipment in kilograms. Today the mass happens to be 20.0.

Work together · 1 / 2

List possible values

Tickets must be whole units, so choose INTEGER. Equipment can weigh 20.4 kg tomorrow, so choose REAL even though today’s reading has no fractional part.

Work together · 2 / 2

Check two invalid proposals

A value of -2 is an INTEGER but is unsuitable as a booking count. A value of 2.5 is unsuitable for Seats because it is not a whole number. These are different reasons for rejection.

Choose the type from all permitted values, then apply any additional rules required by the task.

Check

Try it yourself · Teacher-written

An event stores distances in whole centimetres only. Must Distance be REAL because distance is a measurement?

Check your reasoning

No. INTEGER is suitable when the stated representation allows only whole centimetres. REAL is needed if fractional centimetres must be retained. Read the required unit and permitted precision.

Connect

Keep this idea

INTEGER represents whole numbers; REAL is suitable when fractional values are required.

Some values contain digits without representing a quantity. Treat those as text.

Build a booking system · Concept 02

Preserve names, letters and leading zeros

Observe

Details printed on a booking card

  • Name: Mina
  • Zone: C
  • Booking code: 0072

Look, then discuss

Should booking code 0072 be stored as the number 72?

Compare a name card Mina, a zone letter C and the printed code 0072. The code must keep all four characters and will not be added or multiplied.

Recall

Recall a literal

A literal is a value written directly in pseudocode. Its notation matters: 72 is an INTEGER literal, while "0072" is a STRING literal.

Explain

Explanation · 1 / 3

Store one character with CHAR

A zone represented by exactly one letter fits CHAR. In Cambridge pseudocode a character literal uses single quotation marks, such as 'C'. A space or digit can also be one character.

Explanation · 2 / 3

Store a sequence with STRING

A name and a booking code need STRING. A STRING can have one character, many characters, or no characters. Double quotation marks identify string literals; "C" is therefore a STRING even though it contains one character.

Explanation · 3 / 3

Choose meaning over appearance

The string "0072" retains its leading zeros. The integer 72 represents a quantity and does not retain the four-character code. A telephone number is another identifier whose digits do not make arithmetic appropriate.

DECLARE Name : STRING
DECLARE Zone : CHAR
DECLARE BookingCode : STRING
Name <- "Mina"
Zone <- 'C'
BookingCode <- "0072"

Work together

Read the values without changing their types

Consider '7', "7", 7 and "".

Work together · 1 / 2

Use the notation

'7' is one CHAR. "7" is a one-character STRING. 7 is an INTEGER. Their visual similarity does not make them interchangeable.

Work together · 2 / 2

Explain the empty value

"" is an empty STRING with length zero. It is not the same as " ", which contains one space, and is not a valid character literal containing one character.

Read quotation marks and the required meaning before naming the type.

Check

Try it yourself · Teacher-written

A zone can now be C, D or AB. Is CHAR still suitable, and why?

Check your reasoning

No. AB needs two characters. Choose STRING for a field that must represent all three permitted zone labels.

Connect

Keep this idea

CHAR stores one character; STRING stores text, including digit sequences used as identifiers.

A yes/no state needs a logical value rather than a text label.

Build a booking system · Concept 03

Store whether a booking is confirmed

Observe

One yes/no question

  • Is the booking confirmed?
  • Before confirmation: no
  • After confirmation arrives: yes

Look, then discuss

What should Confirmed contain before the confirmation arrives?

A booking moves from unconfirmed to confirmed. There are two possible answers to the question “Is it confirmed?” Predict the starting value and the later value.

Recall

Recall a condition

A condition is an expression evaluated as TRUE or FALSE. An IF statement performs its action only when its condition is TRUE. A BOOLEAN variable can store that result.

Explain

Explanation · 1 / 3

Use the two Boolean values

BOOLEAN has exactly two values: TRUE and FALSE. FALSE is a meaningful stored state, not missing data. Use unquoted values; "FALSE" is text.

Explanation · 2 / 3

Assign the starting state

A declaration names the variable and its type but does not explicitly initialise it. Confirmed <- FALSE establishes the starting state. When confirmation arrives, assign TRUE.

DECLARE Confirmed : BOOLEAN
Confirmed <- FALSE
Confirmed <- TRUE
IF Confirmed THEN
    OUTPUT "Booking confirmed"
ENDIF

Explanation · 3 / 3

Check the number of states needed

A single BOOLEAN can answer a yes/no question. If a field must distinguish pending, confirmed and cancelled, those are three states and need a representation with more than two possible values.

Work together

Follow the state rather than the label

Confirmed starts as FALSE, then is assigned TRUE.

Work together · 1 / 2

Before the update

IF Confirmed evaluates to FALSE, so the output is skipped. The variable still has a valid Boolean value.

Work together · 2 / 2

After the update

The condition is TRUE, so the message appears. The stored value has changed; its declared BOOLEAN type has not.

Keep the data type, the current value and the decision made from that value separate.

Check

Try it yourself · Teacher-written

Paid is BOOLEAN. Correct Paid <- "FALSE" and explain the correction.

Check your reasoning

Write Paid <- FALSE. Without quotation marks, FALSE is a BOOLEAN literal. "FALSE" is a STRING and is incompatible with the declared type.

Connect

Keep this idea

Use BOOLEAN for a state with exactly two alternatives, and initialise it explicitly.

The event day is a calendar value, so its type and format also matter.

Build a booking system · Concept 04

Interpret a calendar date

Observe

The desk uses dd/mm/yyyy

  • Proposed event date: 09/04/2027
  • Another proposed date: 31/04/2027
  • Text received: "09/04/2027"

Look, then discuss

Does 09/04/2027 mean 9 April or 4 September?

The booking desk uses dd/mm/yyyy. Read the day, month and year separately before deciding whether the whole date is valid.

Recall

Recall text versus a typed value

Quotation marks denote a STRING literal. A date-shaped string is still text until it is interpreted as a date. Appearance alone does not establish the data type.

Explain

Explanation · 1 / 3

State the date convention

DATE represents a calendar date. In this course use the Cambridge dd/mm/yyyy convention: the first part is the day and the second part is the month. Thus 09/04/2027 represents 9 April 2027.

DECLARE EventDate : DATE
EventDate <- 09/04/2027

Explanation · 2 / 3

Check the calendar as well as the format

31/04/2027 has the expected pattern, but April has only 30 days. A matching pattern does not make an impossible date valid.

Explanation · 3 / 3

Separate a date from date-shaped text

EventDate <- 09/04/2027 assigns a DATE literal. The value "09/04/2027" is a STRING literal because it is enclosed in double quotation marks.

Value or proposed valueInterpretation
09/04/2027 as DATE9 April 2027
"09/04/2027"Ten text characters
31/04/2027 as DATEInvalid calendar date

Work together

Read and check a booking day

A booking asks for 06/11/2027 using dd/mm/yyyy.

Work together · 1 / 2

Interpret the parts

06 is the day, 11 is the month and 2027 is the year: 6 November 2027.

Work together · 2 / 2

Assess a replacement

Changing the day to 31 would give 31 November. November has 30 days, so reject that proposed date.

A DATE needs an unambiguous format and a valid calendar day.

Check

Try it yourself · Teacher-written

A variable is assigned "12/05/2027". What type does the literal have?

Check your reasoning

STRING. The double quotation marks make it text, even though its characters resemble a date.

Connect

Keep this idea

Use DATE for calendar values; read the format and literal notation carefully.

Build a booking system · Concept 05

Trace a declaration, an assignment and an update

Observe

Trace in statement order

  • DECLARE Seats : INTEGER
  • Seats <- 3
  • Seats <- Seats + 1

Look, then discuss

Why does Seats <- Seats + 1 make sense when Seats is 3?

Treat Seats as a labelled box containing 3. First read its old value, then calculate 3 + 1, then replace its contents. The assignment arrow describes a sequence, not a mathematical equation.

Recall

Recall how to trace

A trace follows statements in execution order and records values after each statement. Initialise a variable before reading its old value. DECLARE alone is not an instruction to set it to zero.

Explain

Explanation · 1 / 3

Name the three separate facts

In DECLARE Seats : INTEGER, Seats is the identifier and INTEGER is its type. Seats <- 3 assigns the current value. Changing that value does not change the identifier or type.

Explanation · 2 / 3

Evaluate the right side first

For Seats <- Seats + 1, read the old Seats value 3, calculate 4, and store 4 on the left. The old 3 is replaced. For Total <- Seats * Price, Seats and Price are read while Total is changed.

Explanation · 3 / 3

Trace a complete small program

The booking code keeps its leading zeros. Only Seats and Confirmed change after their initial assignments.

DECLARE Seats : INTEGER
DECLARE Price : REAL
DECLARE BookingCode : STRING
DECLARE Confirmed : BOOLEAN
Seats <- 3
Price <- 12.50
BookingCode <- "0072"
Confirmed <- FALSE
Seats <- Seats + 1
Confirmed <- TRUE
OUTPUT Seats
OUTPUT BookingCode
OUTPUT Confirmed

Work together

Record only changes caused by each statement

Start the program above with no values explicitly assigned.

Work together · 1 / 2

Trace the updates

Seats becomes 3 and later 4. BookingCode becomes "0072" and is not changed. Confirmed becomes FALSE and later TRUE.

StatementSeatsConfirmed
Seats <- 33not yet assigned
Confirmed <- FALSE3FALSE
Seats <- Seats + 14FALSE
Confirmed <- TRUE4TRUE

Work together · 2 / 2

Read the output

The displayed values are 4, 0072 and TRUE on separate lines. The program does not display Price merely because it has been declared and assigned.

A trace records the effects of executed statements; it does not invent automatic values or outputs.

Check

Try it yourself · Teacher-written

Seats is 2. After Seats <- Seats + 3 and Other <- Seats, which variable contains 5?

Check your reasoning

Both Seats and Other contain 5 after the two assignments. The second assignment reads Seats and stores that value in Other; it does not move or remove the value from Seats.

Build a booking system · Concept 06

Distinguish one value, a collection and a saved file

Observe

Three requirements

  • Handle one current attendee name.
  • Revisit five names during today’s processing.
  • Open the saved register tomorrow.

Look, then discuss

Will five names stored in variables still be available after the program ends?

The desk needs one current name, a list of names during today’s processing and a register that can be reopened tomorrow. These are three related but different requirements.

Recall

Recall a scalar value

The scalar variable Name stores one STRING at a time. Assigning the next name replaces its previous value unless the previous value has been saved elsewhere.

Explain

Explanation · 1 / 3

Keep several indexed values in an ARRAY

An ARRAY groups elements with a common declared type under one identifier. Names[1], Names[2] and Names[3] can retain different strings at the same time. The number inside brackets selects an element.

Explanation · 2 / 3

Keep data between executions in a file

A file stores saved data for later use. Writing the names to a text file allows another execution to read them. Holding the names in an array alone does not save them between runs.

Explanation · 3 / 3

Recognise their different roles

Cambridge pseudocode declares arrays and uses OPENFILE, READFILE, WRITEFILE and CLOSEFILE to handle files. We will learn those instructions when we need them; a file is not simply another indexed element of the array.

NeedRepresentation
One current attendee nameA STRING variable
Several names for repeated processing nowAn ARRAY OF STRING
Names available in a later runA file containing saved data

Work together

Plan tomorrow’s register

The program has read Mina, Jo and Sam into an array.

Work together · 1 / 2

Identify the remaining need

The array is useful for searching today, but tomorrow’s run needs persistent storage. A file must be written before the data is no longer available.

Work together · 2 / 2

Plan the return journey

Tomorrow the program opens and reads the saved file. It can then build another array for that run. The file and array support different stages of the same task.

Select ARRAY for indexed working data and FILE operations for data that must persist.

Check

Try it yourself · Teacher-written

Does declaring an array of 100 names also create a saved register file?

Check your reasoning

No. It defines an indexed collection for the program. Separate file operations are needed to save the names and read them in a later execution.

Connect

Keep this idea

An array groups working values; a file retains saved data between program executions.

Before storing many bookings, decide how the different facts about one booking belong together.

Question 1 · Command word: State2 teacher marks

State suitable types for a number of pupils and a measured temperature of 18.6 °C. Justify each choice.

S10.01.A01S10.01.A02
Answer and checking points — teacher-written
  1. INTEGER suits a pupil count because only whole pupils are counted.
  2. REAL suits temperature because fractional degrees are permitted.

Common error: A sample whole-number temperature does not exclude later fractional readings.

Write declarations and assignments for Grade containing the single letter A and AccountCode containing 0048.

Answer and checking points — teacher-written

  2. DECLARE AccountCode : STRING followed by AccountCode <- "0048".

Question 3 · Command word: State2 teacher marks

State suitable types for IsOpen and an appointment date, and give one valid value for each. Use dd/mm/yyyy for the date.

Answer and checking points — teacher-written
  1. IsOpen has type BOOLEAN and may contain TRUE.
  2. The appointment has type DATE, for example 09/04/2027 in dd/mm/yyyy format.

Question 4 · Command word: Describe2 teacher marks

Describe what DECLARE Prices : ARRAY[1:8] OF REAL creates and why a shop might also use a file.

Answer and checking points — teacher-written
  1. Prices groups eight REAL elements accessed with indices 1 through 8.
  2. A file retains the prices so another execution can load them.

Common error: An array declaration alone does not save data to secondary storage.
