Build a booking system · Concept 20

Follow one adjacent comparison and one complete pass

Observe

One ascending left-to-right pass

  • Initial array: [8, 3, 5, 1]
  • First adjacent pair: 8 and 3
  • Compare only neighbouring values.

Look, then discuss

After one left-to-right ascending pass on [8, 3, 5, 1], which value has reached its final position?

Compare neighbouring cards only. If the left value is greater than the right, exchange them. Follow the 8 as it meets 3, then 5, then 1.

Recall

Recall assignment overwrites its destination

Writing Left <- Right destroys the old Left value unless it was saved. A swap must preserve both original values, so use a temporary variable.

Explain

Explanation · 1 / 3

Decide when adjacent values are out of order

For ascending order, compare Values[Index] > Values[Index + 1]. If TRUE, exchange the values. Equal neighbours need no exchange. The greatest value encountered so far moves right after each relevant comparison.

Explanation · 2 / 3

Preserve both values in a complete swap

Save the left value in Temp, copy the right value to the left and copy Temp to the right. The three assignments exchange the originals without losing either.

Temp <- Values[Index]
Values[Index] <- Values[Index + 1]
Values[Index + 1] <- Temp

Explanation · 3 / 3

Distinguish a comparison, a swap and a pass

One comparison inspects one adjacent pair. It may or may not cause a swap. A pass visits every adjacent pair in the current unsorted region. One pass generally does not sort the entire array.

Work together

Complete the first ascending pass

Start with [8, 3, 5, 1].

Work together · 1 / 2

Move the greatest value right

Compare 8 and 3: [3, 8, 5, 1]. Compare 8 and 5: [3, 5, 8, 1]. Compare 8 and 1: [3, 5, 1, 8].

Work together · 2 / 2

Identify what is established

8 is now at its final last position. The prefix [3, 5, 1] is not sorted because 5 is still before 1. Another pass is needed.

One pass fixes the greatest remaining value at the right-hand end of the current region.

Check

Try it yourself · Teacher-written

Why is Values[Index] <- Values[Index + 1] followed by Values[Index + 1] <- Values[Index] an incorrect swap?

Check your reasoning

The first assignment overwrites the old left value. The second then copies the new left value back, leaving two copies of the old right value. Save the old left value in Temp before overwriting it.

Connect

Keep this idea

Bubble sort compares neighbours and uses a complete temporary-variable swap when they are out of order.

Repeat passes over a shrinking region and stop early when a full pass needs no swaps.

Build a booking system · Concept 21

Finish the sort and detect an already ordered region

Observe

State after the first pass

  • Current array: [3, 5, 1, 8]
  • Remaining unsorted region: indices 1 through 3
  • The next pass must record whether it makes a swap.

Look, then discuss

What does a complete pass with no swaps tell us?

After a pass on [3, 5, 1, 8], the final 8 need not be compared again. Keep a boundary for the unsorted region and a flag recording whether that pass made a change.

Recall

Recall BOOLEAN flags and nested loops

A flag records whether an event has occurred. The outer WHILE controls passes, while the inner FOR controls adjacent comparisons within one pass. Reset the flag at the beginning of every pass.

Explain

Explanation · 1 / 3

Keep the next neighbour inside the region

If Last is the last index of the unsorted region, Index must stop at Last - 1 because the comparison also reads Index + 1. After the pass, decrement Last because its old final position is fixed.

Explanation · 2 / 3

Reset and set Swapped at the correct times

Set Swapped to TRUE before the outer loop so the first pass can run. At each pass start, set it to FALSE. Set it to TRUE whenever a swap occurs. If it remains FALSE after the whole pass, all adjacent pairs in the remaining region were already in order.

Explanation · 3 / 3

Trace the complete algorithm

The algorithm below fills the array, completes the sort and displays every sorted value. Last > 1 prevents a pass when fewer than two positions remain.

DECLARE Values : ARRAY[1:7] OF INTEGER
DECLARE Index : INTEGER
DECLARE Last : INTEGER
DECLARE Temp : INTEGER
DECLARE Swapped : BOOLEAN
FOR Index <- 1 TO 7
    INPUT Values[Index]
NEXT Index
Last <- 7
Swapped <- TRUE
WHILE (Last > 1) AND Swapped
    Swapped <- FALSE
    FOR Index <- 1 TO Last - 1
        IF Values[Index] > Values[Index + 1] THEN
            Temp <- Values[Index]
            Values[Index] <- Values[Index + 1]
            Values[Index + 1] <- Temp
            Swapped <- TRUE
        ENDIF
    NEXT Index
    Last <- Last - 1
ENDWHILE
FOR Index <- 1 TO 7
    OUTPUT Values[Index]
NEXT Index

Work together

Finish sorting [8, 3, 5, 1]

Use the same algorithm with bounds 1:4.

Work together · 1 / 2

Track the boundary

Pass 1 gives [3, 5, 1, 8] and Last becomes 3. Pass 2 gives [3, 1, 5, 8] and Last becomes 2. Pass 3 gives [1, 3, 5, 8] and Last becomes 1.

Work together · 2 / 2

Test a different starting order

For [1, 3, 5, 8], the first complete pass makes no swaps. Swapped remains FALSE, so the next outer test ends the sort. The algorithm still checks the whole first pass before claiming the region is ordered.

The boundary avoids revisiting fixed values; the flag avoids further passes after a no-swap pass.

What happens if Swapped is never reset to FALSE at the beginning of a pass?
Check your reasoning
Once any swap sets it to TRUE, that value can carry into later passes. A later no-swap pass would no longer be detected correctly, so the early-stop behaviour would be lost.

Move a row’s related values together

    
Observe
Each speed belongs to its sensor
RowSpeedSensor identifier
1407

Look, then discuss
If we sort a measured speed without its sensor identifier, which sensor will the row claim produced it?
Use a two-column INTEGER table: rows (40, 7), (10, 3), (30, 9). The first column is a recorded speed and the second identifies its sensor. Each pair must remain together when rows change position.

    
Recall
Read the procedure wrapper and the loop condition
Reading[Row, 1] and Reading[Row, 2] are two elements in one row. PROCEDURE Sort() groups the sorting statements so they can be executed together; ENDPROCEDURE ends that group and CALL Sort() runs it. A REPEAT loop runs its body before testing UNTIL; it ends when that condition becomes TRUE.

    
Explain
Explanation · 1 / 5
Compare the selected key column
For ascending speed, compare the speed in row Index with the speed in row Index + 1. Do not compare the sensor identifiers to decide the order when the requirement is order by speed. The question declares Reading[1:2000, 1:2] OF INTEGER.
Explanation · 2 / 5
Swap every related column
When the speed comparison requires a swap, exchange column 1 and also exchange column 2. Use a temporary value for each exchange. Moving only the speed would attach a measurement to the wrong identifier.
IF Reading[Index, 1] > Reading[Index + 1, 1] THEN
    FOR Column <- 1 TO 2
        Temp <- Reading[Index, Column]
        Reading[Index, Column] <- Reading[Index + 1, Column]
        Reading[Index + 1, Column] <- Temp
    NEXT Column
    NoSwaps <- FALSE
ENDIF
Explanation · 3 / 5
Read a flag with the opposite name
NoSwaps starts TRUE at each pass and becomes FALSE after any swap. Its meaning is the opposite of Swapped. Continue another pass when swaps occurred and the unsorted boundary still contains a pair; do not copy a condition without checking the flag’s meaning.
Explanation · 4 / 5
Translate the boundary convention
The earlier scalar algorithm uses Last for the final right-hand index and loops to Last - 1. The exam version can use Boundary for the final left-hand comparison index: for 2000 rows, start Boundary at 1999 and loop Index from 1 to Boundary. Index + 1 then reaches at most 2000. Decrease Boundary after a pass.
Explanation · 5 / 5
Transfer the termination condition
With REPEAT, set NoSwaps to TRUE at the start of the pass and set it to FALSE after any swap. UNTIL NoSwaps = TRUE ends after a complete pass without a swap. The procedure wrapper groups these already-known operations; the task still needs complete loops and both column swaps.

Preserve each sensor’s recorded speed
Start with (40, 7), (10, 3), (30, 9), ordered by arrival.
Work together · 1 / 3
Swap the first two complete pairs
40 is greater than 10. Exchange both columns, giving (10, 3), (40, 7), (30, 9). Sensor 7 still has speed 40.
Work together · 2 / 3
Complete the pass
Compare 40 and 30 and exchange their complete rows. The result is (10, 3), (30, 9), (40, 7). A following no-swap pass confirms the remaining region is ordered.
Work together · 3 / 3
Assemble the complete procedure
Assume the global array Reading[1:3, 1:2] already holds the three supplied rows. This procedure sorts them in place; CALL Sort() runs it. Follow the same comparisons as the table trace. For the 2000-row question, the initial Boundary becomes 1999. The question asks you to write a complete procedure, so include both loops and both column exchanges.
PROCEDURE Sort()
    DECLARE Index : INTEGER
    DECLARE Column : INTEGER
    DECLARE Temp : INTEGER
    DECLARE Boundary : INTEGER
    DECLARE NoSwaps : BOOLEAN
    Boundary <- 2
    REPEAT
        NoSwaps <- TRUE
        FOR Index <- 1 TO Boundary
            IF Reading[Index, 1] > Reading[Index + 1, 1] THEN
                FOR Column <- 1 TO 2
                    Temp <- Reading[Index, Column]
                    Reading[Index, Column] <- Reading[Index + 1, Column]
                    Reading[Index + 1, Column] <- Temp
                NEXT Column
                NoSwaps <- FALSE
            ENDIF
        NEXT Index
        Boundary <- Boundary - 1
    UNTIL (NoSwaps = TRUE) OR (Boundary < 1)
ENDPROCEDURE
CALL Sort()
The sorting key decides the order, but the entire logical row must move.

Original question · Cambridge 9618/21
1. Sort paired readings without separating their sensor IDs
Cambridge 9618/21 · May/June 2025 · 6(b) · 8 marks
Selected parts: 6(b) [8].
Hint — reading the question
Each row is one reading: column 1 is speed and column 2 is its sensor ID. Sort by speed, but swap both fields together. This selected task is part 6(b) only; it does not include the test-plan question in part 6(a).
Reasoning and model answer — teacher-written
PROCEDURE Sort()
    DECLARE Temp, J, Boundary : INTEGER
    DECLARE NoSwaps : BOOLEAN
    Boundary ← 1999
    REPEAT
        NoSwaps ← TRUE
        FOR J ← 1 TO Boundary
            IF Reading[J, 1] > Reading[J + 1, 1] THEN
                Temp ← Reading[J, 1]
                Reading[J, 1] ← Reading[J + 1, 1]
                Reading[J + 1, 1] ← Temp
                Temp ← Reading[J, 2]
                Reading[J, 2] ← Reading[J + 1, 2]
                Reading[J + 1, 2] ← Temp
                NoSwaps ← FALSE
            ENDIF
        NEXT J
        Boundary ← Boundary - 1
    UNTIL NoSwaps OR Boundary = 0
ENDPROCEDURE
The initial comparison boundary is 1999 so J + 1 never exceeds row 2000. Each pass places the largest remaining speed at the end of the unsorted region, so the boundary decreases. Reset NoSwaps at the beginning of each pass and change it to FALSE whenever a swap occurs.

Start(40, 7), (10, 3), (30, 9)
After the first comparison(10, 3), (40, 7), (30, 9)
After the second comparison(10, 3), (30, 9), (40, 7)
Next pass: no swapStop; every sensor ID still belongs to its original speed.
The teacher solution additionally stops when Boundary reaches 0. The official example uses its no-swap condition to terminate. Both retain paired rows and the same ascending order.
Official mark scheme
Why this earns marks — teacher explanation
Part 6(b) is capped at eight marks across nine available marking points: procedure wrapper, conditional loop and Boolean initialisation, inner loop, correct initial bounds, adjacent comparison, temporary-variable swap, both-column swap, no-swap mechanism and reduced outer boundary.
Common mistakes — teacher analysis
Swapping speeds alone attaches sensor IDs to the wrong readings. Do not compare J = 2000 with J + 1. Reset the no-swap flag on every pass, not only before the sort.

Explain where Swapped is reset in the supplied bubble sort, when it becomes TRUE, and why the inner upper bound is Last − 1.

Answer and checking points — teacher-written
  1. Swapped is reset to FALSE at the start of every pass.
  2. An actual adjacent swap sets it TRUE.
  3. Index + 1 must be no greater than Last, so Index stops at Last − 1.
Common error: A swap flag records this pass, not whether any earlier pass swapped values.
