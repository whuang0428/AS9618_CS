01

Binary

S1.02.A01

Visual overview

Core explanation

Binary is a base-2 number system. It uses only the digits 0 and 1.

Each position has a place value that is a power of 2. Starting at the right, the place values are 1, 2, 4, 8, 16 and so on; a 1 includes its place value and a 0 does not.

Worked example · Read a binary place-value pattern

  1. Write the place values

    Above 00001101, write 128, 64, 32, 16, 8, 4, 2 and 1.

  2. Select the 1 bits

    The 1 bits select the place values 8, 4 and 1.

  3. Combine the selected values

    The value represented by 00001101 is 8 + 4 + 1 = 13.

Common misconception

A binary digit string is not read like an everyday numeral; every position has a power-of-two place value.

Check your understanding

What binary place value is immediately to the left of the 16s column?

Check your answer

32: each step left multiplies the place value by two.

Denary

S1.02.A02

Visual overview

Core explanation

Denary is a base-10 number system. It uses the digits 0 to 9.

Each position has a place value that is a power of 10. Starting at the right, the place values are 1, 10, 100, 1000 and so on.

Worked example · Read a denary numeral by place value

  1. Separate the positions

    In 407, the digits occupy the hundreds, tens and units positions.

  2. Apply the place values

    The place-value expression is 4 × 100 + 0 × 10 + 7 × 1.

  3. Combine the terms

    The represented value is 400 + 0 + 7 = 407.

Common misconception

Denary is the name of the base-10 system; it does not mean that every written number is automatically base 10.

Check your understanding

What does the zero in denary 205 tell you?

Check your answer

There are no tens; the positions distinguish two hundreds from five units.

03

Hexadecimal

S1.02.A03S1.06.A02

Visual overview

Core explanation

Hexadecimal is a base-16 number system. It uses the digits 0 to 9 followed by A, B, C, D, E and F, which represent the digit values 10 to 15.

Each position has a place value that is a power of 16. Starting at the right, the place values are 1, 16, 256, 4096 and so on.

Hexadecimal is used as a compact way for people to read long binary patterns. One hexadecimal digit represents four binary bits, so it is practical for memory addresses, machine-code or debugging values, and colour codes.

Worked example · Read a hexadecimal numeral by place value

  1. Identify the digit values

    In 3A, the digit values are 3 and 10.

  2. Apply the place values

    The left position has place value 16 and the right position has place value 1.

  3. Combine the terms

    The represented value is 3 × 16 + 10 × 1 = 58.

Common misconception

A to F are single hexadecimal digits with values 10 to 15; they are not variables or separate place values.

Check your understanding

What numerical value does hexadecimal E represent?

Check your answer

14; digits A to F represent values 10 to 15.

04

Binary Coded Decimal (BCD)

S1.02.A04S1.06.A01

Visual overview

Core explanation

Binary Coded Decimal (BCD) is a representation in which each denary digit is encoded separately as a four-bit group. Only 0000 to 1001 are valid BCD digit groups because a single denary digit can only be 0 to 9.

BCD is used when individual decimal digits must be preserved for exact input, processing or display, such as in a digital clock or calculator. This makes digit handling direct, although BCD normally uses more bits than a pure binary representation of the same integer.

Worked example · Encode the denary digits 407 in BCD

  1. Keep the digits separate

    Treat 407 as the three digits 4, 0 and 7.

  2. Encode each digit

    Use 0100 for 4, 0000 for 0 and 0111 for 7.

  3. Join the groups

    The BCD representation is 0100 0000 0111.

Common misconception

BCD does not treat the complete bit pattern as one pure binary number; each four-bit group represents one decimal digit.

Check your understanding

Which display value is encoded by BCD 0110 0010?

Check your answer

62: decode the groups separately as 6 and 2.

05

One's complement

S1.02.A05

Visual overview

Core explanation

One's complement represents a negative fixed-width binary integer by inverting every bit of the positive value: each 0 becomes 1 and each 1 becomes 0.

It is used to represent negative values and makes sign reversal a direct bit inversion. Its drawback is that it has two zero patterns, one positive and one negative, which makes zero testing and arithmetic less convenient.

Worked example · Represent −23 using one's complement

  1. Fix the width

    Write +23 using exactly 8 bits: 00010111.

  2. Invert every bit

    Change each 0 to 1 and each 1 to 0: 11101000.

  3. Label the representation

    11101000 is the 8-bit one's-complement representation of −23.

Common misconception

Do not change only the leftmost bit; one's complement requires every bit in the fixed-width pattern to be inverted.

Check your understanding

What happens when every bit of one's-complement positive zero is inverted?

Check your answer

00000000 becomes 11111111, the second representation of zero.

06

Two's complement

S1.02.A06

Visual overview

Core explanation

Two's complement represents a negative fixed-width binary integer by inverting every bit of the positive value and then adding 1 to the inverted pattern.

It is used because it provides one representation of zero and lets the same fixed-width binary addition circuitry handle positive and negative integers. In 8 bits, its representable range is −128 to +127.

Worked example · Represent −23 using two's complement

  1. Fix the width

    Write +23 using exactly 8 bits: 00010111.

  2. Invert every bit

    Invert the pattern to obtain 11101000.

  3. Add one

    Add 1 to the inverted pattern to obtain 11101001.

  4. Label the representation

    11101001 is the 8-bit two's-complement representation of −23.

Common misconception

Stopping after inversion produces the one's-complement pattern; two's complement requires the additional +1 step.

Check your understanding

What is the smallest eight-bit two's-complement integer?

Check your answer

−128, stored as 10000000; the most significant bit has weight −128.

07

Conversion between number systems and representations

S1.03.A01S1.03.A02S1.03.A03S1.03.A04S1.03.A05S1.03.A06

Visual overview

Core explanation

A conversion preserves the integer value while changing the number base or representation. Identify the source, destination and any required bit width before choosing a method.

Use powers of 2 for binary and denary, four-bit nibbles for binary and hexadecimal, powers of 16 for hexadecimal and denary, separate four-bit digit groups for BCD, and fixed-width inversion rules for one's complement and two's complement.

When there is no convenient direct route, convert through denary or binary as an intermediate representation, then reverse the route to check that the value has not changed.

Convert without changing the value

  1. Name source, destination and widthSeparate number bases, BCD and signed fixed-width representations.
  2. Apply the matching ruleUse place values, nibbles, digit groups or the stated complement rule.
  3. Preserve every required bitKeep leading zeros and the fixed width when the representation requires them.
  4. Reverse-check the resultDecode using the destination rule and confirm the original integer value.

Worked example · Convert 45 through the required representations

  1. Denary to binary

    45 = 32 + 8 + 4 + 1, so 45 is 00101101 in 8-bit binary.

  2. Binary to hexadecimal

    Group 00101101 as 0010 1101; the nibbles map to hexadecimal 2D.

  3. Hexadecimal to denary

    For 2D, calculate 2 × 16 + 13 = 45.

  4. Denary to BCD

    Encode the digits 4 and 5 separately, giving 0100 0101.

  5. Positive to one's complement

    Invert 00101101 to obtain 11010010 as the 8-bit one's-complement representation of −45.

  6. Positive to two's complement

    Add 1 to the inverted pattern to obtain 11010011 as the 8-bit two's-complement representation of −45.

Common misconception

Do not decode BCD as pure binary or use a signed representation without its fixed width; the destination representation determines the rule.

Check your understanding

Give the binary nibbles for hexadecimal A3.

Check your answer

1010 0011: each hexadecimal digit maps to four bits.

Command word: Convert4 marks

Convert the denary integer 159 to hexadecimal and then to 8-bit binary. Show your working.

S1.03.A01S1.03.A02S1.03.A03
Answer and marking points
  1. 159 = 9 × 16 + 15.
  2. The hexadecimal value is 9F.
  3. The nibbles are 9 = 1001 and F = 1111.

Command word: Explain6 marks

Explain how the base and place values determine the value of 101 in binary, denary and hexadecimal. Give each value in denary.

S1.02.A01S1.02.A02S1.02.A03
Answer and marking points
  1. Binary has base 2, so its three place values are 4, 2 and 1.
  2. Binary 101 has denary value 5.
  3. Denary has base 10, so its three place values are 100, 10 and 1.
  4. Denary 101 has value 101.
  5. Hexadecimal has base 16, so its three place values are 256, 16 and 1.
  6. Hexadecimal 101 has denary value 257.

Common error: The same written digits can represent different values when the base changes.

Command word: Give3 marks

A clock displays 59. Give its 8-bit BCD representation and explain why BCD is useful for this display.

S1.02.A04S1.03.A04S1.06.A01
Answer and marking points
  1. The digit 5 is encoded as 0101.
  2. The digit 9 is encoded as 1001, giving 0101 1001.
  3. Each display digit has its own four-bit code, so the two digits can be decoded separately.

Common error: Ordinary binary 00111011 represents the integer 59, but is not the BCD encoding of its digits.

Command word: Explain2 marks

Explain why hexadecimal is suitable for displaying a binary memory address to a programmer.

S1.06.A02
Answer and marking points
  1. One hexadecimal digit replaces four binary digits, making an address shorter to read.
  2. Each hexadecimal digit maps directly to one nibble, so the programmer can recover the binary pattern.

Common error: Hexadecimal changes the notation shown to the programmer; memory still stores bits.

Command word: Explain3 marks

Explain how one's complement represents −18 in 8 bits and state one drawback of this representation.

S1.02.A05S1.03.A05
Answer and marking points
  1. Positive 18 is 00010010 in eight bits.
  2. Inverting all eight bits gives 11101101, representing −18.
  3. One's complement has two zero patterns: 00000000 and 11111111.

Common error: Inverting includes every leading zero; keep the width fixed at eight bits.

Command word: Explain3 marks

Explain how to interpret 11101110 as an 8-bit two's-complement integer. Give its denary value and one advantage of two's complement.

S1.02.A06S1.03.A06
Answer and marking points
  1. The leading 1 identifies a negative value; invert to 00010001 and add 1 to obtain magnitude 00010010.
  2. The denary value is −18.
  3. Two's complement has only one representation of zero, or allows ordinary fixed-width addition for signed operands.

Common error: The leading bit has negative weight in two's complement; the pattern is not unsigned 238.

Command word: Convert3 marks

Convert hexadecimal 7B to an 8-bit binary value and to denary. Show the place-value calculation.

S1.03.A01S1.03.A02S1.03.A03
Answer and marking points
  1. 7 maps to 0111 and B maps to 1011, giving 01111011.
  2. The denary calculation is 7 × 16 + 11.
  3. The denary result is 123.

Question 1 · Command word: Give · 4 marks

Give the 16-bit BCD representation of the denary display value 4072 and explain why this is not the ordinary binary representation of 4072.

Answer and marking points
  • Encode the four denary digits separately as 4 = 0100, 0 = 0000, 7 = 0111 and 2 = 0010.
  • The complete BCD representation is 0100 0000 0111 0010.
  • BCD assigns one four-bit group to each displayed denary digit rather than converting the whole value in one operation.
  • Ordinary binary uses powers-of-two place values for the complete integer, so it produces a different bit pattern.

Common error: Do not convert 4072 directly to binary and label that result BCD; encode 4, 0, 7 and 2 independently.

Question 2 · Command word: Describe · 4 marks

Describe how the denary value −37 is represented in 8-bit one's complement and 8-bit two's complement, and explain why the two bit patterns differ.

Answer and marking points
  • Positive 37 has the eight-bit binary representation 00100101.
  • Inverting all eight bits gives one's complement 11011010.
  • Adding one gives two's complement 11011011.
  • The representations differ because two's complement adds one after inversion; one's complement does not.

Common error: Do not convert the magnitude separately and then attach a minus sign; the fixed-width bit pattern itself represents the negative value.

Question 3 · Command word: Explain · 4 marks

The unsigned binary value 11010110 must be written in denary and hexadecimal. Explain both conversion methods and give both results.

Answer and marking points
  • For denary, add the place values of the 1 bits: 128 + 64 + 16 + 4 + 2.
  • The denary result is 214.
  • For hexadecimal, split the binary value into the nibbles 1101 and 0110.
  • The nibbles map to D and 6, so the hexadecimal result is D6.

Common error: Do not treat the most significant bit as a sign bit because the value is explicitly unsigned.
