Build binary from familiar place values

Look, then discuss

Why does moving the 4 change its value when the symbol stays the same?

The position supplies a multiplier. Denary positions are worth 1, 10, 100 and so on. We can use the same idea with positions worth 1, 2, 4 and 8.

Recall

Base and digit

A digit is one symbol in a numeral. The base tells us how many digit symbols are available and how place values grow. A subscript such as ₂ or ₁₀ identifies the base; it is not another digit in the value.

Revisit: Count possibilities before assigning values

Explain

Explanation · 1 / 3

Read denary as a sum of place values

Denary is base 10. It uses digits 0 to 9 and each place is ten times the place to its right. Thus 304 means 3 × 100 + 0 × 10 + 4 × 1. The zero keeps the hundreds and ones in their correct places.

Explanation · 2 / 3

Change the base to two

Binary is base 2. Only 0 and 1 are available, and each place is twice the place to its right. Starting on the right, the weights are 1, 2, 4, 8, 16, 32, 64 and 128. Each 1 includes its weight; each 0 leaves it out.

Explanation · 3 / 3

Read the value, not the shape

1011₂ = 8 + 2 + 1 = 11₁₀. The symbols 1011 would mean one thousand and eleven in denary. Leading zeros do not change this unsigned value, so 00001011 is also eleven, now written using eight bits.

Look, then discuss

Which weights make exactly 45?

Start with the largest usable weight. 128 and 64 are too large. Taking 32 leaves 13, so continue deciding from left to right.

Explain

Explanation · 1 / 3

Choose and subtract

At each position, write 1 if its weight fits within the remaining amount, then subtract it. Otherwise write 0. For 45, select 32, skip 16, select 8 and 4, skip 2 and select 1. The remainder reaches zero.

Explanation · 2 / 3

Keep every position

Record a digit for every position, including unused weights between selected ones. At eight bits, 45 becomes 00101101. Dropping an internal zero moves later digits to different weights.

Explanation · 3 / 3

Understand the repeated-division alternative

Dividing a whole number by 2 leaves remainder 0 if it is even and 1 if it is odd. That remainder is the rightmost binary digit. Repeat with the whole-number quotient until it is zero, then read remainders from last to first.

Represent information · Concept 06

Read four binary bits as one hexadecimal digit

Observe

Two ways to label the same byte

  • Binary: 1010 1111
  • Hexadecimal: AF
  • A four-bit group has 16 possible patterns.

Look, then discuss

How can two hexadecimal symbols preserve all eight bits?

One symbol labels the left group and one labels the right group. There must be a distinct symbol for every value from 0 to 15, so the ten familiar digits are not enough.

Explain

Explanation · 1 / 4

Supply sixteen digit symbols

Hexadecimal is base 16. It uses 0 to 9, then A, B, C, D, E and F for values 10 to 15. Moving left multiplies the place value by 16, giving weights 1, 16, 256 and 4096.

Hex digitABCDEF
Denary value101112131415
Four-bit binary101010111100110111101111

Explanation · 2 / 4

Convert binary groups without changing the value

Group binary digits in fours from the right. Add leading zeros to the leftmost group if necessary. Convert each group separately: 1010 is A and 1111 is F. Reversing the conversion, write exactly four bits for every hexadecimal digit, including zeros.

Explanation · 3 / 4

Use hexadecimal place values

AF₁₆ = 10 × 16 + 15 = 175₁₀. To convert 175 back, 175 ÷ 16 gives quotient 10 and remainder 15, so the digits are A and F. For longer values, keep dividing the quotient by 16 and read the remainders backwards.

Explanation · 4 / 4

Explain why people use it

Hexadecimal provides a compact, human-readable view of binary values. It is used when displaying memory addresses, diagnostic values and RGB colour values. The shorter written label does not itself compress the underlying data; it changes how a person reads it.

Work together · 2 / 3

Expand each digit

2 → 0010; D → 1101; 3 → 0011. Therefore 2D3₁₆ = 0010 1101 0011₂.

Work together · 3 / 3

Reverse-check by division

723 ÷ 16 gives 45 remainder 3; 45 ÷ 16 gives 2 remainder 13 (D); 2 ÷ 16 gives 0 remainder 2. Reverse the remainders to recover 2D3.

Four-bit grouping and base-16 place values are two consistent ways to check the same conversion.

Keep decimal digits separate with BCD

Observe

A display shows 59

RuleStored pattern for 59
Unsigned binary integer00111011
Binary Coded Decimal0101 1001

Look, then discuss

Why are the stored patterns different even though the display shows the same number?

BCD encodes the displayed 5 and 9 separately. Ordinary binary encodes the whole value fifty-nine. Decide which question each representation answers.

Explain

Explanation · 1 / 3

Encode each denary digit

Binary Coded Decimal, or BCD, represents each decimal digit with its own four-bit code. For 59, convert 5 to 0101 and 9 to 1001, then keep the digit order. Do not first convert the whole value to ordinary binary.

Explanation · 2 / 3

Decode groups separately

Split a BCD pattern into groups of four. Each group must represent a digit from 0 to 9, so 1010 through 1111 are unused in the basic BCD digit code. For example, 0010 0111 decodes to the decimal digits 2 and 7, giving 27.

Explanation · 3 / 3

Link the rule to an application

A decimal counter or digital clock can keep a separate BCD code for each displayed digit, simplifying the link to decimal digit displays. Decimal arithmetic systems can also preserve decimal digits exactly when a fixed decimal place is agreed. This uses more bits than ordinary binary for many values; it is a deliberate trade-off.

Work together

Encode the reading 308

A three-digit counter stores one BCD group for each displayed digit.

Work together · 1 / 3

Encode all three digits

3 → 0011, 0 → 0000, 8 → 1000.

Work together · 2 / 3

Preserve the middle zero

The stored sequence is 0011 0000 1000. Removing the middle group would change the reading to 38.

Work together · 3 / 3

Check the storage cost

Three digits × four bits = twelve bits. Decode the three groups to recover 3, 0 and 8.

BCD preserves the sequence of decimal digits, including meaningful zero digits.

Represent information · Concept 08

Represent negatives with one’s complement

Observe

One temperature, two signs

  • At eight bits, +5 is 00000101.
  • In one’s complement, −5 is 11111010.
  • Compare the patterns one position at a time.

Look, then discuss

What single operation changes every bit of the positive pattern?

Each 0 becomes 1 and each 1 becomes 0. This is inversion. To understand the negative value, we must know both the representation and the number of bits.

Recall

Positive, negative and fixed width

The magnitude is a value’s distance from zero: +5 and −5 both have magnitude 5. Fixed width means every stored number uses the same stated number of bits, such as eight. A negative sign is not stored as an extra printed character in this model.

Revisit: Choose binary weights for a denary value · Read four binary bits as one hexadecimal digit

Explain

Explanation · 1 / 4

Reserve a signed interpretation

One’s complement is a fixed-width representation of positive and negative integers. At eight bits, positive values use ordinary binary with a leading 0. For a negative value, first write its positive magnitude at the full width, then invert every bit.

Explanation · 2 / 4

Decode a negative pattern

In one’s complement a leading 1 indicates a negative value or the special negative-zero pattern. Invert all the bits, decode the resulting positive magnitude and apply the negative sign. Invert the entire width, not just the first bit.

Explanation · 3 / 4

Understand the two zeros and range

Eight-bit +0 is 00000000. Inverting it gives 11111111, called −0. Two patterns therefore represent zero. At n bits the range is −(2ⁿ⁻¹ − 1) to +(2ⁿ⁻¹ − 1); at eight bits it is −127 to +127.

Explanation · 4 / 4

State its purpose and limitation

The rule provides a systematic binary representation of negative integers: inversion connects a positive value to its negative. The duplicate zero complicates comparisons and arithmetic, helping explain why another signed representation is useful. You do not need one’s-complement arithmetic here.

Work together

Encode and decode −37 at eight bits

The required representation is one’s complement.

Work together · 1 / 3

Encode the positive magnitude

Work together · 2 / 3

Invert every position

00100101 becomes 11011010. Do not add one.

Work together · 3 / 3

Check by reversing

Invert 11011010 to recover 00100101 = 37. The original pattern represents −37.

Keep the full width and name the representation before changing any bits.

1. Distinguish capacity, signed representation and base conversion

Cambridge 9618/12 · May/June 2023 · 4(a), 4(b), 4(c) · 5 marks

Selected parts: 4(a) [1]; 4(b) [2]; 4(c) [2].

Hint — reading the question

Treat the three subparts separately: (a) counts distinct patterns; (b) specifies eight-bit one’s complement; (c) uses hexadecimal place values. Both (b) and (c) require working.

Reasoning and model answer — teacher-written

4(a): Each bit has two possibilities, so 16 bits give 2¹⁶ = 65,536 distinct patterns. The largest unsigned value is a different quantity: 65,535.

4(b): 120 = 64 + 32 + 16 + 8, so +120 is 01111000. Invert all eight bits to represent −120 in one’s complement: 10000111. Do not add one.

4(c): A04₁₆ = 10 × 16² + 0 × 16 + 4 = 2560 + 4 = 2564. The middle zero preserves the position of A.

Official mark scheme
Why this earns marks — teacher explanation

4(a) awards one mark for 2¹⁶ or 65,536. In 4(b), showing +120 in binary earns the working mark and the inverted pattern earns the answer mark. In 4(c), a valid place-value or binary method earns one mark and 2564 earns the other.

Common mistakes — teacher analysis

65,535 is the upper endpoint, not the number of patterns. Adding one after inversion changes the requested representation to two’s complement. Reading A04 as A4 loses a place value.

What value does 1011 have under each row of weights?

The unsigned reading is 8 + 2 + 1 = 11. The signed reading is −8 + 2 + 1 = −5. The pattern has not changed; the leftmost weight has.

Explain

Explanation · 1 / 4

Use a negative leading weight

In n-bit two’s complement, the leftmost bit has weight −2ⁿ⁻¹. The remaining weights are positive powers of two. For eight bits the weights are −128, 64, 32, 16, 8, 4, 2 and 1. Add the selected weights to decode any pattern.

Explanation · 2 / 4

Encode a negative magnitude

For a representable negative value, write its magnitude as an unsigned working pattern at the required width, invert every bit and add one. Retain the stated width. For −128, the magnitude pattern is 10000000; this intermediate does not claim that +128 fits eight-bit signed storage. The negative-weight rule explains the final pattern.

Explanation · 3 / 4

Read the range and single zero

The smallest eight-bit value is 10000000 = −128. The largest is 01111111 = +127. Zero has only the pattern 00000000. In general, the range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1, with one more negative value than positive values.

Explanation · 4 / 4

Connect the representation to arithmetic

Two’s complement allows addition involving positive and negative integers to use the same column-addition process. Subtraction can be performed by adding a negative operand. The result still needs a range check: fixed-width arithmetic cannot represent every mathematical total.

Original question · Cambridge 9618/13

1. Explain a negative two’s-complement conversion

Cambridge 9618/13 · October/November 2024 · 8(b) · 3 marks

Selected parts: 8(b) [3].

Hint — reading the question

The representation is supplied. Explain a method as well as giving the denary value; a bare negative answer does not demonstrate the method.

Reasoning and model answer — teacher-written

In eight-bit two’s complement the leftmost bit has weight −128. The other set bits in 10011111 have weights 16, 8, 4, 2 and 1. Therefore the value is −128 + 16 + 8 + 4 + 2 + 1 = −97.

Alternative: invert 10011111 to obtain 01100000, then add one to obtain 01100001. Its magnitude is 64 + 32 + 1 = 97; the original value is negative, so the answer is −97.

Official mark scheme
Why this earns marks — teacher explanation

The mark scheme permits either method. Up to two marks are for the method and one is for −97. Writing both complete methods does not raise the three-mark maximum.

Common mistakes — teacher analysis

Applying ordinary unsigned weights gives 159. Flipping only the first bit is neither of the accepted conversion methods.

Represent information · Concept 10

Ask what the pattern is meant to represent

Observe

The unchanged pattern 1001 0101

  • Read it as an eight-bit unsigned integer.
  • Read it as BCD.
  • Read it as eight-bit one’s complement, then two’s complement.

Look, then discuss

Can all four readings be correct?

Each reading follows a different rule. We should expect different meanings, just as the same word can mean different things in different languages.

Explain

Explanation · 1 / 3

Name the task before choosing a method

Identify the source representation, destination representation and any required width. A base conversion preserves a numerical value; changing only how a pattern is interpreted may change its value. These are different tasks.

Explanation · 2 / 3

Match a rule to its boundaries

Unsigned binary permits values 0 to 255 at eight bits. Signed representations use narrower positive ranges. BCD treats each nibble separately and rejects groups greater than 1001. A hexadecimal numeral is a readable base-16 number; it does not by itself say whether a stored byte is signed.

Explanation · 3 / 3

Preserve the value when converting

To convert a signed pattern to another signed representation, decode its value first, then encode that value using the new rule and check that it fits. Copying the unchanged bits usually does not preserve a negative value.

Work together

Use the same eight bits in every row.

Work together · 1 / 3

Work together · 2 / 3

Read one’s complement

Invert to 01101010 = 64 + 32 + 8 + 2 = 106, so the value is −106.

Work together · 3 / 3

Read two’s complement

Use −128 + 16 + 4 + 1 = −107. The hexadecimal label for the unchanged bits is 95; that label must not be confused with BCD decimal 95.

Always attach a representation to a value claim.

  3. Each display digit has its own four-bit code, so the two digits can be decoded separately.

Common error: Ordinary binary 00111011 represents the integer 59, but is not the BCD encoding of its digits.

Command word: Explain2 teacher marks

Explain why hexadecimal is suitable for displaying a binary memory address to a programmer.

S1.06.A02
Answer and checking points — teacher-written
  1. One hexadecimal digit replaces four binary digits, making an address shorter to read.
  2. Each hexadecimal digit maps directly to one nibble, so the programmer can recover the binary pattern.

Common error: Hexadecimal changes the notation shown to the programmer; memory still stores bits.

Convert BCD 0000 0110 0000 to its three displayed digits. Explain why replacing the last group with 1100 would make it invalid BCD.

  1. The displayed digits are 060; each group decodes separately, including the leading zero.
  2. 1100 is code value 12, outside the valid BCD digit codes 0–9.

State the range of four-bit one’s complement and four-bit two’s complement. Interpret 1000 under each rule, and explain whether −8 has a four-bit one’s-complement representation.

S1.03.A05S1.03.A06S1.02.A05S1.02.A06
Answer and checking points — teacher-written
  1. Four-bit one’s complement: −7 to +7.
  2. Four-bit two’s complement: −8 to +7.
  3. 1000 is −7 in one’s complement and −8 in two’s complement.
  4. −8 lies outside the four-bit one’s-complement range, so it has no representation at that width.

Common error: The minimum signed value depends on the representation as well as the width.

Command word: Convert3 teacher marks

Convert the eight-bit one’s-complement value 11110010 to eight-bit two’s complement while preserving its denary value. Show the decoded value and the new encoding, then verify the destination value.

S1.03.A05S1.03.A06
Answer and checking points — teacher-written
  1. Invert 11110010 → 00001101 = 13, so the original signed value is −13.
  2. Encode −13 in two’s complement: invert 00001101 and add one → 11110011.
  3. The destination decodes to −128 + 64 + 32 + 16 + 2 + 1 = −13.

Common error: Copying the original bits would reinterpret them as −14 rather than preserve −13.

Command word: Explain3 teacher marks

Explain how one's complement represents −18 in 8 bits and state one drawback of this representation.

S1.02.A05S1.03.A05
Answer and checking points — teacher-written
  1. Positive 18 is 00010010 in eight bits.
  2. Inverting all eight bits gives 11101101, representing −18.
  3. One's complement has two zero patterns: 00000000 and 11111111.

Common error: Inverting includes every leading zero; keep the width fixed at eight bits.

Command word: Explain3 teacher marks

Explain how to interpret 11101110 as an 8-bit two's-complement integer. Give its denary value and one advantage of two's complement.

S1.02.A06S1.03.A06
Answer and checking points — teacher-written
  1. The leading 1 identifies a negative value; invert to 00010001 and add 1 to obtain magnitude 00010010.
  2. The denary value is −18.
  3. Two's complement has only one representation of zero, or allows ordinary fixed-width addition for signed operands.

Convert hexadecimal 7B to an 8-bit binary value and to denary. Show the place-value calculation.

S1.03.A01S1.03.A02S1.03.A03
Answer and checking points — teacher-written
  1. 7 maps to 0111 and B maps to 1011, giving 01111011.
  2. The denary calculation is 7 × 16 + 11.
  3. The denary result is 123.

Topic recap
  • Build binary from familiar place values

    A number system assigns weights to positions. In binary, those weights double towards the left.

  • Choose binary weights for a denary value

    Encode by choosing weights or reversing division remainders; decode again to check.

  • Read four binary bits as one hexadecimal digit

    One hexadecimal digit labels exactly four binary bits; hexadecimal uses base-16 place values.

  • Keep decimal digits separate with BCD

    BCD gives each decimal digit its own four-bit code; it does not encode the whole value as ordinary binary.

  • Represent negatives with one’s complement

    At a stated width, one’s complement represents a negative integer by inverting its positive magnitude.

  • Give the leftmost bit a negative weight

    Two’s complement uses a negative leading weight, one zero and a fixed signed range.

  • Ask what the pattern is meant to represent

    Conversion preserves a value under a new rule. Reinterpretation gives unchanged bits a possibly different value.
