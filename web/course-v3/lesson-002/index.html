Positional number systems: denary and binary

Start with the familiar denary system

A positional number system assigns a place value to each position. Denary has ten digit symbols, 0 to 9, and multiplies each place by 10 as you move left. Binary has two symbols, 0 and 1, and multiplies each place by 2. Leading zeros do not change a non-negative value, but they can be required by a storage width.

The same written digits can mean different values

101 in base 101 × 100 + 0 × 10 + 1 × 1101
101 in base 21 × 4 + 0 × 2 + 1 × 15
407 in base 104 × 100 + 0 × 10 + 7 × 1407; zero preserves the empty tens position

Worked example: binary 00111011 to denary

  1. Align the places: From left to right the eight places are 128, 64, 32, 16, 8, 4, 2 and 1.
  2. Select the 1 bits: 00111011 selects 32, 16, 8, 2 and 1.
  3. Add the selected weights: 32 + 16 + 8 + 2 + 1 = 59. The 0 in the 4s position contributes nothing.

Finish and verify the conversion

Reading the decisions from the 128s place to the 1s place gives 00111011. The final remainder is zero, and decoding returns 59. If an unsigned result needs more than the supplied width, report that it cannot fit; deleting its leading 1 would change its value.

Understand repeated division

Another method divides repeatedly by 2 and records the remainders. Each remainder is the next least-significant bit, so read them upwards at the end. For 13: 13 ÷ 2 gives quotient 6 remainder 1; 6 gives 3 remainder 0; 3 gives 1 remainder 1; 1 gives 0 remainder 1. Stop at quotient 0 and read 1101; pad to 00001101 for eight bits.

Core explanation · Exam essentials

  • The base determines the legal digits and the place values.
  • Decode binary by adding the weights of its 1 bits; encode by selecting weights or repeated division.
  • Keep the requested width and reverse-check the value.
Common misconception

A binary digit string is not read like an everyday numeral; every position has a power-of-two place value.

Check your understanding

Why is 102 not a valid binary numeral?

Check your answer

Binary permits only 0 and 1; the digit 2 is not available in base 2.

Sixteen digit values

Hexadecimal is base 16. Its single-digit values are 0 to 9 followed by A = 10, B = 11, C = 12, D = 13, E = 14 and F = 15. Places from the right are 1, 16, 256 and 4096. A letter such as B is one digit, not the denary numeral 11 occupying two places.

Why the four-bit shortcut works

Four binary bits have 2⁴ = 16 patterns, exactly enough for one hexadecimal digit. This is why nibble grouping works directly. It changes the notation people read, not the underlying stored bits. Memory addresses and debugging values become shorter; RGB colour components can also be shown as pairs of hexadecimal digits.

Worked example: convert denary 300 to hexadecimal

  1. First division: 300 ÷ 16 gives quotient 18, remainder 12 (C). This is the units digit.
  2. Continue: 18 ÷ 16 gives quotient 1, remainder 2. Then 1 ÷ 16 gives quotient 0, remainder 1; stop.
  3. Read upwards: The remainders give 12C. Check: 1 × 256 + 2 × 16 + 12 = 300.

Preserve position and width

For a binary integer, group from the right. Binary 101101 becomes 0010 1101 after padding the incomplete left group, giving 2D. Padding on the right would multiply the value instead. A byte always needs two hexadecimal digits when its full width is required: 00000101 becomes 05.

Explain an application through its benefit

For example, a debugging display can show the same byte as 00111011 or 3B. A programmer can recover either nibble immediately. The computer does not need to store an extra hexadecimal copy simply because the display uses hexadecimal.

Core explanation · Exam essentials

  • Hexadecimal uses 0–9 and A–F with powers-of-16 place values.
  • One hexadecimal digit maps to four bits; group binary integers from the right.
  • Hexadecimal is compact, reversible notation for addresses, debugging data and colour values.
Common misconception

A to F are single hexadecimal digits with values 10 to 15; they are not variables or separate place values.

Check your understanding

What numerical value does hexadecimal E represent?

Check your answer

14; digits A to F represent values 10 to 15.

Keep decimal digits separate

Binary Coded Decimal encodes each denary digit separately in four bits. Those groups are digit codes, not powers-of-16 places in one integer. Only 0000 through 1001 are valid digit codes; 1010 through 1111 do not represent decimal digits in this BCD model.

Worked example: encode and decode 407

  1. Separate the digits: The digits are 4, 0 and 7; the zero must retain its position.
  2. Encode each digit: 4 → 0100, 0 → 0000 and 7 → 0111. Join them as 0100 0000 0111.
  3. Decode the groups: 0100 → 4, 0000 → 0 and 0111 → 7. Joining the digits recovers 407.
  4. Check a corrupt group: 0100 1010 0111 is invalid BCD because 1010 is not a decimal digit. Do not silently read it as A.

Connect purpose to a trade-off

A clock or calculator can handle each displayed decimal digit directly from its BCD group. This is useful when the digits themselves are important. The cost is space: two BCD digits need eight bits, although unsigned 59 needs only six bits. There is no rule that all digital clocks must use BCD internally.

State the encoding boundary

A display can retain a leading zero: 007 is 0000 0000 0111 when three digit positions are required. Its numerical value is still 7. Decimal fractions and signed BCD formats require additional conventions; this lesson uses non-negative integer digits only.

Core explanation · Exam essentials

  • BCD assigns four bits to each decimal digit; only codes 0000–1001 are valid.
  • Preserve every required digit, including zero, and decode groups independently.
  • Direct decimal-digit handling can justify BCD despite its storage cost.
Common misconception

BCD does not treat the complete bit pattern as one pure binary number; each four-bit group represents one decimal digit.

Check your understanding

Which display value is encoded by BCD 0110 0010?

Check your answer

62: decode the groups separately as 6 and 2.

Define the interpretation before changing bits

A fixed width contains a limited set of bit patterns. A signed representation assigns some patterns to negative values. In one’s complement, non-negative values use ordinary binary with a leading 0. Negating a value inverts every bit at that same width, including leading zeros.

Worked round trip for −23 in eight bits

Decode the negative patternInvert 11101000 → 00010111The leading 1 identifies a negative pattern.
Restore the sign−23The inverted magnitude is 23.

Swipe horizontally to compare every column →

Derive the range and the two zeros

With n bits, the largest positive pattern has a leading 0 followed by n − 1 ones: 2ⁿ⁻¹ − 1. Its inverse is the most negative value. Eight-bit one’s complement therefore covers −127 to +127. The two remaining zero patterns are 00000000 (+0) and 11111111 (−0), so 256 patterns represent only 255 distinct integer values.

Check width and representation

An input of −128 does not fit eight-bit one’s complement. Increasing the width changes the available range and the stored pattern. An unsigned interpretation is a different rule: 11101000 is unsigned 232, not unsigned −23.

Connect representation to later arithmetic

Bit inversion makes sign reversal simple. Arithmetic still needs the rules of this representation; the two’s-complement rule for discarding the final carry cannot be transferred blindly. Lesson 003 includes a short end-around-carry comparison.

Core explanation · Exam essentials

  • Encode a negative one’s-complement integer by inverting every bit of its positive magnitude at the stated width.
  • Decode a negative pattern by inversion and restore its minus sign.
  • Eight-bit one’s complement has range −127 to +127 and two zero patterns.
Common misconception

Do not change only the leftmost bit; one's complement requires every bit in the fixed-width pattern to be inverted.

Check your understanding

Decode 11101001 as eight-bit one’s complement.

Check your answer

Invert it to 00010110 = 22; its value is −22.

Two's complement

Weight−1286432168421

Swipe horizontally to compare every column →

Use a negative place value

In two’s complement the most-significant bit has negative weight. An eight-bit pattern has weights −128, 64, 32, 16, 8, 4, 2 and 1. This gives one continuous integer range: −128 through +127. A leading 0 is non-negative; a leading 1 is negative.

Worked example: encode −23 at eight bits

  1. Write the magnitude: +23 is 00010111.
  2. Invert all bits: 00010111 → 11101000.
  3. Add one at the same width: 11101000 + 00000001 = 11101001.
  4. Verify using weights: −128 + 64 + 32 + 8 + 1 = −23.

Complete the add-one operation

Adding one may carry through trailing ones. To encode −18: +18 is 00010010; inversion gives 11101101. At the right, 1 + 1 writes 0 and carries 1; the next column 0 + 1 writes 1. The result is 11101110. Lesson 003 develops the full column method.

Reverse direction: decode 11101110

  1. Identify the sign: The leading 1 makes this a negative two’s-complement value.
  2. Find the magnitude: Invert to 00010001, then add 1 to obtain 00010010 = 18. Restore the minus sign: −18.
  3. Independently check: −128 + 64 + 32 + 8 + 4 + 2 = −18.

Derive the asymmetric range

For n bits the smallest value is −2ⁿ⁻¹: only the negative-weight bit is set. The largest is 2ⁿ⁻¹ − 1: that bit is 0 and all remaining bits are 1. There is one zero, all bits 0. Inverting zero and adding one produces a carry beyond the width and leaves the same zero pattern.

Handle the smallest negative value

At eight bits, 10000000 means −128 directly from its negative weight. Invert-and-add-one returns 10000000 again: its unsigned magnitude is 128, but +128 is not an eight-bit signed value. Do not treat this as successful signed negation; use the negative weight to decode the minimum. Positive 128 and negative 129 are both outside the signed range.

Explain why the representation supports addition

For a positive magnitude m, inversion makes the unsigned value 255 − m and adding one makes 256 − m. Adding this pattern to m produces 256, leaving zero when only eight bits are retained. This explains how a fixed-width adder can handle subtraction and why the carry alone does not decide signed overflow.

Core explanation · Exam essentials

  • Two’s-complement weights begin with −2ⁿ⁻¹; the range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.
  • Encode negative values by inversion then addition of one; decode using weights or the inverse process.
  • The minimum negative value has no positive counterpart at the same signed width.
Common misconception

Stopping after inversion produces the one's-complement pattern; two's complement requires the additional +1 step.

Check your understanding

What is the smallest eight-bit two's-complement integer?

Check your answer

−128, stored as 10000000; the most significant bit has weight −128.

Use an intermediate value when rules differ

To preserve −23 while converting between signed representations, decode the source to −23 first, then encode −23 under the destination rule: one’s complement 11101000 becomes two’s complement 11101001. Keeping the bits unchanged would not preserve the value.

Reject impossible conversions

A destination may be unable to represent the value. A negative integer cannot be stored in the unsigned or non-negative BCD models used here; +200 fits eight unsigned bits but not eight-bit two’s complement. State the limitation instead of silently truncating or reinterpreting the result.

Core explanation · Exam essentials

  • Conversion preserves the integer value; negation changes its sign; reinterpretation keeps the bits but changes their meaning.
  • Name the representation and width, convert, then decode to check.
  • Report values outside the destination range instead of dropping significant bits.
Common misconception

Do not decode BCD as pure binary or use a signed representation without its fixed width; the destination representation determines the rule.

Check your understanding

A student calls 00101101 → 11010011 a value-preserving conversion from +45 to two’s complement. Correct the claim.

Check your answer

+45 remains 00101101 in eight-bit two’s complement. 11010011 represents −45, so the student has negated the value.

Original question · Cambridge 9618/12

1. Distinguish capacity, signed representation and base conversion

Cambridge 9618/12 · May/June 2023 · 4(a), 4(b), 4(c) · 5 marks

Selected parts: 4(a) [1]; 4(b) [2]; 4(c) [2].

Reading the question — teacher guidance

Treat the three subparts separately: (a) counts distinct patterns; (b) specifies eight-bit one’s complement; (c) uses hexadecimal place values. Both (b) and (c) require working.

Solution / model answer — teacher-written

4(a): Each bit has two possibilities, so 16 bits give 2¹⁶ = 65,536 distinct patterns. The largest unsigned value is a different quantity: 65,535.

4(b): 120 = 64 + 32 + 16 + 8, so +120 is 01111000. Invert all eight bits to represent −120 in one’s complement: 10000111. Do not add one.

4(c): A04₁₆ = 10 × 16² + 0 × 16 + 4 = 2560 + 4 = 2564. The middle zero preserves the position of A.

Official mark scheme
Why this earns marks — teacher explanation

4(a) awards one mark for 2¹⁶ or 65,536. In 4(b), showing +120 in binary earns the working mark and the inverted pattern earns the answer mark. In 4(c), a valid place-value or binary method earns one mark and 2564 earns the other.

Common mistakes — teacher analysis

65,535 is the upper endpoint, not the number of patterns. Adding one after inversion changes the requested representation to two’s complement. Reading A04 as A4 loses a place value.

Original question · Cambridge 9618/13

2. Explain a negative two’s-complement conversion

Cambridge 9618/13 · October/November 2024 · 8(b) · 3 marks

Selected parts: 8(b) [3].

Reading the question — teacher guidance

The representation is supplied. Explain a method as well as giving the denary value; a bare negative answer does not demonstrate the method.

Solution / model answer — teacher-written

In eight-bit two’s complement the leftmost bit has weight −128. The other set bits in 10011111 have weights 16, 8, 4, 2 and 1. Therefore the value is −128 + 16 + 8 + 4 + 2 + 1 = −97.

Alternative: invert 10011111 to obtain 01100000, then add one to obtain 01100001. Its magnitude is 64 + 32 + 1 = 97; the original value is negative, so the answer is −97.

Official mark scheme
Why this earns marks — teacher explanation

The mark scheme permits either method. Up to two marks are for the method and one is for −97. Writing both complete methods does not raise the three-mark maximum.

Common mistakes — teacher analysis

Applying ordinary unsigned weights gives 159. Flipping only the first bit is neither of the accepted conversion methods.

Lesson review

Summary

Positional number systems: denary and binary

The base determines the legal digits and the place values. Decode binary by adding the weights of its 1 bits; encode by selecting weights or repeated division. Keep the requested width and reverse-check the value.

Hexadecimal

Hexadecimal uses 0–9 and A–F with powers-of-16 place values. One hexadecimal digit maps to four bits; group binary integers from the right. Hexadecimal is compact, reversible notation for addresses, debugging data and colour values.

Binary Coded Decimal (BCD)

BCD assigns four bits to each decimal digit; only codes 0000–1001 are valid. Preserve every required digit, including zero, and decode groups independently. Direct decimal-digit handling can justify BCD despite its storage cost.

One's complement

Encode a negative one’s-complement integer by inverting every bit of its positive magnitude at the stated width. Decode a negative pattern by inversion and restore its minus sign. Eight-bit one’s complement has range −127 to +127 and two zero patterns.

Two's complement

Two’s-complement weights begin with −2ⁿ⁻¹; the range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1. Encode negative values by inversion then addition of one; decode using weights or the inverse process. The minimum negative value has no positive counterpart at the same signed width.

Conversion between number systems and representations

Conversion preserves the integer value; negation changes its sign; reinterpretation keeps the bits but changes their meaning. Name the representation and width, convert, then decode to check. Report values outside the destination range instead of dropping significant bits.
