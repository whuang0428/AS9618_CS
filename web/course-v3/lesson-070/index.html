Implementing ADT operations with arrays

Track active positions and reusable storage as operations change an array-backed structure.

Which representation rules must remain true after an ADT operation?

Before you start

Does an old value left in an unused array cell still belong to an ADT?

Check your answer

No. Membership is determined by the active range, queue state or reachable link chain, not by old bytes alone.

Check active positions when an array is reused

Core explanation

Check active state before each operation

An array-backed stack and queue can contain inactive cells whose old values are still visible in memory. For a stack with Top as the last occupied index, only positions 1 through Top are active. For a circular queue, Count active positions begin at Front and wrap through the array; Rear identifies the last one when Count is positive.

Reject invalid changes without corrupting stored data

Check representation state before adding, editing or deleting. A full structure cannot accept another item without a specified capacity change; an empty structure cannot supply an item. Value edits preserve membership and order, whereas push/pop or enqueue/dequeue change membership and must update the corresponding state variables.

Worked example · Check an edit against active membership

  1. Given

    Capacity 4. Three items A, B and C occupy slots 3, 4 and 1 in FIFO order; the next removal is at 3.

  2. Edit

    Changing the value at slot 4 to X preserves the active order A, X, C and all three state variables.

  3. Invalid position

    Slot 2 is inactive. Writing there alone does not enqueue an item because Rear and Count were not updated.

Common misconception

Storing a value in a spare array cell is not a complete ADT addition; the representation must make that cell active.

Check your understanding

A stack has Top = 2. Does editing Stack[4] edit an existing stack item?

Check your answer

No. Position 4 is outside the active stack.

02

Track free nodes separately from the active list

S10.10.A03S10.10.A04

Visual overview

Core explanation

Track available storage separately

A fixed array can link unused nodes into a free list with its own Free head. Active and free chains must be disjoint. Free = 0 means no unused slot remains.

Allocate a free node
  1. Take the head: Save the node identified by Free.
  2. Advance Free: Read its old free link before reusing that link.
  3. Join the active chain: Write the new active links while preserving access to the existing successor.
Release a deleted node
  1. Unlink it: Remove it from the active chain first.
  2. Join the free chain: Point it to the old Free head, then make it the new Free head. Surviving node data need not move.

Worked example · Move a node between chains

  1. Allocate

    Save slot 1 from Free; advance Free from 1 to 3; set Next[1] to 4 and Next[2] to 1.

  2. Delete slot 4

    Set Next[1] to 0 so slot 4 is no longer active.

  3. Release

    Set Next[4] to the old Free value 3, then set Free to 4. The two chains remain disjoint.

Common misconception

Returning a node to the free list before unlinking it from the active list can make both lists use the same slot.

Check your understanding

Why must the old free link be saved before an allocated node's Next field is overwritten?

Check your answer

Otherwise the remaining free nodes may become unreachable, losing track of available capacity.

Practice questions

Question 1 · Command word: Describe3 marks

A capacity-5 stack has Top = 3. Describe one pop followed by editing the new top; state which positions remain active.

S10.10.A01S10.10.A04
Answer and marking points
  1. Read Stack[3] and decrease Top to 2.
  2. Edit Stack[2] without changing Top.
  3. Only positions 1 and 2 remain active.

Common error: The old content at position 3 does not remain a stack member.

Question 2 · Command word: State3 marks

A capacity-5 circular queue has Front = 4, Rear = 1 and Count = 3. State its active positions, the position used by the next enqueue and the full condition.

S10.10.A02S10.10.A04
Answer and marking points
  1. The active positions are 4, 5 and 1.
  2. The next enqueue uses position 2 and increases Count to 4.
  3. The queue is full only when Count = 5.

Common error: Rear < Front does not imply that the queue is empty.

Question 3 · Command word: State3 marks

Initially the active chain is 2 → 4 → 0 and the free chain is 1 → 3 → 0. Allocate slot 1 after node 2, then delete node 4. State both final chains and explain why they must be disjoint.

S10.10.A03S10.10.A04
Answer and marking points
  1. The final active chain is 2 → 1 → 0.
  2. The final free chain is 4 → 3 → 0.
  3. Sharing a node would allow an insertion to overwrite an active item's storage.

Common error: Move a node out of its old chain before adding it to the other chain.

Question 1 · Command word: Explain · 3 marks

A stack uses indices 1 to 6 and Top = 0. A proposed pop reads Stack[Top] and then decreases Top. Explain the fault and state what the implementation must do instead.

Answer and marking points
  • The stack is empty and index 0 is outside its declared element bounds.
  • Reject the pop before reading the array.
  • Leave Top at 0 and report the defined empty-stack outcome.

Common error: Decreasing an empty stack's pointer makes its representation invalid.

Question 2 · Command word: Explain · 3 marks

A queue has capacity 4, Front = 4, Rear = 1 and Count = 2. A pupil claims that cells 1 through Rear are the entire active queue. Explain the error in this claim and describe one dequeue and one enqueue using this state.

Answer and marking points
  • The active positions are 4 then 1, not only position 1.
  • Dequeue reads position 4, wraps Front to 1 and makes Count = 1.
  • Enqueue then uses position 2, sets Rear = 2 and restores Count = 2.

Common error: Derive membership from Front and Count, not from a linear prefix ending at Rear.

Question 3 · Command word: Describe · 5 marks

A linked-list array has active chain 3 → 1 → 0 and free chain 2 → 4 → 0. Describe inserting free node 2 at the tail, then deleting head node 3 and returning it to the free list. State both final chains.

Answer and marking points
  • Allocate node 2 and advance Free to 4.
  • Set Next[1] to 2 and Next[2] to 0.
  • Delete the head by setting Head to 1.
  • Set Next[3] to 4 and Free to 3.
  • Final active chain: 1 → 2 → 0; final free chain: 3 → 4 → 0.

Common error: A link's meaning changes from free-chain successor to active-chain successor when the node is allocated.

04

Lesson review

Summary

Active state

Pointers and counts define which array cells belong to the structure; old cell contents do not.

Operation checks

Test full, empty and active-position conditions before changing data or representation state.

Free storage

Keep active and free linked-list chains disjoint when allocating or releasing a node.
