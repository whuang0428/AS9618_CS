Build a booking system · Concept 38

Check state before changing an array-backed ADT

Observe

A five-cell implementation at its limit

  • Array bounds: 0:4
  • Stack: Top = 4
  • Queue: Count = 5
  • Requested operation: add one more item.

Look, then discuss

What must remain unchanged when an addition is rejected because the array is full?

Compare a full five-cell stack and a full five-cell queue. Both reject a further addition, but their successful-operation pointer rules differ.

Recall

Recall bounds and active-state conventions

A 0:4 array has five cells. In our stack Top = 4 means full and Top = -1 means empty. In our queue Count = 5 means full and Count = 0 means empty.

Explain

Explanation · 1 / 3

Check before the potentially invalid access

A push must not write above the upper bound. A pop must not read an empty stack. A circular queue must not overwrite its oldest waiting item when full or read a stale value when empty.

Explanation · 2 / 3

Describe the successful state transition

For a stack push, advance Top then write. For our last-inserted Rear queue, advance Rear with wrap, write and increment Count. The check is shared in purpose, but the implementation details are not interchangeable.

Explanation · 3 / 3

Validate the complete state

After a rejected operation, data and pointers must match their prior state. After a successful operation, membership count and access pointers must describe the new collection. A plausible diagram alone does not prove both conditions.

Work together

Test the two boundaries of a five-cell stack

Start with an empty 0:4 stack, Top = -1.

Work together · 1 / 2

Fill and try one extra push

Five successful pushes move Top through 0, 1, 2, 3 and 4. The sixth is rejected, keeping Top = 4 and all five active values unchanged.

Work together · 2 / 2

Empty and try one extra pop

Five successful pops return the values in reverse order and move Top back to -1. The sixth pop is rejected and returns no stored item.

Test the operation immediately before the limit, at the limit and after a rejected attempt.

Check

Try it yourself · Teacher-written

Why is it wrong to decrement a queue’s Count before checking whether the queue is empty?

Check your reasoning

An empty-queue attempt would make Count negative and corrupt the state even though no item was removed. Check first, then update only when the operation can succeed.

Connect

Keep this idea

A failed operation preserves the state; a successful operation keeps the data and access state consistent.

For linked lists, “full” means there is no node left on the free chain.

Build a booking system · Concept 39

Maintain the active list and the free list together

Observe

Two chains share the array storage

  • Active: Head = 3; 3 → 0 → 2 → -1
  • Free: FreeHead = 1; 1 → 4 → -1
  • Insert a new node after active node 0.

Look, then discuss

When node 1 becomes active, how can we still find the remaining free node 4?

In an array indexed 0:4, the active chain is Head = 3: 3 → 0 → 2 → -1. The free chain is FreeHead = 1: 1 → 4 → -1. Every slot belongs to exactly one of these chains.

Recall

Recall two uses of a link

In an active node, Next identifies the next active item. In a free node, Next identifies the next available slot. Reusing a node changes which chain its link belongs to, so retain the remaining free-chain pointer before overwriting that link.

Explain

Explanation · 1 / 4

Read the two chains independently

Head identifies the first active node; FreeHead identifies the first free node. Follow each chain to null. A free cell may contain old Data text, but its membership in the free chain means that text is not an active item.

Explanation · 2 / 4

Allocate before linking into the active list

If FreeHead is null, reject the insertion because the fixed array has no free node. Otherwise retain that index as NewNode and move FreeHead to the node’s old Next. Only then reuse NewNode’s link for the active insertion.

Explanation · 3 / 4

Return a deleted node to the free chain

First remove the node from the active chain by updating its predecessor or Head. Then point the removed node’s Next to the old FreeHead and set FreeHead to the removed index. The node can now be allocated again.

Explanation · 4 / 4

Translate a diagram into parallel arrays

For each physical node index, copy its data and outgoing pointer into matching array positions. Record Head and FreeHead separately. The question may use null = 0 with indices 1:8; follow that declared convention rather than this activity’s -1.

Work together

Insert Break after Workshop and then remove it

Use the initial active and free chains above. Workshop occupies index 0.

Work together · 1 / 3

Preserve the rest of the free list

Take NewNode = 1 and set FreeHead to old Next[1] = 4. The remaining free chain is now 4 → -1.

Work together · 2 / 3

Link the allocated node into the active list

Store Break at Data[1]. Set Next[1] to Workshop’s old successor, 2; then set Next[0] to 1. The active chain becomes 3 → 0 → 1 → 2 → -1.

Work together · 3 / 3

Delete and release the node

Set Next[0] to Next[1], which is 2. Set Next[1] to the old FreeHead, 4, then set FreeHead to 1. Both original chains are restored. Old Break text at Data[1] is inactive.

Preserve access to both chains throughout allocation and release.

Experiment

Inspect both the active chain and free chain before insertion. Predict which free node will be allocated and where FreeHead will move. Delete a node, then insert again and follow its reuse. Try a full array and an empty list.

Follow links, not neighbouring array slots

The active list starts at Head. The free list starts at FreeHead. Each node belongs to exactly one chain; −1 marks the end.

Change the example / explore

Edits take effect only when you select Prepare. Preparation starts a fresh trace.

Why must the old Next[FreeHead] be retained before the allocated node’s Next is changed?
Check your reasoning
It is the link to the remaining free nodes. Overwriting it first can lose the rest of the free chain or make FreeHead point into the active list. Advance or save the free-chain pointer before reuse.

Original question · Cambridge 9618/22
1. Insert a node while preserving both lists
Cambridge 9618/22 · October/November 2023 · 3(b) · 4 marks
Selected parts: 3(b) [4].
Hint — reading the question
Use the first free node F1 and insert it between D32 and D11. Preserve the remaining free list as well as the active list.
Reasoning and model answer — teacher-written
Step 1: Store D6 in the node currently labelled F1.
Step 2: Set that node’s pointer to the node containing D11.
Step 3: Set Ptr2 to the node containing F2.
Step 4: Set the pointer of D32 to the new D6 node.
The resulting active chain is D40 → D32 → D6 → D11 → D100 → null. The remaining free chain begins at F2. When implementing these steps, retain access to F2 before overwriting F1’s old link.
Official mark scheme
Why this earns marks — teacher explanation
There is one mark per completed step. The official answer labels nodes by their data; the pointer values in an implementation refer to locations, not the text “D6”.
Common mistakes — teacher analysis
Overwriting D32’s link before saving access to D11 can lose the remainder of the list. F1 must also be removed from the free list.

Why this earns marks — teacher explanation
The five marking groups are the start pointer, row 2, rows 3 and 4 together, row 5, and rows 7 and 8 together. The diagram’s outlined groups preserve these limits. The scheme accepts null as 0, ∅ or another out-of-bounds index.

Question 1 · Command word: State3 teacher marks
A capacity-5 circular queue has Front = 4, Rear = 1 and Count = 3. State its active positions, the position used by the next enqueue and the full condition.
S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. The active positions are 4, 5 and 1.
  2. The next enqueue uses position 2 and increases Count to 4.
  3. The queue is full only when Count = 5.
Common error: Rear < Front does not imply that the queue is empty.
Question 2 · Command word: State3 teacher marks
Initially the active chain is 2 → 4 → 0 and the free chain is 1 → 3 → 0. Allocate slot 1 after node 2, then delete node 4. State both final chains and explain why they must be disjoint.
S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. The final active chain is 2 → 1 → 0.
  2. The final free chain is 4 → 3 → 0.
  3. Sharing a node would allow an insertion to overwrite an active item's storage.
Common error: Move a node out of its old chain before adding it to the other chain.
Question 3 · Command word: State3 teacher marks
After the lesson's four-slot free-list trace reaches active chain 2→1→4→3→0 and Free = 0, delete node 1, then reuse it as the new head. State both chains after each operation.
S10.10.A03S10.10.A04
Answer and checking points — teacher-written
  1. Delete: set Next[2] = 4; active is 2→4→3→0 and free is 1→0.
  2. Reuse: advance Free to 0, set Next[1] = 2 and Head = 1.
  3. Final active is 1→2→4→3→0; free is 0, with no shared nodes.
Common error: Change the predecessor before returning a node to free storage.
Question 4 · Command word: Describe3 teacher marks
A capacity-5 stack has Top = 3. Describe one pop followed by editing the new top; state which positions remain active.
S10.10.A01S10.10.A04
Answer and checking points — teacher-written
  1. Read Stack[3] and decrease Top to 2.
  2. Edit Stack[2] without changing Top.
  3. Only positions 1 and 2 remain active.
Common error: The old content at position 3 does not remain a stack member.
