Original question · Cambridge 9618/11

1. Describe a presentation feature other than prettyprint

Cambridge 9618/11 · October/November 2024 · 4(d)(i) · 2 marks

Selected parts: 4(d)(i) [2].

Reading the question — teacher guidance

Prettyprint is already supplied and is excluded as your chosen answer. Name a different presentation feature and describe what the programmer sees.

Solution / model answer — teacher-written

Feature: expand/collapse code blocks.

Description: a programmer can collapse the statements within a block to see the overall program structure, then expand that block to see its contents again.

Official mark scheme
Why this earns marks — teacher explanation

One mark is for the feature name and one for the matching description. The scheme also accepts auto-indentation or auto-formatting with a description of how it makes the structure clear.

Common mistakes — teacher analysis

Collapsing a block changes what the editor displays. It does not delete the statements, skip them during execution or correct an error in them.

Original question · Cambridge 9618/12

2. Describe the supplied IDE features precisely

Cambridge 9618/12 · May/June 2023 · 7(c) · 4 marks

Selected parts: 7(c) [4].

Reading the question — teacher guidance

The four feature names are already supplied. Describe the behaviour of each; avoid giving the same debugging description in every row.

Solution / model answer — teacher-written
FeatureDescription
BreakpointsPause execution at a selected line so current values or progress can be inspected.
Dynamic syntax checksHighlight syntax errors while code is being entered.
Context-sensitive promptsSuggest appropriate code or complete a statement for the current context.
Single steppingExecute one statement or line at a time and pause so values can be checked.
Official mark scheme
Why this earns marks — teacher explanation

Each distinct correct description earns one mark. Merely copying the feature name back into its description does not provide the behaviour.

Common mistakes — teacher analysis

Syntax highlighting is not proof that the algorithm is correct. A breakpoint pauses at a chosen location; stepping controls subsequent individual execution.

Teacher-written practice
Question 1 · Command word: Explain3 teacher marks

Explain how dynamic syntax checking helps locate a missing keyword. Then explain how a report window can help investigate a syntactically valid but incorrect calculation.

S5.07.A02S5.07.A08
Answer and checking points — teacher-written
  1. Dynamic checking can highlight the grammar violation while the statement is entered.
  2. A report window shows variable values and how they change during execution, so the programmer can compare them with expected values.
  3. An incorrect calculation can still obey the language grammar, so syntax checks alone cannot prove its result correct.

Common error: Distinguish a rule violation from a logic error.

Question 2 · Command word: Compare3 teacher marks

Compare prettyprint with expanding and collapsing code blocks. Explain whether collapsing a block prevents it from executing.

S5.07.A03S5.07.A04
Answer and checking points — teacher-written
  1. Prettyprint uses consistent indentation or syntax styling to make source structure clearer.
  2. Expand/collapse controls reveal or hide a block's text to aid navigation.
  3. Collapsing changes the editor view only; control flow can still execute the hidden block.

Common error: Do not confuse collapsing a code block with removing statements.

Question 3 · Command word: Describe4 teacher marks

A debugger is paused before Amount <- Amount * 2 with Amount = 7. Describe how to execute just that statement, state Amount afterwards, and explain how to inspect Amount + 1 without assigning it to Amount. Name the facility that caused the initial pause.

S5.07.A05S5.07.A06S5.07.A07
Answer and checking points — teacher-written
  1. Single stepping executes the selected statement and pauses again.
  2. Amount is then 14.
  3. An expression watch or inspection evaluates Amount + 1 as 15 without that arithmetic expression assigning a new Amount.
  4. A breakpoint at the selected statement caused the initial pause.

Common error: A syntactically valid multiplication can still implement the wrong rule. Step and inspect the actual value to diagnose a logic error; expression inspection itself does not assign a new Amount.

Question 4 · Command word: Describe6 teacher marks

The required cost is Quantity multiplied by UnitPrice; Delivery must not be included. Describe how to choose a breakpoint and inspect the operands in the supplied syntactically valid program. State Cost after stepping the faulty assignment, evaluate Quantity * UnitPrice without changing Cost, observe the actual output, then give the correction and expected result after restarting.

The program has no external input. Line numbers identify debugger locations; a breakpoint pauses before its selected statement.

1  DECLARE Quantity : INTEGER
2  DECLARE UnitPrice : INTEGER
3  DECLARE Delivery : INTEGER
4  DECLARE Cost : INTEGER
5  Quantity <- 3
6  UnitPrice <- 4
7  Delivery <- 2
8  Cost <- Quantity * Delivery
9  OUTPUT Cost
S5.07.A02S5.07.A05S5.07.A06S5.07.A07S5.07.A08
Answer and checking points — teacher-written
  1. Pause before line 8: Quantity=3, UnitPrice=4 and Delivery=2. Syntax checking may accept the wrong variable because its use is grammatically valid.
  2. Single stepping line 8 makes Cost=6 because the actual operands are Quantity and Delivery.
  3. Watching Quantity * UnitPrice evaluates to 12 while Cost remains 6.
  4. Step line 9 to produce 6 in the program-output window; merely inspecting the expression does not output it.
  5. Replace line 8 with Cost <- Quantity * UnitPrice.
  6. Restart from the given initialisations and run the corrected program; it outputs 12.

Common error: Choose the intended variable, not a different operator; 12 in a watch window does not mean Cost has become 12.

Question 5 · Command word: Describe2 teacher marks

Describe how context-sensitive prompts help when entering a call to a library routine and explain one limit of that help.

S5.07.A01
Answer and checking points — teacher-written
  1. The editor can suggest the routine name or display its expected parameters at the call location.
  2. The programmer still has to choose arguments that are correct for the intended task.

Common error: A suggested call can be syntactically acceptable but logically inappropriate.
