Coding with context-sensitive prompts

Core explanation

An Integrated Development Environment (IDE) brings programming tools into one working environment. While code is entered, context-sensitive prompts suggest suitable identifiers, keywords, members or parameters based on the current position and language context.

A prompt can reduce typing and help a programmer recall a routine's interface. The programmer must still select the intended operation and supply meaningful arguments; a syntactically available suggestion may be inappropriate for the problem.

Common misconception

Code completion suggests valid options; it does not choose the correct algorithm for the programmer.

Check your understanding

Can accepting a suggested variable name introduce a logic error?

Check your answer

Yes. The identifier can be valid in that scope but refer to the wrong value for the calculation.

02

Dynamic syntax checking

S5.07.A02

Visual overview

From a highlight to a correction

  1. Incomplete sourceAn expression is missing an operand.
  2. Editor feedbackA highlight and diagnostic identify a syntax problem.
  3. Inspect sourceRead the surrounding statement, including preceding lines.
  4. Correct and retestSupply the intended expression and check its behaviour.

Core explanation

Dynamic syntax checking examines source as it is entered and highlights violations of the language's rules, such as an incomplete expression or a missing keyword. Feedback before a full run helps the programmer locate and correct an error early.

An inline diagnostic can describe the detected problem and indicate its source location. Read the message with the surrounding statement to investigate its cause. A reported location can be where a problem becomes detectable rather than where the original mistake was made.

Syntax checking does not establish that the program solves its intended task. For example, a legal subtraction can still be wrong when the specification requires addition, so expected results and execution evidence are also needed.

Common misconception

A blank error list means no errors were reported by that check, not that every algorithmic result is correct.

Check your understanding

Why might a missing closing bracket be reported on the next line?

Check your answer

The parser may only discover the incomplete construct when it encounters the next token.

Pretty-printing and code folding

Core explanation

Pretty-printing presents source in a consistent readable form, for example by indenting nested blocks and applying syntax colouring to keywords or other language elements. This helps a programmer recognise structure and spot suspicious formatting or missing elements.

Expanding and collapsing code blocks reveals or hides sections in the editor so attention can be focused on the relevant part of a large program. Folding changes the display only: hidden statements still belong to the program and execute whenever control flow reaches them.

Worked example · Read a formatted decision

  1. Cambridge pseudocode
    DECLARE Mark : INTEGER
INPUT Mark
IF Mark >= 50 THEN
    OUTPUT "Pass"
ELSE
    OUTPUT "Retry"
ENDIF
  2. Presentation

    Indent the two output statements inside their respective branches; syntax colouring can distinguish IF, THEN, ELSE and ENDIF.

  3. Fold and run

    Collapsing the IF block hides its body in the editor, but Mark = 60 still selects the Pass output.

Common misconception

Collapsing code is not commenting it out, deleting it or disabling its execution.

Check your understanding

A collapsed loop still changes a variable. Is the IDE malfunctioning?

Check your answer

No. Folding only hides source text in the editor; it does not alter control flow.

04

Single stepping, breakpoints and inspection

S5.07.A05S5.07.A06S5.07.A07S5.07.A08

Visual overview

State around one assignment

Debugger stateTotalIncrementTotal + Increment
Paused before line 512416
After stepping line 58412

Swipe horizontally to compare every column →

Core explanation

Single stepping advances through execution one statement at a time, pausing so its effect can be examined before the next statement runs. This lets the programmer relate a change in program state to the instruction that just executed.

A breakpoint pauses execution when a selected location is reached, normally before that statement executes. Place it where relevant values are available and just before the suspect calculation or decision. Reaching a breakpoint does not itself correct the fault.

While paused, variable or expression inspection shows current values for comparison with the expected state. A report window displays information such as program output, run-time errors and diagnostic messages. Its output can be compared with the expected result after stepping an OUTPUT statement; inspecting a variable alone does not execute that output.

Use a deliberate loop of predict, execute one step, inspect and compare. If a watched value changes unexpectedly, inspect the statement that just executed and its inputs rather than placing unrelated breakpoints throughout the program.

Worked example · Locate a wrong operator

  1. Program with a logic error; line numbers identify debugger locations
    1  DECLARE Total : INTEGER
2  DECLARE Increment : INTEGER
3  Total <- 12
4  Increment <- 4
5  Total <- Total - Increment
6  OUTPUT Total
  2. Predict and pause

    The required operation adds Increment. Set a breakpoint on line 5. Before it executes, Total is 12 and Increment is 4; the intended next Total is 16.

  3. Step and inspect

    Execute line 5 once. Total becomes 8, showing that subtraction was performed; line 6 has not executed yet.

  4. Correct

    Replace line 5 with Total <- Total + Increment. Run again from the initial state; the output should be 16.

  5. Check an expression

    At the original pause Total + Increment evaluates to 16. After the faulty step it evaluates to 12 because Total has changed to 8.

Common misconception

Always state whether a variable value is observed before or after the selected statement executes.

Check your understanding

At the breakpoint on line 5, has the subtraction already changed Total?

Check your answer

No. In this example the pause occurs before line 5, so Total is still 12.

Question 1 · Command word: Describe2 marks

Describe how context-sensitive prompts help when entering a call to a library routine and explain one limit of that help.

S5.07.A01
Answer and marking points
  1. The editor can suggest the routine name or display its expected parameters at the call location.
  2. The programmer still has to choose arguments that are correct for the intended task.

Common error: A suggested call can be syntactically acceptable but logically inappropriate.

Question 2 · Command word: Explain3 marks

Explain how dynamic syntax checking and a diagnostic window help locate a missing keyword. State why they may not identify a valid but incorrect calculation.

S5.07.A02S5.07.A08
Answer and marking points
  1. Dynamic checking can highlight the grammar violation while the statement is entered.
  2. The diagnostic window can report a message and source location to guide inspection.
  3. An incorrect calculation can still obey the language grammar, so syntax checks alone cannot prove its result correct.

Common error: Distinguish a rule violation from a logic error.

Question 3 · Command word: Compare3 marks

Compare pretty-printing with expanding and collapsing code blocks. Explain whether collapsing a block prevents it from executing.

S5.07.A03S5.07.A04
Answer and marking points
  1. Pretty-printing uses consistent indentation or syntax styling to make source structure clearer.
  2. Expand/collapse controls reveal or hide a block's text to aid navigation.
  3. Collapsing changes the editor view only; control flow can still execute the hidden block.

Common error: Do not confuse folding with removing statements.

Question 4 · Command word: Describe4 marks

A debugger is paused before Amount <- Amount * 2 with Amount = 7. Describe how to execute just that statement, state Amount afterwards, and explain how to inspect Amount + 1 without assigning it to Amount. Name the facility that caused the initial pause.

S5.07.A05S5.07.A06S5.07.A07
Answer and marking points
  1. Single stepping executes the selected statement and pauses again.
  2. Amount is then 14.
  3. An expression watch or inspection evaluates Amount + 1 as 15 without that arithmetic expression assigning a new Amount.
  4. A breakpoint at the selected statement caused the initial pause.

Common error: Observe the value after multiplication, and distinguish expression evaluation from assignment.

Question 1 · Command word: Explain · 3 marks

A programmer accepts an IDE suggestion for TotalCost but intended to use UnitCost. The statement has valid syntax. Explain what the prompt supplied, why dynamic syntax checking may accept the statement, and how execution evidence could reveal the mistake.

Answer and marking points
  • The prompt supplied an available identifier matching the current coding context.
  • Using TotalCost can obey the language rules even though it is the wrong variable for this calculation.
  • Inspecting the operands and comparing the resulting value with the expected unit-based calculation can expose the logic error.

Common error: A context-sensitive suggestion does not know every requirement of the calculation.

Question 2 · Command word: Describe · 3 marks

A programmer formats a nested decision and collapses its inner block. Describe one benefit of indentation, one benefit of syntax colouring, and what happens when execution reaches the hidden block.

Answer and marking points
  • Indentation makes it easier to see which statements belong to each branch.

Question 3 · Command word: State · 5 marks

A program sets Count <- 5, then executes Count <- Count + 2, then OUTPUT Count. A breakpoint pauses before the addition. State Count at that pause and after one step. Describe how to inspect the new value and verify the output, and explain why a second step is needed to produce it.

Answer and marking points
  • Count is 5 before the selected addition executes.
  • Single stepping the addition changes Count to 7.
  • Variable inspection can show the new value while execution is paused again.
  • The first step performed the addition, so OUTPUT has not yet run.
  • Stepping the output statement produces 7 in the program-output/report window.

Common error: Do not report the post-addition value as the value before the breakpointed statement.
