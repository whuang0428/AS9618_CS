A design counts positive values. Should an input of zero increase the count?

No. Positive means greater than zero; the condition is Value > 0.

Core explanation

Read the whole design before writing statements. Identify the inputs, initial values, processing order and required outputs. Translate a precise action such as increase Count by one into Count <- Count + 1; do not leave the action as an unexplained instruction to process data.

Consider this design: set a count to zero; read three integers in turn; increase the count for each positive integer; output the final count. Initialisation belongs before repetition, the input and positive-value decision belong inside it, and the final output belongs after it. Indentation makes these responsibilities visible.

Worked example · Implement the three-value design

  1. Pseudocode
    DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  2. Trace and check

    Inputs -2, 0, 5 produce 1. Inputs 1, 2, 3 produce 3.

Common misconception

Counting values greater than or equal to zero changes the supplied design.

Check your understanding

Where is the count initialised?

Check your answer

Once, before reading the three values.

Core explanation

A flowchart's arrows specify execution order. A decision requires both outcomes to reach the correct next operation. A backward arrow identifies repetition; determine which state changes before execution returns to the decision. A terminal marks the end of that execution path.

The flowchart below implements the same three-value design. Count and Index are initialised before the first test. Each completed input advances Index once, including a non-positive value. The loop exits to the final output when Index exceeds three; execution ends after that output.

Common misconception

An End terminal must not continue into another iteration.

Check your understanding

Why must Index advance after a non-positive value?

Check your answer

That value has still been read and must count toward the three inputs.

Practice questions

Question 1 · Command word: Write2 marks

Write pseudocode for this structured English: input a real-valued length and width; multiply them; output the area.

S11.01.A01
Answer and marking points
  1. Declare Length, Width and Area as REAL and input Length and Width.
  2. Assign Area <- Length * Width, then OUTPUT Area.

Common error: Do not output before assigning the area.

Question 2 · Command word: Write3 marks

Write pseudocode equivalent to the supplied three-value flowchart. State the output for inputs -4, 2 and 7.

S11.01.A01
Answer and marking points

One valid pseudocode solution

DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  1. Initialise Count before a loop that obtains exactly three values.
  2. Increment Count only for Value > 0.
  3. Output the completed count after repetition; these inputs give 2.

Common error: The loop counter and positive-value count have different purposes.

Question 3 · Command word: Explain2 marks

Explain why moving Count <- 0 inside the loop changes the three-value algorithm. Use inputs 2, 3 and -1.

S11.01.A01
Answer and marking points
  1. Each new iteration discards the previous count.
  2. The final negative value leaves 0 instead of the correct count 2.

Common error: Trace all iterations, not only the first.

Question 1 · Command word: Write · 3 marks

Write pseudocode for this design: input a non-negative integer Count; while it is positive, output it and reduce it by one; after repetition output "Finished". State the output when Count starts at zero.

Answer and marking points

One valid pseudocode solution

DECLARE Count : INTEGER
INPUT Count
WHILE Count > 0
    OUTPUT Count
    Count <- Count - 1
ENDWHILE
OUTPUT "Finished"
  • Input Count before testing Count > 0.
  • Output Count and decrement it inside a WHILE loop.
  • After ENDWHILE output "Finished"; zero produces only that text.

Common error: Decrement before the repeated condition is tested again.

Question 2 · Command word: Write · 3 marks

Write pseudocode for this structured English: input a real temperature; if it is below zero output "Ice"; otherwise output "Water". State which output occurs at zero.

Answer and marking points
  • Obtain Temperature before testing Temperature < 0.
  • Use IF/ELSE with the two stated outputs and ENDIF.
  • Zero follows ELSE and outputs "Water".

Common error: A strict comparison excludes the boundary.

Question 3 · Command word: Describe · 3 marks

A design reads four prices, totals them and outputs the total once. A translation reads Price before the FOR loop, adds it four times and outputs Total inside the loop. Describe the changes needed to match the design.

Answer and marking points
  • Place INPUT Price inside the loop so four new prices are read.
  • Initialise Total to zero before the loop and add each new price.
  • Move OUTPUT Total after the loop so only the final total is displayed.

Common error: Four additions of one input do not implement four separate inputs.
