Read the complete contract

Read the whole design before writing statements. Identify the inputs, initial values, processing order and required outputs. Translate a precise action such as increase Count by one into Count <- Count + 1; do not leave the action as an unexplained instruction to process data.

Place each action at the correct level

Consider this design: set a count to zero; read three integers in turn; increase the count for each positive integer; output the final count. Initialisation belongs before repetition, the input and positive-value decision belong inside it, and the final output belongs after it. Indentation makes these responsibilities visible.

Build the translation in dependency order

  1. Identify the data: Value is the current INTEGER input. Index identifies which input is being processed; Count counts only positive inputs. Their meanings differ even though both counters are integers.
  2. Establish starting state: Set Count to 0 once. No positive input has been seen at the start. Declaring Count does not establish that value.
  3. Translate one repeated responsibility: Obtain a fresh Value, test Value > 0 and increment Count only on TRUE. Complete all three inputs, including non-positive ones.
  4. Place the final report: Output Count after repetition. The requirement asks for one completed count, not three intermediate counts.

Check the meaning as well as the notation

Changing the input values is a useful way to challenge the translation. All non-positive values must leave Count at zero; three positive values must give three. A zero input is data, not a stopping signal in this task. A sentinel would need to be explicitly specified.

Use the design boundary

The basic constructs are introduced in Lesson 053; Lessons 073 and 076–078 explain their precise statement forms. Here the supplied design determines which operations belong together. Do not invent new validation rules or outputs while translating it.

Worked example · Implement the three-value design

  1. Pseudocode
    DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  2. Trace and check

    Inputs -2, 0, 5 produce 1. Inputs 1, 2, 3 produce 3.

Core explanation · Exam essentials

  • Translate the stated input, processing and output without changing the rules.
  • Initialise once, preserve every branch and place repeated actions inside the correct loop.
Common misconception

Counting values greater than or equal to zero changes the supplied design.

Check your understanding

Where is the count initialised?

Check your answer

Once, before reading the three values.

Follow every flowchart edge

S11.01.A01

Visual overview

Read each directed edge

A flowchart's arrows specify execution order. A decision requires both outcomes to reach the correct next operation. A backward arrow identifies repetition; determine which state changes before execution returns to the decision. A terminal marks the end of that execution path.

Check the repeated and final paths

The flowchart below implements the same three-value design. Count and Index are initialised before the first test. Each completed input advances Index once, including a non-positive value. The loop exits to the final output when Index exceeds three; execution ends after that output.

Explain the exit

After the third value, Index becomes 4. The next test is FALSE, so no fourth input is read. Moving the Index update inside the positive branch would mean a non-positive input fails to advance the processed-input count.

Recognise an equivalent representation

The previous unit expresses the known three inputs with FOR. The direct WHILE version below makes the graph’s initialisation, test and update explicit. Compare their consumed inputs, decisions and final output. This does not require an assumption about the FOR control variable after the loop has ended.

Worked example · Translate every flowchart edge

  1. Requirements and starting conditions

    Read exactly three INTEGER values and output how many are strictly positive.

  2. Cambridge pseudocode
    DECLARE Count, Index, Value : INTEGER
Count <- 0
Index <- 1
WHILE Index <= 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
    Index <- Index + 1
ENDWHILE
OUTPUT Count
  3. Expected result

    For -2, 0, 5, Count becomes 0, 0, 1; Index advances to 2, 3, 4. The output is 1.

Core explanation · Exam essentials

  • Preserve both outcomes, the back edge and the path to the final output.
  • A loop update outside the inner IF executes after either branch.
Common misconception

An End terminal must not continue into another iteration.

Check your understanding

Why must Index advance after a non-positive value?

Check your answer

That value has still been read and must count toward the three inputs.

Question 1 · Command word: Write3 teacher marks

Write pseudocode equivalent to the supplied three-value flowchart. State the output for inputs -4, 2 and 7.

S11.01.A01
Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  1. Initialise Count before a loop that obtains exactly three values.
  2. Increment Count only for Value > 0.
  3. Output the completed count after repetition; these inputs give 2.

Common error: The loop counter and positive-value count have different purposes.

Question 2 · Command word: Explain2 teacher marks

Explain why moving Count <- 0 inside the loop changes the three-value algorithm. Use inputs 2, 3 and -1.

S11.01.A01
Answer and checking points — teacher-written
  1. Each new iteration discards the previous count.
  2. The final negative value leaves 0 instead of the correct count 2.

Common error: Trace all iterations, not only the first.

Question 3 · Command word: Write5 teacher marks

Write complete pseudocode for the supplied flowchart. Inputs are INTEGER temperatures ending with sentinel 999. State the outputs for 29, 30, 31, 999 and for 999 alone.

S11.01.A01
Answer and checking points — teacher-written

One valid Cambridge pseudocode solution

DECLARE Temperature, Count : INTEGER
Count <- 0
INPUT Temperature
WHILE Temperature <> 999
    IF Temperature > 30 THEN
        Count <- Count + 1
    ENDIF
    INPUT Temperature
ENDWHILE
OUTPUT Count
  1. Declare Temperature and Count as INTEGER; set Count to zero.
  2. Read Temperature before WHILE Temperature <> 999 so the first sentinel permits zero data items.
  3. Inside the loop, increment Count only when Temperature > 30.
  4. Read the next Temperature after either branch, and output Count once after ENDWHILE.
  5. The two runs output 1 and 0 respectively; 30 does not meet the strict threshold.

Common error: A new input is needed on both data paths, including a temperature of 30.

Original question · Cambridge 9618/23

1. Write a complete positive-number total

Cambridge 9618/23 · October/November 2024 · 2(a) · 5 marks

Selected parts: 2(a) [5].

Reading the question — teacher guidance

Declare all variables, prompt before each input and process exactly 100 integers. Zero contributes nothing. Output once after the loop.

Solution / model answer — teacher-written
DECLARE Count, Total, NextNumber : INTEGER
Total ← 0
FOR Count ← 1 TO 100
    OUTPUT "Input an integer value"
    INPUT NextNumber
    IF NextNumber > 0 THEN
        Total ← Total + NextNumber
    ENDIF
NEXT Count
OUTPUT Total

The total starts at zero. Each positive input is added once; negatives and zero leave it unchanged. If every input is non-positive, the output is zero.

Official mark scheme
Why this earns marks — teacher explanation

The scheme lists six points but awards at most five. Declaration, iteration, prompt/input, condition, accumulation and final output all matter to a complete solution.

Common mistakes — teacher analysis

Initialising Total inside the loop loses earlier additions. Output inside the loop gives intermediate totals instead of the single requested result.
