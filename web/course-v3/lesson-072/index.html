Program a booking system · Concept 22

Place each action at the right level

Observe

Structured English design

  • Set the positive-request count to zero.
  • Read three integers in turn.
  • For each positive integer, increase the count by one.
  • Display the completed count once.

Look, then discuss

Which actions happen once, which repeat and which happen only on one branch?

The desk reads exactly three integer requests, counts those that are positive and displays the final count. Zero and negative requests still occupy input slots but do not increase the positive count.

Recall

Recall counter and accumulator roles

Index identifies the current input slot. Count records how many inputs meet a condition. They may have different values even though both are INTEGER. A total of the input values would be a third, different quantity.

Explain

Explanation · 1 / 3

Identify the required data and starting state

Declare Index, Value and Count as INTEGER. Set Count to 0 before any inputs, because no positive values have yet been observed.

Explanation · 2 / 3

Translate one repeated responsibility

Use FOR for the three slots. Read one fresh Value inside each iteration. Only IF Value > 0 should execute Count <- Count + 1. Do not change the rule to >= 0.

Explanation · 3 / 3

Put final reporting after repetition

OUTPUT Count belongs after NEXT Index. This produces one completed result. Check that every sentence in the design has a corresponding operation and that no extra input, condition or output has been invented.

DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count

Work together

Translate first, then challenge the translation

Use inputs -2, 0 and 5.

Work together · 1 / 2

Trace the three decisions

The tests are FALSE, FALSE and TRUE. Count stays 0, stays 0, then becomes 1. The loop still reads all three values.

Work together · 2 / 2

Distinguish a count from a total

This design outputs 1, not 5. A different requirement to total positive values would use Total <- Total + Value. Read that distinction carefully in the real-paper task, which requires 100 inputs and a positive-number total.

A translation must preserve the specified operation, not merely use the right control-structure names.

Check

Try it yourself · Teacher-written

If Count <- 0 is moved inside the loop, what is output for 2, 3, -1?

Check your reasoning

0 instead of 2. Each iteration resets Count, and the final negative value causes no increment.

Original question · Cambridge 9618/23

1. Write a complete positive-number total

Cambridge 9618/23 · October/November 2024 · 2(a) · 5 marks

Selected parts: 2(a) [5].

Hint — reading the question

Declare all variables, prompt before each input and process exactly 100 integers. Zero contributes nothing. Output once after the loop.

Reasoning and model answer — teacher-written
DECLARE Count, Total, NextNumber : INTEGER
Total ← 0
FOR Count ← 1 TO 100
    OUTPUT "Input an integer value"
    INPUT NextNumber
    IF NextNumber > 0 THEN
        Total ← Total + NextNumber
    ENDIF
NEXT Count
OUTPUT Total

The total starts at zero. Each positive input is added once; negatives and zero leave it unchanged. If every input is non-positive, the output is zero.

Official mark scheme
Why this earns marks — teacher explanation

The scheme lists six points but awards at most five. Declaration, iteration, prompt/input, condition, accumulation and final output all matter to a complete solution.

Common mistakes — teacher analysis

Initialising Total inside the loop loses earlier additions. Output inside the loop gives intermediate totals instead of the single requested result.

Program a booking system · Concept 23

Preserve both branches and the back edge

Observe

Flowchart checkpoints

  • Initial state: Count 0, Index 1.
  • Loop test: Index <= 3.
  • Inner test: Value > 0.
  • Both inner paths advance Index before returning to the loop test.

Look, then discuss

Why must the flowchart advance Index after a non-positive input?

Follow the No arrow from Value > 0 in the supplied three-input flowchart. It skips the count increment but still reaches the Index increment and the return to the loop test.

Recall

Recall a flowchart path

Arrows give execution order. A diamond selects a branch; a backward edge represents repetition; the End terminal has no outgoing execution path. A statement after a rejoin belongs to both branches.

Explain

Explanation · 1 / 3

Translate the initialisation before the loop

The graph explicitly sets Count to 0 and Index to 1. Its pre-condition test becomes WHILE Index <= 3.

Explanation · 2 / 3

Translate the inner decision without swallowing the shared update

INPUT Value occurs in the loop body. Put only the Count update inside IF Value > 0. Put Index <- Index + 1 after ENDIF so it runs for a positive, zero or negative value.

Explanation · 3 / 3

Translate the exit and the terminal

When Index reaches 4, the condition is FALSE. Continue to OUTPUT Count and then finish. There is no fourth input or return from End.

DECLARE Count, Index, Value : INTEGER
Count <- 0
Index <- 1
WHILE Index <= 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
    Index <- Index + 1
ENDWHILE
OUTPUT Count

Work together

Verify two representations of one design

Trace -2, 0, 5 through the graph and the direct WHILE translation.

Work together · 1 / 2

Track the two counters separately

After each input, Index becomes 2, 3 and 4 while Count becomes 0, 0 and 1. The non-positive inputs still advance Index.

Work together · 2 / 2

Compare with the previous FOR version

Both consume three inputs and output 1. The WHILE version makes the graph’s test and update explicit; the FOR version manages the known iteration sequence in its header and NEXT.

Check observable inputs, outputs and state changes along every path, not just a visually similar code layout.

Check

Try it yourself · Teacher-written

What would happen if Index <- Index + 1 were placed inside IF Value > 0?

Check your reasoning

A non-positive input would not advance the slot counter. The program could request more than three values and might fail to terminate if no positive values arrive.

Question 1 · Command word: Write3 teacher marks

Write pseudocode equivalent to the supplied three-value flowchart. State the output for inputs -4, 2 and 7.

S11.01.A01
Answer and checking points — teacher-written

One valid pseudocode solution

DECLARE Count, Index, Value : INTEGER
Count <- 0
FOR Index <- 1 TO 3
    INPUT Value
    IF Value > 0 THEN
        Count <- Count + 1
    ENDIF
NEXT Index
OUTPUT Count
  1. Initialise Count before a loop that obtains exactly three values.
  2. Increment Count only for Value > 0.
  3. Output the completed count after repetition; these inputs give 2.

Common error: The loop counter and positive-value count have different purposes.

Question 2 · Command word: Explain2 teacher marks

Explain why moving Count <- 0 inside the loop changes the three-value algorithm. Use inputs 2, 3 and -1.

S11.01.A01
Answer and checking points — teacher-written
  1. Each new iteration discards the previous count.
  2. The final negative value leaves 0 instead of the correct count 2.

Common error: Trace all iterations, not only the first.

Question 3 · Command word: Write5 teacher marks

Write complete pseudocode for the supplied flowchart. Inputs are INTEGER temperatures ending with sentinel 999. State the outputs for 29, 30, 31, 999 and for 999 alone.

S11.01.A01
Answer and checking points — teacher-written

One valid Cambridge pseudocode solution

DECLARE Temperature, Count : INTEGER
Count <- 0
INPUT Temperature
WHILE Temperature <> 999
    IF Temperature > 30 THEN
        Count <- Count + 1
    ENDIF
    INPUT Temperature
ENDWHILE
OUTPUT Count
  1. Declare Temperature and Count as INTEGER; set Count to zero.
  2. Read Temperature before WHILE Temperature <> 999 so the first sentinel permits zero data items.
  3. Inside the loop, increment Count only when Temperature > 30.
  4. Read the next Temperature after either branch, and output Count once after ENDWHILE.
  5. The two runs output 1 and 0 respectively; 30 does not meet the strict threshold.

Common error: A new input is needed on both data paths, including a temperature of 30.

Question 4 · Command word: Write2 teacher marks

Write pseudocode for this structured English: input a real-valued length and width; multiply them; output the area.

S11.01.A01
Answer and checking points — teacher-written

One valid Cambridge pseudocode solution

DECLARE Length, Width, Area : REAL
INPUT Length
INPUT Width
Area <- Length * Width
OUTPUT Area
  1. Declare Length, Width and Area as REAL and input Length and Width.
  2. Assign Area <- Length * Width, then OUTPUT Area.

Common error: Do not output before assigning the area.
