Bubble sort and linear search algorithms: Linear search using arrays

S10.06.A01S10.06.A02

Visual overview

Core explanation

Linear search examines array elements in index order until the target is found or every populated element has been checked. It works on unsorted data.

A complete algorithm initialises the index and found flag, keeps every array access within declared bounds, compares the current element, advances after a failed comparison and reports both found and not-found outcomes.

Stopping the loop immediately after the last valid comparison prevents an out-of-bounds access. A trace of one search is useful evidence, but

Bubble sort repeatedly compares adjacent elements and swaps a pair when it is in the wrong order. Each ascending pass fixes the largest remaining value at the high end, so the next pass can use a shorter inner-loop bound.

Linear search procedure

  1. Set the first index and found stateStart at the declared lower bound with Found set to FALSE before reading an array element.
  2. Compare within the valid boundsTest the current item against Target and advance the index only when the current item does not match.
  3. Report found or exhaustedStop on a match or after the upper populated bound and return an index or a clear not-found result.

Worked example · Write a bounded linear search

  1. Code
    DECLARE Found : BOOLEAN
DECLARE Index : INTEGER
Found <- FALSE
Index <- 1
WHILE Index <= Count AND NOT Found
  IF Code[Index] = Target THEN
    Found <- TRUE
  ELSE
    Index <- Index + 1
  ENDIF
ENDWHILE
  2. Found case

    Searching [K4, M2, P7] for M2 checks indexes 1 then 2 and stops with Found=TRUE and Index=2.

  3. Absent case

    Searching the same array for Z9 checks indexes 1, 2 and 3, then stops when Index=4 without accessing Code[4].

Common misconception

A linear search does not require sorted data, but it must still respect the declared array bounds.

Cambridge command words

Practice questions

Command word: Write8 marks

Write complete Cambridge pseudocode for a linear search of Code[1:Count] for Target. Initialise all state, stay within the bounds, and report both found and not-found outcomes.

S10.06.A01S10.06.A02
Answer and marking points
  1. initialises Found to FALSE and Index to 1.
  2. loops while Index <= Count and not Found.
  3. compares Code[Index] with Target.
  4. sets Found on match.
  5. otherwise increments Index.
  6. never accesses beyond Count.
  7. reports Index/found or a clear not-found result.

Common error: Test the bound before every array access.

Command word: Describe5 marks

Describe the path of the linear-search algorithm for [K4, M2, P7] with targets M2 and Z9. Demonstrate Index, current value and Found after each valid comparison.

S10.06.A01S10.06.A02
Answer and marking points
  1. M2: index1 K4 false, index2 M2 true and stop.
  2. Z9: indexes1 K4 false, 2 M2 false, 3 P7 false, then stop not found without reading index4.

Common error: Do not read a fourth element from a three-element array.

Command word: Explain3 marks

Explain how linear search using arrays would be applied in a suitable computing context.

S10.06.A01S10.06.A02
Answer and marking points
  1. Before tracing a search, define the data structure it traverses.
  2. An array is a fixed-size indexed collection whose elements have one declared data type.
  3. The index selects one element.
  4. it is not the value stored in that element.
  5. Cambridge pseudocode declares explicit inclusive bounds.
  6. In DECLARE Names : ARRAY[1:4] OF STRING, 1 is the lower bound, 4 is the upper bound and the valid indexes are 1, 2, 3 and 4.
  7. A search must start and stop within those declared bounds.
  8. Linear search checks successive indexed elements until the target is found or every populated element has been checked.
  9. Binary search also uses indexes, but requires the array to be sorted so each comparison can discard one half of the remaining index range.

Common error: Do not copy the worked example unchanged; transfer the method and check it against the new context.
