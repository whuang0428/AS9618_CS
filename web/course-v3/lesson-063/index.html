Linear search using arrays

Inspect unsorted values in sequence and distinguish a matching position from absence.

How can a search inspect every permitted element and report absence safely?

Before you start

Must an array be sorted before a linear search?

Check your answer

No. Linear search compares elements one by one and works on unsorted data.

Compare each element with the search value

Visual overview

Core explanation

Find the first match
  1. Initialise: Index starts at the lower bound and Position at 0. Zero means not found because it is outside the 1-based bounds.
  2. Guard: Continue only while Index is valid and Position is still 0.
  3. Compare: On a mismatch advance Index; on a match store Index in Position. The next test then stops the loop.
Return a position without reading past the array

The array access is inside the guarded body. An absent target checks indices 1 through 5 and stops before Values[6]. For [9, 4, 6, 4, 2] and target 4, report index 2; later equal values are not visited.

Linear search procedure

  1. InitialiseSet Index to the lower bound and Position to 0.
  2. ContinueRepeat while Index is in range and no match has been saved.
  3. CompareSave Index when Values[Index] equals Target; otherwise advance Index.
  4. ReportOutput the saved position or the not-found sentinel.
Common misconception

The first matching index is not the target value, and duplicate target values do not require this version to continue.

Check your understanding

What is returned when 4 occurs at indices 2 and 4?

Check your answer

2, because this algorithm stops at the first match.

Core explanation

Initialise and guard the search

The complete algorithm first inputs five values and a target, then initialises the search state. Position starts at 0 for each new search, preventing a previous result from being mistaken for the result of this target. The loop conditions refer only to scalar state; they do not depend on short-circuit evaluation to protect an array subscript.

Test first, last, duplicate and absent targets

Test a match at the first position, a match at the final position, an absent target and repeated matching values. An absent target causes five comparisons and finishes with Index equal to 6 and Position still 0. A match at index 5 leaves Position at 5 and performs no sixth comparison.

Worked example · Search a five-element array

  1. Task

    Read five INTEGER values and a target; output the first matching index or 0 if absent.

  2. Pseudocode
    DECLARE Values : ARRAY[1:5] OF INTEGER
DECLARE Index : INTEGER
DECLARE Target : INTEGER
DECLARE Position : INTEGER
FOR Index <- 1 TO 5
    INPUT Values[Index]
NEXT Index
INPUT Target
Index <- 1
Position <- 0
WHILE (Index <= 5) AND (Position = 0)
    IF Values[Index] = Target THEN
        Position <- Index
    ELSE
        Index <- Index + 1
    ENDIF
ENDWHILE
OUTPUT Position
  3. Result

    Inputs 9, 4, 6, 4, 2 followed by target 4 output 2; target 7 instead outputs 0.

Common misconception

Stopping at Index < 5 misses the last element; continuing through Index = 6 exceeds the upper bound.

Check your understanding

What changes after a mismatch at index 5?

Check your answer

Index becomes 6. The loop ends before any further array access, and Position remains 0.

  1. Declare and input the array and target.
  2. Initialise the index to 1 and result to 0.
  3. Continue only while the index is in range and no match has been found.
  4. Save a matching index; otherwise advance the index.
  5. Output the result after the loop.

Question 1 · Command word: State · 3 marks

The supplied linear search reads 11, 7, 9, 2, 6 and target 6. State the final Index, final Position and number of comparisons, and explain why a condition Index < 5 would be wrong.

Use this complete algorithm in the question.

DECLARE Values : ARRAY[1:5] OF INTEGER
DECLARE Index : INTEGER
DECLARE Target : INTEGER
DECLARE Position : INTEGER
FOR Index <- 1 TO 5
    INPUT Values[Index]
NEXT Index
INPUT Target
Index <- 1
Position <- 0
WHILE (Index <= 5) AND (Position = 0)
    IF Values[Index] = Target THEN
        Position <- Index
    ELSE
        Index <- Index + 1
    ENDIF
ENDWHILE
OUTPUT Position
Answer and marking points
  • Final Index is 5 and final Position is 5.
  • Five element comparisons are made.
  • Index < 5 would stop before comparing the last value, losing this valid match.

Common error: Use the inclusive upper bound when checking the last position.

Question 2 · Command word: Identify · 3 marks

A 0-based array uses indices 0 to 4. A linear search returns 0 both for a first-element match and for absence. Identify the ambiguity and propose a corrected result convention.

Answer and marking points
  • A result of 0 cannot distinguish a valid match at index 0 from not found.
  • Return the matching index and use −1 for absence, since −1 is outside the valid bounds.
  • Alternatively use a separate BOOLEAN Found together with a position valid only when Found is TRUE.

Common error: Changing the array bounds is unnecessary; correct the result convention.

Question 3 · Command word: Explain · 3 marks

A search of unsorted codes [21, 8, 30, 4, 17] stops after the first element greater than target 4. Explain why this is incorrect and describe the stopping rules for a correct first-match linear search.

Answer and marking points
  • 21 being greater than 4 gives no information about later elements in unsorted data.
  • The target 4 occurs later, at index 4.
  • Stop after a match or after every valid element has been checked.

Common error: Do not introduce an ordering assumption into linear search.

04

Lesson review

Summary

Search rule

Compare sequentially and stop at the first match or after the final permitted element.

Result

Return an index for a match and an unambiguous sentinel for absence.

Safety

Guard the array access with valid bounds and test both end positions, duplicates and absence.
