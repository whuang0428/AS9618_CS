Look, then discuss

Where is the first request for 3 in [8, 3, 5, 3, 1]?

Inspect one card at a time from index 1. Index 1 contains 8, which does not match. Index 2 contains 3. Decide whether later cards need inspection when the task asks for the first match.

Recall

Recall a comparison and a position

Request[Index] = Target compares the stored value with the target. If it is TRUE, Index gives the position of that match. The position and target value need not be equal.

Explain

Explanation · 1 / 3

Start at the lower bound

Linear search checks elements sequentially. It works on an unsorted array because it does not assume that greater or smaller values occupy a particular region.

Explanation · 2 / 3

Advance only after a mismatch

Compare the current element with the target. If it does not match, move to the next legal index. If it matches and the requirement is first match, record that position and stop.

Explanation · 3 / 3

Report absence explicitly

If every legal position has been checked without a match, report not found. For a 1-based array, 0 can be a not-found result because it is outside the legal index range. A question may specify -1 instead; follow that convention.

Work together

Compare present and absent targets

Use Request[1:5] = [8, 3, 5, 3, 1].

Work together · 1 / 2

Search for 3

Compare 8 with 3, then 3 with 3. Stop at index 2. The duplicate at index 4 does not replace the first match.

Work together · 2 / 2

Search for 9

All five comparisons fail. After index 5, stop without reading index 6 and return the chosen not-found result.

The stopping rule comes from the required result: first match or a confirmed absence.

Check

Try it yourself · Teacher-written

A first-match search returns 2 for target 3. Does that mean the stored value is 2?

Check your reasoning

No. It means the first match is at index 2. The element at that index contains the target value 3.

Connect

Keep this idea

Linear search checks elements in sequence and can stop as soon as the required match is found.

The loop must preserve both safety conditions: a legal index and no match found yet.

Build a booking system · Concept 19

Write a search that stops safely

Observe

An absent-target test

  • Values[1:5] = [8, 3, 5, 3, 1]
  • Target = 9
  • Initial Index = 1; Position = 0 means not found.

Look, then discuss

What prevents the search from reading past the final element?

Imagine searching for 9 when the final legal index is 5. After the final mismatch, Index becomes 6. The next loop test must stop before the body reads another element.

Recall

Recall WHILE and a sentinel

WHILE tests its condition before each execution of the body. A sentinel is a reserved value with a special meaning, such as Position = 0 for not found. Choose a value that cannot be a valid result.

Explain

Explanation · 1 / 4

Initialise both pieces of state

Set Index to the lower bound and Position to the not-found sentinel. Position changes only when a match is found. Index advances only after a mismatch.

Explanation · 2 / 4

Guard entry to the array access

The loop condition tests Index <= 5 and Position = 0. Neither part accesses the array. The body therefore reads Values[Index] only when Index is in range, without depending on short-circuit evaluation.

DECLARE Values : ARRAY[1:5] OF INTEGER
DECLARE Index : INTEGER
DECLARE Target : INTEGER
DECLARE Position : INTEGER
FOR Index <- 1 TO 5
    INPUT Values[Index]
NEXT Index
INPUT Target
Index <- 1
Position <- 0
WHILE (Index <= 5) AND (Position = 0)
    IF Values[Index] = Target THEN
        Position <- Index
    ELSE
        Index <- Index + 1
    ENDIF
ENDWHILE
OUTPUT Position

Explanation · 3 / 4

Explain why a continued FOR loop can waste work

A FOR loop might prevent a later match from overwriting the first result, yet continue through all remaining iterations. A suitable WHILE loop can stop immediately once Position changes from its sentinel.

Explanation · 4 / 4

Read the supplied function wrapper in the question

A FUNCTION packages these search steps so they can be called with a search value. Its parameter SearchString receives that value; RETURN FoundAt sends the result back. The question supplies this wrapper. Focus on the comparisons, sentinel and loop; you do not need a new search method.

Work together

Trace the final legal comparison

Values = [8, 3, 5, 3, 1], Target = 9, Index starts at 1 and Position at 0.

Work together · 1 / 2

At index 5

The loop condition is TRUE, Values[5] is 1 and the comparison fails. Index becomes 6 while Position stays 0.

Work together · 2 / 2

At the next loop test

Index <= 5 is FALSE, so the body is skipped. Output 0. There is no access to Values[6]. For target 1, the body instead sets Position to 5 and the next test stops because Position = 0 is FALSE.

Make the end-of-array test and the found test control whether another comparison is attempted.

Experiment

The experiment uses -1 for not found; the complete code above uses 0. Both are outside its 1-based legal indices. Try first-position, last-position, duplicate and absent targets. Before each step predict Index and Position and explain why the search stops.

Hint — reading the question
The function is supplied: SearchString is the value to find, and RETURN sends the result back. Explain the existing statements before improving the loop. The valid array indices are 1 to 10000.
Reasoning and model answer — teacher-written
PartReasoning
5(a)(i)-1 is outside the valid indices 1 to 10000, so it cannot be mistaken for a found position.
5(a)(ii)The outer IF compares the current array element with SearchString.
5(a)(iii)FoundAt changes only while it is -1. After the first match it stores a valid index, so later matches cannot replace it.
5(b)(i)The FOR loop checks the remaining elements even after the first occurrence has been found.
5(b)(ii)Use a conditional loop such as WHILE. Continue only while the index is in range and no match has been found, so a successful search stops immediately.
For a small array containing Ada, Lin, Ada and target Ada, the first comparison records index 1. The original loop still visits all three elements, but the inner condition prevents index 3 from replacing 1. An absent target leaves the sentinel unchanged.
Official mark scheme
Why this earns marks — teacher explanation
There is one mark for each of the first four explanations; part 5(b)(ii) gives one mark for a conditional loop and one for early termination after a match. Six marks in total.
Common mistakes — teacher analysis
Do not say the FOR loop gives the wrong position: its first-match guard is correct. Its problem is unnecessary comparisons after a match. A conditional search also needs a bound for the unsuccessful case.
