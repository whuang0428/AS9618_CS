Section 9 · Algorithm design and problem-solving

Build a ticket system, one decision at a time.

Begin at a school event desk. Decide what information matters, make the instructions precise and test how they behave. Each new version adds one idea you can explain and use.

A connected learning route

Each suggested session allows 45 minutes for explanation, prediction and practice. Take more time when needed. The route links ideas in the order you need them; a session can include more than one page.

Browse by topic

From a real ticket desk to an abstract model

Begin with concrete requests and decide which information and instructions a useful solution needs.

Connect responsibilities through program modules

Use the values and control structures already learned to design cooperating parts of a ticket solution.

Represent data with meaningful names

Separate a data item’s name, type, purpose and current value before using it in an algorithm.

Make input, processing and output visible

Follow the source of every value and reveal each assignment before displaying the result.

Choose and repeat the required operations

Build selection and three loop forms in separate sessions, then combine them in complete solutions.

Preserve an algorithm across representations

Translate between words, pseudocode and flowcharts, progressing from a short sequence to two input phases.

Refine a design to programmable detail

Expand unresolved operations and test the final steps against their original purpose.

Turn exact rules into reliable conditions

Construct, trace and challenge comparisons and compound logic before relying on their results.

Integrate the method and transfer it

Complete the ticket purchase, adapt the method to a new calculation and independently design an unfamiliar solution.
