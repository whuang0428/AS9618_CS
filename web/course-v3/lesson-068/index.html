Queues and FIFO operations

Arrival order remains consistent even when a circular array reuses earlier positions.

How does a queue preserve arrival order when array positions are reused?

Before you start

Jobs A, B and C arrive in that order at a first-come, first-served printer. Which is removed first?

Check your answer

A, the earliest job still waiting. This is FIFO.

Add at the rear and remove from the front

Serve the earliest item still waiting

A queue is a first-in, first-out structure. ENQUEUE adds at the rear and DEQUEUE removes and returns the front item. A new arrival joins behind the items already waiting, so serving the front preserves arrival order.

Choose FIFO only when it fits the rule

A first-come, first-served print queue or service desk suits FIFO. The requirement concerns waiting items: a job already removed is no longer in the queue. An ordinary FIFO queue does not automatically move a later urgent job ahead of earlier arrivals; that would require different scheduling rules.

Use the requirement, not the scenario name

The queue describes waiting items. After A is served, the order begins with B; A is no longer a member even if an array cell still contains A. A priority service is a different policy, so a hospital example must explicitly state first-come, first-served before FIFO is justified.

Worked example · Serve arrivals without reordering

  1. Arrivals

    Start with an empty queue. Requests 12, 15 and 18 join the rear in that order.

  2. Service

    Two dequeues return 12, then 15.

  3. Later arrival

    Enqueue 21 leaves 18 at the front and 21 at the rear.

Core explanation · Exam essentials

  • Enqueue at the rear; dequeue from the front.
  • FIFO preserves the arrival order of the remaining waiting items.
Common misconception

A queue does not remove the newest arrival first; that is stack behaviour.

Check your understanding

After A is served and C joins behind B, which item is next?

Check your answer

B remains at the front and is served before C.

02

Use front, rear and count consistently

S10.10.A02S10.10.A04

Visual overview

Use one declared circular model

This circular array implementation uses Front for the next removal position, Rear for the last occupied insertion position, and Count for the number of active items. Initially Front = 1, Rear = 0 and Count = 0. A successful enqueue advances Rear with wrap-around, stores the item and increases Count; a dequeue reads Front, advances it with wrap-around and decreases Count.

Reuse a released position without reordering

Count = 0 means empty and Count = capacity means full. Wrapping from the final index back to 1 reuses positions released by earlier dequeues. An allowed edit changes an active item's value without changing its arrival position or Count. Reading or editing an inactive cell must not turn it into a waiting item.

Update the correct end

  1. Enqueue: Check Count < capacity; advance Rear, wrapping after the upper bound; store the item and increase Count.
  2. Dequeue: Check Count > 0; return the item at Front; advance Front with wrap-around and decrease Count.
  3. Allowed edit: Change only the specified active value. Do not move its arrival position or change Count.

Avoid mixing pointer conventions

Here Rear means the last inserted occupied position when Count > 0, not the next free position. Count is authoritative when empty. Other conventions are possible, but their initial states and update rules cannot be mixed into this trace.

Core explanation · Exam essentials

  • Front selects the next removal; Rear is the last insertion position in this model.
  • Count = 0 is empty; Count = capacity is full. Wrap indices while preserving FIFO.
Common misconception

Physical array order need not equal FIFO order after wrapping; begin at Front and follow the circular positions.

Check your understanding

In the final diagram state, what are the next three dequeue results?

Check your answer

B, C, D: start at Front = 2, then use indices 3 and 1.

Follow every successful and rejected operation

Use Queue[1:3] with Front as the next removal position, Rear as the last insertion position, and Count as the active length. The initial state is Front = 1, Rear = 0, Count = 0; advance a position after 3 back to 1.

An empty queue can be reused

A successful enqueue advances Rear and increases Count. A successful dequeue reads Front, advances Front and decreases Count. This interface also permits editing the front item without changing its position; failed full or empty operations change nothing.

Read the state table

The trace uses capacity 3, indices 1 through 3, and the same Front/Rear/Count convention as the previous unit. Only active values are shown in the logical-order column. Old cell contents have no effect on membership.

Explain the empty-to-nonempty transition

After the final D is removed, Front = 2, Rear = 1 and Count = 0. This is a valid empty state even though it differs from the initial pointers. The next enqueue advances Rear to 2, placing E at Front; there is no need to reset both pointers.

Check before changing anything

Trying to remove from empty or insert into full must leave all three variables and active values unchanged. Do not advance a pointer first and then discover that the operation was impossible.

Core explanation · Exam essentials

  • Derive active order from Front and Count, not from physical left-to-right storage.
  • Empty and full operations are rejected before any state change; emptied storage can be reused.
Common misconception

Count, not matching pointers alone, distinguishes empty from full in this model.

Check your understanding

When F = 2, R = 1, C = 0, which slot receives the next item?

Check your answer

Slot 2: advance Rear from 1 to 2 and increase Count to 1; Front stays 2.

Practice questions

3 core tasks · 9 teacher marks · 13–18 minutes (teacher estimate). Explain your reasoning before checking the answer.

Question 1 · Command word: Describe3 teacher marks

A circular queue has capacity 3 with Front = 2, Rear = 3, Count = 2; indices 2 and 3 hold B and C. Describe enqueueing D.

S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. Rear wraps from 3 to 1 and D is stored at index 1.
  2. Count becomes 3 and Front remains 2.
  3. The logical order is B, C, D.

Common error: Wrapping does not make D the next item to be served.

Question 2 · Command word: State3 teacher marks

An allowed edit changes a queued job's filename without changing its position. State which data changes and which of Front, Rear and Count change. Explain why FIFO is preserved.

S10.09.A02S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. Only the filename stored in the selected active item changes.
  2. Front, Rear and Count remain unchanged.
  3. The job remains in the same arrival position, so dequeue order is preserved.

Common error: Editing a value is not the same operation as removing and re-enqueueing a job.

Question 3 · Command word: State3 teacher marks

A circular queue has capacity 4, F = 4, R = 1, C = 2, with A in slot 4 and B in slot 1. Dequeue twice, attempt another dequeue, then enqueue Z. State the final variables, removal results and Z's position.

S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. The successful dequeues return A then B, leaving F = 2, R = 1, C = 0.
  2. The empty dequeue is rejected with no state change.
  3. Enqueue places Z at slot 2, giving F = 2, R = 2, C = 1.

Common error: Advance through the declared wrap rule and check Count before accessing an item.

Lesson review

Summary

FIFO

Enqueue at the rear and dequeue from the front to preserve arrival order.

Circular storage

Wrap indices to reuse space and use Count to distinguish empty and full states.

Logical order

Read active items from Front, even when their array positions wrap around.
