Build a booking system · Concept 32

Use first in, first out for waiting requests

Observe

Waiting requests in arrival order

  • A arrives.
  • B arrives.
  • C arrives.
  • The desk is ready to serve one request.

Look, then discuss

If requests A, B and C arrive in that order, should C be served first?

Three request cards wait at the booking desk. New cards join the rear, while service takes the card at the front. Trace the waiting order after each arrival and departure.

Recall

Recall current membership

An item removed by an earlier operation is no longer in the collection. The next operation uses the remaining items and any later additions.

Explain

Explanation · 1 / 3

Use different ends for addition and removal

Enqueue adds at the rear. Dequeue removes and returns the front item. A peek operation, if provided, inspects the front without removing it.

Explanation · 2 / 3

Explain FIFO

First in, first out means the earliest added item still waiting is served next. This suits a printer processing jobs in arrival order or a waiting list that must respect arrival order.

Explanation · 3 / 3

Compare the required rule with a stack

Both collections can contain A, B and C. A queue removes A first; a stack removes C first. Select the structure from the required next operation, not from the labels or physical appearance of the data.

Work together

Add a new request after service begins

Enqueue A, B and C; dequeue once; enqueue D.

Work together · 1 / 2

Serve the front

The dequeue returns A. B becomes the earliest remaining request.

Work together · 2 / 2

Add at the rear

D joins after C, leaving B, C, D in front-to-rear order. The next dequeue returns B.

Later arrivals join after existing waiting requests.

Check

Try it yourself · Teacher-written

A printer job with a higher number arrives last. Does FIFO make it run first?

Check your reasoning

No. FIFO follows arrival order, not numerical size or priority. The earliest remaining job is next unless a different scheduling rule is explicitly specified.

Connect

Keep this idea

A queue adds at the rear and removes from the front, preserving first-in-first-out order.

A circular array can maintain that logical order even when it crosses the final physical index.

Reuse released cells with circular pointers

Observe

Queue[0:4]; Front = 3, Rear = 4, Count = 2

Index01234
DataunusedunusedunusedAB
StateFrontRear

Look, then discuss

If the rear reaches the final array cell, can the queue still use a free cell at index 0?

Use a five-cell array indexed 0:4. Front points to the next item for removal; Rear points to the last inserted item; Count records how many items are active. The next position after 4 wraps to 0.

Recall

Recall physical position and logical order

The queue order is obtained by starting at Front and following Count consecutive circular positions. Sorting the physical indices would not necessarily give arrival order.

Explain

Explanation · 1 / 4

State empty and full using Count

Count = 0 means empty and Count = 5 means full. A starting empty state can use Front = 0 and Rear = -1. These pointer values only make sense with the stated convention.

Explanation · 2 / 4

Describe enqueue

If Count = 5, reject the addition. Otherwise advance Rear, wrapping 4 to 0, store the new item there and increase Count. Existing waiting items remain in their current logical order.

Explanation · 3 / 4

Describe dequeue

If Count = 0, reject the removal. Otherwise read the item at Front, advance Front with the same wrap rule and decrease Count. The released cell becomes available for a later enqueue.

Explanation · 4 / 4

Recognise other rear conventions

Some representations make Rear point to the next insertion position instead of the last inserted item. Such a design writes first and advances Rear afterwards. Read the question’s convention; do not mix the two operation orders.

Work together

Cross the final index

Front = 3, Rear = 4 and Count = 2. A is at index 3 and B at index 4; all other cells are inactive.

Work together · 1 / 2

Enqueue C

There is space. Rear wraps from 4 to 0, C is stored at 0 and Count becomes 3. Logical order is A at 3, B at 4, C at 0.

Work together · 2 / 2

Dequeue once

Return A from index 3, move Front to 4 and reduce Count to 2. B at 4 is still before C at 0.

Wrapping changes the physical index sequence while preserving the arrival sequence.

Experiment

Predict Front, Rear and Count for each operation. Dequeue some items, then enqueue enough to wrap around. Read the active order from Front rather than from the leftmost array cell.

A circular queue reuses free slots

Front points to the next removal; Rear points to the last insertion. Count distinguishes an empty queue from a full one.

Build a booking system · Concept 34
Keep edits, removals and failed operations consistent

    
Observe
Front = 4, Rear = 1, Count = 3
Index01234
DataCDold Xold YB
PointerRearFront
Look, then discuss
Does a non-blank cell necessarily contain an item that is still waiting?
After a dequeue, the old data may remain visible in the released cell. Use Front and Count to decide membership before counting items or applying an edit.

    
Recall
Recall data changes versus membership changes
Editing a value changes its contents. Enqueue and dequeue change which items belong to the queue. These actions need different state updates.

    
Explain
Explanation · 1 / 3
Count active positions rather than visible labels
With a last-item Rear convention, follow from Front through the active sequence to Rear, using the count or the stated full/empty rule. Do not include stale values outside that active sequence.
Explanation · 2 / 3
Describe a permitted edit without reordering
If the queue interface allows correcting the current front item, update its data while leaving Front, Rear and Count unchanged. Ordinary FIFO enqueue/dequeue operations do not provide arbitrary middle removal. A requested maintenance edit must be explicitly supported and must preserve the waiting order.
Explanation · 3 / 3
Protect the state at both limits
An enqueue on a full queue and a dequeue on an empty queue fail without moving pointers or changing Count. Test the condition before any write or read that assumes an item or space exists.

    
Work together
Read a wrapped queue with old values
In a 0:4 array, Front = 4, Rear = 1, Count = 3. Active items are B at 4, C at 0 and D at 1. Cells 2 and 3 show old labels.
Work together · 1 / 2
Identify the active collection
The queue contains three items in the order B, C, D. The two other labels do not count.
Work together · 2 / 2
Correct then serve the front
If permitted, correcting B’s data changes cell 4 only. Dequeue then returns that corrected item, advances Front to 0 and reduces Count to 2; C and D remain in order.
Use the logical queue state to determine what may be read, edited or removed.

    
    
Check
Try it yourself · Teacher-written
A full queue rejects a new request. Should Rear still advance to record the attempt?
Check your reasoning
No. A rejected enqueue must leave Rear, Front, Count and active data unchanged. Moving Rear would describe an addition that did not occur.

Question 1 · Command word: Describe3 teacher marks
A circular queue has capacity 3 with Front = 2, Rear = 3, Count = 2; indices 2 and 3 hold B and C. Describe enqueueing D.
S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. Rear wraps from 3 to 1 and D is stored at index 1.
  2. Count becomes 3 and Front remains 2.
  3. The logical order is B, C, D.
Common error: Wrapping does not make D the next item to be served.
Question 2 · Command word: State3 teacher marks
An allowed edit changes a queued job's filename without changing its position. State which data changes and which of Front, Rear and Count change. Explain why FIFO is preserved.
S10.09.A02S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. Only the filename stored in the selected active item changes.
  2. Front, Rear and Count remain unchanged.
  3. The job remains in the same arrival position, so dequeue order is preserved.
Common error: Editing a value is not the same operation as removing and re-enqueueing a job.
Question 3 · Command word: State3 teacher marks
A circular queue has capacity 4, F = 4, R = 1, C = 2, with A in slot 4 and B in slot 1. Dequeue twice, attempt another dequeue, then enqueue Z. State the final variables, removal results and Z's position.
S10.10.A02S10.10.A04
Answer and checking points — teacher-written
  1. The successful dequeues return A then B, leaving F = 2, R = 1, C = 0.
  2. The empty dequeue is rejected with no state change.
  3. Enqueue places Z at slot 2, giving F = 2, R = 2, C = 1.
Common error: Advance through the declared wrap rule and check Count before accessing an item.
Question 4 · Command word: State2 teacher marks
A queue receives ENQUEUE 6, ENQUEUE 2, DEQUEUE, ENQUEUE 9, DEQUEUE. State both returned values and the remaining item.
S10.09.A02
Answer and checking points — teacher-written
  1. The dequeues return 6 and then 2.
  2. 9 remains waiting.
Common error: Remove the earliest item still present.
