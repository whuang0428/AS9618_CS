Bit streaming, rates and buffers

Track incoming rate, playback bit rate and buffer level instead of treating ‘buffering’ as a vague delay.

A video needs 4 Mbit each second but only 3 Mbit arrives. What exactly is being used up, and why can a larger buffer delay—but not permanently fix—the pause?

Before you start

Does a larger buffer increase broadband speed?

Check your answer

No. It stores more already-arrived data; the connection’s sustained incoming rate is unchanged.

01

Concept teaching

Visual overview and core explanation

01

Streaming begins before the complete media file arrives

S2.12.A01S2.12.A02

Visual overview

Core explanation

Bit streaming delivers an ordered flow of media data progressively so playback can begin before the complete file has arrived.

On-demand streaming sends stored content chosen by the user; the user controls when to begin. Real-time streaming sends content as it is produced, such as a live event, with minimal practical delay.

Both methods may use a buffer. ‘Real-time’ does not mean zero delay, and ‘on-demand’ does not require downloading the complete file first.

Common misconception

Real-time streaming still has encoding, network and buffering delay.

02

The buffer level is the difference between two rates over time

S2.12.A03S2.12.A04S2.12.A05S2.12.A06

Visual overview

Core explanation

Incoming rate and playback demand

Bit rate is the number of bits transmitted or consumed each second. The incoming rate is limited by available broadband capacity and current conditions; the playback bit rate is how quickly the media player consumes encoded data.

How the stored level changes

A buffer stores data that has arrived but has not yet been played. If incoming rate exceeds playback bit rate, the level rises. If the rates are equal, the level is stable. If incoming rate is lower, the buffer drains.

What a larger buffer can and cannot solve

A buffer absorbs short variation. If the deficit continues, stored data reaches zero and playback must pause or switch to a lower-bit-rate version. More buffer increases the time before interruption but does not repair sustained insufficient speed.

Worked example · Worked rate example

  1. Given

    Video uses 4 Mbit/s; connection supplies 3 Mbit/s; buffer holds 30 Mbit

  2. Difference

    4 − 3 = 1 Mbit/s deficit

  3. Time

    30 Mbit ÷ 1 Mbit/s = 30 seconds until empty if rates stay constant

  4. Then

    Pause, reduce quality/bit rate, or obtain a higher sustained incoming rate

Common misconception

A buffer stores media data; it is not extra broadband capacity.

02

Cambridge command words

Practice questions

Command word: Define4 marks

Define bit streaming and compare real-time streaming with on-demand streaming.

S2.12.A01S2.12.A02
Answer and marking points
  1. An ordered sequence of data is transmitted progressively so playback can start before the complete file arrives.
  2. Real-time streaming delivers content as it is produced.
  3. On-demand streaming delivers content that has already been stored.
  4. The viewer chooses when to start on-demand content, whereas real-time content follows the ongoing event.

Common error: Do not define streaming as downloading the whole file first.

Command word: Calculate4 marks

A stream plays at 5 Mbit/s and arrives at 7 Mbit/s for 12 seconds. Calculate the buffer increase and explain the result.

S2.12.A03S2.12.A04S2.12.A05
Answer and marking points
  1. Difference = 2 Mbit/s.
  2. Increase = 2 × 12 = 24 Mbit.
  3. Buffer stores arrived but unplayed data.
  4. Playback can absorb a later short drop using this stored data.

Common error: Keep Mbit and Mbit/s units distinct.

Command word: Explain5 marks

A connection remains below a video’s playback bit rate. Explain why increasing buffer size alone cannot provide uninterrupted playback forever.

S2.12.A03S2.12.A04S2.12.A05S2.12.A06
Answer and marking points
  1. Playback consumes data faster than it arrives.
  2. Buffer level falls by the sustained deficit.
  3. A larger buffer can hold a larger initial reserve of unplayed data.
  4. Eventually it becomes empty.
  5. Player must pause, reduce bit rate/quality or receive a faster sustained connection.

Common error: Do not claim the buffer increases connection speed.

Question 1 · Command word: Describe · 5 marks

Describe how an on-demand recorded lecture can begin playing before its complete file has arrived, including the role of ordered data and the buffer.

Answer and marking points
  • The stored lecture is delivered progressively as an ordered stream of data rather than waiting for the complete file.
  • The player accumulates an initial portion of the arriving stream in a buffer before playback begins.
  • Playback consumes buffered data in sequence while later portions continue to arrive from the server.
  • Because the lecture is on demand, the user chooses when to start the already stored content.
  • A temporary fall in arrival rate can be absorbed while enough unplayed data remains in the buffer.

Common error: Do not say that streaming requires the complete file to arrive before playback; progressive delivery is the defining distinction in this scenario.

Question 2 · Command word: Calculate · 3 marks

A player starts with 90 Mbit of unplayed data. The incoming rate remains 3 Mbit/s while playback uses 6 Mbit/s. Calculate how long playback can continue before the buffer empties.

Answer and marking points
  • The net buffer depletion rate is 6 − 3 = 3 Mbit/s.
  • Time to empty = initial buffered data / net depletion rate = 90 / 3.
  • Playback can continue for 30 seconds.

Common error: Use the deficit between consumption and arrival; dividing by the playback rate ignores incoming data.

Question 3 · Command word: Explain · 5 marks

A live video requires 8 Mbit/s but the connection can sustain only 6 Mbit/s. Explain how changing the stream to 5 Mbit/s can prevent repeated interruption and state the trade-off.

Answer and marking points
  • At 8 Mbit/s, playback consumes data 2 Mbit/s faster than the connection can supply it.
  • Any finite stored data is progressively exhausted, causing the player to pause and refill.
  • At 5 Mbit/s, the 6 Mbit/s connection can supply data at least as quickly as playback consumes it under the stated sustained rate.
  • The buffer can remain stable or gain data, so the sustained deficit no longer forces repeated pauses.
  • The lower stream bit rate normally reduces video or audio quality.

Common error: Do not claim that a larger buffer changes the sustained connection rate; adaptation works here by reducing the consumption rate below the arrival rate.
