Communicate data · Concept 32

Play arriving media before the complete recording is available

Observe

Two classroom viewing activities

  • The teacher opens a previously recorded revision clip.
  • The class joins a live video discussion with a partner school.
  • In both activities, later media can still be arriving while earlier media plays.

Look, then discuss

Why would waiting for the complete file fail for a live discussion that has not finished?

Discuss the observation

The future part of a live event does not yet exist. Streaming lets playback proceed from available data while more data is transmitted and received.

Recall

Recall compression at the point it becomes useful

Digital audio and video contain data represented in bits. Compression reduces the data required for a representation. A lossy delivery version may sacrifice some detail to use fewer bits; lossless compression preserves its source data exactly. The codec details are outside this networking activity.

Revisit: Balance access and capacity against specific dependencies · Resolve the name, then ask the web server for the resource

Explain

Explanation · 1 / 4

Explain streaming as overlapping work

In bit streaming, media data is delivered as an ongoing sequence and playback can start before the entire resource has been received. Arrival, temporary storage and playback overlap rather than waiting for one complete file download first.

Explanation · 2 / 4

Describe on-demand streaming

On-demand media has already been recorded. The viewer chooses when to start and may be able to pause or seek within the available resource. Data can be delivered ahead of the current playback position, subject to the application’s buffering choices.

Explanation · 3 / 4

Describe real-time streaming

Real-time media is produced and transmitted as the event happens. In a video discussion, capture, encoding or compression, transmission and playback occur continuously. Excessive waiting damages the conversation even if every bit eventually arrives.

Explanation · 4 / 4

Introduce the receiver buffer

A buffer temporarily stores arriving media until playback consumes it. It can absorb short variations in arrival, but it does not create future live content or an unlimited supply. The next concepts quantify its stored amount and changes.

Work together

Trace one live contribution

A student speaks during a live school discussion delivered through a media service.

Work together · 1 / 3

Capture and prepare

The microphone and camera produce digital media. Encoding and compression prepare an ongoing stream for transmission.

Work together · 2 / 3

Send and temporarily store

The stream is sent through the network and, in this scenario, relayed by a media server. The receiver stores available arriving data in a buffer.

Work together · 3 / 3

Play while receiving

The receiving device reads buffered media for playback while later media continues to arrive. Waiting for the discussion to finish would defeat the live interaction.

The exact service arrangement can vary, but ongoing arrival and progressive playback are essential to this example.

Check

Try it yourself · Teacher-written

Distinguish on-demand from real-time streaming and explain why both may use a buffer.

Check your reasoning

On-demand streaming delivers a previously recorded resource when the viewer chooses; real-time streaming delivers an event as it is produced. Both can temporarily store arriving media before consumption so that short arrival variations do not immediately interrupt playback. A live buffer cannot contain content that has not yet been produced.

Connect

Keep this idea

Streaming overlaps delivery and playback; on-demand and real-time differ in when the source media exists.

To explain whether arriving data can keep up, measure how many bits arrive and how many playback consumes each second.

Communicate data · Concept 33

Compare two rates using the same units

Observe

Two labels on the player

  • Incoming usable media data: 6 Mbit/s
  • Playback consumes media data: 4 Mbit/s
  • One byte contains eight bits.

Look, then discuss

While playback is running, how much extra media data arrives each second?

Discuss the observation

Six million bits arrive while four million are used. The difference is two million bits per second, provided there is space to hold it.

Recall

Read b and B carefully

A bit rate is a quantity of bits per second. Here Mbit/s uses the decimal multiplier 1,000,000. A byte contains eight bits, so 1 MB of data is 8 Mbit under these decimal units. Storage capacity and transfer rate are different quantities.

Revisit: Play arriving media before the complete recording is available

Explain

Explanation · 1 / 4

Define the incoming rate

The incoming media rate is the amount of usable media data received per second. It can change as network conditions and shared use change. A connection’s advertised maximum is not a guarantee of the sustained rate this player actually receives.

Explanation · 2 / 4

Define the playback rate

Playback consumes encoded media data at a required rate. A higher-resolution or less-compressed version may need more bits per second, but the precise requirement belongs to the actual media representation. Use the supplied playback rate in calculations.

Explanation · 3 / 4

Convert before comparing

Keep bits and bytes separate and use consistent prefixes. A rate of 500 kB/s is 500 × 8 = 4000 kbit/s = 4 Mbit/s in decimal units. Comparing 500 with 4 without their units gives no useful conclusion.

Explanation · 4 / 4

Relate rate and amount

At a constant rate, amount = rate × time. Receiving 6 Mbit/s for 5 seconds supplies 30 Mbit. Time = amount ÷ rate when the rate remains constant. These are simplified usable-media quantities, so add protocol overhead only when the problem supplies or requests it.

Work together

Check whether a 500 kB/s arrival keeps up

A video needs 3 Mbit/s. The player receives a constant usable media rate of 500 kB/s. Use decimal prefixes.

Work together · 1 / 3

Convert the arrival rate

500 kB/s × 8 = 4000 kbit/s = 4 Mbit/s.

Work together · 2 / 3

Compare like units

The incoming 4 Mbit/s exceeds the 3 Mbit/s consumption by 1 Mbit/s.

Work together · 3 / 3

Count ten seconds

Arrival supplies 40 Mbit and playback consumes 30 Mbit in ten seconds. Stored content would increase by 10 Mbit if the buffer has enough space.

The comparison becomes meaningful only after rates use the same unit.

Check

Try it yourself · Teacher-written

A player receives 0.75 MB/s and consumes 5 Mbit/s. Convert the incoming rate and find the difference using decimal units.

Check your reasoning

0.75 MB/s × 8 = 6 Mbit/s. The incoming rate exceeds consumption by 1 Mbit/s. During steady playback the buffer can gain 1 Mbit each second while it has spare capacity.

Connect

Keep this idea

Bit rate measures bits per second; convert units before comparing arrival with playback.

A rate difference changes a stored quantity. Track that quantity through successive time intervals.

Communicate data · Concept 34

Track what is stored, not just whether the connection is fast

Observe

A buffer has a starting amount

IntervalIncoming ratePlayback rate while running
First 4 seconds3 Mbit/s2 Mbit/s
Next 3 seconds1 Mbit/s2 Mbit/s

Look, then discuss

If playback starts with 4 Mbit buffered, does the slower second interval immediately cause a pause?

Discuss the observation

No. Previously stored content can cover a temporary shortfall. We need the starting buffer amount as well as the rates and duration.

Explain

Explanation · 1 / 5

Describe the temporary store

The receiver buffer holds media that has arrived but has not yet been consumed. During initial buffering, playback may wait until a chosen threshold is reached. Arrival can then continue while playback removes older content.

Explanation · 2 / 5

Calculate the change during playback

While playback runs and neither boundary is reached, new buffer amount = old amount + (incoming rate − playback rate) × time. Equal rates keep the amount unchanged; a positive difference fills it; a negative difference drains it.

Explanation · 3 / 5

Handle the empty boundary

The buffer cannot become negative. If it empties and arrival cannot sustain playback, the player must change behaviour, such as pausing to refill or reducing the required media rate. Once playback pauses, its consumption rate is zero until it resumes, so the earlier running-state calculation no longer applies.

Explanation · 4 / 5

Handle finite capacity

A buffer also has a maximum size. Once it is full, the simple unlimited accumulation calculation stops being valid. The application may pause requests or otherwise control delivery. Do not draw more stored data than the specified capacity permits.

Explanation · 5 / 5

State the model assumptions

Use constant rates only for the stated interval. The experiment uses one-second steps, receiving data before deciding whether to play in each step. It shows the starting threshold and rate balance but does not impose a full-buffer capacity limit. A real buffer is finite; use a supplied capacity when analysing that boundary. Different players can use different pause and restart policies.

Work together

Carry the buffer state from one interval to the next

Start with 4 Mbit buffered. Capacity is 12 Mbit and playback is already running at 2 Mbit/s.

Work together · 1 / 3

Calculate the first interval

For 4 seconds, incoming rate is 3 Mbit/s. Change = (3 − 2) × 4 = +4 Mbit, so the buffer reaches 8 Mbit.

Work together · 2 / 3

Use the new starting amount

For the next 3 seconds, incoming rate is 1 Mbit/s. Change = (1 − 2) × 3 = −3 Mbit, leaving 5 Mbit.

Work together · 3 / 3

Check the boundaries

The amount stays between 0 and 12 Mbit, so neither interval needs a pause or full-buffer adjustment. Playback can continue despite the slower second interval.

Every interval starts from the amount left by the previous one.

Experiment

Predict when the buffer reaches the start threshold, then step through playback. Compare arrival above, equal to and below playback, and explain the stored amount rather than just saying “fast” or “slow”.

Change the rates, then advance one second at a time. Track the data received, played and left in the buffer.

Change conditions

Predict: Will playback run this second, and how many Mbit will remain?

Discrete one-second model: receive first, then consume one complete second or pause. Rates stay constant, playback keeps its position, and the buffer has no capacity limit. On-demand content is already available; live content is produced at the playback data rate. Real players use smaller chunks and other restart policies.

Check

Try it yourself · Teacher-written

A running player has 10 Mbit buffered and consumes 4 Mbit/s. Incoming data is 2 Mbit/s for 3 seconds. How much remains, and why must the calculation change if the buffer later empties?

Check your reasoning

The deficit is 2 Mbit/s, so 6 Mbit is consumed from the reserve in 3 seconds, leaving 4 Mbit. If the buffer empties, it cannot become negative; the player must pause, adapt or use another stated policy. A paused player is not still consuming at the previous playback rate.

Connect

Keep this idea

A buffer absorbs a temporary rate mismatch by increasing or decreasing its finite stored reserve.

A finite reserve helps temporarily. Now test whether it can overcome a permanent shortfall.

Communicate data · Concept 35

Explain why a finite buffer cannot solve a permanent deficit

Observe

The connection settles below the video requirement

  • Playback needs 4 Mbit/s.
  • Usable arrival remains at 3 Mbit/s.
  • The player begins with 12 Mbit stored.

Look, then discuss

Would doubling the starting buffer make uninterrupted playback possible forever?

Discuss the observation

The reserve is being spent at 1 Mbit every second. Doubling the reserve doubles the time it can cover that deficit, but the continuing shortfall remains.

Explain

Explanation · 1 / 4

Find the sustained deficit

When playback consumes faster than usable media arrives, the buffer decreases by the difference. If those conditions continue, any finite starting reserve eventually runs out. Extra initial buffering buys time rather than changing the ongoing rate balance.

Explanation · 2 / 4

Compare practical responses

A player may pause to accumulate more content, select a representation with a lower required bit rate, or benefit from a more reliable usable network rate. Each response changes a relevant quantity. Repeating the same fixed-rate playback with an unchanged deficit recreates the problem.

Explanation · 3 / 4

Keep latency visible for live media

A larger live buffer can smooth some arrival variation but puts playback further behind capture time. In a conversation, that delay may be undesirable. A live source also limits how much future content can be prefetched because it has not yet been created.

Explanation · 4 / 4

Diagnose the correct stage

Successful DNS resolution or an open page proves neither sufficient throughput nor an available buffer reserve. Check arrival, consumption, stored amount and time. A paused video is not by itself proof that the school’s domain name failed to resolve.

Work together

Predict the pause and test a lower-rate version

The buffer starts at 12 Mbit. Arrival remains 3 Mbit/s and the current version needs 4 Mbit/s.

Work together · 1 / 3

Calculate depletion

The deficit is 4 − 3 = 1 Mbit/s. The 12 Mbit reserve covers 12 seconds of that continuing deficit before the buffer empties.

Work together · 2 / 3

Test a bigger reserve

A 24 Mbit starting reserve would cover 24 seconds under the same conditions. It still cannot cover an unlimited duration.

Work together · 3 / 3

Change the requirement

A version requiring 2 Mbit/s would leave a 1 Mbit/s surplus at the same arrival rate. That can support sustained playback under these simplified steady conditions, with a possible quality trade-off.

A lasting solution changes the sustained rate balance or accepts interruptions.

Experiment

Predict how long the starting reserve lasts. Compare a lower playback rate with the same on-demand arrival capacity. Then switch to live: explain why arrival cannot prefetch media beyond what the source has produced.

Check

Try it yourself · Teacher-written

A 20 Mbit reserve covers a sustained 2 Mbit/s deficit. Find the depletion time and explain one lasting response and one response that only postpones interruption.

Check your reasoning

20 ÷ 2 = 10 seconds until the reserve is exhausted while playback continues. Reducing the required media rate sufficiently, or increasing sustained usable arrival, can remove the deficit. Increasing a finite starting reserve only postpones interruption if the same deficit continues.

Original question · Cambridge 9618/13

1. Explain real-time audio and video streaming

Cambridge 9618/13 · October/November 2024 · 9(c) · 4 marks

Selected parts: 9(c) [4].

Hint — reading the question

Explain an ongoing conference, where playback must occur while more data arrives. Include the sending stream and the receiver’s buffer.

Reasoning and model answer — teacher-written

Audio and video are compressed and sent continuously as a stream of bits to a media server. The server sends the incoming stream to the receiving device’s buffer. The buffer temporarily holds arriving data until it can be processed. The device reads buffered data to play the conference while later data is still arriving.

Official mark scheme
Why this earns marks — teacher explanation

The scheme awards up to four marks from compression, continuous bit transmission, the media server and the receiver’s buffer operations. The explanation connects those stages instead of repeating “it streams live”.

Common mistakes — teacher analysis

Waiting for the entire conference file before playback would not meet the real-time requirement. A buffer absorbs variation; it does not fix a permanently insufficient average arrival rate.

Question 1 · Command word: Explain5 teacher marks

A connection remains below a video’s playback bit rate. Explain why increasing buffer size alone cannot provide uninterrupted playback forever.

S2.12.A03S2.12.A04S2.12.A05S2.12.A06
Answer and checking points — teacher-written
  1. Playback consumes data faster than it arrives.
  2. Buffer level falls by the sustained deficit.
  3. A larger buffer can hold a larger initial reserve of unplayed data.
  4. Eventually it becomes empty.
  5. Player must pause, reduce bit rate/quality or receive a faster sustained connection.

Common error: Do not claim the buffer increases connection speed.

Question 2 · Command word: Calculate5 teacher marks

Calculate the buffer contents after each interval. Playback has already started at 5 Mbit/s, the initial reserve is 10 Mbit and capacity is 30 Mbit. Arrival is 7 Mbit/s for 3 s, then 3 Mbit/s for 8 s. Ignore overhead. State what happens if the low arrival rate continues after those intervals.

S2.12.A03S2.12.A04S2.12.A05S2.12.A06
Answer and checking points — teacher-written
  1. In the first interval, net gain is (7 − 5) × 3 = 6 Mbit.
  2. After 3 s, the content is 10 + 6 = 16 Mbit.
  3. The second interval loses (5 − 3) × 8 = 16 Mbit.
  4. At total time 11 s, the reserve is zero.
  5. Continued input at 3 Mbit/s cannot support 5 Mbit/s playback; pause/rebuffer or reduce the media rate.

Common error: Carry content forward between intervals and stop the uninterrupted-playback calculation at zero.

Question 3 · Command word: Calculate4 teacher marks

Calculate the startup time for an empty buffer to collect 18 Mbit at an arrival rate of 6 Mbit/s before playback begins. Playback then starts at 4 Mbit/s and the connection immediately fails for 2 s. State the remaining reserve, and explain why a capacity of 40 Mbit does not give 10 s of outage protection at that moment.

S2.12.A03S2.12.A04S2.12.A05
Answer and checking points — teacher-written
  1. Startup time is 18 / 6 = 3 s because playback consumption is zero before starting.
  2. The outage consumes 4 × 2 = 8 Mbit.
  3. The remaining reserve is 18 − 8 = 10 Mbit.
  4. Capacity is the maximum storable amount; only the actual reserve protects playback, so 40 / 4 does not describe this starting state.

Common error: Do not subtract a playback rate during startup or substitute capacity for current content.

Question 4 · Command word: Define4 teacher marks

Define bit streaming and compare real-time streaming with on-demand streaming.

S2.12.A01S2.12.A02
Answer and checking points — teacher-written
  1. An ordered sequence of data is transmitted progressively so playback can start before the complete file arrives.
  2. Real-time streaming delivers content as it is produced.
  3. On-demand streaming delivers content that has already been stored.
  4. The viewer chooses when to start on-demand content, whereas real-time content follows the ongoing event.

Common error: Do not define streaming as downloading the whole file first.

Question 5 · Command word: Calculate4 teacher marks

A stream plays at 5 Mbit/s and arrives at 7 Mbit/s for 12 seconds, with playback already running and enough free buffer capacity for all arrivals. Calculate the buffer increase and explain the result.

S2.12.A03S2.12.A04S2.12.A05
Answer and checking points — teacher-written
  1. Difference = 2 Mbit/s.
  2. Increase = 2 × 12 = 24 Mbit.
  3. Buffer stores arrived but unplayed data.
  4. Playback can absorb a later short drop using this stored data.
