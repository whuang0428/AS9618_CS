Choose names and types

Use DECLARE Identifier : DataType for a variable. Choose INTEGER for whole-number counts, REAL for values that may have a fractional part, BOOLEAN for TRUE or FALSE, CHAR for one character and STRING for text. A declaration does not provide an initial value.

Give constants literal values

Declare and initialise a named constant with CONSTANT Identifier = Literal. Its type follows from the literal and its value remains fixed. Use double quotes for a STRING literal and single quotes for a CHAR literal. In this notation a constant declaration uses a literal, rather than an expression involving other identifiers.

Separate three responsibilities

StatementWhat it establishesWhat it does not establish
DECLARE Total : REALA variable name and permitted data type.No initial numeric value.
Total <- 0.0The current value of the declared variable.A new declaration or a permanent restriction to zero.
CONSTANT TaxRate = 0.20A fixed named value supplied by a literal.A variable that can later store a different rate.

Choose from the meaning of the data

A meaningful name exposes a value’s role: Quantity is an INTEGER count while ProductCode is a STRING if leading zeros matter and arithmetic is not required. Lesson 058 develops the data types in full, including DATE; this lesson concentrates on using declarations correctly in programs.

Distinguish a fixed value from a computed value

A constant avoids repeating an unexplained literal throughout a program. Changing its declaration for a different version updates all uses of the name. In Cambridge pseudocode, CONSTANT DoubleRate = TaxRate * 2 is not a valid constant declaration: only a literal is allowed on its right side.

Core explanation · Exam essentials

  • DECLARE gives a variable its type; initialise it before reading its value.
  • Use CONSTANT Name = Literal; quoted STRING, quoted CHAR and BOOLEAN literals are different types.
Common misconception

CONSTANT TaxRate <- 0.20 uses the assignment symbol in a declaration.

Check your understanding

Which type suits an identifier that stores either TRUE or FALSE?

Check your answer

BOOLEAN.

02

Obtain, assign and output values

S11.02.A03S11.02.A05

Visual overview

Evaluate before storing

Assignment evaluates the expression on the right and stores the result in the variable on the left. Total <- Price * Quantity changes Total; Total = Price * Quantity is a comparison. A later assignment replaces the variable's earlier value. INPUT obtains a value from the keyboard, while OUTPUT writes a value or expression to the console.

Follow the purchase dependencies

For a purchase with tax charged per item, read Price and Quantity before using either. Compute Tax <- Price * TaxRate, then multiply the tax-inclusive item price by Quantity. Declaring all identifiers, obtaining the inputs and assigning intermediate results in order prevents undefined values from reaching the calculation.

Read Quantity <- Quantity + 1

  1. Read: Obtain the old Quantity value.
  2. Evaluate: Add one to that old value.
  3. Store: Replace Quantity with the result. The statement is an update, not a mathematical equality.

Copy a value rather than establish a link

B <- A copies A’s value at that moment. A later assignment to A does not cause B to be recalculated. A variable on the right side must already have a value, even when it is also the destination on the left.

Make the report understandable

OUTPUT can display several values separated by commas, for example OUTPUT "Total: ", Total. The text is a label and Total supplies the current number. Output does not store a new variable. Constructing a reusable STRING with & is a separate operation taught in Lesson 075.

Worked example · Calculate a tax-inclusive purchase

  1. Requirements and starting conditions

    Input a non-negative REAL Price and non-negative INTEGER Quantity. Tax is 20% of the price per item.

  2. Cambridge pseudocode
    CONSTANT TaxRate = 0.20
DECLARE Quantity : INTEGER
DECLARE Price, Tax, Total : REAL
INPUT Price
INPUT Quantity
Tax <- Price * TaxRate
Total <- (Price + Tax) * Quantity
OUTPUT Total
  3. Expected result

    Price 10 and Quantity 3 give Tax 2 and Total 36. Price 0 gives Total 0.

Worked example · Trace copies and replacement

  1. Requirements and starting conditions

    A and B are separate INTEGER variables. Follow all three assignments before output.

  2. Cambridge pseudocode
    DECLARE A, B : INTEGER
A <- 4
B <- A
A <- A + 3
OUTPUT "A = ", A, "; B = ", B
  3. Expected result

    After A <- 4: A is 4 and B is uninitialised. After B <- A: both are 4. After A <- A + 3: A is 7 and B remains 4. Display: A = 7; B = 4.

Core explanation · Exam essentials

  • Obtain all inputs before calculations that read them.
  • Assignment evaluates the right side and replaces the left-side variable; OUTPUT displays values.
Common misconception

OUTPUT displays a result; it does not assign that result to a new variable.

Check your understanding

What does Quantity <- Quantity + 1 do?

Check your answer

It reads the old Quantity, adds one and stores the result back in Quantity.

DECLARE Stock : INTEGER

CONSTANT DiscountRate = 0.10
  1. Use INTEGER, REAL, BOOLEAN and CHAR for Stock, Price, InStock and Grade respectively.

Common error: A constant declaration supplies its value with =.

Question 2 · Command word: State2 teacher marks

State the final values of A and B after A <- 4, B <- A and A <- A + 3. Explain why B has that value.

S11.02.A03
Answer and checking points — teacher-written
  1. A finishes as 7 and B as 4.
  2. B receives the value of A at assignment time, not a permanent link to A.

Common error: Ordinary scalar assignment copies a value.

Question 3 · Command word: Write3 teacher marks

Write pseudocode that inputs an integer Quantity and a real Price, calculates Total <- Price * Quantity, and outputs Total.

S11.02.A02S11.02.A03S11.02.A05
Answer and checking points — teacher-written

One valid Cambridge pseudocode solution

DECLARE Quantity : INTEGER
DECLARE Price, Total : REAL
INPUT Quantity
INPUT Price
Total <- Price * Quantity
OUTPUT Total
  1. Declare Quantity as INTEGER and Price and Total as REAL.
  2. INPUT Quantity and INPUT Price occur before the calculation.
  3. Assign the product to Total and OUTPUT Total.

Common error: Use <- for assignment, not =.

Original question · Cambridge 9618/22

1. Make repeated postal rates maintainable

Cambridge 9618/22 · May/June 2023 · 1(a)(i), 1(a)(ii) · 4 marks

Selected parts: 1(a)(i) [1]; 1(a)(ii) [3].

Reading the question — teacher guidance

The same postal costs appear at several places in the program. Explain how your representation improves this specific maintenance problem.

Solution / model answer — teacher-written

1(a)(i): Use named constants for the postal rates.

1(a)(ii): Each rate is defined once, so a rate change requires one edit rather than changes throughout the program. Reusing that constant avoids inconsistent or mistyped rate values in different calculations. A meaningful name also makes the purpose of a postal rate clear where it is used.

Official mark scheme
Why this earns marks — teacher explanation

Part (i) is one mark. Part (ii) has three marks from four accepted benefits, including defining rates once, avoiding errors, changing a rate once and improving understanding.

Common mistakes — teacher analysis

A constant’s definition can be edited between program versions; its value is not reassigned during a run. A meaningless name such as C1 loses much of the readability benefit.
