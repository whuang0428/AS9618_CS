01

And use procedures with parameters passed by reference and by value: Procedures and parameter passing

S11.06.A01S11.06.A02S11.06.A03S11.06.A04S11.06.A05

A procedure is a named subroutine used for an action or coherent sequence of actions. It may have no parameters, one parameter or several parameters.

A parameter is declared in the procedure header; an argument is the actual value or variable supplied in a CALL. BYVAL gives the procedure a value without allowing assignments to change the caller's variable. BYREF allows a procedure assignment to update the caller's variable.

Use a procedure when a repeated action has a clear interface, such as validating input, updating a record or displaying a report. The call hides implementation detail while the header documents the required data.

Mechanism in examinable order

  1. Declare the procedure interfaceName the procedure and declare each typed parameter as BYVAL or BYREF where the mode matters.
  2. Supply matching argumentsPass actual values or variables in the documented order and with compatible types.
  3. Check which caller values can changeAssignments to a BYREF parameter persist in the caller; assignments to a BYVAL parameter do not change the caller's variable.

Worked example · Contrast BYVAL and BYREF

  1. Definition
    PROCEDURE AddBonus(BYVAL Rate : REAL, BYREF Pay : REAL)
  Pay <- Pay + Pay * Rate
  Rate <- 0.00
ENDPROCEDURE
  2. Call
    Rate <- 0.10
Pay <- 500.00
CALL AddBonus(Rate, Pay)
  3. Result

    Pay becomes 550.00 because it is BYREF. Rate remains 0.10 in the caller because the parameter received it BYVAL.

Common misconception

BYVAL protects the caller's variable from assignments to the parameter; BYREF allows those assignments to update the caller. Both still pass an argument at the call.
