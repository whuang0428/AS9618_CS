Sound representation and file compression

Phase 1: sample, quantise, encode and size sound. Phase 2: encode, decode and evaluate compression across media.

How is continuous sound sampled into binary data, and how do lossy, lossless and RLE compression change stored files?

Before you start

A recorder stores 8000 samples, each using 8 bits. How many bytes is that, and what changes if each sample uses 16 bits?

Check your answer

8000 bytes at 8 bits per sample; 16000 bytes at 16 bits. Doubling bits per sample doubles data size for the same sample count.

01

Analogue sound and the sampling process

S1.10.A01S1.10.A02

Visual overview

Separate three stages

An analogue sound signal varies continuously with time and amplitude. Digital storage contains discrete measurements: sampling chooses equally spaced times, quantisation chooses from a finite set of amplitude levels, and encoding assigns a binary code to each chosen level.

Define a complete teaching model

This small model uses four samples per second and three bits per sample. There are eight allowed levels −4, −3, −2, −1, 0, 1, 2, 3. Round each measurement to the nearest allowed level; an exact halfway case would round upwards, and values beyond the range would clip to the nearest endpoint. None of the measurements below needs a tie or clipping rule.

Preserve the mapping and order

The stored stream is 001 011 110 111, in time order: four samples × three bits = 12 bits of sample data. The code mapping is an explicitly defined offset code, not three-bit two’s complement and not a claim about a real audio file format. The −3 level has code value 1, so it is 001.

Decode and reconstruct

  1. Read the sample codes: Split the stream into three-bit groups: 001, 011, 110, 111.
  2. Recover levels: Convert codes to values 1, 3, 6, 7 and subtract 4, giving −3, −1, 2, 3.
  3. Recover timing: At 4 Hz, place those levels at 0, 0.25, 0.50 and 0.75 seconds.
  4. Explain the limit: A playback system uses timed levels to construct an analogue output. It cannot recover the exact original values −3.2, −0.6, 1.6 and 2.7 or all changes between sample times from these codes alone.

Connect data to devices

The brown line is a simplified continuous source trace; blue points show the quantised levels at the sample times. The trace’s straight segments are a teaching model, not a claim about the shape of every sound wave. Lesson 016 connects this data model to microphones, ADCs, DACs and speakers.

Core explanation · Exam essentials

  • Sampling chooses times; quantisation chooses levels; encoding stores their binary codes.
  • Decode using the same code mapping, width, order and sampling rate.
  • Quantisation and finite sampling limit how closely a recording can represent the analogue source.
Common misconception

Sampling records discrete measurements of a continuous wave; it does not store the complete continuous waveform directly.

Check your understanding

Are sound samples taken at arbitrary or equally spaced time intervals?

Check your answer

Equally spaced intervals, determined by the sampling rate.

02

Sampling rate

S1.10.A03

Visual overview

Change timing independently of amplitude levels

Sampling rate is the number of samples taken per second per channel, measured in hertz (Hz). Rate determines the spacing in time: at 4 Hz the interval is 1/4 second; at 8 Hz it is 1/8 second. Keep the amplitude levels unchanged when comparing the effect of rate.

Read the controlled comparison

In the diagram, both rows sample the same defined one-second analogue trace at the same three-bit resolution. The 4 Hz row takes four values; the 8 Hz row takes eight and captures additional changes between the earlier sampling times. This illustrates greater time detail during capture; it does not imply that doubling the rate always audibly improves every source.

Worked uncompressed sound size

  1. State the inputs: Duration 5 s; rate 16,000 Hz; resolution 16 bits per sample; one channel (mono). Exclude headers and compression.
  2. Count samples: 5 × 16,000 × 1 = 80,000 sample values.
  3. Count bits: 80,000 × 16 = 1,280,000 bits.
  4. Convert to bytes: 1,280,000 / 8 = 160,000 bytes.
  5. Vary one parameter: Doubling rate to 32,000 Hz doubles data to 320,000 bytes. Keeping 16,000 Hz but using two channels also gives 320,000 bytes.

Generalise and connect

In general, raw sound bytes = duration × sampling rate × bits per sample × channels / 8. Use seconds and samples per second consistently. Sampling rate is not the connection’s transfer bit rate; Lesson 012 uses the resulting data volume when reasoning about streaming.

Separate recapture from upsampling

Resampling an existing recording at a higher rate computes extra values from stored samples. It does not make new measurements of the original source or recover detail already lost during capture.

Core explanation · Exam essentials

  • Sampling rate specifies samples per second per channel and controls time spacing.
  • At fixed duration, resolution and channel count, raw sound size is proportional to rate.
  • Upsampling an existing recording cannot restore uncaptured source information.
Optional extension · Too few samples

A rapid change can occur between sample times and leave little evidence in the stored values. Raising the capture rate may reduce that ambiguity. A full treatment of frequency limits, filtering and aliasing belongs to a later signal-processing course.

Common misconception

Sampling rate is samples per second; it is not the number of bits used for each sample.

Check your understanding

Does upsampling recover sound information that was never captured?

Check your answer

No. Interpolated values are not new measurements of the original analogue source.

Sampling resolution

S1.10.A04

Visual overview

Change amplitude precision independently of timing

Sampling resolution is the number of bits used for each amplitude sample. With n bits there are 2ⁿ codes and therefore up to 2ⁿ distinguishable levels. Keep the amplitude range and sample times fixed to isolate the effect of resolution.

Explain the accuracy improvement precisely

Both models cover the same input amplitude range −4 to +4, with allowed reconstruction levels explicitly shown. Smaller gaps between levels can reduce quantisation error; an individual sample can still quantise to the same value at both resolutions. The number and timing of samples do not change.

Connect resolution to capacity and size

Four samples require 4 × 2 = 8 bits at two-bit resolution or 4 × 3 = 12 bits at three-bit resolution. In practical settings, moving from 8 to 16 bits per sample doubles raw size at fixed rate and duration, but increases the number of possible levels from 256 to 65,536.

State the boundary

More bits in an existing file cannot restore amplitude differences previously rounded away. The benefit comes from retaining finer measurements when capturing or preserving higher-precision source data.

Core explanation · Exam essentials

  • n bits per sample supports 2ⁿ amplitude levels.
  • More levels over the same range can reduce quantisation error.
  • At fixed sample count, raw data size is proportional to bits per sample.
Common misconception

Sampling resolution is bits per sample; it is not the number of samples taken each second.

Check your understanding

How many amplitude levels are possible with 12 bits per sample?

Check your answer

2¹² = 4096 levels.

Why files are compressed

S1.11.A01

Visual overview

Same link, fewer bits

File sizeBitsTime at 8,000,000 bits/s

1,000,000 bytes8,000,0001 second

Swipe horizontally to compare every column →

Connect a smaller file to a practical need

Compression represents data using fewer stored bits when the method can exploit its structure or discard acceptable information. Smaller files need less storage and fewer transmitted bits. Compression itself does not increase the physical connection’s bit rate.

Work through a transfer example

Suppose a link carries 8,000,000 bits each second and overhead is ignored. A 2,000,000-byte file contains 16,000,000 bits and needs two seconds. Compressing it to 1,000,000 bytes reduces transfer time to one second at the same link rate. Encoding and decoding may also cost processing time.

Check the trade-off

Compression is useful for limited storage, downloads and streaming. The method must suit the data and whether exact recovery is required. No lossless compressor can guarantee a smaller result for every input; headers, tables or references can outweigh the savings.

Core explanation · Exam essentials

  • Fewer bits can reduce storage and transfer time.
  • The benefit depends on the data, method and overhead.
  • Consider exact recovery as well as size and processing cost.
Optional extension · State a compression ratio convention

Using original size / compressed size, a reduction from 2000 bytes to 1000 bytes is 2:1, with a 50% size saving. Other sources may report compressed/original as 0.5 or 50%; always state the definition. Include all stored overhead when comparing complete files.

Common misconception

Compression means reducing the number of stored bits; it does not automatically mean that information or quality has been lost.

Check your understanding

Why can compression shorten a transfer without changing the connection's bit rate?

Check your answer

Fewer bits need to be transmitted at the same number of bits per second.

Use reversibility as the deciding test

Lossless compression can reproduce every original data value exactly after decoding. Lossy compression discards some source information, so its decoded result is an approximation. Judge the recovery of the original data, not whether a user notices a difference.

Choose a method for a stated purpose

Data and requirementChoiceReason
Source code or text that must remain exactLosslessChanging even one character may alter the meaning or program.

Photograph preview with a tight transfer budgetLossy may be suitableSome fine image information may be sacrificed if the resulting quality is acceptable.

Swipe horizontally to compare every column →

Avoid labels without a mechanism

Lossless does not mean “uncompressed”, and lossy does not mean “always visibly damaged”. A photograph can use either approach. A file extension alone is less useful than a stated encoding method and settings when deciding whether exact recovery is possible.

Core explanation · Exam essentials

  • Lossless decoding restores the original data exactly; lossy decoding cannot restore discarded information.
  • Choose lossless when exactness or an editable master is required.
  • Justify any lossy choice using both the size constraint and acceptable quality.
Common misconception

File type alone does not decide the method; the required reconstruction fidelity and intended use decide whether loss is acceptable.

Check your understanding

Why choose lossless compression for an editable master copy?

Check your answer

Every original value remains available for later editing and new exports.

Run-length encoding (RLE)

S1.11.A03

Visual overview

Define the encoded format

Run-length encoding replaces a consecutive run of identical values with a count and the value. The order of runs must remain unchanged. Here a pair stores an eight-bit count followed by an eight-bit character code; the human-readable notation 4A is shorthand for those two fields.

Worked encode and decode

Source runStored pairDecoder output
AAAA(4, A)AAAA
BB(2, B)BB
CCCCCCCC(8, C)CCCCCCCC
DD(2, D)DD

Swipe horizontally to compare every column →

Complete both directions

Scan AAAABBCCCCCCCCDD from left to right. Count until the value changes, emit that count and value, then start the next run. The result is (4,A), (2,B), (8,C), (2,D). Decoding repeats each value its stated number of times and concatenates the runs, recovering all 16 original characters in the same order.

Count storage under the stated format

InputOriginal costRLE costConclusion
AAAABBCCCCCCCCDD16 × 8 = 128 bits4 × (8 + 8) = 64 bits64 bits saved; size halved.
ABC3 × 8 = 24 bits3 × (8 + 8) = 48 bitsEncoded size doubles.

Swipe horizontally to compare every column →

Keep order and field limits

The counts above exclude any header and assume count/value fields are unambiguous. AAABAA must encode as (3,A), (1,B), (2,A); merging the A runs would move or lose B. An eight-bit unsigned count has maximum 255, so a run of 260 As must split, for example into (255,A), (5,A), under this format.

Transfer the method to bitmap data

RLE is effective for long uniform bitmap runs or other repeated adjacent data. A detailed or noisy image with frequent changes may contain mostly short runs. Its encoded size can grow. If the original pixels use one bit each but each run needs an eight-bit count plus one-bit value, compare with that nine-bit pair cost, not the character example’s sixteen bits.

Core explanation · Exam essentials

  • RLE stores a count and value for each consecutive run and decodes them in order.
  • Count both fields and any supplied overhead when judging savings.
  • Short runs or limited count fields can reduce or reverse the benefit.
Common misconception

RLE groups only adjacent identical values; separated occurrences of the same value belong to different runs.

Check your understanding

Can the two A runs in AAABAA be combined into one RLE run?

Check your answer

No. The intervening B must keep them separate to preserve order.

Complete a numerical sound example

A small sound model contains 12, 12, 12, 12, 13, 13, 9, 9, 9, 9, 9, 9. Store runs (4,12), (2,13), (6,9). With an eight-bit count and eight-bit sample value, the original 12 × 8 = 96 bits becomes 3 × 16 = 48 bits, excluding headers. Expanding the runs exactly restores all twelve values. Real audio often has little adjacent repetition; this example proves the mechanism, not that RLE is generally the best audio compressor.

Distinguish drawing reuse from exact file recovery

For a vector drawing, define one five-point star S with its geometry and fill, then place references to S at (10,20), (40,20) and (70,20). The renderer can reconstruct the three identical objects at those positions. This can reduce repeated object descriptions. It preserves the drawing model and appearance under these assumptions; rewriting the object list does not guarantee restoration of the original file’s byte sequence. Byte-for-byte file compression must preserve that sequence too.

Core explanation · Exam essentials

  • A lossless format must retain everything needed to reverse its encoding.
  • Text references must preserve literals, separators and order as well as repeated strings.
  • For media, state exactly what is reconstructed and account for metadata or reference overhead.
Common misconception

Lossless means exact reconstruction, not that the compressed representation contains fewer bytes for every possible input.

Check your understanding

Must lossless encoding make every input smaller?

Check your answer

No. Dictionary or other overhead can outweigh savings when little repetition exists.

Lossy compression and different file types

S1.11.A02S1.11.A05S1.11.A07S1.11.A08

Visual overview

Irreversible reconstruction

Source valuesStored representativeDecoded values
100, 101, 102, 103102 for each position102, 102, 102, 102

Swipe horizontally to compare every column →

Describe the loss and its purpose

Lossy compression trades exact recovery for a more compact approximation. A codec may discard fine visual differences or parts of an audio signal judged less noticeable. The precise mechanism depends on the method; removing every second sample or merely changing a filename is not a general description of audio compression.

Show why information cannot be recovered

A simple image model maps original grey values 100, 101, 102, 103 to the single stored representative 102. After decoding, all four become 102. The decoder cannot know which pixel was originally 100 or 103. The example demonstrates irreversible value reduction; whether the complete file becomes smaller depends on how the reduced values and metadata are encoded.

Apply the distinction to images and sound

For bitmap photographs, reducing less noticeable fine detail can lower the amount of data needed while retaining acceptable appearance. Stronger loss may create visible artefacts. Lossless bitmap compression instead restores all original pixel codes. For sound, a lossy method may remove or simplify signal information judged less audible; lossless sound compression restores all original digital sample values.

Apply the distinction to text and vectors

Ordinary text and programs normally require exact characters, so lossy alteration is unsuitable. Simplifying a vector drawing by deleting small shapes or reducing coordinate precision also changes its geometry; sharing an unchanged object definition does not itself introduce that loss.

Make a justified choice

Keep a lossless master when future editing matters. Choose a lossy delivery copy only when its size advantage and quality are appropriate to the task. Increasing resolution later cannot reconstruct information that was discarded during compression.

Core explanation · Exam essentials

  • Lossy methods permanently discard some source information.
  • State the kind of detail sacrificed and why the result meets the use case.
  • Exact text, geometry or editable masters require preservation of the relevant source data.
Optional extension · Repeated lossy exports

Editing a decoded lossy copy and encoding it again can introduce further error. Repeatedly copying an unchanged compressed file does not do this: its bytes remain the same. Preserve an appropriate master and make new delivery copies from it.

Common misconception

Lossy decompression does not restore the removed information; it only reconstructs an approximation from the retained data.

Check your understanding

Can decoding a lossy file restore all discarded source information?

Check your answer

No. The loss is permanent; the decoded result is an approximation.

1. Connect sampling resolution to accuracy

Cambridge 9618/12 · October/November 2023 · 6(b) · 3 marks

Selected parts: 6(b) [3].

Reading the question — teacher guidance

Sampling resolution is the number of bits per sample. Explain its effect on representable amplitudes and quantisation; sampling rate is a different variable.

Solution / model answer — teacher-written

Increasing sampling resolution gives each sample more bits. More amplitude levels can therefore be represented, so rounding a measured amplitude to a stored level usually introduces a smaller quantisation error. The digital recording can follow the original amplitude more closely.

Decreasing resolution has the reverse effect: fewer levels, coarser quantisation and potentially greater error.

Official mark scheme
Why this earns marks — teacher explanation

The mark scheme allows points along either causal chain, with a maximum of three marks overall. “More accurate” needs the intermediate mechanism; writing both directions does not double the available marks.

Common mistakes — teacher analysis

More samples per second describes sampling rate. More amplitude levels describes the resolution asked about here.

Summary

Analogue sound and the sampling process

Sampling chooses times; quantisation chooses levels; encoding stores their binary codes. Decode using the same code mapping, width, order and sampling rate. Quantisation and finite sampling limit how closely a recording can represent the analogue source.

Sampling rate

Sampling rate specifies samples per second per channel and controls time spacing. At fixed duration, resolution and channel count, raw sound size is proportional to rate. Upsampling an existing recording cannot restore uncaptured source information.

Sampling resolution

n bits per sample supports 2ⁿ amplitude levels. More levels over the same range can reduce quantisation error. At fixed sample count, raw data size is proportional to bits per sample.

Why files are compressed

Fewer bits can reduce storage and transfer time. The benefit depends on the data, method and overhead. Consider exact recovery as well as size and processing cost.

Lossless and lossy compression compared

Lossless decoding restores the original data exactly; lossy decoding cannot restore discarded information. Choose lossless when exactness or an editable master is required. Justify any lossy choice using both the size constraint and acceptable quality.

Run-length encoding (RLE)

RLE stores a count and value for each consecutive run and decodes them in order. Count both fields and any supplied overhead when judging savings. Short runs or limited count fields can reduce or reverse the benefit.

Lossless compression and different file types

A lossless format must retain everything needed to reverse its encoding. Text references must preserve literals, separators and order as well as repeated strings. For media, state exactly what is reconstructed and account for metadata or reference overhead.

Lossy compression and different file types

Lossy methods permanently discard some source information. State the kind of detail sacrificed and why the result meets the use case. Exact text, geometry or editable masters require preservation of the relevant source data.
