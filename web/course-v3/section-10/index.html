Browse by topic

Choose the values a booking needs

Begin at a school event desk. Describe each fact before choosing its data type, then follow the difference between naming a variable and storing its value.

Keep one booking together in a record

A booking has several related facts with different data types. Define their structure once, create a record variable and read or update one named field at a time.

Locate a value in an array

Turn a row of separate seat requests into one indexed collection. Distinguish an element’s position from its value and count the positions permitted by the declaration.

Process a one-dimensional collection

Keep the values that later operations need. Traverse them forward or backward, distinguish a count from a total and find an extreme without assuming all values are positive.

Use two coordinates for a seating plan

Move from a list to a grid. Use one index for each dimension, trace the nesting of two loops and decide exactly where a total or a count must be reset.

Find a request with linear search

Search an unsorted collection one position at a time. Distinguish a returned position from its stored value, then use a guarded loop to stop safely at a match or at the end.

Build order through adjacent comparisons

Watch one value move through a bubble-sort pass, preserve both values during each swap and then organise complete passes. Finally keep related table values together while sorting.

Save and recover text between program runs

A booking register must survive after the program ends. Choose whether to replace or extend a file, read every line safely and transform records without losing their boundaries.

Describe the rules before choosing the storage

A collection is more than a place to put values. Specify which operations are allowed and what they must do, then distinguish those rules from one possible array implementation.

Undo the latest action with a stack

Use a stack when the next removal must be the latest remaining addition. Follow push and pop, then describe how an array and a top pointer enforce that rule.

Serve waiting requests with a queue

Keep arrival order with separate addition and removal ends. Use a circular array to reuse released positions while keeping front, rear and count consistent.

Follow links instead of neighbouring array positions

Use a short programme of activities to introduce a linked list. A node contains data and a link; follow the links to find logical order, then preserve them during insertion and deletion.

Protect active data and reuse free storage

Review full and empty checks across array implementations. Then follow two linked chains in one array: active nodes and free nodes available for the next insertion.

Combine structures for a complete booking task

Choose a representation for each responsibility. Keep records, seating arrays, waiting requests, undo history and persistent files consistent while explaining why each structure is suitable.
