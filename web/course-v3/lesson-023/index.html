Processor fundamentals · Concept 01

Fetch the instruction, not its operand

Observe

Start with a question

Why does fetching LDD 4 first access address 0 rather than address 4?

PC = 0. Memory[0] holds LDD 4 and Memory[4] holds 18. The CPU must obtain the instruction before it knows which operation and operand it requires.

Explain

Explanation · 1 / 5

Read the arrow

Register-transfer notation describes copying or changing stored values. The destination is on the left of ←. [PC] means the contents of PC. MAR ← [PC] therefore copies the next instruction address from PC into MAR; PC is not emptied.

Explanation · 2 / 5

Select the instruction location

With PC = 0, MAR ← [PC] makes MAR = 0. The address bus selects memory location 0. The CU sends a memory-read signal on the control bus. We are asking for the instruction word stored there.

Explanation · 3 / 5

Read the selected contents

The instruction returns on the data bus into MDR. MDR ← [[MAR]] means read the contents of memory at the address held in MAR. The inner [MAR] supplies address 0; the outer brackets obtain Memory[0]. MDR now contains the encoded instruction displayed as LDD 4.

Explanation · 4 / 5

Retain the instruction and advance the address

CIR ← [MDR] copies the instruction into CIR for decoding. PC ← [PC] + 1 makes PC = 1, the next sequential instruction address in this one-location model. Some transfers can overlap in real implementations, but MDR must receive the instruction before CIR can copy it.

TransferResult in the example
MAR ← [PC]MAR = 0
Read; MDR ← [[MAR]]MDR contains LDD 4
CIR ← [MDR]CIR contains LDD 4
PC ← [PC] + 1PC = 1

Explanation · 5 / 5

Check what has not happened yet

Fetch has obtained LDD 4, but it has not yet loaded 18 into ACC. Reading the data at address 4 belongs to executing that instruction. Keeping these two reads separate explains why one load can require more than one memory access.

Work together

Fetch the second instruction

The first load has finished. PC = 1, ACC = 18 and Memory[1] holds ADD 5.

Work together · 1 / 2

Copy and read

MAR receives 1. A read of Memory[1] puts ADD 5 in MDR; CIR then receives that instruction.

Work together · 2 / 2

Identify the next address

PC becomes 2. ACC is still 18 because fetching ADD 5 has not performed the addition.

After fetch, CIR contains the current instruction and PC identifies the next sequential instruction.

Check

Explain it yourself · Teacher-written

With MAR = 4 and Memory[4] = 18, what is the difference between MDR ← [MAR] and MDR ← [[MAR]]?

Check your reasoning

The first copies the address value 4 into MDR. The second reads memory at that address and puts 18 into MDR.

Apply the idea · Teacher-written practice
Question 1 · Command word: Use4 teacher marks

Use register-transfer notation to show the fetch stage when PC=120 and Memory[120] contains LDD 500. Instructions occupy one address. Include the read control signal and state PC and CIR after the fetch.

S4.07.A02S4.07.A01
Answer and checking points — teacher-written
  1. MAR ← [PC], so MAR becomes 120.
  2. The CU issues a memory-read signal and MDR ← [[MAR]], loading LDD 500.
  3. CIR ← [MDR], so CIR contains LDD 500.
  4. PC ← [PC] + 1, so PC becomes 121; the increment may overlap other fetch transfers.

Common error: Fetch transfers the instruction to CIR, not to PC.

Connect

Keep this idea

Fetch: PC → MAR; memory read → MDR; MDR → CIR; advance PC.

Decoding now identifies the operation, and execution makes the required state change.

Check a common misunderstanding

PC holds an instruction address. Fetching a load instruction does not itself load the data operand into ACC.

Processor fundamentals · Concept 02

Decode, execute, then fetch again

Observe

Start with a question

What changes when the current instruction is a load, an add or a store?

The calculation uses the same fetch pattern three times, but each fetched instruction asks for a different action. Predict whether execution will read memory, calculate or write memory.

Explain

Explanation · 1 / 5

Decode the operation and operand

The CU decodes the instruction held in CIR. The operation code, or opcode, identifies the operation. The operand supplies a value, an address or other information required by that operation. In LDD 4, LDD identifies load-direct and 4 identifies the data location.

Explanation · 2 / 5

Execute the load

After fetching LDD 4, MAR receives 4. A memory-read signal causes MDR to receive 18 from that location. ACC ← [MDR] then makes ACC = 18. PC remains 1. This operand read follows the separate instruction read from address 0.

Explanation · 3 / 5

Execute the addition

After fetching ADD 5, MAR receives 5 and a read places 24 in MDR. The ALU adds the two values: ACC ← [ACC] + [MDR], giving 42. PC is now 2. The original values in memory remain available.

Explanation · 4 / 5

Execute the store

After fetching STO 6, MAR receives 6 and MDR ← [ACC] places 42 in MDR. The data bus carries 42 towards memory and a write signal stores it: [[MAR]] ← [MDR]. Memory[6] becomes 42. Fetching STO was a read; executing it is a write.

Explanation · 5 / 5

Choose the next action

Normally the next fetch uses the advanced PC. A jump instruction can replace PC with another target during execution. In the basic interrupt model, the CPU checks for pending enabled requests at the boundary after the current instruction; the following unit explains this. END finishes our program and returns control to the operating system, the software that manages running programs.

Why must STO 6 first read memory even though its purpose is to write?

Check your reasoning

The processor first reads the instruction STO 6 from its instruction address. After decoding it, execution writes ACC to data address 6.

Apply the idea · Teacher-written practice
Question 1 · Command word: Describe4 teacher marks

Describe the decode and execute stages for CIR=STO 510 and ACC=36. Use register-transfer notation for the memory write and state whether the ACC changes.

S4.07.A01S4.07.A02
Answer and checking points — teacher-written
  1. The CU decodes STO as a store operation with destination address 510.
  2. MAR ← 510 and MDR ← [ACC], so MDR becomes 36.
  3. The CU issues a write signal and [[MAR]] ← [MDR], placing 36 at address 510.
  4. ACC remains 36; storing copies its contents to memory.

Common error: A memory write uses MDR as the transferred value, not as the destination address.

Question 2 · Command word: Explain3 teacher marks

Explain the error in the proposed fetch transfer PC ← [MDR]. Give the correct instruction destination and explain when a different value may legitimately be loaded into PC.

S4.07.A01S4.07.A02
Answer and checking points — teacher-written
  1. During fetch, MDR contains the instruction read from memory, not normally the next instruction address.
  2. Use CIR ← [MDR] to retain that instruction for decoding.
  3. An executed jump may load its target address into PC to change instruction order.

Common error: Do not confuse a branch during execution with the standard fetch transfers.

Original question · Cambridge 9618/13

1. Translate descriptions into register-transfer notation

Cambridge 9618/13 · May/June 2023 · 7(c) · 2 marks

Selected parts: 7(c) [2].

Teacher solution and explanation

An arrow means assignment. Square brackets mean contents, so reading memory via an address held in MAR needs two levels of contents.

StageRegister-transfer notation
Increment PCPC ← [PC] + 1
Read the memory location addressed by MAR into MDRMDR ← [[MAR]]

The inner [MAR] is the stored address. The outer brackets mean the contents of memory at that address.

Each correctly written transfer earns one mark. The second notation expresses a memory read rather than copying the address itself.

MDR ← [MAR] copies the address value, not the memory contents requested. PC ← 1 overwrites the counter instead of incrementing it.

Original question · Cambridge 9618/13

2. Explain MAR and MDR through instruction fetch

Cambridge 9618/13 · October/November 2025 · 6(b) · 4 marks

Selected parts: 6(b) [4].

Hint — reading the question

Connect the two registers to the fetch-execute sequence. Give the source of the address and the destination of the fetched instruction.

Reasoning and model answer — teacher-written

MAR holds the address of the memory location to be read or written. During instruction fetch it receives the next instruction address from PC. The instruction at that memory address is read into MDR. It then passes from MDR to CIR for decoding and execution. When executing a data read/write, MAR and MDR carry the required operand address and transferred value.

Official mark scheme
Why this earns marks — teacher explanation

The four listed points are the MAR role, the address from PC, the MDR role and passing the instruction to CIR. The final sentence distinguishes operand access from instruction fetch; it does not add marks.

Common mistakes — teacher analysis

Do not say that the operand address always comes from PC: the PC supplies the instruction address during fetch. MDR does not select a memory location.
