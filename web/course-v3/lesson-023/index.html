01

Fetch using register-transfer notation

S4.07.A01S4.07.A02

Visual overview

In this notation [PC] means the contents of PC, while [[MAR]] means the contents of the memory location whose address is in MAR. Thus MAR ← [PC] copies an address; MDR ← [[MAR]] reads the selected memory contents. The left arrow copies a value to its destination.

The fetch selects the current instruction address before advancing PC. In this teaching sequence, copy PC into MAR, issue a memory read and receive the instruction in MDR, copy it into CIR, then advance PC by one and decode CIR. Some internal transfers can overlap on real processors; the address must still identify the intended instruction.

Fetching LDD 4 reads the instruction at address 0. Executing it then reads the data at address 4. Those are two separate memory reads. Fetching STO 6 still reads its instruction; only its execution writes the result to memory.

Worked example · Fetch the first instruction of the calculation

  1. Given

    PC=0, ACC=0, IX=0. Memory[0]=LDD 4 and Memory[4]=18. MAR, MDR and CIR will be overwritten; the comparison result is unset.

  2. Select and read

    MAR ← [PC] gives 0. The address bus selects 0; the CU sends read. MDR ← [[MAR]] receives the encoded LDD 4 instruction on the data bus.

  3. Retain and advance

    CIR ← [MDR] retains LDD 4; PC ← [PC]+1 gives 1. The CU decodes LDD. ACC is still 0: the data at address 4 has not been loaded yet.

Core explanation · Exam essentials

  • MAR ← [PC]; read into MDR; CIR ← [MDR]; advance PC; decode CIR. Distinguish register contents from memory contents.
Common misconception

There is no MDR → PC instruction transfer in the standard fetch sequence.

Check your understanding

What does [[MAR]] mean when MAR=700?

Check your answer

The value stored in memory location 700, not the number 700 itself.

02

Decode, execute and select the next instruction

S4.07.A01S4.07.A02

Visual overview

Decoding identifies the operation and interprets its operand. The CU then coordinates the transfers and ALU operation required for execution. Execution depends on the instruction: a load reads data, a store writes data, arithmetic calculates a result, and a jump changes the next instruction address.

The PC's sequential increment is not a guarantee that the next instruction will be adjacent. A taken branch can replace PC during execution. At the end of the cycle the processor checks for pending enabled interrupts before continuing the normal instruction sequence.

A decoded instruction tells the CU which transfers to arrange. LDD 4 uses MAR ← 4, a read into MDR, then ACC ← [MDR]. ADD 5 reads another operand and uses ACC ← [ACC]+[MDR]. STO 6 uses MAR ← 6, MDR ← [ACC], and a write [[MAR]] ← [MDR].

Between these execution steps, the processor fetches each next instruction. The table records state after each whole instruction, so the MAR/MDR values shown are their last values for that instruction, not all intermediate transfers. The diagram separates instruction reads from operand reads and the final write.

After fetching JMP 40 from address 9, PC first becomes 10. Executing the jump replaces it with 40, so the next fetch is from 40. A trace’s “next PC” is the value after execution. END transfers control to the operating system; it does not execute the adjacent data.

Worked example · Supplied program and initial state

  1. Conditions

    Initial ACC=0, IX=0, PC=0; comparison result unset. Memory[4]=18, Memory[5]=24, Memory[6]=0. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

Worked example · Read, calculate, write and finish

  1. Load

    Fetch address 0, then read Memory[4]=18 into ACC.

  2. Add

    Fetch address 1, then read Memory[5]=24; ACC becomes 42.

  3. Store

    Fetch address 2, put 6 in MAR and 42 in MDR, and issue write. Memory[6] becomes 42 while ACC stays 42.

  4. End

    Fetch address 3 and execute END. IX stays 0 and source data 18 and 24 are unchanged. No input or character output is involved.

Core explanation · Exam essentials

  • Execution depends on the opcode: load reads into ACC, arithmetic uses an operand, store writes through MDR, and a jump replaces PC.
Common misconception

Fetching an instruction is separate from fetching a data operand needed to execute it.

Check your understanding

Why can a load instruction require two memory reads in one complete cycle?

Check your answer

One fetches the instruction; the other reads the data at its operand address.

Practice questions

Question 1 · Command word: Use4 marks

Use register-transfer notation to show the fetch stage when PC=120 and Memory[120] contains LDD 500. Instructions occupy one address. Include the read control signal and state PC and CIR after the fetch.

S4.07.A02S4.07.A01
Answer and marking points
  1. MAR ← [PC], so MAR becomes 120.
  2. The CU issues a memory-read signal and MDR ← [[MAR]], loading LDD 500.
  3. CIR ← [MDR], so CIR contains LDD 500.
  4. PC ← [PC] + 1, so PC becomes 121; the increment may overlap other fetch transfers.

Common error: Fetch transfers the instruction to CIR, not to PC.

Question 2 · Command word: Describe4 marks

Describe the decode and execute stages for CIR=STO 510 and ACC=36. Use register-transfer notation for the memory write and state whether the ACC changes.

S4.07.A01S4.07.A02
Answer and marking points
  1. The CU decodes STO as a store operation with destination address 510.
  2. MAR ← 510 and MDR ← [ACC], so MDR becomes 36.
  3. The CU issues a write signal and [[MAR]] ← [MDR], placing 36 at address 510.
  4. ACC remains 36; storing copies its contents to memory.

Common error: A memory write uses MDR as the transferred value, not as the destination address.

Question 3 · Command word: Explain3 marks

Explain the error in the proposed fetch transfer PC ← [MDR]. Give the correct instruction destination and explain when a different value may legitimately be loaded into PC.

S4.07.A01S4.07.A02
Answer and marking points
  1. During fetch, MDR contains the instruction read from memory, not normally the next instruction address.
  2. Use CIR ← [MDR] to retain that instruction for decoding.
  3. An executed jump may load its target address into PC to change instruction order.

Common error: Do not confuse a branch during execution with the standard fetch transfers.

Question 4 · Command word: Describe4 marks

The supplied calculation starts with Memory[6]=0. Describe the operand transfers for ADD 5 and the write transfers for STO 6, then state the final memory and ACC values.

Initial ACC=0, IX=0, PC=0; comparison result unset. Memory[4]=18, Memory[5]=24, Memory[6]=0. No input is needed. Addresses are denary; each listed instruction or data item occupies one location.

000  LDD 4
001  ADD 5
002  STO 6
003  END
S4.07.A01S4.07.A02
Answer and marking points
  1. After fetching ADD 5, MAR=5 and a read gives MDR=24.
  2. The ALU combines ACC=18 with 24 and ACC becomes 42.
  3. STO 6 sets MAR=6 and MDR=42 and uses a memory-write signal.
  4. Memory[6]=42 and ACC=42 at termination; Memory[4]=18 and Memory[5]=24 remain unchanged.

Common error: Fetching STO is a read; executing it is a write.

Question 1 · Command word: Use · 5 marks

Use register-transfer notation to fetch the instruction ADD 710 from address 88. PC initially contains 88 and instructions occupy one location. Explain how Memory[710]=9 is then added to ACC=4 during execution.

Answer and marking points
  • MAR ← [PC] selects location 88; a read signal causes MDR ← [[MAR]].
  • CIR ← [MDR] retains ADD 710, and PC ← [PC] + 1 gives 89.
  • The CU decodes ADD and sets MAR ← 710 for the operand read.
  • After the read signal, MDR ← [[MAR]] supplies operand 9.
  • ACC ← [ACC] + [MDR] produces 13.

Common error: Fetching ADD 710 and reading its operand require separate memory reads.

Question 2 · Command word: Describe · 4 marks

Describe what happens after JMP 450 has been fetched from location 90. Explain why a trace may show PC=91 during fetch but PC=450 after execution.

Answer and marking points
  • Sequential fetch advances the address with PC ← [PC] + 1, giving 91.
  • The CU decodes the current instruction as an unconditional jump.
  • Execution loads the target with PC ← 450.
  • The next fetch uses address 450 rather than 91.

Common error: A PC increment does not prevent a later jump from replacing the next address.

Question 3 · Command word: Explain · 4 marks

Explain why this proposed memory-write notation is wrong: MAR ← [ACC]; [[MDR]] ← 620. Give the correct transfers for storing ACC=58 at address 620 and identify the control signal.

Answer and marking points
  • MAR must hold the destination address, so use MAR ← 620.
  • MDR must hold the transferred value, so use MDR ← [ACC] to copy 58.
  • Use [[MAR]] ← [MDR] to store 58 in the selected location.
  • The CU issues a memory-write signal on the control bus.

Common error: An address belongs in MAR and the value being written belongs in MDR.

04

Lesson review

Summary

Fetch

Copy the next address to MAR, read the instruction through MDR to CIR, and advance PC.

Decode/execute

The CU identifies the operation and coordinates its required transfers or ALU work.

Control flow

A jump can replace the sequential PC; interrupt checking follows the current instruction.
