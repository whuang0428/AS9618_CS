Post-condition and pre-condition loops

Place condition tests correctly and distinguish stopping from continuing.

Does REPEAT ... UNTIL Valid repeat when Valid becomes TRUE?

Check your answer

No. TRUE ends repetition; FALSE starts another iteration.

01

Use a post-condition REPEAT loop

S11.04.A05

Visual overview

A post-condition loop executes its body before testing, so the body runs at least once.

Read the REPEAT rules

  • Syntax: Write REPEAT, the body, then UNTIL Condition. There is no ENDREPEAT.
  • TRUE: Stop and continue after the loop.
  • FALSE: Return to the body for another iteration.

Apply the rule to validation

Read Mark inside the body and accept it when (Mark >= 0) AND (Mark <= 100). An invalid integer triggers another input. This example assumes integer input: the range test does not itself handle text instead of a number.

State what makes the loop finish

The condition uses the value just obtained in the body. If the first input is 0, both comparisons are true on the first test and only one read occurs. If no valid integer is ever supplied, the program continues requesting input; a stopping guarantee would need an additional attempt limit.

Keep validation within its stated purpose

A range check establishes whether an integer is allowed; it does not establish whether the original real-world mark was entered accurately. Nor does this integer-input example handle text typed in place of a number.

Worked example · Read a mark in the inclusive range

  1. Pseudocode
    DECLARE Mark : INTEGER
REPEAT
    INPUT Mark
UNTIL (Mark >= 0) AND (Mark <= 100)
OUTPUT Mark
  2. Trace and check

    Inputs -1, 101, 100 lead to three reads and output 100. Input 0 is accepted on the first attempt.

Core explanation · Exam essentials

  • REPEAT executes before testing; UNTIL TRUE ends repetition.
  • Obtain a fresh attempt inside the loop and make the stopping condition express acceptance.
Common misconception

UNTIL states when to stop, so a validity test is not negated here.

Check your understanding

How many reads occur when the first Mark is 0?

Check your answer

One; the valid first input ends repetition.

02

Use a pre-condition WHILE loop

S11.04.A04

Visual overview

A pre-condition loop tests before the body; the body may run zero times.

Read the WHILE rules

  • Syntax: Write WHILE Condition, the indented body and ENDWHILE. Do not add DO to the header.
  • TRUE: Execute the body, then return to the condition.
  • FALSE: Skip the body and continue after ENDWHILE.

Initialise and update the condition

Read Value before the first test so it is defined. While Value <> -1, add it and read again. The sentinel is not added: a first input of -1 leaves Total at zero.

Separate a stopping signal from a data value

A sentinel is a value reserved to signal the end. This task permits integers other than -1 as data, including zero; if -1 itself needed to be ordinary data, the input contract would need another ending mechanism. Read the next value on every processed path, even when a later version filters some data out.

Connect the loop form without confusing input sources

For text files, the comparable pre-condition is NOT EOF before READFILE, as in Lesson 065. The keyboard priming input used here should not be copied blindly into a file algorithm: an empty file must be checked before its first read.

Worked example · Total integers until a sentinel

  1. Pseudocode
    DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
WHILE Value <> -1
    Total <- Total + Value
    INPUT Value
ENDWHILE
OUTPUT Total
  2. Trace and check

    Inputs 3, 4, -1 output 7. Input -1 alone outputs 0.

Core explanation · Exam essentials

  • WHILE tests before the body and may execute zero times.
  • Define the condition data before the first test and update it on every continuing path.
Common misconception

A missing fresh input can keep the condition unchanged indefinitely.

Check your understanding

Why is the first INPUT before WHILE?

Check your answer

The initial test needs a defined Value, and a first sentinel must allow zero body executions.

Check condition meaning

WHILE Valid continues on TRUE; UNTIL Valid stops on TRUE. Moving the same condition between loop forms can therefore reverse the behaviour.

Preserve the first-iteration rule

Negating the condition alone does not preserve a zero-iteration path. Check the allowed inputs; an outer decision may be needed before REPEAT to preserve a WHILE loop's original behaviour.

Preserve a sentinel algorithm when changing the loop form

  1. Read first: Read Value before either form so the first sentinel can mean no data.
  2. Guard REPEAT: Only enter REPEAT when Value <> -1; this preserves the zero-body path.
  3. Process and update: Add the current data value, then obtain the next one.
  4. Reverse the test meaning: UNTIL Value = -1 ends processing. Both programs output Total once afterwards.

Compare observable behaviour

The complete alternative below consumes the same inputs and reports the same totals as the WHILE example. Negating the condition is only one part of the conversion: the first-execution rule, input placement and final output must also be preserved.

Worked example · Preserve the empty-input path with a guard

  1. Requirements and starting conditions

    Integers other than -1 are data; -1 is the sentinel and may be the first input. Sum data and output one total.

  2. Cambridge pseudocode
    DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
IF Value <> -1 THEN
    REPEAT
        Total <- Total + Value
        INPUT Value
    UNTIL Value = -1
ENDIF
OUTPUT Total
  3. Expected result

    3, 4, -1 gives 7; -1 alone gives 0; 0, -1 gives 0. The sentinel is never added.

Core explanation · Exam essentials

  • WHILE TRUE continues; UNTIL TRUE stops.
  • Changing loop form must preserve the zero-iteration path, data updates and output placement.
Common misconception

Negating the condition alone does not preserve a WHILE loop's empty-input case.

Check your understanding

For non-negative Count, can REPEAT OUTPUT Count; Count <- Count - 1 UNTIL Count = 0 replace a countdown WHILE for Count 0?

Check your answer

No. It executes at zero, decrements to -1 and never reaches zero by further decrements.

Question 1 · Command word: Write2 teacher marks

Write a REPEAT loop to read an integer Rating until it is from 1 to 5 inclusive. State the number of inputs for 0, 6 and 5.

S11.04.A05
Answer and checking points — teacher-written

One valid solution to the requested statements

REPEAT
    INPUT Rating
UNTIL (Rating >= 1) AND (Rating <= 5)
  1. Place INPUT Rating between REPEAT and UNTIL (Rating >= 1) AND (Rating <= 5).
  2. Three inputs are read before the valid 5 ends repetition.

Common error: UNTIL should be true for an accepted rating.

Question 2 · Command word: Calculate2 teacher marks

Calculate the output of the supplied sentinel total for 2, 0, 5 and -1. State why the final input is excluded.

Use this complete program for the stated task.

DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
WHILE Value <> -1
    Total <- Total + Value
    INPUT Value
ENDWHILE
OUTPUT Total
S11.04.A04
Answer and checking points — teacher-written
  1. The final total is 7.
  2. Value -1 makes the pre-condition false before its addition can execute.

Common error: Zero is ordinary data here; only -1 is the sentinel.

Question 3 · Command word: Explain3 teacher marks

Explain the purpose of the outer IF in the supplied REPEAT version of the sentinel total. State the output for first input -1. Describe the change in behaviour if the guard is removed while the body still adds Value before reading the next input.

Use this complete program and the stated inputs.

DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
IF Value <> -1 THEN
    REPEAT
        Total <- Total + Value
        INPUT Value
    UNTIL Value = -1
ENDIF
OUTPUT Total
S11.04.A04S11.04.A05
Answer and checking points — teacher-written
  1. The outer IF preserves the zero-data path by skipping REPEAT when the first Value is -1.
  2. With the guard, Total remains 0 and the program outputs 0 without a second input.
  3. Without it, the first sentinel would be added and another input requested before the UNTIL test, changing both processing and input consumption.

Common error: A stopping-condition negation alone does not preserve the first-execution rule.

Original question · Cambridge 9618/22

1. Stop input at a sentinel or a full array

Cambridge 9618/22 · October/November 2025 · 2 · 5 marks

Selected parts: 2 [5].

Reading the question — teacher guidance

The sentinel 99.9 is not stored. Stop after the twentieth ordinary value without requesting a twenty-first value.

Solution / model answer — teacher-written

Start at Index = 1. Check the sentinel before storing. After storing an ordinary value, increment Index; end when it becomes 21. If the first input is 99.9, no array element changes.

Official mark scheme
Why this earns marks — teacher explanation

The five points cover index initialisation, repeated input, the sentinel stop, the capacity stop, and storing with index advancement. Both official flowchart alternatives are included below. The second official diagram requests another input before testing Index = 21; the teacher diagram checks capacity immediately after storing, so it needs no twenty-first input.

Common mistakes — teacher analysis

Testing the sentinel only after storage violates an explicit condition. Testing for Index = 20 before storing can allow only 19 values.
