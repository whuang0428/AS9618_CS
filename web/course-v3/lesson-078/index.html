Program a booking system · Concept 16

Check before processing the next request

Observe

Two possible streams

  • Requests then stop: 3, 2, 4, 0
  • Stop immediately: 0
  • Only positive quantities are ordinary requests in this task.

Look, then discuss

How can a stream end before any booking has been processed?

The desk reads positive seat requests until the integer 0 signals the end. Compare the streams 3, 2, 4, 0 and just 0. The stopping marker is not a booking.

Recall

Recall a sentinel

A sentinel is a special value that marks the end of input. Its meaning comes from the stated task. Here 0 ends the stream; in another task 0 could be ordinary data.

Explain

Explanation · 1 / 3

Obtain the first value before testing it

INPUT Seats before WHILE supplies the value used by the first condition. WHILE Seats <> 0 means continue while the value is not the sentinel.

Explanation · 2 / 3

Process only after a TRUE test

When Seats is 0, the body is skipped. If that happens on the first test, the body executes zero times and Total remains 0.

Explanation · 3 / 3

Read the next value inside the body

After adding the current request, read another Seats value. ENDWHILE returns to the condition. Omitting this input can leave Seats unchanged and cause endless repetition.

DECLARE Seats, Total : INTEGER
Total <- 0
INPUT Seats
WHILE Seats <> 0
    Total <- Total + Seats
    INPUT Seats
ENDWHILE
OUTPUT Total

Work together

Trace the marker before the addition

Input 3, 2, 4, 0.

Work together · 1 / 2

Follow the ordinary values

Tests on 3, 2 and 4 are TRUE. The additions produce totals 3, 5 and 9.

Work together · 2 / 2

Follow the exit

The next INPUT stores 0. The next test is FALSE, so no addition occurs and OUTPUT displays 9. If the first input is 0, OUTPUT displays 0.

A pre-condition loop can process no data, because its condition is tested before the body.

Experiment

Predict the final total and whether the first body executes. Compare requests 3, 2, 4, 0 with the immediate sentinel 0. Locate the input that changes the next continuation test.

Read requests until the sentinel

Try 0 first. It stops the loop without adding to Total. Values after the first 0 remain unread.

Change inputs / prepared constants

Changing a field does not execute code. Prepare validates the fields and starts a new trace. Reset restores the original example.

Obtain an attempt before checking it

Observe

Validate one booking quantity

AttemptSeatsAcceptable?
10FALSE
27FALSE
33TRUE

Look, then discuss

How can the desk keep asking until the seat quantity is from 1 to 6?

A user tries 0, then 7, then 3. The first two attempts are outside the allowed interval. Only the final 3 may become an accepted booking.

Recall

Recall a range condition

A quantity is inside 1 to 6 inclusive when (Seats >= 1) AND (Seats <= 6). Assume the input operation supplies integers; checking whether typed text can be converted to an integer is outside this example.

Explain

Explanation · 1 / 3

Perform the required first attempt

REPEAT begins the body immediately. INPUT Seats supplies a value before the program tries to test it. This post-condition loop executes its body at least once.

Explanation · 2 / 3

Stop when the UNTIL condition is TRUE

UNTIL (Seats >= 1) AND (Seats <= 6) expresses the acceptance condition. FALSE repeats the body; TRUE ends the loop. This is the opposite polarity from WHILE.

Explanation · 3 / 3

Use the accepted value after the loop

Place the booking calculation or update after UNTIL so rejected attempts do not affect totals.

DECLARE Seats : INTEGER
REPEAT
    OUTPUT "Enter seats from 1 to 6"
    INPUT Seats
UNTIL (Seats >= 1) AND (Seats <= 6)
OUTPUT "Accepted seats: ", Seats

Work together

Separate attempts from accepted data

Execute with attempts 0, 7, 3.

Work together · 1 / 2

Test each attempt

For 0 the lower comparison fails; for 7 the upper comparison fails. The body repeats after both. For 3 both are TRUE, so the loop stops.

Work together · 2 / 2

Read the final state

There were three inputs but one accepted booking quantity. Seats retains 3 and the final result output reports the accepted value.

Validation retries obtain a replacement attempt; they do not automatically create additional bookings.

Program a booking system · Concept 18

Match the test position and its meaning

Observe

Two loop contracts

StructureTest positionTRUE meansMinimum body executions
WHILEBefore bodyContinue0
REPEAT … UNTILAfter bodyStop1

Look, then discuss

Does changing WHILE to UNTIL without changing the condition preserve a program?

For a booking quantity, “still invalid” and “now valid” are opposite questions. One condition permits another attempt; the other ends the attempts.

Recall

Recall complement conditions

The complement of (Seats >= 1) AND (Seats <= 6) is (Seats < 1) OR (Seats > 6). Both comparison boundaries and the connecting operator change.

Explain

Explanation · 1 / 3

Write the required stopping event in words

For validation, stop when the value is valid. A REPEAT loop directly uses that stopping condition; a WHILE loop needs the continuation condition that the value is invalid.

Explanation · 2 / 3

Provide a value before a pre-condition test

A WHILE version must read the first attempt before testing it, then read replacements in the body. It can implement the same validation task, but needs different setup.

DECLARE Seats : INTEGER
OUTPUT "Enter seats from 1 to 6"
INPUT Seats
WHILE (Seats < 1) OR (Seats > 6)
    OUTPUT "Try again"
    INPUT Seats
ENDWHILE
OUTPUT Seats

Explanation · 3 / 3

Check whether zero processed items are possible

A sentinel can be the first input. A bare REPEAT that adds a value before checking the sentinel would wrongly process it once. Add a suitable guard or use WHILE; changing only the keyword is insufficient.

Work together

Compare the same validation stream

Use 0, 7, 3 with the WHILE program above and the earlier REPEAT program.

Work together · 1 / 2

Compare consumed values

Both programs read three attempts and retain 3. The WHILE body runs twice because the initial input is outside it; the REPEAT body runs three times.

Work together · 2 / 2

State the comparison precisely

The accepted value and number of inputs agree. The shown prompt text differs, so the two displayed message sequences are not identical. Specify which required behaviour is being compared.

Equivalent input processing does not imply identical body counts or identical display messages.

Check

Try it yourself · Teacher-written

For WHILE NOT Finished and REPEAT … UNTIL Finished, what does Finished = TRUE mean?

Check your reasoning

It prevents entry to another WHILE body and ends the REPEAT loop after its current body. The test positions remain different.

Write a REPEAT loop to read an integer Rating until it is from 1 to 5 inclusive. State the number of inputs for 0, 6 and 5.

Answer and checking points — teacher-written

One valid solution to the requested statements

REPEAT
    INPUT Rating
UNTIL (Rating >= 1) AND (Rating <= 5)
  1. Place INPUT Rating between REPEAT and UNTIL (Rating >= 1) AND (Rating <= 5).
  2. Three inputs are read before the valid 5 ends repetition.

Common error: UNTIL should be true for an accepted rating.

Question 2 · Command word: Calculate2 teacher marks

Calculate the output of the supplied sentinel total for 2, 0, 5 and -1. State why the final input is excluded.

Use this complete program for the stated task.

DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
WHILE Value <> -1
    Total <- Total + Value
    INPUT Value
ENDWHILE
OUTPUT Total
S11.04.A04
Answer and checking points — teacher-written
  1. The final total is 7.
  2. Value -1 makes the pre-condition false before its addition can execute.

Common error: Zero is ordinary data here; only -1 is the sentinel.

Question 3 · Command word: Explain3 teacher marks

Explain the purpose of the outer IF in the supplied REPEAT version of the sentinel total. State the output for first input -1. Describe the change in behaviour if the guard is removed while the body still adds Value before reading the next input.

Use this complete program and the stated inputs.

DECLARE Value, Total : INTEGER
Total <- 0
INPUT Value
IF Value <> -1 THEN
    REPEAT
        Total <- Total + Value
        INPUT Value
    UNTIL Value = -1
ENDIF
OUTPUT Total
S11.04.A04S11.04.A05
Answer and checking points — teacher-written
  1. The outer IF preserves the zero-data path by skipping REPEAT when the first Value is -1.
  2. With the guard, Total remains 0 and the program outputs 0 without a second input.
  3. Without it, the first sentinel would be added and another input requested before the UNTIL test, changing both processing and input consumption.

Common error: A stopping-condition negation alone does not preserve the first-execution rule.

Question 4 · Command word: Compare2 teacher marks

Compare the minimum number of body executions of WHILE and REPEAT, and explain what a TRUE condition means in each.

S11.04.A04S11.04.A05
Answer and checking points — teacher-written
  1. WHILE may run zero times and a TRUE condition permits the next body execution.
  2. REPEAT runs at least once and a TRUE UNTIL condition ends repetition.
