Run-length encoding and dictionary-style compression

Lesson 013 | 45 minutes | Informal questioning

Compression likes patterns. Randomness is less polite.

This lesson shows two lossless compression ideas: run-length encoding stores repeated runs as count plus value, while dictionary-style compression replaces repeated patterns with shorter references.

Teaching cue

Make students count runs aloud. Most mistakes come from one run too many or one run too few.

Why this matters

Cambridge questions often test the mechanism, not just the name of the compression method.

Common trap

RLE can make alternating data larger because every short run still needs a count and value.

Warm-up hook

Which string is most suitable for RLE?

Pick an answer. RLE likes long repeated runs, not a keyboard having a restless day.

Knowledge point 1

Run-length encoding

Encoding rule

Replace each consecutive run with `count + value`.

`AAAAAABBBBCCCCCCCC → 6A4B8C`

Decoding rule

Expand each count and value back into repeated data.

`3A2B1C → AAABBC`

Chinese support: run = 连续重复段；encode = 编码；decode = 解码。

Knowledge point 2

Dictionary-style compression

Idea

Find repeated patterns and store them once in a dictionary.

Reference

Replace later occurrences with a shorter code or pointer to the dictionary entry.

Example

`COMPUTER COMPUTER COMPUTER` can store `COMPUTER` once, then use references.

Dictionary`#1 = COMPUTER`
Compressed form`#1 #1 #1`
Decoded form`COMPUTER COMPUTER COMPUTER`

Knowledge point 3

When does it help?

RLE helps

Long repeated runs, simple graphics, repeated pixels or repeated characters.

RLE struggles

Alternating or random-looking data with very short runs.

Dictionary helps

Repeated words, phrases, byte patterns or sequences across the file.

Both methods are lossless if the dictionary and encoded data allow exact reconstruction.

Fix the run count

`AAAAAABBBBCCCCCCCC → 5A4B8C`

There are six `A` characters, so the correct encoding is `6A4B8C`.

“RLE is always smaller because it is compression.”

RLE can be larger for data such as `ABABAB`, because each short run needs its own count and value.
