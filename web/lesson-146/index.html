Why this matters

Mixed Section 12 questions punish generic answers. The same case study can ask for requirements in one part and evaluation in the next.

Common trap

Do not write the lifecycle as a memorised list. Marks come from selecting the right stage and explaining it in the scenario.

Which mental toolbox should open first?

Case study

School activity sign-up system

A school wants a system for students to sign up for after-school activities. Students can view activities, reserve a place, cancel a reservation and see a waiting list. Staff can create activities, set capacity, view registers and close sign-ups. The school wants the system ready before the new term.

Every review task on this page uses this case. That forces answers to be specific instead of floating around as textbook fog.

Design review

Design answers must name the artefact

Algorithm

Describe how the system checks capacity and places extra students on a waiting list.

Data dictionary

Define ActivityID, StudentID, Capacity, PlacesTaken and WaitingListPosition.

Interface

Show activity list, reserve/cancel controls, confirmation prompts and validation messages.

Cambridge-style pseudocode is suitable for algorithm design. Java can support implementation practice, but final code is not the whole design document.

Maintenance and evaluation review

After release, classify changes and judge success with evidence

Maintenance examples

  • Corrective: fix a crash when cancelling a reservation.
  • Adaptive: change the system for a new two-term activity structure.
  • Perfective: make the activity search faster or clearer.

Evaluation evidence

  • Timing logs from sign-up tasks.
  • User survey results linked to success criteria.
  • Test records showing capacity rules were met.

Homework

Complete one full Section 12 case-study response pack

  1. Write three requirements and two measurable success criteria for the activity sign-up system.
  2. Create one data dictionary entry and one algorithm outline for the waiting-list feature.
  3. Write four test cases for capacity, including normal, boundary and abnormal data.
  4. Answer one 6-mark evaluation question using evidence and a clear judgement.
Marking focus: precise Section 12 vocabulary, case-specific examples, and no unsupported “better/easier/faster” claims.
