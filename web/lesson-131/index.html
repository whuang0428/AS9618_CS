Does the subroutine get a copy, or the original?

A parameter can receive a copied value, or it can be linked to the caller's variable using BYREF. That one word decides whether a change inside the procedure survives after the call. In other words, this is the lesson where a variable can leave the room and come back wearing a new value.

Why this matters

Paper 2 questions often test whether a procedure updates data outside itself, especially in trace and debug tasks.

Common trap

Changing a parameter inside a procedure does not automatically change the argument. It only does that with BYREF.

Parameter and argument

The header names the parameter. The call supplies the argument.

Chinese support: parameter 参数, argument 实参, procedure 过程, caller 调用者。

Parameter in the procedure header

PROCEDURE DisplayMessage(Message : STRING)
    OUTPUT Message
ENDPROCEDURE

Message is the parameter. It is a named input expected by the procedure.

Argument in the call

CALL DisplayMessage("Ready")

Text <- "Saved"
CALL DisplayMessage(Text)

"Ready" and Text are arguments. They are the actual values supplied.

Passing by value

By value means the subroutine works with a copy

Cambridge-style pseudocode

PROCEDURE AddOne(Number : INTEGER)
    Number <- Number + 1
ENDPROCEDURE

X <- 5
CALL AddOne(X)
OUTPUT X

Trace reasoning

Before callX = 5
Inside procedurelocal Number becomes 6
After callcaller's X is still 5
No BYREF means do not update the original caller variable.

Passing by reference

BYREF links the parameter back to the caller's variable

Cambridge-style pseudocode

PROCEDURE AddOne(BYREF Number : INTEGER)
    Number <- Number + 1
ENDPROCEDURE

X <- 5
CALL AddOne(X)
OUTPUT X

Trace reasoning

Before callX = 5
Inside procedureNumber is linked to X
After callcaller's X becomes 6
BYREF is useful when a procedure must update the caller's variable directly.

When to use BYREF

Use it when the procedure must deliberately update caller data

Good use

IncrementScore(BYREF Score : INTEGER) updates a stored score in the main algorithm.

Good use

Swap(BYREF A : INTEGER, BYREF B : INTEGER) must change both original variables.

Avoid if unnecessary

If the subroutine only needs to read a value, by value is clearer and reduces accidental changes.

Java support only

Do not replace Cambridge BYREF with Java syntax

Cambridge exam answer format

PROCEDURE Increase(BYREF Score : INTEGER)
    Score <- Score + 1
ENDPROCEDURE

Java support note

// Java support example only, not exam pseudocode
static void increase(int score) {
    score = score + 1;
}

Java primitive parameters are passed by value. Do not use this as evidence that Cambridge BYREF is absent.

Summary

Three sentences to leave with

By valueThe parameter receives a copy; local changes do not alter the caller variable.
BYREFThe parameter is linked to the caller variable; changes can be visible after the call.
