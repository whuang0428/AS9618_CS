Free software is not always free of responsibility.

This lesson compares open-source and proprietary software. The exam skill is not to declare one side "better"; it is to explain the trade-off for a given user, organisation or project: cost, control, support, security, customisation, compatibility and licensing.

Defineopen source, proprietary software and ownership restrictions
Comparecost, support, customisation, security and lock-in trade-offs
Recommenda suitable choice using scenario-specific evidence
Source visible? Can modify? Who supports it? What licence terms? What costs? What risk?

Choosing software by slogan is like choosing a database by logo colour. Entertaining, not evidence.

Teaching cue

Every comparison must include a scenario: school, startup, hospital, developer team or ordinary user.

Why this matters

Marks come from trade-offs: low cost may mean less formal support; vendor support may mean less control.

Common trap

Open source does not mean no copyright, no licence, no security risk or no maintenance cost.

Warm-up hook

A school wants free software for its network servers. Should it automatically choose open source?

"Free download" is a starting price, not the total cost of ownership wearing a tiny hat.

Choose one. The exam likes trade-offs more than fan clubs.

Knowledge point 1

Open-source software makes source code available under a licence

Source code availableUsers can inspect the program code rather than only using compiled software.
ModifyLicence may allow users to adapt the code for their own needs.
RedistributeLicence may allow sharing original or modified versions under conditions.
CommunityDevelopment and support may come from volunteers, companies or mixed communities.
Chinese support: open source = 开源；source code = 源代码；modify = 修改；redistribute = 再分发。

Knowledge point 2

Proprietary software keeps control with the owner

Closed sourceSource code is usually not available to users.
Restricted rightsLicences often restrict copying, modification and redistribution.
Vendor supportUsers may receive official updates, warranties, help desk or service agreements.
Vendor lock-inUsers may depend on one supplier, format, subscription or ecosystem.

Knowledge point 3

Compare by factor, not by favourite label

Factor
Open source may offer
Proprietary may offer
Cost
Low or no licence fee, but support and training can still cost money.
Licence/subscription cost, but bundled support may reduce operational risk.
Control
More ability to inspect, modify and adapt code.
Less control over internals; vendor controls source and roadmap.
Security
Code can be reviewed publicly, but someone must apply updates and assess trust.
Vendor may provide tested updates, but users must trust closed code and vendor response.
Support
Community help or paid third-party support may vary.
Official support agreements may be clearer for organisations.

Knowledge point 4

Ownership and licence obligations still matter

Copyright remainsOpen-source software is still protected; the licence grants permissions.
AttributionSome licences require credit or notices to be kept.
Share-alikeSome licences require modified versions to be shared under similar terms.
ComplianceOrganisations must track third-party components and meet licence conditions.

Knowledge point 5

Use a scenario-based comparison structure

1. NeedIdentify the user's priority: cost, support, control, reliability, security or compatibility.
2. Open source pointExplain one benefit or risk linked to that priority.
3. Proprietary pointExplain a contrasting benefit or risk.
4. JudgementRecommend one option with conditions and trade-offs.
Answer frame: For [scenario], [option] may be suitable because [factor]. However, [trade-off]. Therefore, the best choice depends on [condition/evidence].

Summary

Open source vs proprietary in six exam-ready ideas

Open sourceSource code is available and can often be modified under licence.
ProprietaryOwner controls source code and licence restrictions.
CostLicence price is not the same as total cost.
SupportCommunity support and vendor support suit different risks.
SecurityReviewability and responsibility for updates both matter.
JudgementRecommend by scenario, not by slogan.

Homework

Practise balanced comparison

Task 1: Comparison table Compare one open-source and one proprietary tool for the same task. Use columns: cost, support, customisation, security updates, compatibility, licence obligations.
Task 2: Rewrite weak claims Rewrite these with qualifications: "Open source is free", "Proprietary is safer", "Open source has no owner", "Paid software gives ownership".
Task 3: Timed response Answer in 8 minutes: "A school is choosing between open-source and proprietary software for a learning platform. Discuss the trade-offs." Include a final recommendation.
